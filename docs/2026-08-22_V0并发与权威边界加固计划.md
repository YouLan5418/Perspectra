# Harness / Cordis World V0 并发与权威边界加固计划

> 日期：2026-08-22
>
> 状态：已完成（本机门槛）
>
> 输入：独立代码审查、冻结实施规格 V0.2、ADR-0023～ADR-0037

## 1. 结论

Phase 0～5 的功能闭环和逐文件覆盖率已经建立，但现有测试主要证明串行路径。V0 在发布候选之前还必须闭合三类系统性风险：

1. Provider 输出、Memory source mapping 等派生输入必须经过权威边界验证，不能仅因结构自洽就成为世界事实或可信来源；
2. Outbox、Round Inbox、Writer Lease 等跨连接状态机必须用租约和 compare-and-swap 防止迟到 Worker 回写；
3. Export、Import、Restore 和 Audit 必须形成可验证的一致快照与来源闭环。

本轮不增加产品功能，不降低 WorldLog、Hash、as-of、FIFO 或 SQLite 原子性不变量。

## 2. 修复原则

- **事实只从 Kernel 产生**：Agent/Director Provider 只产生 Proposal；Validator 负责结构和授权，Rulebook 负责领域裁定，只有 Resolution/Event Draft 可以进入 `commitRound`。
- **领取权是显式耐久能力**：Outbox claim 带 owner、不可复用 token 和到期时间；完成/失败必须携带原 claim 并用状态 CAS 更新。
- **Round 完成必须有提交证明**：Inbox completion 必须同时验证当前 Writer Lease 和对应 `round_commits`，不能接收调用方任意结果。
- **事务窗口不得让出执行权**：FaultInjector 在 SQLite 事务内只能同步命中；提交后故障点也保持同步接口。硬崩溃测试使用子进程同步停驻。
- **Memory 不信任调用方 View**：reconcile 由可信 CharacterView source 在指定 address/character/asOfSeq 内部重建；同一 source 的序号只能单调前进，同序号不同 Hash fail-closed。
- **Export 是一个读快照**：所有 authority 表在同一 `BEGIN DEFERRED` 事务读取；Import 重算 Event chain、Head、Round bundle 和引用闭包。
- **运行态与权威态不混装**：authority-only Export 把 Outbox 归一化为可重投递状态，但保留既有 `session_delivery_seq` 与 counter；物理 Restore/Import 清除 sender receipt/claim 并按原序号重新投递。Session/Memory 仍是独立数据库，通过耐久 World Outbox/Event 重建，不伪装成同文件原子备份。
- **行政动作先过 Barrier**：fork 在同一写事务中验证父分支准入、无 pending/claimed Round、Head、forkSeq 和事件锚点；archived/draining source 一律拒绝。archive 必须先 draining，并等待 Writer、Round 与 critical Outbox 清空。
- **审计采用可调和终态**：不尝试跨数据库事务。权威数据库在 `commitRound` 主事务内保存 `round.committed`；sidecar 保存带 correlationId 的 requested/completed Hash chain，恢复来源写入目标端。

## 3. 实施单元与验收

| 单元 | 生产变更 | 必须新增的回归证据 |
|---|---|---|
| H1 权威输入 | Simulation 接入授权 Validator 和 Rulebook；拒绝未授权 actor/type/version | 恶意 Provider 不能生成 accepted Event；合法 Proposal 仍确定性重放 |
| H2 ID 边界 | 品牌 ID 拒绝 ASCII 控制字符，尤其是 `U+001F` | 两组曾可碰撞的 WorldAddress 均在解析边界被拒绝 |
| H3 Outbox | claim owner/token/deadline；delivered/failed CAS；只重领过期 inflight | 两 Worker 交错下迟到 failure 不能覆盖 delivered，未过期 claim 不可重抢 |
| H4 事务故障 | `FaultInjector.hit` 改为同步；移除事务内全部 `await` | 原硬终止矩阵继续覆盖 COMMIT 前后窗口 |
| H5 Round fencing | claim 查询当前 lease；completion 校验 lease 与 round commit/result hash | 旧 fencing token 和无 commit completion 均失败；提交后恢复仍幂等 |
| H6 Memory | 注入可信 ViewSource；内部重建和 bundle/source 验证；序号单调 | 伪造自洽 View、倒退 source、同序号分叉均被拒绝 |
| H7 Transfer | 一致性读事务；完整导入不变量；authority-only 状态归一化 | export↔commit 交错不撕裂；篡改 Head/链/Bundle/receipt 状态导入失败 |
| H8 Branch | fork Admission 条件和 archived-source 明确规则；archive 另行等待 Writer/critical Outbox | queued/claimed Round 阻止 fork；父归档后既有子分支仍可提交；父 future canary 仍不可见 |
| H9 Audit/Provenance | audit 终态与 hash chain；目标端 restore/import provenance | requested 可与 completed 对账；悬空 requested 表示未完成；目标库能自证来源 artifact hash |

## 5. 提交顺序

每个单元在相关测试、typecheck 和 lint 通过后独立提交；Schema 迁移和使用该列的代码处于同一提交，避免中间提交无法打开既有数据库。

完整门槛仍为：

```powershell
corepack pnpm@11.7.0 check
```

逐文件 100% 覆盖率保留，但不再把覆盖率当作并发正确性的替代品。最终阶段报告记录每个审查结论的处置状态、测试名称、提交和仍未执行的跨平台 CI 门槛。

## 6. 不采用的修复方式

- 不把父分支 Outbox、Session、Memory 或 Snapshot 复制到子分支；子分支使用新的派生 namespace，由继承的 Event 历史重建。
- 不把 sidecar 审计当成第二份世界事实；`round_commits/events/heads` 继续是提交证明，主库同事务 `round.committed` 只提供操作索引与对账入口。
- 不用延长重试时间掩盖 Outbox 竞态；使用 claim token 和 CAS。
- 不仅重算调用方提供的 CharacterView Hash；Hash 无密钥，不能证明来源可信。
- 不通过暂停并发、禁用 WAL 或全局大锁规避一致性导出问题。
