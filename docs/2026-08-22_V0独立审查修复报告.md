## 3. 关键设计取舍

1. 子分支只继承 forkSeq 之前的 Event 权威前缀，不复制父 Outbox、Session、Memory 或 Snapshot。父分支只有在 critical delivery 已完成后才能 archive，避免用复制派生状态制造第二份真相。
2. 恢复不假设 World DB 与 Session DB 能跨文件原子提交。目标 World Outbox 被重置为可重投递状态；即使 Session 同时恢复，消费端 deliveryId 幂等也会阻止重复 Observation。
3. sidecar audit 不是世界事实，也不参与 World Hash。它提供可检测篡改的操作链；真正的提交证明仍是 `round_commits/events/heads`，`round.committed` 只是在同一主事务内建立审计索引。
4. requested 后没有 completed 被解释为未完成或崩溃中的操作。恢复工具不得仅凭 requested 宣称业务已经发生。
5. 一致性测试使用可控交错点证明状态机行为；逐文件 100% 覆盖只作为补充门槛，不作为并发正确性的替代证明。

## 5. 尚未闭合的外部门槛

仓库没有远程，因此 GitHub Actions 的 Windows/Ubuntu × Node 22.19/24 四组矩阵仍只是已配置、未执行。这不是本机实现阻塞，但在声明发布候选可跨平台之前必须由远程 CI 给出证据。

本地 Hash chain 能发现记录级修改、删除中段和重排，但不能单独发现攻击者把整个 World DB 与 audit sidecar 一并替换或删除。若威胁模型包含拥有文件系统写权限的恶意管理员，仍需把周期性 chain head 锚定到仓库外的不可变存储或签名服务；V0 不引入远程依赖，因此明确保留这一边界。
