# 三角色悬疑 Demo：首个可执行切片

> 日期：2026-08-23
>
> 状态：Scripted Scenario 首轮已可执行、保存和恢复；不是最终交互产品

## 已落地

`@harness-world/simulation` 现在提供 `createMysteryDemoSpec`、`compileMysteryDemo` 与 `MysteryDemoScenario`。示例世界“灰林宅邸疑案”包含 Alice、Bob、侦探和玩家调查参与者，以及书房钥匙和一个共同调查 Scene。

初始认知通过角色私有 Claim/Observation 建模：

- Bob 的 CharacterView 含 `is_culprit = true` 的 author-secret Claim；
- 侦探只含 `may_be_involved` 的 suspected Claim；
- Alice 只有对 Bob 的信任，不含凶手秘密；
- 玩家也不含凶手秘密；
- 四个角色对同一把钥匙具有不同 interpretation。

开场 Turn 中，玩家说“我们从书房开始调查”，Bob 的 Scripted Agent 只提交 `take` ActionRequest。Rulebook v2 检查 Bob 与钥匙同处书房、钥匙尚无人持有后生成正式 `entity.taken`；Alice 不作为本轮 Agent 调用，Director 只明确 abstain，没有让所有持久角色每轮运行。

## 已验证不变量

| 不变量 | 证据 |
|---|---|
| Alice/玩家不知道系统秘密 | 实际 CharacterView JSON 不含 `is_culprit` |
| 侦探怀疑不等于客观定罪 | 私有 Claim 为 `suspected / may_be_involved` |
| Bob 不能直接改世界 | Provider 只返回 `take` ActionRequest，Kernel 生成 Event |
| 钥匙不再在书房 | Event 重放结果为 `locationId=null, holderId=character:bob` |
| 正式裁定可解释 | Round Authority 保存 Bob Proposal、Action、orderKey 与 Resolution |
| 非全员调度 | Authority 无 `agent:alice` participant |
| 保存/恢复稳定 | 新 Scenario 打开同一 SQLite 后同键 replay，Provider 调用为 0，Event/View Hash 不变 |
| Session 投递幂等 | 首次投递 2 项，重启后再次 drain 为 0 |

## 如何从代码调用

```typescript
import { MysteryDemoScenario } from '@harness-world/simulation'

const demo = new MysteryDemoScenario({
  worldPath: 'data/mystery/world.sqlite',
  sessionPath: 'data/mystery/session.sqlite',
})

try {
  await demo.runOpeningTurn()
  await demo.deliver()
  const snapshot = await demo.snapshot()
  // snapshot 是作者/调试用全知结构；面向玩家只投影允许公开的字段。
  console.log({
    head: { headSeq: snapshot.headSeq, tick: snapshot.tick },
    entity: snapshot.entity,
    playerView: snapshot.views.player,
  })
} finally {
  await demo.close()
}
```

也可以直接运行固定开场：

```powershell
corepack pnpm@11.7.0 demo:mystery -- D:\path\to\mystery-world.sqlite D:\path\to\mystery-session.sqlite
```

标准输出只包含玩家 CharacterView、公开钥匙状态、Round 结果和本次调用计数，不输出 Bob/侦探的私有 Claim。

`snapshot()` 同时包含四个角色的视图和 Authority，仅供作者验收与本机调试，不能整体发送到玩家通道。Claim/Goal payload 中的 `visibility`、`epistemicStatus` 是故事语义元数据；当前真正的访问边界是 CharacterView 按 owner 投影，消费者不得用这些 payload 字段自行扩大权限。

## 距离完整 Demo 仍缺什么

当前切片证明的是最关键的架构纵切面，不是完整故事体验。下一批仍需：

1. 把任意玩家文本解析/选择为受约束的 speak、move、take 等 Action，而非固定开场脚本；
2. 为 Alice、Bob、侦探分别从裁定生成可见性不同的正式 Observation，并进入来源可追踪 Memory；
3. 增加检查、询问、出示证据等调查 Action 与最小胜负/揭露条件；
4. 把当前固定开场命令扩展为可连续输入的交互壳；
5. 增加多 Turn Scripted Scenario、fork 和崩溃恢复验收（同轮竞争拿取已由正式 RoundCoordinator 集成测试覆盖）。

因此，当前已经从“底层架构原型”进入“悬疑 Demo 可执行骨架”，但尚未达到可自由调查和对话的成品 Demo。
