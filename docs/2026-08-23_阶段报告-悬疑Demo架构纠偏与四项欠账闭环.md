- 日期：2026-08-23
- 状态：本机完整门槛通过

## 结论

本轮没有改变产品方向，也没有启动 World Pack、创作者 SDK、GUI 或酒馆格式兼容。悬疑仍是验证“不同角色看到、相信和记住不同内容”的试金石；调查玩法已经从 Kernel 产品语义中移除，接下来的 Demo 价值重新落在题材无关的横向能力上。

```text
Core Kernel: speak / move / take + versioned Rulebook host
                         ↑ exact registry
Mystery Demo: inspect / ask / present / accuse + author truth

WorldApplication: Scene → per-character Context/Memory → Proposal → Rulebook → Authority
```

## 已完成

### 1. Rulebook 边界

- Kernel 只定义 `RulebookResolver`、`RulebookRegistry` 与 v1/v2 Core Resolver。
- v3/v4 调查 Resolver、证据 Projection 与结案规则位于 `@harness-world/simulation`，由悬疑组合根显式注册。
- 通用组合根打开调查世界会在 Writer Lease 前返回非重试 `RULEBOOK_NOT_REGISTERED`，没有默认回落。
- 禁止新激活 v3；存量 v3/v4 已验证继续提交、quarantine recovery、fork 后提交和 archive。
- 搬迁前冻结的 Resolution canonical bytes/hash、Event Hash、bundleHash、authorityHash、Manifest/Registry Hash 在搬迁后保持逐字节全等。

### 2. Scene 权威决断

- 新 v4 Demo Manifest 锁定 `builtin:scene-decision@1.0.0`；存量 Manifest 仍按历史静态调度。
- 唯一 active Scene、观察者、可调度 NPC/Director 与结果可见范围由耐久 Scene/Location/Visibility/Lifecycle 和 Runtime Availability 决定。
- 多 active Scene、畸形 Scene/Visibility 进入完整性错误；离场、不可见或 unavailable 角色不会调用 Provider。
- Observation 改为按 Scene 观察者分别生成，只有绑定玩家的 Observation 进入其 Session Outbox。

### 3. Cognitive Memory v2

- 新 v4 Demo Manifest 锁定 `builtin:agent-context@2.0.0` 和独立 `memoryPath`。
- World Commit 在 Event、Outbox、Round Commit 与 Head 的同一事务写入每角色 cognitive job；Provider 调用或 recall 前按明确 as-of 水位追平。
- capture 来源严格限制为已提交 Observation、Claim、Goal；Memory schema v4 为 Goal 增加来源映射，Summary 仍被拒绝。
- Context v2 稳定绑定 CharacterView、SceneDecision、recall、玩家 Action 与 Capability；每位参与者分别进入 Authority 的 contextHash、source refs 和 recall hash。
- Bob 的作者秘密只能由 Bob recall；Alice、侦探和玩家对同一查询结果不同。交流内容是带 Observation 来源的记忆，不会自动升级为真命题。
- 重启、fork、父分支 future canary、跨 Branch 与跨角色 recall 均保持隔离；已提交 Round 重放不重新检索。

### 4. 通用连续交互

- `WorldApplication.submitText` 与 `PlayerInputInterpreter` 已成为正式应用能力。
- 普通非空文本直接形成候选 `speak`；`/move`、`/take`、`/act` 只产生当前 Affordance 允许的候选 Action。
- 未知命令、缺参、非法 World JSON 和不可用 Action 返回 `clarification_required`，不写 Inbox、不推进 Tick；结果以独立耐久账本和 Audit 跨重启幂等重放。
- 悬疑解释器只处理明确调查语法，普通对白和通用命令回落到 Application 解释器。
- `demo:mystery:shell` 在同一个 mounted world 中逐行提交并即时输出玩家安全结果，不要求每轮选择调查行为。

### 5. 可恢复降级演练

`demo:mystery:drill` 支持：

- `agent-failure`
- `agent-timeout`
- `budget-exhausted`
- `director-fallback`
- `memory-catchup-failure`
- `session-dead-letter`

六种模式都验证：玩家 Round 提交且只推进一个 Tick；失败参与者写入准确 terminal；Round Audit 绑定 authorityHash 与 terminal 摘要；Application Metric 和 Runtime Availability 更新；Health 显示 degraded 原因；同键重放 Provider 调用为零；恢复后 Health 回到 healthy，下一轮 Provider 再次参与。

Drill 输出只含玩家 Result、参与者 terminal、Health、Audit/Metric 摘要与恢复步骤，不输出私有 Claim 或 Memory 内容。

### 6. 独立审查后的闭环加固

- shell 不再用进程内计数器派生幂等键；每条输入使用不可跨重启碰撞的随机 UUID，测试覆盖两个进程实例连续写同一数据库。
- Rulebook、Scene 与 Context/Memory 插件契约在 Inbox 受理和 Writer Lease 之前验证；Context v2 缺 Scene 或 `memoryPath` 会立即拒绝。
- cognitive job 从 Memory 本地队列提升为 World 事务内恢复账本，worker 回执受 Writer Lease/fencing token 保护；COMMIT 后、Memory 前终止可由新进程追平。
- quarantine recovery 会从已验证 World 前缀清空并重建派生 Memory；缺少 Memory 配置或来源分歧均保持 quarantine。
- clarification 增加 append-once Hash 账本与同事务 Audit；同键不能因解释器变化从“未受理”漂移为世界 Round。
- v3/v4 Golden 补齐 ask、present 与正确 accuse 的完整 Resolution canonical bytes/hash；未修改既有 expected。
- 新增不含 `inspect/ask/present/accuse` 的社交参考切片，以 Core v2 验证 Scene、角色私有认知、通用输入与重启幂等。
- Drill 断言失败参与者没有伪造 Action/Observation/Memory，并核对精确 Health 原因与 Memory 来源账本。
