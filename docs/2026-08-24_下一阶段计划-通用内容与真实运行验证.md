# 下一阶段计划：通用内容与真实运行验证

- 日期：2026-08-24
- 基线：私有源码 `v0.1.0`
- 建议阶段名：Phase 7
- 建议候选版本：`0.2.0`，完成门槛前不创建 Tag

## 目标

V0 已证明世界事实、角色认知、分支、恢复和本机运行边界可靠。下一阶段不扩充悬疑玩法，而是验证同一运行时能承载创作者定义的不同题材，并让一个真实角色 Provider 进入既有提案、裁定、提交和重放链路。

完成后应能回答三个问题：

1. 创作者能否在不修改 Kernel 的前提下定义角色、Scene、Goal、初始知识和内容入口；
2. 普通社交、探索等非悬疑世界能否复用相同 CharacterView、Memory、Scene 和 Rulebook 边界；
3. 真实 Harness Provider 能否在失败、重启和重放时仍服从“模型只提案、历史不重跑模型”的不变量。

## 工作流一：最小创作包契约

新增版本化、JSON-compatible 的最小创作包，不引入通用规则 DSL，也不允许内容包执行脚本。

创作包至少表达：

- 世界元数据和时间策略；
- Character、PlayerBinding、Location 与 Scene；
- 角色生命周期、初始 Observation、Claim 与 Goal；
- Rulebook、Scene Decision、Agent Context 和 Presentation 插件引用；
- 可选的确定性开场输入与验收断言。

提供 `compile`、`validate`、`inspect` 和 canonical hash 输出。编译结果仍是现有 Compiled Manifest 与 Genesis Plan；创作包不是新的世界事实源。

## 工作流二：通用本机交互壳

在 stdio only 边界内形成面向普通叙事世界的连续交互入口：

- 选择或激活一个已编译世界；
- 持续提交普通文本、`/move`、`/take` 和已注册 `/act`；
- 输出玩家授权视图、公开 Scene 变化和确定性 Presentation；
- 查询角色可用性、Round 状态、Health 和恢复提示；
- 不暴露作者全知视图、NPC 私有 Memory 或底层 Store Handle。

本阶段只做可验证的本机交互壳，不做 GUI、Web 或远程监听。

## 工作流三：真实 Harness Provider

在现有 `HarnessAgentPort` 后新增独立 Bridge，实现一个受配置控制、默认关闭的真实 Provider：

- 不复制或修改只读上游源码；
- Secret 仅从环境或 Secret Provider 获取，不写入 World、Audit 或导出包；
- 模型调用保存 request/context/response Hash、Profile、预算决定和终态；
- 合法输出仍必须经过 `submit_actions`、Capability、Rulebook 和 Resolution；
- 超时、失败、预算耗尽和非法输出只使参与者降级，不阻塞玩家提交；
- 已提交 Round 重放 Authority/Replay，禁止重新调用模型。

若没有版本匹配且许可清晰的 Harness 接入面，Bridge 保持禁用并记录阻塞证据，不绕过端口引用本地内部路径。

## 工作流四：非悬疑内容验证

至少增加两个不使用调查 Resolver 的创作包：

1. 酒馆社交场景：验证多人对白、私密动机、传闻不等于事实、角色进出 Scene 和连续 Memory；
2. 探索或旅途场景：验证位置切换、物品持有、角色离队、Scene 切换和 Goal 更新。

两个创作包必须只使用 Core Rulebook 或各自显式注册的题材插件。不得把题材条件写入 Kernel，也不得以更新悬疑 Fixture 代替通用性验证。

悬疑 Demo 保留为回归套件，继续验证知识隔离、错误命题、future canary、fork、降级和旧 v3/v4 兼容；本阶段不增加谜题、证据类型或结案机制。

## 实施顺序

1. 新增 ADR，冻结创作包所有权、版本、信任边界和插件引用规则；
2. 实现创作包 Schema、Compiler Adapter、诊断目录和 Golden Fixture；
3. 让现有悬疑与社交 Fixture 通过同一创作包入口编译，保持 Manifest/Genesis Hash 兼容；
4. 增加第二个非悬疑内容包并完成跨题材矩阵；
5. 实现通用连续 stdio 交互壳；
6. 接入默认关闭的真实 Harness Provider 与 Replay/降级矩阵；
7. 运行本机和 GitHub 四格门槛，形成 Phase 7 报告，再决定是否冻结 `0.2.0`。

## 验收门槛

- 创作者修改内容包不需要修改 Kernel、Store 或 Application；
- 未注册插件、未知版本、非法引用、循环引用和超限内容在激活前 fail-closed；
- 两个非悬疑世界完成连续多轮、重启、fork、Memory 和 Scene 验收；
- 不同角色对相同输入形成不同、可重建且不串线的 Context；
- 真实 Provider 输出不能绕过 Validator/Rulebook，失败不阻塞玩家 Tick；
- 同键重放不重新调用 Provider，完整重放不依赖网络；
- `v0.1.0` 的所有 Golden、P0～P6 和硬崩溃矩阵继续通过；
- Windows/Ubuntu × Node 22.19/24 clean install 与完整 `pnpm check` 全绿。

## 明确非目标

- 不建设完整创作者 SDK、可视化编辑器、素材市场或插件市场；
- 不兼容或导入旧酒馆角色卡格式；
- 不实现远程、多用户、认证、计费或 Web UI；
- 不实现通用脚本、通用规则 DSL 或不受信任插件沙箱；
- 不启用 TencentDB Memory；
- 不增加悬疑玩法范围；
- 不改写 `v0.1.0` Tag、历史 Event、Manifest 或 Golden Hash。

## 停止条件

若创作包需要改变 Accepted ADR、破坏 Manifest/Genesis Hash、让内容代码进入 Kernel、使模型获得世界写权限，或要求使用许可/版本不明确的 Harness 内部接口，则停止对应单元，记录证据并新增 superseding ADR；不得通过放宽不变量完成演示。
