# Phase 7 独立审查修复报告

- 日期：2026-08-25
- 候选版本：`0.2.0`
- 对照审查范围：`5f49bad..fac70d4`
- 结论：5 项中等问题全部闭合；6 项轻微问题修复，2 项按私有源码边界保留并记录

## 结果

这轮没有改变 Phase 7 的范围，也没有放宽 World、Hash、Memory 或角色视角不变量。修复重点是让创作者实际触碰的 Pack 契约与文档声称一致，并在 `v0.2.0` Tag 前把仍处于候选期的 v1 格式收口。

## 中等问题闭合

| 审查项 | 修复 |
|---|---|
| M1 激活未检查 Pack 版本分歧 | `WorldApplication.activate` 在写入前比较已存储 Pack 身份；同 id/version 异 Hash 返回 `PACK_VERSION_DIVERGED` |
| M2 进程入口硬编码来源错误 | `worldpack` CLI 统一输出 Canonical `ErrorEnvelope`，保留领域错误和结构化 Pack 诊断，未知异常不泄漏内部路径 |
| M3 v1 候选字段曾继续增长 | ADR-0063 明确实体字段属于 Tag 前候选收口；`v0.2.0` Tag 后新增必填字段必须升级格式版本 |
| M4 Schema 版本被当作对白开关 | Manifest v3 新增显式 `runtimeCapabilities.publicSpeechObservationVersion`；Round 观察行为只读取能力，不读取 schemaVersion |
| M5 存量 Pack Manifest 浅校验 | 深度验证 Compiler、Canonical 版本、插件锁与 Hash、能力、Presentation、初始事实、重复 ID 和未知字段 |

## 轻微问题处理

已修复：

1. Markdown 的 `contentHash` 现在按 UTF-8 原字节重新计算并核对。
2. Genesis 生命周期映射移除非空断言，遇到未知角色返回 `PACK_REFERENCE_INVALID`。
3. `worldpack test` 不再虚称 `passed`，而返回 `compiled` 与 `assertionsExecuted: 0`；正式多轮行为仍由 Testkit E2E 负责。
4. Chat 对领域错误保留原信封，对未知异常返回安全的通用错误，不输出本机路径。
5. `PLUGIN_NOT_REGISTERED`、`REGISTRY_HASH_MISMATCH` 已进入实际诊断映射与测试。
6. 进程型测试的基础超时从 15/20 秒提高到 30 秒；具体活性断言仍使用更短的局部超时，不用放宽时限掩盖死锁。

本轮保留：

- 来源目录读取仍面向本机可信创作者进程，不能抵御另一个恶意本机进程在 `realpath/lstat/readFile` 窗口持续换文件。路径逃逸、符号链接越界、大小与总预算仍 fail-closed；更强的目录快照属于未来 Host 隔离能力。
- `social` scaffold 从仓库参考 Pack 复制，符合当前“私有源码、不发布 npm”的冻结边界。发布独立二进制或 npm 包前必须把模板改为随制品安装的资源。

## 决策与兼容

新增 [ADR-0063](adr/ADR-0063-pack-runtime-capability-and-v1-closure.md)，明确能力选择、v1 格式冻结和错误契约。

- `v0.1.0`、Manifest v1/v2、悬疑 v3/v4、既有 Event/Authority/Golden 均不重写。
- 审查前生成但从未 Tag 或发布的 Phase 7 Manifest v3 临时制品不承诺兼容；应从来源目录重新编译。
- Pack 作者版本、Compiler 版本、项目版本与格式版本继续彼此独立。
