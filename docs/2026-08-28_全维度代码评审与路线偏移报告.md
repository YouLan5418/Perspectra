## 1.2 原始目标

> **V0 唯一目标 [V0-01]**（修订版 §17.1）：验证多个角色能否在共享世界中，依据不同知识、记忆和状态独立行动，同时由统一世界事实系统维持长期一致性。

- 项目从「AI 酒馆（SillyTavern 类）」演化为「**插件化 AI 叙事运行时**」；
- 一句话定位：*让 AI 角色真正"生活在世界里"，而不是只"存在于提示词里"*；
- **V0 不是完整产品**，不以漂亮 UI、生态兼容或功能数量作为成功标准；
- 上层产品形态规划三种模式挂载于统一运行时：**酒馆模式 / 小说模式 / 剧本模式**。

## 2.1 三类问题汇总

**🔴 规划中缺失的功能（6 项）**：Harness 运行时复用（D01）、Model Router（D02）、TencentDB 适配器（D03）、三种上层模式（D04）、规模与性能基准验收（D07）、L2/L3 记忆（D08，按计划推迟）。
→ 其中 **D01、D02、D07 是真正值得警惕的缺失**；D03/D04/D08 有明确推迟依据。

**🟢 超出规划新增的功能（3 项）**：子进程硬终止崩溃矩阵（D12）、降级 Drill + 运维加固（D13）、逻辑 Export 增强（D14）。
→ **超出项极少且全部为工程加固**，说明团队对范围控制严格，未出现功能蔓延（scope creep）。这是一条重要的正面结论。

**🔵 技术栈/架构层面变更（4 项）**：Harness 运行时 → 仅 Cordis（D01，ADR 授权）、能力接口抽象缺失（D05）、world-pack→application 依赖倒置（D06，规格授权）、静态包依赖替代动态插件（D15，V0 收敛）。
→ 无一项是失控变更；但 **D05 是唯一没有 ADR/规格背书、纯属实现惯性的架构偏差**。

## 2.2 总体结论与纠偏建议

> **总体结论：主线未偏，收缩有据，但"叙事运行时"的外壳尚未落地。**

项目最核心的命题——**世界事实与角色认知分离、事件溯源、崩溃可恢复、知识隔离**——在代码中被严格且高质量地实现，与 12 条系统不变量 INV-01～12 逐条吻合。真正偏离的是**承载这些能力的宿主**：文档设想站在 Harness 之上，实际是自建最小运行时 + 零模型 Provider。

**是否需要纠偏：需要，但应是"补齐"而非"回退"。**

| 建议 | 具体动作 |
|---|---|
| ① 修订顶层定位文档（优先） | D01 已有 ADR 授权，问题在文档没跟上。应在 `项目上下文与架构决策说明（修订版）.md` §5 补充一条 superseding 决策：V0 阶段以「最小自建运行时 + Cordis」替代 Harness 运行时，Bridge 在 Phase 11 接入。否则新读者会判定为严重偏移 |
| ② 补性能与规模基准（优先） | 按验收清单写 2 个基准用例：连续 200 Turn、10,000 事件查询；达不标则按文档要求"解释未达标原因"。这同时能把第 4 维度的性能判断从静态推断变为实测 |
| ③ 补 Model Router 接口占位 | 不需要立即实现路由策略，但应在 `contracts` 冻结 `ModelProfile`/路由选择契约，避免 Phase 11 接真实模型时反工（Phase 8 已冻结 `ProviderModelProfile`，可在此基础上加选择器） |
| ④ 抽 WorldStore 接口 | 在 `contracts` 或 `store-sqlite` 内定义 `WorldStorePort` 接口，让 `kernel`/`memory`/`agents` 依赖接口。工作量大但能同时改善可测试性与 D06 的耦合 |
| ⑤ 同步版本与文档 | 包版本推进到 `0.3.0-0` 或在 CHANGELOG 增加 Phase 8 条目；README 状态段与文档索引补齐 Phase 8 |

# 第五部分 · 最终产品画像（基于实际进展推断）

> 以下推断基于**当前代码实际能力**，而非文档最初设想。

## 5.1 产品定位与一句话概述

**一句话**：一个**事件溯源、可崩溃恢复、知识严格隔离的多角色世界模拟内核**，外加一套**纯数据内容包**编译与创作工具链；当前不含任何真实模型调用，是一个"确定性可验证的世界运行时"。

**定位判断**：它**不是**文档设想的"插件化 AI 叙事运行时"成品，而是该运行的**内核与验证平台**——文档里的酒馆/小说/剧本三种上层模式尚未出现。若按现状交付，它面向的是"需要可信多智能体世界状态的人"，而非"想玩 AI 角色扮演的终端用户"。

## 5.2 目标用户与典型使用场景

| 用户 | 场景 | 当前可用性 |
|---|---|---|
| 架构研究者 / 内核开发者 | 验证"世界事实 vs 角色认知"分离、事件溯源、崩溃一致性 | ✅ 完全可用（这是它最擅长的） |
| AI 应用工程师（做多智能体/长期记忆） | 借鉴其 CharacterView / Memory 水位 / 双 Hash / 上下文可重建的设计与实现 | ✅ 完全可用（可当参考实现） |
| 内容创作者（写世界/角色） | 用 `worldpack init/validate/compile/activate` 编辑纯数据 Pack，再用 `worldappctl chat` 交互 | ⚠️ 工具链完整，但**无 LLM 就跑不出角色行为** |
| 终端玩家 / 普通用户 | 与 AI 角色互动 | ❌ 当前不可用（无模型、无 UI、仅 stdio） |

## 5.3 核心特点（相对同类方案的差异点）

1. **知识隔离是结构性保证，不是 Prompt 约束**——角色只能读到自己的 CharacterView，跨角色/未来/跨分支泄漏有 canary 测试与 fail-closed 兜底。SillyTavern 类方案靠"提示词里要求别说漏"，这里靠架构。
2. **崩溃一致性由真实子进程硬终止验证**——19 项 kill -9 恢复测试，不是模拟异常。多数同类项目没有这一层。
3. **上下文完全可重建且可证明**——`contextHash`（语义）与 `providerRequestHash`（精确字节）分离，配合 ContextReceipt 与 mutation matrix，能证明"同一水位重建出同一份模型输入"。这是 Agent 可复现性上少见的做法。
4. **内容包是严格数据而非脚本**——Pack 不能注入代码/网络/权限，编译产物不可变且带来源 Hash，创作者只能改内容。
5. **零运行时依赖**——除 Cordis 外无任何生产依赖，无网络监听，stdio only。

## 5.4 完整功能清单

**主功能**
- 事件溯源世界内核：World Event Log、Tick、Head、Round 提交、单 writer fencing（`world_writer_leases` + `instance.lock`）
- 行动裁决与原子提交：Rulebook v1/v2 注册、稳定排序、同事务提交 Event/Tick/Head/Outbox/Authority
- 角色观察与知识隔离：CharacterView、Observation 生成、可见性收窄（`scene_public`/`direct`/`private`/`self`）
- 角色主观状态（Phase 8）：七类时态认知（Claim/Goal/Relationship/Affect/InnerTension/Commitment/OpenLoop），可按 asOfSeq 精确重建
- Scene v2：created→active→closed 生命周期、成员管理、动作时刻可见性、稳定 decisionHash
- Cognitive Memory v2：耐久 Job、独立水位、四类捕获、FTS5 召回 + RecallReceipt、确定性 L1 摘要
- Context v2：12 段固定布局、Checkpoint + Interaction Tail、latent/conscious 分离、双 Hash
- Director：最小权限规划上下文、Dramatic Signal、抽象 Directive
- 分支与维护：fork（最大深度 8）、archive、quarantine 与恢复、Snapshot、Compaction
- 内容包工具链：`worldpack init/validate/compile/inspect/test/activate`

**辅助功能**
- 运维：Backup/Restore、authority-only `.dshworld` 逻辑 Export/Import、Health、固定基数 Metrics、append-only Audit
- 入口：`worldctl`（健康检查）、`worldhost`（NLJSON-RPC stdio Host，无网络监听）、`worldappctl chat`（持久交互）
- 演示与验证：三角色悬疑 Demo、六种降级 Drill、19 项硬终止崩溃矩阵
- 可诊断性：`context.explain/rebuild/verify`（Admin/Author/Player 三面）

## 5.5 安装与运行使用方式

**前置**：Node 22.19+ 或 24+，可用 Corepack，Windows 或 Linux。
当前**无 npm 包、无 Release 产物**，形态为源码分发。

```powershell
# 1. 安装
corepack pnpm@11.7.0 install --frozen-lockfile

# 2. 验证（typecheck + lint + 100% 覆盖率 + P0~P6 + 19 项硬终止）
corepack pnpm@11.7.0 check

# 3. 创建并运行一个非悬疑世界（创作者路径）
corepack pnpm@11.7.0 worldpack init   --profile social D:\worlds\my-tavern
corepack pnpm@11.7.0 worldpack validate D:\worlds\my-tavern
corepack pnpm@11.7.0 worldpack compile D:\worlds\my-tavern --out D:\worlds\my-tavern.worldpack.json
corepack pnpm@11.7.0 worldpack activate D:\worlds\my-tavern.worldpack.json --data-dir D:\worlds\my-tavern-data
corepack pnpm@11.7.0 worldappctl chat --data-dir D:\worlds\my-tavern-data

# 4. 无模型悬疑 Demo（幂等，可重启恢复）
corepack pnpm@11.7.0 demo:mystery      D:\w.sqlite D:\s.sqlite
corepack pnpm@11.7.0 demo:mystery:turn D:\w.sqlite D:\s.sqlite turn:inspect "检查一下书桌"
corepack pnpm@11.7.0 demo:mystery:shell D:\w.sqlite D:\s.sqlite
corepack pnpm@11.7.0 demo:mystery:drill agent-timeout D:\drill-w.sqlite D:\drill-s.sqlite

# 5. 运维
corepack pnpm@11.7.0 worldctl -- D:\path\to\world.sqlite health
corepack pnpm@11.7.0 worldhost -- --config D:\path\to\world-host.yml
```

**运行边界**：私有源码、stdio only、无远程监听、Harness/TencentDB/真实模型 API 全部默认禁用。遇到 `SESSION_DELIVERY_DIVERGED`、`BUNDLE_HASH_MISMATCH` 等 integrity 错误**不得重试覆盖数据**，应停止写入并进入受控诊断。
