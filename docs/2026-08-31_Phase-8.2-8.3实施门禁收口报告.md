# Phase 8.2 / 8.3 实施门禁收口报告

| 属性 | 值 |
|---|---|
| 日期 | 2026-08-31 |
| 分支 | `phase8.2/correctness-closure` |
| 基线 | `v0.3.1` 候选提交 `c2b3141` |

| 结论 | **Phase 8.2 正确性门禁与 Phase 8.3 性能基线均已关闭** |

> 本报告中的“Phase 8.2 / 8.3”是 ADR-0077 为 Phase 9 设置的前置门禁，不是 Phase 8 实施规格中同编号的 P8.2 / P8.3 功能单元。

## 1. 结果先行

Phase 9 的生产 Schema 仍未开始变更，但它依赖的两道前置门已经具备可执行证据：

- post-COMMIT Availability 可从 World 事务内的耐久意图恢复；
- Context 数据库采用一个连续、可修复旧部分 Schema 的迁移目录；
- ProviderCall 继续保持 append-once 与 dispatch 歧义不重发；
- NPC-only Round 的 Action 顺序不需要伪造玩家 Action；
- Context Tail、CharacterView、认知 Projection 与 Memory Observation 不再调用完整 Event Log 读取接口；
- 10,000 行固定数据门槛验证 Event range、Checkpoint 和 Job 候选查询计划；
- 稳定调用预算在 Provider dispatch 前一次冻结，并产生可重建 `planHash`。

这不等于 Phase 9A 已获无条件开工许可。ADR-0077 的 v15 → v16、logical v5 → v6、四库恢复和玩家抢占矩阵仍须先完成评审。

## 2. Phase 8.2 正确性门禁

| 门禁 | 实现证据 | 验证结果 |
|---|---|---|
| post-COMMIT Availability 对账 | `4a824b3` | Availability 意图与 World Commit 同事务；`store.after-commit` 硬终止后可从 Round Authority 对账恢复，不重调 Provider |
| Context 数据库迁移纪律 | `88c53bd` | `CONTEXT_APPLICATION_ID`、连续 v1～v5 migration、旧部分 Schema 修复、外来 identity 与 future version fail-closed |
| ProviderCall append-once | 既有 `ProviderCallStore` + `88c53bd` 迁移复核 | `prepared → dispatch_started → response_received → validated → committed` 保持 CAS 式状态转换；歧义 dispatch 不自动重发 |
| NPC-only ActionOrderKey | `f8b612e` | agent-only 集合无需 player 行；U+10000 / U+E000 使用 UTF-16 code unit 全序，Golden Hash 固定 |

### 2.1 不变量

- Availability 是派生运行状态，不进入 World Hash；恢复前必须先验证 World 内的 operational summary 与 Round Authority 一致。
- Context/ProviderCall 数据库可以晚于 World Commit，但不能凭未验证 sidecar 数据反写世界事实。
- ProviderCall 的外部计费仍只承诺世界效果 at-most-once，不宣称外部 exactly-once。
- NPC-only Round 只是允许 Action 集合没有 player 行；模型输出仍是 Proposal，Rulebook 仍是唯一裁决者。

## 3. Phase 8.3 性能基线

### 3.1 生产读取路径

| 路径 | 提交 | 变化 |
|---|---|---|
| Interaction Tail | `e2ff5d9` | 使用 `readEventsRange(afterSeq, asOfSeq, ['observation.upsert'])`，只读取 Checkpoint 后的窗口 |
| Round Authority 有效性 | `e2ff5d9` | 使用 transaction identity 与 branch ancestry/cap 校验，不再 `readEvents(...).some(...)` |
| CharacterView /基础 Projection | `2e2bfcf` | 按冻结事件词汇使用继承安全的 Event range；测试令 `readEvents()` 直接抛错以防回归 |
| Cognition Projection | `2e2bfcf` | 只读取七类 cognition upsert 与 `character.reflect` |
| Memory Observation | `2e2bfcf` | 只读取 `observation.upsert`，不遍历无关 World Event |

这些改动不改变 Event、Hash、fork/as-of 或 Projection 字节。`readEventsRange` 仍沿父链应用 fork cap，并在应用层返回有效继承顺序。

### 3.2 固定数据门槛

`19f3d04` 将独立性能门槛加入 `pnpm check`；`4682c8d` 让 Job 基准直接调用生产稳定预算规划器。

| 数据集 | 查询/规划 | 固定边界 |
|---|---|---|
| 10,000 World Event | 最近 128 seq 内的 Observation | 64 条结果；查询计划必须为 `SEARCH`，禁止顶层 `SCAN` |
| 10,000 Context Checkpoint | 查一个不晚于 as-of 的最新 Checkpoint | 使用 `(namespace_key, as_of_seq)` 前缀索引 |
| 10,000 Job 行 | 仅 256 条 active candidates | 应用层 UTF-16 全序；一次冻结最多 8 个调用 |

本机回归阈值为每项 2,000 ms，实际整组性能测试约 0.2 秒。阈值用于发现查询计划退化，不是吞吐量或生产 SLA。

### 3.3 稳定预算

`planStableCallBudget` 冻结以下顺序与语义：

```text
(wave ASC, characterId UTF16 ASC, stimulusHash ASC, jobId ASC)
```

它先应用 `maxCallsPerCharacter`，再应用 Cycle call 余额，最后应用 token 余额。每个候选得到 `reserved` 或带明确原因的 `skipped`；本 wave 中失败或少用 token 不会把名额临时转给排序靠后的 Job。完整计划计算 `stable-call-budget-plan/v1` Hash，因而可被 World Job 账本重建和核对。

## 4. 边界与未声称事项

- 本门槛证明“有索引的固定数据查询与确定性规划不会退化为无界表扫描”，不声称所有相关投影查询是 O(1)。
- 认知状态的精确 as-of 重建仍会读取该词汇的有效历史；这是权威重放路径，不得用未验证缓存替代。
- Root Round 当前每轮仍只读取一次完整历史供 Rulebook 与 Scene 裁定。Phase 9 的每个 Reaction wave 不得照搬为多参与者重复全量读取。
- `reaction_job_candidates` 仍只是性能测试中的拟议 Schema。正式表、约束、索引和逻辑传输字节只能由 Phase 9A v16 migration 冻结。
- 本轮未创建 Reaction Cycle 表、RPC、Worker 或空 Adapter。

## 6. Evidence → Finding → Path

### Evidence

- E-001：`4a824b3`、`88c53bd`、`f8b612e` 分别关闭 Availability、Context migration 与 NPC-only 排序门禁。
- E-002：`e2ff5d9` 与 `2e2bfcf` 把模型可见路径从完整 Event API 收缩到继承安全的类型/range 查询。
- E-003：`19f3d04` 与 `4682c8d` 把 10k 查询计划和稳定预算生产实现纳入统一 `pnpm check`。

### Finding

- F-001：Phase 8.2 正确性门禁已关闭，Phase 9 可以复用现有 Authority、ProviderCall 与 UTF-16 全序，不需要另建信任边界。
- F-002：Phase 8.3 已具备可重复的性能回归基线，但正式 Reaction Job 索引仍须在 v16 migration 中逐字冻结。
- F-003：下一风险中心已经从“能否实现”转移为 World/Context 跨库恢复和 Cycle 状态机的事务边界。

### Path

1. 评审并冻结 v15 → v16 表、索引、迁移回滚和旧二进制拒绝策略；
2. 评审 logical v5 → v6 的 Cycle/Job/Stimulus/Authority 完整性校验；
3. 定义 World、Context、Memory、Session 同一恢复集合的水位和双向引用验证；
4. 关闭玩家 freeze/dispatch/Tx B 前后抢占矩阵；
5. 以上通过后进入 Phase 9A 权威骨架实现。
