## 一、问题概述

Phase 9 的权威骨架（Schema v16、Logical Authority v6、四张 Reaction 表、partial unique index、Manifest v5 能力门、ADR-0076 Proposed / 0077～0082 Accepted）**全部按 spec 落地且路线一致**，9A/9B 的核心不变量（Hash 分层、租约+fencing、append-once、wave 串行/并行、抢占线性化、损坏账本隔离）实现正确。但 Phase 9 **整体远未达到 spec 第 27 节"完成定义"**：P9C.5 真实磁盘迁移演练、P9C.6 长历史性能门槛、P9C.7 Release Closure 与远程四格 CI 仍未闭合；同时存在若干代码层缺陷与测试覆盖缺口，需要在进入发布前修复。

**问题数量统计**：P0（阻塞发布）2 项；P1（应修复）5 项；P2（建议改进）5 项。

## 三、已确认的正确实现（无问题）

以下 spec 要求经代码核对已正确落地，列入正面证据，避免重复返工：

1. **Schema v16 与四张 Reaction 表**：`world-store.ts` `WORLD_REACTION_SCHEMA` 含 `world_reaction_cycles/waves/jobs/job_stimuli`；`store.test.ts` 断言 `user_version=16`；含 `events_type_range` 索引。
2. **Partial unique index**：`world_reaction_cycles_one_open ON world_reaction_cycles(address_key) WHERE status <> 'terminal'` 保证每 branch 最多一个未终结 Cycle；`world_reaction_jobs_provider_call` 等唯一索引齐备。
3. **Logical Authority v6**：`logical-transfer.ts` `format: 'dshworld-authority/v6'`、`authorityVersion: 6`，支持 v4/v5→v6 升级与 Hash 重验。
4. **Manifest v5 能力门**：`world-spec.ts` `CompiledWorldManifestV5.reactionPolicy`；`reactionPolicyFromManifest` 对非 V5 返回 `disabled`；`parseReactionPolicy` 严格校验 mode/profile。
5. **ADR 状态**：ADR-0076 Proposed（原型证据，未升格）；ADR-0077/0078/0079/0080/0081/0082 均 Accepted，符合 spec 门禁要求。
6. **Hash 分层**：`reaction-cycle.ts` `hashReactionCycleAuthority` 只覆盖 initial wave 不可变字段；`hashReactionCycleBundle` 覆盖可变状态；Authority 与 State Hash 分离正确。
7. **租约与 fencing**：`claimNextReactionJob/renewReactionJobClaim/bindReactionJobProvider` 均校验 Writer Lease + Job fence + CAS；符合 spec §12。
8. **append-once 与歧义恢复**：`reaction-scheduler.ts` `#executeJob` 对 `dispatch_started` 状态重入时标记 `timed_out_ambiguous`，不自动重发；符合 spec §13。
9. **抢占线性化**：`requestReactionCycleStopInTransaction` 在 World `BEGIN IMMEDIATE` 内与 Inbox enqueue 同事务线性化；符合 9A 评审 §6。
10. **损坏账本隔离**：`quarantineReactionCycleInTransaction` 对 `readActiveReactionCycle` 失败返回 `unresolvedReactionCycle: true`，不修复坏账本；符合 ADR-0082。
11. **公平调度器**：`branch-work-scheduler.ts` `MAX_CONCURRENT_BRANCHES_DEFAULT=4`、`MAX_RESIDENT_WAKE_KEYS=1024`、UTF-16 round-robin、wake lossy/mergeable、graceful shutdown with timeout；符合 ADR-0079。
12. **行政边界纳入 Cycle**：`branch-administration.ts` `enterMaintenance` 检查 `openReactionCycleId !== undefined` 并拒绝；`archive/fork` 对 active/stop_requested Cycle 返回可重试错误；符合 spec §17 行政矩阵。

## 四、整体审查结论

Phase 9 的**权威骨架与不变量实现质量高**，9A/9B 交付的核心路径（Cycle/Job/Stimulus 耐久化、wave 串行/并行、抢占、恢复、隔离）经代码核对与 spec 一致，无 P0 级架构偏移。主要风险集中在**发布收口尚未完成**（Q-001）与**长历史性能未达标**（Q-002），这两项是阻塞 Phase 9 宣称完成的硬门槛。

**修改优先级建议**：

1. **P0（阻塞发布，立即处理）**：Q-001（闭合 P9C.5/9C.6/9C.7）、Q-002（长历史性能优化）。
2. **P1（应修复，发布前完成）**：Q-003（补齐硬终止测试点）、Q-004（性能门禁入 CI）、Q-005（claim 事务语义对齐）、Q-006（显式 LIMIT 1）、Q-007（ActionOrderKey 正式冻结）。
3. **P2（建议改进，可并行）**：Q-008～Q-012，多为文档一致性、字段统一、注释澄清，不阻塞发布但应纳入收口。

**停止条件核查**（spec §25）：当前未触发任何停止条件——公平调度未改变 Branch 内顺序、背压未丢弃耐久工作、行政操作未跳过完整性检查、Pack v3 未改写 v1/v2、after-dispatch 崩溃未自动重发、性能未通过放宽事务/减少故障点/关闭 fail-closed 达标。实现可继续推进，但必须按上述优先级闭合剩余单元，不得以"本机通过"冒充"远程矩阵通过"或"Phase 9 完成"。
