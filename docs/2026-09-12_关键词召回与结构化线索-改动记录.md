## 1. 这批要解决的问题，以及它是怎么被找到的

第一批让"上下文放不下"不再表现为角色永久掉线，但**没解决角色记不记得住**。于是先做了一次只读测量（雨夜同行参考世界、单角色、200 轮闲聊、脚本提供方，不改生产代码），结论比预想更糟：

| 查询 | 命中候选 |
| --- | ---: |
| `钥匙` / `备用钥匙` / `花盆` / `第三个花盆` | **0** |
| 只有把当初那句话一字不差地复述 | 2 |
| 玩家问"钥匙放在哪了？""我们要出门了，你有什么要提醒我的吗？" | 进入角色上下文 **0 条** |

原因不是容量、不是上限、也不是裁剪，而是**匹配**：中文句子没有空格，旧路径把整句当一个词元，于是只有"整段完全相同"才可能命中。原文一条没丢——这一点把方向从"压缩"彻底改成了"检索"。

这条链条决定了后面每一件事的顺序：**先测量 → 定位到匹配 → 修匹配 → 再测量 → 定位到线索 → 加线索 → 再测量 → 定位到加权 → 加词典**。每一步都用同一把尺子（那份测量脚本）验收。

## 2. 逐项改动：做了什么、怎么改、为什么

### 2.1 关键词匹配（提交 `9424427`、`970fd17`）

**为什么**：中文常用名词以两字为主（钥匙、花盆、车站）。旧路径只有"整段相同"，任何子串、任何改述都是 0 命中。按上位契约的版本警告，旧语义不得原地替换。

**怎么改**：
- 新增**版本化切词器**：连续中日韩文字同时产生相邻**二字与三元**词元（纯三元会让两字名词产生不出任何词元，反而更差），拉丁字母/数字/标识符沿旧规则并折叠大小写。
- 匹配语义放宽为**命中任一词元**，只作用于新的计划版本（`recall-query-plan/v2`），旧版本一字不动。
- **排序只用当前命名空间、当前水位之前的统计**，不用数据库内置的全表 bm25。排序为：相关性、`source_seq` 降序、`memoryId` 的规范文本序（用三轮稳定排序实现，避免一条永远不可达的判据分支）。
- 新增**词元索引表**（迁移 6）：词元是已捕获来源文本的纯函数，因此索引是**派生数据**、可随时重建；命名空间行记录"由哪个切词器建立"，换切词器只重建一次。
- 新增**检索回执 v2**：记录切词与策略版本、每条候选命中的词元与分数、**被条数上限截掉的候选数**与裁剪理由。旧回执字段与封闭枚举不变。
- **失败即停**：声明了新策略却没有索引时，拒绝并降级参与者（可重试），而不是悄悄返回"什么都没想起来"。

**效果**（同一批已存语料，旧 vs 新）：`钥匙` 0→2、`花盆` 0→1、`钥匙放在哪了？` 0→27。

### 2.2 分词器改为外部依赖（提交 `491bf19`，规矩文件 ADR-0089）

**为什么**：二元切分能召回但把词边界切开、噪音偏大。用户批准引入外部分词器，但仓库规则原本只允许 `@deepseek-ai/cordis` 一个上游运行时依赖，所以先立规矩再动代码。

**怎么选**：实测两个候选后选了 `jieba-wasm` 而不是 `@node-rs/jieba`：

| | `@node-rs/jieba` 2.0.3（原生） | `jieba-wasm` 2.4.0（WASM） |
|---|---|---|
| 同步调用 | 是 | 是，无需 await |
| 文档语义是否可用 | **不符**：精确模式切成单字、词性全返回 `x`、2.x 实例没有 `addWord` | 与文档一致 |
| 单次耗时（热） | 0.004 ms | 0.025 ms（首次约 200 ms，每进程一次） |
| 平台一致性 | 每平台一份二进制，官方矩阵只写到 Node 18 | **一份字节，全平台同一份** |

**关键设计取舍**（每条都有实测依据）：
- **必须保留二元兜底，不能只用词切分**：实测证明，分词器一旦把复合词合并成一个词，只提到其中一部分就查不到了。`第三个` 是一个词，那么查询 `三个` 在纯词索引里**一条都匹配不到**；二元兜底仍然命中。所以两者同表并存，词命中权重更高（4）、三元 2、二元 1。
- **用精确模式**（词典 + 动态规划，不含统计模型）：最可预测。它的弱点（`林小满` 被切成三个字）由二元兜住；另一种 HMM 模式能合成人名，却会造出错误合并（`串挂`）。
- **不用 jieba 的全局词典能力**：`add_word` 会全局改状态，等于把某个角色声明的名字泄漏到别的角色的切分结果里，还会让同一水位重建出不同结果。
- **只索引两字及以上的词**：单字会让任何查询都把每句话变成候选。
- **排除会崩的接口**：实测 `tokenize` 用两个汉字调用会抛 `memory access out of bounds`；生产只用 `cut`，并加了异常输入用例（emoji、补充平面、孤立代理项、全角、两万字长文、重复字符）。

### 2.3 消费层：让效果真正到达角色（提交 `b8ee0e2`、`982d6a8`）

**为什么**：记忆层修好了，但没有任何世界能用——**上下文层会独立复验召回回执**（自己重算计划/查询/排名/结果四个哈希），新版本的回执它认不了。这是"能不能在试玩里看到"的唯一堵点。

**怎么改（没有放宽任何检查）**：
- 把召回校验单独抽出来，**两代各按各的规则验**。新版本多一条旧版本没有的校验：**回执里的排名必须仍然指着角色实际用到的那几条记忆、顺序一致**——因为回执指纹只能证明"这份回执没被改过"，证明不了"排名和记忆还对得上"。
- **两代混用直接判为完整性故障**，不做任何"善意重新解释"。
- **选择显式且被记录**：应用层选项 → 计划代次 → 计划身份 → 回执写下策略与分词器。换选择重建会 fail-closed；**没有选择的世界逐字节不变**（有测试锁住）。
- 试玩入口加参数 `--recall-keyword jieba-hybrid/v1`，写错的标识直接报错不猜。

**效果**（真实回合、真实上下文）：同一件 120 轮前的旧事，四种问法里前三种都能进入她的上下文，包括只说了两个字的那种。

### 2.4 结构化线索（提交 `5edb693`，规矩文件 ADR-0090）

**为什么**：即使匹配修好了，查询仍然只是"玩家当前那句话"，所以只要玩家没提相关词就想不起来。上位契约的 T-01/T-02 要求"再次见到承诺对象""同一人物不同措辞"能被召回，这两条不可能靠原话查询满足。

**怎么改**：
- 新增**线索通道**：线索只来自两处已授权、可重建的来源——**场景决策的权威成员名单**（排除她自己）与**她自己的未完成事项**。不用模型推断、不读其他角色的私密状态。
- **线索取最低权重档**：它能保证候选不被漏掉，但永远压不过玩家明说过的内容。
- **每条候选记录"它是不是因为线索才进来的"**，回执记录用了哪些线索 → "为什么它进来了"可解释。
- **线索为空时结果与纯关键词完全一致**（有测试锁住），只会补充、不会劣化。

**过程中抓到一个会静默失效的真问题**：线索最初取自"角色的目标视图"，看起来很自然，写测试时发现**那个视图上角色的目标永远是空的**——角色视图用的投影器和记忆捕获用的不是同一个。若不写这条测试，这条线索通道会在真实世界里一声不响地永远不触发。改成从**该角色已捕获的目标来源**读取：与词元索引同源、同水位、不需要多跑一次投影重建，目标不再"进行中"就自动不再是线索。

**效果证据**（提交 `1778686`）：测量世界现在含一件**属于某个人**的旧事（Bob 说一次、之后不再说话，所以她记忆里带 Bob 身份的只有这一条）。

| 玩家的说法 | 问之前纯关键词能匹配 | 进上下文 | Bob 那件事在里面 |
| --- | ---: | ---: | --- |
| 一字不差复述 | 19 | 10 | 不在 |
| `钥匙` | 4 | 10 | 在 |
| `钥匙放在哪了？` | 19 | 10 | 不在 |
| 我们要出门了…（没提相关词） | 15 | 10 | 不在 |
| **`嗯，随便吧。`** | **0** | **10** | **在** |

最后一行是闭合的证据：那句话与那件事**没有任何共同词元**，那件事也不含玩家身份，所以它只可能靠"Bob 在场"这条线索进来。对照数字在**提问之前**测量，不会把它自己刚说的话算进去。

### 2.5 名称词典（提交 `3b858e8`，规矩文件 ADR-0088 第 2～4 条）

**为什么**：ADR-0088 定下了"专有名词词典只影响排序、按角色隔离、可按世界停用"三条，但一直挂着"未实现，传 true 报错"。

**怎么改**：
- **只影响排序，不改可匹配性**：加权是**命中词元**的属性——候选命中已捕获的名字则相关性翻倍，而**候选集合与顺序完全不变**（开/关对照断言：命中集合相同、分数成倍）。这是它敢对已有世界开启的原因。
- **隔离与水位是构造上成立的**：词典来源是**该角色自己已捕获的记忆里携带的身份**（如说话者 id），且只取水位之前的来源。别的角色私下知道的名字进不了这本词典；同一水位永远派生出同一本词典。
- **可按世界停用**：计划记下是否启用，回执记下派生于哪个水位；换选择重建会 fail-closed。默认**不启用**，现有世界一字不改。
- 删掉了那条已经过时的"词典未实现"拒绝规则——保留一个假的拒绝比没有更糟。

**这个功能没有世界级效果可以测，必须说清**：词典**永远不改变哪些记忆能被找到**，只改变名字在其中的分量。所以开/关跑测量会看到一样的结果——这不是没做好，是它的定义如此。它可测的效果就在分数上，已用对照断言精确锁住。

## 3. 版本与数据结构变更

| 项 | 变更 | 为什么 |
| --- | --- | --- |
| 记忆库迁移 | 5 → 6（词元表 + 切词器标记），6 → 7（加宽词元种类并清空标记） | 词元是派生数据，换切词器只需重建一次；迁移必须连续，所以第 6 版原样保留、第 7 版新增 |
| 检索计划 | 新增 `recall-query-plan/v2`（含线索字段、词典开关） | 旧版本语义不得原地替换，否则升级后重算旧回合会触发完整性故障 |
| 检索回执 | 新增 `recall-receipt/v2`（版本、命中词元、被上限截掉的条数、线索、词典水位） | 旧回执字段与封闭枚举不变，继续可校验 |
| 上下文复验 | 支持两代回执，各有各的规则 | 消费侧必须自己复算，不能信记忆层自报 |
| 部署备份集 | 记忆库版本号随迁移变化 | 既有行为：备份与二进制版本绑定，升级前后的备份不通用 |

## 4. 过程中发现并修正的错误（诚实清单）

1. **原生分词器 2.x 的文档与实物不符**——精确模式切成单字、词性全返回 `x`、实例上没有 `addWord`。实测发现后改选 WASM。
2. **`tokenize` 接口会崩**——用两个汉字调用抛 `memory access out of bounds`。排除出生产路径并加异常输入用例。
3. **角色目标视图是空的**——线索最初取自它，会静默永不触发。改为从已捕获来源读。
4. **纯词切分会漏**——`第三个` 合并成一个词后，查询 `三个` 匹配不到。据此确定"二元兜底 + 词加权"的混合方案，而不是用分词器替换 n-gram。
5. **我自己写的测试预期算错过多处**（词元数量、水位随夹具新增事件平移、诊断的零词元分支、词典加权的前提）。逐条修正测试而不是改实现来迁就错误预期。
6. **测量脚本一度把两个数字写成同一个来源**（纯关键词候选与含线索候选都取自同一次诊断），后来把纯关键词的对照改到**提问之前**测量。

## 5. 明确没做的事

- **世界内容里声明策略**：现在仍是应用层选项与试玩开关。世界怎么声明落在正在改动的世界包编译器与 Manifest 版本上，等那边落地再动，避免照着会变的靶子画靶心。
- **创作者显式加权**（作者标注"这条重要"）：我实测反复暴露的短板都在这里——没有结构关联的重要旧事，只有作者说"这条重要"才救得回来。需要新的决定。
- **跨平台一致**：只在 Windows / Node 24 验过。WASM 在"一份字节、全平台一致"上结构性地更强，但**仍需要在 Linux 上实跑一次才算证明**，已写进 ADR-0089 作为未完成项。
- **语义/向量检索**、模型生成的查询词、全知别名推断：各自需要新的决定。
