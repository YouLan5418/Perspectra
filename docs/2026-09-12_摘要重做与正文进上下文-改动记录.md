# 摘要重做与正文进上下文：改动记录

- 日期：2026-09-12
- 分支：`feat/summary-digest`（从 `feat/long-term-memory-compression` 的 `d228bc6` 新开）
- 目的：把"经历摘要"从"给基线做校验锚点的死数据"改造成"角色真的能读到的长期记忆"。

主 worktree（`codex/player-immediate-character-interactions`）与前一条记忆分支都没有被改动。

---

## 1. 起因：这套摘要机制四项都过时了

| 问题 | 改动前的实际状态 |
| --- | --- |
| 分组方式 | 每攒够 8 条记忆硬切一刀，不管场景、轮次、话题有没有断 |
| 正文内容 | 就是把那 8 条原文逐条抄下来，名字叫"提取式"，实际是复制 |
| 覆盖不全 | 不足 2 条的尾组被直接丢弃，所以**最新发生的事反而没有摘要** |
| 定位 | 它诞生时是给连续性基线当**校验锚点**用的（只留编号、序号、校验值），不是给模型读的 |

第 3 条有一个可见的后果：基线的来源末端与摘要覆盖末端之间始终有一条缝（实测基线到 668、摘要只到 624），缝里的内容既不在近期对话里，也不在任何摘要里。第 4 条正是 ADR-0068 当年明确定下的边界——只引用、不复制正文，理由是防止出现两套会互相漂移的摘要来源。

---

## 2. 第一块：摘要机制重做（不需要新 ADR）

ADR-0067 决策 8 限定 L1 必须是"确定性、提取式、单层、来源完整"。下面每一处都在这个范围内，所以属于实现升级。

### 2.1 分组改为按轮次切

`world.tick-advanced` 每轮恰好提交一次，所以它的序号就是"这一轮到哪结束"的耐久陈述。摘要现在以它为边界，每 **4 个完整轮次**成一组。

代价是每次追平多读一次事件范围——但它只过滤 Tick 事件，读的是"每轮一条"而不是整条日志。

### 2.2 尾组不再丢弃

只要有一轮就成组。最新的事第一次也有摘要，基线与摘要之间那条缝随之消失。

### 2.3 正文按轮次结构化

一条摘要有几个轮次就有几行，每行形如：

```
第 3 轮 ｜ character:player：我把备用钥匙放在门口第三个花盆下面了，你们别忘了。
        ｜ character:bob：今天雨下得真大。
```

轮次内同一个人说的话合并；`character:x said: ` 这个捕获样板换成 `：`，读起来是一段经历而不是一堆记录。

### 2.4 版本

- `schemaVersion` 保持 `memory-l1/v1`：字段结构没有变，变的只是算法，所以升的是 `algorithmId` → `deterministic-rollup-l1/v2`
- 注册表里的 `summaryPolicy` / `summarySource` 两个字符串**一个字都没动**。它们是全局精确锁（`world-spec.ts` 会逐字节比对），改了就拒绝所有已编译的世界包和试玩存档。它们是 v1 时代的锁定声明，实际算法由摘要记录自己的 `algorithmId` 标识；等 Manifest 支持世界级策略声明时再把它变成真正可选项

### 2.5 迁移

摘要和基线都是派生数据，所以两处都只是把失效的行丢掉：

- 记忆库 schema **8**：清空 `cognitive_memory_v2_summaries`（下次追平自动重建）
- 上下文库 schema **6**：清空 `continuity_checkpoints`（它按 identity + Hash 引用摘要，摘要分组一变就无法在同一 as-of 重建）

**没有**清空 Context Receipts 与 Provider 调用记录——它们描述的是已经发生过的轮次，不是可以重算的派生值。

---

## 3. 第二块：摘要正文进上下文（ADR-0091）

ADR 已从"待接受"落定为 **Accepted**。落地内容：

1. 正文随第 5 段"连续性"一起给模型，**段数仍是十二段**、顺序不变
2. 只取 **Tail 起点之前**的摘要——近期对话已经给了原文，同一件事说两遍没有价值；组装时会校验这一点，越界直接 fail-closed
3. 从最近往前取，受**档位派生**的预算约束（请求预算的八分之一：紧凑 4 KB / 标准 12 KB / 深档 24 KB）
4. **整条摘要要么全取要么不取**，绝不从中间截断；超预算时放弃的是更早的那些组
5. 属于第四级可裁剪内容，**先于**低相关召回、更先于整块对话被放弃；每次放弃逐来源记账为 `budget_trimmed`
6. 正文的编号、来源范围与校验值来自 Memory L1 本身，上下文层不会重新生成或改写它

## 4. 实测（60 轮，只读诊断）

| 观测项 | 改动前 | 改动后 |
| --- | --- | --- |
| 基线引用的摘要 | 1 条（覆盖 11–31） | 12 条（覆盖 11–655） |
| 摘要正文进入上下文 | 无（正文从未被使用） | **12 组 / 8275 字节** |
| 上下文总字节 | 35472 | 63955 |
| 最后一轮 Tail 里有那句重要事实吗 | 没有 | 没有（Tail 仍只保留最近 10 块） |
| 最后一轮召回段 | 空 | 空（提问与任何既往记忆都没有共同用词） |
| **那句重要事实到达模型了吗** | **否** | **是——只经由摘要正文** |

最后一行是这次改动的全部意义：在"没人提到、也没有结构关联"的情况下，角色第一次能记得更早发生过什么。

## 5. 必须守住的不变量

| 不变量 | 保障方式 |
| --- | --- |
| 分组落在真实轮次边界 | 单元测试造 6 轮、断言两组各覆盖哪些轮次 |
| 尾组一定保留 | 断言 6 轮得到 2 组；另一处断言单条记忆也有摘要 |
| 没有 Tick 事件的世界仍可用 | 现有 genesis 日志（无 Tick）断言归为一组 |
| 畸形 Tick 事件 fail-closed | 断言 `tick: 'soon'` 抛错 |
| 摘要在 Tail 之外 | 组装层校验越界与乱序，两者都 fail-closed |
| 超预算不截断 | 断言整组放弃、不出现半条正文 |
| 可重建 | 重启后重建得到同一批摘要与同一份上下文；分歧以完整性错误暴露 |
| 不写世界 | 摘要与正文都只改变"给模型看的内容"，世界事件日志与 head 不变 |
| 权限不变 | 摘要只来自该角色自己的 namespace |

## 6. 验证

- `corepack pnpm@11.7.0 check` 退出码 0。
- `test:coverage`：99 个生产文件四项指标全部 100%，逐文件门槛通过。
- 全量 104 个测试文件、1100+ 用例通过。
- 因行为变化而更新的既有测试：摘要断言（algorithmId、条数、格式）、两处 schema 版本改用常量而不是硬编码数字、基线摘要引用数、以及**缓存前缀**——第 5 段现在每轮随基线前移而变化，可复用的前缀从五段变为四段（协议、契约、世界锚点、角色锚点），这与独立评审当年的建议一致。

## 7. 明确不做（留给乙）

- **没有让摘要变小。** 去样板、合并同人、按轮次成行大概省两三成；真正的压缩（把八条经历写成一句话，十倍以上）必须替换 L1 算法本身，那要先改 ADR-0067 决策 8，并新建"模型产出写进耐久记录"的通道。
- 不做分层摘要（summary-of-summary）——ADR-0067 明确禁止。
- 摘要不按世界声明策略——等交互升级落地，和"关键词策略进世界内容"同一批。
- 不改裁剪优先级、Context Profile 数值、世界事件日志、记忆库存储结构。

node --import tsx tests/experiments/measure-context-compression.ts <新目录> 60
