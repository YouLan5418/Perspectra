## 1. 本次实现

`PlayerInputJobs` 在 World SQLite 内保存原文、Principal、输入顺序、幂等身份、状态及追加式状态证据。受理/claim/advance 使用短事务和 Writer Fence；同键异文拒绝，已终态结果不可重新解释。内存 Promise 队列只协调当前进程，不能替代数据库 FIFO。

`PlayerIntentCallStore` 在 Context v6 中单独标记 `purpose=player_intent`，使用 inputId 派生调用身份，不虚构 Round、participant 或 receipt ID。精确请求包含 Host Affordance、原文、冻结前缀及版本化 Profile；请求/响应既检查自身 Hash，也核对 World 已持久化证据。旧调用迁移保留原字段和 Hash，work_id 使用原 model_call_id，不拼接可能歧义的 round/participant 字符串。

`PlayerIntentWorker` 完成受理后准备、dispatch、响应验证、Round enqueue 和提交结果恢复。解释网络等待不持有 World 写事务；等待期间续租，失去租约立即中断当前处理。明确已 dispatch、无耐久响应的恢复进入 `timed_out_ambiguous`，不自动重发；迟响应只留审计 Hash，不能复活输入。

`WorldApplication.submitText` 根据 Manifest policy 区分旧对白入口与新解释入口。`/move`、`/act` 和结构化 submit 使用相同输入 FIFO，且不依赖解释 Provider。Provider 缺失、预算不足、非法 Profile、候选无效或超时均可返回耐久 clarification，不将原文自动作为对白。Profile 由调用方显式注入；本切片未选择生产 Provider 默认值。

`RoundCoordinator` 将完整玩家组排在 phase 0，逐步预裁定后再准备 NPC Context；ContextReceipt 绑定组 Hash 和参与者可见的逐步视图。整组 ActionId 纳入碰撞检查，玩家 proposal/response Hash 覆盖完整组；原有单 Action 返回字段继续对应首 Action，完整逐步结果保存在 Authority/Event 中。第二步失败不改写第一步返回结果；首步失败则停止后续步骤。

## 2. 持久化与维护边界

| 边界 | 当前行为 |
|---|---|
| Context 记录丢失，World 为 prepared | 从 World 准备证据重建未 dispatch 调用 |
| Context 丢失，World 已 dispatch/response_received | 歧义终态；禁止无证据重发 |
| Round 已 enqueue，但输入仍 validated | 使用相同幂等身份复用 Inbox，不重复 Round |
| World 已 COMMIT，但输入未 completed | 读取已提交结果并补齐输入终态，不重复 Tick |
| admission 改为 draining | 拒绝新输入；已受理 validated 输入经身份核对后仍可入 Round 排空 |
| fork、maintenance、archive | 未完成 Player Input 与未完成 Round 一样阻止越过屏障 |
| Logical v7 导入 | 不允许夹带 player_input_jobs；迁移为空输入表，不补造历史 |
| Logical v8 导入 | 传输输入记录并验证状态 Hash、输入 Hash 和确定性身份 |

当前 Logical 输入校验不是完整状态机证据、Round 关联及 Context 跨库闭包验证；不能以一次 round-trip 宣称这部分全部完成。

## 5. 未关闭项与下一步

1. **C3 Host 接入**：当前由 `submitText`/`submit` 触发恢复；`processNextBranchWork` 尚未消费未完成 Player Input。必须接入启动重扫、调度 quantum 和停止/排空流程，不能把“用户再次提交才恢复”称为完整后台恢复。
2. **C3 产品入口**：Operations CLI/Web 的生产 Provider/Profile 配置与适配器尚未接通；当前只提供 Application 注入端口。Profile、调用实际成本/预算账本、明确未发送的超时分类及用户取消/澄清关联仍需收敛。
3. **C3/C4 Authority**：补齐受理时 Manifest/head 记录、输入状态证据闭包、Logical 输入与 Round 的关联校验，以及已完成输入的 backup/restore、fork/as-of、Snapshot/Full Replay 专项对照。
4. **C4 语义与真实模型**：fixture 手工给出正确 source spans，不证明模型不会将“她没有挣脱/永远服从”等叙述误标为 speech。保持结构性动作约束，不以关键词、Prompt 承诺或手工 fixture 替代语义门禁与真实 Provider 数据。
5. **原有遗留**：C0 预声明真实模型矩阵、C1 lifecycle 自动结束关系的端到端路径、新 Pack 示例及 Creator Runbook、C4 长程试玩仍独立保留。
