## 2. 关键设计选择

**编译输入是数据，不是实现。** 编译只需要锁与定义描述，不需要规则/效果函数，因此新增 `InteractionPackageDescription` 作为 `InteractionPackageImplementation` 的数据投影。这让 `world-pack` 不新增任何依赖边（仍只依赖 contracts/kernel/application），而不是让编译工具链去 import 运行时包。

**目录不含地址。** `InteractionCatalogV3` 是世界选择去掉 `WorldAddress` 的形态，因此一份编译产物可以被多个地址打开而不必重编；地址在 Host 打开世界时绑定。

**v5 的 Manifest 适配显式失败。** `adaptCompiledWorldPack` 遇到 `worldpack/v5` 直接抛出，而不是落回 v1 编译器把 v5 Pack 当旧格式解释。Manifest v10 绑定与生产入口按规格第 7 章由 I3/I4 接通。

**配置只能收窄。** 作者 `config` 逐字段按定义自己的 `bindingConfigSchema` 校验（闭合字段、boolean、安全整数上下限、UTF-8 上限与可选枚举），作者无法借 config 扩大能力。

## 4. 验证范围

两个新测试文件二十项：

- **编译与哈希**：示例源编译为 v5，包锁与三个定义的 `definitionHash`/`implementationHash` 由安装描述派生；规范化字节可写回并通过 `verifyCompiledWorldPackV5`。
- **只改内容**：只改 `interactionBindings` 就改变目录与 packHash，而物品的身份字段不变。
- **拒绝面**：包未安装、定义未提供、定义版本不匹配、重复 bindingId、config 含未声明字段、目标 kind 与定义不符、包/定义/绑定超限、目录版本不符、V5 清单版本不符与文件数超限、实体/角色文件版本不符与数量超限、选择文件超限与重复。
- **篡改面**：手改目录后重算哈希仍被 `validateInteractionTargets` 拦下（未知目标、目录外定义、relation 目标）；字符目标合法时通过；包哈希不匹配被拒。
- **跨包一致性**：编译产物直接喂给 I1 的 `InteractionRegistry.freeze()` 并成功裁定一次 take，证明**编译与激活读同一份定义描述**。
- **回退安全**：v5 Pack 的 `adaptCompiledWorldPack` 抛错；v1/v2/v3/v4 路径未改。

## 6. 已知取舍

**配置校验在 world-pack 与 interaction-runtime 各有一份实现，读的是同一份 `bindingConfigSchema`。** 运行时的 `parameters()` 是激活期权威，world-pack 的 `bindingConfig()` 是编译期诊断。两份实现存在漂移风险，本轮用第 4 节的跨包一致性测试把两侧钉在同一个例子上：编译接受的目录必须能被 `freeze()` 接受。按规格"模型 Schema 与 Host 验证从同一结构派生"的要求，I2-c 应把这段校验收敛到 contracts 一份实现，本轮不为此重构 I1。

**`verifyCompiledWorldPackV5` 会先把内容按 V1/V2 形状解析一次再按 V2/V3 形状重解析。** 这是为了让 V4 信封解析器原样复用而不改动它；代价是目标文件被校验两遍，失败信息可能来自其中任一遍。
