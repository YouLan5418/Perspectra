## 2. 逐条处置

### P1 模型请求 Schema 拒绝 Host 已支持的 performance

**复现**：定义声明了可用 cue 时，一个带合法表现的请求被 Host 接受，却被 `createInteractionRequestSchema()` 拒绝。

**根因**：`anyOf` 分支写死了 `additionalProperties: false` 与四项 `properties`，表现字段立约时新增了 `performance`，Schema 没有跟着走。

**修法**：视图新增 `performances`（按定义身份排序的接受清单），Schema 每个分支据此声明 `performance` 字段——`independent`/`onSuccess` 两个数组，各自 `enum` 为该位置允许的 cue、`uniqueItems: true`。**无条件下声明**，因为 Host 对空策略也接受空对 `{independent:[],onSuccess:[]}`；省略字段会让 Schema 拒绝一个 Host 允许的请求。

**修复过程中发现的次生问题**：表达"该位置不允许任何 cue"时我最初用了 `enum: []`，而 draft-07 的元 Schema 要求 `enum` 至少一项，Ajv 直接拒绝编译整个 Schema。改用 `maxItems: 0`，语义相同且合法。

**回归测试**：`declares the accepted manifestation instead of forbidding the field`。覆盖接受合法表现、拒绝策略外 cue、跨列表重复被 Schema 的 `uniqueItems` 拦下、空策略只接受空对，以及位置受限的 cue 只出现在被声明的那一列。

### P2 角色参数枚举忽略动作声明的参数限制

**复现**：定义把 `recipientId` 的 `values` 限定为 Bob，视图仍向模型提供 Alice；Schema 接受该选项，Host 随后拒绝。

**根因**：`argumentCombinations()` 对承载角色的字符串字段直接取"全部已授权同类对象"，没有与字段自身的 `values`（声明枚举）和 `maxBytes`（UTF-8 上限）求交。

**修法**：角色只决定候选来源，字段自己的契约仍然生效。域现在是"已授权同类目标 ∩ 字段枚举 ∩ 字节上限"。

**回归测试**：`offers only recipients the definition argument contract itself allows`——同一个世界里的 Alice 已授权且在附近，但因为字段只声明 Bob，视图只提供 Bob；且用 Alice 构造的请求被 Schema 拒绝。

### P3 动作失败时丢失独立表现

**复现**：规则拒绝时 `performance` 恒为 `null`，一次失败的拿起会把合法的独立微笑一起抹掉。

**根因**：`resolve()` 在 `#plan()` 返回拒绝时直接 `finish(plan)`，用了默认的 `null`。

**修法**：拒绝时保留 `independent`、清空 `onSuccess`。

**这条不是修一个 bug，而是修一处语义冲突。** 仓库里既有的 `stepManifestation()`（`packages/application/src/action-groups.ts:23`）在动作未被接受时就是这样做的：

```ts
const codes = [...value.independent, ...(accepted ? value.onSuccess : [])]
```

也就是说"动作失败仍保留独立表现、只取消 onSuccess"是**既有冻结语义**，只是交互路径没有照做。规格 §2 那句"independent 表示本次尝试中独立成立的自我表现"也是这个意思——它属于"尝试"本身。

**回归测试**：`keeps independent expression when the action fails and cancels only onSuccess`——同一份表现先在一个可成功的世界上被完整接受，再在一个不可成功的世界上只保留 `independent`；只提交 `onSuccess` 的表现被拒时 `performance` 为 `null`。

### P4 跨列表去重掩盖了列表内部的非法重复

**复现**：`{independent:["smile"], onSuccess:["smile","smile"]}` 被接受。

**根因**：先做跨列表折叠（把 `onSuccess` 里与 `independent` 重复的项滤掉），再检查唯一性。上面两项都在 `independent` 里，于是被一起滤掉，唯一性检查看不到它们。

**修法**：先分别校验两个列表各自的唯一性（冻结的步骤 Schema 对每个列表都是 `uniqueItems: true`），**再**做跨列表折叠。折叠语义本身不变。

**回归测试**：`refuses a repeat inside one list before collapsing the cross-list restatement`。

### P5 编译器与运行时的配置大小约束不一致

**复现**：四个各 1024 字节上限的字段，各字段都合法，编码后 5161 字节；编译通过，运行时 `freeze()` 以 4096 字节上限拒绝。

**根因**：world-pack 的 `bindingConfig()` 只逐字段校验，运行时的 `freeze()` 另外限制整段编码大小。

**修法**：编译器补上同一约束（`MAX_INTERACTION_CONFIG_BYTES = 4096`），在编译阶段就以 `PACK_LIMIT_EXCEEDED` 报出。

**回归测试**：`reports the encoded config budget the runtime enforces, not only per-field bounds`。

**这条是 §6 那个已知重复的直接代价。** 我在 I2-a 记录里说过应把配置校验收敛到 contracts 一份实现，当时没有做；现在同一份约束在两侧各写了一遍，这次的漏配就是它造成的。**收敛仍未做**，本轮只是把两侧对齐。
