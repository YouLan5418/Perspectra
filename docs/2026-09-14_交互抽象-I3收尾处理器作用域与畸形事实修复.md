## 1. 两处修复

**D1 畸形事实不再生成畸形事件。** `contact:end-on-move` 原先把 `entry.state.initiatorId` 直接当作 `endedByCharacterId`。当该字段不是字符串时，`outOfReach()` 正确判定为不可达，事件却携带一个非字符串的参与者——而冻结的关系事件词汇要求它是字符串，运行时不校验事件 data 形状，所以畸形事件会通过。

现在：参与者可用时用它；只有一方可用时用另一方；**两方都不可用时整条关系不产出事件**。回归测试断言每个产出的结束事件都署名一个字符串参与者，且两方都不可读时输出为空。

**Q5 处理器必须声明自己能消费什么。** 原先 `end-on-move` 扫描快照里**每一条**活跃关系并结束离开可达范围的——正是 V0.3 §7 明令禁止的"扫描全部 active relation，再按同地点结束"。ADR-0094 §6 同样写着"接触处理器不能消费任意活跃关系"。

现在处理器声明 `consumes: readonly InteractionRef[]`（可消费的定义）。fold 据此把交给它的快照**裁剪**到"由这些定义创建的关系实例"，并校验输出：任何 `character.relation-ended` 若指向裁剪后集合之外的关系，整组失败。

## 2. 两处实现细节值得记下

**关系实例必须携带创建它的定义。** 裁剪按 `state.interactionId` 判定，而关系开始事件本来就带 `interactionId`（`contact-start` 写的是 `context.definition.id`），所以 Host 从事件重建状态时天然可得。**这不是新增要求，是把已有字段用在判定上。**

**按定义 id 比较，不按 `id@version`。** 关系实例记录的是创建它的定义 id，不含版本；而实例存在本身就意味着 Host 已经准入过那个精确的编译定义。版本比对在这里既无信息也无处取。

## 3. 验证范围

新增/改动 3 项（接触套件 15、生命周期 10，交互用例合计 **90 → 91**）：

- 畸形关系（一方非字符串参与者）署名另一方；两方都不可读时不产出事件。
- 声明外的关系实例**不进入**处理器可见的快照（用一条由别的定义创建的关系验证）。
- 声明内的关系实例正常进入。
- 处理器为裁剪范围外的关系产出结束事件 → 整组失败。

## 4. 与 V0.3 §10 的关系

V0.3 §10 把「I3 收尾」列为独立阶段，Gate 是"接触处理器不误处理通信；畸形事实不生成畸形事件"。本轮把这两条对应的**机制**落地并验证：

- "畸形事实不生成畸形事件"**已完全满足**，有直接断言。
- "接触处理器不误处理通信"要求的**声明式作用域**已就位；但通信本身尚不存在，所以这条目前是用"由别的定义创建的关系"作为替身验证的。真正的通信场景要等 I4 前置 fixture。

**I3 Gate 的其余状态不变：**「move 无具体接触名分支」仍不成立（`rulebook.ts` 未动、应用层未接 `fold()`），§6.2 退出选项保留与容量失败仍未实现。
