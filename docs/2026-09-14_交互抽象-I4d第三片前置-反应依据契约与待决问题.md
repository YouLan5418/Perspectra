## 1. 现状：这半边是空白

`roleClass`、`reaction-evidence`、`ReactionEvidence` 这三个词在生产代码里**一次都没有出现**（`packages/*/src` 全量检索为空）。今天存在的是更早的结构：

```ts
// round-coordinator.ts
const reactionStimuli: {
  sourceEventOrdinal: number
  observationId: string
  observerId: CharacterId
  actorId: CharacterId
  sourceRole: 'player' | RoundParticipantRole
}[] = []
```

也就是说：规格 §5 要求的**新证据结构、roleClass 分级、排序规则、耐久 Observation 前置**，一件都还没做。Authority 6 那一片只让**已有的**证据结构落进了耐久记录。

## 2. 规格要求（逐条拆开）

| 要求 | 现状 |
|---|---|
| 证据结构固定为 `sourceEventRef`、`observationId`、`observerCharacterId`、`actionId`、`definitionRef` 或专用入口身份、`roleClass` | 只有一个 `sourceEventOrdinal` 与 `observationId`；没有 `actionId`、`definitionRef`、`roleClass` |
| `roleClass ∈ {self, direct, addressee, witness}` | 不存在 |
| 每个观察者必须有**耐久 Observation 来源**，不凭角色槽直接生成私有刺激 | 刺激确实伴随 `observation.upsert` 产生，但"必须先有耐久来源"没有作为前置被校验 |
| 仅观察到**失败尝试**的旁观者不得被标为效果 `direct`；失败是否可观察由动作观察策略决定 | 不存在（今天的刺激只从接受的动作产生，失败尝试根本不产生刺激） |
| 新 `responsive/v2` 按 direct → addressee → witness 排序，再按角色 ID、来源事件序、jobId | 不存在；今天是既有的 v1 顺序 |
| `self` 不自动派生自我追加调用 | 不存在 |
| 预算仍是 3 waves / 8 calls / 每角色 2 calls，不足稳定跳过，不强制回复 | v1 已有，需在 v2 保持**逐字节相同** |
| 旧 `responsive/v1` 的候选顺序、预算 Hash、恢复路径全部保留 | v1 今天在用，必须一动不改 |

## 3. 已裁定与仍需判断的问题

**2026-09-14 用户已裁定两处（决定契约形状的那两处）：**

| 问题 | 裁定 | 落点 |
|---|---|---|
| Q1 `direct` 与 `addressee` 的判据 | **效果落在谁身上，谁算 `direct`**；只是被点名而未被触及的算 `addressee`；两者同时成立时 `direct` 优先 | 与"仅观察到失败尝试的旁观者不得标为 `direct`"自洽：效果没落到谁身上，谁就不是 `direct` |
| Q4 `responsive/v2` 由谁选择 | **写在世界的作者文件里**（`reaction.json` 的 `profile`），编译进 Manifest | 与 ADR-0088 已记在案的原则一致："停用必须是世界内容/Manifest 的显式选择，不是运行时 Host 开关" |

**仍未判断的两处：**

**Q1 「direct」与「addressee」怎么分？**
规格把两者分开，但没说判据。两种读法：(a) `direct` = 动作**效果**直接落在其身（如被递交的一方）；`addressee` = 被动作**言语/意图**指名（如 `speak` 的 `addresseeIds`）。(b) 反过来。我倾向 (a)——它与"仅观察到失败尝试的旁观者不得被标为 direct"那句自洽：效果没落到谁身上，谁就不是 direct。

**Q2 没有定义引用的专用入口身份是什么？**
证据里 `definitionRef` 的位置写着"或专用入口身份"。冻结 `interact@2` 请求已有 `definitionRef`；需要专用身份的是 `speak`、`move` 等不由交互定义裁定的入口。候选：用固定动作身份（如 `actionType@version`）或入口策略标记。这会影响证据哈希，所以要一次定对。

**Q3 失败尝试的可观察性——本文第一版写错了，此处更正。**

初稿写的是"失败尝试的刺激今天根本不产生"。**这是错的。** 核查代码后的事实：

- 失败**已经**是世界事实：`rejectRulebookResolution` 产出 `action.rejected` 事件（`rulebook.ts`），它在冻结事件词汇表里（`world-spec.ts`），而且 `character-view.ts` 已经在读它。
- 失败**已经**产生观察与刺激：协调器的观察/刺激循环**没有** `accepted` 守卫，观察内容是 `status: skipped ? 'skipped' : resolution.status`——`rejected` 也会为每个观察者生成一条观察并推入反应刺激。

所以 v2 在这一项上不是"新增能力"，而是三件整理工作：

1. 把这条行为从**硬编码**变成**声明出来的策略**（规格："失败是否可观察由动作观察策略决定"）。
2. 给它加**角色分级**与那条约束：**仅观察到失败尝试的旁观者不得被标为 `direct`**——这条今天无从谈起，因为今天根本没有 `roleClass`。
3. 提供**可关闭**的抑制能力——这才是真正新增的东西。

**用户裁定：默认开启。** 也就是默认行为与今天一致（失败可被旁观者察觉），世界可以显式关掉。

**Q4 v2 由谁选择？**
两种：(a) Manifest 的 `reactionPolicy.profile` 写 `responsive/v2`，v10 世界由编译器或作者选择；(b) Host 运行时开关。ADR-0088 的原则是"停用必须是世界内容/Manifest 的显式选择，不是运行时 Host 开关"，所以我倾向前者——但那就意味着 `worldpack-reaction/v1` 的 `profile` 取值要加一档，并且 `reaction-cycle.ts` 现在硬性要求 `responsive/v1` 的地方要按档案放宽。

## 4. 实施形状（Q1/Q4 已定，可直接开工）

1. `contracts`：`reaction-evidence/v1` 的闭合结构 + `ReactionRoleClass` 联合；`responsive/v2` 档案常量。
2. `round-coordinator`：刺激按观察者带 roleClass 与证据；耐久 Observation 先行；失败尝试按观察策略决定是否成为刺激。
   - `direct` 由受锁效果／专用入口的反应依据策略声明受影响角色槽，Host 将声明解析到实际角色，并核对该角色具有对应的耐久 Observation；不能因事件任意字段出现角色 ID 就推断受影响。`addressee` 取专用发言入口的授权收件人；`self` 取观察者等于 actor；其余为 `witness`。运行时只认识注册策略和角色槽，不认识具体定义名。
   - 失败尝试：**默认可观察**（与今天的硬编码行为一致），由声明出来的观察策略可关；其旁观者**不得**为 `direct`；事实层不受影响（见 §5）。
3. `reaction-cycle` / `reaction-scheduler`：v2 的排序（roleClass → 角色 ID → 来源事件序 → jobId）与 v1 的保留并存；周期策略校验按档案分支；`responsive/v2` 作为 Manifest 显式选择（Q4 的裁定）在 `worldpack-reaction/v1` 与 `parseReactionPolicy` 各加一档。
4. 预算与哈希：v1 逐字节不变；v2 的预算 Hash 单独一条。
5. 用例：同一场景下 v1 与 v2 的候选顺序可对照；"见证失败尝试者不是 direct"；"没有耐久 Observation 就不产生刺激"；"self 不自我追加调用"；v1 的既有黄金不动。

**规模判断：** 与 I4-b + I4-c 两片相加相当。它没有更小的自洽切片——只落契约类型会变成没有生产者的死代码，那正是这个项目一路在避免的东西。Q3 与 Q2 仍会在实现中逼出小决定（失败尝试的观察策略从哪读、玩家动作在证据里的身份取什么），但两者的取值范围已被上面的裁定收窄，可以在实现时就地选定并记录。

## 5. 一条必须写明的边界：开关只影响"谁知道"，不影响"发生了什么"

"关闭失败的可观察性"**不等于**截断失败、让它不进事实。这条边界不是措辞问题：

| 层 | 关闭时 |
|---|---|
| World Event Log | **照常写入** `action.rejected`。世界事实权威不受观察策略影响——这正是"Session、Projection、Memory 和 Telemetry 都不能反写或替代世界事实"那条约束的同一面 |
| Observation | 这条事实**不生成**观察：旁观者的角色视角里不出现它 |
| Reaction | 旁观者**不因此获得反应资格**；提交该动作的角色自己仍然知道自己失败了 |

开关管的是**知情范围**，不是**事实存废**。实现上这一点很难写错：事件集合来自 `resolution.events`，它本来就含 `action.rejected`，与观察循环是两条独立的写入路径。
