## 1. 补的是哪一条

I2-d 把 `interaction-performance/v1` 做成受锁注册件，并明确"Host 侧把被接受的表现转成观察事实（`character.manifested` 路径）属 I3/I4"。I4-b 到 I4-d 都没有接这条线：冻结请求里出现 `performance` 一律被入口拒绝，理由是（代码注释原文）"Host 还欠着把被接受的表现转成观察事实这一步，此刻接受就等于声称发生了没人记录的事"。

这一片把欠的那一步补上。运行时的另一半其实已经完整：它按定义的受锁策略收窄提交的 cues，接受时把完整表现交出来、拒绝时只保留"无论成败都成立"的独立表现，并且**效果执行上下文不含表现**（所以同一动作带不带表现在世界状态上逐字节相同）。

## 2. 实现

| 位置 | 改动 |
|---|---|
| [kernel/frozen-interactions.ts](../packages/kernel/src/frozen-interactions.ts) | 入口接受可选的 `performance`（与四个既有键并列），并在此判定"交互步骤**能不能**带这组 cue"：闭集词表、排除自带动作的声音/步态 cue、同一列表内不得重复；不合规即 `INVALID_INTERACTION_PARAMETERS`（不把运行时异常留给调用方） |
| 同上 | 取景步骤落地：`adjudication.performance` 经 `stepManifestation` 变成提案，再由 `resolveManifestation` 产出 `character.manifested`，事件追加在定义自身的事件之后 |
| 同上 | 冻结上下文新增 `roundId`：表现是回合作用域的事实，没有回合而接受了 cue 直接抛 `TypeError`（Host 接线错误，不是模型输入） |
| [application](../packages/application/src/round-coordinator.ts)、[reaction-scheduler](../packages/application/src/reaction-scheduler.ts) | 两处解析都带上自己的 `roundId` |
| [interaction-runtime/registry.ts](../packages/interaction-runtime/src/registry.ts) | 策略拒绝从**抛异常**改为**拒绝提案**（`PERFORMANCE_NOT_ACCEPTED`）：调用方无从知道定义的受锁策略，一条它不接受的表现是坏提案而不是 Host 故障，计划也不能在没人同意的表现上运行 |
| [interactions-basic](../packages/interactions-basic/src/basic.ts) | 新增 `base:expressive`：闭集词表减去声音/步态后的五个 cue（`smile`/`frown`/`nod`/`shake_head`/`avert_gaze`），placement `both`。`base:give` 用它——递交是首批里唯一真正社会性的动作；take/drop 仍是状态转移、接触本身就是表达，两者继续 `base:no-performance` |

**一处单一来源的搬迁**：`stepManifestation`（步骤 cue → 提案）从 application 移到 kernel 的 `manifestation.ts`，application 改为再导出。冻结路径与动作组路径从此读同一份映射，不会对同一种表达给出两种描述。

## 3. 语义

- **接受时**：`independent` 与 `onSuccess` 都在提案里；事实记录 cue 的顺序与描述。
- **拒绝时**：只有 `independent` 成立（"尝试本身的表现"），`onSuccess` 被取消——只在成功时说的话，不能被一次失败的尝试认领。
- **空步骤**：`{independent: [], onSuccess: []}` 与"没写"等价（动作组路径的既有读法），不构成坏提案。
- **效果不受影响**：带表现与不带表现在 `entity.transferred` 等效果事件上逐字段相同；差别只有多出的事实与其在观察内容里的 `manifestation`。

## 4. 用例与证伪

- **端到端**（生产入口，两次运行对比）：玩家把杯子递给同行者并说"皱眉"+"微笑"，落库恰好一条 `character.manifested`，两个 cue 的描述都在；旁观者的观察内容带上 `manifestation`；同一递交不带表现时的**效果载荷逐字段相同**。
- **拒绝语义**（解析器层）：递给快照里不存在的收件人 → 拒绝，且事件序列恰为 `['action.rejected', 'character.manifested']`，cue 只剩"点了点头"。
- **入口**：九种不合规步骤（声音/步态、未知 cue、同列表重复、非数组、缺键、多键）一律 `INVALID_INTERACTION_PARAMETERS`；空步骤被接受；策略不接受的合规步骤是 `PERFORMANCE_NOT_ACCEPTED` 而不是异常。
- **缺回合**：带 cue 的步骤在没有 `roundId` 的上下文里明确报错，不落一条对着空回合的事实。

四条回退全部变红：R-1 把表现事件丢弃、R-2 策略拒绝改回抛异常、R-3 入口不再拦声音/步态 cue、R-4 递交回到 `no-performance`。
