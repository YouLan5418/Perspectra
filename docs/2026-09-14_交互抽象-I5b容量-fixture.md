## 1. 补的是哪一条

I5-a 与 I5-b 第一片的记录都写着同一句：各上限**只有单点测试**（fold 累计 64、参数域、绑定数等），没有成规模的容量 fixture，也没有"上限 + 超限行为"的成对语义。单点测试能证明某个数字被拒绝，但不能证明**恰好在上限的内容是合法的**——而后者才是作者依赖的那一半：一个被静默裁掉的列表同样会让单点测试变绿。

## 2. 做法：在强制执行它的那一层测

新增 [tests/frozen-capacity.integration.test.ts](../tests/frozen-capacity.integration.test.ts)，每条上限两问：**边界上通过**、**多一个单位确定性失败**。全部用纯函数入口，不经世界、不经数据库——上限是冻结契约的性质，在它被强制的地方测最省也最准。

| 上限 | 在哪一层强制 | 边界通过 / 越界失败 |
|---|---|---|
| 每世界启用包 32 | 作者源 `parseWorldPackInteractionsSource` | 32 / 33 → `PACK_LIMIT_EXCEEDED at most 32 packages` |
| 选中定义 128 | 同上 | 128 / 129 |
| 关系绑定 4096 | 同上 | 4096 / 4097 |
| 单 config 4096 B | 同上（见 §3） | 4085 字符（含 11 字节信封恰为 4096）/ 加一字节 |
| 每定义角色槽 8 | `registry.install` | 8 / 9 → `array outside limits` |
| 参数字段 8 / config 字段 8 | 同上 | 各 8 / 9 |
| 前置规则 16 | 同上 | 16 / 17 |
| 依赖引用 64 | 同上 | 64 / 65 |
| 生命周期处理器 16（每定义） | 同上 | 16 / 17 |
| 每绑定参数组合 64 | `view()`（组合在选项枚举时真正展开） | 8×8=64 通过 / 9×8=72 → `argument domain exceeds the binding budget` |
| 每动作主效果事件 16 | `resolve()` | 16 条通过 / 17 条失败 |
| fold 累计事件 64 | `resolve()` 的 fold | 效果 16 + 三步各 16 = 64 通过 / 第四步 → `lifecycle fold exceeds the total event budget` |

选项预算（128）不走"拒绝"路线：普通选项按设计裁剪并由 `candidateCount` 报出真实数量，**必须保留的退出选项**超预算才是失败——后者由 I5-b 第一片的用例覆盖（§6.2 的退出选项优先保留）。

## 3. 它立刻找到的一处不对称（已修）

容量 fixture 第一次运行就红了：**关系绑定的 config 在编译期没有 4096 字节上界**，而实体/角色绑定有。运行时对两者都查（`binding config exceeds budget`），于是结果是"包编译通过、freeze 才拒绝"——正是编译器自己那条注释说不要发生的事：

> The runtime also bounds the whole encoded config, not just each field, so the compiler has to report the same limit here instead of letting a pack compile into something freeze() refuses.

修法是在关系绑定的解析里补同一检查（[world-pack/schema.ts](../packages/world-pack/src/schema.ts)），错误类型与措辞与实体绑定一致。这正是容量 fixture 的价值：不对称只在**贴着边界**的时候才显形。

## 4. 证伪

三条代表性的上限放宽后，对应的越界用例当场变红：

| 回退 | 结果 |
|---|---|
| R-A 去掉刚补的关系 config 上界 | 红：`takes a 4096-byte config and refuses one byte more` |
| R-B 把 `MAX_INTERACTION_DEFINITIONS` 改成 129 | 红：`takes 128 selected definitions and refuses 129` |
| R-C 把 `MAXIMUM_ARGUMENT_COMBINATIONS` 改成 72 | 红：`takes 64 argument combinations on one binding and refuses 65` |

## 5. 仍未做

| 项 | 说明 |
|---|---|
| 世界级 fold 计划 256 次调用 | 该上限是**世界**计划（所有定义的处理器并集）的长度，要越过它需要 ≥17 个定义、跨 ≥5 个包（每包处理器 ≤64）。成对证据（256 通过 / 257 失败）需要一份多包夹具，尚未做 |
| 上限的**规模**证据 | 本片证明的是边界语义；"4096 条绑定的编译耗时"这类性能数字不在 §6 的分工内，也没有阈值可依 |
| I5-d 真实模型用例 | 需要真实 provider（外部条件） |
