## 1. 这一片要回答什么

规格 §8 要求 I5 有"冻结真实模型用例"并**单独报告**：到此为止 v10 的模型协议只在**测试夹具**里验证过——夹具里的"模型"是我写的 `async () => ({...})`，它当然知道该填什么形状。真实模型是否也能在冻结世界下行动，此前无人验证。

门禁的做法是**把生产的 `exactProviderRequest` 原样交给真实端点**：上下文是 Host 组装的那份，工具契约是 v7 的那份，模型回来的载荷**原样**交给世界自己的校验器与裁决。它不是打分，只回答一件事——真实模型拿到冻结词表与每条定义接受的 cue 之后，能不能用 `interact@2` 行动、并让它的表现落成事实。

运行方式（密钥只走环境变量，不落任何文件）：

```
DEEPSEEK_API_KEY=… node --import tsx tests/experiments/v10-provider-gate.ts --model deepseek-flash
```

## 2. 结果

世界是示例包 `hand-in-hand`（Manifest v10、`responsive/v2`），场景是玩家把共用伞交给同行者并请它转交给等车的人、递的时候笑一下。

| 观测 | 值 |
|---|---|
| 协议 | `submit_actions/v7` over Manifest v10（上下文工具版本与 v7 一致） |
| 真实调用 | 4 次，4 次都返回 tool_calls（无超时、无 HTTP 错误） |
| **被接受的冻结步骤** | **4 次**——模型提出的 `interact@2` 被世界按定义裁决为 accepted |
| **落成事实的表现** | 1 条 `character.manifested`，cues 为「摇了摇头」「点了点头」 |
| 物品移动 | 4 次 `entity.transferred`（模型每轮把伞递给它正在对话的一方） |
| 关系结束 | 0 |

两个 cue **都在世界给出的接受清单里**（`base:expressive` 的五条），也就是说模型是在被告知的范围内选，而不是猜中。

**范围限定（写清楚，免得被当成分数）**：一个模型、一个世界、一次运行；它的价值是"协议可被真实模型驱动"这一条证据，以及下面两处前置条件。它不是基准，也不该进自动套件。

## 3. 门禁找出的前置条件之一：Host 的 `tools` 不是可绑定的 Schema

第一次运行 4 次调用全部返回，但**三次答案的形状各不相同、都不是工具载荷**：

```jsonc
// 1) 把 group 塞进字符串，且用 actionType/actionVersion/text 代替完整动作
{"actionGroup": "{\"version\":\"bounded-action-group/v2\",\"actions\":[{\"actionType\":\"speak\",…}]}"}
// 2) 按动作类型嵌套（speak/interact 各一个子对象），没有 actionId/actorId/parameters
{"actionGroup": {"actions": [{"actionType":"speak","speak":{…}}, {"actionType":"interact","interact":{…}}]}}
// 3) 平铺但同样缺 actionId/actorId/parameters
{"actions": [{"actionType":"speak","text":"嗯。","manifestation":{…}}]}
```

原因不在模型：Host 交出来的 `tools` 是**契约描述**（`type: object` 加上动作组策略与各动作的注解），不是带 `properties` 的 JSON Schema。把它塞进端点的 `tools[].function.parameters`，模型拿不到任何可绑定的结构，只能自己编。

仓库里为 v4/v5 词表**有过**这种 Schema（`tests/experiments/compact-context.ts` 的 `externalActionSchemaFor`），但**从没给冻结词表造过**。门禁现在自己造一份（`frozenWireSchema`）：从上下文里提供的**选项**与**每条定义的接受清单**派生——因此模型能选的 `targetRef/bindingId/definitionRef` 组合恰好是世界的选项，cue 的枚举恰好是定义接受的那些。造完再跑，模型立刻给出合法载荷（§2）。

**这条不是世界侧的缺口**，但它是一个真实集成前置：任何真实 provider 适配器都必须做这件事，而仓库此前只为旧词表做过。

## 4. 前置条件之二：上下文里有一个端点不认的 role

Host 组装的上下文里有一段的 `role` 是 `developer`（角色控制器契约）。DeepSeek 端点只接受 `system`/`user`/`assistant`/`tool`，原样发送会被 400 拒绝：

> Failed to deserialize the JSON body into the target type: messages[1].role: unknown variant `developer`

门禁里映射为 `system`（**只改 wire 形状，不改给模型看的内容**，代码注释写明了这一点）。真实适配器同样需要这个映射。

## 5. 仍然没有的

| 项 | 说明 |
|---|---|
| 生产 provider 适配器 | 门禁把 wire 映射写在实验里。把它做成生产件（含 v7 的 JSON Schema 与 role 映射）属于 Host 集成，不在本片范围，也没有被 Gate 要求 |
| 反应波里的真实模型 | 门禁只驱动根回合；反应回合的真实模型调用所需的上下文与预算另有其面（`maxActionsPerCall`、刺激包），未取样 |
| Player Intent 的真实模型 | 意图协议是另一条契约（`player-intent-candidate/v1` → 候选 → Host 绑定），未取样 |
| 多模型 / 多次运行 | 一次运行不是分布；换模型或重复运行需要再次付费调用 |

## 6. 验证结果

- `corepack pnpm@11.7.0 check` 退出码 **0**：主用例 **1412** 项 / 128 个文件、崩溃套件 **55** 项、生产 `src` 逐文件四项 **100%**。
- 新文件是**付费/手动实验**，无 `.test.ts` 后缀，不在 vitest 套件内；`tsc` 与 lint 覆盖它。
- 密钥只来自 `DEEPSEEK_API_KEY` 环境变量：仓库内任何文件（含 `.tmp/` 证据）都不含它；证据目录被 `.gitignore` 覆盖。
- 未使用 `--update`；未改任何生产代码（本片只有实验文件）。

**（2026-09-15 补充，不改本片结论）** 本片当时不得不把「Host 的 `tools` 描述 → 端点能绑定的 wire schema」这段映射写在门禁脚本里。它现在是生产包 `@harness-world/provider-chat`，门禁脚本已改为调用它——所以这条门禁验的是生产代码，而不是一份手工保持同步的副本。那次推广还修掉了脚本版映射的两个缺陷（漏掉 `move`、无选项时渲染出非法 schema `oneOf: []`）；详见 [I7 记录](2026-09-15_交互抽象-I7真实模型试玩线四步.md)。
