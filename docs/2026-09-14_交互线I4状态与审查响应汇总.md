## 2. 审查发现 1：持久化边界不核对证据与档案（成立，已修）

### 问题

[reaction-cycle.ts](../packages/store-sqlite/src/reaction-cycle.ts) 的首波与延续两处准备只核对刺激引用的 Observation，随后把 `evidence` 原样接收并纳入 `stimulusEntryHash`；读回只重算哈希。于是同时接受过：

- 一个 `responsive/v2` 周期，候选与刺激**都没有** `roleClass`/`evidence`；
- 一个 `responsive/v1` 周期，刺激带着观察者、Observation、事件序号互相矛盾、类别冲突的证据。

两者都会进入耐久哈希：**"为什么这个角色被称重"可以成为自洽但语义错误的权威记录**。

### 修法

新增 [contracts/reaction-evidence.ts](../packages/contracts/src/reaction-evidence.ts)：`REACTION_ROLE_RANK`、`strongestReactionRoleClass`、`assertReactionEvidenceBinding`。类序表从两份（`stable-call-budget.ts` 与 `application/reaction-evidence.ts`）收敛成一份，应用侧与持久化边界读同一张表。

| 档案 | 要求 |
|---|---|
| `responsive/v2` | 候选必须有类；每条刺激必须带证据；证据的 `version`/`sourceEventOrdinal`/`observationId`/`observerCharacterId` 与本刺激一致；`actionId` 与来源 Observation 相同，完整内容下入口身份也与来源动作一致；证据的类是四个冻结类之一；草稿同时写出刺激类与证据类时两者必须相同；候选的类必须等于其刺激中的**最强类** |
| `responsive/v1` | 候选不得有类；刺激既不得有类也不得有证据 |

证据按**精确键**校验（`version`、`sourceEventOrdinal`、`observationId`、`observerCharacterId`、`actionId`、`entry`、`roleClass`），`entry` 两个变体各自精确：`{kind:'definition', definitionRef:{id,version}}` 或 `{kind:'action', actionType, actionVersion}`。

边界三处：**首波准备**（任何东西被哈希之前）、**延续波准备**（同一条规则）、**读回**（行不仅重新哈希，还重新核对——条目哈希覆盖的正是存进去的那份证据，所以自洽的谎会一致地通过）。

### 用例与证伪

23 条 v2 变更用例 + 3 条 v1 用例 + 一条**自洽篡改**读回用例（把证据里的动作改成另一动作并重算条目哈希，读回必须按来源 Observation 拒绝），另加两条 v1 表格行与一条 v2 延续波用例。`occurrence_only` 有意隐藏动作类型，因此只核对仍公开的 `actionId`，不从 `private_interaction` 反推动作身份。

逐条回退全部变红：R-A 首波不校验、R-B 延续波不校验、R-C 读回不重新核对、R-D 去掉"最强类"规则、R-E 不把证据与刺激对齐、R-F v1 不再拒绝无档案记录。**R-B 第一次是绿的**——延续波的覆盖漏洞是我自己的证伪脚本翻出来的，随后补齐；这条值得记，因为"实现写了但没测到"正是上一片留下的同类问题。

### 一个形状认知错误与一处收紧

- 第一版校验把 `roleClass` 与 `evidence` 都当刺激的必填字段，读回时对**每条 v2 行**都误报：存库的刺激**不带独立的 `roleClass`**，类在证据里面。草稿有两份必须一致，行只有一份。
- 读回校验意味着上一版（同分支、未发布）写下的 v2 延续刺激（当时不带证据）现在会被拒。该档案是本分支同日引入的，仓库内没有任何耐久基线含这种行——是收紧而非破坏，但确实属于"此前被接受的耐久状态现在会 fail-closed"，记在这里而不是埋着。

## 3. 审查发现 2：失败观察与 ADR-0096 §3 相反（成立，已修）

### 问题比描述的更严重

ADR-0096 §3 决定：**失败默认可观察，由世界声明的观察策略可关；关闭只抑制知情范围，事实层照常写 `action.rejected`**。核查后发现两件事：

1. 那句"与今天的硬编码行为一致"说的是**非冻结**路径：`rejectRulebookResolution` 不带观察范围，协调器因此退回 `scene_public`——失败在今天本来就可观察；
2. 冻结路径（`043737f`，I4-b）把失败**硬编码成 `self`**，把 ADR 的前提推翻了；而交互定义契约里一直没有可声明的字段（规格 §2 的 Definition 表里 `observationPolicyRef` 早已列出）。

结果是旁观者看不到失败尝试，规格 §5 所说的 witness 刺激因此缺失。

### 修法：受锁观察策略

| 位置 | 改动 |
|---|---|
| [contracts](../packages/contracts/src/interaction-definition.ts) | 新增 `InteractionObservationPolicyV1`（`onAccepted`/`onRejected` ∈ `{scene_public, self}`）与实现锁；`InteractionDefinitionSpec` 增加必填 `observationPolicyRef`；`InteractionPackageImplementation` 增加 `observation`；`InteractionAdjudication` 增加 `observationScope`（与 `resolvedRoles`/`affectedCharacterIds` 一样放在被哈希载荷**之外**，交出去不移动任何 trace 哈希） |
| [runtime](../packages/interaction-runtime/src/registry.ts) | 安装期校验策略形状；冻结期要求每个启用定义的策略可解析（否则 `observation policy missing`）；`resolve()` 按状态取 `onAccepted`/`onRejected` |
| [kernel](../packages/kernel/src/frozen-interactions.ts) | 不再自己决定范围：**定义级拒绝**用定义的声明；**没能命名定义的请求**（`INTERACTION_NOT_BOUND`、非法参数）仍留给 actor——那条理由会点名世界的目录结构 |
| [首批包](../packages/interactions-basic/src/basic.ts) | `base:public-outcome`（成功与失败都 `scene_public`）用于拿/放/递；`base:private-refusal`（成功 `scene_public`、失败 `self`）用于牵手与解除。事实层两种情形都写 `action.rejected` |

范围只允许 `scene_public` 与 `self`：`direct`/`private` 要点名收件人，而定义在动作提交前无从知道收件人是谁。

### 用例与证伪

- 单元：被拒的取物 `scene_public`、被拒的牵手 `self`、未能命名定义的请求 `self`，每种都写出 `action.rejected`；
- 端到端：同一世界两次同形拒绝——杯子已被拿走、两人已牵着手——旁观者只收到前者的 Observation，后者只有 actor；
- 运行时：策略不在选择内、版本不支持、范围写了 `private`，以及组件参与包锁（数组顺序无关）。

四条回退全部变红：kernel 自己决定范围、runtime 两种状态报同一范围、去掉冻结期检查、去掉范围校验。

**ADR-0096 加了一条注明日期的事实更正**（决定与方向不变）：那句括号对非冻结路径成立、对冻结路径不成立。

## 4. 审查发现 3：Player Intent 在 v10 下走不通（成立，已修）

### 问题：不是缺样本，是路径不通

| 位置 | 问题 |
|---|---|
| [player-intent-preparation.ts](../packages/application/src/player-intent-preparation.ts) | 交互选项写死 `actionVersion: 1` |
| [player-submission.ts](../packages/contracts/src/player-submission.ts) | `PlayerIntentAffordance.actionVersion` 是字面量 `1`；`choice.actionVersion !== 1` 直接判非法；交互参数只认 `{targetId, interactionId, arguments}`；产出的动作写死 `actionVersion: 1` |
| 同上 | `/act` 与显式 `input.action` 路径同样写死 `1` |

而冻结路径的 `affordances()` 已经正确报出 `interact@2` 与冻结请求形状——**选项摆在面前，绑定层把它拒了**，所以"缺样本"的背后是没有可跑的对象。

### 修法

- 版本归**动作类型**而不是适配器：言语与移动只能 1，交互 1 或 2；
- 交互参数按版本分派：v1 仍是 `{targetId, interactionId, arguments}`，**v2 是冻结请求 `{targetRef{kind,id}, bindingId, definitionRef{id,version}, arguments}`**，逐字段校验（目标 kind 闭集、定义版本为正安全整数、参数为对象）；
- 产出的动作沿用选项自己的版本；显式命令路径从它所行使的 affordance 取版本（命令本身不带版本）；
- 新增夹具 `frozenIntentWorld(profile?)` 与崩溃 worker 的 `frozen` 模式；
- **模型可见契约 `player-intent-candidate/v1` 一个字没改**：候选仍然只点名 `affordanceId` 与 key。**（2026-09-15 更新：后来按 I6 升到 v2——加了一个可选的 `performance` 槽位；这一行描述的是当时那一轮没动它。）**

### 四类样本

| 样本 | 断言 |
|---|---|
| 提交 | 模型被提供的正是冻结请求形状（`binding:entity:cup:base:take`、`"actionVersion":2`、`definitionRef`），杯子只被拿走一次 |
| Authority 6 | 同一用例读回该回合 Authority：`schemaVersion` 为 6，且至少一条 resolution 带 `interaction` |
| 重放 | 同一输入再提交返回同一结果，provider 只被问过一次（`calls === 1`） |
| 恢复 | 两个 store 中止点硬杀后，租约过期重启自行完成：provider 不再被问（`calls === 0`）、转移恰好一次、Authority 仍为 6 |

另加两条单元用例：显式命令从 affordance 取版本（成功路径）；**一个走不通的动作类型要澄清而不是被编造版本**（`action is not currently afforded` 守卫）。

### 证伪与一处删掉的代码

三条回退全红：产出动作钉死版本 1、绑定层恢复"只接受版本 1"、准备层把交互版本钉死 1。

**删掉了一段我自己加的代码**：准备层"先解析验证再提供交互选项"（照抄 move 分支）。回退它没有任何用例变红——冻结路径的 `view()` 本来就只列可尝试的选项，所以它在 v10 下是死代码、在 v9 下是没人验证过的行为变化。用例保留了"模型看不到 `binding:entity:cup:base:drop`"这条断言，但注释改成归因于世界自己的视图。
