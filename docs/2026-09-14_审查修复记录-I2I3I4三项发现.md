## 1. 激活只检查"装了包"，没有验证世界所需的精确包与锁（P1 · I4）

**成立。** `WorldApplication` 用 `#interactionPackages.length > 0` 当作"冻结运行时可用"，于是装一个无关包也能让 v10 世界激活并写入 Genesis；随后第一次 move 才抛 `package missing or lock drift`。数量不是可用性。

**修法：** 门禁从"有没有装包"改成"这个 Manifest 的选择闭不闭合"。

- `FrozenInteractionRulebook.adopt(manifest, manifestHash)`：显式冻结一次某个 Manifest 选出的世界，结果进同一份缓存，后续 `resolve` / `affordances` 复用。
- `WorldBootstrap` 的第三个参数由布尔开关改为**那个冻结路径本身**；v10 激活时调用 `adopt`，失败即 `MANIFEST_RUNTIME_UNAVAILABLE`，**在任何 Genesis 字节写入之前**。
- `WorldApplication` 只构造一份冻结路径，同时交给注册表与激活门禁——裁定用的和校验用的必须是同一份。

**用例与证伪：** 装一个真实的、可安装的、但**不是这个世界所选**的包（同一批组件换一个包 id 并重算包锁），断言 `activate` 抛出且 `readManifest` 仍为 `undefined`。把 `adopt` 换回纯存在性判断后，该用例失败（"expected [Function] to throw an error"）。

**顺带补的失败路径：** 冻结运行时抛出非 `Error` 时仍然失败关闭并带诊断，而不是裸崩。

## 2. fold 没有限制累计事件数（P1 · I3）

**成立。** `#fold` 只检查每个处理器**单次**返回量（`list(added, maximumEvents)`），追加后不检查整组大小。冻结 profile 里这是两个数：每动作主效果 16、含生命周期效果 64。审查的复现是主效果 1 条 + 5 个处理器各 16 条 = 81 条被接受。

**修法：** 在 `#fold` 里按累计量校验，两个路径共用：

```ts
if (added.length > 0) {
  folded = immutable([...folded, ...added])
  if (folded.length > MAXIMUM_TOTAL_LIFECYCLE_EVENTS) throw new TypeError('lifecycle fold exceeds the total event budget')
}
```

常量 `MAXIMUM_TOTAL_LIFECYCLE_EVENTS = 64` 与 profile 同源；超限**整组失败**，不截断尾部。

**用例与证伪：** 三个 16 条 + 一个 15 条的处理器加主效果 1 条 = **恰好 64 条，接受**；再加一个 1 条的处理器 = 65 条，拒绝。边界落在数轴上而不是"很大就炸"。删掉那行检查后该用例失败（11 通过 1 失败）。

## 3. 非法交互参数穿过入口，变成运行时异常（P2 · I4）

**成立。** `frozenRequest` 只确认 `arguments` 是对象。给一个合法的 take 请求加 `arguments: { unexpected: true }`，会一路走到 `registry.resolve` 内部的 `parameters()`，抛出 `missing or extra fields`——把"模型提了个不合适的参数"变成"这一轮崩了"。

**修法：** 在非可信请求边界用**同源**参数验证。

- `FrozenInteractionWorld.acceptsArguments(bindingId, value)`：用**裁定本身要用的那份冻结 `argumentSchema`** 判断参数是否良构；找不到绑定返回 false。验证留在运行时内一处，Host 不另写一份。
- `frozenRequest` 据此返回新的明确拒绝 `INVALID_INTERACTION_ARGUMENTS`，而不是让异常穿出去。

**真正的完整性异常仍然抛出：** 缺包、锁漂移、WorldAddress 不符等仍由 `#world` 在到达参数检查之前抛出；被转成拒绝的只有"提案本身不合定义"这一类。

**用例与证伪：** `arguments` 为 `null` / `{ unexpected: true }` / `{ recipientId: … }`（take 没有这个字段）三种都得到 `INVALID_INTERACTION_ARGUMENTS`，而 `base:give` 的合法 `recipientId` 仍然被接受。把检查换回"是对象就行"后该用例失败（得到 `INVALID_INTERACTION_PARAMETERS`）。
