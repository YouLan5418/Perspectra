## 1. 决策与范围

保留 speak、move、interact 顶层入口，具体动作由受信任包声明。新增 CommunicationScene，组织通信成员、端点、生命周期和传播策略。Physical Scene 仍负责物理场景成员；角色物理位置不因通信变化。

首批基础动作迁移范围不变。电话和消息是抽象验证案例，不自动加入基础包。未来梦境、VR 和精神链接不承诺共用通信语义。世界级记忆策略仍后续独立升版。

本文名称、事件概念和能力引用均为设计候选，不是已分配的运行时 API。

## 2. 分类与权威

交互事实语义、空间要求、传播媒介、时间条件为正交维度，不新增 LOCAL/CROSS_SCENE/CROSS_TIME 互斥总枚举。

| 概念 | 权威职责 | 不推导的能力 |
|---|---|---|
| Location / Physical Scene | 所在地与物理场景成员 | 同地点不证明触手可及 |
| CommunicationScene | 会话身份、成员、端点、状态、策略引用 | 成员身份不证明接通、已读或物理可达 |
| 传播策略 | 从来源事件及端点状态推导授权送达 | 不转发整个现场上下文 |
| Observation | 某角色实际有权获得的内容与来源 | 不赋予操作会话或设备的权限 |
| ReactionEvidence | 授权观察支持的反应候选依据 | 不保证调用模型或产生回复 |

所有事实来自 World Event Log。同一完整 WorldAddress、候选前缀和 as-of 下裁定；Projection、Memory、运行时 Session 不能补写事实。此处会话为世界领域对象，与模型 Session 分离。

## 3. 成员与空间不变量

1. 保留现有角色零或一个活跃物理 Scene 的约束；允许有上限的通信成员集合。
2. 通信成员不得混入旧 sceneIds 后让旧 space:scene-intersection 自动接受。物理动作必须验证物理 Scene 交集。
3. 必测同 Location、不同 Physical Scene、共享电话的案例：通信不得使牵手、递交等变得合法。
4. move 只迁移物理成员；通信是否失效由通信定义按设备、连接等事实裁定。
5. 可交互目录分别呈现物理目标与通信端点的授权操作。知道联系方式不等于知道远端位置或现场物品。
6. 目标仍由作者绑定能力；模型不得自建成员、受众、连接或授权。新增 targetKind 或参数形状须单独版本化，不能借任意字符串偷渡。

## 4. 通信会话与包声明

会话至少记录身份、创建动作、包与定义身份、生命周期、成员及角色、端点、媒介策略和状态版本。包实现受宿主信任与锁定，作者仅选择已注册定义及参数。

电话参考状态：呼叫、响铃、接通、拒绝、结束。来电通知可以在对方成为已接通成员之前送达；接通依赖明确动作或已声明自动接听规则，不能因拨号强制成立。

消息参考状态：发送、投递、阅读。聊天空间可以长期存在；收件人无需同时在线或加入当前反应轮。正文可见性、历史范围、新成员历史访问分别声明，默认无隐式追溯授权。角色不可用时保留耐久投递状态，不虚构阅读与回复。

禁用包不得留下无法结束的活跃会话：激活、撤销与迁移契约必须规定拒绝禁用或原子收尾。历史重放所需包和策略版本持续可用。

## 5. 一次来源、多条受限传播路径

speak 仍表达一次发言。Host 根据动作时刻的接通、静音与端点事实选择传播路径，不能把模型给出的受众作为授权。

例如 A 在厨房、B 在办公室：A 的语音可被厨房有权听见者和电话另一端 B 接收；B 不获得 A 的手势、表情或厨房对象清单。B 的声音只有在 A 的外放端点成立时才能继续传向厨房旁观者。

每条送达保留来源事件、会话/端点、策略身份、有效前缀及裁剪后的内容。传播阶段不能读取或转发接收者无权获得的完整 Observation。设备转播保持同一来源身份；如需正式转播事件，必须由注册效果产生并链接来源，不能伪造第二次角色发言。

同一接收者经多路收到同一来源时，按冻结规则归并观察与反应依据；不同媒介的合法信息可以保留，但不得重复计数、重复触发同一反应。传播回路必须通过来源与路径约束及硬上限终止，不模拟无限麦克风反馈。

## 6. 统一反应与上下文

处理链为：裁定与候选事件 → 生命周期与完整性验证 → 授权传播/观察 → 反应依据 → 统一预算下的后续轮候选。

来电送达可以让远端角色取得反应资格；加入会话本身不能无条件激活角色。当前轮参与者仍冻结，新资格在后续允许的轮次生效，不中途插入当前模型调用集合。

远端角色的上下文从其自身位置、授权观察和耐久记录重建，不能复用发起者的现场上下文。角色不可用、候选不足或预算耗尽均按冻结策略记录，不能把观察送达等同于已回应。

通信与物理场景共享一个因果周期的总预算，不按场景创建可无限嵌套的周期。会话可以跨周期存在，周期关闭不挂断；会话存续不自动唤醒角色。

## 7. 生命周期归属与资源预算

处理器必须声明可消费/处理的关系或会话类型，宿主只传入授权范围并校验输出。不得用“扫描全部 active relation，再按同地点结束”的方式处理通信。

包选择必须闭合生命周期依赖；持续实例不能仅因某个结束动作未被选择而失去收尾机制。未知或畸形实例按明确完整性错误失败，不能用猜测的参与者生成畸形事件。

激活前冻结以下数值：每角色会话数、每会话成员/端点数、每动作送达数、每路径跳数、消息字节数、候选数及共享反应调用数。具体数值须通过容量 fixture 后分配；没有数字和超限语义不得关闭契约 Gate。

传播/事件完整性预算超限时不截断提交部分事实；异步部分送达只能作为显式、耐久、可重放的协议状态。反应预算结束则正常停止模型续轮，不撤销已提交送达。

## 8. 时间边界

会话跨轮不等于世界时间调度。第一阶段不新增墙钟超时和通用 FutureEvent 系统；需要到期行为时另立世界 Tick/时间推进契约。

“明天来找我”等话语只构成表达事实，不自动建立保证发生的未来行动。结构化计划、触发条件、取消和到期重新裁定均需独立授权契约。

## 9. 版本、迁移与恢复

ADR-0093 保持 Accepted 原文；新 ADR 局部替代新路径的单 Scene 观察/调度假设，不原地改写旧语义。

Manifest v10 仍归交互，不夹带世界级记忆策略。本扩展具体绑定 v10 还是后续版本，须在 I4 版本冻结前依据是否已有外部持久化依赖决定；本文不抢占协议号。

旧 Manifest、Scene、模型 Schema 和黄金 expected 保持可验证。新 Manifest 锁定会话 Schema、传播/观察/反应策略、生命周期作用域及预算。恢复应由事件和锁定实现重建会话、端点与投递进度；COMMIT 后恢复不得重复投递、重复反应或重复记忆。

### 10.1 通信 Gate 的延期与本次 I4 的验收边界

**延期声明。** 原表中"通信 fixture 作为 I4 前置"一行**已被取代**：它不构成既有交互范围 I4 的前置条件，也不在本次交付中宣告通过。通信接线、远端上下文隔离与"预算不按 Scene 翻倍"三项 Gate 随该阶段整体后移；本方案不因为既有交互 I4 合格而宣称通信部分达标。

本次 I4（既有交互范围）的三条验收边界：

1. **新路径的 move 经统一生命周期收尾，不包含具体接触名判断。** 旧 v9 冻结兼容路径可以保留旧实现（`rulebook.ts` 的 `endCharacterRelations` 分支不动）；成立的是**新版本路径**不再按接触名分支。
2. **fold 只有一个执行位置。** `resolve()` 已在裁定内部调用 fold，应用层接线**不得再无条件执行第二遍**；接线要保证处理器看到的是**正确的候选状态**（含本次动作已产出的候选事件），并明确哪一条路径负责 fold、哪一条只透传结果。
3. **完成原 I4 的观察、反应依据、入口与恢复门禁。** 四入口（Root / Reaction / 显式玩家 / Player Intent）与 Authority 持久化、恢复接线在本次范围内。

**不在本次范围：** 通信成员与端点、传播策略与送达、远端调度，以及 §3.3 起的通信验收矩阵。这些将来按新版本追加，**不得原地向已冻结语义追加**。

**通信验收矩阵（随 §10.1 延期，本次不验收）：** 以下条目全部依赖通信成员或传播，属已延期的通信接线阶段，本次 I4 不逐条验收、也不宣告通过。

- 同地点不同物理 Scene 共享电话，物理动作仍拒绝。
- 未接听、静音、挂断前后同轮动作按各自候选前缀路由。
- 本地旁观者只得本地授权信息；外放不授予控制权；电话不传手势。
- 来电送达远端非当前成员，后续轮可候选；不可用角色不伪造回复。
- 相同来源双路径归并、反馈回路终止、跨 Scene 共享预算。
- 周期停止而通话继续；发新输入后恢复通信；单纯存续不唤醒。
- 离线投递与阅读分离；新成员不自动获得历史；跨 Branch 请求拒绝。
- 接触与电话同时存在，move 只按各定义结束应结束的实例。
- 会话/消息提交中硬终止与 COMMIT 后回执前硬终止，重启重放一致。
- 禁用包、缺锁定实现、预算超限和非法事件按冻结失败语义处理。

其中**最后三条的前半段与通信无关**（禁用包/缺实现/预算超限的失败语义、Hard-Kill 重放一致性、跨 Branch 拒绝）由既有交互范围承担，本次 I4 按规格 §6 与既有硬终止套件验收；"接触与电话同时存在"要等通信落地才有对立面。
