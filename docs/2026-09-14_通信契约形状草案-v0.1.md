## 1. 需要先定的一件事：`CommunicationScene` 的载体

这是唯一会卡住 I4 的决定。ADR-0094 说通信"复用观察、上下文与反应基础设施，**但需要扩展其授权输入，不能声称无需接线**"——所以载体选哪个，决定 I4 的观察接线要不要一次做对。

**案一（推荐）：通信是一等世界状态。** 新增事件族 + 投影，与 `character.relation-*` 同类；送达作为 Observation 的一种**受限来源**，需要扩展观察授权输入。

- 依据：V0.3 §9 要求"恢复应由事件和锁定实现重建**会话、端点与投递进度**"；§4 要求会话记录"状态版本"。这两条都要求状态可从事务性事件重建，而不是靠 Manifest 声明反推。
- 代价：新事件族、新投影、观察授权输入扩展一处。I4 的观察/反应接线必须按此设计，否则要接两遍。

**案二：通信只是 Manifest 声明 + 现有事件的受限用法。** 不新增事件类型，会话状态作为通用状态事件承载。

- 依据：改动面最小，I4 接线不受影响。
- 代价：§4 的"成员及角色、端点、媒介策略、状态版本"要在通用事件里靠约定编码，而这正是 V0.3 §3.6 反对的"借任意字符串偷渡"；且"投递进度"没有自然的归属。

**我的判断是案一。** 但这条有产品含义——**远端说的话会不会进 Observation 与 Memory、能不能被召回**——所以它该由你点头，不是我在契约里默认。

## 2. 类型骨架（全部为候选）

### 2.1 会话

会话身份，按世界已有的做法派生：WorldAddress + 创建动作 + 定义锁 + 实例序号，**不用墙钟或随机**——与关系身份同一模式，重放铸同一个会话。

会话记录至少包含：身份、创建定义（id/version/锁）、生命周期状态、成员及角色、端点、媒介策略引用、状态版本。

**电话参考状态**：呼叫 → 响铃 → 接通 → 拒绝 / 结束。
**消息参考状态**：发送 → 投递 → 阅读。

两条已由 V0.3 定死、本文不动的语义：**来电通知可以在对方成为已接通成员之前送达**；**接通依赖明确动作或已声明自动接听规则，不能因拨号强制成立**。

### 2.2 成员与端点

成员是"谁在这条会话里、以什么角色"，端点是"以什么设备、在什么状态"。

关键不变量（V0.3 §3）：**通信成员不得进入 `sceneIds`**。因此物理成员与通信成员是**两个字段**，`space:co-location` / `space:scene-intersection` 只读物理的那个，**一行都不用改**。

需要端点的状态事实至少包括：接通中、静音、外放。V0.3 §5 的例子依赖它们：B 的声音只有在 A 的外放端点成立时才能继续传向厨房旁观者。

### 2.3 传播策略

一个**受锁注册件**，与规则/效果/生命周期处理器同类，由定义引用。它声明：本策略能把一个来源事件推导成哪些送达观察，以及路径与规模上限。

V0.3 §5 的硬约束在此落地：**Host 根据动作时刻的接通、静音与端点事实选择路径，模型给出的受众不是授权**；不能转发接收者无权获得的完整 Observation；设备转播保持同一来源身份；如需正式转播事件，必须由注册效果产生并链接来源。

### 2.4 送达观察

一条送达至少保留：来源事件引用、会话与端点、策略身份、有效前缀、**裁剪后**的内容。

这是 Observation 的**一种新来源**，不是新的事实账本——V0.3 §2 的分工表已经这么写。

### 2.5 生命周期作用域

V0.3 §7 第一句要求"处理器必须声明可消费/处理的关系或**会话**类型"。I3 收尾刚为关系建立了同一机制（处理器声明 `consumes`，fold 裁剪可见实例并拒绝范围外输出），**会话直接沿用**：声明可消费的会话定义，fold 同样裁剪。

V0.3 §7 那句"**不得用'扫描全部 active relation，再按同地点结束'的方式处理通信**"，在 I3 收尾里已经按关系实现了；通信只需把同一约束套到会话上。

### 2.6 目录呈现

V0.3 §3.5：物理目标与通信端点的授权操作**分别呈现**。所以端点要能被枚举成选项，这意味着一个**新的 `targetKind`**（会话或端点），而 V0.3 §3.6 要求"新增 targetKind 或参数形状须单独版本化"——它不能借现有字符串混进来。

## 3. 与既有实现的关系

| 既有机制 | 通信如何使用 |
|---|---|
| 生命周期相位（`spatial` / `relation-end` / `observation`） | **不新增相位**。传播发生在动作时刻，属 `observation` 相位，走同一个 fold |
| 处理器 `consumes` 作用域 | 直接复用，约束对象从关系换成会话 |
| 目标快照 `{ ref, state }` | 会话/端点作为新 kind 的目标进入快照；**物理成员字段不动** |
| `space:co-location` / `space:scene-intersection` | **不改**。只读物理成员，V0.3 §3.3 的必测案例正依赖这一点 |
| 观察、上下文与反应预算 | 复用基础设施，但**授权输入要扩展**（ADR-0094 明说） |
| `rulebook.ts`、旧 v9 路径、旧黄金 | **不动** |

## 4. 预算表（数值留空）

V0.3 §7 要求激活前冻结七项。下表只给**测量方法**，数值待 I4 前置 fixture 得出：

| 项 | 测量方法 |
|---|---|
| 每角色会话数 | 容量 fixture 压到拒绝，取拒绝前一刻 |
| 每会话成员数 / 端点数 | 同上，分别测 |
| 每动作送达数 | 一条 speak 经最大路径扇出 |
| 每路径跳数 | 构造设备转播链，直到回路终止约束触发 |
| 消息字节数 | 与 `interaction-limits/v1` 的字符串上界同一量级核对 |
| 候选数 | 与现有单角色 128 选项的关系（是否共享同一预算） |
| 共享反应调用数 | V0.3 §6 要求"统一使用现有因果周期总预算"，须验证**不按 Scene 翻倍** |

最后一项是 I4 的 Gate 之一（"预算不按 Scene 翻倍"），也是为什么载体决定要在 I4 接线前定。

## 5. 版本与绑定

V0.3 §9 已经定了规矩，本文照办：**Manifest v10 仍归交互，不夹带世界级记忆策略**；通信绑 v10 还是后续版本，"须在 I4 版本冻结前依据是否已有外部持久化依赖决定"。

若绑 v10，则该版本槽要同时承载交互包选择**与**通信策略声明——这是 I4 版本冻结时必须一并考虑的约束，不能事后追加。

## 6. 未解问题

1. **会话成员资格与接通资格的关系。** §4 说来电通知可先于接通送达，那么"收得到通知"与"是成员"是两个不同判定，各自的前置条件需要分开定义。
2. **多路归并的冻结规则。** §5 要求"按冻结规则归并观察与反应依据"，但"同一来源经两条路径到达同一接收者"时，两条路径携带的裁剪内容不同时怎么归并，没有说。
3. **设备转播是否首批需要。** §5 是条件句（"如需正式转播事件"）。不做则传播契约里少一类事件；做则要定转播事件的形状与来源链接。
4. **§7 的"未知或畸形实例按明确完整性错误失败"** 与 I3 收尾对关系采取的策略一致（畸形事实不生成事件），但会话侧的"畸形"边界还没定义。
