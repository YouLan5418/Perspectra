## 1. 要重新回答的产品问题

角色应该理解自己所在的场景、眼前的人与物、刚刚发生的互动，以及可以尝试的行为。它可以自由说话、沉默、迟疑、观察、表达人物细节；当它要执行创作者声明的交互时，应调用执行入口并依据结果继续扮演。

本实验不追求把每个文学动作转换为可枚举状态。程序追踪哪些机制，由世界内容显式声明。例如，同一句“把杯子往旁边挪了挪”，在不追踪杯子位置的世界中可以是自由描写；在声明了杯子位置、归属和移动规则的世界中，其受控效果必须由交互执行。

“没有给目标提供某个交互”不等于“文本可以修改它的受控状态”。铜钥匙属于受控物品，即使角色当前没有拿取选项，描述“收进口袋”也不能改变其归属。表达空间与执行能力是两件事。

本实验希望保留的差异是：自然角色表达、多个角色依据各自可见信息反应，以及少量可靠的世界机制。对未来版本兼容、模型调用中间态恢复、表现语义全覆盖的承诺均不进入首轮范围。

## 4. 三类记录与权威边界

下表是逻辑分类，不要求新增三个包、数据库或版本体系。

| 记录 | 内容 | 可以驱动什么 | 不能驱动什么 |
| --- | --- | --- | --- |
| 交互执行结果 | 操作者、目标、接受/拒绝、受控效果、已提交事件引用 | 世界投影、场景成员、持有关系、后续交互资格、对应结果观察 | 不能凭“触碰发生”生成“对方喜欢”的事实 |
| 已发布会话内容 | 谁在何处向哪些人说了什么、公开描述了什么 | UI、近期互动、角色反应、带来源的主观记忆 | 不能作为状态 patch、到达证明、物品归属或接触关系证明 |
| 私有意图与未发布草稿 | 玩家待解释输入、模型工具前草稿、失败提案、角色私有思考 | 当前输入解释或该角色自己的继续决策 | 不自动广播、不写其他角色记忆、不作为成功事件 |

会话记录的可信部分是“此角色发布了这段内容、这些受众收到它”，不是“正文中所有陈述都真实”。对白可以包含谎言。叙述可以包含对神态的描写。两者都不能让程序认定受控交互已经成功。

角色自己的心理、对他人的猜测与受控世界状态不能合并。对话摘要可以写“她似乎犹豫”“他声称拿到了钥匙”；当前钥匙归属始终从受控状态读取。

## 5. 创作者如何声明交互

### 5.1 最小定义与目标绑定

| 字段或职责 | 用途 |
| --- | --- |
| 稳定 definition ID、可读名称与说明 | 说明这是哪种行为，以及哪些结果需要执行 |
| 参数 Schema 与参与者/目标要求 | 描述可提交的参数；actor 由 Host 确认，不能让模型冒充 |
| 可尝试条件 | 只展示角色有权知道的信息；不能通过隐藏条件说明泄漏秘密 |
| 裁定函数 | 根据最新状态检查存在性、位置、持有、参与资格等 |
| 受控效果 | 仅由接受结果产生的类型化事件；不接受模型任意 patch |
| 结果受众 | 由 Host 按执行时状态计算或收窄 |
| 必要解除规则 | 仅对确实创建持续关系的定义提供，例如任一方松手、离场终止 |

内容作者可以把定义绑定到某个人、物件或地点入口，调整显示名、描述和已有参数。增加全新可执行语义，需要受信任的本地定义实现；一段自然语言规则不会自动获得写世界的能力。通用 Kernel 不应为每种题材交互增加名字分支。

受控状态域是引擎/定义的类型信息，用于限制写入能力，不是一套根据叙述关键词判定越权的词典。创作者对“拿取”“收进口袋”等含义的说明帮助模型选择工具，但不构成任意语言的机械识别器。

### 5.2 首轮示例

- 工作区入口提供“前往工作区”；成功改变位置并刷新可见对象。
- 铜钥匙提供“拿取”；角色物品提供“递交给指定人物”。成功改变归属。
- GPT 提供“握手”和“松手”示例，验证人物交互与扩展入口。示例可采用合法接触立即发生、NPC 随后反应的策略；同地点、目标存在和接触资格仍需裁定。回握、拒绝、挣脱属于角色后续行为，不由玩家替 NPC 决定心理。
- 若创建持续握手关系，移动或任一参与者松手必须终止它。首轮仅实现该定义需要的明确收尾，不建设通用生命周期 DAG。

“递交”在示例中的成功语义必须明确为立即转移或等待接收之一。首轮选择立即转移、目标后续可退回，以减少跨轮 pending 状态；其他玩法可在后续独立扩展，不能隐式混用两种语义。

## 6. 角色看到的上下文

### 6.1 场景视图

Host 先按角色可见性生成数据，再渲染成可读场景。首轮采用直接模板，不引入第二个模型负责生成场景事实。表达模板可以改，事实来源不能换成对话摘要。

```text
你是 GPT，目前在卧室。
玩家与你同处一室，刚才说自己不确定是不是在做梦。
你看得到床边的铜钥匙，以及通往工作区的门。

可以尝试：
- 前往工作区（入口：bedroom-to-workspace）。到达后才获得那里的新观察。
- 拿取铜钥匙（目标：copper-key）。是否成功由执行结果决定。
- 与玩家握手（目标：player）。执行后，双方可以继续回应或松手。

刚才的互动：
玩家：真的不是梦么？
你此前公开的表现：稍稍前倾，龙尾巴轻轻摆动。

最近的执行结果：尚未发生握手；钥匙仍在床边。
```

例中的 ID 是隐藏执行引用的可读表示，不要求玩家填写。实际工具参数由同一份可尝试交互数据生成，不能手写另一套不一致的菜单。

### 6.2 上下文顺序与限制

优先保留角色设定、当前可见场景、当前刺激、最近执行结果、近期会话，再装入较旧记忆。预算不足时先缩减旧会话，不丢掉当前状态与最近拒绝原因。

程序保证：未移动不会获得目的地的新对象、秘密或操作资格；被拒绝拿取不会获得持有者选项。移动事件的离开和到达受众分别根据动作前后状态计算，不能只看提交后的同房间成员。

会话片段带来源和说话者，但这些标记不能保证模型不误解。含矛盾的自由叙述仍可能影响模型；G3 专门测试这一点。场景模板必须明确列出原型追踪的状态，不把整个世界日志、所有私密认知或注册表倾倒给角色。

首轮每次请求记录所使用的场景版本/事件位置、会话引用与必要调试信息，不要求所有 Provider 字节永久精确重建。不要为这一点新建独立 Hash 链或多库水位体系。

## 7. 输入、工具执行与自由回复

### 7.1 玩家输入

玩家可以输入对白、纯表现、混合表达和交互意图，不要求掌握 Action 或 cue。已明确标为对白的输入原样发布；自然语言混合输入需要解释时，解释器只负责分出待执行的交互和公开表达，不把每个修饰词结构化。

模型不负责计算 UTF-16 偏移或 Hash。必要的引用定位由 Host 完成；纯语气、修饰无法分类不能成为拒绝整句的理由。原始输入保留，已接受的公开表达不能擅自追加玩家情绪、决定或别人的反应。

只有会改变受控执行的关键歧义才澄清，例如两把可见钥匙无法确定指哪把。纯微笑或沉默不是缺少主动作；直接成为有受众的会话表现并触发 NPC 反应。未知显式命令提示不支持，并保留输入，不静默当成公开对白。

如果整个混合输入无法可靠解释，不把其中可能声称完成交互的原文作为成功旁白广播。已显式确定的对白/表现可以发布；不确定部分留在玩家可见的输入记录中，给出具体未执行原因。这里是解释失败的用户反馈，不再启动额外语义审核模型。

### 7.2 NPC 的最小执行接口

下列是拟议语义形状，不是已发布 API，也不是对旧 submit_actions 增加一个兼容版本：

```text
perform(bindingId, arguments)
  → accepted: operationId + eventRefs + 可见结果 + 刷新后的场景
  → rejected: operationId + 可见拒绝原因 + 未改变的受控状态

publish({ narration?, speech?, audience? })
  → Host 确定的消息身份与实际受众

yield()
  → 本次不发布内容、不继续执行
```

`narration` 与 `speech` 都是自由文本，可只填其中之一；不包含 cue、placement、表现次数和逐句 actionId。`audience` 只能选择当前提供的公开或明确私密受众，Host 复核并确定实际投递范围。初次实验只需同地点公开与对可见角色私语，不要求先实现电话系统。

普通最终回复可由适配器映射为 publish，不强迫模型另行调用工具。若需要先说话再离开，则先发布，再执行移动；移动后发布面向新场景。不能把跨两个地点的一整段文本无差别投给两个场景。

### 7.3 执行顺序

```text
角色可见场景 + 当前刺激
    → 模型决策
        → 纯回复：确定受众 → 保存并发布 → 产生会话刺激
        → 交互请求：校验最新状态 → 原子提交 → 返回结果与新场景
                                             → 模型继续自由回复或下一次交互
```

含工具调用的模型响应中，未经执行结果支持的草稿先不公开；同一次响应不能把尚未执行的工具结果提前当成成功旁白发布。工具提交后，模型获得结果再继续。这是时序约束，不是程序已经理解并验证了全部自然语言。

执行调用串行提交；模型推理期间不持有数据库事务。每个执行操作由 Host 分配稳定身份，提交重试不重复产生效果。成功的前一步不会因后续回复格式错误或下一步领域拒绝被撤销。

发布时再次核验角色状态、受众和当前交互周期。玩家打断或场景改变后，旧调用返回的草稿不能继续投递；应在最新场景继续或结束。晚到结果不恢复旧反应周期。

## 8. 执行失败与叙事矛盾

| 情况 | 对用户与角色的行为 | 程序保证 |
| --- | --- | --- |
| 目标不存在、距离或持有条件不满足 | 返回具体可见拒绝原因，角色可自由回应或改选动作 | 不产生成功效果，不授予新权限 |
| 模型工具参数格式错误 | 在本轮剩余预算内允许一次格式修正；仍失败则报告本次未执行 | 不把猜测参数当有效请求；不重复已经提交的操作 |
| 模型回复失败，但前一步已提交 | 展示简短的真实执行结果并结束或后续继续 | 已发生结果保留，不能回滚为“什么都没发生” |
| Provider 超时或不可用 | 保留已提交内容，显示角色本次未完成回应 | 不伪造回应；重启不自动重发不确定调用 |
| 自由叙述声称未执行的受控行为 | 记录为叙事一致性失败；当前场景和交互资格仍按程序结果生成 | 不能自动从文字补一个事件来使之成立 |

表中最后一行由人工试玩或已知反例复核识别，不表示运行时已有自动理解任意叙述的检测器。不增加关键词守卫或第二模型裁判。也不宣称一个“非权威”标签足以解决它。若模型持续让其他角色把虚构到达当作现实，新方案的行为 Gate 失败，即使所有硬状态断言通过。

人工试玩中发现矛盾时，可以要求角色在最新场景下重试叙述；原有记录保留，新的重试不修改已提交效果。修正后的展示不能抹去本次失败计数。首轮不建设自动纠错、自动改写历史或会话分支系统。

## 9. 会话、记忆与反应

### 9.1 会话与记忆

发布时固化受众，之后离场、入场或重启都不能让未收到消息的角色追溯获得私语。对外发布的 narration、speech 均可进入接收者的近期上下文，纯表现也能刺激回应。

原始会话可耐久保存；短期窗口可以裁剪。长时记忆按角色与来源隔离，可以记录表情、印象和被告知的说法，但不能写回硬状态，也不能向场景构建器提供位置、物品归属或受控接触关系。

机制结果与会话摘要分别保留来源。对当前受控事实有疑问时，场景构建器只查询程序状态；对话摘要不充当它的缓存。摘要包含“她已经去了”这种文字时，仍可能诱导模型，这是行为验收对象，不伪装成类型系统可以完全防止的问题。

### 9.2 有界 Reaction

首轮顺序调度相关 NPC，避免为并行调用引入租约和恢复账本。可见会话或执行结果都能入内存反应队列；同一刺激不会给同一角色重复排队。被提及不自动获得信息，只有实际受众可受刺激。

起始预算为每次玩家输入最多 8 次 NPC Provider 调用、最多 3 波反应、每个角色激活最多 2 次受控交互尝试。工具结果后的续写、格式修正也计入调用预算；不按微笑、手势或描写段落计数。这些数值是可调整的实验默认值，不成为 Manifest 永久语义。

玩家新输入停止旧周期后续调度。已提交效果保留，未执行工作丢弃；通过进程内周期身份丢弃晚到输出。重启时世界恢复已提交状态，反应队列为空，不恢复到“某角色本来准备继续说一句”的位置。

## 10. 不变量与非保证

| ID | 必须成立的机械不变量 |
| --- | --- |
| P-01 | 受控状态只有经裁定、原子提交的效果可以改变 |
| P-02 | 自由文本、摘要、记忆不能调用状态写入或补交互事件 |
| P-03 | 可尝试选项不是执行授权，执行时检查最新状态和实际 actor |
| P-04 | 未移动不能获得目的地新观察、受众或操作资格 |
| P-05 | 会话只向发布时已授权受众投递，当前场景不从会话推导 |
| P-06 | 相同提交身份不会重复产生效果，已成功步骤不被后续文本失败回滚 |
| P-07 | 超时、打断、重启后的旧周期输出不发布、不执行 |
| P-08 | 只有表现、没有主动作的输入可以成立，角色能观察并响应 |

以下不作为机械保证：任意自然语言都被正确分类；自由文案绝不虚构；模型永不泄漏自己知道的秘密；同样历史得到同样措辞、召回排序或模型输出。程序会限制可获得的信息与投递对象，但已授权模型如何表达其所知仍需行为验证。

接受原型的不确定性不等于接受 E1/E2 的反复发生。关键场景分叉必须作为失败显式报告，不能降级为“只影响展示”或通过忽略该案例达成验收。

### 11.2 断代规则

新实验使用一个格式身份，只打开自己创建的世界。不在运行时维护 v1～v11 路由；格式不同就明确拒绝打开。以后需要断代时由旧程序打开旧世界，不要求新程序内嵌旧行为。

`D:/worlds` 下全部历史存档保留只读。新世界从选定内容重建，不迁移历史自由表现为可信事实。若希望继续原剧情，由创作者明确整理起始状态，不能通过摘要推断旧 GLM 已到工作区。

当前数据库若发生基本完整性错误，停止写入并保留证据，不静默忽略。取消复杂恢复承诺不等于容忍半提交或重复提交。World Event 与关键投影保持单库原子性；会话成功发布的判断以记录已保存为准，不宣称网络或 UI 投递 exactly-once。

## 13. 分阶段交付与验收

### 13.1 阶段

| Gate | 交付 | 通过条件 |
| --- | --- | --- |
| G0 契约落地 | 当前契约与基线记录；实验分支与入口；具体复用/存储选择；小世界内容 | 不改旧存档；新路径只用一种协议；场景可读且执行引用一致 |
| G1 最小执行 | 自由发布、perform 循环、两房间/两 NPC/铜钥匙/握手示例 | P-01～P-08 通过必要的模型无关测试；纯表现与声明交互均可走通 |
| G2 失败闭环 | 打断、格式错误、超时、拒绝、重启处理和有界诊断 | 无重复效果、无迟到提交；保留已成功效果；明确指出未完成部分 |
| G3 真实体验 | 固定场景与一段连续自由试玩 | 按下表评估；关键叙事分叉或输入被无关格式阻断时不得宣告通过 |
| G4 架构减法 | 根据实际依赖提出删除清单与迁移记录 | G3 达标后才扩大清理，不把重构规模当作产品进展 |

### 13.2 首轮固定情境

每项至少用真实 Provider 完成一次，先记录使用的模型、配置、世界起点与输入，再执行。它是定性体验 Gate，不是统计可靠性证明；不得中途换样本后只报告成功例。

| 样本 | 玩家情境 | 机械检查 | 人工体验检查 |
| --- | --- | --- | --- |
| T1 | “我有点尴尬地笑了笑”，不附带对白 | 不要求主动作，已授权 NPC 收到表现 | 回应自然，不要求玩家补协议字段 |
| T2 | “发生了什么？” | 能发表正常对白；Host 不让模型算偏移 | 没有无关澄清或整句丢弃 |
| T3 | 提议去工作区查看电脑，参考 v3 | 真移动后才给目的地场景；未移动者仍受原场景限制 | 不能持续把卧室角色当作已到工作区 |
| T4 | 尝试触摸 GPT 的手，参考 v6 | 已声明接触必须执行；结果与关系一致 | 保留微怔、笑、语气等自由度；拒绝时也能自然接话 |
| T5 | 关键钥匙拿取因条件不满足被拒 | 归属不变，后续使用钥匙仍被拒 | 不继续演成已经收入口袋 |
| T6 | 人为注入一次 Provider 格式失败，参考 v7 | 不产生伪造动作；重试不会重复已提交效果 | 下一轮知道哪里未完成，不通过旁白补执行结果 |
| T7 | 玩家中途插话；另测向单个角色私语 | 旧调用输出丢弃；非受众无消息/记忆 | 角色回应当前输入，不泄漏私语 |
| T8 | 离开房间再返回，随后停止并重启 | 互动资格恢复；只恢复已提交状态，队列为空 | 房间不变成永久无法互动的场所 |

另做一段至少 20 次玩家输入的连续试玩，观察上下文增长、人物细节延续、重复和反应耗时；不靠换新目录避开长会话问题。格式故障注入需注明是人工故障，不混入自然失败率。

G3 要求固定情境无关键受控结果与持续叙事分叉、无因表现词表/主动作要求造成的澄清；连续试玩中同类问题一旦出现就记录并复查，不以总体“看起来不错”掩盖。这并不保证所有未来输入都正确。角色自然度由玩家对具体片段评议，不用 cue 数量、组合熵或 Hash 相等代替。

### 13.3 记录与工程验证

记录输入、实际模型标识、必要模型输出、执行结果、消息受众、最终状态、延迟及失败分类；不保存凭据或完整 Provider 信封。非法输出保留有界正文和截断标志，以免重复 v7 无法查明坏字段的问题。日志容量可清理，不进入权威恢复链。

每轮汇总明确区分：输入澄清、解释失败、Schema 错误、领域拒绝、Provider 不可用、主动沉默、预算停止、叙事矛盾。工程通过与真实体验通过分别报告。

按 AGENTS.md 根据改动风险选择验证。默认 `corepack pnpm@11.7.0 check` 只做类型检查、Lint 与少量核心测试；不要求 100% 覆盖率，不默认执行旧全量、性能或硬终止测试。权限、状态与事务改动验证对应不变量和失败路径；只有涉及进程中断、恢复或事务边界时才运行相关硬崩溃测试。新行为明确替代旧行为时同步调整测试，不以旧测试强迫兼容。真实模型试玩另行报告，轻量检查不能代替体验验收。

## 玩家输入语义证据（实验 10）

**解释结果可以不确定，但不能丢失原始语义证据。**

- 输入记录保留完整原文；抽取片段和裁定结果分别表示解释选择与执行事实。
- 完整原文按既有观察权限进入后续角色上下文，并在该角色的记忆来源中保留。私密局部受众和移动见证者不因原文附件获得额外信息。
- 原文只证明玩家提交了这段表达，不证明受控动作成功，也不能替其他角色决定行为。证据保留不代表模型一定正确理解或使用它。
