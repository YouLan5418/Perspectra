| 属性 | 内容 |
| --- | --- |
| 日期 | 2026-10-05 |

## 1. 判断与实际问题

当前分层有必要，但多次语义处理尚未证明都值得成为必经步骤。需要收缩的是“角色回应前必须经过多少判断”，不是取消证据与认识的区别。

Source / Atom / Episode / Observation 是逻辑层级，不要求每个层级都有独立模型调用、数据库或服务。Retrieval Projection 和 Delivery Projection 继续分别表达“如何搜索”和“如何阅读”，不新增第三套记忆本体。

现有实验工具、离线审计与运行时机制应分开：保留研究记录，不代表将所有实验路径接入常规试玩。

| Evidence | Finding | Path |
| --- | --- | --- |
| 双牌即时续写：原始 JSON 0/6保留分歧、分散自然语言2/6、成组自然语言6/6、更新认识6/6 | 当前材料的组织可以影响理解，额外认识更新不是这个即时任务的唯一途径 | 优先清楚交付已授权证据，不要求每次新证据都先更新 Observation |
| 四类认知更新各三次分类一致，但家族由实验指定，正文仍有概括过强问题 | 版本和反证组织有价值，分类成功不等于认识正确 | 保留自然语言认识与修订追溯，不把分类枚举升级为完整生命周期 |
| 默认三项预算下发生过认识保留、必要反证丢失，已修复 | 预算和证据依赖不能只交给角色模型补救 | 保留去重、反证存在与摘选完整度标注；原完整成组预算仅作复杂路径对照 |
| 最新行动闭环中9次真实询问产生 Source 并进入更新；延迟后的9次检索全部为空 | 自主取证路径能运行，但未来认知影响断在初筛，未进入 JEV 或 Character | 首先验证认识能自然进入候选与阅读，不把断点归给角色不理解 |
| 二十条 Bank 中初筛遗漏相反认识，强制同家族成组又带回不适用分支 | 更复杂的筛选、分组并不总是改善结果 | 保留必要证据依赖，不强制交付整个主题家族 |

这些都是少量受控案例，不是总体正确率或所有模型能力的证明。最新 updated 组5/6真实询问、paired组1/6，尤其说明表达保留冲突不能直接外推为实际核实。

## 2. 宿主与模型的分工

原则：模型理解材料、形成主观判断并提出行动；宿主控制可见范围、可执行能力、预算和提交。创作者定义玩法与可取得的证据，不通过记忆机制替角色规定行为。

| 职责 | 主要负责者 | 必须守住的边界 |
| --- | --- | --- |
| 谁可以看到哪些经历 | 宿主 | 先授权再提供；候选、索引和模型判断都只能使用角色授权前缀 |
| 引用属于哪份证据 | 宿主 | 保留 sourceId / sourceHash / epistemicKind / worldSeq / CharacterId / WorldAddress 映射 |
| 当前材料意味着什么 | 角色模型 | 允许不确定、误解和相反认识；不得由宿主宣布某条认识是真理 |
| 怎样回应、是否取证、尝试什么行动 | 角色模型 | 不添加“必须核实”等行为指令，不把工具可用解释为必须使用 |
| 操作是否允许、是否成功、如何提交 | 宿主与 Rulebook | 只有 accepted 且 committed 的结果才能证明受控操作发生 |
| 哪些材料放进有限上下文 | 宿主 | 去重、预算、来源类型、反证存在和摘选完整度；允许少量证据未读，不能把省略当成不存在或已解决 |
| 长期认识的整理与修改 | 模型提出、宿主检查引用后保存 | 只有新增授权证据才触发实质更新；旧证据与旧版本不被改写 |

程序能检查来源范围和引用身份，不能仅靠引用合法就证明自然语言认识被证据充分支持。自由文本语义漂移仍需真实试玩观察，不新增通用语义审查器来追求形式化保证。

## 3. 建议的常规路径

```text
当前授权刺激 + 近期授权经历
                 │
                 ▼
检索一小批可能相关的旧经历 / 当前认识
                 │
                 ▼
去重 → 组织相关证据 → 标明来源与时间 → 控制阅读预算
                 │
                 ▼
Character 理解材料，选择 publish / perform / recall / abstain
                 │
          若提出受控行动
                 ▼
Rulebook 裁定 → 原子提交 → 产生新的授权 Source
                 │
                 ▼
交付实际执行结果，继续角色回应
```

需要长期保留的理解另行整理：

```text
新增授权证据 + 相关旧认识及其证据
                 │
                 ▼
模型提出当前认识与证据引用
                 │
                 ▼
宿主检查授权、引用、时间与版本关系
                 │
                 ▼
保存当前认识和历史版本 → 重建派生检索表示
```

“另行整理”首先复用现有手动整理或明确实验触发点，不新增耐久后台任务或调度平台。若本次 Character Turn 没有更新长期认识，新证据仍然保存，并能参与近期理解与后续检索；不为等认识整理而阻塞每次即时回应。

## 4. 各组件如何收缩

| 组件 | 保留 | 简化或延期 |
| --- | --- | --- |
| Source | 不可变原始经历、授权范围与来源类型 | 不复制出多个权威证据版本，不增加新 Hash 或协议体系 |
| Event Atom | 引用原文的最小语义单位，区分听到发言和已提交结果 | 能根据已有元数据和原文确定性形成时，不另加语义模型；不把每句文学细节都结构化 |
| Episode | 经历关联、活动开场结尾与必要上下文 | 不要求每次回应先完成完美分段，不把整段经历变成不可分割事实 |
| Observation | 自然语言正文、支持与反驳、证据时间、形成/修订时间、旧版关系 | 不加数值置信度、完整状态机或强制判断单元拆分；不是每次新来源都必须形成认识 |
| 认知家族 | 复用已知活动、对象或实验明确的关系 | 暂不自动发现所有认知维度，不把相似度当作修订关系 |
| Retrieval Projection | 派生、可重建、查询与索引使用一致清理规则 | 简单表示作为对照；复杂适用性字段只在确有召回收益时保留 |
| 检索 | 现有关键词/语义和明确 ID 关联，保留原始分数与空结果 | 不新增图框架、检索路或编码器；少量候选不要求检索器充分理解每个例外 |
| JEV | 保留当前协议与现有路径，作为对照或可选筛选 | 不默认要求所有角色回合必经 JEV；先比较省略它的实际收益和噪声代价 |
| Delivery | 来源、时间、去重、完整度、反证存在与预算 | 授权认识正文可直接交付，附少量关键证据；不要求支持全为直接观察/已接受行动，不要求整个证据组完整入预算 |
| 审计与 trace | 能追溯刺激、候选、阅读内容、原始输出、执行与新增来源 | 复用现有记录，不将所有离线重放工具变成运行时依赖 |

四类更新关系可以保留用于实验诊断，不宜继续承担正文形态和分支数的硬性产品约束。未解决冲突可以写在同一条认识内，也可以保留多个必要分支；该选择要另行验证，不能在本轮直接更改既有 updater。

## 5. Observation 的最小职责

Observation 用于保存跨经历形成、需要长期延续的角色认识。刚看到两块不同的牌子不必先生成一条认识才能回应；反复遇到不同来源、形成对某人或某类情境的稳定理解时，认识整理更有价值。

先复用现有字段表达：正文、支持/反驳引用、证据时间范围、形成/修订时间、上一版本关系。已知家族默认使用当前版本，明确历史问题仍能找到旧版；当前冲突不能只因为新近程度或名次被宣布已解决。

角色当场表达的猜测可以是主观内容，但不能直接转成证实事实，也不应将它自己的多次表达当成新增独立支持。新 Source 的数量不等于独立信息源数量：重新读取同一块牌是新的读取经历，不是另一份独立印证。

无新增证据时不调用更新模型随意重写认识。认识整理仍允许出错，保存追溯使错误可被调查和后续证据修订；引用检查不冒充蕴含校验。

## 6. 最小验证顺序

先保留旧实验输入和结果，使用新目录。常规路径的局部消融各自改变一个主要变量；另加一个故意放宽材料量的长上下文暴力基线。暴力基线同时改变候选组织和阅读量，用来比较整条路径的实际收益，不能将差异单独归因于 JEV、Observation 或上下文容量。

### 6.0 先建立长上下文暴力基线

目标：比较复杂记忆链与“直接给角色大量相关授权历史，让模型自己理解”的实际表现。这个基线不必等待复杂初筛修通，先复用最新实验的冻结前缀，并与后续各阶段并排运行。

```text
角色授权来源过滤（角色 / 世界地址 / asOfWorldSeq）
                      │
                      ▼
最近经历 + 与当前人物 / 地点 / 活动直接相关的大量历史材料
                      │
                      ▼
确定性去重、自然语言呈现、来源与时间标注、上下文预算
                      │
                      ▼
直接交 Character 理解并选择行动
```

基线不经过语义编码、BM25、RRF、JEV或复杂适用性判断；不生成临时 Observation，也不交付已有 Observation 正文。这样能够观察模型是否能从经历本身重新理解问题。模型当场形成猜测属于正常推理，不能因此说基线“没有认知”，也不把这次推理自动保存为证实事实或新的持久认识。

**材料选择规则：**

- 先取该角色、该世界地址和该时点真正授权的 Source 前缀，再在其中选择材料；不得先搜索全世界或其他角色档案。
- 近期窗口与其他组一致。历史选择只使用当前场景和刺激中已有的人物 ID、地点 ID、活动 ID，以及角色已经授权获知的显式关联；不额外调用模型猜“这条认识适不适用”。
- 人物关联包括参与或明确被提及；地点关联包括记录发生地或明确涉及的地点；活动关联使用已有活动元数据。同地点的泛泛闲聊也可以被带入，这正是需要测的噪声代价。
- 不能仅因为 Source 的观察者是该角色，就把所有历史都算作当前人物相关。当前缺少可用 ID/元数据时，只使用已有明确关联和近期材料，记录覆盖不足，不注入研究者知道的目标 Source 或答案。
- 按人物、地点、活动三种关系取并集，再按 sourceId 去重。保留同一说法的不同实际来源和相反材料，重复表达不当成独立印证。
- 使用原始授权描述、发言或引用原文的 Atom。只做确定性可读呈现，不调用模型压缩、不借用 Episode 摘要或 Observation 概括。发言写明“谁说了什么”，读取写明“看到了什么”，不把牌面文字写成登记处已确认位置。
- 使用稳定的时间顺序，不按研究目标人为突出某条材料。重叠的近期材料不重复交付，引用留在 trace 中；对角色无需重复打印完整哈希，但来源、主体和认识论类型仍须清楚。

**材料量故意较大，但明确受预算限制：**

此基线使用独立的实验材料预算，不受窄路径“三项 / 4500 JSON 字符”限制；不以把几十条塞进一项的方式绕过原检查。实验适配只替换材料数量上限，继续逐项核验授权与引用，不解除宿主执行权限。

准备阶段先核实实际网关和所选 Character 模型可接受的请求容量。可先比较约8k和24k历史材料 token 两档；这些是待验证的预算设想，不是对当前模型容量的声明。全部请求还需预留人物设定、玩法契约、近期刺激、输出和执行后续写空间。

材料不足就报告实际数量，不复制或补写经历填满窗口。预算溢出时，近期内容先保留，相关历史按预先固定的最近来源优先截取，再按时间升序呈现；不从 Source 中间截断。记录已提供、因预算未提供的来源和时间范围，不用相关度阈值再次筛选。两档差异属于材料范围与阅读量的综合影响。

**并排比较三条路径：**

| 路径 | 交给 Character 的材料 | 主要回答什么 |
| --- | --- | --- |
| 现有复杂路径 | 原检索/JEV/Delivery决定的经历与认识 | 当前机制实际做到什么 |
| 简化窄路径 | 简单候选与受预算控制的材料，JEV按阶段做消融 | 能否减少处理环节而保持体验 |
| 长上下文暴力基线 | 近期经历 + 大量直接关联的原始授权历史；无 JEV、无 Observation 交付 | 模型阅读原始材料是否足以完成当前任务 |

保持模型、人物、玩家问题、能力、执行裁定、非历史上下文和单次激活调用预算一致。可共用的原始证据使用相同的自然语言呈现；不同路径的材料集合、认识正文和长度差异如实记录。这是端到端基线，不是独立组件因果证明。首次选择比较使用相同已提交前缀；真实行动后历史可以分叉，不能再声称后续请求完全相同。

记录：实际历史来源数、时间覆盖、材料/全请求 token、模型调用数、首步与执行续写的总等待、提供商返回用量和可核实的成本；判断仍以真实 submitted/accepted/committed 行动、证据冲突保留、发言与事实区分、无关旧事侵入为主。没有真实定价就只报告用量，不虚构金额；长上下文不是“免费少一次调用”。

少量重复和负对照沿用现有实验，不新增大型标注设施。基线中没生成持久认识，因此它即便成功，也只说明这些规模与任务可以依赖原始历史；不能证明无限历史无需记忆整理，或长期人格认识已被替代。若它较好但成本高，复杂路径应证明其成本收益；若复杂路径并未更好，先不将更多筛选与更新环节正式接入。若暴力基线也失败，仍需检查相关证据是否实际在窗口里，不能直接断言模型能力不足。

### 6.1 先定位并修通候选入口

复用双牌闭环的三条已提交轨迹、八次无关互动和相同后续刺激。冻结 Source、Observation 正文、Capability、角色模型和 Delivery；只在实验检索入口比较现有路径与一个更简单的候选准入方案。

优先复用授权对象/活动 ID 与现有检索表示。不得在查询里注入目标认识 ID、203/105或答案来制造自然召回；不得把二十条人物 Bank 的9/9交付直接当作局部牌面认识已覆盖。

记录目标、必要相反证据、无关项在哪里入选或被拒绝。先确保新路径确实让相关认识进入候选；否则后续 JEV 和 Character 对照没有检验模型理解能力。

### 6.1.1 极简 Delivery 对照（用户选定）

不修复杂Delivery，保留其原行为作对照。冻结同一候选池、认识正文和JEV选择结果；另一路只要求认识已授权、引用属于本角色已知Source、已被JEV选中，直接交付正文、来源类型、反证是否仍存在和少量关键证据。

认识标为主观、可修正，不成为权威世界事实。证据可以按预算摘选，不要求支持全为直接观察/已接受行动，也不要求整个Evidence Group必须完整进入预算。部分反证未展示时，仍保留反证存在、总数/已展示数与不完整标记，不能声称已核实或冲突已解决。授权、引用、时间、预算与Rulebook提交边界继续严格验证。

这条路径替代的是主观认识的全支持真实性门槛与完整证据组取消规则；全体原引用不删除。非认识证据投影复用现有实现，不扩大为整个交付体系重写。先确认正文实际进入角色请求，再做下述消融。

### 6.2 再比较 JEV 是否值得保留为必经步骤

冻结上一阶段选定的同一候选池和阅读预算，两臂都采用极简Delivery：A沿用当前JEV；B不经过JEV，沿用已有排序与确定性授权/引用/预算检查。B从相同授权候选池选择，不伪造JEV接受。不改JEV协议，不新建角色模型筛选器。

增加同对象无关刺激和不同对象刺激作为负对照。比较实际阅读噪声、必要材料遗漏、角色回应、真实行动、模型调用数和等待时间。跳过一次调用只是直接成本收益，是否抵消角色理解噪声需要看结果。

若 B 经常将无关旧事带入对白，就保留 JEV；若两者体验接近且 B 减少等待，则把 JEV 作为需要时才使用的选项。证据不足时保持实验结论，不先删除旧实现。

### 6.3 验证即时回应能否不等待认识整理

复用即时双牌结果继续测实际选择：比较“清楚交付原始证据、没有前置更新”与“交付已有更新认识”。不加入核实提示，不强迫执行。

区分 publish 建议和真实 perform；认识更新只在明确整理点执行。已有实验支持表达收益，尚不支持成组证据提高行动率，本阶段不得省略行动测量。

### 6.4 完成延迟后的行为闭环

在上述路径确定后，再复用现有更新器，将真实新 Source 接入已知认知家族。经过无关互动后，分别测试当前认识、旧认识、无认识。

逐段确认：相关认识自然进入候选 → 实际被阅读 → Character 提出行动 → Rulebook 接受 → 提交产生新 Source。若最终请求相同、各组记忆为空，行动差异属于采样波动，不能归因于认识。

只有这条链通过，才接入正常网页连续试玩。自动 Evidence Group / family 发现、多分支通用更新和正式 schema 改造继续延期。

## 7. 验收与取舍

| 项目 | 验收方式 |
| --- | --- |
| 隔离与事实边界 | 对应测试和来源审计：未授权内容不可见；对白不触发 Capability；拒绝或失败不提交行动与证据 |
| 候选与阅读 | trace明确区分未进候选、JEV拒绝、预算未读；允许证据摘选，但反证存在和不完整标记必须保留，原引用不可伪造或删除 |
| 当前理解 | 角色能表达不确定或分歧，无关旧事没有经常被硬塞；逐样本阅读，不只统计关键词 |
| 行为 | accepted + committed 的 perform/interact才算执行，publish中的计划不计完成 |
| 长期认识作用 | 延迟后自然交付，且与旧认识/无认识相比出现可追溯的实际选择变化；小样本只作条件证据 |
| 简化收益 | 记录实际模型调用和整段等待时间，连同噪声与遗漏；不只按代码行数或 token判断 |

接受偶尔遗忘、主观判断不确定和暂时无法收敛的矛盾。不接受权限泄漏、把话语当成规则提交事实、丢失必要反证后还表现为完整认识。

样本先复用现有三段短历史并做少量重复，报告逐次选择和失败。不声称统计显著或稳定概率，不新建池化标注/AUC设施。通过后正常试玩中记录怪事回合，按真实问题决定下一项投入。

## 8. 实施与退出边界

先在实验目录增加一个明确的简化对照入口，复用现有桥接、授权快照与日志；不新增通用接口层、不复制完整核心、不修改 World State / Event Log / Rulebook 或正式 Memory schema。

如果简化路径表现更差，停止接入并保留旧路径；实验记录不删除，但不必为临时配置建设永久兼容机制。后续确需接入正常试玩时，再明确替换哪些必经调用，避免两条完整链路长期叠加。

这份方案收缩的是语义处理次数，把理解交回角色模型。宿主继续保证授权、引用、预算、执行与提交；模型无法恢复未交付材料，也不能代替程序保证权限。
