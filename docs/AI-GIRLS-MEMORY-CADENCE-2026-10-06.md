## 2. 如何测量遗忘

先向实际在场的两人自然告知三项安排：项目代号“银杏电台”、周末在旧书店门口见面、礼物避开香薰蜡烛及气味敏感的原因。接着穿插正常闲聊，在之后第5、10、15轮分别询问一个方面；问题不给出答案。第16轮再检查项目代号。每轮保留玩家转录、实际Character请求、Core召回与计时，分别检查信息是否仍在近期观察、自身表达或长期交付中。

Claude第5轮主动复述了三项内容，其中没有复述气味敏感的原因。它的这次回复定向发给玩家，GLM没有获得该提醒。因此不同角色的保留时间必须按自己最后实际收到或说出的内容计算，不能按玩家屏幕上的整段转录计算。

旧长期档案前缀为175，新安排的授权Source在386/387及之后。Core模式不走原生自动/主动召回，尚未整理的新Source不会自动加入当前Python档案；近期窗口退出后，保存过原始经历不代表本次模型请求还能读到它。原始世界事件及Source仍在，没有发生数据删除。

## 3. 整理后的细节遗漏：不能归为频率问题

第10轮旧礼物追问中，Claude收到完整原始发言，包含香薰蜡烛和气味敏感；GLM收到一条关于自己前后记忆不一致的主观认识、一个旧提问、以及过去“我不记得”的答复。GLM因此只答出禁忌，遗漏原因，并再次说玩家“应该没提过”。

离线复核：GLM长期档案的`atom:event:387:0`和`:2`均包含原始原因，在本次召回候选中分别排第6和第7；实际三项Delivery没有把它们交付。原始信息不是未整理、被删除或角色越权读取失败，而是本次选择和交付没有带入问题所需的细节。第5轮提醒、本次整理、紧接整理后的正确回答，以及后来的部分遗漏均保留，未通过换问法反复重试挑选成功结果。

## 4. 耗时与继续试玩的体验

31次玩家输入全部正常提交，62次Character调用均返回，没有这轮的30秒截断或格式错误。整轮8.81—18.88秒，中位数12.95秒；首条可见NPC回复4.57—12.15秒，中位数8.36秒。这是两角色、主要定向对白的轨迹，不能据此宣称四角色30秒问题已解决。

Character prompt为11845—14763 token。固定认知压缩仍在生效，但连续长对白占据近期窗口，完整输入不会始终停在开场约8k token。62条角色回复中有22条含字面转义序列，最多两层反斜杠后接`n`；页面用文本节点渲染，会显示这些符号。本轮记录为文案/输出体验问题，未在频率测试中修改解析或做全局替换。

本机Node诊断客户端等待响应时发生`UND_ERR_HEADERS_TIMEOUT`，没有收到整理的完整HTTP结果；服务端继续处理，最终成功。没有重新提交，通过state轮询确认恢复空闲、四次成功构建、更新档案及随后的实际回答。Core后台连续构建区间约458.59秒，四次构建相加458.27秒；HTTP耗时不能填写成成功458秒。Node客户端约300秒的响应等待限制不等于浏览器必然在5分钟失败。

前轮约154秒与本轮458秒都是实际阻塞等待。当前建议在重要信息或场景段落结束时人工考虑整理，尚不能接受“每6—8轮强制暂停几分钟”的默认体验。等待频繁程度、四人参与密度、不同档案规模及Utility耗时分布仍需更多自然轨迹；本次已经提供进一步处理整理等待的具体证据，不以一次测量推导稳定线性增长。
