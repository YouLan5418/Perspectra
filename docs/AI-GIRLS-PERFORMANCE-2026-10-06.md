# AI美少女包：真实模型耗时追踪（2026-10-06）

## 1. 范围与计时口径

| 属性 | 内容 |
| --- | --- |
| 世界包 | `examples/world-packs/ai-girls-awaken-v10`，v5源包，四个NPC |
| 入口 | 实际本机网页HTTP接口；原生记忆与简化Core各用一个新存档 |
| 模型 | 本机8046网关，请求别名`gemini-3.7-flash`；不据别名证明底层身份 |

| 工作 | 11次输入（含2次移动）+1次手动整理；41次角色HTTP尝试、12次整理Utility调用 |
| 改动 | 临时本机测量探针与本报告；没有改变运行时、世界包、角色顺序、提示词、预算或重试策略 |

使用原有运行时与服务器，通过临时脚本包装`PrototypeCharacterTurn.run`、`PlaytestMemoryCore.project`、模型HTTP和原有Python桥。Python探针细分提炼、分组、认识整理、索引、嵌入及初始化，回包仅额外记录网关提供的usage。计时日志不记录请求正文、认证头或密钥；现有Core私有trace仍只留本机。

客户端HTTP耗时从提交开始到完整响应正文读取完毕。输入归属按同模式的实际开始/结束时间窗口校验，而非依赖HTTP服务回调继承客户端异步上下文。模型HTTP含网络、网关、生成、响应读取与JSON解析，无法在本轮进一步拆出远端排队或首token时间。表中的调用数是进入HTTP探针的尝试数（包括取消），不等于调度器预留的调用计数。

每750毫秒读取一次现有玩家state，对照游戏页的750毫秒轮询。此轮通过相同HTTP接口实际推进游戏，没有操作真实浏览器或测量DOM绘制。

## 3. Evidence → Finding → Path

| Evidence | Finding | 优先处理方向 |
| --- | --- | --- |
| 原生四轮总耗时24.02—30.32秒，模型HTTP每轮占98.1%—98.5%，宿主其余0.43—0.53秒 | 当前原生路径主要等待模型，数据库与宿主CPU不是本轮主要瓶颈 | 先看请求体积和串行调用次数；不以重构存储作为第一项优化 |
| 角色HTTP成功请求原生5.10—9.59秒、Core3.54—10.01秒；共有6次HTTP尝试被期限中断 | 四角色逐个响应累加，操作/回忆后的再次决策还会占用调用时间 | 依据实际参与者与已提交观察审视调度，不预先规定角色情绪或强制其沉默 |
| 11次输入有7次约30.3秒结束，均为反应期限中断；其中一次在Core召回阶段取消，没有发出该角色后续HTTP | 默认30秒是当前四角色世界的实际体验限制，后面的角色可能没有完整回应机会 | 不能把这些截断时长当作完整回合速度；单纯提高期限只会允许更长等待 |
| 首轮Claude激活约6.22秒已结束并提交，输入24.02秒返回；轮内31次state读取均未出现新增NPC转录 | 已提交回应没有及时呈现，玩家体感等待被整轮处理放大 | 优先评估在角色提交后刷新玩家授权转录；无需先把模型输出改成token流 |
| 成功角色请求的网关prompt_tokens约9356—13228；Core首轮固定cognition约14012—14545个JSON字符 | 固定认知投影是较大的重复输入，称呼、关系、目标等被完整结构化交付 | 检查哪些结构字段不帮助角色决策，做内容保持的更简洁呈现并复验人物自然度与隔离 |
| Core整理前投影每轮仅0.06—0.10秒，没有Python召回进程 | 开关与授权快照本身不是明显等待来源 | 不把Core所有成本混成一个笼统的“记忆慢” |
| 9次需新嵌入的完整Core召回各4.68—4.79秒；10份初始化完成记录均3.42—3.50秒（含随后被取消的一次召回）；一次无需初始化的召回1.03秒 | 每次短生命周期Python进程会重新加载ONNX模型；相同查询缓存能省加载，但新查询继续支付初始化 | 优先评估如何复用既有模型加载结果；没有证据要求替换检索算法或恢复复杂Delivery |
| 饮料回忆输入27.80秒：三次角色HTTP合计13.16秒、Core投影14.22秒、其余0.41秒 | 整理后的记忆成本已接近角色生成成本 | 同时观察每次召回开销和不必要的重复召回，不只比较模型生成时间 |
| 最后一轮仅DeepSeek：10.91秒=模型5.82秒+记忆4.79秒+其余0.31秒 | 参与角色数直接影响总等待，单角色仍有约5秒Core前置成本 | 用这个场景作为后续局部优化基线 |

默认角色顺序按characterId排序，为Claude→DeepSeek→GLM→GPT。点名GPT的普通发言仍可能被其他同场角色观察，调度没有据自然语言点名将GPT提前；因此点名不能保证最快回应。该观察不意味着应剥夺其他角色自行回应的机会。

源码依据：`tests/experiments/playtest-view.ts`的`playtestModelCharacters`排序；`packages/application/src/prototype-activation-cycle.ts`的顺序await与期限；`tests/experiments/playtest-frozen-runtime.ts`的`submit`最终refresh及缓存state；`tests/experiments/hindsight-python.ts`的逐次execFile；`experiments/hindsight-core/vector_core.py`的进程内`_MODELS`及查询文件缓存。

网关usage仍报告reasoning_tokens；Character请求现有`thinking: disabled`不据此证明网关实际关闭了推理。模型/网关对该参数的解释没有在本轮核验，不能把全部延迟归因于推理token。

## 4. 整理成本与实际行为

一次四角色整理156.59秒，依次构建Claude、DeepSeek、GLM、GPT，各约41.40、35.22、40.38、39.29秒。

| 阶段 | 耗时 | 说明 |
| --- | ---: | --- |
| 提炼、分组、认识整理的12次Utility模型调用 | 134.93秒 | 占总时长约86.2%；三个流程阶段内部包含这些调用，不能双计 |
| 索引构建 | 16.31秒 | 内含嵌入16.30秒、其中模型初始化14.54秒 |
| 其余 | 5.34秒 | 含Python启动/导入、授权快照、验证、文件读写等残差 |

整理前后世界head均181，没有新增权威事实。之后GPT实际回答记得“柠檬茶”“不喜欢太甜”；这只能说明本轨迹实际可用，近期观察仍可能包含偏好，不证明独立长期记忆收益。Core移动后DeepSeek实际跟到客厅，随后正常回应；本轮没有为了获得速度数字固定模型决策。

## 5. 验证与限制

完成计时一致性校验：12阶段均收到HTTP200；41份角色HTTP计时全部归属输入窗口，其中35次返回usage、6次被取消；12次Utility返回；各阶段残差为正且小于1.1秒；整理前后世界前缀不变。HTTP200不等于反应完整完成，7次中断已单列，未选择性重试失败回合。

本轮仅文档和本机临时诊断，没有运行时行为修改，没有运行完整check、单元套件、硬崩溃或桌面发布测试。没有进行完整权限审计、长期自然度验收、并发用户负载测试、真实浏览器绘制测量或远端网关性能拆解；一条自然轨迹不能作为稳定分位数或跨记忆模式因果收益。

本轮服务保留在本机，继续使用这份Core存档；临时探针继续记录角色HTTP、Core投影和Python阶段。后续手动输入不会自动进入已冻结的12阶段汇总。脚本在忽略目录，是本次诊断记录，未接入桌面启动器或默认运行配置。
