## 1. Evidence → Finding → Path

实验 08 用显式命令隔离了玩家意图解释，没有验证自然输入。当前真实基线证明这个缺口会影响实际玩法：翻页、临时拿起查看再放回、挪到灯下，都被原解释器映射为 `base:take`；“暂放桌上，仍由我保管”被映射为 `base:drop`。

本次只修改现有输入解释请求的语义说明，并补充既有可选角色 ID 对应的公开姓名。沿用原解释模型、候选格式、原文绑定、Action / Rulebook / Event 路径。没有新增 NLP 分类器、语义审查、继承体系、状态字段或事件。

Jev 继续在正常发布后审查、对账和记录；没有启用 `publicationAudit`，没有修改发布、World 或角色认知。

## 2. 固定前缀的真实输入探针

### 2.1 方法与边界

复用雨站失物台 Pack 和正式 `preparePlayerIntent`、Provider、`bindPlayerIntentCandidate`。固定 World 初始前缀，按案例在内存中加入合法形状的保管迁移，形成玩家保管、陆舟保管和无人保管三个条件。合成前缀用于隔离语义解释，不声称这些前缀经过真实事务提交；完整事务另由连续试玩验证。

每个案例两次真实调用。保存原请求、原模型答案及绑定结果。探针不提交动作、不唤醒 NPC，前后 World 一致。正式迁移案例另核对物品及接收人的精确参数。

意图明确的案例包括翻页、临时查看归还、桌面挪动、自己保管时暂放、查看别人的保管物、收进随身包纳入保管、正式转交、解除保管，以及向 NPC 邀请和不可用的自身转交。

另有两个边界样本：孤立“我拿起日记”期望澄清是否纳入保管；孤立“我放下日记”期望只作物理放置。这是本实验的解释约定，不代表产品已经稳定执行了该约定。

### 2.2 结果

| 版本 | 调用 / 符合预期 | 明确意图样本 | 剩余失败 |
| --- | --- | --- | --- |
| `baseline` 原解释契约 | 24 / 12 | 12/20 | 四类物理操作各两次误迁移；裸拿起、放下也误迁移 |
| `aligned` 统一保管语义 | 24 / 21 | 20/20 | 拿起两次自动取得保管；放下一次自动解除保管 |
| `named` 最终契约，加姓名映射 | 26 / 24 | 22/22 | 拿起两次仍自动取得保管 |

最终新增两次“转交程雨”样本，均选择正确的 `character:friend`；陆舟样本选择 `character:companion`。其余受控样本的物品目标均为日记。

明确说“不接管”“仍由我保管”“交由某人保管”时，当前契约能改善解释。**裸动作依然没有通过。** 不继续根据这些答案反复调整提示，不将这组重复样本视为泛化准确率或分叉概率降幅。

## 3. 连续自然输入试玩

### 3.1 方法

每段新建独立数据目录；所有 11 轮玩家输入都经自由文本解释，没有 `/act`。前三轮查看、临时拿起归还、收进随身包；第四轮暂放仍保管；第五轮转交指定 NPC；第六至九轮闲聊；第十轮邀请保管人暂放并整理衣袖；第十一轮固定为：

> 陆舟，麻烦把布面日记交给我，方便我收台。

比较日记归陆舟或程雨保管的两个条件。角色自主选择，调度、预算、性格、权限规则未改。正常发布后 Jev 只审查日记；不据此宣称怀表和其他事实也被完整审查。

### 3.2 第一对条件暴露的错误

`live-companion`：正式日记迁移顺序为玩家取得、玩家交陆舟、陆舟末轮交玩家。第十轮却把“陆舟，你可以……”截成玩家的 `narrate`，删掉称呼和邀请部分，发布“把自己保管的布面日记暂放桌上……”。seq198 因此错误宣称玩家保管，而正式 holder 仍为陆舟。

`live-friend`：第五轮自然输入明确写程雨，实际解释成转交陆舟，正式 seq88 接收人为 `character:companion`。NPC 随后依据实际 World 承认陆舟保管；第十轮程雨纠正“日记不在我手上，在陆舟那儿”。这段没有建立程雨保管条件，不能计作预期对照通过。

检查请求发现解释器只有不透明角色 ID，没有姓名映射。最小修复是在既有 Host 契约中提供**已被 affordance 引用的角色**的 ID / name，不发送完整角色名册、私密信息或远处角色。没有扩大模型执行权限。

### 3.3 最终两条件的实际选择

修复姓名供给后，重新跑两段原协议，未修改刺激文本：

| 项目 | `live-companion-named` | `live-friend-named` |
| --- | --- | --- |
| 第五轮正式日记接收人 | 陆舟，seq88 | 程雨，seq101 |
| 第十轮暂放 | seq176，自由表达，holder 仍陆舟 | seq217，自由表达，holder 仍程雨 |
| 末轮陆舟请求中的日记 holder | 陆舟 | 程雨 |
| 末轮陆舟决定 | `perform base:give`，接收人为玩家 | `publish`，说明应找程雨 |
| 末轮正式事件 | seq194 陆舟 → 玩家；seq200 才发布“给。收吧。” | 没有尝试或提交日记转交 |
| 程雨的选择 | 观察已正式发生的转交 | 说明自己保管，并追问请求是向谁提出的 |
| 总模型调用，含解释器 | 35 | 42 |
| NPC 发布 | 23 | 29 |
| 日记影子记录 | 32/32 | 38/38 |
| 审查失败 / 冲突提示 | 0 / 0 | 0 / 0 |

`review.json` 保存末轮实际请求中的 items、affordances、观察/召回来源序号、原决定和提交事件。程雨条件下陆舟没有日记 give 选项；他未尝试无权限动作，也未在叙述里冒充成功。这里不是“模型先越权、被 World 拒绝后才修正”的成功。

两条件的第一至四轮均完成临时查看不迁移、取得个人保管及暂放不解除的预期路径；第五轮均按指定接收人提交。22 轮全部输入完成。

### 3.4 这个结果证明到哪里

支持：**保管事实跨多个回合持续进入角色请求，可以对应不同的后续行动或拒绝/澄清选择。** 桌面物理放置与个人保管能共存，角色无需把“桌上”理解成任何人都能转交。

不能据此证明长期记忆、认知更新或无提示主动履约已经稳定。末轮前一轮明确提及保管，当前 items 本身也直接提供事实；陆舟条件下原转交观察仍在近端 16 条窗口内。程雨条件下陆舟近端观察从 seq139 开始，原转交 seq101 已退出，旧转交观察 seq103 仍进入召回，items 也直接显示程雨保管。

两段后续自由对话有差异：程雨条件下陆舟自行取得怀表保管；角色反应数量、话题和记忆选择不同。不是只改变 holder 的严格因果 A/B，也没有重复足够次数来估计成功概率。

体验仍有缺陷：陆舟条件末轮程雨 seq205 / seq211 逐字重复表达；程雨条件有多次预算耗尽通知。此次没有扩大到调度修改。

## 4. Jev 的实际帮助和边界

全部四段开发试玩共 44 轮、137 条日记影子记录。全部完成，0 调用/审查失败、0 跳过；四段排空审查前后 World 摘要均未变化。Jev 总费用 $0.051705822，不含 DeepSeek。

它在 `live-companion` seq198 抓到上述真实错误：发布宣称玩家保管，当前 World 保管人为陆舟。这提供了定位输入解释主体错误的线索。

seq204 后续仅写“玩家刚搁下的日记”，是对物理放置的回述，没有明确宣称保管归属。Jev 又推导成玩家当前保管并报冲突，引用 seq198，却另建 root204。按本轮边界，这条保管判断属于过度推导，不能计为稳定的虚构链传播发现。

最终两段没有冲突提示，与重点表达的人工核对相符；但不能用无警报证明所有叙述均正确。本轮人工核对由当前 Codex 完成，非独立盲评。没有新增合成分叉注入测灵敏度，未重验正常历史回忆和完整虚构链召回矩阵。

**继续保留 Jev 影子模式。它能帮助找到具体错误，但不承担阻断、自动修复或事实证明。**

## 6. 判断与下一步

可以继续使用“受控保管关系 + 自由物理表现”的方向。明确意图已经能沿正式路径结算，持续可见事实也能影响跨回合选择，没必要因此加入继承框架或更复杂自治机制。

下一步的具体缺口在**自由输入解释**：孤立拿起仍会默认改变保管；NPC 邀请偶尔被截成玩家自身动作。先围绕主体归属、原文保留和歧义处理做少量未见输入验证，不把当前结果扩大成“所有自由输入都可靠”。Jev 原样提供发布后线索。

若下一轮要验证经历自身的持续影响，应去掉第十轮保管提示，拉开观察窗口，并单独区分当前 items、旧经历召回和角色选择三层证据。此项尚未执行。
