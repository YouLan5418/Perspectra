# Gemini 记忆阶段复测：长程约定与主动查询边界

> 2026-09-28；Perspectra V1 当前工作区。请求模型 `gemini-3.7-flash`，本机 8045 响应字段为 `gemini-3.7-flash-tiered`。所有试跑使用新的 `.tmp` 存档，未改动历史试玩数据。

## 问题与修复

网页试玩已用平铺的工具参数 schema 解决 Gemini 对根级 `oneOf` 的兼容问题，但独立的主动记忆实验仍发送旧 schema。旧脚本的三个提问全被模型选为 `abstain`，不能据此判断 Memory 检索失败。本轮将现有 Gemini 请求格式提取为 `tests/experiments/local-prototype-turn-call.ts`，网页运行时与主动记忆脚本共用；角色决定仍经过原有验证，世界状态仍由 Rulebook 和 Event 路径提交。

同样三个提问在新独立存档中全部得到 `publish`，未泄露另一角色的私密观察，也没有改变物品的正式 holder。三次请求的旧取得观察与旧说法已在首次模型请求中，模型均未主动选择 `recall`。因此这只验证了兼容格式与自动呈现的旧证据能支持回答。原始结果在 `.tmp/active-recall-gemini-flat-20260928-1804/` 与 `.tmp/active-recall-gemini-flat-20260928-1805/`。随后用更间接的提问做两次新存档复测，模型两次主动查询“鲍勃 杯子”并完成回答；但两条旧证据原本已在首次请求，去重后的 `recallEvidence.memories=[]`。实验脚本现将“出现召回结果字段”和“真正返回新证据”分别记录，避免空结果被误报为成功。结果见 `.tmp/active-recall-gemini-indirect-20260928-1820/` 和 `.tmp/active-recall-gemini-indirect-20260928-1830/`。

## 长程约定／无约定对照

沿用现有 `prototype-g1` 的 24 轮脚本；两组只替换首轮私语，其余输入一致。第 12 轮后关闭并重新打开存档。首轮有约定组，玩家私下提议“打算去后室时提醒看门缝有没有光”，同行者回复“好。”；无约定组只谈前室的桌子。末轮玩家仅说打算去后室，没有直接要求提醒。

| 组别 | 末轮同行者第一次回复 | 末轮请求中的相关旧经历 | 存档 |
| --- | --- | --- | --- |
| 有约定 | “看看门缝有没有光。” | 玩家私语 `sourceSeq=22`、同行者回复“好。” `sourceSeq=28` | `.tmp/frozen-playtest-drive-2026-09-28T10-04-58-755Z/` |
| 无约定 | “好。” | 没有门缝约定 | `.tmp/frozen-playtest-drive-2026-09-28T10-08-10-063Z/` |

两组各 24 轮、48 次模型请求，全部 HTTP 200。末轮同行者都在前室；有约定组的 `observations`、`selfObservations` 与其余当前上下文不含“门缝”，该内容只在长期 `memories` 中。留守者的末轮请求不含私语正文。有约定组并非每轮都呈现玩家最初的私语，末轮 `sourceSeq=22` 重新进入模型请求。

这是一组探索性轨迹，支持“旧经历经自动召回进入角色请求，可能改变随后自主表达”。首轮“好。”没有明确复述具体承诺，不能把它当成严格的角色自选承诺验收；也不能从单组对照估计稳定成功率或证明主动查询已通过。两组中间角色表达不同，因果结论只限于本次可见请求和末轮差异。

## 冷来源主动召回：补回原始经历

在原脚本已有的 `--away`（鲍勃离开同场）和 `--indirect`（不说“鲍勃／杯子”）条件下，做了三次独立新存档复测：`.tmp/active-recall-gemini-away-indirect-20260928-1840/`、`.tmp/active-recall-gemini-away-indirect-repeat-20260928-1850/`、`.tmp/active-recall-gemini-cold-metrics-20260928-2020/`。

| 证据 | 发现 | 处理 |
| --- | --- | --- |
| 三次首次请求的 `memories=[]`；近期 `observations` 来源为 `seq=20–35`，不含 `seq=13/14` | 两条旧观察原文没有自动进入请求 | 实验摘要记录首次记忆来源、近期来源与主动查询新增来源，避免把简短线索当作完整证据 |
| 首次请求的 `items.lastObserved` 只有角色自己曾观察到的“鲍勃取得杯子保管”，并注明不能确认当前归属；没有鲍勃声称交给玩家的原话 | 角色仍有合法的索引线索，但没有矛盾双方的完整来源 | 不移除这条线索，也不向角色注入他人私密上下文 |
| Gemini 三次自行发起 `recall`，分别查询“鲍勃 杯子 亲眼看到”“杯子 鲍勃 看到”“鲍勃 杯子 拿走 看到”；每次新增 `sourceSeq=13/14` | 主动查询确实补回亲见的取得动作和鲍勃的旧说法，不是空结果或重复已显示来源 | 保留现有一次激活一次查询与来源去重；本窄场景无需新增检索路线 |
| 三次均将鲍勃的“已交给玩家”区分为其说法，未泄漏另一角色的私密观察，召回没有提交新的物品迁移 | 来源归因和程序权限边界在本样本成立 | 继续按“亲见动作／他人发言／当前未知”分别评估角色表达 |

第一次回应说“杯子现在也还在鲍勃手里”，超过该角色在鲍勃离场后的可确认范围；后两次只说自己亲眼看到鲍勃拿走杯子，并把后续交给玩家归为鲍勃的说法。实际 World Event Log 的 holder 仍是鲍勃，但恰好说中世界真相不能替代角色的认知边界验收。这个越界表达只在三次中出现一次；先保留为真实体验反例，暂不为它增加文本分类器或新的状态协议。

## 时间归属假设：离场后发生了不可见变化

为核对“把过去当现在”的原因，实验脚本增加 `--offscreen-drop`：鲍勃离开同场后，在角色视线外把杯子放到下一地点；没有给 NPC 添加该变化的观察。三次独立新存档位于 `.tmp/active-recall-gemini-offscreen-drop-20260928-2050/`、`.tmp/active-recall-gemini-offscreen-drop-repeat-20260928-2052/` 和 `.tmp/active-recall-gemini-offscreen-drop-repeat2-20260928-2053/`。

这三次世界中的当前 holder 为 `null`，而首次模型请求与无暗中变化的对照一样，仍仅显示 `items.lastObserved`：“鲍勃取得了杯子的保管”，且明确注明目前不能确认归属或位置。首次 `memories=[]`；主动查询仍补回旧来源 `seq=13/14`，没有泄漏暗中放下的事件。三次答复都把亲见的拿取与鲍勃的发言区分开；其中一次“由他保管着”的时态较含糊，但没有明确断言“现在仍在鲍勃手里”。

因此，当前证据支持**历史观察的时态校准偶有失误**，不支持“运行时完全没有时间观念”这一更强结论：模型已收到“上次观察、当前未知”的区别，且在暗中变化的三次样本中基本沿用了过去时。原始 `sourceSeq` 也在记忆数据里，但角色请求没有统一的游戏时钟或显式的来源时间轴。本阶段先记录限制，不为一次随机越界表达增加时钟、状态槽位或文字审查层；若真实长程试玩出现持续的当前归属误判，再核对来源时间呈现是否需要最小补充。

## 当前决策与验证

本轮没有修改 Memory 检索算法、认知事件或世界事实协议。自动与主动召回各有窄场景 Gemini 正例；没有足够的新反例支持增加 Episode、Jev 精排、关系网络或额外的承诺状态。冷来源对照已验证主动查询能补回完整旧来源，但只覆盖一个物品争议场景；离场后暗中变化的三次复测尚未显示稳定的“旧状态当当前状态”误判。后续以真实长程试玩中是否持续出现这种偏差决定是否调整来源时间呈现。

改动前 `corepack pnpm@11.7.0 check` 通过（默认 108 项），Gemini 运行时与记忆相关 23 项通过。共用 schema 后类型检查与相关 11 项通过；真实模型复测包括 1 轮约定建立、11 个独立主动记忆提问及 2 组各 24 轮的长程对照。尚未验证跨世界包泛化、重复多次稳定性或浏览器视觉体验。
