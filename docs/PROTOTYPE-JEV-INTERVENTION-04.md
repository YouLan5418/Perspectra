| 属性 | 内容 |

| 日期 | 2026-09-27 |
| 分支 | `codex/jev-shadow-minimal` |
| 范围 | 实验 Host；两件物品、两名 NPC，prototype-g1；核心生产包不变 |

| 假设 | 发现明确客观持有冲突后修正一次，可以减少最终发布的分叉及后续传播，且误干预与成本可接受 |

## 1. 实验实现与事实边界

角色沿现有 perform → 正式结果 → publish 路径行动。实验 Host 包装既有模型 decide：只有 publish 返回后、表达进入 World/Observation 之前才进行审查。无需增加核心发布钩子，也没有把正常回合改为强制行动优先。

- A：原始表达直接提交；Jev 事后影子记录。额外记录草稿，不等待审查。
- B：每次 publish 对两件物品并行审查；本地按当前 World 与最近一次玩家行动边界对账。有明确 OBJECTIVE_NOW/NEW/DURING 冲突才请求主模型修正一次。
- SPEECH_NOW/PAST、OBJECTIVE_PAST、未确定来源不触发修正。不以角色对白错误为由禁止说谎、回忆或争执。
- 修正只能 publish 或 abstain；不能 perform，不能更改原来的收件人。正式行动已经提交，不重新执行、不回滚，也不修改 World 的物品状态。
- 超时、调用失败、修正格式或收件人不合规则回退原表达；不循环重试。最终发布继续由现有影子日志审查，仅用于观察。
- 仅当物品在原角色请求 `items.current` 可见时可触发修正。反馈复用该角色原 Context 和可见执行结果，不附世界全量持有历史。
- Jev 只得到角色/物品元数据、表达和已观察过的历史表达；不发送私有 cognition、goals、anchors。后来收紧至同一事务中逐条匹配已观察表达，防止同一玩家事务中一条公开表达为另一条私密表达授予访问。

最近玩家提交至当前 head 的窗口沿用上一轮规则。待发布表达使用 `baseHeadSeq+1` 作临时识别位置，不构造或写入假的 World 事件。原角色调用预算和 30 秒激活时限不扩张；修正是另外统计的额外主模型调用，不计入原决策步数。

## 2. 失败样本预检

冻结四条真实负样本和一条真实事故，各重复三次：15 调用，目标人物类别匹配 6/15。修正提问仅补充“结合明确的历史提问理解刚拿到”，不是通过程序关键词过滤。

| 样本 | 结果 |
| --- | --- |
| Live-04 seq144，明确回答过去拿钥匙经历 | 3/3 从 SPEECH_NOW 改为 SPEECH_PAST |
| free seq139，摸钥匙后归还但未正式持有 | 3/3 OBJECTIVE_DURING |
| seq56 邀请拿钥匙、seq117 已给别人、seq133 旁观杯子 | 仍错误判为 SPEECH_NOW，各 3/3 |

这些负样本没有客观类别误报，因此不触发本轮干预，但不能宣称时间/人物判断已全部修好。

重复相似经历的反事实再跑：前三项正确，最后回述错误指向旧的真实经历，得到 HISTORICAL_SUPPORTED，而非新虚构链。仍是 3/4，且这次比未确定更差。**传播归链没有验收通过。** 本轮继续实验的范围据此限制为首次客观持有冲突，不用历史关联自动修改记忆。

## 3. 连续试玩设计与审阅

3 对、每场 20 回合，总计 120 回合；六个独立新存档。相同 Pack、模型、参数、输入顺序。输入含拿起、正式交付、观察/触摸、正常回忆、短暂接收归还和相似经历对照。对白用既有 `/act speak` 保证不被输入解释器误当移动；第 14 轮用正式 `/act interact` 向留守者交付钥匙。NPC 输出没有预写。

每场 protocol 在第一轮模型调用前保存；六场实际 submitted 文本逐项相同。六场并发运行，模型随机输出不作可重复种子保证，也不是同一模型输出的反事实分叉。

审阅共 349 条 NPC 最终发布：先按匿名 ID 打乱、隐藏组别及 Jev 标签，对文本与截至发布时的正式物品事件逐条核对，再揭组统计。审阅者为当前 Codex 主代理，**不是外部人工评审；此前已读部分修正记录，不是严格盲评**。原文、判定和映射保留供复查。

主要统计“存在明确客观归属冲突的发布条数”，同一虚构在多条旁白持续出现会逐条计数，**不是独立事故根的数量**。另区分人物持有与地面/桌面放下。未完成递出、伸手去拿、等待接稳后才放开不直接认定转移完成；角色对白单独记录，不升级为客观事故。

## 4. 最终文本结果

| 场次 | NPC 发布 | 未支持的人物持有 | 未支持的放下/桌面归属 | 修正调用 | 主模型总调用 |
| --- | ---: | ---: | ---: | ---: | ---: |
| A1 | 53 | 0 | 0 | 0 | 62 |
| A2 | 69 | 1 | 0 | 0 | 73 |
| A3 | 60 | 18 | 0 | 0 | 62 |
| B1 | 62 | 0 | 0 | 2 | 67 |
| B2 | 54 | 0 | 6 | 1 | 59 |
| B3 | 51 | 0 | 0 | 2 | 56 |
| A 合计 | 182 | 19 | 0 | 0 | 197 |
| B 合计 | 167 | 0 | 6 | 5 | 182 |

人物持有这一窄范围为 19 → 0；加入放下后为 19/182 → 6/167，发布占比约 10.4% → 3.6%。原始条数减少约 68%，占比相对减少约 66%。**这些是本样本描述，不能作为总体发生概率下降百分比。** A 的 18 条集中在 A3 保温杯虚构连续链，发布不是独立样本；按对比较 A1/B1 都没有，A2/B2 从 1 增至 6，A3/B3 从 18 降至 0。只有三对且交互轨迹不同，不能宣布稳定大幅降低。

也不能用日志报警量作为效果：A1 的 5 条 CONFLICT 并非审阅确认的人物持有事故；B2 的 6 条放下分叉全部未报 CONFLICT。所有统计以逐条文本审阅为准。

## 5. 五次修正是否有效

| 存档 / 修正前 head | 原文问题 | 最终结果 | 审阅 |
| --- | --- | --- | --- |
| B1 / 95 | “把保温杯往自己这边挪了半寸” | 改成移开视线 | **误修**：杯子原本在桌上，挪半寸未改变声明追踪的归属/房间，无须正式拿起 |
| B1 / 426 | 旁白“朝玩家手里的钥匙看了一眼”，正式 holder 仍为留守者 | 改成看留守者，并要求先递过来 | 正确修正客观持有人错误 |
| B2 / 176 | “把保温杯拿起来，掂了掂”但未正式拿起 | 改成伸手，未完成拿起 | 正确；下一次角色自行 perform，正式 seq188 拿杯，随后旁白可正常端起 |
| B3 / 37 | “把钥匙捏起来”但未正式拿起 | 改成凑近观察，没有伸手 | 正确；后续正式 seq56 拿钥匙 |
| B3 / 379 | “接过钥匙……递回玩家手里”，本轮没有实际转移 | 改成“钥匙你递过来，我看完就还你” | 正确消除既成事件，但未阻止后来虚构回忆 |

5 次均格式有效并实际进入正式发布；4 个真实冲突草稿在修正后不再有原冲突，1 次不必要干预。没有自动删除物品、补转移或泄漏审查说明。修正保持对白/收件人及语气较自然，但没有用户自然度评分，不能视作完整体验验收。

## 6. 传播与剩余失败

### 6.1 放下遗漏仍向其他角色传播

B2 的杯子在 seq188 正式由留守者持有；seq365/370 旁白写已搁回桌上，正式没有放下事件。钥匙在 seq296 正式交给留守者后仍由其持有，但 seq407 写“把手里的钥匙往桌上一搁”。随后同行者 seq413/436 都以“桌上的钥匙”继续客观叙述，留守者 seq430 也如此。

这是**当前检测范围未覆盖的客观分叉和跨角色传播**。B2 不能因为影子日志 0 CONFLICT 被算作成功。

### 6.2 首次旁白修正不保证后续回忆真实

B3 seq380 已发布的是未来邀请“钥匙你递过来，我看完就还你”，没有假接收归还。后续 seq396 却说“钥匙是你递过来的，看完还你了”，seq412 又重复；正式 holder 自 seq299 起一直为留守者，本段未发生交接。

因此可以确认首次客观虚构被修掉，但后续角色仍能自行产生主观虚构经历。不能把这两个回忆当成原未发布文本已经传播的证据，也不能宣称认知/记忆污染已清除。本实验没有输出给角色的虚构链标记或记忆删除机制。

另保留 A2/A3 的未支持回忆样本，供后续来源分析；不把角色说谎或误记自动改写成权威事实。

`corepack pnpm@11.7.0 check`：TypeScript、Lint、13 文件 / 94 测试通过。实际运行时 fixture 验证：受控拿起只提交一次，修正发生在 Observation 前，原虚构没有进入 World/Observation，受众不变；失败/非法修正回退、不调用新行动；私有 Context 和同事务未授权表达不发送 Jev。

试玩后收紧历史表达可见性筛选；对 B 的全部 167 次草稿前缀复算，新旧筛选结果一致，因此没有改变这轮模型所见输入。没有额外重跑六场。未运行全部历史测试、崩溃恢复或外部人工验收。

## 8. 结论与下一步

**本轮首次得到“检测 → 修正 → 实际发布”的真实模型证据。** 四次明确冲突修正有效，额外主模型调用很少，不需要重做核心执行路径，值得保留实验入口。

但整体验收仍未通过：1/5 误干预；放下分叉漏检且跨角色延续；后续对白能自行构造经历；正常类别及重复经历来源仍不稳定。总体结果受一场长虚构链主导，不能宣布 Jev 已稳定大幅降低所有事实/数据库分叉。

下一刀建议只覆盖两项已出现的问题：识别明确放下/桌面归属，并区分“挪桌面杯子”与实际取得物品；复用同一 World 对账与一次修正，不增加审查层。来源归链保留独立失败项。待这两项改好再做小规模同样对照；不要继续无改动地扩大试玩数量，也不要先建立自动记忆纠错系统。
