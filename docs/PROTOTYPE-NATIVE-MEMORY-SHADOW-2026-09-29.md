# 原型角色记忆语义影子接入：首轮真实试玩

日期：2026-09-29。分支 codex/native-memory-shadow。本轮只给 PrototypeCharacterTurn 增加可选的实验观察点；正式 Memory 召回、角色 Context、模型请求、World Event 与 Rulebook 裁定没有改变。Hindsight 服务和代码未进入运行链路。

## 实际问题与做法

合成问答证明语义排序能补同义漏召回，但尚不清楚真实角色互动的旧记忆是否因此受益。原型网页实际使用 PrototypeCharacterTurn，而不是旧 Phase8ContextPipeline。因此，在该角色每次自动召回及主动召回完成后，可选地记录：角色、世界地址、as-of 事件序号、真实查询、关键词来源 ID、最终送入角色的记忆来源 ID，以及已在近期 Context 中的来源序号。默认不启用；实验网页运行时启用后将其写到新数据目录的 memory-shadow.jsonl。

离线脚本 [native-memory-shadow-rank.py](../tests/experiments/native-memory-shadow-rank.py) 再按世界地址、角色 ID 与 as-of 序号从同一 memory.sqlite **只读**取来源，排除已有近期来源，并用本机 multilingual-e5-small ONNX 模型排序。输出仅列来源 ID、哈希、认识类型与分数；候选没有回写 Memory，也没有发给 Character Agent。它核验原本送入角色的来源都属于该角色当时可见的关键词结果。

## 当前决定与限制

影子接线可用，但**这一轮没有证据支持把语义候选送入正式角色 Context**。它证明了真实查询可被角色内、时间前缀内离线比较，也说明目前最重要的旧约定案例已经由关键词成功召回。下一步是挑选实际漏召回的连续互动，而不是直接增加索引、图谱或语义裁判。若后续证据表明“来源已到达角色却仍不影响行动”，应转向角色认知与行为使用，而非继续堆检索。

这是一个世界、一次长局与两次后续询问；没有稳定性统计，也没有生产在线语义延迟。离线排序的耗时不代表正式模型调用成本。角色是否持续相信未经裁定的叙事仍需另外试玩检查。
