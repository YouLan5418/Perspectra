# 玩家命令模式

| 属性 | 内容 |
| --- | --- |
| 日期 / 分支 | 2026-09-27 / codex/custody-transfer-experiment |
| 依据 | 用户明确要求停止猜测玩家意图；实验 10 的裸动作误迁移、NPC 邀请误执行和错误对象选择 |
| 改动 | 删除自由输入的模型解释准备；复用确定性命令适配和既有 Rulebook 提交路径 |
| 原则 | 普通文字用于表达，玩家受控状态操作只来自显式操作 |

## 1. 玩家可用入口

| 输入 | 含义 |
| --- | --- |
| 普通文本 | 完整作为玩家发言；没有意图模型调用 |
| `/narrate 我把日记暂放桌上。` | 自由表现；不解除保管 |
| `/move location:back-room` | 提议移动，Rulebook 裁定 |
| `/take entity:diary` | 提议取得指定物品保管 |
| `/give entity:diary character:companion` | 提议转交指定物品给指定角色 |
| `/drop entity:diary` | 提议解除保管，物品留在当前场所 |
| `/act interact {完整交互参数}` | 创作者声明的其他交互；沿用通用入口 |
| `/act speak {"text":"只告诉你。","scope":"private","addresseeIds":["character:companion"]}` | 明确私密受众 |

短命令只根据明确 ID 匹配当前交互选项；匹配不到或存在多个候选则要求检查命令，不猜姓名、不替换物品。通用 `/act` 及结构化 action 继续由规则重新验证。没有新增协议版本、分类器或审查阶段。

普通文本“我拿起日记，准备带走”现在是发言，不会替玩家执行 take；邀请“陆舟，你把日记放桌上吧”仍作为完整发言到达 NPC。NPC 自主执行受控交互的能力保留。

网页输入框增加命令说明，阶段提示改为“正在提交发言 / 正在执行命令”。当前仍要求明确 ID，尚未制作可点击交互菜单或名称映射。旧意图调用账本和实验资料没有删除；本轮新输入不进入模型解释准备路径。历史意图探针脚本应按当时源码快照复跑，不能作为当前命令模式验收。

## 2. 验证

### 自动化

- 用户上轮十句加移动句共 11 句，均完整提交为 speech，意图调用为零，重复提交幂等；NPC 固定 abstain，未发生物品转移或移动。
- 实际 take/give/drop 命令产生指定物品迁移；错误物品、无权解除保管和缺失接收人拒绝，不替换对象。
- 显式 narration 保留原文，不改变保管。
- 授权原文进入观察和记忆；私密旁观者与移动出发见证者不取得越权原文。
- 网页入口复合文本不再被解释成移动；显式 move 才移动。

最终 `corepack pnpm@11.7.0 check`：类型、Lint、15 文件 105 测试通过；网页 Runtime、玩家输入、命令适配/准备及 HTTP 服务相关测试：5 文件 21 测试通过。未修改事务恢复机制，未运行全量历史意图解释及硬崩溃测试；这些旧测试的自然语言执行预期不再是现行要求。

### 五轮真实连续试玩

证据：`experiments/jev-narrative-auditor/player-command-2026-09-27/`。DeepSeek `deepseek-flash`；Jev 仅影子。原有未提交记忆接线保留用于试玩，当时源码另存 sources.json，不纳入本轮提交。

| 轮次 | 输入 | 玩家操作 | 日记最终保管 |
| --- | --- | --- | --- |
| 1 | 我拿起日记，准备带走。 | speak | 无人 |
| 2 | /take entity:diary | interact，取得保管 | 玩家 |
| 3 | /narrate 暂放桌上仍由我保管 | speak/narration | 玩家 |
| 4 | /give entity:diary character:companion | interact，转交保管 | 陆舟 |
| 5 | 陆舟，你把日记放桌上吧。 | speak；陆舟自己 perform drop | 无人 |

18 次真实 DeepSeek 调用全部用于角色，没有玩家意图调用。19 个发布对应 38 条 Jev 影子记录，失败/跳过为零，费用 $0.012823776（不含主模型），排空未修改 World。

Jev 的记录为 29 个 NO_CLAIM、8 个 SUPPORTED、1 个 SPEECH_UNBACKED；seq26 陆舟的“日记你拿着”被标为无状态支持的对白线索，未作自动修复。

按用户后续明确的三层标准重新判定：第 1 轮陆舟说“日记你拿着”，程雨劝玩家别急着带走，可以属于角色对发言的理解或误解；日记仍无人保管。第 5 轮陆舟自行选择解除保管并经正式裁定提交，是 NPC 自主行为，不因偏离玩家预期就判为输入或主体性缺陷。期间还有预算达到上限通知，没有以这些输出宣称连续体验完整通过。

试玩脚本完成五轮后曾调用不存在的 drainShadow 方法导致导出失败；finally 中现有 close 正常排空审查。脚本已改用 close，依据持久化日志只读恢复 events/summary，没有重复任何模型调用。summary 明确记录该恢复；最终脚本没有另行真实复跑。试玩后另将纯 narration 的源跨度标为 narration，已通过准备单测；当时快照保留为实测证据，不冒称与最终源码逐字相同。

## 3. 接受的限制

本轮解决的是玩家意图误执行和原文裁剪入口。NPC 误解玩家、拒绝请求或据此选择不同动作，允许作为角色行为；不要求 NPC 总能恢复玩家真实意图。命令限制不等于语义分叉解决，也不让玩家替 NPC 决定行动。没有启用 Jev 阻断或自动改写。

## 4. 三层分离的验收标准（用户后续澄清）

| 层次 | 记录的意义 | 验收 |
| --- | --- | --- |
| 玩家说了什么 | 原始发言及受众 | 保留原文和说话人，不替换成 NPC 的解释 |
| NPC 理解成什么 | 角色的理解、信念、怀疑或转述 | 可以误解，也可以由此决定行动；保留认知主体及信息来源 |
| 世界实际发生了什么 | 正式行动经规则裁定后的事件与状态 | 不由玩家发言或 NPC 信念直接证明；以已提交事件为准 |

NPC 的对白“你拿走了”只证明它说了这句话，不证明玩家取得保管。错误认知被另一个角色听到、相信或转述，也不单独构成运行时失败；不得在传播中丢掉来源、自动升级成权威执行结果。

NPC 因误解而提出行动，若规则接受，则该行动的实际效果成为世界事实。规则裁定行为能否执行，不裁定 NPC 是否理解了玩家真正的意思。

Jev 的 SPEECH_UNBACKED 等记录继续作为线索，不能仅凭对白与 World 不一致就判为缺陷或要求改写。需要调查的是解释/传播是否把角色说法混同为已裁定的世界变化。

这是现行产品验收原则和对上述证据的重新判定，不表示认知、记忆和叙事传播中的所有来源边界已经得到实现证明。本次只修改文档，不新增认知状态槽位或语义审查。
