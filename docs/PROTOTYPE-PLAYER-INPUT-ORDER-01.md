# 玩家输入“表现＋移动”错序：最小修复与验证

日期：2026-09-23。对应 [G3 开放式试玩](PROTOTYPE-G3-FREE-PLAY-01.md)第 6、7 次失败。

原句是“我把钥匙握在手心，走进后室看看有没有能配它的锁。”两次解释都把后面的 `move` 列在前面的 `narrate` 之前。第一次还把移动前后的两段文字放进同一个 `narrate.quotes`，不符合单段表现文本的契约。Host 按候选动作顺序从原文中依次寻找引用；找不到前一动作之后的片段就拒绝候选。因此这两次没有经过 `validated → round_enqueued → World Event Log`，世界 Head 保持在 seq166。旧网页只提示“格式无效、重试同一句”，且发送时清空输入框；原句重试仍失败。

本轮保持了原有顺序校验与最多两项动作的边界，没有对模型候选自动排序。解释器契约增加一个“先表现、后移动、移动附带查看意图”的例子，要求各动作使用连续、按原文顺序的引用，不把移动后的目的语拼到前一个表现里，也不省略后面的有意义分句。Host 现在把“原文有该片段但次序错了”与“原文根本没有该片段”区分；前者在网页明确提示模型顺序错误和整条输入未提交。网页在输入解释失败、服务失败、需要澄清或暂停时恢复原文；玩家 Root 已提交而后续 NPC 处理失败时不会恢复，以免诱导重复提交。提交成功后，网页还按本次提交的 ActionId 查 `action.resolved`，对批量动作中后来被规则拒绝的项逐项提示，避免只看第一项结果而误报全句成功。如果模型只引用了移动片段而漏掉后面的有意义句尾，网页会明确指出该句尾未映射；已接受的移动不会被说成未提交。

验证：绑定器回归测试证明倒序候选仍被拒绝、正确顺序可绑定；网页运行时集成测试证明错误候选不会改变 Head，同一句改为正确顺序后表现与移动一并提交；另一项集成测试让模型故意省略“看看有没有锁”，验证移动已提交时仍显示句尾遗漏。真实 DeepSeek 在全新世界对同结构句子返回 `narrate("我轻轻笑了笑") → move("走进后室看看有没有锁")`，玩家进入后室。随后从原 G3 试玩存档复制一份独立数据库，再输入**原失败句子**：模型返回 `narrate("我把钥匙握在手心") → move("走进后室看看有没有能配它的锁")`；副本 Head 从 seq258 到 seq280，玩家进入后室。原始存档未修改。

限制：这验证的是这一种表现加移动结构，不能证明模型永远不会产出错序、遗漏中间片段或语义依赖不清的候选。句尾遗漏会提示，中间未引用的连接或内容尚未做语义审查。Host 仍拒绝无法安全绑定的候选，不会为了让它通过而重排行动；已接受候选中自由叙述与受控事实可能分叉，仍按 G3 风险追踪。批量中后项被规则拒绝的提示路径已经接线，但本轮没有构造真实模型触发该分支。
