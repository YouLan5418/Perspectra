# 第二轮模块实测：NPC 自由表达

日期：2026-09-20。工作树：harness-cordis-world-prototype；模型：deepseek-flash；世界包：ai-girls-awaken-v10。状态：表达切片可用，整体体验验收未通过。

## 这次改变了什么

NPC 不再从闭合表现码菜单选择 smile、nod 等固定文案。当前发布表达的参数是：

```json
{"text":"实际说出的对白，可以为空", "narration":"自由外显叙述，可以省略"}
```

至少一项非空。纯表现不要求捏造对白，不要求附着在一次物理交互上。当前工具仍把发布表达命名为 speak，这只是复用既有入口的暂时命名；没有为这个切片新建包、数据库或协议版本。

每次提案仍最多两步、最多一次重要状态操作，但允许两步都是表达。发布表达只读取 text、narration 与显式受众字段；多余的 narrationNote 或 statePatch 等字段不进入发布事件、不会调用状态修改。受众字段自身仍须通过校验。移动与交互参数保持原来的执行校验。

相关改动跨输出、裁定、记忆和展示位置，是同一条表达链路的必要接线：只改模型 Schema 会被旧 Rulebook 拒绝；只改 Rulebook 会让记忆和界面丢掉纯表现。因此没有把本轮扩大成独立调度或存储重构。

## 权威边界记录

- 复用 character.speak 作为“角色发布了内容”的记录，narration 是发布内容，不是其所述行为已发生的证明。
- 不把 narration 转成 character.manifested、可见状态、位置或物品事件；观察携带原始发布内容，受众仍走现有权限路径。
- Memory 使用已有 communication / reported_speech 分类，注明 `published narration (not an adjudicated outcome)`，保留说话者；不把描述升级为 observed_action 或 direct_observation。
- 模型面对的交互选项仍为已授权引用。移除表现菜单，并不放开模型任意写状态。
- 历史 cue 实现尚未从所有旧调用路径删除；当前 NPC 适配器已不提供它。没有增加兼容路由，也不承诺旧世界继续受支持。

这不是任意自然语言一致性的证明。模型仍可能在叙述里声称未执行的动作并影响其他角色；此类问题必须记为体验失败，不能以“数据库没变”宣告解决。

当前仍批量提案，尚未实现 perform 后获得结果再即时续写。提示要求只描述当前表达和意图，不预写本次未裁定动作的成功。旧的共同提案快照、反应重复与玩家输入解释仍在；不能把这个切片称为完整原型契约已完成。

## 第一次实测 A：保留失败证据

目录：`.tmp/narration-playtest-20260920`。3 条输入，17 次调用。模型确实开始生成自由表情、语气和姿态，但暴露了两类表达丢失：

- responses.json call4/7/9/13/16：模型连续给出两条 speak，被旧“一说一做”约束拒绝；其中部分最终表现为 provider_terminal。
- call5/17：GPT 多给了空 narrationNote；Rulebook 以未知字段拒绝整段表达，events seq127/195 可复核。

据此在同一表达链路内完成两项减法：允许连续表达；发布时提取有意义字段，不让不可执行的附注取消整段表达。仍限制总步数和重要状态操作次数，仍检查 actor、scope、接收者与实际执行权限。

另一个独立失败保留未修复：输入“GPT，先不要说话，可以只用表情或手势回应我一下吗？”被输入模型判为 unsupported，整条没有进入世界。该问题发生在 NPC 接收之前，不能算 NPC 不能纯表现。

A 的 GLM 一边说愿意留下，一边提交了移动；这是言行一致性/角色决策问题，程序确实执行了移动，不能当成旁白绕过。
