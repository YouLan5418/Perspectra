# 第八轮：一次 perform，提交结果，再自由表达

日期：2026-09-20。完成独立的单角色执行切片及实测。**尚未替换网页群体试玩中的 Root / Reaction 批量提案路径，不宣告完整 G1 或 G3 通过。**

## 本次解决的问题

旧路径先收集整批动作，再统一裁定，角色可以在知道结果前写出成功后的表现。本切片把执行和续写放在两次模型调用、两次实际提交之间：

1. 角色选择 `perform`、`publish` 或 `abstain`。
2. `perform` 只携带一次移动或创作者绑定交互的参数，不接受同包叙述、对白或旧 performance。
3. Host 分配行动身份，以实际 NPC 身份调用原有 Rulebook；重要事件、结果观察及 outbox 使用原有 `WorldStore.commitRound` 原子提交。
4. 提交完成后，重建该角色的可见场景、近期观察、自身表达和可见物品状态，连同接受/拒绝结果再次调用模型。
5. 第二次只能自由表达或 abstain。不存在第三次调用、后续计划或恢复模型中间态。

每次激活最多两次决策调用，结果后的调用同样计数。传入 `maxCalls: 1` 时只执行首步，明确返回预算停止。纯表达和 abstain 一次调用结束。执行成功不因续写失败、非法第二次交互或取消而回滚。

## DeepSeek 实测

模型：`deepseek-flash`，temperature 0.3，每次最多 2048 输出 token、45 秒超时。最终样本目录：`.tmp/perform-playtest-20260920-b`，含 `success.sqlite`、`rejected.sqlite`、`evidence.json`。证据保存实际请求、提案、调用前 Head、结果和公开表达，不含凭据。

使用小型测试世界，角色名 GPT、一个房间及下一地点、玩家和两只杯子；不是此前四名 NPC 的人设对照实验。初始玩家可见请求为“GPT，帮我拿一下杯子（entity:cup）吧。”

| 情境 | 初始决策来源 | 裁定与提交 | 结果后的真实模型表现 |
| --- | --- | --- | --- |
| 可拿取的杯子 | DeepSeek 自主选择 `perform base:take` | seq13 转移给 NPC；第二次调用前已持久化 | seq19 才发布“喏，给你。”及“GPT 顺手把杯子拿起来，轻轻递向 Player。” |
| 杯子已由玩家持有 | **脚本注入同一个 take 提案** | 原有规则真实拒绝，`PARTICIPANT_NOT_AUTHORIZED`；归属不变 | 得到拒绝后发布“抱歉，我好像拿不了那个杯子——权限上不允许我碰它。要不你自己拿一下？我在这儿陪你聊。” |

最终样本共三次真实模型调用：成功情境两次，拒绝情境一次。拒绝不是模型自主决定去尝试的自然样本，也没有伪造裁定结果；它验证真实拒绝进入模型续写的闭环。

结论与限制：

- 已观察到“选择交互 → 实际提交 → 读取成功结果与新持有状态 → 续写”。第一次决策没有同时发布成功表现。
- 拒绝后的模型没有把拿取演成成功，世界状态与这段回复一致。
- 成功样本的“递向”“给你”存在交付含义的阅读歧义，但没有明确写出玩家已接过；数据库仍由 GPT 持有。不能把这段当作已证明不存在后续叙事越界。
- 拒绝回复把内部权限码带成了角色台词，说明执行结果的角色可读呈现仍需打磨。本次保留原始结果，不添加自动改写或第二模型审查。
- 没有运行观察者的后续反应，所以没有验证歧义是否会传播到其他角色记忆。

### 保留的失败尝试

`.tmp/perform-playtest-20260920` 保留首轮失败证据：成功情境第一次调用未形成提案，旧诊断只分类为 `provider_or_output_invalid`，未保存异常细节，不能断言确切 Provider 原因；拒绝情境的实验初始转移事件缺少必需字段，状态重建报错，因此未进入模型调用。

随后补齐实验事件字段、Schema 根对象类型及实验传输异常记录，在新目录完成以上两种情境。失败目录未删除，也未计入成功样本。最终运行时分别报告 `provider_failed` 和 `invalid_output`，存储/规则/上下文异常继续向调用方抛出。

## 使用与下一接入边界

在项目根目录，先在环境中提供 DeepSeek 凭据，再运行：

```powershell
node --import tsx tests/experiments/perform-playtest.ts .tmp/perform-playtest-new
```

目录必须是新目录。脚本固定两个情境，最多三次真实请求；它不启动服务。若要进行任意交互，可通过 `PrototypeCharacterTurn.run` 的单角色入口接入，必须让 Host 管理取消信号和外层总调用预算。

当前有意接受：没有自动群体调度、私语选择 UI、多步计划、未完成续写恢复及跨轮任务。观察与会话已保存，但不自行唤醒旁观者，也不跑长时记忆任务。Authority 使用简单执行记录，不伪造旧批量提案回放账本；旧运维导出/恢复链未验收，不把此实验数据库当成冻结网页存档继续使用。

下一步接入群体试玩时，应复用这个真实提交边界，并保持当前旁观表现触发规则；续写调用必须计入外层预算。不能把这一实现包装成旧 Provider 的内部递归，然后漏算调用、在未提交的候选状态上返回“成功”，或破坏已冻结波次的 Head。
