# 第十轮：连续互动中的执行反馈与事实分叉

日期：2026-09-21。本轮只观察第九轮接线，不修改生产代码、人设、表达协议、Reaction 规则或预算。结论：拿取和递交后的反馈在本样本中及时，但连续互动的叙事一致性未通过，暂不扩大新执行路径。

## 方法与记录

使用 `ai-girls-awaken-v10`、四名 NPC、`deepseek-flash`、`performNpcId: character:gpt`，在同一个全新存档中通过现有网页服务 `/api/submit` 顺序提交输入。未进行浏览器视觉验收。

驱动：`.tmp/continuous-perform.ts`。记录：`.tmp/continuous-perform-20260921/`，含 `requests.json`、`responses.json`、`turns.json`、SQLite，以及筛选调用的完整上下文和输出 `selected-evidence.json`。请求记录不含凭据。以下 call 是该目录的请求编号，seq 是 `world.sqlite` 事件序号。

共尝试八次输入，前七次玩家输入已提交；第七次后续 NPC 反应部分失败，第八次输入未提交。82 次服务调用中 77 次 HTTP 200、5 次 HTTP 402。402 响应正文未记录，不能据此确定具体账单或额度原因。已停止调用并关闭服务。

## 执行者反馈是否及时

手机拿取与递交都在 GPT 的第一次正常 Reaction 中获得已提交结果，分别为 call19（请求时 head235）和 call29（head307）。两次均未使用周期末补充续写，也没有重复执行拿取或递交。

这支持“本样本反馈及时”，不证明调度顺序与调用上限的边界已经解决：没有采到执行者直到预算耗尽仍未获得机会的样本，也未覆盖周期末补充表达无法立即触发他人反应的情况。

## 他人依据了什么信息

第三次输入中，DeepSeek call25 的触发信息只有玩家请求递交，尚无递交成功记录，就说“诶，手机又转手啦”。这段表达的玩家观察为 seq300，真正转移发生在 seq301。措辞有预期意味，但呈现得像已经发生；不能把它计为看到裁定后再回应。该调用没有收到未提交的 GPT 提案，因此证据指向模型自行预判，而不是系统提前泄露执行结果。

更明确的分叉发生在第六次输入：

1. seq568，DeepSeek 正确说：“GPT早就递给你了，现在在你手里呢。”
2. GPT call60 却说：“手机在我这儿——刚才你让我拿，我就一直拿着，没递给别人。”对应已发布对白 seq582。
3. GPT 的真实请求中仍有 `base:give` 成功、`toHolderId: character:player` 的自身观察，还有突出呈现的自身对白“手机给你了”及递交叙述。因此不能解释成结果或自身历史根本没进入上下文。
4. DeepSeek call62 同样能看到成功递交记录，却在 seq601 改口：“诶，手机原来一直在 GPT 手里呀——那我刚才那句「在你手里」说错了，算我记岔了。”
5. GPT call64 在 seq615 再次坚持手机没有离手。此后手机没有任何新的转移事件。

数据库保持一致，但角色把别人的最新说法置于已观察的执行结果之上，错误已经传播。这是体验失败。当前状态的呈现是否足够清晰、旧历史与当前说法如何争夺注意力，仍需单独验证；不能仅凭这一例确定修改提示词就能解决。

## 结果续写仍能用叙述绕过下一次重要交互

第七次输入中，GPT 拿起键盘（seq684）。call77 明确收到 accepted 执行结果及 `binding:keyboard-take`，本次只允许表达或 abstain。它随后发布：

> 她把手里的键盘轻轻放回桌面，指尖离开键帽时没有留恋。

对应 seq713。没有提交 `base:drop`，最终键盘仍归 GPT。这个例子直接发生在新执行路径的结果后续写中：拿取真实成功，但续写又声称完成了第二次受控变化。

GLM 也多次声称把笔记本放在桌上，包括 seq707“这台我先放回桌上”，但笔记本从 seq167 起一直由 GLM 持有，没有放下事件。旧路径和新续写都存在语义边界问题；不能只推广接线就预期它消失。

## 跨场景与观察范围

主要路线的移动均有实际事件。最终玩家在卧室，四名 NPC 在工作区；手机归玩家、笔记本归 GLM、键盘归 GPT。

GPT seq713 的键盘叙述产生了 Claude、DeepSeek、GLM、GPT 的观察，没有给已经离开工作区的玩家生成该表达的观察。这一处观察范围正确，但范围正确并不等于内容正确。

第八次交流未能提交，而且 Claude、DeepSeek 已经自行前往工作区，玩家回卧室时并不与她们同场。因此“回来后与其他人交流”的验收尚未完成，不能用最后一次失败请求证明跨场景对话正确。

## 下一步与验证边界

暂不推广到移动和其他角色。优先区分两个独立问题：

- 已提交结果仍在上下文，但模型对当前归属判断错误。下一轮可只验证对角色有权知道的当前物品状态作简明呈现，观察它是否能保持正确判断；不注入全局不可见信息。
- 续写声称完成第二次受控交互。需明确单次交互切片结束后的表达边界；本轮没有据此增加分类器、语义审查模型或多步工具框架，也没有恢复闭合表现枚举。

本轮新增实验驱动、证据摘录和报告，README 增加入口；生产实现保持原状。验证为真实模型 HTTP 连续试玩及请求、响应、事件、观察的只读核对。没有重新运行类型检查、单元测试、全量或硬崩溃测试；没有修复上述问题，也没有验证执行者饥饿与周期末补充续写的后续互动。
