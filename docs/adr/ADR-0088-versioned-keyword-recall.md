# ADR-0088：版本化关键词召回与中文切分

- 状态：Proposed（待接受后转 Accepted）
- 日期：2026-09-12
- Extends：ADR-0035、ADR-0067、ADR-0068
- 上位契约：[记忆模块实施规格 §5～§7](../spec/memory-evolution-implementation-v0.1.md)、[实施规格 §11](../spec/implementation-v0.2.md)
- 范围：记忆模块实施规格 M1.3 与 M2.1～M2.2 的最小切片，含版本化中文切分与专有名词词典

## 背景

当前 v2 召回把查询按空白切分、逐项加引号后用 AND 连接。中文句子不含空白，一整段会被当作一个词元，于是只有"一字不差地重复整段（到标点或空白为止）"才可能命中。本机只读测量（雨夜同行参考 Pack、单角色、200 轮、脚本 Provider，不改生产代码）给出：

| 查询 | 命中候选数 |
| --- | ---: |
| `钥匙` / `备用钥匙` / `花盆` / `第三个花盆` / `门口第三个花盆下面了` | 0 |
| `我把备用钥匙放在门口第三个花盆下面了`（整段，到标点为止） | 2 |

在真实回合里，玩家说"钥匙"、"钥匙放在哪了？"或"我们要出门了，你有什么要提醒我的吗？"时，进入角色上下文的旧事为 **0 条**；只有一字不差复述整句时才进入 2 条，且最近一次重复排在最初那次之前。原文一条未丢，用整段仍能查到：这不是容量、上限或裁剪问题，而是查询线索与匹配粒度问题。

按上位契约的版本警告，旧 `recall-query-plan/v1`、`fts5-bm25-stable/v1` 与 L1/Context 语义不得原地替换，因此本决定只新增并存版本。

## 决定

1. **分词版本化，中文同时建二元与三元。** 连续中日韩文字同时产生相邻二字与相邻三字词元；拉丁字母、数字与标识符沿用"非字母数字为分隔符"的现行规则。两档同时建是必需的：中文常用名词多为两字（钥匙、花盆、车站），纯三元切分会让它产生不出任何词元，反而比现状更差。大小写、空白、标点与补充平面字符行为在 Golden 中冻结。不新增第三方运行时依赖，算法是仓库内的确定性代码。
2. **专有名词词典只影响排序，不影响可匹配性。** 词典收录世界内容中已声明的名称（角色、已授权别名、物件、地点）以及创作者显式列出的词；命中词典词的候选获得更高的相关性权重。词典不参与索引构建——索引只存二/三元词元——因此词典变化不需要重建既有索引，也不存在"旧文本曾被旧词典切过"的历史不一致。
3. **词典按角色隔离并带水位。** 词典状态是"该角色在某 as-of 水位上已获授权的名称集合"，只能由该角色可读的来源派生；私密会话里出现的名称不得进入其他角色的词典，也不得通过排名变化、候选数或解释面间接泄漏其存在。同一水位重建必须得到同一词典，否则 fail-closed。
4. **词典可以显式停用。** 停用是世界内容或 Manifest 的显式选择，不是运行时 Host 开关；停用后匹配与排序等同于"从未启用词典"，只保留二/三元词元权重。回执必须记录词典是否启用，同一水位重建必须使用同一选择，否则 fail-closed。停用同时用于对照评测，使"词典是否真的有用"可以被测量而不是被假设。
5. **匹配语义放宽为"命中任一词元"。** 查询切分后命中至少一个词元即为候选，不再要求整段相同。该语义只作用于新的计划版本，旧计划版本的整段 AND 语义保持不变。
6. **排序只用限定范围的确定性统计。** 相关性只由当前 namespace 且 `source_seq <= asOfWorldSeq` 前缀内的统计得出，不得使用数据库内置 bm25 的全表语料统计；命中三元、命中词典词与命中覆盖率作为确定的加权项。排序为：相关性、`source_seq` 降序、`memoryId` 的 `compareWorldText` 顺序。
7. **同文重复保持近期优先。** 同一内容多次出现时最近一次在前，这是现行语义，新增验收用例固定它，避免实现者各自解释。
8. **策略由世界显式选择，不自动升级。** 旧世界继续使用旧计划与旧回执版本；新语义必须由世界内容或 Manifest 显式声明（具体字段在实施提交中与当时的 Manifest 版本一同冻结）。未注册策略 fail-closed，Host 配置不能悄悄改变已激活世界的行为。
9. **新增检索回执版本。** 记录分词与策略版本、词典版本与水位、词典是否启用、每个候选命中的词元、相关性身份、被结果上限截掉的候选数，以及 `no_match`、`result_limit` 等裁剪理由。旧回执的字段与封闭枚举不变，继续可校验。
10. **结果上限仍是硬上限，但必须可观测。** 被上限截掉的候选数进入回执与只读诊断，使"命中很多但只给 10 条"可被测量，而不是只能被猜测。
11. **本决定不改变查询线索的来源。** 查询仍由当前刺激构造；基于在场人物、未完成事项与场景线索的结构化召回，属于后续独立决定。

## 后果

- 角色第一次能在"玩家提到相关词但措辞不同"时找回旧事；关键词之外的关联召回仍然缺失，直到结构化线索落地。
- 召回结果随版本改变，因此不原地替换：同一历史水位在旧版本下仍重建出旧结果，只有显式选择新语义的世界使用新行为。这同时避免升级后重算旧回合触发完整性故障。
- 中文索引同时存二元与三元词元，体积相比现状明显增长，候选集变大，排序与结果上限的重要性上升。
- 词典让排名依赖"该角色在当时已获授权的名称集合"，所以回执必须记录词典版本与水位；这也意味着涉及词典的调参必须在固定水位上对比。
- 跨 namespace 的统计隔离与词典隔离都成为可测试属性，而不是从 WHERE 隔离推断出来的假设。

## 非范围

结构化线索通道（在场人物 / 未完成事项 / 地点物件）、经历分组索引、生成式或多层摘要、模型自带搜索工具、向量或远程检索、名称的语义消歧与全知别名推断。以上各自需要独立的 superseding 决定。

## 验证

- 只读测量脚本（`tests/experiments/measure-recall-quality.ts`）中 `钥匙`、`备用钥匙`、`花盆` 等查询从 0 命中变为命中，整段复述仍命中；两字查询必须确实命中，作为纯三元方案的反例。
- 词典加入或移除一个词只改变排名权重，不改变既有条目"能否被匹配"，也不要求重建索引。
- 同一语料在启用与停用词典两种选择下，"哪些条目能被匹配"完全一致，差异只出现在排名权重；两种选择各自同水位重建一致，混用 fail-closed。
- canary：加入其他角色语料、未来事件、父分支文本后，既有计划的排名与 Hash 不变；某角色的私密别名不改变其他角色的候选数、排名或解释面。
- 同水位重建得到同一词典、同一排名；水位回退或词典分歧 fail-closed。
- 边界：U+10000 与 U+E000 排序、大小写、标点、单字与两字查询、空查询、无命中负例、结果上限边界。
- 同一 `(address, characterId, planId)` 同水位重建一致，重启一致。
- 旧世界字节、Golden Hash 与旧回执校验全部不变。
- 生产代码逐文件四项 100% 覆盖，`corepack pnpm@11.7.0 check` 退出码 0。
