# ADR-0089：记忆检索引入分词器运行时依赖

- 状态：Proposed（待接受）
- 日期：2026-09-12
- Amends：`AGENTS.md` 的 Phase 0 依赖边界（仅限本决定所述范围）
- 上位契约：[ADR-0088](ADR-0088-versioned-keyword-recall.md)、[记忆模块实施规格 §7.1](../spec/memory-evolution-implementation-v0.1.md)

## 背景

ADR-0088 的切词最初完全由仓库内实现（重叠二元与三元）。它是确定性的、无依赖的，但中文常用名词以两字为主，纯三元切不出词元；二元能召回，却把词边界一并切开，候选噪音偏大。要拿到真实词边界就需要一个中文分词器，而仓库规则原本只允许 `@deepseek-ai/cordis` 一个上游运行时依赖，所以这需要先改边界。

本机验证（Windows / Node 24.14.1，隔离目录，未进仓库）比较了两个候选：

| | `@node-rs/jieba` 2.0.3（原生） | `jieba-wasm` 2.4.0（WASM） |
|---|---|---|
| 同步调用 | 是 | 是，无需 await 初始化 |
| 文档语义是否可用 | 不符：精确模式切成单字，词性标注全为 `x`，2.x 实例没有 `addWord` | 与文档一致 |
| 单次耗时（热） | 0.004 ms | 0.025 ms |
| 首次开销 | — | 约 200 ms，每进程一次 |
| 平台一致性 | 每平台一份二进制，官方支持矩阵只写到 Node 18 | 一份 WASM 字节，全平台同一份 |

## 决定

1. 记忆检索引入一个上游运行时依赖：`jieba-wasm`，**锁定精确版本**（当前 2.4.0），并且只使用已验证的接口。实测用两个汉字调用 `tokenize` 会抛 `memory access out of bounds`，该接口不进入生产路径。
2. 选择 WASM 而非原生绑定：同一份字节在所有平台产生同一切分结果，这是本仓库"跨平台字节一致"不变量的结构性前提。原生绑定是按平台分发的二进制，且官方支持矩阵不覆盖本仓库要求的 Node 版本。
3. 分词器是**版本化的可替换件**：`jieba-hybrid/v1` 与仓库内实现（`cjk-ngram/v1`）并存，后者保留为无依赖回退。词元索引是由来源派生的可重建数据，换分词器只需换标识并在追平中重建一次。
4. 分词只影响匹配与权重，**不改变权限、as-of 或来源闭包**。专有名词词典继续由仓库层维护（只提高权重，不写入分词器的全局词典），因此不会通过分词器状态在角色之间泄漏，也不会破坏同水位重建。
5. 只索引两字及以上的分词词与全部二元三元；单字不入索引，否则任意查询都会把每句话变成候选。
6. 本决定不改动世界事实权威、事务边界、Provider 契约与部署恢复集合。

## 后果

- 仓库多一个约 16 MB 的运行时依赖，进程首次分词有约 200 ms 的一次性开销。
- 分词质量提高（真实词边界并作为更强权重），但**分词器的词边界不构成召回下限**：二元继续兜底，所以分词器把复合词或生僻专名合并成一个词时，只提到其中一部分的旧事仍然查得到。
- 升级分词器版本会改变切分结果，因此版本必须锁定；升级必须走新的分词器标识并重建索引，不能原地替换。
- 跨平台一致从"逐平台二进制"变为"单一 WASM 制品"，风险下降但仍需实跑证明。

## 验证

- 同一批语料在两种分词器下的召回结果与排名有固定 Golden；`corepack pnpm@11.7.0 check` 退出码 0，生产代码逐文件四项 100% 覆盖。
- 异常输入（emoji、补充平面字符、孤立代理项、全角字符、两万字长文、重复字符）不崩溃、不抛异常。
- 计划的分词器标识与命名空间索引标记不一致时 fail-closed，不静默回退到另一种切分。
- **跨平台证据仍然缺失**：本轮只验证了 Windows。WASM 的跨平台一致必须在 Linux 上实跑一次后才算证明，完成前不宣称已跨平台一致。
