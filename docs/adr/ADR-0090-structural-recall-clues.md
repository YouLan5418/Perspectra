# ADR-0090：结构化线索召回（在场人物与未完成事项）

- 状态：Proposed（待接受）
- 日期：2026-09-12
- Extends：[ADR-0088](ADR-0088-versioned-keyword-recall.md)、[ADR-0035](ADR-0035-knowledge-memory.md)、[ADR-0067](ADR-0067-cognitive-memory-worldpack-v2.md)
- 上位契约：[记忆模块实施规格 §6.2、§7.1～7.3](../spec/memory-evolution-implementation-v0.1.md)

## 背景

ADR-0088 只修好了"匹配"，没有改变线索来源：查询仍由当前刺激构造。本机实测结果说明了这个上限——同一件旧事，玩家四种说法里前三种能想起来（一字不差、`钥匙`、`钥匙放在哪了？`），但"我们要出门了，你有什么要提醒我的吗？"这一类**与旧事没有任何共同用词**的问法，命中的 16 条候选里没有那件旧事。

同时，上位契约已经把两条通道列为验收场景：T-01"百轮后再次见到承诺对象"要求当前承诺与原始依据同时可见；T-02"同一人物不同措辞出现"要求实体召回命中，不依赖原句完全匹配。这两条都不可能由"只拿玩家原话去查"满足。

ADR-0088 第 10 条把线索来源的变化明确留给后续独立决定，本决定即为其一。

## 决定

1. **新增结构化线索通道。** 线索只来自已授权且可重建的来源：**当前在场角色**（场景决策的权威成员名单）与**该角色自己的未完成事项**（当前认知中的目标/承诺/开放事项）。线索不使用模型推断、不使用全知资料、不读取其他角色的私密状态。
2. **线索进入既有的 v2 检索计划，作为一个独立字段。** v2 计划至今没有任何世界启用（只有本地试玩入口显式打开），所以可以在其上增加字段；一旦有世界声明启用，之后再加字段必须走新的计划版本，不能原地修改已发放的回执语义。
3. **线索只扩大候选并参与加权，不改变权限、as-of 与来源闭包。** 线索本身也必须能在同一水位重建——它由场景决策与认知投影派生，二者都已满足这一要求。
4. **线索词元取最低权重档。** 线索是"联想"，不是"提问"：线索词元按最低一档权重参与匹配与排序，显式词元保持各自的更高档（二字/三字/词/分词词依次更高）。因此线索保证候选不被漏掉，而两者都命中时显式内容自然占优。
5. **回执必须记录线索。** 记录本轮使用了哪些线索、每条候选命中了哪些词元（已有字段）以及线索贡献，使"它为什么进来"可解释；线索为空时也记录，便于对照。
6. **线索必须按角色隔离。** 只使用该角色有权看到的场景成员与它自己的认知；任何其他角色的私密状态都不得成为线索。这条要有 canary 测试。
7. **线索为空时的召回结果必须与纯关键词路径完全一致。** 候选集合、排名与分数不得因为线索通道存在而改变（回执新增的线索字段除外），确保这条通道只会补充、不会劣化。

## 非范围

模型生成的查询词、向量或语义检索、全知别名与实体消歧、跨场景泄漏、以线索为名绕过受众过滤。创作者声明的专有名词词典与"停用"开关属于另一项独立决定。

## 后果

- 人物与目标相关的旧事第一次能在"玩家没提"时被想起，满足 T-01 与 T-02；这也是"角色为什么突然想起某个人"的机制来源。
- **没有结构关联的旧事仍然想不起来。** 我实测的第四种问法属于这一类：那件旧事既不关于在场的人，也不属于任何未完成事项，任何结构化线索都够不到它。那需要创作者显式加权（专有名词词典）或语义检索，本决定不解决。
- 线索来源必须是真正被捕获的来源，而不是"看起来应该存在"的视图字段：实现中发现角色目标在某个视图上是空的，若据此取线索会静默失效；因此未完成事项直接从**该命名空间已捕获的目标来源**读取，与词元索引同源、同水位。
- 候选池变大，排序与结果上限的重要性继续上升；线索权重必须冻结，否则同一水位会算出不同排名。
- 线索来源增加两个依赖（场景决策与已捕获的目标来源），二者都必须已在 as-of 上可重建，否则召回应 fail-closed 而不是退回无线索。

## 验证

- T-01：百轮后再次见到承诺对象，当前承诺与原始依据同时进入上下文。
- T-02：同一人物以不同措辞出现时，与该人物相关的旧事被召回，不依赖原句完全匹配。
- 线索为空的世界，召回结果与纯关键词路径逐字节相同。
- 线索权限 canary：其他角色的私密状态、未在场角色、导演可见信息都不得通过线索影响候选、计数、排名或解释面。
- 同一水位重建得到同一线索集合与同一排名；线索分歧 fail-closed。
- 生产代码逐文件四项 100% 覆盖，`corepack pnpm@11.7.0 check` 退出码 0。
