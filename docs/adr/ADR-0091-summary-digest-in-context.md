# ADR-0091：把经历摘要正文接进角色上下文

- 状态：Accepted
- 日期：2026-09-12
- Extends：[ADR-0068](ADR-0068-phase8-context-summary-signal-quality-closure.md)、[ADR-0067](ADR-0067-cognitive-memory-worldpack-v2.md)、[ADR-0088](ADR-0088-versioned-keyword-recall.md)
- 上位契约：[记忆模块实施规格](../spec/memory-evolution-implementation-v0.1.md)、[Phase 8 实施规格 §10.4](../spec/phase-8-implementation-v0.1.md)

## 背景

ADR-0068 第 1 条让 Checkpoint 只引用 L1 摘要的身份、来源范围和 Hash，不复制正文，用意是防止出现两套会互相漂移的摘要事实源。这条边界有一个副作用：**压缩出来的文字从来没有到过模型眼前**。

本机实测（60 轮，只读诊断 `tests/experiments/measure-context-compression.ts`）说明了这个副作用的形状：

| 观测项 | 实测（基线前移之前） |
| --- | --- |
| 角色上下文保留的近期对话 | 最近 10 块（Profile 上限） |
| 基线水位 | seq 34，**冻结在开局** |
| 基线引用的摘要 | 1 条，覆盖 seq 11–31 |
| 更早 50 轮的内容 | 既不在近期对话里，也不在任何被引用的摘要里 |

第一批改动把基线改为随 Tail 窗口前移（见[连续基线前移改动记录](../archive/prototype-g1-g4/2026-09-12_连续基线前移-改动记录.md)），摘要引用因此从 1 条增加到 12 条，第一次覆盖到 Tail 起点之前。但引用仍然只有 id、序号和 Hash：**挂载面铺好了，上面还没有内容。**

## 决定

1. **L1 摘要正文进入角色的连续性段。** 摘要正文随 `continuity_checkpoint` 段一起给模型，作为一个独立的 `digest` 字段；不新增第十三个段，段数与顺序保持不变。
2. **只取 Tail 起点之前的摘要。** Tail 已经提供了那之后的原文，重复给同一件事没有价值。判别依据是摘要的 `sourceEndSeq` 不晚于 Tail 的起点。
3. **从最近往前取，受字节上限约束。** 上限是配置值，不是"能放多少放多少"；超出上限时放弃更早的整条摘要，绝不从中间截断一条。
4. **正文忠实于 L1，不重写、不重新生成。** 每条摘要的正文是它自己的 `extracts` 按原顺序连接；identity、来源范围与 Hash 与 Memory 中的 L1 完全一致，上下文层必须能重新验证它们，不一致就 fail-closed。
5. **摘要正文只影响"给模型看的内容"。** 不写世界事件日志、不改记忆库、不改变可见性与权限、不改变 as-of 语义。
6. **摘要属于可裁剪内容。** 体积超限时，摘要与低相关 Recall 同属第四级，先于整块对话被放弃；每次放弃逐条记账，理由为 `budget_trimmed`，可按 as-of 重建。
7. **与 ADR-0068 的边界。** 本决定**不生成第二套摘要**：算法、分组粒度、正文来源都仍是 Memory L1 那唯一一套。改变的只是"Checkpoint 段只含引用"这一条渲染边界，因此本决定 supersede ADR-0068 第 1 条中关于"Checkpoint bytes 中不存在经历正文"的表述范围，其余部分继续有效。

## 非范围

用模型改写或概括记忆（乙方案）、变更 L1 算法或分组粒度、把摘要结果写回世界或写进记忆库、向量与语义检索、让摘要跨越未授权来源、以摘要为名绕过受众过滤。创作者声明的记忆权重属于另一项独立决定。

**甲的边界要说清楚**：本决定能让更早的经历到达模型，但**没有让摘要变小**。分组的重做（按轮次切、尾组保留、正文按轮次成行）同时落地在同一批改动里，它去掉样板并让一组对应一段完整的经历，压缩比仍然只有两三成。真正的压缩——把八条经历写成一句话——需要替换 L1 算法本身，那是乙。

## 后果

- 角色第一次在"没人提到"的情况下也大致记得更早发生过什么。这是"长期记忆"在体验上的实际含义，也是 ADR-0090 那条线索通道够不到的部分。
- **正文是原文拼接，不是真压缩。** L1 每组八条记忆，正文就是这八条的文字；它的价值是"能带进去"，不是"体积变小"。轮数很多时，字节上限会自动只保留最近若干组，更早的组退回"只能被关键词召回"。真正的压缩需要替换 L1 算法，那是独立决定。
- 上下文会变大。摘要正文与段内原有的认知状态合计仍受 Profile 的请求预算约束，因此它是可裁剪的第四级内容，而不是新的必需内容。
- 基线与摘要之间存在分组边界造成的缝隙（实测基线来源末端 668、摘要覆盖末端 624）：末端不足两条的记忆不会被分成一组。缝隙内容仍可由关键词召回覆盖，本决定不额外处理。
- 摘要正文进入 `contextHash` 覆盖范围，因此历史 Context 收据的字节会变化；同一轮次重放必须得到同一份摘要集合，否则以完整性错误暴露，而不是静默降级。

## 验证

- 60 轮诊断（`tests/experiments/measure-context-compression.ts`）：更早轮次说过的事实出现在角色真正收到的上下文里——最后一轮那句提问与它**没有任何共同用词**，近期对话不含它，召回段是空的，事实只在 digest 里。
- 摘要为空（或全部晚于 Tail 起点）时，上下文与"没有摘要通道"逐字节相同。
- 摘要集合、顺序与正文在重启后重建一致；摘要 Hash 或来源范围分歧 fail-closed。
- 越权 canary：其他角色的私密来源、未授权记忆不得通过摘要进入上下文。
- 上限生效：超出预算时放弃的是更早的整条摘要，不是某条摘要的中间部分；被放弃项记 `budget_trimmed`。
- 生产代码逐文件四项 100% 覆盖，`corepack pnpm@11.7.0 check` 退出码 0。

**实测（60 轮，本机）**：基线引用 12 条摘要，覆盖序号 11–655；其中 12 组、共 8275 字节正文进入第 5 段，上下文从 37564 增至 63955 字节（该世界使用标准档，请求预算 96 KiB）。
