# ADR-0092：Epoch 快照与只追加的第二层

- 状态：Proposed（待接受）
- 日期：2026-09-12
- Extends：[ADR-0068](ADR-0068-phase8-context-summary-signal-quality-closure.md)、[ADR-0091](ADR-0091-summary-digest-in-context.md)
- 上位契约：[Phase 8 实施规格 §10.4](../spec/phase-8-implementation-v0.1.md)

## 背景

Provider 的前缀缓存只复用它上一次调用中**逐字节相同**的那一段。本机实测（60 轮，`tests/experiments/measure-context-compression.ts`）说明这块优惠基本没吃到：

| 观测项 | 实测 |
| --- | --- |
| 缓存命中率 | 5.58% |
| 中位数每轮新增 token | 21 |
| 缓存断点 | 恒定落在 `continuity_checkpoint` |
| 60 轮里连续性基线重建次数 | **49** |

第三行与第四行是同一件事：连续性基线**每轮都在前移**，所以它每一轮都变。而它排在稳定内容（协议、输出契约、世界与角色锚点）之后，于是那一段稳定前缀之后的一切都必须全价重算——**每轮真正新增 21 个 token，却按 17,242 个 token 付费**。

基线之所以每轮前移，是因为 Tail 被当成滑动窗口：`recentInteractionBlocks` 既表示"给模型看多少块"，也表示"基线跟到哪里"。滑出去一块，基线就得往前挪一格，快照随之重算。

## 决定

1. **第二层是"快照 + 只追加"。** 基线一旦建立就冻结，其后的 Interaction Block **只追加、不改写**，直到满足重建条件才整体前移一次。三层结构因此是：永久前缀（协议、输出契约、世界与角色锚点）／Epoch 快照与该快照以来的事件／本轮尾部（当前状态、场景、召回、当前刺激、可行动作）。
2. **重建由累积预算触发，而不是由轮次触发。** 预算是所选 Context Profile 请求预算的一半。Profile 的预算是渲染请求的硬上限，而且被注册表锁定，所以第二层必须住在它里面而不是旁边：另一半留给摘要、当前状态、场景与两条固定契约。当前三档分别对应约 16 KB / 48 KB / 96 KB 的第二层。
3. **`recentInteractionBlocks` 的含义变为"重建时保留多少块"。** 它仍然是 Profile 的容量字段、数值一个都不改、注册表锁不受影响；但它不再决定每轮发送多少块。平时第二层的长度由预算决定，重建时才回落到这个数值。
4. **第三层保持每轮变化。** 当前认知状态、场景、召回、当前刺激与可行动作本来就每轮不同，它们排在最后，不参与缓存前缀——这也是它们必须排在最后的原因。
5. **只追加的第二层必须仍然可按 as-of 重建。** 同一水位重建必须得到同一份字节：基线的前移点完全由"预算是否越界"决定，而预算是 as-of 的纯函数；摘要集合同样由水位决定。任何依赖时间、随机或调用顺序的取值都是缺陷。
6. **摘要正文仍受 ADR-0091 的约束。** 它取自快照覆盖范围，只带 Timeline 起点之前的组，整组取舍，受档位预算限制。

## 非范围

让模型生成摘要、把阈值做成世界可配置（等 Manifest 支持世界级策略声明）、跨角色的前缀共享（隐私面不同，缓存不能共享）、按调用类型分级上下文。这些都不在本决定内。

## 后果

- **缓存命中率从 5.58% 升到七成以上**（60 轮实测 72.09%，单次调用最高 86%）：第二层只追加，新增块之外全部命中，折扣是 1/50。
- **上下文不再稳定在一个固定大小，而是增长到档位允许的上限。** 三档的请求预算是 32 / 96 / 192 KiB，也就是上下文总长最多约 5 万 token。**要容纳更大的第二层（例如 16 万 token）必须提升 Profile 数值，而那会改变注册表锁、让所有已编译的世界包失效**——本决定不这么做，第二层的规模由档位决定，需要更大的世界应当选用更大的档位。
- **每轮真正变的东西只剩第三层与第二层的新增块**，实测中位数从 21 token 升到 530 token——因为第二层现在真的在增长，而不是每轮用同样的内容重付一次钱。
- **正在进行的轮次在升级后无法重放。** 前移策略变了，同一 as-of 会算出不同基线，收据因此以完整性错误暴露而不是静默降级；与 ADR-0091 那次的处理一致，升级安排在空闲时。
- **第二层变大之后，Profile 的请求预算仍然是硬上限。** 预算越界时以既有第四级/第三级顺序放弃内容，这条路径不变。

## 验证

- 60 轮诊断：缓存断点从 `continuity_checkpoint` 后移到本轮的追加处，命中率显著上升，且角色能看到的历史轮数明显变多。
- 未越界时不重建基线：连续多轮的基线水位逐轮相同。
- 越界时基线前移且把保留量回落到 Profile 声明的块数。
- 同一水位重建得到逐字节相同的 Context、摘要集合与排序；分歧 fail-closed。
- 权限与隔离不变：其他角色的私密来源、未授权记忆不得进入第二层。
- 生产代码逐文件四项 100% 覆盖，`corepack pnpm@11.7.0 check` 退出码 0。
