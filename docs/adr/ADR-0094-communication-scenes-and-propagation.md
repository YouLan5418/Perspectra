# ADR-0094：通信 Scene 与跨边界传播

- 状态：Proposed（用户于 2026-09-14 确认方向；具体契约及工程 Gate 待完成）
- 日期：2026-09-14
- Extends：[ADR-0093](ADR-0093-interaction-definition-abstraction.md)
- 拟局部 supersede：新版本路径中 [ADR-0072](ADR-0072-location-bound-scene-transition.md) 及既有 Scene 决策对成员/受众范围的相关限制；物理迁移和旧版本语义保留
- 上位方案：[V0.3](../2026-09-14_方案-交互抽象与按需交互包-v0.3-report.md)

## 背景

电话和消息需要跨物理场景传播，同时保留角色所在地与认知隔离。直接加入普通 Scene 会冲突于单活跃场景约束，并可能污染物理交互授权。单独增加远程调度器则会重复反应预算和上下文链路。

## 提议决定

1. 分开 Physical Scene 成员与 CommunicationScene 成员，角色物理位置不因通信改变。
2. 通信场景组织成员、端点、生命周期和锁定传播策略；成员身份不自动授予观察、接通、已读或操作权限。
3. 物理空间能力只使用物理成员证据；共享电话不能满足物理 Scene 交集。
4. 同一来源事件经受限传播产生接收者专属观察，保留来源和路径；不得传播整个现场上下文。
5. 反应候选依赖实际授权观察，统一使用现有因果周期总预算。当前轮成员冻结，新增资格在后续轮生效；会话存续不自动继续周期。
6. 生命周期作用域由声明和宿主验证共同限制，接触处理器不能消费任意活跃关系。
7. 电话和消息分别验证持续会话与异步投递；世界时间调度另议，不由自然语言自动生成未来行动。
8. 版本、数值预算、恢复和失败语义按 V0.3 Gate 冻结，未完成前不发布扩展契约。

## 后果与替代方案

复用观察、上下文与反应基础设施，但需要扩展其授权输入，不能声称无需接线。拒绝将通信身份直接放入旧 sceneIds，也不采用全局 crossScene 开关。

新增世界状态仍由 Event Log 权威管理。新包只在启用时提供能力，历史锁定依赖不能因禁用丢失。通信产品包不自动加入首批基础包范围。

## 验证与接受边界

以 V0.3 §10 为验收矩阵，特别验证同地点不同物理 Scene 的权限、同源多路径归并、共享预算、生命周期类型隔离和恢复幂等。用户已确认的是方向；本 ADR 保持 Proposed，旧 Accepted ADR 与黄金基线不改写。
