## 1. 已实现契约

模型候选使用 `player-intent-candidate/v1`：顶层仅含 version、decision、闭合 reason、actions 和 sourceSpans。每项 action 只携带局部 key 与 affordanceId；不能携带 actorId、最终 ActionId、任意 parameters、resolutionAuthority 或 manifestation。clarification 只能带空 actions/spans，reason 为 ambiguous、not_afforded 或 unsupported。

**（2026-09-15 补充，不改本片结论）** 候选已升 `player-intent-candidate/v2`（请求同步升 `player-intent-request/v2`）：每项 action 多一个可选 `performance`，让玩家也能声明"怎么做"，同时选项带上该选择接受的 cue。v1 的两个形状都不再被解析——宿主把 schema 放进它派发并参与哈希的请求里，不合 schema 的响应是"无视契约"而不是"旧对端"。候选仍然不携带 actorId、最终 ActionId、任意 parameters、resolutionAuthority 或自由文案。详见[I6 记录](../interaction-abstraction-i0-i7/2026-09-15_交互抽象-I6玩家声明表现槽位.md)。

Host 提供冻结的精确 Affordance 选择集：move 的 locationId、interact 的 targetId/interactionId/arguments 均复制自选择集，不由 Adapter 生成。speak 选择的参数模板为空，最终 text 从已核对原文 span 提取。此 API 只检查选择集结构；选择集是否来自正确 Manifest/as-of、玩家身份是否经 PlayerBinding 授权，由后续 Application 耐久准备层负责，不能从外部直接提供。

正式 `PlayerSubmissionV2` 保存 sourceText、`player-source-text/v1` Hash、最终 Action、重写为最终 ActionId 的 sourceSpans、interpretationProfile 与 Host 提供的 interpretationReceiptHash。ActionId 按 `player-intent-action/v1` 中的完整 WorldAddress、inputId、ordinal 确定生成。返回对象与输入参数深拷贝隔离；同一绑定重复执行得到相同字节，但这不替代耐久幂等。

## 2. 原文与动作组约束

- 一至两项 Action；两项必须恰好一次 speak 和一次 move/interact。
- UTF-16 span 非空、有序、非重叠、不越界，text 必须等于原文 slice；非法 Unicode、非 safe integer 与未知字段被拒绝。
- 每项 Action 至少一个 span，span 引用必须唯一解析到本次局部 key；引用顺序必须与 Action 顺序一致，不允许 a→b→a 交错。
- 当前候选绑定器要求 speak 只有一个连续 span，避免把不相邻引文拼接成原文没有的新句子。世界 Action 可有多个有序 span。无法满足时应澄清，不自动拼接或补词。
- 未映射叙述不进入 Action parameters；原文全文仍留在 Submission 输入证据中，未来 Context/Observation/Memory 必须只消费裁定效果。

span 只能证明来源，不能证明自然语言语义被正确理解。例如模型将目标陈述误标为 speech，单靠 slice 校验不能识别。此切片没有声称通过“她没有挣脱/永远服从”全链路语义验收；该门禁仍需解释输入契约、端到端反例和真实 Provider 证据，不能靠测试中手工挑选正确 span 宣称关闭。

## 4. 后续实施顺序与恢复边界

本切片验证：新增 60 项契约测试通过；完整 `corepack pnpm@11.7.0 check` 通过，覆盖率主套件 103 个文件、1067 项测试，生产 `src` 逐文件四项覆盖率均为 100%；P0～P6、3 项性能测试和 39 项既有硬崩溃回归通过。保留既有 `grouped-runtime.test.ts:25` lint warning。本次未改持久化代码，既有崩溃回归不等于未来 Player Intent 状态机的专项硬终止验收。

1. World v18 `player_input_jobs`：受理、Branch FIFO、同键冲突、fence、append-once submission/result；Logical v8 显式传输与校验。
2. Context v6 ProviderCall purpose/work identity：保存精确解释请求响应，与 World 状态确定对账；旧 Round 调用 Hash 不改写。
3. 解释 Worker：冻结 Manifest/as-of、Affordance、Profile/Provider、预算与截止时间；歧义 dispatch 不自动重发，迟响应不能翻转终态。
4. WorldApplication/CLI/Web：普通文本耐久解释，显式命令同 FIFO 降级；validated 提交幂等入队，失败返回耐久 clarification，不推进 Tick。
5. RoundCoordinator：完整两步玩家 phase 0 预裁定、整体 S1 与逐步绑定；随后覆盖 C0 Spike 定义的硬终止窗口。

只有上述闭环和阶段验收完成后，才能解除 `player-intent/v1` 激活限制。C0 真实模型门禁、C1 lifecycle 端到端遗留和 C4 发布验收保持独立，不因本次契约测试通过而关闭。
