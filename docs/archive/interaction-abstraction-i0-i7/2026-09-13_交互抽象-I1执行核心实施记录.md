## 2. 执行路径与事实边界

宿主安装受信任实现 → 世界明确选择包/定义/绑定 → 冻结注册闭包 → Host 提供角色授权与候选前缀 → 请求精确匹配绑定 → 解析全部角色 → 权限/空间/前置规则 → 效果生成 → 事件闭包及领域不变量检查 → 候选结果。

每个包的发布契约 Hash 覆盖组件锁、允许事件与定义描述；世界集合 Hash 覆盖所选锁和绑定。
包/定义/绑定清单采用稳定排序，清单排列不改变集合 Hash；角色与规则的声明顺序仍保留。
代码实现 Hash 是受信任发布契约锁，不宣称能够对任意 JavaScript 做代码完整性沙箱。

actor 和 authority 来自 Host，不能通过 arguments 覆盖。recipient 等辅助目标也需在 Host 当前授权集合中；猜中物品或角色 ID 不构成权限。
参数不匹配、未知绑定等结构性错误抛出；领域规则拒绝产生无事件结果。任何效果超预算、事件类型越界或领域校验失败均不返回部分事件。
请求、定义和候选状态复制为只读数据；规则拿不到数据库、文件或网络句柄。

结果包含 definitionSetHash、resolvedRoleBindingsHash、规则结果和绑定 WorldAddress/Manifest/候选前缀/Action/authority 的 ruleTraceHash。
它仍是提交候选，不是新的事实账本。本轮没有新增持久化事务或改变现有世界状态提交权。

## 3. 验证范围

八项针对性测试覆盖：

1. take → give → drop → take 完整闭环；同前缀重复裁定相同，持有变化后过期动作拒绝。
2. 主目标和辅助角色权限、不同 Branch、角色自指、快照/授权集合完整性、输入不可变。
3. 包/定义锁漂移、缺规则/空间/效果依赖、重复身份和依赖环；失败安装不残留注册。
4. 闭合角色/参数定义、未知来源、保留字段、Unicode、整数与配置字节上限。
5. 效果事件预算、事件类型/版本闭包、多事件转移拒绝、前后持有与目的地校验。
6. actor 生命周期、持有、同地点、Scene 及收件人资格均由基础包规则裁定。
7. 包/定义/绑定排列变化保持规范集合 Hash。
8. 独立 fixture 注册新的 fixture.marked 事件，只在选择其包与定义时可裁定；不修改通用运行时。

fixture 仅证明 I1 的注册与执行扩展能力，不替代 I5 的独立 Reducer、观察、Memory、恢复和真实模型端到端验收。
