## 1. 本轮实现

I2 的五项产出中，本轮落地第四项（可见目标与可尝试选项）与第三项（参数域）。

| 模块 | 实现 |
|---|---|
| [contracts/interaction-definition.ts](../../../packages/contracts/src/interaction-definition.ts) | `InteractionViewContext`、`InteractionViewOption`、`InteractionCharacterView` |
| [interaction-runtime/registry.ts](../../../packages/interaction-runtime/src/registry.ts) | `FrozenInteractionWorld.view()`；抽出 `#plan()` 供裁定与枚举共用；`snapshot()`、`argumentCombinations()`、稳定排序 |

`view()` 接受 Host 的只读视图上下文（地址、Manifest、as-of 水位、候选前缀 Hash、角色、authority、候选快照、授权集合、裁剪策略 Hash），返回三组互不相干的集合——可见角色、可见物品、可尝试选项——外加候选总数、被裁剪后的选项与 `selectedAffordanceHash`。

## 2. 关键设计选择

**枚举与裁定跑同一份规则计划，但绝不调用效果。** 我把裁定里的角色解析与规则循环抽成 `#plan()`，`resolve()` 与 `view()` 共用它。枚举因此不会写状态、不会生成真实关系身份、不会分配 Action ID（内部用固定的 `action:affordance-only` 占位）。测试用一个会计数的效果构造器证明枚举期间它一次都没被调用。

**选项可见不是执行许可。** 视图是提案集合，正式裁定仍在最新候选前缀上重跑完整计划。规格 §1.3 的这条边界因此不需要额外机制——`view()` 输出什么都不能让一次越权提交通过。

**参数域只来自受限来源，绝不来自自由字符串。** 一个字符串字段如果承载 `argument` 角色，它的取值域是 Host 授权的该 kind 目标集合；如果字段自带枚举，取值域是枚举本身；boolean 是两值；integer 在范围内取值。字段既无枚举又不承载角色时**显式抛错**，而不是悄悄少列一个选项——静默删除会把"这个角色能被怎么用"说少，是安全相关的沉默。

**组合是联合产生的，不是各字段独立枚举的笛卡尔积。** 规格 §6.2 明确禁止后者。所有候选组合都经过同一份计划过滤，因而 `give` 不会向自己枚举、alias 冲突的组合不会出现。

**预算按整项裁剪。** 单角色 128 项、单绑定 64 个参数组合，均取自冻结的 `interaction-limits/v1`。排序键是定义身份、目标身份、绑定身份、参数 Canonical bytes，顺序与裁剪都不改变权限，`candidateCount` 记录裁剪前的数量。

## 4. 验证范围

十二项针对性测试：

- 三组集合互不相干：可见角色按 kind 与 id 排序、可见物品包含**没有任何绑定**的 `entity:lamp`（可见但无交互仍显示）。
- 收件人域来自授权目标：`give` 恰为两个授权角色各一项，且每项参数都是该 kind 的授权目标。
- 确定性与哈希：两次独立实例化给出同一选项序列与同一 `selectedAffordanceHash`；水位或裁剪策略改变时哈希必须改变。
- 计划过滤：`fixture:hidden` 拒绝的绑定不出现在选项里，且视图字节中**不含拒绝原因**（断言 `BLOCKED` 不出现）。
- 效果不被调用：枚举前后效果构造/校验计数均为 0。
- 可见与可执行分离：目标可见但未授权时选项为空，可见集合不变。
- 预算：142 个候选裁剪到 128，`candidateCount` 保留 142。
- 失败关闭：无枚举域的字段、超过组合预算的整数域（1..100）、超过组合预算的授权集合（65 个收件人）全部抛错。
- 上下文校验：地址不匹配、重复快照目标、授权集合含未快照目标全部拒绝。
- 域枚举完整性：enum × boolean × integer 三字段联合产生 12 个组合，且两次运行顺序一致。

## 5. Evidence → Finding → Path

E1：`resolve()` 与枚举都需要同一份角色解析与规则循环。F1：复制一份就会漂移，视图与裁定对同一状态给出不同判断。P1：抽成 `#plan()` 共用，`resolve()` 行为由既有八项 I1 测试证明未变。
E2：规格 §6.2 禁止"各字段独立 enum 后允许任意笛卡尔积"。F2：独立枚举会让模型看到计划必然拒绝的组合，泄露授权边界形状。P2：联合产生 + 计划过滤。
E3：规格 §6.2 要求枚举不得调用效果构造器。F3：效果会生成关系身份并可能写状态。P3：`view()` 只到 `#plan()` 为止，并有计数测试。
E4：无枚举域字段只能静默跳过或显式失败。F4：静默跳过会把可用动作说少。P4：显式抛错，并在 I2-c 考虑把它提前到安装期约束。
E5：退出选项保留需要一个"哪些定义是恢复入口"的声明。F5：首批没有此类定义，现在加字段无法验证。P5：与 I3 的 `end-contact` 一起定义。
