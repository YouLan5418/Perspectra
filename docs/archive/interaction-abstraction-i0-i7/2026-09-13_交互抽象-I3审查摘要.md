## 3. 我主动标出的可质疑点

**D1（缺陷，已知未修）`end-on-move` 会为读不懂的关系产出畸形事件。** C16 说读不懂的关系会被收尾，但收尾事件的 `endedByCharacterId` 直接取 `entry.state.initiatorId`。当该字段不是字符串（例如 `42`）时，`outOfReach()` 正确判定为不可达，`build()` 却把 `42` 原样塞进事件——而冻结的关系事件词汇要求 `endedByCharacterId` 是字符串。运行时不校验事件 data 形状（只校验 eventType/version 属于闭包），所以这个畸形事件会通过。

我的 `contact.test.ts` 里那条测试**恰好断言了它会被产出**，等于把缺陷写进了期望值。这也是我把它列在第一位的原因：它不是我审出来的，是我写测试时撞见却按现状固化下来的。修法是：参与者 id 不可用时改用另一方，或直接跳过该关系而不是产出事件。**这一条应当在我修之前挡住 I3 的验收。**

**Q1 `move 无具体接触名分支` 这条 Gate 不成立。** `rulebook.ts` 一行未动（旧 v9 路径按冻结规则不得改），而新路径的替代——应用层在 move 之后调用 `fold()`——属 I4。也就是说关系收尾的机制齐全且被验证，但**生产里没有调用者**。

**Q2 世界 fold 会对每次 fold 运行所有处理器。** 处理器是纯函数，但"每次动作都跑一遍全部关系处理"在关系数量大时的成本没有实测。规格只给了"单 fold 处理器调用次数 256"，没给时间预算。I5 之前没有容量承诺。

**Q3 派生角色的授权语义是我的判断，规格没有明写。** 见 C2。我给的论证是：派生角色来自 Host 已放进快照的关系事实，且 Host 从不把 actor 列进它授权的目标集合，若要求授权则 end-contact 永远走不通。这个论证可以被反驳（例如主张"关系里的另一方也应当是 Host 显式授权的目标"）。

**Q4 I3-b 的处理器签名在 I3-c 被改了。** 由 `(context, events)` 改为 `(context)`，上下文收窄为 `{ host, events }`。理由是 move 没有定义。代价是 I3-b 记录里的签名与现状不一致——两份记录合起来读才对得上。

**Q5 `end-on-move` 挂在 `base:end-contact` 的 `lifecycleRefs` 上。** 语义上它属于"关系"而不是"解除动作"，但当前契约里生命周期处理器是**按定义**声明的，而世界 fold 取的是所有启用定义的并集，所以挂在哪里效果相同。这是绕过契约形状的实现选择，值得审。

**Q6 每包 64 个处理器的上限与 256 的 fold 预算不同量级。** 预算的测试必须跨五个包串链，说明在单包世界里它不可达。这可能意味着两个上限中的一个定得不合理。

## 4. 建议的攻击面

按"如果我是审查者会先打哪里"排序。

**A1 先修 D1 再谈其余。** 用一条 `initiatorId` 为非字符串（或另一方缺席）的活跃关系调用 `fold()`，看产出的事件是否满足冻结的关系事件 Schema。**我认为当前不满足。**

**A2 派生角色的授权边界。** 构造一个关系，其另一方是一个**未被授权**但**在快照里**的角色，看 `end-contact` 是否接受。按 C2 它会被接受——审查者需要判断这是否构成越权。

**A3 自指的结构性拒绝是否丢了东西。** I3-a 删掉了 `contact:unpaired` 里的自指分支，理由是 `distinctFrom` 更早拒绝。试着构造一个 `distinctFrom` 为空、但目标等于 actor 的定义，看是否还有任何一层拦住它。

**A4 `end-on-move` 在新建关系上的行为。** 一次 hold-hand 的 fold 也会跑 `end-on-move`。若 Host 传入的快照与候选前缀不一致（例如还没包含新建的关系，或已包含一次尚未提交的移动），会不会立刻结束刚建立的关系？C4 的重放断言只覆盖了事件相同，没有覆盖 fold 之后的事件。

**A5 fold 事件闭包与冻结词汇的关系。** 让一个处理器声明并产出 `character.visible-state-upserted`，看运行时是否允许。I2 的审查摘要 §4 A2 提过同一个问题，**I3 没有改变这个答案**。

**A6 计划的可达顺序校验是否足够。** 试着构造一条跨三个相位、每个相位都有同相位逆 ID 依赖的链，看是否全部被拦下。

**A7 世界 fold 的地址与授权校验。** 试着用另一个 Branch 的 WorldAddress、或授权集合含快照外目标调用 `fold()`，看是否拒绝。相关：C13。

**A8 I3-a/b/c 是否碰了 I2 已冻结的字节。** 尤其是 `interaction-baseline.integration.test.ts`（编译黄金）与 `interaction-runtime-baseline.integration.test.ts`（运行期黄金）——两次都没有使用 `--update`。
