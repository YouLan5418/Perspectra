## 2. 三条验收边界的现状

### 边界 1：新路径的 move 经统一生命周期收尾，不含接触名判断 —— **成立**

生产路径已被端到端验证：一个 v10 世界经 `WorldApplication.activate` 打开，玩家先经冻结路径成立一条 `base:hold-hand` 关系，再提交一次 `move`，落库事件里恰好一条 `character.relation-ended`，`reason` 为 `participant_moved`。

这条用例刻意做成**可证伪**的：它在同一份事件上直接调用 `SpeakMoveRulebook`，断言 Kernel 对 v10 的 move **只产出 `character.moved`**。因此上面那条结束事件不可能来自 Kernel 侧的关系分支——`manifestUsesCharacterInteractions` 仍是 `9` only，v10 没有回退可走。

旧 v9 冻结兼容路径一字未改。

### 边界 2：fold 只有一个执行位置 —— **成立**

- `interact`：fold 在 `FrozenInteractionWorld.resolve()` 内部（I3-b 起就在那里），应用层不介入。
- `move`：fold 在 `FrozenInteractionRulebook.resolve()` 里，且**只看移动之后的前缀**。
- 应用层没有任何代码调用 `fold()`，所以不存在"第二遍"。

用例断言结束事件**恰好一条**：同一候选集被 fold 两次会产出两条。

## 3. Host 决定装什么包

`WorldApplicationOptions.interactionPackages` 默认安装首批基础包。这个决定属于 Host 而不是世界：世界只能按锁选择 Host 已经安装的包，无法自己加入一个。装 0 个包是合法配置——那时任何 v10 世界在激活时失败关闭，而 speak / move 照常工作。
