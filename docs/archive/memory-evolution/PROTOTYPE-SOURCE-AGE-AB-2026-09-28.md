# 记忆来源 tick 年龄：Gemini 配对对照

> 2026-09-28；Perspectra V1 独立原型工作树。模型请求 `gemini-3.7-flash`，本机 8045；每次使用全新 `.tmp` 存档，未触碰 `D:/worlds`。

## 要回答的问题与控制

上一轮将 `sourceAgeTicks = 当前 tick − 记忆最新来源事件 tick` 加入自动记忆和主动召回的模型可见条目。这里检验它是否减少角色把离场前观察推断为当前物品归属的表达。对照组只在送给模型时移除 `sourceAgeTicks` 与对应的一句系统解释；处理组保留。两组使用相同世界历史、同一问题和同一个 Gemini 模型。存档、模型输出彼此独立；模型随机性没有固定。

世界在创世时记录 NPC 看到鲍勃取得杯子和听到鲍勃声称已交给玩家；鲍勃随后离场，在 NPC 视线外放下杯子。真实当前 holder 为 `null`，NPC 没收到这次放下的观察。为隔离时间字段，实验额外提交 2 或 20 个仅推进逻辑 tick 的受控轮次；这不是 20 轮真实角色互动。当前归属题作为最后一轮的观察提交。两组的权威事件前缀完全相同。9 对样本的首次角色请求在从处理组删除时间字段后逐对相同。

## 证据 → 发现 → 处理

| 条件（各 3 对） | 模型实际看到的记忆 | 可见回答 | 结论 |
| --- | --- | --- | --- |
| 问“亲眼看到什么”，相距 2 tick | 两组均自主查询并取得旧来源 `seq=13/14`；处理组两条均标 `sourceAgeTicks=2` | 两组均把亲见拿取与鲍勃口头说法分开，大体使用过去时 | 这道题天然要求回忆历史，不能衡量时间提示对当前归属误判的作用 |
| 问“现在还在鲍勃手里吗”，相距 2 tick | 两组首次请求均自动呈现 `seq=13/14`，未再主动查询；处理组两条均标 `2` | 两组都出现过“应该还在”式当前推断，也都有只陈述最后所见的回答 | 2 tick 提示没有显示稳定改善；带“应该”的推断仍超出亲眼确认范围 |
| 同一当前归属题，相距 20 tick | 两组首次请求仍自动呈现相同旧来源；处理组两条均标 `20` | 处理组 3 次中有 2 次明确表示无法确定后来转交或现在是否仍持有；对照组也基本只说最后所见 | 处理组出现了合适的不确定表达，但对照组同样谨慎，不能据此归因于 tick 字段 |

所有 18 次回答均成功发布；没有把另一角色的私密观察带入模型请求，召回本身没有改变正式物品归属。模型没有看到暗中放下；判断标准是角色是否承认其认知边界，而不是是否碰巧猜中真实 holder。对“应该还在”这类带保留措辞的现在时推断，报告为体验风险，不计作已提交世界事实。

原始存档分别在 `.tmp/active-recall-source-age-ab-20260928-{control|age}-{1..3}/`、`.tmp/active-recall-current-age-ab-20260928-{control|age}-{1..3}/`、`.tmp/active-recall-current-age20-ab-20260928-{control|age}-{1..3}/`。每个目录的 `protocol.json`、`case-1/requests.json`、`case-1/events.json`、`case-1/summary.json` 可逐条复核。实验入口是 `tests/experiments/active-recall-drive.ts` 的 `--hide-source-age`、`--current-question` 和年龄选项。

## 当前判断与边界

`sourceAgeTicks` 已验证能准确进入模型请求，且没有破坏这组召回与权限边界；**尚未证明它能稳定纠正旧状态当现状的表达**。不增加新的世界时钟、记忆协议或文本审查层。暂保留这个小提示，后续真正连续多轮试玩若再次出现明确的当前状态误报，再对比无提示与有提示，并检查 `items.lastObserved`（目前只有“上次观察、当前未知”的文字，没有 tick 年龄）是否才是角色主要依据。

此次使用人工受控 tick 推进与小样本随机模型回答，不能替代连续玩家/NPC 互动的行为验收，也不能估计效果率。现有 24 轮约定脚本测试的是履约，不能回答本物品时态问题，故未把它当作本次证据。实验脚本变更后类型检查、定向 lint 与 `git diff --check` 通过；未运行完整测试套件。
