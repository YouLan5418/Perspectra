## 三、新发现

### N1 [中等 · 信任边界] Director 上下文包含全部 `character.speak` 事件

`packages/application/src/context-pipeline.ts:268`：

```ts
const publicEvents = history.filter(event => event.eventType.startsWith('scene.') || event.eventType === 'character.speak')
```

该过滤不看 `scope`、不看 Scene 归属：

1. **私密发言泄漏**：`speak` 参数 `scope: 'private'/'direct'`（kernel `phase8Speech` 已实现 scope 字段）产生的 `character.speak` 事件携带完整正文，会被原样放进 Director 的 `publicEntries`，且 sourceKind 标注为 `scene_public_event`——把私密内容错误标记为公开来源。ADR-0066 §7 明确"Director 不能看到私密正文"，spec §11 要求权限过滤先于聚合。
2. **跨 Scene 泄漏**：多 Scene 世界中其他 Scene 的发言也会进入。
3. **无测试覆盖**：`context-pipeline.test.ts` 的 Director 用例只断言禁键（`rawMemory|latentGuidance`）不出现；rainy-road 的隐私 canary 全部是角色↔角色方向。

建议修复：按 `scope === 'scene_public'`（以及 Director 可见策略）过滤 speak 事件，并补 Director 方向的私密正文/跨 Scene canary 测试。修复后 §19.1 泄漏矩阵才算闭合。

### N2 [轻微] Director directiveTargets 的 sourceRef 是轮转合成值

`context-pipeline.ts:272-275`：`sources[index % sources.length]` 给每个 target 分配一个任意 Scene 事件作为 sourceRef。spec §11 要求"Directive target 必须已在接收角色自己的授权 Context 中"——该检查仍未实现（前次 F17 的遗留），现在用一个合成映射满足 schema 形状。当前 Director 仅输出抽象 Directive、目标即 Scene 成员，实际风险低，但这是"为通过校验而造来源"，建议要么实现真实授权校验，要么在 ADR 中明确该简化。

### N3 [轻微·潜在] Director 调度复用 NPC 成员过滤，`directorEligible` 未被消费

`round-coordinator.ts:717`：所有参与者（含 director 角色）按"actorId ∈ 玩家焦点 Scene 的 schedulableCharacterIds"过滤。Director 的 eligibility（spec §7.2 的 `directorEligible` 字段）不驱动调度；测试中 Director 参与者借用 Scene 成员 character id 才能被调度。当前无生产 Director 装配（rainy-road 无 Director），属潜在设计缺口。

### N4 [轻微] `controllerEpoch` 硬编码为 1

`context-pipeline.ts:229/249/279/297`：Receipt、ProviderCallIntent 的 controllerEpoch 恒为 1。当前没有任何 epoch 递增机制，无实际影响；将来引入控制器换代时需一并设计。

### 观察项（不构成缺陷）

- **Reflection 强度限制适用于新建记录**：`reflection.ts:417-424` 把无前值按 0 计算，新建记录的 intensity/priority 实际上限 200 permille——角色无法一轮内通过 Reflection 形成 >200 的强情绪/高优先级目标。ADR-0071 §4 的字面规则如此，实现一致；语义后果建议在 ADR 或规格中显式记录。
- **inner-tension 的 pole 级 basisRefs 被批次 basisRefs 覆盖**（`reflection.ts:162-167`）：pole 自身依据被稀释，投影校验只要求字段存在。
- **`recordResponse` 的重放幂等返回旧状态**（provider-quality `#mutate`）：重放同 outcomeId 不推进状态——正确的耐久幂等，仅记录。
- **共享 context.sqlite 的 user_version 轴**：四个 store 各自 bump（1/2/3/4），全部接受 0..4。旧版本二进制打开新版本文件仅在 version>4 时失败；未来每加一个 store 必须同步放宽所有白名单，建议在文件头注释或 ADR 中固化该约定。
