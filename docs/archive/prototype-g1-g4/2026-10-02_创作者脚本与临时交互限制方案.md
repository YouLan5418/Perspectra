# 创作者脚本与临时交互限制方案

| 属性 | 内容 |
| --- | --- |
| 日期 | 2026-10-02 |
| 状态 | 单活动原型已实现；已扩展脚本声明多 NPC 与有界调度链，新增角色主持实验；完整平台仍为后续方案 |
| 目标 | 创作者用包内脚本定义玩法，自行决定玩法期间允许哪些表达、行动与工具；角色仍能形成连续记忆 |
| 当前基础 | 原包 2.4.1、主持实验包 1.0.0、包内变量／活动脚本与现有 Character Turn |
| 首轮范围 | 可信本地作者脚本、单个活动玩法、指定参与者、一种小游戏 |

## 1. 要解决的问题

创作者可能希望平时自由扮演，进入小游戏后只允许对白和游戏操作，也可能希望保留表情、允许离场，或彻底只留固定选项。宿主不能预先替创作者规定收缩程度。

新增的是一份由脚本提供、随玩法阶段变化的交互限制。它替代依靠提示词要求模型遵守玩法的做法，并约束现有表达与执行入口；不建设另一套角色系统、记忆系统或通用插件平台。

现行原型契约的自由表达继续作为默认行为。本方案允许创作者在明确的作用范围和生命周期内主动收紧，不把所有世界的自然表达改成闭合枚举。

## 2. 创作者控制什么

| 配置维度 | 可表达的选择 |
| --- | --- |
| 对象范围 | 玩家、指定 NPC、当前参与者；不参加的角色保持原有能力 |
| 对白 | 自由对白、固定选项、预定义结构或关闭；可保留直接对话，也可限制收件对象 |
| 外显表现 | 允许自由 narration、完全关闭，或只允许作者定义的结构化表现 |
| 世界行动 | 分别允许或禁止移动与已有交互，必要时按交互定义、绑定和参数限制 |
| 游戏操作 | 当前可用的游戏交互／工具，以及参数格式、操作资格和阶段条件 |
| 生命周期 | 开始、各阶段切换、正常结束、退出和中止时启用或解除 |
| 调度 | 生命周期内谁先处理、何时唤醒、每阶段处理次数、等待条件及是否发生连锁反应 |

允许所有、只允许部分、全部关闭都属于作者选择；宿主不强制保留说话。但角色仍可以不提交操作，不将工具可用解释成角色必须执行。关闭输出不替作者决定角色的情绪、意图或策略。

限制可以收窄包原本支持的能力，也可以展示本包已注册的游戏交互；不能凭一个工具名获得宿主未安装的执行能力。

配置形式只作示意，尚不是已发布的 API：

~~~text
参与者：玩家、GPT
对白：允许自由说话
自由外显表现：关闭
移动：关闭
普通交互：关闭
游戏操作：猜数字、退出游戏
开始时生效，结算或中止后解除
~~~

允许什么与如何展示是两件事。游戏操作可映射到现有 interact，也可在模型端呈现为 guess_number(value) 等独立 tool；两种形式使用同一份执行资格和规则，不能成为两条权限通道。

## 3. 宿主如何执行限制

同一份有效配置同时用于以下入口：

1. **生成模型契约和玩家选项。** 移除被禁止的字段与操作，按作者定义生成允许的格式；需要同步修改普通 provider 契约和本机 Gemini 的扁平契约。受限模式的说明也应同步，不能仍提示模型自由写 narration。
2. **接收提案并验证。** 配置禁止自由外显表现时拒绝 narration；固定选项模式下只接受选项 ID。非法混合输出整包拒绝，不能删掉非法字段后执行剩下的对白或合法操作。先验证整个提案，再允许任何执行或发布；被禁内容不发布、不广播、不写入记忆。
3. **执行前再核对。** 按最新游戏阶段和参与者检查许可。即使旧页面、旧模型请求或直接调用仍带着操作，也不能绕过当前限制。通过许可检查后，继续执行原有规则裁定。
4. **发布真实结果。** 游戏脚本裁定后，由宿主按授权受众发布结果，模型再根据结果说话或继续操作。合法执行已提交后，后续对白失败不会回滚游戏结果。

玩家按钮、/act、普通文本解释、NPC perform 和独立 tools 应遵守同一规则。不能只藏按钮或只改 JSON Schema。进入游戏后，现有 /vars 调试命令也不能作为普通游戏输入绕过规则；作者调试编辑须明确作为调试能力，首轮可在玩法期间关闭该命令。

不参加的角色不受整局锁定影响。参与者离场、退出或中止后，只移除本玩法添加的限制，回到其原本拥有的能力，而不是无条件开启所有权限。首轮每个参与者只允许一个活动玩法，不实现多个插件的优先级或叠加仲裁。

## 4. 脚本、变量与权威结果

模型提出意图，作者定义玩法，宿主负责权限、调度执行、规则裁定和提交；任何一层都不越权替另一层做决定。脚本定义初始化、可执行操作、阶段条件、结果和结束条件。宿主确认操作者身份，校验输入，并提供该次裁定所需的状态；角色不能指定自己是另一个参与者，也不能让任意模型文本成为变量 patch。

脚本的规则计算与给模型阅读的数据分开。涉及隐藏答案、手牌等信息时，裁定代码可以在宿主控制下使用所需状态，但给角色的视图必须只包含它有权知道的部分。当前 variables.js 接口不会直接变成一个向所有角色暴露全部游戏数据的接口。

现有 pack-variables.json 是独立保存的变量快照，与世界事件没有共同事务，不能直接承担可靠的“扣分／发牌／结算，同时通知并记忆”的闭环。首轮必须沿用 Action / Rulebook / Event 提交路径记录已接受的重要游戏结果，使关键状态、该操作的结果、下一阶段／轮次及活动修订号原子提交；变量快照若展示这些结果，只能由已提交记录派生。不会通过先写 sidecar、再追加事件来伪装原子性。具体事件承载只按首个小游戏的必要状态确定，不提前设计全玩法通用数据库。

脚本无权修改受控世界位置、其他角色秘密或其他插件状态。若游戏需要移动、关键物品或关系变化，仍调用相应已注册规则。第一版继续仅运行可信作者脚本；现有 Node VM 不是恶意插件安全沙箱。

## 5. 如何保留记忆

限制的是当前可执行、可发布的行为，不是删除历史记忆。现有 CharacterViewBuilder / CognitiveMemoryService 继续作为角色认知入口；读自己的记忆不等于拥有被禁的行动能力。

| 内容 | 进入记忆时的含义 |
| --- | --- |
| 已接受并提交的游戏结果 | 角色确实观察到某次出牌、猜测反馈或结算；保留执行来源 |
| 游戏期间的合法对白 | 某人说过这句话，不证明正文中的行动或胜负已经发生 |
| 该角色获知的私人结果 | 只对该角色授权，例如自己的手牌或私下收到的提示 |
| 被拒绝的提案／外显草稿 | 不作为已经发生的行为；必要的拒绝反馈仅交给有权接收者 |
| 对参与者风格的印象 | 后续可以形成主观认识，不能反写成程序确认的游戏事实 |

游戏结果应提供角色可读的过程细节和来源引用，不能只记“变量从 2 变成 3”。例如记“第 3 次猜 37，收到偏小反馈”，而不是把隐藏答案和完整游戏快照送入每个角色的 Source。结果受众由宿主收窄，不允许脚本扩大到未授权角色。

若使用独立 Hindsight Core 实验，仍需通过同样授权的来源接入；本方案不意味着当前包入口已自动使用该实验后端。

## 6. 自由文本的保证范围

允许自由对白时，角色仍可能说“我已经出牌了”或把动作写进话里。确定性限制能阻止这句话改变游戏状态，却不能仅凭 speech 字段证明其语义始终只是对白。

作者可选择固定选项、结构化回复或模板对白来进一步收紧；宿主不默认增加关键词过滤、语义分类器或第二模型审查。对白和程序结果在呈现及记忆来源上保持区分，但这不等于自由文本语义一致性已经证明，仍需试玩观察是否持续造成错误认识。

## 7. 场景示例

| 场景 | 创作者选择的范围 | 程序裁定什么 | 角色可以记住什么 |
| --- | --- | --- | --- |
| 猜数字 | 保留自由对白；关闭外显表现、移动和普通交互；允许猜数、退出 | 参与资格、猜数次数、偏大／偏小、命中与结束；答案不提供给猜测者 | 自己猜过哪些数、谁给过什么建议、上一局结果 |
| 牌局 | 保留说话，允许或关闭表情由作者决定；只允许当前合法的抽牌、出牌、过牌、退出 | 轮到谁、持有什么牌、出牌是否合法、公开牌和胜负 | 公开出牌顺序、自己的手牌变化、对手的发言与策略印象 |
| 双人解谜 | 允许私聊或限定交流渠道；只允许查看线索、提交答案、操作指定机关 | 哪个角色能看哪条线索、解答条件、机关变化 | 本人获得的线索、对方转述、误解与后续核实；不能直接知道对方私有线索 |
| 限定选项的审讯／辩论 | 禁用自由对白和外显表现，只允许作者提供的问题或回应选项 | 当前可问的问题、提交证据、阶段推进 | 问过什么、对方如何选择、公开或本人可见的证据 |
| 共同烹饪小游戏 | 保留对白和日常表情；追踪的烹饪步骤只允许选料、加热、关火等操作 | 材料消耗、步骤、温度档位和成败 | 谁忘了关火、谁提出建议、最终结果；对白不能直接完成步骤 |
| 仪式／模型实体化装置 | 可关闭全部自由输出，只允许检查、切换、确认、取消；结束后恢复自由表达 | 开关、顺序、消耗和装置结果 | 自己看到的仪式过程与结果，之后自由互动时仍能谈起 |
| 平时闲聊 | 不启用限制；沿用包原有自由表达和执行规则 | 当前世界明确追踪的少数机制 | 按现有权限记录互动与经历 |

这些场景不成为 core 的新动作枚举。它们是作者脚本和交互定义的实例，也不预设角色应当开心、合作或选择最优策略。

## 9. 首轮实施与验收

先使用猜数字完成最小闭环：开始 → 参与者受到配置限制 → 角色猜测／说话／沉默 → 脚本裁定 → 授权结果进入观察和记忆 → 结算或退出 → 解除限制 → 后续角色能谈起该局经历。小游戏只用于验证载体，不决定后续所有玩法的收缩程度。

实施顺序：

1. 接入由包脚本返回的表达和交互许可，覆盖模型契约、玩家输入与宿主执行检查。
2. 接入一种受信任游戏交互的裁定、原子结果提交和授权观察，复用已有执行与记忆路径。
3. 接入玩法参与者的临时调度，约束玩家提交并替换其默认自动反应；接通开始、阶段变化、结算／退出／中止及新进程恢复。已提交的游戏阶段用于恢复限制；不要求恢复未完成模型草稿。
4. 用真实 Gemini 做一次小游戏及游戏后自然互动，记录权限拒绝、结果、记忆来源和可见回应。

必须验证：

- 禁用 narration 后，该字段即使被模型提交，也不会传播到其他角色或记忆。
- 隐藏移动或普通交互后，直接调用及过期请求同样失败。
- 非参与者不被锁定；退出和中止解除正确；恢复存档不会悄悄放开尚未结束的游戏。
- 无非法批次部分写入，关键结果和状态不出现一半提交。
- 角色记得自己获知的游戏过程，其他角色不能读取隐藏答案或私人结果。
- 自由对白对玩法事实的错误声称是否造成可见认知漂移，单独记录，不以机械权限测试通过替代体验验收。

第一版不做完整插件商店、任意代码安全沙箱、多玩法叠加、跨版本存档迁移或新的检索算法。此文只整理方案，不修改当前运行时，也不表示以上能力已经实现。

## 10. 生命周期内由创作者定义调度

可行，并与表达／交互许可一起随玩法生效。许可回答“这一刻能做什么”，调度回答“这一刻谁获得处理机会、何时轮到下一位”。调度仍不替角色选择具体操作、策略、情绪或对白。

当前 [runPrototypeActivations](../../../packages/application/src/prototype-activation-cycle.ts) 按已授权观察产生候选，在既定角色顺序中逐个调用 [PrototypeCharacterTurn](../../../packages/application/src/prototype-character-turn.ts)，有波次数、调用预算、超时和中止机制。因此单角色决策可复用，玩法期间替换参与者的调度选择，不需要另造角色执行器。现有调度只识别特定 accepted 观察，游戏结果触发也须一并接入，不能认为写入任意结果就已经能唤醒角色。

作者可定义固定轮流、指定主持人、结果触发、按阶段顺序、等待玩家输入，或只在特定操作后给旁观者一次回应机会。调度脚本只返回调度决定，不能直接调用角色模型或获得模型凭证；实际 Character Turn、预算、超时和取消由宿主执行。定义可以按游戏状态计算，不要求把所有玩法限制在几个宿主枚举中；宿主仅要求返回可以验证并有界执行的调度决定。

| 场景 | 调度例子 |
| --- | --- |
| 轮流猜数字／出牌 | 玩家提交合法操作后才轮到 GPT；GPT 合法操作提交后再等待玩家 |
| 主持人小游戏 | GPT 开场 → 玩家选择 → Claude 裁判处理 → 给指定参与者一次回应机会 |
| 双人解谜 | 提交线索或请求协助时唤醒指定同伴；普通闲聊不自动让全部角色接力 |
| 投票或同时揭示 | 先收集各参与者的决定，未收齐前不向其他人展示，再统一发布结果；不等于必须并行写库 |
| 分阶段仪式 | 当前阶段只激活负责角色；确认成功后才进入下一阶段和下一角色 |

玩法调度接管指定参与者的活动触发，不与其默认反应循环叠加；未参与者仍走原有机制。结束或中止后移除调度接管，恢复原有机制。若作者允许游戏参与者处理外部刺激，何时插入或暂存该处理机会也由玩法调度决定，但不能删除已经提交的合法观察。

玩家输入也必须检查当前轮次与许可，不能仍允许其先提交游戏行动，再让调度发现“还没轮到玩家”。对白是否允许在非行动回合发表，由作者单独定义；它不必自动消耗游戏行动回合。游戏回合与现有世界 tick 分开理解，不能把每次对白的提交都当成换手。

等待玩家时返回控制给页面，不保持无限循环。角色选择 abstain、返回非法操作、模型失败或预算耗尽时，要有作者定义的等待／重试／跳过／中止路径；跳过只代表让出机会，不能伪造该角色已作出的行动。宿主负责执行总量与超时上限、串行状态提交、暂停和取消，脚本不能绕过这些执行边界。作者可在宿主资源上限内配置次数和顺序。

唤醒资格不授予新信息读取权限。其他人公开出牌可以触发回应，某人的私密牌面不会因此进入回应者上下文；观察与记忆按原有授权独立记录。即使某个阶段不唤醒角色，该角色有权收到的经历也不能仅因为没有模型调用而被丢弃。后续处理时可读取其授权记录。

首轮仍只做一个玩法及其参与者的调度接管，先验证轮流和等待玩家；不增加后台无限自治、通用并发写入或多玩法调度仲裁。重启后根据已提交的玩法阶段和行动顺序恢复当前轮次，不要求精确恢复未提交的模型调用。

新增验收：未轮到者不能提交游戏行动；非行动回合对白按作者配置处理；默认调度不重复唤醒参与者；沉默或失败不会卡住宿主；未唤醒者的授权经历可供后续记忆读取；退出／中止／重启后调度归属和当前轮次正确。以上为验收目标；首轮实际范围与验证见第 12 章，其他配置不因列入方案而视为已实现。

## 11. 首轮必须守住的系统边界

以下是待实现并测试的不变量，不表示当前运行时已经满足全部条件。

~~~text
未提交，不换手。
未授权，不可见。
未轮到，不可执行。
未唤醒，不等于未观察。
~~~

### 11.1 四条不变量的准确含义

| 不变量 | 实现含义 | 首轮验收 |
| --- | --- | --- |
| 未提交，不换手 | 动作结果、关键游戏状态和下一轮次一起原子提交；只在提交成功后采用新状态并计算下一调度 | 提交失败后结果、阶段、修订号和行动者都不变；不会唤醒下一位 |
| 未授权，不可见 | 模型视图、UI、结果观察和记忆来源均受角色授权约束；裁定代码的完整状态不直接交给角色 | 隐藏答案及私人反馈不出现在其他角色请求、玩家状态或其授权来源里 |
| 未轮到，不可执行 | 对有轮次要求的游戏操作，在玩家和 NPC 执行前检查当前行动资格；不能只看是否刚被唤醒 | 非当前行动者直接调用猜数也被拒绝；允许的非行动回合对白仍可发布而不换手 |
| 未唤醒，不等于未观察 | 授权观察的提交独立于角色调度，模型处理可延后；实际长期提炼也可延后 | 不调用某角色模型时，其合法观察仍留在授权记录中，之后能读到，且无私密泄漏 |

“未轮到”不是禁止所有输出的全局 isTurn。表达许可、行动资格与唤醒资格分别判断；游戏回合、阶段、世界 tick、worldSeq 也不混用。非行动回合的对白是否可用、是否推动某个玩法阶段，均按作者规则明确处理。

“已发生”包括合法收到某人的发言，以及确实收到一次拒绝反馈，不表示这些文本的全部内容已成事实。被拒动作不能记成动作成功，但“我的请求被拒绝”可以作为该角色获知的反馈；这与广播被拒提案草稿不同。

### 11.2 正确提交顺序

~~~text
收到完整提案
→ 检查请求时效、角色权限与操作资格
→ 验证整个输出（含所有字段）
→ 按最新状态进行规则裁定，计算拟议结果和下一阶段／轮次
→ 原子提交：动作结果 + 游戏状态 + 下一阶段／轮次 + 修订号 + 授权观察
→ 从已提交状态更新视图，计算下一调度
~~~

阶段与轮次可以在裁定时计算，但在提交前只能是候选，不能成为有效状态。不能先提交动作、再另写轮次；也不能先把轮次切给下一人、再提交上一操作。进程在提交成功后中断，重启应从同一批已提交记录恢复新轮次；未提交的计算允许丢弃。

首轮复用 expectedHeadSeq/expectedTick、writer fencing 和 transactionId；活动结果、状态修订和授权观察在 commitRound 中原子提交。执行前另外核验活动 ID／修订号与当前行动者，世界事务检查不替代活动资格检查。

### 11.3 请求时效与重复提交

将用户建议的活动请求版本纳入首轮，但避免维护多个表达相同状态的计数器：

- **活动 ID**：标识这一次活动实例，不是玩法定义 ID；新开一局不能复用旧实例身份。
- **活动修订号**：从已提交活动状态取得，是首轮的请求时效依据；活动状态、有效策略或行动资格变化时，在对应提交中更新。
- **阶段 ID、游戏轮次**：作为明确的玩法状态供作者使用，不承担世界 tick 或全局事件序号的职责。
- **轮次令牌**：首轮不增加独立令牌；活动 ID + 修订号足以表示请求对应的状态。若以后同一修订内需要多个独立提交资格，再按实际需求增加。

活动相关模型请求与玩家操作携带其所依据的活动 ID 和修订号，执行时核对当前状态。已结束、已切换阶段或已经轮转后返回的旧提案，不执行其任何部分，也不沿用旧许可。单纯与活动状态无关的世界对白不自动改变活动修订号。

时效检查不能代替幂等。相同已完成请求重试，复用原提交结果，不再次执行或换手；相同请求标识却改了内容应拒绝。过期且尚未成功提交的新提案拒绝。优先复用既有幂等提交机制，不引入新的 Receipt、Hash 或通用协议层；是否需要将幂等键传到现有页面，由接入时核对，不能仅因内部已有 transactionId 就宣称重复点击已经覆盖。

### 11.4 不把技术失败当成角色行为

| 结果 | 含义 | 能否当作主动让出回合 |
| --- | --- | --- |
| abstain | 本次没有提交表达或操作 | 不能自动当作 pass；后续机会由作者调度规则决定 |
| pass | 角色明确提出作者定义的让出操作，经许可、裁定并提交 | 可以，是一次真实游戏操作 |
| invalid output／非法操作 | 整个提案或操作被拒绝，没有成功执行 | 不能伪造为主动 pass |
| provider failure／timeout／budget exhausted | 调用没有成功完成或不能继续 | 不能伪造角色意图；按作者配置等待、重试或提交明确的规则性跳过／中止 |

若规则因失败或沉默而跳过，该跳过本身也须经宿主提交，记录其真实规则原因，才改变轮次；不套用“角色主动放弃”的叙事。重试始终受宿主预算和取消控制。已有操作成功而后续模型续写失败时，保留真实操作结果，不再次执行，也不误判整次操作未提交。

### 11.5 首轮收口

只做一局猜数字、玩家与一个 NPC、同一活动接管这组参与者，每次最多让一个 NPC 获得处理机会，然后回到等待玩家或结束。不开放多活动仲裁、多人同时收集或新的并发数据库路径；场景章节保留这些作为后续应用例子。

开始、阶段变化、正常结束、退出、中止与重启恢复均属于首轮。限制与调度从已提交活动状态派生；解除时恢复包原本合法的能力，不恢复成“全部开放”，也不把未参与者一起锁住。授权记录不依赖即时唤醒。

除四条不变量外，必须单独覆盖整包拒绝、旧版本提案、幂等重试、abstain 与 pass 与技术失败的区别、默认调度不重复激活，以及 /vars 等直接入口不能绕过活动规则。自由对白的语义越权仍靠真实试玩单独验收，不声称四条机械不变量已证明语义完全正确。


## 12. 首轮实现与玩家逃生

### 12.1 宿主最高优先级的中止

玩家“逃生按钮”位于宿主外层页面，与创作者页面及游戏选项分开。POST /api/escape 仍要求本机宿主令牌，但不调用作者的 policy、resolve、schedule 或 onOutcome。作者即使没有定义退出、关闭所有游戏操作，或玩法本身报错，也不能通过这些定义禁用宿主中止。

处理中先取消模型，等待当前提交路径结束，再按最新已提交状态原子写入 host-aborted：active=false、turn=null、revision+1，并记录参与者可见的中止经历。正常世界能力和默认调度据此恢复；迟到的模型输出不能提交。暂停同时解除。重复中止已经结束的活动不追加事件。

“恢复”只解除本活动施加的限制，不回滚世界、不删除已提交记忆，也不把其他权限全部打开。SQLite 或存档损坏时仍允许明确报错，不通过伪造成功规避事务失败。

此原型只接受可信作者包。页面为同源 iframe，宿主控制条避免被作者普通页面布局或游戏策略隐藏，但这不是隔离恶意 JavaScript 的浏览器安全沙箱；不宣称抵御故意操作宿主 DOM 的代码。

### 12.3 范围与证据

已实现：一个活动、玩家与 GPT、同一场景开始；基于当前状态的权限与调度；自由／关闭／固定原文选项对白、narration／移动开关、原交互白名单；同步确定性猜数裁定；动作和下一轮次同事务；模型及玩家入口复核；按已提交活动恢复；随时宿主逃生。其他 NPC 不继承本局限制。

首轮历史实现中 schedule 只能 wait 或 activate 本局 NPC，每次一次激活；这项限制已被第 13 章替代。onOutcome 只支持 wait；失败保留真实当前轮次，由玩家显式请求重试或逃生，不实现自动规则跳过。每次最多两次决策机会，若使用主动 recall，可能有一次额外模型补问，全部请求均有超时与取消。未提交的模型机会不做持久化重放或跨重启精确幂等。

游戏结果与开始／中止产生参与者授权观察，现有 CognitiveMemoryService 只读取这些授权记录。未唤醒测试在零模型调用时仍能保留经历，逃生后可召回自己的猜数反馈；旁观角色无该私密游戏来源。独立 Hindsight Core 仍未自动接入此世界包，不把现有记忆桥接称为 Hindsight 长期提炼验证。

自动化验证包括实际事务插入后故障回滚、非法混合输出不提交、非当前行动者拒绝、版本失效与已提交请求去重、秘密和非参与者隔离、重启当前轮次恢复、无唤醒仍可形成授权记忆、技术失败不伪造主动 pass、取消迟到输出和宿主逃生。浏览器实际检查了包内页面嵌入、游戏按钮、开始后隐藏移动、逃生后恢复移动且保留转录。

真实 Gemini 3.7 Flash 短冒烟在新局中完成三次 NPC 猜数及三次结果后对白。早期网页另两次调用返回成功但未通过提案验证，没有换手或产生假动作；后续成功样本不能证明格式问题已经消失。此限制通过保留轮次、显式重试与逃生处理，尚未进行长试玩，也不声称自由对白已经完全不存在语义越权。

## 13. 多角色主持与包内玩法扩展

### 13.1 当前需求与最小改动

玩家希望主持角色私有持有答案并由模型裁决；后续玩法尽量只改包。原桥接把参与者固定为一个 NPC，initialize 还由宿主提供随机数字，onOutcome 只能等待。这三处把具体玩法写进了宿主。本轮用脚本声明 npcIds、通用初始化和有界下一角色决定替代它们，没有新增玩法核心枚举、数据库表或插件框架。

活动桥接仍在 tests/experiments，未改动正式 Memory schema。原包升级 2.4.1，独立目录 ai-girls-hosted-guess 版本 1.0.0；本轮使用新存档，保留旧目录与运行中的旧世界，不迁移旧资产 hash 或重解释旧脚本。

### 13.2 脚本和宿主分工

定义精确声明 title、npcIds、operations；最多八个 NPC，玩家身份由宿主绑定，全部参与者须存在并在开始时同场景。initialize 只接收 playerId/npcIds，随机答案由具体脚本生成。角色模型只收到公开状态与自己的 private；internal 不进入角色视图。

policy 分别决定表达和操作许可。resolve 接收裁定所需完整游戏状态，返回新状态、结果描述和观察范围；脚本不能直接写世界或调用模型。schedule 和 onOutcome 返回 wait 或 activate 已声明参与者。模型契约、UI、提案检查和执行检查沿用同一策略；游戏操作与阶段／换手及其授权观察原子提交后才计算后续调度。

每次输入最多串行四次角色激活，每次最多两次决策机会，主动 recall 最多增加一次补问，至多十二次实际模型调用；活动链总时限 90 秒。超时、取消、预算耗尽和技术失败均保留已提交状态，不生成假 pass。具体脚本可请求后续角色，宿主不会无限执行；非参与者保留原机制，本次链参与者不会再被默认循环重复激活。

观察范围 self 同样适用于玩家操作与角色操作。它只约束结果描述授权收件人：作者仍须把秘密存放在对应 private 中，不能把 secret 放入 public 后指望 self 隐藏它。

### 13.3 主持实验流程

```text
Claude 开场 → 玩家猜测 → Claude 裁决 → GPT 猜测 → Claude 裁决 → 玩家
```

Claude.private 持有答案；玩家与 GPT 没有答案。主持模型提出 judge(偏大／偏小／猜中)，包内脚本根据裁决转阶段或结束，不读取答案比较数字。宿主只裁定当前角色、阶段、schema、权限与提交合法性。因此允许主持人判断错误，不在程序中暗中纠正。结果来源写“Claude 主持人裁决为……”，准确记录裁决发生，不宣称数字比较已经被独立核实。

正常结束和宿主逃生恢复原本能力；旧裁决仍是参与者已发生的经历。现有 CognitiveMemoryService 可读取各自授权来源；独立 Hindsight Core 未接入本入口。角色私有答案仅用于当前玩法上下文，本轮不承诺结束后自动形成长期秘密记忆。

### 13.4 证据与接受的限制

自动化覆盖三人调用顺序、私有答案范围、错误裁决仍被采用、未授权角色拒绝、调用链预算、等待裁决时重启及逃生、结束后回忆裁决。真实 Gemini 3.7 Flash 八次调用完成开场、一次玩家猜测、两次主持裁决及一次 GPT 猜测与对应对白，全部通过验证且回到玩家；角色 Claude 仍由 Gemini 扮演，不表示改用了 Claude 模型供应商。

程序隔离不保证模型不会在自由对白透露自己的秘密，不保证主持算对或台词完全遵循已提交状态。本轮是短冒烟，完整长试玩仍待进行。不实现多玩法叠加、同时输入仲裁、后台自治、任意模块导入或恶意作者沙箱。能在现有状态、同步裁定、单角色激活中表达的玩法可继续通过包脚本扩展；需要新的宿主能力时再按实际需求补桥接，而不是承诺任意玩法零核心改动。

## 14. 已提交活动结果的记忆关联

玩家与 NPC 的完整授权结果统一包含 `resultMetadata.activity`：活动 id、revision、作者阶段 phase、游戏 round、active 和 started/updated/ended 标记。宿主根据提交结果产生最小元数据，复用 Character Turn 的 executionResult 回调附带 observationMetadata；默认角色回调不产生额外元数据。只有获得完整结果的收件人收到它，occurrence_only、未参与者和 self 范围以外的角色不获得详细活动元数据。完整状态、private/internal 不复制到观察。

该信息与原有结果观察同事务提交，不新增正式 Memory 表或世界状态。独立记忆实验按该角色授权档案和前缀，把 Atom／Episode 与已有开场、结束证据关联；Delivery 补入原文并说明材料是否包含结尾，不将概括提升为世界事实。作者阶段字符串不是通用生命周期枚举，主体动机仍不能从“活动已结束”推出。

当前接入和真实重放证据见 experiments/activity-memory/reports/report-closure.md。实际网页仍使用现有 CognitiveMemoryService；独立 Hindsight 核心未接入网页，不将受控重放描述成正式长期记忆上线。

## 15. 连续试玩暴露的问题与局部修正（2026-10-03）

第一轮长试玩发现固定房间最后一人离开后被永久关闭，导致返回后虽然位置正确，却没有场景成员与观察者。固定 location-bound Scene 现在只移除离开者，空房间仍可经受控移动重新加入；临时无地点会话的最后离场仍关闭，显式 scene.closed 仍为终态。没有修复或迁移冻结旧存档，本轮使用新存档。分离期间的发言不会因为以后重新相遇而追补授权。

活动唤醒改为按授权观察的 sourceSeq 取最近八项，取代按观察 ID 的尾部取样。它与原 Character Turn 的近期观察时间顺序一致，不增加角色读取权限，不把未唤醒等同未观察。

实验 Delivery 的结束补全现在只由命中的具体 Atom 自带的已提交活动元数据，或明确且已授权的活动 ID 触发。同一 Episode 中的饮料闲聊不再继承活动 ID，也不因 Episode 整体有关联就补入开场与结尾。Episode 的结构关联仍保留在档案中，Source／Atom 不改写。没有直接活动元数据的旧对白可能漏掉结尾扩展，这是本轮接受的限制，不以语义猜测来补活动身份。

这些修改没有改变正式 Memory schema、World State、Event schema 或 Rulebook 裁定。实验记忆仍只从各角色授权 Source 前缀构建；真实重放、预算与六字段追溯见 experiments/activity-memory/reports/report-live-v2.md。正式网页仍使用原生记忆。
