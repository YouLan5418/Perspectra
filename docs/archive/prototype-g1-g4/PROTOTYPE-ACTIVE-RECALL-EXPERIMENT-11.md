# 实验 11：角色主动召回作为证据

| 属性 | 结果 |
| --- | --- |
| 日期 / 分支 | 2026-09-28 / `codex/custody-transfer-experiment` |
| 依据 | 玩家原话、角色理解、世界事实必须分离；当前自动召回不能让角色自己决定查什么 |
| 范围 | 只试 RECALL；不做 ASK / INSPECT / CONSULT_RECORD / COMPARE_REPORTS 的新接口 |
| 验收 | 角色可自选一次查询；仅从自己的记忆读到带来源证据；可在拿到证据后自行表达或行动；查询本身不提交世界变化 |
| 证据 | `experiments/active-recall-2026-09-28/`、`experiments/active-recall-opaque-2026-09-28/`、`experiments/active-recall-away-2026-09-28/` |

## 1. 选择最小切口

`PrototypeCharacterTurn` 以前在角色激活前调用 `CognitiveMemoryService.prepareStimulus`，把近端观察和自动召回交给模型。记忆服务已有角色与世界前缀范围内的 `recall(address, characterId, query, asOfWorldSeq)`；v2 返回的 metadata 带 `epistemicKind`、说话人和事件来源。缺口是角色无法主动选择查询词。

本实验在原有决定中增加 `recall(query)` 候选。一次激活最多查询一次，限 2–120 字；记忆服务仍按当前角色和该次激活的 World 事件前缀取数，默认最多 10 条。返回完整命中条目的文本、证据类别、说话人和来源序号，并明确声明“未命中不代表未发生”。随后仍由同一角色模型自行决定 publish / perform / abstain。一次查询多耗一次模型调用，查询本身不生成 World 事件，不写入新的信念。角色刚执行了受控行动后的结果续写保持原有边界，不额外开放查询。

没有新增工具总线、记忆协议、数据库、分类器、Jev 干预或认知提交字段。无记忆服务时不给模型 recall 选项；第二次 recall 按无效输出拒绝。记忆服务完整性错误继续向外抛出，不伪装成模型格式错误。

## 2. 模型无关验证

以同一 NPC 的两条旧观察建立冲突：正式观察到鲍勃取得物品，随后听见鲍勃声称已交给玩家；另一角色的私密观察只属于其本人。

- 首次请求可选 recall；角色提出“钥匙”后，续次请求取得该 NPC 范围内的 `observed_action` 和 `reported_speech` 两类记忆。后者保留鲍勃为说话人和来源事件。
- 另一个角色的私密内容不进入 NPC 请求。查询没有产生物品转移、移动或信念事件；最终表达仍按现有 Rulebook 路径提交。
- 一次激活第二次请求 recall 被拒绝，World 头不变。

`tests/prototype/active-recall.test.ts` 以真实记忆 SQLite 和角色激活执行这几条，不用模拟检索结果。相关 `perform` 续写及记忆检索测试验证原路径仍可运行。

## 3. 真实 DeepSeek 决策

同一前缀内：鲍勃正式取得杯子；NPC 看到了这次转移，却又听见鲍勃说“我早把杯子交给玩家了”。两段旧观察被 18 条无关近端输入隔开。另有只属于鲍勃的私密观察。所有 World 数据目录为本轮新建；模型为 `deepseek-flash`，原始请求、决定、World 导出均保存，不记录密钥。独立脚本显式给角色装配记忆服务；网页试玩本来已有的自动记忆接线仍属工作树中的另一组未提交修改，不纳入本轮提交。样本小、没有盲评或统计成功率。

| 条件 | 初次请求已有旧证据？ | 真实模型行为 | 主动查询新增了什么 |
| --- | --- | --- | --- |
| 明确问杯子来源 | 有，两条都由自动召回进入 | 直接回答，并区分亲见与听说 | 未查询；结果不能归功于新入口 |
| 请先核对杯子旧经历 | 有，两条都由自动召回进入 | 自主查询“杯子 保管 转移 鲍勃 玩家”，再区分亲见与听说 | 返回两类来源及当前问题；验证主动入口和来源使用，无法证明行为因查询才改善 |
| 用“从桌上被拿走的东西”间接指代，鲍勃仍在场 | 有，在场角色线索让自动召回命中旧记录 | 自主查询，但主要重复已在上下文的来源 | 仍不能隔离主动查询收益 |
| 同样间接指代，鲍勃已离场 | 无旧证据；上下文仅有“上次看见鲍勃保管、现在不能确认”的可见物品历史 | 自主查询“桌上被拿走的东西 到了谁手里”；只命中当前玩家问题；随后谨慎表示不能确认后来去向 | **未命中旧交接/传闻。** 未把旧经历作为新增证据；谨慎回答主要有赖原有 `items.lastObserved` |

四次真实激活共七次模型调用；其中三次自愿选择 recall。所有请求都没有包含另一角色的私密观察，查询没有改变正式杯子 holder，最终仍由鲍勃保管。这里的“自愿”只指没有注入决定；玩家问法显然影响是否查询，不能推成长期自主核查能力。

类型检查、Lint、默认测试（16 文件 107 项）通过；主动召回、续写和记忆检索的相关测试（4 文件 54 项）通过。未运行全量历史套件、跨进程恢复及更多模型/世界包测试；本轮没有改动事务或恢复语义。

## 4. 判断

**机制验证通过，体验收益尚未通过。** 角色能够主动调已有记忆，权限和证据来源保持可见；当自动召回已经命中旧记录时，额外查询的因果收益无法判断。当自动召回漏掉间接指代时，角色虽主动查询，基础词项检索仍可能只回当前问题。

因此本轮不能宣称“复杂争议信息可可靠核查”，更不能把查询结果当客观答案。下一次若继续，应固定同一旧经历，分别测角色实际使用的查询词、带物品 ID 的查询词和同义转述的候选命中，再决定是否需要小幅改善可检索线索。优先检验命中、进入请求、角色最终使用三个环节，不先建设多层工具系统或改写记忆权威。
