## 1. Evidence → Finding → Path

07 连续试玩中，桌面翻书、压页、挪动和翻转怀表触发了 10 次不必要重写。把微小物理操作推导成物品取得，既不符合当前玩法追踪的机制，也会撤回正常查看进展。

本轮把受控对象收窄为当前的保管/携带关系。该选择替换了“手里/桌上直接证明 holder”的解释；沿用已有 `holderId` 和 `entity.transferred`，没有增加物理姿态字段、所有权字段、分类器、事件种类或裁定阶段。

## 2. 实验契约

- `holderId = A`：当前由 A 保管或携带，A 可以按已有规则提出转交或解除保管。手是否接触、物品暂放何处不由该字段表示。
- `holderId = null, locationId = L`：留在 L，未分配个人保管；符合规则的角色可取得保管。这里不额外定义法律所有权或完整使用权限。
- `base:take`：纳入自己保管；`base:give`：转交保管；`base:drop`：解除个人保管并留在当前场所。ID、参数、事件与权限校验维持原路径。
- 翻页、扶住、挪动、短暂托起查看后放回、临时接过查看后归还，以及保管人把物品暂放桌上，都不自动要求保管迁移。
- 收进自己的随身包准备带走、交给另一人负责保管、解除个人保管供他人取用，属于受控变化。
- 对话可以表达主观说法；表达没有写世界状态的权限。未执行的保管迁移仍可能成为叙事体验缺陷，不能用数据库未变证明文本一致。
- Jev 只解释文本对该关系的宣称，World 在发布对应的本地窗口内对账；不以全历史“曾保管”支持本次取得。

### 已接受的边界

本轮同一房间内允许开放的微小物理表现，不要求手部或桌面姿态完全与库存一致。此前仅“手里”“桌上”的分叉不再自动计入保管冲突；这是主动缩小机制承诺。

`holderId` 与 `locationId` 仍互斥，现有持有物可达性仍随保管人处理。本轮没有实现“保管人已离开，但物品在另一个房间”或丢失/盗窃/委托的通用机制。跨房间携带与留下的规则另需体验验证。

## 3. 改动

1. 角色请求解释 `holderId` 与 take/give/drop 的保管语义；既有执行反馈改为“取得/转交/解除保管”，不再用“不在你手里”解释执行权限。
2. 玩家转录中的正式转移显示“交由某人保管”或“解除个人保管，留在当前场所”。
3. Jev 人物判定只确认保管/携带关系；原放置问题只确认解除个人保管或当前无人个人保管。桌面背景本身不作为解除证据。
4. 真实试玩发现一次“已有保管人收进口袋”被判成新取得。之后在 World 对账增加小修正：如果窗口开始与结束均为同一保管人，且无进入/离开迁移，将 `OBJECTIVE_NEW` 留为 `UNCERTAIN`，不建立虚构根，也不触发实验性重写。保留原始日志。

第 4 项承认当前分类结果没有描述迁移来源/去向，不能区分新取得与已有保管人的操作；不把它改成确定支持。在这种条件下，声称发生了某次往返交付也可能只能待确认，这是接受的检测限制。

Jev 全程影子运行，发布前自动改写未启用。没有自动记忆回写或新认知事件。

### 4.4 真实发现的限制与后续修正

**一次误报：** seq265“把怀表塞进外套口袋”，Jev 选 `OBJECTIVE_NEW`；实际早在 seq205 已由陆舟保管，本窗口没有迁移。原审查建立 root265，seq367 的正常怀表历史回述还被接为 `CHAIN_RECALL`。

据此实施第 3 节的小对账修正。`reconcile265/` 复用真实 Jev 原答案，零新模型调用，重新经过影子对账后结果为 `UNCERTAIN`，三个角色的 root 均为 null。单元测试验证待确认结果不成为后续虚构链。**修正后没有再跑整段真实对话，不能声称后续 Jev 来源选择已实测恢复。**

**错误回忆仍在：** seq367 陆舟说“程雨没接”日记，seq373 / 385 程雨沿用此说法；正式 seq187 已转交，seq199 程雨还明确说“我接下”。这三条对白是同一错误经历的传播，本轮没有解决否认接受、事实选择与记忆更新。Jev 也没有稳定标出这段错误。

**重复互动仍在：** 后段多次复述“站着等方向”；本轮没有改调度或角色行为策略。

## 6. 判断及下一步

支持将保管/携带关系作为少量权威机制，把同一场景内的微小物理操作留给自由叙事。真实玩法已经显示二者可以共存，且能消除已知查看误伤。

这不是 Jev 自动纠正的通过结论。评价范围缩小、一次真实误报和错误回忆传播均需保留在判断中。下一步优先验证自由玩家输入对这一边界的解释，以及跨回合保管事实能否影响角色选择；Jev 继续提供影子线索。
