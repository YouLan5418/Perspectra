# G3 移动观察与玩家在场反馈：第一轮接线验证

日期：2026-09-23。依据 [对照实验](PROTOTYPE-G3-CONTRAST-01.md) 中“到达端信息能改善 NPC 决策”的结果，修改现有观察内容和网页试玩状态；没有更改移动裁定、空间模型或 Reaction 调度。

## 改动与权限边界

- Root 玩家移动成功后，`observation.content.movement` 沿用现有 NPC 移动观察字段。行动者本人收到实际起点和终点；只在出发场景有权观察的角色收到 `fromLocationId`；只在到达场景有权观察的角色收到 `toLocationId`。私密交互的 `occurrence_only` 观察不携带方向。来源是已裁定的 `character.moved` 和移动前后的 `SceneDecision`，不从玩家话语或 NPC 自由叙述推断。
- 权限核对发现原有单角色 NPC 移动观察把完整 `movement` 给了出发场景观察者。相同裁剪也用于该路径，避免新增 Root 保护后仍通过 NPC 移动泄漏未目击的目的地。
- 网页群体试玩状态从玩家视图对应的同一事件前缀计算当前地点和可见在场者，页面顶部显示“当前地点／在场角色”，输入框只提示眼前角色。它不列出不在场者的当前位置，也不把叙述当作位置事实。

固定两房间测试同时核对 Event 观察与实际 NPC 请求：玩家从前室到后室，前室的留守者和同行者仅见到 `fromLocationId: front-room`；玩家从后室回来，后室同行者仅见到出发端，前室留守者仅见到 `toLocationId: front-room`；玩家本人两端都可见。同行者移动到后室时，前室留守者只收到离开前室，已经在后室的玩家只收到到达后室。页面状态依次呈现前室两人、后室同行者、返回前室留守者。

## 真实模型与网页运行时

使用 `deepseek-flash` 和固定 `prototype-g1` 世界，在新存档 `.tmp/g3-movement-web-c-20260923/` 运行 5 句连续输入、15 次 Provider 调用。玩家显式移动到后室后，页面状态为“后室／眼前没有其他角色”；返回前室后为“前室／同行者、留守者在场”。两名 NPC 收到的玩家返回刺激均只有 `toLocationId: front-room`，没有后室起点；留守者留在原处回应，并在下一句确认看见玩家进门。请求、响应与每轮玩家可见状态保存在该目录，不含请求头或密钥。

一个先行探索存档 `.tmp/g3-movement-web-20260923/` 在第一句因模型把同一文本同时引用为对白和移动而格式无效，世界未提交；它属于 G2 输入解释问题。随后用显式玩家动作固定这个变量。另一个独立存档 `.tmp/g3-movement-web-b-20260923/` 跑通同样五句，曾直观看到 NPC 旧路径向出发端泄漏完整目的地；修复后的最终真实模型样本没有发生 NPC 移动，因此该路径的最终验证依赖上述模型无关组合测试，而非宣称真实样本覆盖了它。

`corepack pnpm@11.7.0 check` 通过：类型检查、Lint、7 个原型测试文件的 40 项测试。网页服务相关 5 项测试另行通过。Lint 保留一条既有 `grouped-runtime.test.ts` 可选链警告。本轮没有进行浏览器视觉检查；真实模型试玩驱动的是网页使用的同一 `FrozenWorldPlaytestRuntime` 和 `PlaytestState`。

**结论边界：**移动观察权限和网页当前在场反馈这一切片通过；G3 整体仍未通过。最终样本中没有任何 `entity.transferred`，黄铜钥匙仍在前室原位置；同行者却反复叙述自己把钥匙拿起来、拿在手里。首个探索输入也再次暴露 G2 格式失败。当前页面只说明谁在眼前，不猜测已离场角色的去向。
