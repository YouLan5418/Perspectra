## 改动与范围

仅改变 agents 的 Provider 请求呈现：current_scene 与 current_self_state 从协议 JSON 改为中文场景资料；场景只呈现 observerIds，不把含离场/隐藏人物的 memberIds 当作可见人物；不再给模型呈现这两个段落的调度名单、可用性与 Hash。自身心理内容继续标为主观视角。

受控交互 Schema、角色身份锚点和 affordances 保持原样，仍由同一份已授权输入生成。改动发生在 Provider 请求预算计算和记录之前；没有在网络适配器里偷偷替换请求。没有增加模型调用、版本或兼容分支。

这只是可读场景的第一步：仍显示地点/人物 ID，其他上下文部分仍为旧结构；没有实现完整的自然语言场景，也没有解除 cue 和两步行动限制。README 只修正 check 的过时描述。

## 可复核发现

1. **移动确实走规则。** world.sqlite 的 events：seq136 GLM 去工作区，166 Claude 去工作区，181 DeepSeek 去客厅、216 再去工作区，228 GPT 去工作区，259 玩家去工作区。第二条没人回复本身符合不同地点的观察限制；跟随后能恢复，不能据此宣称存在永久互动死区。
2. **场景与叙述仍可能错位。** seq153 的 GPT 发言含“我们四个都在，谁也没走”，但 GLM 在 seq136 已移动。对应首次 GPT 请求仍包含四名 NPC；这支持同轮提案使用共同旧状态的解释，不应简单归咎于模型无视最新场景。后续 GPT 请求的观察者已逐步缩至 GPT 与玩家。该问题未在本轮修复。
3. **表现约束仍实际阻断行动。** seq244 为 GLM 的 action.rejected，reason=PERFORMANCE_NOT_ACCEPTED。这是下一步检查表现输出契约的直接证据，不能通过放过重要状态裁定修复。
4. **自然度没有得到证明。** GPT 在 seq227、300、344 多次提出近似的“先弄清原因还是确认不会消失”问题；“微微一笑、点了点头、说话声音很轻”等固定表现持续重复。第三轮 seq346 的 Claude participant-terminal 状态为 provider_terminal、actionCount=0；仅凭这个状态不能断言是超时、格式还是其他原因，根因待查。

没有未改动基线的同期 A/B，没有用户对人物自然度的评价，也没有长会话测试。因此只能说明新呈现进入了真实请求且基本交互链路可运行，不能声称质量已提升或认知隔离已全面验证。
