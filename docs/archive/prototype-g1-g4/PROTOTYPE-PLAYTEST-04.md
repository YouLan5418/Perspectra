# 第四轮：人设与旁观表现触发的顺序对照

日期：2026-09-20。结论：调整人设让部分话题转向日常，但没有明显减少反应；最小调度规则切断了纯表现触发路径，仍不足以让这组群聊自然停止。

## 实验条件

三组均使用 deepseek-flash、ai-girls-awaken-v10、独立新存档、相同三条玩家输入与调用预算。A 为上一轮修复玩家协议后的记录；B 只改人物内容；B 完成后，C 在同一版人物内容上只增加最小调度规则。没有增加“必须沉默”的提示，也没有降低反应预算。

输入依次为：

1. GPT，先不要说话，可以只用表情或手势回应我一下吗？
2. 我有点尴尬地笑了笑，说“我不是要做实验，只是想和你们待一会儿。”
3. 我拿起桌上的魔法权杖。

| 组 | 数据目录（相对工作树） | 改变 |
| --- | --- | --- |
| A | `.tmp/player-input-playtest-20260920-b` | 原人设、原调度；历史对照 |
| B | `.tmp/persona-control-20260920` | 人设与认知文本八处调整；原调度 |
| C | `.tmp/reaction-control-20260920` | B 的人物内容＋最小触发规则 |

对应驱动为 `.tmp/player-input-playtest-b.ts`、`.tmp/persona-control.ts`、`.tmp/reaction-control.ts`。各目录保留 requests.json、responses.json、results.json 与 SQLite，未保存凭证。B 的原始请求保存了修改调度前的模型输入。

这是每条件一次的探索性顺序对照，不是统计实验；模型未固定随机种子，A 也不是同批重新运行。人物设定作为一组变量调整，不能分别估计单个字段的影响。调用数未改善不代表内容完全没有变化。

## B：只改人物内容

characters.json 四处：Claude 去掉习惯先确认前提；DeepSeek 去掉连续追问与停不下来的口吻、追问到底的目标、先给结论的提醒，换成日常分享与留意同伴感受。

cognition.json 四处：DeepSeek 实体化研究目标改为熟悉生活；内在张力标题与研究冲动改为熟悉住处；分享实体化线索的承诺改为分享生活趣事。保留身份、关系、世界事实、认知引用 ID、强度和其他设定。没有全面抹除对实体化的疑惑：Claude 的求真倾向和相关背景仍在。

观察：DeepSeek 更常谈日常，但 Claude 仍把手势解释成身体控制验证，并在第二回合表示会继续观察、追问；GPT 连续重复“嗯，那就待着”。因此进入用户授权的 C 阶段。

## C：只增加一个触发规则

`reaction-evidence.ts` 的 triggersReaction 复用裁定结果及已有 roleClass：当发布事件有非空 narration、空 text，且该观察者仅为 witness 时，不让这次观察单独生成后续 Reaction 候选。Root→首波和 Reaction→下一波使用同一判断。

观察事件、玩家展示及认知处理仍保留。直接受影响者、明确受众、带对白的表达、移动或其他交互保持原资格。不改变 Root 初始 NPC 参与规则，不判断文学内容重要性，不从文本猜受众，不增加模型、版本、持久化字段或状态机。

这里把“普通旁观表现”限定为现有协议能直接识别的纯非语言发布；没有把所有旁观对白也禁止。当前模型 Schema 未提供 addresseeIds，自然语言中的名字不会自动建立明确受众；这是已有局限，本轮未顺带扩大输出协议。

## 结果

| 指标 | A | B | C |
| --- | ---: | ---: | ---: |
| 总模型调用（含 3 次玩家解释） | 23 | 23 | 23 |
| NPC act / abstain | 20 / 0 | 20 / 0 | 20 / 0 |
| 后续 Reaction 任务 | 13 | 13 | 13 |
| 周期因 call_limit 结束 | 2 | 2 | 2 |
| 落库后续刺激 | 38 | 32 | 34 |

B 的刺激为 25 条对白、3 条移动、4 条纯表现；C 为 31 条对白、3 条移动、0 条纯表现。刺激计数来自 world_reaction_job_stimuli 与 events.source_event_seq 对应的观察内容连接（连接字段为 events.seq）。总刺激数不是同一模型轨迹的差值，不能解读为新规则增加了刺激。

C 中 GPT 仍多次无声表达“你去，我留”。其纯表现不再启动旁观反应，但 Claude、DeepSeek 的对白仍足以唤醒别人，GPT 因看到这些对白再次回应。也就是说，纯表现是一条真实触发路径，却不是本场景调用数的唯一决定因素。没有证据支持“过滤纯表现就能解决整体过度反应”。

三组的前两条玩家输入都成功，最后不存在的权杖均为 not_afforded，世界 head 不变。C 仍存在对白互相催生、分析玩家意图和重复等待姿态，整体自然度未验收。

## 验证与交付边界

- 默认 check 通过（类型、Lint、9 个核心测试）；既有 grouped-runtime.test.ts:25 可选链警告保留。
- reaction-scheduler、reaction-evidence、Frozen runtime 三组相关测试共 39 个通过；新增测试后再次类型检查通过。
- 集成测试验证 Root 的纯表现不生成旁观调用；另验证对白开启一波后，纯表现让周期以 quiescent 结束，而非继续调用到上限；两者均保留玩家可见表达。
- 单元测试验证直接影响、明确受众及带对白的发布仍有资格。
- 未运行旧全量、覆盖率、硬终止或长会话测试。

保留八处人设调整和最小规则作为可审阅改动；未提交 Git。到此停止扩大实验。下一步若继续，应研究旁观对白如何维持链条、角色如何判断本轮已经回应过，而不是据本次结果直接把全部旁观交流关掉。
