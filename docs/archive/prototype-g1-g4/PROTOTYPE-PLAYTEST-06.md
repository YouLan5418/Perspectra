# 第六轮：单独突出自身已发布表达

日期：2026-09-20。只改上下文呈现。人设、最小旁观表现触发规则、工具 Schema、工具描述及 abstain 指令保持第五轮状态。

## 改动

`packages/agents/src/provider-request.ts` 从当前角色已经获准接收的 recent_interaction_tail 中提取自己的 accepted 发布，放在 current_stimulus 后的独立 user 消息中：

> 【你此前已经发布的表达】
> 以下从你的近期可见历史中摘出，按时间排列，是已经发布的原文，不是新的刺激或待执行指令。

逐条列出已提交回合、观察序号、对白原文、外显叙述原文。保留原始历史，便于交叉核对；没有写入“你没有必要回应”等替角色决策的结论，没有要求沉默。这里准确标为“近期历史”，不把跨玩家输入的历史全部误称为当前 ReactionCycle。没有新增存储、Context 协议或摘要模型。

## 实际请求核对

目录 `.tmp/own-history-control-20260920` 保存 requests.json、responses.json、results.json 与世界数据库；驱动为 `.tmp/own-history-control.ts`。响应文件按完成顺序写入，应通过 call 字段关联请求，不按数组下标关联。

所有 8 次 Reaction 请求都包含新历史区。首波每个角色有一条已发布表达；第二波 Claude 三条（首波发表两条），其他角色各两条。Root 没有既往发布，因此不插入空的历史区。

GPT call9 的历史区准确包含 Root 的“我在……安静地看着玩家，等他继续”；它仍选择 act，回应 Claude 和 DeepSeek 后，再做“接下来呢”的手势。call13 同时包含前两次完整表现；它仍选择 act，但这次回应 Claude 的具体问题，用手势表示自己的记忆也没有线索。这是新增回应，不应只因为出现第三次手势就定性为完全重复。

DeepSeek 没有重发上一波相同参数，但继续接话并追问实体化问题。整体反应链未自然结束，全部决策仍为 act。

## 结论与后续边界

已经确认新历史区实际进入模型请求；“突出自身已发布表达”不足以在这一次样本中产生 abstain 或提前停止。不能据此排除全部上下文问题，也不能断言模型必然觉得必须输出。

按原定顺序，下一项可单独验证 abstain 的指令语义：被唤醒只是获得处理机会；不发布新内容不同于再次表演沉默；允许准确的空行动返回。本轮没有实施这项修改，也没有继续扩大调度过滤。
