# 第九轮：角色可读的执行结果与网页最小集成

> 历史实验记录。G4 已移除本页使用的 `HCW_PERFORM_NPC_ID` 对照入口；当前 v5 网页默认使用通用单角色激活，见 [G4 架构减法盘点](../reviews/PROTOTYPE-G4-ARCHITECTURE-AUDIT.md)。

日期：2026-09-20。在第七轮的默认表达/调度基线上增加一个可选 NPC 的物品交互实验。没有修改 Reaction 候选规则、波次排序、默认预算、人设或玩家解释器。

## 诊断与角色理解分开

`character-execution-result.ts` 从已裁定结果和角色已获得的观察生成简短执行说明，不调用第二模型、不分类自由文本、不生成角色对白。

程序的 `action.resolved`、Authority 及实验诊断结果继续保留原始错误码。模型侧的结果只提供状态与可读原因；新切片写入的结果观察使用可读说明，读取已有近期观察时不把其 reason 码直接递给续写模型。网页复用 Reaction 时也替换本次诊断码对应的结构化 reason 字段，原数据库记录不改写。

具体原因保持区别：不在同一地点、物品不在自己手中、对方无法接收、当前场景不支持互动、缺少必要参数等，不统一降级为“失败”。只有裁定明确返回同意相关原因时才说明尚未同意/不同意，不能从 `PARTICIPANT_NOT_AUTHORIZED` 推测对方态度。同意相关映射目前只做了确定性测试，不表示现有基础交互已新增同意机制。

对“物品已由别人拿着”，需要该 NPC 自己收到过对应持有变化的观察，并且此后没有新的物品状态变化使该观察过时，才能说明持有人。只有全局状态知道的隐藏持有人不对模型揭示。无法区分隐藏目标与不存在目标时，只说眼前找不到可操作目标/目前接触不到，不把全局不存在当作角色已经知道的事实。

独立拒绝实测位于 `.tmp/readable-result-20260920`：

- 脚本提交拿杯子的提案；原有 Rulebook 返回真实 `PARTICIPANT_NOT_AUTHORIZED`，杯子仍由玩家持有。
- 该样本明确包含 NPC 观察到玩家持有杯子的初始观察。
- DeepSeek 收到“这个物品已经由 Player 拿着，你没有成功拿到它”，实际回复：**“啊，杯子已经在你手里了呀——那我就不用拿啦。要不要我帮你倒点水？”**
- 原始码仍在诊断中；角色请求与本次台词不含该码。该拒绝的初始提案是脚本注入，不计为模型自主尝试。
- 同目录成功对照回复“给你，杯子拿好了”，仍有交付含义歧义；并未发生 give，不把这句话当成叙事越界问题已经全面解决。

## 网页接入方式

使用现有 `FrozenWorldPlaytestRuntime` 与网页 HTTP 服务，只对 `performNpcId` 指定的 NPC 生效：

1. Root 中它若选择物品 `interact`，该提案只能包含这一交互，不能夹带成功对白、叙述或旧 performance。普通纯表达仍使用原协议。
2. 原有 Root Validator / Rulebook / commit 正常裁定提交，不在 Provider 内部模拟执行结果。
3. 若该 NPC 随后被原有 Reaction 规则调度，则**复用第一次现有调用**：附上真实提交结果及角色可读说明，这次只允许表达或 abstain。结果仍通过原有 Validator 和 Reaction 提交流程发布，发布后是否刺激其他人仍由原规则决定。
4. 若整个周期没有它的调用，则周期结束后最多补一次第八轮单角色续写；这一次在 `providerCalls` 中计数，诊断单独列出。没有新增无限循环或自动重试。

操作匹配同时限定 actor、actionId 和本次输入前的世界序号，避免模型重复使用行动名时读到旧回合结果。补充续写只在无活动 Cycle 时执行，先释放应用 writer，再使用原有租约提交，之后重新挂载应用。自动化验证了后续下一轮仍可正常使用。

仍然是最小切片：只处理选定 NPC 在 Root 的一次物品交互；它之后普通 Reaction 中新发起的交互、其他 NPC、移动等没有全面切换到此模式。补充续写会保存观察并展示，但暂不再开启一个 ReactionCycle，因此它对其他角色的刺激要留到后续正常处理；复用现有 Reaction 的主要路径没有此限制。补充续写可在暂停/关闭时取消，已提交物品交互保留。

本次没有推出通用工具编排框架，旧数据库格式及 Reaction 账本也未升级。

## 真实网页群体实测

沿用 `ai-girls-awaken-v10` 世界、四名 NPC、`deepseek-flash` 和默认预算。启动现有网页服务，通过 `/api/submit` 提交自然语言；页面 GET 和提交均返回 HTTP 200。没有进行浏览器视觉布局验收，页面布局未修改。

输入：

> GPT，请把卧室里的手机拿起来，拿到后告诉我一声，先不用递给任何人。

最终样本：`.tmp/web-perform-20260920-b`，含 requests / responses / result JSON 与各 SQLite。模型所有请求及结果已记录，不含凭据；服务已关闭。

| 证据 | 结果 |
| --- | --- |
| Root 模型提案 | GPT 只提出 `base:take`，无预写成功表现 |
| world.sqlite seq134 | `entity:phone` 从卧室转移给 `character:gpt` |
| seq135 | `gpt-take-phone-1` 的已提交接受结果 |
| Provider call 9 | 第一次 GPT Reaction 明确收到 executionResult；只能表达或 abstain |
| seq173 / 玩家观察 seq178 | GPT 发布“拿到了，手机在我手里。”及自由表现 |
| 最终状态 | 手机仍归 GPT，没有重复拿取或交付事件 |
| 调用预算 | 13 次真实调用：1 次玩家解释、4 次 Root、8 次 Reaction；续写包含在这 8 次之内 |
| 周期 | 两波后 `call_limit`；没有因本功能额外提高原预算 |

首次集成样本 `.tmp/web-perform-20260920` 也保留：当时把续写放在整个 Cycle 末尾，产生第 14 次调用；GPT 已在普通 Reaction 中回应过执行结果，因此出现多余表达。依据此证据改为优先复用已有 Reaction 调用，再进行上述新目录复测。没有删掉首测或将两次结果混为一个样本。

GPT 的续写提到了屏幕亮着，这是本样本没有独立裁定的自由细节；本次只验收已声明的物品归属与执行时序，没有证明所有叙事细节真实。其他角色仍讨论实体化原因，保持冻结的表达/调度基线，不顺带调整。

## 验证与使用

- 默认 `check`：类型检查、Lint 与 30 项核心测试通过；仅保留原有 grouped-runtime optional chaining 警告。
- 网页运行时：11 项测试通过，包括复用 Reaction、无调用时补充续写、真实拒绝及错误码不进入续写上下文、下一轮继续使用。
- 同轮 Provider / wire 相关测试 20 项通过。未跑旧全量、覆盖率或硬终止套件；没有修改 SQLite 的事务实现。
- 自由连续长局、所有角色所有重要动作、重启后的未完成续写仍未验收，不宣告完整原型契约通过。

在已设置 DeepSeek 凭据的终端，开启这一个 NPC 的实验：

```powershell
$env:HCW_PERFORM_NPC_ID = 'character:gpt'
corepack pnpm@11.7.0 experience:web:flash --pack examples/world-packs/ai-girls-awaken-v10 --data-dir .tmp/web-perform-manual-new
```

使用新目录，不打开 `D:/worlds` 历史数据。未设置 `HCW_PERFORM_NPC_ID` 时仍为原冻结入口；清除该环境变量即可回到默认行为。这次实验已结束，没有留下后台服务。
