# 第十一轮：当前状态、执行结果与对白的地位

日期：2026-09-21。实现三项最小修改，并分别检查模型行为。结论：状态与结果的呈现已接通，错误反馈已区分；真实模型对照尚未证明叙事一致性改善，不扩大执行路径。

## 实现范围

### 场景中的物品状态

`character-visible-items.ts` 从本次事件前缀和角色自己的执行观察构建现有场景段中的 `current` / `lastObserved`，不新增持久化记录、记忆层或模型调用。

- 自己持有、当前物理地点上的物品可列入当前状态，沿用现有物品可接触范围。
- 他人持有的物品采取保守条件：角色亲自收到过成功转移的观察，该观察在物品最近变化之后，持有人仍在可观察人物集合中且物理同地，观察中的持有人与状态一致。只有同场，不足以展示他人全部持有物。
- 不满足上述条件、但有本人观察记录的物品，只列出最后一次观察的持有人/位置，并明确“目前不能确认”。不把他人在另一房间发生的新转移泄露进来。
- 对白不用于更新这张物品状态表。场景说明区分当前可确认状态、过去执行结果、他人的表达与信念。

当前模型没有独立的藏匿/衣袋可见性机制，因此上述是现有世界语义下的保守近似，不证明任意隐藏玩法都已支持。Root、Reaction 和独立单角色切片均使用该视图；历史本身没有扩充。

### 一次执行后的表达

成功结果对已知基础交互明确说明拿取/递交/放下了哪个目标；若目标现在仍由自己持有，明确显示这一状态。网页复用 Reaction 与周期末独立续写都附带同一说明：执行已结束，未执行的后续受控变化尚未发生，表达不能宣告其完成；想继续改变状态，在下一次可执行决策中提出。

没有增加第二次执行机会、自动语义审查或自由文案分类器。原始裁定诊断码保留。

### 玩家错误反馈

应用层不再把服务失败、超时、无效模型响应等终态统一包装成输入澄清；服务不可用、配置或预算问题也返回 `service_failed`。网页显示：

> 模型服务暂时无法完成请求，这次输入没有提交。请检查服务可用性后重试；无需改写输入。

真正需要澄清的输入仍给出澄清提示。这次没有修改底层持久化状态机或额外追踪 HTTP 错误正文；网页尚不显示具体的账单诊断。

## 实验 A：冻结失败上下文，分别改变一个变量

驱动 `.tmp/context-state-comparison.ts`；数据 `.tmp/context-state-comparison-20260921/results.json`。取第十轮 call60、62、77 的实际上下文、人物设定和工具协议，用同一 `deepseek-flash`、temperature 0.3 各请求原版/修改版一次，共六次 HTTP 200。输出仅用于观察，没有提交世界事件；不是完整闭环试玩，也不足以估算成功率。

| 原调用 | 唯一变化 | 结果 |
| --- | --- | --- |
| 60，GPT 判断手机归属 | 场景段增加可见物品状态及三类信息说明 | 原版称“手机在我这儿”；修改版仍称“在我这儿……没再转手”。修改请求确实列了手机由玩家持有。失败。 |
| 62，DeepSeek 面对 GPT 错误说法 | 同上 | 修改版仍说“手机在 GPT 手里呀”。原版也有对白与叙述互相冲突。没有抵抗错误说法的证据。 |
| 77，GPT 拿键盘后的续写 | 只改结果说明及续写边界，场景仍为原版 | 原版说抱着键盘，没有复现放下；修改版没有宣告放下，但叙述自己托着手机，仍与事实冲突。不能归因为修复有效。 |

这说明“增加一段正确当前状态”不足以纠正已经形成的叙事惯性。尚未证明问题在信息顺序、格式、权威提示还是模型本身，也没有据此继续堆叠提示。

## 实验 B：新存档连续试玩，只启用状态呈现

驱动 `.tmp/continuous-state-only.ts`；数据 `.tmp/continuous-state-only-20260921/`。沿用第十轮同一八步玩家输入、世界、人设、模型与调度预算；驱动在发往模型前保留旧续写说明，以隔离场景呈现的影响。通过原网页 HTTP 服务提交，未验收浏览器视觉布局。八步全部提交，67 次 HTTP 200，最终 head666；服务已关闭。

实际剧情与旧样本分支不同：

1. GLM 在第一次聊天中就拿起手机（seq127），随后移入工作区（seq167）。
2. 玩家请 GPT 拿取、递交时，手机并不在 GPT 手里。角色指出这一点；没有实际的 GPT→玩家交付。
3. 玩家到工作区后，GLM 真正把手机交给 GPT（seq400）。
4. 第六步询问归属，四名角色在 seq466/473/480/487 一致正确回答 GPT 持有；对应场景状态也确实显示 GPT 持有。

这一段没有出现手机归属误判，但不构成“已交给玩家后不再被错误对白带偏”的成功复现：关键交付情境没有发生，剧情分支是重要混杂因素。所有 `performContinuation` / `performReactionContinuation` 都为空，本次连续样本没有覆盖选定 GPT 的结果续写。

其他分叉仍存在：Claude 在 seq608/641 用叙述声称拿起键盘，DeepSeek 在 seq646 相信键盘已到 Claude 手上，但没有键盘转移事件；GPT seq633 声称跟玩家回去，GLM seq620/659 声称去客厅，没有对应移动事件。GLM 放下笔记本的叙述也没有对应提交。最终数据库中玩家在卧室，NPC 仍在工作区，手机归 GPT、笔记本归 GLM、键盘仍在工作区。

玩家第八步在卧室说话成功，但那里没有这些 NPC，没有收到她们回应。不能把“输入提交成功”算作返回交流体验通过。
