日期：2026-08-23

## 修复原则

本轮不原地改变已经锁定的 Rulebook v3，而是以 ADR-0049 新增 v4。旧 v1/v2/v3 的 Registry 与历史重放语义继续保留；Demo 改用新 World 地址和 v3 输出协议，避免用新 Manifest 解释旧数据库。

## 问题与落点

| 审查发现 | 修复 |
|---|---|
| `entity.kind` 派生证据与手写目录脱钩 | v4 使用实体 ID 派生唯一证据 ID；Demo 目录从 Compiled Manifest 的全部实体生成 |
| 目录外耐久证据导致后续每轮抛异常 | Parser 对授权集合取已知交集，无法表示时返回 clarification，不再抛进程异常 |
| Parser 无授权时默认暴露全目录 | 无授权默认为零角色、零实体、零证据；调用方必须显式传可见目录 |
| 任意同形 Claim 可被当作真凶事实 | Genesis 为合格作者 Claim 生成专用 `investigation.culprit-seeded`；v4 结案只读该事件 |
| 畸形真凶历史静默跳过 | 畸形 `investigation.culprit-seeded` 立即 fail-closed |
| Bob 的已裁定对白不进入玩家观察 | v4 Round Observation 附带已接受的 `character.speak` 数据，进入 Event/Outbox/Session 耐久路径 |
| CLI 输出全角色调查台账 | 新增角色裁剪的调查视图，CLI 不输出 `discoveredBy`/`presentedBy` |
| 结案后仍能继续调查 | v4 结案后统一拒绝 inspect/ask/present/accuse |
| 相同 kind 实体证据碰撞 | evidenceId 绑定唯一 entityId；保留 v3 的旧行为仅用于历史兼容 |
| 中文指控只能引用一项证据 | 窄语法支持 `、`、逗号和空白分隔的多证据 |
| Turn CLI 错路径会静默新建世界 | Turn 入口要求 World/Session 数据库均已存在，提示先运行 opening 命令 |

## 回归矩阵

- 开场前合法检查钥匙，继续询问，重启后继续出示钥匙证据。
- 无授权解析不泄漏候选；未知授权证据 ID 不使进程崩溃。
- 同 kind 的两个实体得到不同证据 ID。
- 同一 Proposal 内重复检查同一实体：第一项 accepted，第二项在同轮前缀上 `ALREADY_INSPECTED`。
- 模型可产生的通用 Claim 即使伪装为 `is_culprit` 也不能结案；作者种子可以；畸形种子失败关闭。
- 正确结案后四类调查 Action 全部拒绝。
- Bob 否认文本同时出现在 Bob 自身状态与玩家 Observation；CLI 仅保留玩家调查能力。

## 尚未扩展的范围

- Parser 仍是确定性窄语法输入适配器，不是开放式自然语言理解模型。
- clarification 发生在 Round 受理前，按 ADR-0048 不形成世界 Tick；本轮未把它改成权威世界事件。
- 作者调试用 `MysteryDemoSnapshot` 仍可查看全角色视图；该能力不暴露给 CLI/RPC 玩家入口。
