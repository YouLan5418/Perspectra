# 当前项目状态

**语言 / Languages：[简体中文](PROJECT-STATE.md) | [English](PROJECT-STATE.en.md)**

核对日期：2026-10-18，对应 main 提交 `0289605`。实时状态以 Git 为准。

一句话概括：Perspectra 是一个玩家推动的多角色扮演原型。模型决定角色说什么、做什么；程序负责“谁能知道什么”，以及物品、位置这类重要状态是否真的发生了变化。

怎么实现的见[代码技术文档](architecture/README.md)，长期想做成什么见[产品愿景](vision.md)，更早的阶段见[旧状态记录](../archive/prototype-g1-g4/PROJECT-STATE-history-through-20261009.md)。

## test3 之后源码新增了什么（2026-10-15 ～ 10-18）

**Launcher 改版。** 打开后是铺满窗口的世界包封面，左侧细栏切换世界包。点“⋯”或状态标签，右侧滑出“本局抽屉”，在里面管理存档、模型、角色预设、前端权限、运行参数和创作者工具。右上角 ⚙ 是设置窗口。游戏运行中也能改设置，下次启动生效。见 [Launcher 接入](launcher-core-integration.md)。

**模型连接与按角色选模型。** 可以保存多条模型连接（OpenAI 兼容、Anthropic、Google），API Key 存在 Windows 凭据管理器，重启不用重填。每个实例选自己的模型；还能让某个重要角色单独用强模型，并单独指定它的记忆整理模型。见[模型接口协议](model-protocols.md)和[验收记录](studies/launcher-role-models-20261017.md)。

**创作者页面。** 游戏运行时可从 Launcher 在浏览器里打开一个只读页面，查看对话、行动轨迹、实际模型请求、物品去向和角色记忆。它只读，不会改动世界。见[创作者调试接口](creator-debug-api.md)。

**游戏页。** 默认舞台改成情景式布局，可选四种主题色；顶部工具栏可以直接“保存进度”生成故事节点。见[默认情景舞台](frontend-stage.md)。

**角色行为修正。**
- 角色对着听不到的人说话，这次发言会被拒绝；角色最多再决定一次（走过去、换个说法或作罢），而不是假装对方听见了。见 [Interaction](architecture/interaction.md)。
- 发给模型的上下文会明确写出“这件物品现在在谁手里”，减少角色记错归属。
- 只剩玩家场景之外的角色还在处理时，玩家不用再等，可以直接继续说话。
- 行动被拒绝时，角色拿到的原因说明更清楚；行动后的续写调用次数有上限。

**创作与预设。**
- 新试玩包《赔罪晚宴》（`examples/world-packs/model-girls-dinner`）：四个室友、一场晚宴、没有预定结局。活动可以声明“一键操作”和旁白。见[活动与状态](guides/activity-and-variables.md)。
- 世界包里的物品可以写显示名，界面不再只显示机器 ID。
- 世界包根目录放 `cover.webp/png/jpg` 就会作为 Launcher 封面。
- 酒馆（SillyTavern）预设可用 `preset:import` 命令离线转换成原生格式；Launcher 界面本身仍不能直接导入酒馆文件。本机预设保存在已忽略的 `preset/`，不随源码分发；已有的 `native-writing-suite.json` 仍可从本机导入。见[预设说明](model-presets.md)。

## 已经能玩的部分

- **官方序章**：112 条固定表达（其中 5 条是中性的玩家台词），按正常的提交、观察、记忆流程运行。最后一句之后交还给玩家，不替玩家答应收留。
- **生活事件**：晚餐、私密交流、蛋糕、跨日回访都有触发条件；之后的发展由真实角色模型决定。美术是占位角色和简单背景，没有正式音效。
- **说话的范围**：公开、定向、私密、仅自己四种。程序保证没资格的角色收不到内容，但不能保证模型从不虚构。
- **多角色反应**：玩家每次输入后，相关角色依次获得处理机会，可以回应、行动或沉默。次数和时间有上限（源码网页默认 3 波、8 次调用、30 秒；Launcher 默认反应时限 120 秒，可按包调整）。没有持续运行的后台自治。
- **模型协议**：OpenAI 兼容、Anthropic Messages、Google Gemini 原生。思考强度可选关闭/低/中/高，部分 Gemini 不能关闭。
- **重要状态**：移动、物品转移和机制状态都要经过规则裁定才算数。角色在台词里说“我拿到了”不等于真的拿到；这类叙事矛盾需要在试玩中单独检查。

## 记忆与故事线

**长期记忆（Core）**：上下文估算到约 170k 时，后台把较老的约 120k 整理成长期档案，保留约 16k 原文作为衔接。整理期间可以继续玩；失败或取消时，已有档案和原文都保留。这些数字是本地估算，不是供应商 tokenizer 的精确值。

**故事线**：保存的完整节点包含世界、会话、变量和当时的长期档案。从节点分叉时只恢复这些副本并做一致性校验，不调用模型重新整理。单个节点可以导出成文件给别人导入（不含 Key、模型配置和请求日志，但包含角色私密历史）。一次只运行一条线；整棵树分享、线路合并、跨包迁移都没做。见[故事线](storylines.md)。

**重新生成最近一回合**：用相同起点和输入再生成一组结果，可以在候选之间切换；下一次输入后就不能再切回。它和节点分叉、活动重试是三件不同的事，见[重新生成](tail-round-regeneration.md)。
