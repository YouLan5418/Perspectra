# 从一次角色互动理解代码

本文面向知道“Agent 会读取上下文、调用模型和使用工具”，但还不熟悉本项目的读者。核对日期：2026-10-08；说明当前源码，不代表便携发行包已同步更新。

## 1. 这个项目在做什么

Perspectra 让多个角色在同一个世界里持续互动。每个角色有自己的经历、认识和表达方式；系统保存重要世界状态，并判断角色提出的行动能否成立。

例如，你和两个 NPC 在客厅里，其中一人知道钥匙在哪里，另一人不知道。系统要让他们各自拿到合适的上下文；当有人尝试拿钥匙时，还要检查钥匙的位置和归属。模型决定怎么说、是否行动，程序记录实际成功的行动。

Harness 可以理解为 Agent 周围的运行程序：准备上下文、调用模型、检查输出、执行合法行动、保存结果，再把结果送给有权知道的人。

## 2. 先认识七个词

| 名称 | 通俗解释 | 在钥匙例子中的含义 |
| --- | --- | --- |
| World Pack（世界包） | 作者提供的世界设定与玩法材料 | 客厅、人物、钥匙，以及允许哪些交互 |
| Context（上下文） | 本次交给某个角色模型的信息 | 它现在在哪、见过什么、有哪些可尝试操作 |
| Action（行动） | 等待程序裁定的请求 | “尝试拿取桌上的钥匙” |
| Rulebook（规则裁定） | 判断请求是否合法、产生什么结果的代码 | 钥匙是否存在、是否可达、是否已被别人持有 |
| Event（事件） | 已提交的世界记录 | 钥匙归属变化，或角色发布了某段表达 |
| View / Observation（视图／观察） | 从记录中整理出的、某个角色有权知道的材料 | 旁观者看见拿取结果；隔壁的人未必知道 |
| Memory（记忆） | 角色对授权经历的保存、检索与整理 | “我记得他之前拿过钥匙”，可能包含误解 |

记忆中的“认识”和世界状态不是一回事。某人说“钥匙在我手里”，只证明他说过这句话；当前钥匙归属仍要看程序提交的状态。

## 3. 玩家说一句话以后发生什么

以下是阅读顺序图，省略了预设、活动和重新生成等分支；具体入口见[代码路线](code-walkthrough.md)。

~~~mermaid
flowchart TD
    A[玩家在游戏页输入] --> B[网页宿主处理输入]
    B --> C[裁定并提交玩家表达或操作]
    C --> D[整理各角色获授权的新观察]
    D --> E[给相关 NPC 一次处理机会]
    E --> F[准备该角色的上下文与记忆]
    F --> G[模型选择表达、行动或放弃]
    G --> H[程序检查输出并裁定行动]
    H --> I[提交结果与授权观察]
    I --> J[更新玩家可见内容]
    I --> K{还有新刺激且预算允许？}
    K -->|有| E
    K -->|没有| L[等待下一次玩家操作]
~~~

普通玩家输入是自由表达，不会因为写了“我走到隔壁”就自动完成移动。当前受控操作使用页面选项或 /act。具体有哪些选项取决于世界包和当前状态。

NPC 自己决定怎么处理。当前普通角色决策包括 publish（发布有序对白／叙述）、perform（尝试受控行动）、abstain（放弃本次机会）。原生记忆在允许阶段还支持 recall（主动召回）；Core 模式不开放重复的原生召回。**角色决策协议里的 perform 是行动请求，与内部同名表现动作须按所在层次区分。**

行动结果会返回角色，供它继续表达。例如拿取被拒绝后，角色可以收回手、抱怨或沉默；不能把拿取请求直接显示成已经成功。后续表达失败也不会撤销已提交的合法行动。

新观察可能让另一个 NPC 回应，但系统不会无限运行。调度只给角色处理机会，不替它选择情绪和对白。

## 4. 两种启动方式为什么可能不同

| 入口 | 用途 | 记忆选择 |
| --- | --- | --- |
| launcher:desktop | Tauri 桌面 Launcher 管理实例，启动系统浏览器里的游戏 | Launcher 后端启用 Core 记忆 |
| experience:web | 直接启动源码网页宿主 | 默认原生记忆；加 --memory-core 启用 Core |
| launcher:dev | 浏览和开发 Launcher 的 Mock 界面 | 不启动真实游戏 Core |

“Core 记忆”是 Python 长期记忆桥；“Launcher Core”是桌面管理后端，两者职责不同。启动步骤和环境要求见[源码试玩指南](../guides/creator-playtest.md)与[Launcher 开发说明](../../../apps/launcher/README.md)。

## 5. 当前保证到哪里

程序检查角色可获得的信息范围，并让重要状态通过裁定和提交变化。自由文本仍可能虚构细节，甚至让后续角色误信未经执行的变化。权限测试通过不能证明模型始终理解正确；数据库没变也不能证明叙事没有矛盾。

遇到“角色说拿到了钥匙”的 Bug，要同时看实际归属、发布正文、受众和后续角色理解。
