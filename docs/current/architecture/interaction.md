# 当前 Interaction

2026-10-22 核对：例如玩家选择“把钥匙交给”，再在“交给谁”中选择汤汤。这是一个物品选项加 `recipientId` 参数；每个接收者不再单独占一个选项。拿起、放下、交给以及料理／修理都由各包的 `scripts/status.js` 裁定，宿主不再安装旧的三种物品规则；标准写法见[作者模板](../../../examples/templates/item-rules.js)和[物品操作接口](../guides/activity-and-variables.md#对物品做的操作2026-10-22当前源码)。候选按作者 policy 筛选，执行前重新检查，成功后才提交权威物品变化与授权观察。下列带日期的验收记录保留当时的入口和选项形态。

2026-10-21：玩家一个回合 = 一次表达 + 至多一个行动。例如玩家在输入框写“这个给你。”，再点“把 钥匙 交给 汤汤”：两者作为同一回合提交，先说后做（也可选先做后说），角色只反应一次，且同时看到这句话和交接结果；以前要分两回合，NPC 会先对一句空话作出反应。两步仍各自走原有裁定与提交（发言是 `/act speak`，行动是 `/act` 或 `/status`），不是一次原子提交：先说的话在后面的行动被拒绝时照样成立，并照常得到反应；选了先做后说时，行动被拒绝就不再说这句话。整个回合在[末端回合重新生成](../tail-round-regeneration.md)里记为一次输入，重新生成时两步一起重演。入口在[末端回合运行时](../../../desktop/host/tail-runtime.ts)的 `perform(action, line)` 和[宿主](../../../desktop/host/world-runtime.ts)的 `turn(texts)`。

同日，[玩家视图](../../../packages/frontend/src/player-view.ts)的 `actions` 不再按“哪个脚本提供”区分，而是给每项标出 `kind`（`move` 移动、`interact` 世界内行动、`activity` 活动内行动或开始活动、`manage` 暂停／继续／放弃／重试等游戏外管理）和 `target`（地点、物品、角色、自己或活动）。需要玩家填写的操作（如购买金额、偷窃对象）也进入列表，带 `argumentSchema`，指向角色的输入列在 `characterArguments`；`perform` 以 `arguments` 传入，宿主只接受表单里开放的字段，固定字段（如活动 revision）由选项自带并优先，规则照常校验完整参数。因此 `/status`、`/act` 只保留给创作者调试，不再是玩家路径。自动测试覆盖 API 校验、同回合只反应一次、拒绝后的两种顺序与重新生成；默认舞台在本机桩模型下点击核对过附带行动和表单，未做真实模型试玩。

2026-10-19：状态操作复用 `interact`：例如同行者想偷玩家的钱，它的候选里有 bindingId `status`、definitionRef `status:steal` 的选项，参数里的 targetId 必须是当前授权场景内的角色。裁定由作者脚本给出，结果描述按作者声明的 audience（本人、指定在场角色或现场）投递；被拒绝时只有行动者收到带原因的执行结果，不告知任何值。叙事文本不改变状态，台词里说“我偷到了钱”不会让余额变化。玩家用 `/status` 提交同一类操作；没有参数的操作也出现在行动选项中。见[活动与状态指南](../guides/activity-and-variables.md#3-状态2026-10-19当前源码)。

2026-10-18：已撤销最初花房实验的信任数值交互、事件及面板。角色对他人的态度、同意和情感不由外加分数或门槛裁定；依据人设、预设、记忆与对话历史自主表达。客观玩法效果继续通过现有交互／规则／事件提交，变量不会因为一句情感叙述自动改变。边界例子见[世界设定指南](../guides/world-knowledge.md#3-客观变量与角色态度的边界)。

> [跨场景短信实验](../studies/cross-scene-communication-20261010.md)通过独立安装的 `experiment:message` 交互投递自由正文；[电话实验](../studies/cross-scene-phone-20261010.md)用独立绑定裁定呼叫、接听、通话和挂断。普通 publish 仍只面向现场授权受众。2026-10-25 起短信规则移入[宿主](../../../desktop/host/pack-communication.ts)：包根目录有 `communication.json` 时默认宿主安装它，玩家行动里出现“给 X 发短信”（正文在表单里填），NPC 的规则链为 core → 短信 → 状态 → 活动，自主行动可在 `autonomy.json` 里列出 `experiment:message`。玩家短信走独立提交（同 `/status`），活动进行中不能发。电话实验仍未加入默认宿主。作者 argumentSchema 提供动态正文；本地模型参数 Schema 的必填项取实际候选契约的共同字段，不再默认要求活动专用字段。

> [活动组合实验](../studies/cross-scene-activity-20261010.md)由活动策略先裁定通信定义是否允许，再执行通信规则；接收消息不改变游戏回合，也不自动授权发送或接听。

当前原型允许自由对白和外显叙述；移动、物品归属和包明确追踪的机制状态通过受控行为提交。二者共同构成角色互动，不要求把眼神、姿态和所有细微动作变成结构化事实。

## 表达与行动

自由文本表达角色的说法、姿态或意图，不独立证明重要状态变化。玩家普通自然语言不会自动执行移动、取物或交接；日常游玩使用页面提供的当前选项。创作者调试物品操作可用 `/status take@entity:brass-key {}` 等写法；`/take`、`/give`、`/drop` 已删除，`/act` 保留用于其他受控行动调试。

角色决策协议中的 perform 表示尝试受控行动，publish 发布对白与叙述；内部表现动作也保留 perform 名称，需区分所在层次。move 是位置变化；拿起、放下、交给来自作者状态脚本，在 `interact` 中使用 bindingId `status`、definitionRef `status:take`／`status:drop`／`status:give`。是否提供某个行为取决于包内操作声明、当前目标、作者 policy 和活动／自主许可；宿主不会自动给所有物品补上拿取能力。内置规则只剩 `base:hold-hand` 与 `base:end-contact`，仍须由包显式绑定。

声明式 Interaction 描述可选能力、绑定与参数。模型选择并提出动作，Action / Rulebook 检查当前资格、存在性、位置与重要状态约束，接受后通过 Event 提交。世界事件日志是已提交权威事实的来源；模型生成文本和主观记忆不能代替它。

## 有序角色表达

2026-10-08 起，Character 的 `publish` 使用 `segments` 替代独立的 `speech/narration` 字段。例如：

```json
{"decision":"publish","segments":[{"type":"speech","text":"你真的要走？"},{"type":"narration","text":"她停顿了一下。"},{"type":"speech","text":"等雨停吧。"},{"type":"narration","text":"声音放轻。"}]}
```

片段按数组顺序发布，可交替、重复同类型，或只含一种类型。每段必须有非空白文本；所有 text 合计默认最多 2000 个 UTF-16 单位，上限可由宿主游玩设置覆盖，按当前请求中的 publicationCharacters 校验。整个序列共用可选 `scope` 与 `addresseeIds`，仍为一次 `speak` 裁定、一次原子提交和一个 tick；发布后结束本次激活。不能在片段间插入受控执行或分别指定受众，受控交互仍须先执行并获得结果。

NPC 的发布范围可选 `scene_public`（公开）、`direct`（仅指定对象）、`private`（指定对象获得完整内容，旁观者仅观察交流发生）和 `self`（仅自己）。`direct/private` 必须指定当前可见的其他角色；`scene_public/self` 不指定接收对象。省略 scope 时，有接收对象默认 direct，否则默认 scene_public。标准和本地模型接口、执行结果后的续写、预设 output 转换及活动发布校验均支持这些字段；不新增事件协议或状态机制。self 不刺激其他角色，private 的发生观察仍可触发旁观者反应。活动表达许可继续生效。

例如玩家悄悄对汤汤说“别声张”，汤汤若省略 scope 回应，这句回应会全场可闻。2026-10-20 试玩中她在叙述里写了“压低嗓子”，实际仍是公开发布，把秘密泄给了旁观者。为此，[角色回合](../../../packages/application/src/character-turn.ts)给 stimulus 中“`direct/private` 且收件人含本角色”的来话附加 `audienceHint`，提醒回应受众需要自己用 scope 选择、叙述不改变受众。它只是上下文提示，不替角色决定是否私下回应，也不改变默认值或 Rulebook。自动测试只覆盖标记出现的条件；真实模型是否因此改选受众尚未试玩验证。

事件、授权观察、自观察、记忆 Source 与玩家公开视图保留片段顺序。记忆仍将其记为角色发表的内容，不证明叙述中的受控结果。预设 output/history/display 规则逐片段按 speech 或 narration 类型处理；显示规则只修改投影副本。

活动仍可关闭对白或叙述；固定原文选项模式一次发布最多一个 speech 片段，可由许可的 narration 包围，避免把多个选项组合成一次新对白。普通场景没有这一限制。

玩家公共输入仍使用 `text` 与可选 `narration`，不要求玩家编写片段数组。角色的旧双字段模型输出不再接受；当前玩家双字段事件及已保存表达仍由同一发布读取函数呈现，没有数据库迁移或协议版本升级。

本轮验证：默认 `corepack pnpm@11.7.0 check` 的类型、Lint、38 文件 293 项通过；随后局部完善自观察预设处理及空显示片段，相关 35 项与额外上下文／展示／宿主 32 项通过，类型与 Lint 再次通过。回归覆盖四段交替表达、两个模型 Schema、单次提交、受众隔离、原生及 Core Source 顺序、活动许可和总长度边界。

真实模型验证：初次默认端口 8045 拒绝连接；按用户提供的 `127.0.0.1:8046` 使用 `gemini-3.7-flash` 与 prototype-g1，在新 `.tmp/ordered-expression-live-1791441609114/` 目录完成两轮输入。第一轮同行者实际发布 speech → narration → speech → narration，第二轮发布 narration → speech → narration → speech；事件与玩家 transcript 均保留类型、原文及顺序。共 6 次模型调用、3 次发布和 1 次弃权。第二轮两次取钥匙尝试均被 `INVALID_INTERACTION_PARAMETERS` 拒绝（最终请求的 definitionRef.version 为字符串 `"1"`），没有物品转移事件；角色收到拒绝后继续表达，没有宣称取得钥匙。因此已验证交替表达及拒绝后的续写，未验证成功执行交互后的续写，也不代表长期试玩或任意叙事越权均已验收。证据见该目录 `evidence.json` 与 `world.sqlite`。本轮未重建桌面发行包，未修改默认服务端口。

## 当前自由度与限制

### 2026-10-12：普通角色体验衔接实验

例如角色想私下回应玩家却漏填接收者，普通宿主现在先用严格决策 Schema 检查，并复用活动已有的一次格式修正。标准及本机发送 Schema 检查 direct/private 的非空接收者、scene_public/self 的空接收者要求；本机 Schema 同时要求所选行动的必要字段。宿主依然按当前权限及 Rulebook 裁定，不猜接收者、不修改模型字段或代替它执行。

普通 Character Turn 为修正预留一次实际模型调用，计入本次激活及所属调度预算；预算不足保留格式失败。修正后若选择行动，仍须为结果续写留有调用余量，否则不执行该行动。已经提交的行动不会因续写修正失败撤销，也不会重复执行。普通串行宿主同样传入严格调用预算；活动原有修正和预算处理未在本实验中重构。

移动成功后，最终模型文本额外突出同一请求内的当前位置和授权在场名单，不添加远处位置或新观察。模型提示明确 publish 会结束本次机会，计划不会自动执行；本实验没有改为表达后继续决策。来源与事实提交路径不变。

这是实验分支源码能力；自动回归与真实模型验证范围见[实验记录](../studies/interaction-continuity-20261012.md)。随后 8045/Gemini 3.8 Flash 完成 56 回合基线/实验对照，权限与预算核验通过；另有两次真实格式修正探针通过。受阻样例有减少重复的迹象，但自然组未触发格式失败，两版均未重现旧移动叙事错误，不能推出普遍改善。发行包未更新，表达后停顿及长期行动可靠性仍保留。

### 表达后继续决策的独立实验

例如角色先说“我去后室看看”，开启宿主 continueAfterPublish 实验选项后，首次行动前的表达成功提交且仍有两次调用余量时，角色可在同一激活内再决定移动或结束；移动后照常看到真实结果。它替代实验模式的“首句表达立即结束”，默认关闭，不从台词自动生成动作。

2026-10-25 起，玩家也可以在本局抽屉“运行参数 → 普通反应周期”里把“角色发言后可接着行动”设为 1 打开它（[play-settings.ts](../../../desktop/play-settings.ts) 的 `continueAfterPublish`，默认 0），宿主在设置为 1 或实验选项打开时启用；它属于游玩设置，末端重新生成按设置区分环境。在玩家真实存档（《屋檐下的心动日程》第 2 天傍晚、Core 记忆、deepseek-flash 思考低）的两份副本上做 9 步对照：关闭时玩家让 GPT 去书房叫 Claude，GPT 走到书房后后续表达格式失败，两人整晚留在书房；打开时 Claude 被叫到厨房，之后角色实际执行了泡茶、去卧室等操作。代价是调用 26 → 48 次、未命中输入 token 约 21 万 → 53 万；其中一部分来自更多角色同场后的正常反应。单次对照，样本小。

最多三次决策步骤，首次表达后的第二次表达直接结束；自主机会仍最多一次受控行动，普通机会保留原先的一次/两次行动上限。格式修正、召回和后续决策沿用当前模型调用及时间预算，不增加调度机会。每一步重新构建授权上下文，已发表表达可见且可被打断，已提交动作与表达保留。活动和外部发布审计路径不启用（2026-10-19 起不再因变量脚本关闭），启动器未增加设置项；末端候选环境记录该开关。真实对照及限制见[实验记录](../studies/interaction-continuity-20261012.md)。

### 一份决策中的行动前表达与行动

例如角色说“我先回旅馆看看”，并在同一份 `perform` 提案中附 `before` 表达与移动参数。开启 `beforeActionExpression` 后，宿主先完整校验提案，再提交这段表达、按最新前缀裁定一次移动；下一次模型调用看到真实执行结果和新的授权场景，才生成行动后表达。没有行动时仍用 `publish`，没有表达和行动时用 `abstain`；不接受预先生成的 `after` 字段。

`before` 复用 `segments/scope/addresseeIds`、长度上限、预设 output 文本处理和现有 speak 权限，不增加事实事件或新的行动能力。表达和行动各自为一次原子提交，中间可被打断；行动失败不撤回已经说过的话，续写失败也不撤回已提交行动。两次提交共用现有串行提交区段，但行动重新取最新状态裁定；意外前缀变化停止使用旧提案。前后表达各自按发生时的授权场景检查受众。

实验开关默认关闭，普通宿主仅在没有活动和外部发布审计时提供该能力（2026-10-19 起不再因变量脚本关闭）；活动请求再次排除。末端候选环境包含开关，不能跨模式复用。预算仍至少预留两次模型调用，未增加自主机会或每次决策的受控操作数量。与“先 publish 再重新决策”的三次调用实验不同，表达与行动由同一份提案选择，结果续写仍需第二次调用。实现、真实模型对照和限制见[行动前表达协议实验](../studies/pre-action-decision-20261012.md)。

### 角色决策原则与思考强度

例如角色确实想取回原件，可以直接请求移动；若改变主意，可以拒绝、表达或沉默。2026-10-12 的系统提示新增明确的独立角色身份，要求结合性格、目标、承诺、经历、情绪、环境与可执行行为判断，不强制先向玩家解释计划，不给行动、表达和沉默设置固定优先级。承诺和经历可来自授权历史，不增加强制状态字段；具体动作仍受工具、预算与规则约束。

提示原则已接入普通 Character 决策构建，未改变调度或事实裁定。同日使用 8045/Gemini 3.8 Flash 对照旧提示 low 和新提示 low/medium/high，关闭表达后继续决策，统一输出上限；方法、实测结果与适用限制见[提示与思考实验](../studies/decision-prompt-thinking-20261012.md)。不同思考强度不代表不同角色策略，也不保证更强就更好；实例默认设置与发行包未更新。

随后加入即时行动与计划表达的区分：已经决定立即执行且工具提供对应动作时直接选择动作；建议、愿望、征求同意、等待和犹豫仍可正常表达。只有规则裁定的行动改变权威状态。新增段落没有将全部计划都强制转成动作，配对重放及完整轨迹验证见[即时行动提示实验](../studies/action-intent-prompt-20261012.md)。

2026-10-22 核对：[操作说明](../../../packages/provider-chat/src/character-action-explanations.ts)仍按已有 affordances 生成 actionExplanations。例如“前往旅馆”附对应的 perform/move 参数；物品交互使用作者给出的操作标签和已有目标，携带 `argumentSchema` 提醒填写必要参数，不再为旧拿取、交付、放下定义提供专用语义模板。未知效果不猜测，关闭 perform 时不提供说明。它不增加操作或改变权限、世界裁定路径。2026-10-12 的配对验证只说明当时版本，见[操作语义说明实验](../studies/action-semantics-20261012.md)；当前作者规则的真实样本范围见[项目状态](../PROJECT-STATE.md#验证到了哪一步)。

普通场景尽可能自由表达。活动可以显式收窄对白、外显表现、移动与交互能力，见[受控交互](controlled-interaction.md)。扩展玩法先复用交互定义和可信包内脚本，不把题材动作全部加入 core 枚举。

程序没有直接修改物品归属，不代表叙事一致性已经通过。真实试玩仍有自由叙述虚构受控事实、私语送达等问题；其他角色相信未提交转移也属于体验失败，不能把任意自然语言永不越权当成已证明保证。

2026-10-17 修复定向表达的静默丢失：例如 A 向另一房间的 B 私语，现会明确拒绝整次发布；即使另一个指定收件人在场，也不会部分送达。普通 `direct/private` 要求全部收件人属于发布时当前场景的有效观察者（包括成员、位置、生命周期及可见性），Rulebook 和观察投递复用 [场景读取与观察者过滤](../../../packages/kernel/src/scene-state.ts)。拒绝不产生 `character.speak`，仅发话者收到失败结果；场外对象和同场旁观者都不会因此获知内容、收到发生观察或获得反应机会。成功发布时 `private` 的同场非收件人仍只收到 occurrence_only；`direct` 的非收件人没有观察。之后入场也不会补发旧表达。普通发话不提供远程通信，短信和电话仍走各自授权交互。

NPC 的模型 Schema 继续只列当前可见收件人；选错时沿用已有一次格式修正，明确提示原话未发表、未传达。如果合法形状的提案到达执行裁定后因收件人不可达而被拒，Character Turn 最多额外重新决策一次，消耗原有模型调用和时间预算；预算足够时可自行移动、改换合法表达或结束。没有显式调用上限的入口，恢复过程仍以原有 maxCalls 限制调用；已经执行成功的动作保留，行动前表达被拒则不执行附带动作。未知 ID、重复收件人和非法字段仍是输出错误。失败反馈不揭示目标的远处位置或隐藏状态。
