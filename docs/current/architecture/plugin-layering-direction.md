# 插件分层方向与范围沿革

2026-11-11，用户确认[可组合游戏引擎架构定稿](composable-engine.md)。本文保留原先暂缓事项的来源和当前范围，由[核心与插件规范](plugin-standard.md)统一导航，实际接通状态见[实施计划](../../superpowers/plans/2026-11-11-composable-engine-refactor.md)。

例如料理比赛或搜证活动，核心提交重要事实与授权观察，能力服务提供状态、活动和决策接口，玩法定义具体规则与呈现，游戏包选择组合。角色保持主体性，正式结果由核心裁定执行路径维护。

## 1. 已确认的方向

采用核心、能力服务、玩法插件和游戏包四层。宿主承担装配和端侧交付，默认提供者与具体玩法按显式选择进入组合。

原生模块与包内脚本共用作者定义。核心提供硬预算、实例执行资格、规则执行和原子提交，周期边界与世界时间分别表达。生命周期由实例根 Fiber 拥有，服务解析由 Context 隔离。

## 2. 目录表达职责

当前目录与入口见[模块地图](modules.md)。sdk、core、providers、memory-core、plugins、world-pack、frontend 作为参考布局，实施按依赖和独立导入能力决定实际拆合。

现有 `official-*`、application、desktop 与 Lens 中的能力先按公开边界迁移，目录整理集中在相应批次完成。每次真实包职责变化后同步模块地图。

## 3. 当前范围与恢复边界

| 内容 | 当前决定 | 实施归属 |
| --- | --- | --- |
| 原生插件声明状态 | 已进入施工范围，复用现有事件与状态能力 | B4、B6、B7 |
| 剧情节奏 | 已有 official-pacing，按共同周期和玩法接口迁移 | B5 |
| 原生执行允许状态 | 安装、允许执行、世界启用分别表达 | B2、B7 |
| 周期跨重启继续执行 | 可选恢复能力 | 基础实现采用有限恢复 |
| 临时任务恢复 | 根据已保存事实与有效来源重新计算 | 所属 Provider 的现有能力 |

已提交事实和必要玩法状态保持一致，未提交周期后续、反应计划及剩余结算允许丢弃。需要一次性奖励等业务时，用现有状态把领取事实与效果共同提交。

## 4. 曾经暂缓的两个需求

### A. 剧情导演与节拍器

2026-11-05 已实施为 official-pacing，通过世界包节奏脚本选择节拍或活动，并可提出状态与观察效果。当前能力及验收见[剧情节奏指南](../guides/story-pacing.md)和[当次记录](../studies/2026-11-story-pacing.md)。

新定稿沿用已有消费者，迁移其候选计算和正式效果应用。onCycleEnd 处理正常周期结算，玩法轮次由具体状态定义，机会提名继续保留角色自主决策。

### B. 插件声明宿主管理的持久化世界状态

原先仅记录需求，2026-11-11 定稿后已纳入施工。目标包含 Schema、初值、作用范围、可见性、公开操作与必要数据兼容声明。

跨插件变更通过状态所属模块公开方法生成合法效果，核心核对结构、状态转换和原子提交。实例、分支、重生候选和存档采用其真实生命周期。

当前源码已有包内状态、StatusState 与事件存储基础，通用原生注册仍待相应批次接通。具体契约见[定稿状态能力](composable-engine.md#8-stateservice-与原生状态注册)。
