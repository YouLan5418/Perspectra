## 一次输入

1. 网页宿主接收玩家输入。普通自由表达与显式 `/act` 操作分开处理；有活动时，先经过当前活动策略。
2. 玩家行动经现有裁定与提交路径形成世界事件。宿主按角色可见的新刺激提供处理机会。
3. `PrototypeCharacterTurn` 用当前提交前缀构建角色 view、场景、认知、授权观察和自身表达。角色地点来自该前缀的角色 view，不使用初始设定代替当前位置。
4. 默认模式使用原生记忆；`--memory-core` 通过宿主实验桥加入该角色长期 Delivery。最终模型呈现合并按事件排序的授权观察与自身表达，去除宿主追踪字段，并将动态信息放在历史之后；原始宿主请求仍保留完整记忆证据。详见[模型上下文呈现](cognition-memory.md#模型上下文呈现)。
5. Character Agent 调用模型，自主选择回应、放弃或提出行动。模型提案经过协议检查和 Action / Rulebook 裁定，不能直接写世界库。
6. Commit 完整返回后更新玩家授权投影。已提交 NPC 回复可在后续反应尚未结束时显示；页面通过轮询取完整结果，没有 token 流或草稿发布。
7. 已授权的新观察可以触发后续 Reaction Round；执行预算或期限到达后结束。启动器普通入口默认 3 波、8 次 NPC 调用、每角色 2 次激活、120 秒期限，可在包级运行参数中调整，下次启动生效。直接使用旧实验 tuning 或未传期限的底层调用仍保留 30 秒回退值。

完整玩家回合包含一次玩家操作及其引发的全部有界处理，结算与关键投递完成后才标记结束。[末端回合重新生成](../tail-round-regeneration.md)从该操作前的完整起点隔离重演，成功后追加并选中新候选，末端的 ‹ i/n › 可原子切换完整结果；继续输入后关闭上一组切换。只冻结长期档案，新观察照常传播。内部候选不进入正式转录。

普通反应只从授权 `observation.upsert` 中选择候选。满足当前普通路径条件时，调度器按已提交观察动态派发，而不等整波完成：最多两个在途激活，场外至多一个；派发时地点不能与在途角色相同，同一角色不并行。当前场景候选优先，其次优先较少 stale 重算、已完成激活次数较少的角色，同级再随机排序。每个在途任务先预留模型调用预算；新提交产生的授权观察会立即唤醒调度器并占用空闲名额。这里的最大波次限制因果深度，而不是要求一批角色全部结束后才能继续。同一角色、同一预算来源的待处理观察保留最深深度；较浅的新观察或 stale 重算合并不会降低深度，也不能因此派生超出最大深度的激活，超限观察以 `wave_limit` 收束。

动态调度只在没有 `--serial-scheduling`、包变量脚本、活动参与者排程和 `publicationAudit` 的普通路径启用；其他入口沿用原有串行调度。角色等待模型时不持写租约。模型返回后先检查授权投影；提交轮到该角色时先取写租约、读取最新前缀，再在租约内重新检查授权 view、认知、当前可见角色、可见物品和可用 affordances。单独的全局提交序号或 sourceAgeTicks 相对时间变化不会使角色状态过期；Rulebook 仍按最新前缀重裁定并原子提交。

stale 会计入总模型调用预算，但不计为完成的一次激活。调度器对同一待处理机会最多自动重算一次；第二次连续 stale 会停止该角色本轮剩余处理。完成一次非 stale 激活后清零该角色的连续 stale 计数。角色已 inactive 会停止该角色本轮调度，不会把整个 Reaction Cycle 标成 interrupted。某个角色的模型失败会停止该角色；其他已在途处理会收束，周期按实际失败结果报告。若受控行动已经提交、只有结果续写过期，重算只续写真实提交结果；再次 stale 时可丢弃迟到续写，不会重放或撤销已提交行动。细节与实测见[动态调度实验记录](../studies/dynamic-scheduling-20261011.md)。

地点互斥约束新派发。已在途角色提交移动后可以与另一个在途角色合流，已有行动结果续写继续，另一角色的旧视图可能 stale；不会把已提交移动撤销，也不保证所有在途任务始终位于不同地点。双向交换由顺序提交与一次重算处理，自动回归包含普通与自主角色的移动冲突。

普通、自主和自主后续反应分别预留与结算调用预算；召回、结果续写和 stale 重算均计费，未用的预留归还本组。普通与后续反应共用每角色激活上限，到期自主角色只消耗自己的配置机会，普通根刺激并入自主机会。已经就绪的普通回应可合并自主观察；消费旧观察后只剩自主来源时，下一次调用使用自主后续预算。普通期限与自主及后续共用期限独立，从共享派发开始计时，一组截止不取消其他组。

同一角色的行动与真实结果续写保持连续。调度优先级只决定处理机会，不强制回应，也不改变角色的意图或对白；序章与活动排程保留原有顺序。自主候选与普通角色按相同的地点、前台和公平优先级派发，预算或期限不足时不保证每个自主角色轮到。NPC 处理中宿主可公开 `canInterrupt`；允许插话时，玩家的新输入会取消旧回合未提交的 NPC 计算，等待旧回合收束后再开始新输入，已提交的玩家输入和 NPC 行动保留。页面仍只显示已提交表达，没有 token 草稿流。控制对照驱动、样例包和边界说明见[动态调度实验记录](../studies/dynamic-scheduling-20261011.md)。

活动入口复用角色处理能力，但由脚本的 schedule / onOutcome 请求本次实际参与者处理，采用自己的有界链。名单可由作者固定或由玩家从当前授权候选中选择，开始后固定；邀请是否接受由目标角色的作者操作裁定。旁观者仍按普通观察权限收到公开表达，但不自动加入活动调度。包可声明多个活动，一次只运行一个；暂停活动保留进度，不施加许可或调度，恢复时检查当前世界条件，见[创作者运行时](creator-runtime.md)。调度机会不规定角色情绪、意图或对白。

## 后台记忆与边界

Core 长期整理在排队前冻结授权 Source 前缀。后台运行期间前台继续对话和移动；成功安装后保留新经历尾部。玩家回合期间延后档案安装，任务提交前核对运行实例的世界版本；替换世界线时取消并收束旧任务。未提交计算允许取消和丢弃，已提交世界事实保持一致。默认原生模式没有因此改为 Core。

完整节点保存当时已安装的 Core 档案，分叉仅恢复节点快照并校验授权来源和时间前缀，不调用 Build；旧节点没有档案时保留截至节点的完整授权原始经历。启动恢复失败仍保留现有恢复标记。详见[故事节点记忆边界](cognition-memory.md#故事节点的记忆时间边界2026-10-09)。

核心实现入口：[网页宿主](../../../tests/experiments/playtest-frozen-runtime.ts)、[Character Turn](../../../packages/application/src/prototype-character-turn.ts)、[网页玩家视图](../../../tests/experiments/playtest-view.ts)、[Core 桥](../../../tests/experiments/playtest-memory-core.ts)。性能证据见[研究索引](../studies/ai-girls/README.md)。一次真实轨迹仍出现普通反应约 30 秒中断；增量显示没有消除整轮等待。

## 角色思考强度

玩家在启动器“模型 → 修改”选择关闭、低、中、高，保存为当前实例的模型配置；“模型设置”可修改新实例默认值。选项在下一次启动传入运行时，仅影响角色决策及行动结果续写，玩家输入解析和记忆 Utility 沿用原配置。未设置的新字段不改变已有实例；不会重写存档事件。

OpenAI 兼容模型使用 reasoning_effort；DeepSeek 单独发送 thinking 开关，低、中、高映射为 low、high、max，开启时采用 auto 工具选择，返回仍经过现有解析、Schema 和 Rulebook 校验。Google 原生 Gemini 3 使用 thinkingLevel，旧支持型号使用 0 / 1024 / 4096 / 16384 思考预算；不支持完全关闭的 Gemini 3 / 2.5 Pro 在界面禁用关闭，宿主拒绝保存该选择。Anthropic 原生使用 disabled 或 enabled 加预算，开启时不发送与思考冲突的 temperature / top_p；现有 auto 工具选择保持不变。

开启思考时，模型输出预算至少提高到低 8192、中 16384、高 32768，保留原设置中更大的上限，容纳推理与最终回答；字符发布上限及超时不随档位改变。该预算不是保证输出完整或保证所有角色在周期截止前回应。思考强度加入末端候选环境比较，不能跨设置复用候选。

2026-10-09 本机 8046 的公开无历史测试请求四档均返回 abstain，实际上游低/中/高分别为 thinkingBudget 1024 / 4096 / -1；关闭被网关映射为 1024，因此 Gemini 3 的关闭已明确禁用，不把参数发送成功当成关闭生效。其他网关的配置仍可能覆盖客户端强度，原生 DeepSeek / Anthropic 四档尚未逐档真实验收。参数映射、意图调用隔离和实例持久化有回归测试；未把内部思考写入世界事实或长期记忆。
