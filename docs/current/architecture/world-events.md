# 独立世界事件和插件消费

核对日期为 2026-11-18。料理进行到第 4 个玩家回合时，作者可以让厨房停电。料理继续占用原活动位。世界包在 `plugins` 选用 `official-world-events`，在 `assetFiles` 锁定 `world-events.json`，并用包自己的基础状态脚本声明公共布尔值 `power`。要让已安装的演出插件收到通知，还需要在包的 `plugins` 选用该插件，并在规则文件中授权。

```json
{
  "rules": [{
    "id": "kitchen-blackout",
    "type": "power.outage@1",
    "round": 4,
    "location": "location:kitchen",
    "audience": { "anyOf": ["scene", { "holds": "entity:radio-1" }] },
    "set": { "key": "power", "value": false },
    "observation": "灯熄灭了。"
  }],
  "grants": [{ "plugin": "stage-cue", "type": "power.outage@1", "mode": "live" }]
}
```

`ctx.content` 生成器只提出该文件里声明的规则 ID。Host 从锁定的原始文件独立核对可选规则、状态写入和消费授权。状态写入限基础包的公共布尔状态，排除原生玩法、模块和活动专用状态。默认硬规则按声明顺序在首个达到或超过阈值的合格结算周期执行一次。宿主在写租约内用同一已提交前缀判定回合、规则标记和受众。省略受众即同场，使用发生地点唯一活跃场景的见证资格。同一地点若有多个独立活跃场景，地点无法确定同场受众，此项不给任何人授权；组合中的持有物等条件仍各自有效。`global` 含所有活跃角色，包括玩家和暂未被调度的 NPC。持有按具体实体 ID 查询。一层 `anyOf` 最多四项，死亡、离开或失能角色统一排除。没有见证者时仍可改变状态。

作者还可把规则的 `trigger` 设为 `paced`，在节奏配置的 `events` 里以相同规则 ID 声明强度。省略 `trigger` 或显式 `hard` 均按硬条件执行。原有状态结算（−20）、硬事件与延后回执（−15）、节奏或活动（−10）依序各用自己的事务。节奏器拿到合格 ID；选中后，Host 在该次结算快照上复核阈值、一次性标记和活动占位条件，通过相同的发生与见证提交路径写入。活动占位时，可选规则需显式 `duringActivity: true`。关闭节奏器时，硬事件照常结算，可选事件等待再次开启。可选规则的实际发生回合随发生记录保存，供当前分支恢复节奏冷却；硬事件、未选中或提交失败均不计为一次节奏选择。[创作者配置](../guides/story-pacing.md)

日历硬触发用 `"when":{"crossesPackTime":{"dayKey":"day","slotKey":"slot","slots":["清晨","午后","傍晚","深夜"],"at":{"day":2,"slot":"傍晚"}}}` 替代 `round`。天数与时段取锁定包自己声明的公共数值与字符串状态。Host 在有效分支上逐笔比较事务前后完整的日历，首次满足「旧值小于目标，新值达到或超过目标」即可结算。初始化只建立基准；未知时段或无效天数会产生诊断并切断这段比较。不要把改包后的配置装进旧包存档。

时钟和工资等动作结果可以先提交。若随后断电提交失败，同包重开后的下一次合格结算从分支历史重新找到跨越；发生记录含来源事务，状态和授权观察在断电自己的事务落库，查询不触发补算。活动重试本身不计玩家回合；若其 NPC 操作实际跨过阈值，本次只放行刚到期的日历规则。[日历判定](../../../apps/host/src/runtime/pack-time.ts)

若本轮唯一的停止原因是普通调度的模型调用额度用尽，周期仍记为 `budget_exhausted`。此时 Host 只结算当前选中分支在本轮实际提交的日历跨越。状态回合钩子、普通回合硬规则、延后回执、节奏和自动开场仍等待正常合格周期。已提交的显式唤醒继续遵守原有的独立额度与活动占位规则。

同场日历规则可在 `sceneNotices` 声明最多四组场景，每组最多十六个互不重叠的已知地点。每组继承主观察或给出专用 `text`。Host 在发生事务之前计算每个地点的活跃场景与见证资格，同一角色只收到一条。可选的 `fromOperation` 进一步限定给跨越时那次状态操作的完整内容接收者。来源不匹配、无法唯一确定动作或只有发生级可见性时，不发该组观察。这样家中角色可以目击断电，当时参与游园且仍在公园的人可以看到远处线索。[正式包声明](../../../examples/world-packs/model-girls-sweet-days/world-events.json)

每次发生有独立发生 ID。状态、各见证者观察及含规则标记的发生记录由同一结算事务提交。见证写入已有的 `eventNotice`。这类事实没有行动裁定的 `status: accepted`，默认调度器不会只因看见停电就唤醒 NPC。角色在下一次有资格行动时仍可读取自己的观察。活动保留自己的进度、参与者与结算。发生记录保存在现有 round authority，Host 用每一分支的有效事务前缀重建索引。[宿主实现](../../../apps/host/src/runtime/world-events.ts) · [结算入口](../../../packages/core/src/application/world-round-execution.ts)

## 让指定目击者获得一次角色决策

在一条规则中可选填 `"wakeCharacters": ["character:gpt"]`。每条最多列八个互异的包内 NPC。Host 将名单与该次实际收到个人观察的活跃 NPC 取交集，随发生记录一起提交。省略字段时只交付观察。《屋檐下》的正式包沿用此默认值。

在选中的分支上，Host 在玩家或系统交互的结算窗口按发生顺序处理，每窗最多四次，其余保留到以后。正在参与活动的角色等活动释放。即使普通自主机会设为零或普通调度已耗尽额度，也能处理已提交的待办；外层请求的取消、硬上限和失败仍然有效。一次发生与一个角色对应一次正常决策，角色可以沉默。受控操作仍可沿正常角色流程得到结果续写，每次激活最多两次模型调用。模型的刺激只取角色自己的原始授权观察。普通活动发言时，若历史已含完整目击，模型在原有位置读到它，当前刺激省去重复正文。独立事件决策需要知道本次因由。原文仍在该角色可读历史时，`stimulus` 指向本次请求的 `context.history[i]`。仅有摘要或原文已滑出窗口时，`stimulus` 提供完整授权原文。历史窗口及排序不因一次唤醒而改变。

发生记录、发送前的占用记录和完成回执都属于当前分支的有效事务前缀。打开存档、查阅状态和重生成未选候选不调用模型。发送前先持久记录占用，收到明确的决策结果后记完成。进程在占用提交后崩溃或传输结果不确定时，Host 保留占用并输出未确认诊断，后续窗口不会自动重发。占用到实际发送之间崩溃也归为未确认。这里保证分支内不会盲重试；外部模型调用与本地提交之间没有共同事务。

## 订阅

原生插件须获得宿主执行许可，在自己的静态清单中声明 `worldEvents`，再于 Cordis 初始化期间注册。例如：

```js
export const hostApi = '2.12'
export default ctx => {
  ctx.effect(() => ctx.worldEvents.subscribe({
    type: 'power.outage@1',
    mode: 'live',
    open({ signal }) {
      return event => {
        if (!signal.aborted) recordLocalCue(event.occurrenceId)
      }
    }
  }))
}
```

示例中的 `recordLocalCue` 由演出插件实现，只记录服务内部的提示。[离线演出消费者](../../../tests/fixtures/world-event-stage-cue.mjs)是可独立装载的模块，测试把它的交付记录保存在一次性目录。Host 按注册 Fiber 的真实插件身份、包选择、发生时和当前授权交集交付。回调只拿到版本化类型与发生 ID。每个挂载实例首次交付时单独打开处理器；关闭实例、撤销订阅或销毁订阅所属 Fiber 都会取消它的 signal。启动后新增订阅须重新装载插件。玩家与 NPC 通过各自获准的观察阅读内容。内部服务通知不提供玩家已读证明，不能直接当成一条可展示的旁白。

| 模式 | 实际保证 |
| --- | --- |
| live | 活跃实例从选中时的首部向前读取，确认提交后每次发生最多尝试一次。回调失败、重启或选中已有候选均不补播。 |
| durable | 仅在后续合格周期处理。同一插件对同一次发生返回 `ack`，或返回 `apply` 选择包在该 grant 的 `effect` 预先声明的布尔写入。同步回调抛错或返回非法值时只推迟该消费者。 |
| 重开与回退 | 效果与回执同事务。空效果回执沿用正常结算 tick。事务前中断可再次调用处理器，涉及外部系统的动作需自行幂等。分叉继承分叉点之前的发生与回执。未选候选不调用消费者，选中后 durable 在下一合格周期补处理，故重生成当回合可能暂缺原分支已经落下的消费效果。 |

消费接口没有发布或活动控制方法。授权的 `apply` 可以写入事先声明的效果，后续规则仍需等合法结算时机。同一事务中多条规则的受众统一取事务前的触发快照。生产者身份不进入消费信封或一次性标记。代码入口见 [SDK](../../../packages/sdk/src/world-events.ts)、[官方内容插件](../../../packages/plugins/src/world-events/index.ts)及[故障与分支回归](../../../tests/host/world-events.test.ts)。
