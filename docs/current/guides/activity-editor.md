# 在编辑器里制作和试玩活动

在「门廊便笺」里，阿林和玩家同处门廊时，玩家可以请她帮忙。把阿林的开局改到书房，再次试玩，这个选项就会消失。创作者可以用这个例子核对自己写的条件。

## 打开作品

从仓库根目录执行下面的命令。首次使用或更新界面后需要构建页面。

```powershell
corepack pnpm@11.7.0 launcher:build
node --import tsx apps/host/src/cli/worldpack.ts editor serve examples/world-packs/porch-note
```

命令会在本机浏览器打开作品，点总览中的「读便笺」直接进入画布。左侧「活动流程图」可打开活动目录。省略目录可进入[创作工作台](world-workbench.md)首页打开或新建作品。也可以用下面的命令创建一个新目录，再用同一入口打开。

```powershell
node skills/perspectra-creator/scripts/create-world.mjs ./my-world pack:my-world 我的作品
node --import tsx apps/host/src/cli/worldpack.ts editor serve ./my-world
```

## 做一个选择

1. 在「活动目录」选中活动，或点「新建活动」。新活动使用唯一的小写英文标识。在流程图点开场可编辑活动名和开场文字。
2. 点「新增节点 → 玩家选项 → 添加玩家选项」，在右侧填写选项文案。在「查找条件」输入角色名、物品名或 ID，再从「出现条件」选择「阿林在场」或「玩家持有开信刀」。也可以选择「始终可选」。字段存储稳定 ID，同名记录可用 ID 搜索。
3. 在「选择结果」写玩家选择后发生的事。在「玩家发言」填玩家自己要说的话，留空即可跳过发言。「接下来」决定回到日常或留在活动。用「上移」「下移」调整玩家看到的顺序，「移除选项」从当前草稿移走选中的分支。
4. 点「试玩活动」。展开「试玩起点」可以指定角色开局所在的场景。逐个查看哪些选项可用，「定位条件」会选中节点并把光标移到对应字段。「从起点执行」会重新开局并执行一次选项。这里运行正式 Host 的活动裁定，NPC 使用脚本化模型。
5. 点「导出源包」后，提示里会显示新目录。导出内容含标准清单与活动脚本，可以重新打开编辑，也可以用普通的 `worldpack validate`、`worldpack compile` 命令处理。

「保存」在当前源包的 `creator-activities/` 写入草稿。导出会校验并写入一个新目录，手写活动脚本保持原样；列表把它们标作「手写活动」。手工调整过的生成脚本也按照手写脚本处理。当前流程图覆盖单玩家选项、结果、玩家发言和去向，一项活动最多 16 个选项。其他原生玩法和事件的源字段见[创作者字段总览](creator-fields.md)。

### 整理子流程和追踪引用

在「读便笺」点「拆阅便笺」进入子流程。用「新增节点 → 子流程」勾选当前层的玩家选项或其他子流程，或在空子流程内继续新增。点「编辑子流程」调整成员、改名或解散到上层。拖动节点或聚焦后按 Shift 和方向键调整位置。子流程组织编辑视图，玩家选项仍按活动中的顺序和各自条件执行。

点「引用」搜索角色、物品、世界变量、活动变量和裁定脚本。默认列出当前低代码活动；勾选「包内全部低代码活动」扩大范围。「所有使用位置」按对象 ID 和活动变量的所属活动查找。「打开定义」进入相应表单，点来源行定位到选项的具体条件、赋值或裁定字段。失效引用标红，可以点来源修复。这个索引读取结构化字段，手写 JavaScript 中的动态访问需要查看脚本。

外部 Agent 用 `worldpack editor activity-references <源目录>` 查询同一索引，末尾可传 JSON 请求文件。可按 `activity`、`choice`、`kind`、`id`、`scope` 过滤，如 `{"kind":"held","id":"entity:opener"}`。索引会返回 `field`（例如 `condition/1`）、`fieldLabel` 和 `valid`。用 `open` 读取活动，用 `save` 提交 `{base,graph}`。可选的 `graph.layout` 数组用 `id` 定位节点，带 `title` 的记录声明组，可用 `parent` 指向上层组，`x`、`y` 是同层坐标。画布处于前台时会自动载入外部保存的同一活动，以磁盘草稿为准。

### 让「展开便笺」同时检查物品和灯光

1. 在「读便笺」选中「展开便笺」。它已经引用开信刀。点「添加条件」，从「新增条件」选择已有的世界变量「门廊有电」。如需创建，点「新建条件变量」，填写键 `power-on`，选择世界公共、布尔型和初值「是」。把条件的「等于」设为「是」。
2. 在「匹配方式」选「全部满足」。流程图会列出两项要求。点「条件 2」可更换引用或修改值。若选「满足任一项」，玩家持刀或有电就能展开便笺。移除一项后，剩下的一项会成为独立条件。
3. 展开「试玩起点」，勾选「指定门廊有电的开局值」。用下面三组设置各点一次「试玩」。勾选「先拿起开信刀」时，玩家会在起始地点执行包里的拾取操作。每次试玩都从独立副本重新开始。

| 先拿起开信刀 | 门廊有电开局值 | 「全部满足」下的展开便笺 |
| --- | --- | --- |
| 否 | 是 | 不可选 |
| 是 | 否 | 不可选 |
| 是 | 是 | 可选，点「从起点执行」读信 |

保存后，在开信刀的「物品用途」或「门廊有电」的「被哪些地方引用」中点「展开便笺」，会回到该分支并选中对应的条件行。如果外部 Agent 已经调整顺序，编辑器会在最新草稿中查找同一引用。如果引用已删除，页面会提示你核对当前分支。

## 通过 CLI 修改活动

例如让 Codex、Claude Code 或 DSH 添加一个「请阿林帮忙」选项，可让外部 Agent 通过 `worldpack editor open` 读取当前活动和包内候选，使用 `save` 提交修改、`play` 检查选项。下表列出所需参数。

变量条件保存为 `{"kind":"world","ref":"power-on","value":true}`，局部字段使用 `kind:"local"`。结果可通过同样格式的 `effect` 赋一次值。局部定义写在图的 `variables` 列表，每项需要 `key/label/type/initial/scope`，可选 `options`。同一个键可以在不同活动使用。参与者共享、行动者私有、活动内部分别使用 `shared/private/internal`。世界状态更新与活动进度一起提交。完整操作见[做一次门廊停电](world-workbench.md)。

## 给选项添加裁定

玩家用 2 点精力搜查房间。在「活动流程图」选中「搜查房间」，在「操作裁定」选「消耗数值」，选择已经声明的精力变量，消耗量填 `2`，不足时的提示填「精力不足。」。「结果赋值」可指向另一个变量，例如玩家自己的「已找到线索」。成功才提交扣费、线索和活动进度。点「试玩 → 从起点执行」可看到玩家能读取的裁定前后值，例如「精力：2 → 0」。专属 HTML 页面的按钮绑定同一个操作即可。

复杂计算可在「规则脚本 → 新建裁定脚本」编写。文件名就是引用键，例如 `scripts/adjudications/search-cost.js`。首行声明名称、变量类型和参数；参数沿用变量表中的键、名称、类型、默认值和可选枚举。

```js
// @perspectra-rule {"title":"搜查消耗","type":"number","parameters":[{"key":"cost","label":"消耗","type":"number","initial":2}]}
export default function adjudicate(value, parameters) {
  if (value < parameters.cost) return { rejectReason: '精力不足。' }
  return { value: value - parameters.cost }
}
```

脚本保存后，在流程图的「裁定方式」选择「搜查消耗」，再选择变量、填写参数。多个活动可以共用脚本并分别填值。一次绑定处理一个可读写的世界公共变量、活动共享变量或玩家自己的活动变量，函数返回同类型的新值或拒绝原因。完整手写活动可自行组织多个输入、调度和世界效果。

在「规则脚本」也能打开已有手写活动，查看源码、已声明的操作及其参数。外部 Agent 也可通过脚本 CLI 读取和修改源码。导出携带裁定源文件并将已引用的函数编入对应活动，重新打开导出目录仍可编辑表单和源码。

## 外部 Agent CLI

以下子命令都接在 `node --import tsx apps/host/src/cli/worldpack.ts editor` 后。浏览器和命令行共用相同的读取、引用检查、保存、试玩和导出逻辑。JSON 文件使用 UTF-8。修改现有选项时保留 ID，移除后另建的选项使用新 ID，以便仍在运行的助手能识别原节点已经删除。

| 命令 | 输入与结果 |
| --- | --- |
| `open <源包>` | 返回可编辑活动、手写活动键和角色、物品、场景候选。 |
| `save <源包> <edit.json>` | 提交 `{"base":原活动,"graph":修改后的活动}`。新活动用 `"base":null`。同字段冲突返回非零退出码、冲突值和已有活动的整批候选。 |
| `play <源包> <request.json>` | 必填 `key`，选填 `choice`、角色场景映射 `scenes` 和上次读到的活动 `expected`。可传 `"take":["entity:opener"],"world":{"power-on":true}`。可拿物品和可设置的世界变量取自本活动条件。返回开局可用选项、源包指纹和执行结果。 |
| `export <源包> <新目录>` | 写入经过校验的独立源包。目标目录必须尚未存在。 |
| `assist <源包> <request.json>` | 例如 `{"key":"read-note","selected":"leave","provider":"codex","prompt":"把当前选项改成「待会儿再拆」"}`。可用 provider 为 `codex`、`claude`、`dsh`。成功返回的 `undo` 可原样交给 `save`。 |
