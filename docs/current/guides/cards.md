# 纸灯牌桌：可扩展卡牌活动

玩家打出「光矢」并支付牌，青可以交「折光」取消攻击，也可以放弃防御，让墨交「续灯」援助。等待防御和求援时可以保存；从同一个节点分叉后，交牌和放弃各自结算，另一分支不会收到这次事件。牌桌结束或中止后回到日常互动。

这是 `official-cards` 的首版原创样板。它不依赖 official-rpg，不引入第三方美术、卡库或源码。源码、自动化与本次浏览器验证范围见[实施验收记录](../../superpowers/plans/2026-11-16-card-activity-foundation.md)，不表示发行包已经包含或真实模型自然度已验收。

## 启动样板

仓库根目录（Node 24，按仓库锁文件安装依赖）：

```sh
corepack pnpm@11.7.0 install --frozen-lockfile
node --import tsx tests/experiments/cards-preview.ts
# 或直接进入身份战
node --import tsx tests/experiments/cards-preview.ts --identity
```

打开终端的本机地址。此入口使用临时 SQLite、确定性 NPC 和回环测试 provider，不读取模型密钥；退出进程清理临时世界。普通起始页面可在「行动」中选择三个活动。读完开场后可在牌桌点击合法选择；宿主工具栏支持保存、中止和切回默认界面，默认界面的活动卡支持暂停与继续。

正式内容在 [card-table](../../../examples/world-packs/card-table)。源清单只启用 `official-cards`，并把 `cards.json` 列入 `assetFiles`。配置 `npcIds` 为参与角色，`npcMode` 可为 `deterministic` 或 `model`；省略为确定性模式。`model` 模式角色仍按自己的授权上下文决定，收费与模型自然度不在本次验收范围。可选整数 `seed` 用于复现；未指定时用 Host 已记录的一次随机抽取种子。

三席是样板包配置，不是纯引擎限制。身份战至少三席，接龙由规则决定顺序，竞价要求恰好三席。配置额外角色时，三席竞价会在开始校验中拒绝，其他活动仍可独立使用。

## 三个规则包

| 活动 | 规则及结束条件 | 私有信息 |
| --- | --- | --- |
| 四色接龙 | 同色牌、选色牌、折返牌；可抽牌过牌；手牌出尽获胜，40 步以最少手牌结算 | 本人手牌，牌堆顺序 |
| 灯塔守望 | 光矢支付→目标防御→其他活席求援→护光修正→伤害；守灯人/逐影者倒下或坚持20回合结束 | 随机身份、随机初手、本人合法选项 |
| 密封竞价 | 同一个逻辑请求收三份0–9整数报价；先交不能改；收齐揭晓，最高获胜，同价按声明席位顺序 | 揭晓前只知道本人报价；已提交哪些席位是规则明确公开的进度 |

身份战固定优先级是防御取消(10)、援助减伤(20)、一次护光减伤(30)、伤害(40)。取消也不退还已支付的攻击与响应牌；所有费用一次移入弃牌，结算帧出栈。等待期间原回合所有者不变。求援请求向所有其他合资格活席发出，各席都能放弃；手中是否有援助牌只影响本人选项，不影响公开请求席位、轮数或操作次数。

当前样板把每个 Host 角色绑定一个席位；纯引擎显式分开席位 ID、控制者 ID 与规则目标，支持一个控制者管理多个席位、非人物目标、自定义牌区及不带牌的数值选择。没有把出一张牌、选一个人写进引擎。

## 分层与提交

[engine.ts](../../../packages/plugins/src/cards/engine.ts) 是无 Host、无 SDK/Node 依赖的纯 TypeScript 模块，提供牌定义/实例、唯一归区、原子移动、请求、已接受输入、随机记录、结算帧、结果和授权投影。`submit` 在副本上按控制者、当前请求和合法候选校验，再调用规则与终态不变量；拒绝不改变原状态。随机记录使用 uint32 整数，满足 Host WorldJson 的整数约束；相同种子与已接受输入可重放出逐字段相同状态。

[rules](../../../packages/plugins/src/cards/rules) 定义合法选择、顺序、阶段、优先级、政策和胜负。竞价没有顺序回合所有者，`pending.answers` 在收齐前保留在私有真值。规则函数是可信插件代码，候选和投影得到独立副本，不能通过读操作改写原状态。

[activity.ts](../../../packages/plugins/src/cards/activity.ts) 把纯牌桌保存在 Activity `internal.table`，把公开桌面和每个控制者自己的牌/身份/候选分别写入 `public`、`private`。实际变更通过 `nativeGameplay` 展开为 `GameplayDefinition/Operation`，玩家和 NPC 使用同一个 `submit`。NPC 的确定性模式仅产生正常决策，不直接提交。持久选择与帧都是 JSON，没有悬挂 Promise。

[content.ts](../../../packages/plugins/src/cards/content.ts) 生成活动与原生玩法定义；[渲染器](../../../packages/plugins/src/cards/stage-renderer.ts) 仅消费已授权的有限 payload，并通过既有 `perform` 提交选择。Host 只在官方内容和可信舞台清单登记插件；Core、SDK、通用前端没有卡牌语义，没有 `ctx.cards` 服务。

Host 的旧 Activity 要求 active 时 `game.turn` 是参与者。适配层为没有顺序回合的竞价放一个生命周期锚点；这不是合法行动者判断，操作声明 `requiresTurn:false`，多席逻辑请求和一次性报价仍由纯引擎决定。Host 可以依次采集 NPC 报价，但仍是同一轮密封请求。

## 信息边界和恢复

普通玩家拿到的手牌是本人牌面，对手只有数量。公开区域的展示句柄不包含稳定实例 ID，移动/洗牌增加展示世代，展示后洗回牌堆再展示不会复用旧句柄。牌堆只投影数量；私有身份与候选只进本人的 Activity 私有部分。日志只放规则明确公开的文本。插件没有注册调试视图；已有创作者检查器属于 Host 本地主人通道，普通 iframe 公共 API 不获内部真值。

`pending.seats`、`submitted`、回合所有者和日志在当前规则中是公开包络。**增加秘密响应政策时，不要直接用隐藏身份筛掉请求席位**：应向固定的公开候选集发请求，为没有私有权限的席位提供同样一步的空响应/放弃，再在本人候选里控制真实权利。Host 的处理者、revision、观察 actorId 仍可显露实际操作身份和次数；它不是隐藏调度框架。成对测试专门改变别席角色和防御牌能力，保留固定包络，对照 `actorId`、目标、revision、请求/续接、观察与授权记忆。测试归一随机 UUID、装配 scope、对应派生哈希及非确定耗时；观察按 sourceSeq 比较，不删除语义字段。它不证明任意第三方秘密调度或自然语言都不会泄漏。

数据兼容声明为 `official-cards/dataVersion:1`；每个纯规则还校验 `schema/rule/version`。恢复时校验所有牌区、实例、报价范围、请求席位与目标/费用绑定，以及持久投影与真值的一致性。不兼容安全拒绝，不自动迁移。

仅 Activity id/revision 不能区分相同节点的恢复副本，见[可重跑探针](../../../tests/host/cards-admission-probe.test.ts)。卡牌在每次装配时给选择操作生成独有 scope，外部旧实例的完整操作在同 id/revision 下仍会被拒绝；纯牌局不保存这个 scope。节点恢复、树导入和分叉重新装配后，刷新新操作即可继续，已提交选择不重新询问模型。

**已知限制：末端「重新生成」**会把录下的旧操作交给新装配实例，因 scope 变化被拒绝，原结果、事件和当前可用操作保留。探针在 [cards-activity.test.ts](../../../tests/host/cards-activity.test.ts)；不把它报成通过的重生成体验。最小通用改进是由 Host 的可信历史重放入口区分「已接受输入重放」与外部新提交，并在验证原输入后把逻辑操作重绑定到当前实例；外部请求仍必须绑定当前实例/分支。不要让插件接受旧 scope，也无需新增卡牌服务。普通节点恢复与纯输入重放已可用。

首版只产生局内 `Activity.id + table.result` 的终局边界，不自动改变世界物品、货币或奖励状态。测试验证正常结束与强退均无世界奖励事件、未完成无 result、结束请求不能重复提交。未来跨局奖励应由显式组合的受控操作以 Activity.id 做原子去重；本版没有暗藏商店或奖励发放器。

## 添加第四个规则包

1. 在 `cards/rules` 实现 `RulePack`，声明稳定 id/version、初始化、合法候选、接受后的转换、公开/私有数据和恢复不变量。复用 `request/move/shuffle/finish`，不复制 `submit` 状态机。
2. 用 `addZone` 声明公开、所属控制者可见或隐藏牌区；用 `CardDefinition` 复用牌的定义，每张实牌给独立实例 ID。候选 `Choice.value` 可为数值、对象或多目标数组。
3. 把规则加到 `officialCardRules`，或在独立原生装配中调用 `createCardsContent([...])`。游戏包显式选择该内容生成器和配置。生成器负责活动入口，规则无需读 Host。
4. 为请求的公开包络定义政策；隐藏资格用私有合法候选和空响应遮蔽。增加纯完整流程、拒绝无变更、兼容、种子重放及真实 Host 成对投影测试。
5. 破坏持久状态/阶段语义时递增规则版本和插件数据兼容版本，明确拒绝旧数据或提供经验证的迁移。

首版不做联机、通用棋盘/商店、规则 DSL 或完整三国杀卡库。没有把隐藏技能任意插入调度的能力宣称为已经安全接通。
