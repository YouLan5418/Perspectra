# 包透视：不开游戏看清世界包

2026-10-31 按 `feat/pack-lens` 分支源码核对。

例如你对 AI 说“深夜冰箱事件改成傍晚也能触发”。AI 改完后给你一段总结，你没法判断它改全了没有；亲自试玩要开新实例、走到傍晚、走进厨房。包透视让你不开游戏就能看三件事：事件“深夜冰箱的偷吃抓包”现在有哪几条触发条件，其中“时段是傍晚”是不是新出现的；把起点设成“傍晚，玩家在客厅，DeepSeek 在厨房”后让玩家走进厨房，这场事件会不会触发，没触发时卡在哪一条；你想再改的地方，选中它写一句“再放宽一点”，AI 自己去读这条清单。

本页说明怎么用。设计动机和取舍见[设计稿](../../superpowers/specs/2026-10-31-pack-lens-design.md)。

## 1. 它能做什么，不能做什么

包透视是**只读**的：它读世界包源目录，不编辑包，也不写存档。唯一写入是包源目录下的 `.perspectra-lens/`，里面是你的“已看过”快照、对比点、待改清单和推演脚本。字段和规则仍交给 AI 修改。

它**不证明体验**。推演用的是真实宿主运行时（同一份状态脚本、活动脚本、规则裁定与事件提交），但模型换成了桩：角色默认弃权，或者照你指定的计划说话或行动。所以推演能回答“规则和触发对不对”，不能回答“角色演得自然不自然、会不会作出符合性格的选择”。推演通过不等于体验验收通过，后者仍需真实模型试玩。

## 2. 入口

| 入口 | 谁用 | 做什么 |
| --- | --- | --- |
| Launcher 主页的“透视”按钮 | 作者 | 打开当前包的透视窗口；包校验失败时按钮不可用，悬停提示写出校验错误 |
| `worldpack.cmd lens view <源目录>` | AI | 输出与界面同源的透视结果 JSON，外加相对“已看过”基准的改动列表 |
| `worldpack.cmd lens requests <源目录>` | AI | 输出未关闭（open 或 changed）的待改清单 |
| `worldpack.cmd lens simulate <源目录> <脚本.json>` | AI | 跑一份推演脚本，输出逐步经过与期望结果 |

用源码而不是发行包时，把 `worldpack.cmd lens` 换成 `node --import tsx desktop/lens/cli.ts`，参数相同。脚本名可以是一个文件路径，也可以是 `.perspectra-lens/scenarios/` 下的文件名。输出是单行 JSON；失败时退出码为 1，stderr 带 `{"error":{"code","message"}}`。

CLI 三条命令都是只读的：读透视不会移动“已看过”基准，也不能新增或关闭待改条目。

## 3. 窗口里的视图

窗口左侧是导航，中间是主视图，右侧是选中条目的详情，风格沿用创作者控制台。

- **角色**：她的人设摘要、说话方式、立绘、初始场景，以及自主唤醒（每几个玩家回合、几次机会、哪些事件会叫醒她、主动时可用的交互）。推演开始后，会按当前时刻显示她此刻真正被运行时提供的选项。
- **事件**：每个活动的标题、开场文案、参与者、玩家可选操作，以及自动触发条件。条件逐条显示标签和 ✔/✘，按推演的当前时刻计算，没开始推演时按开场状态计算。玩家在推演里实际选过某个操作后，才会在该事件下显示这一步带来的状态变化；工具不翻译脚本，没选过的选项不会预测它改了什么。
- **回合推演**：见下一节。
- **谁知道什么、地点、状态、物品、规则、预设**：对应各自的设置摘要。预设只显示摘要，不展开全文。
- **待改清单**：见第 6 节。

窗口的作者能看到所有私有内容（角色私有观察、internal 状态），这和创作者控制台一致；这些内容不会进入玩家页面。

## 4. 推演

推演会把包复制到临时目录，在那里启动真实宿主运行时，结束后丢弃，不碰包文件、存档或历史试玩目录。

**起点**可以直接设定，被当作“另一种开场”：在运行时启动之前改写临时副本里的初始数据，再按正常开场初始化，起点之后的每一步都走真实规则。可以覆盖：

- `status`：公共状态与各角色自己的状态初始值，如 `{ "public": { "slot": "傍晚" } }`；
- `scenes`：角色所在场景，玩家也在内，如 `{ "character:deepseek": "scene:kitchen" }`；
- `skipAutoStart`：这次推演不要自动开始的活动标识，如 `["prologue"]`。

引用了不存在的角色或场景会直接报错，不会自动修正。

**点选推演**在窗口里进行：选起点，然后点玩家当前可用的行动（移动、交互、活动操作、说一句话、静观）。每点一步，“逐步经过”追加这一步：玩家输入、规则判定、移动与物品转移、状态变化、自动事件检查（哪个活动触发了，哪个没触发以及哪条条件不满足）、哪些角色获得了机会、回合结束钩子做了什么。可以给某个角色指定一次行为：弃权、说一句话，或尝试她此刻被提供的某个选项（照样经过规则裁定，可能被拒绝）。

**脚本推演**由 AI 写一份 JSON，一口气跑完。格式见 [gameplay.md](../../../skills/perspectra-creator/references/gameplay.md)。示例：

~~~json
{
  "title": "深夜厨房",
  "start": {
    "status": { "public": { "slot": "深夜" } },
    "scenes": { "character:player": "scene:living-room", "character:deepseek": "scene:kitchen" },
    "skipAutoStart": ["prologue"]
  },
  "steps": [
    { "move": "location:kitchen", "expect": { "started": "midnight-fridge", "status": { "slot": "深夜" } } }
  ]
}
~~~

玩家行动用游戏里的名字写，运行器对照当前实际可用的选项匹配；找不到时这一步报错并列出当前可用项，之后的步骤不再执行。一个交互在多个目标上都可用时必须写 `target`。`expect` 写 `started`、`notStarted` 或 `status`，结果以 ✔/✘ 逐条报告。

## 5. 改动标记

透视结果会规范化为一份条目快照，比较的是内容而不是 JSON 文本，所以 AI 只改了缩进或格式不会出现标记。

- **默认基准**是你上次点“已看过”时的快照。打开或关闭窗口、AI 通过 CLI 读取，都不会移动基准，避免你没看完标记就消失。
- **对比点**：在窗口顶栏输入名字，点“存对比点”；之后可在“基准”下拉里选它，一起检查攒了几轮的改动。
- 改动按条目标出：新增、删除，以及字段变化（例如条件新增了“时段是傍晚”）。

从未点过“已看过”时没有基准，窗口和 `lens view` 都不标改动；第一次查看后点一次“已看过”，之后的改动才会被标出。

## 6. 待改清单与让 AI “按清单改”

在任意条目的详情里写一句“想改这里”，它就进入待改清单。每条记录包含你的原话、条目在游戏里的叫法、精确位置（文件加 JSON Pointer，或脚本文件、hook 与条件标签）和创建时的当前值。

AI 改完后，如果该条目的内容变了，清单上显示“已改动，待确认”。**条目只能由你在窗口里关闭**，AI 不能关闭或修改它。

AI 不能运行命令行时，在待改清单页点“复制给 AI”，把待改和已改动待确认的条目（id、原话、条目叫法、位置、创建时的值、状态）复制成文本贴给它；文本里写明 AI 不能关闭条目。复制成功或失败都会在按钮旁提示。

对 AI 说“按清单改”时，它会：运行 `lens requests` 读清单；逐条修改；运行 `validate`；为相关条目写或复用推演脚本并运行 `lens simulate`；交付说明逐条对应清单 id。

## 7. 让条件可读

自动开始条件建议写 `[标签, 布尔值]`，详见[活动与变量](activity-and-variables.md)。没有标签的条件在透视里只显示“条件 2：✘”。

## 9. 已知限制

- 只读：不能在窗口里编辑包。
- 不翻译脚本代码；说明文字只来自你写的标签和运行时实际算出的结果。
- 不会自动从当前状态分叉去试跑每个选项，只有你选过的才显示效果。
- “复制给 AI”只是备用：它把当时的待改与已改动条目复制成文本，不会随包变化更新；能运行命令行的 AI 仍应通过 `lens requests` 读取。
- 活动操作的参数结构较复杂（超出字符串、数字、布尔、枚举）时，窗口提示改用推演脚本填写。
- 只支持当前 `worldpack-source/v5`。
- 编译只读取清单列出的文件，没有为 `.perspectra-lens/` 另做忽略；该目录已列入仓库 `.gitignore`，打包时是否带走未专门验证。
