# 玩家试玩指南

本指南同时记录 Windows x64 test3 便携候选包与当前源码 Tauri Launcher；标为“当前源码”的新增功能未必包含在 test3。下述多连接和角色模型选择属于当前源码，旧包仍使用原有模型配置。候选 ZIP 的下载与版本说明见 [README](../../../README.md)，独立说明见 [测试包说明](../../../scripts/release/README.zh-CN.md)。

## 1. 配置并开始

1. 整体解压，保留 `Perspectra.exe` 同目录的 `runtime`。首次加载后包路径需要继续可用，先选好长期存放位置。
2. 当前源码：点右上角 ⚙ 打开设置窗口，在“模型接口”添加连接：起个名字，选择 OpenAI、Anthropic 或 Google 协议，填写完整请求地址和必要的 API Key，点“保存连接”。见[模型接口协议](../model-protocols.md)。（test3 是单个“模型设置”对话框，直接填地址、模型和 Key。）
3. 在这条连接上点“查看模型”确认能拿到列表，再点“测试连接”。测试会实际调用一次模型，只证明接口能响应，不保证游戏的 JSON 协议或角色效果。然后点主界面的模型标签（或“⋯ → 模型”）为实例选模型。
4. 加载 `examples/大模型变成美少女了`，校验后导入，创建实例并开始游戏。源码仓库对应 `examples/world-packs/model-girls-official`；基础示例另见 `examples/前室与后室` 和 `examples/测试示例`。
5. 在系统浏览器中游玩，Launcher 保持独立窗口。普通发言、移动、物品与角色交互都以当前页面提供的选项和提交结果为准。

每个实例有独立进度和独立的模型选择。新实例沿用你最近一次保存的选择；修改已有实例请在本局抽屉的“模型”里改。当前源码中游戏运行时也可以修改模型、预设和运行参数，抽屉会提示“修改将在下次启动游戏时生效”，当前这局不受影响。

当前源码可给重要角色换强模型：例如默认选 Flash，在本局抽屉“模型 → 按角色单独设置”取消 Claude 的“跟随默认”，再选另一连接的强模型及思考强度。记忆整理默认跟随该角色决策；需要节省整理成本时，可取消“记忆整理跟随该角色的决策模型”，另选便宜模型。其他角色沿用默认配置，主界面模型标签显示单独配置的角色数。未配置角色覆盖时，默认记忆也可独立选择；角色覆盖不会自动继承默认层另选的记忆模型。保存并重新启动生效。模型连接及本轮角色覆盖尚未重建到既有 test3 发行包。

API Key 按连接保存在 Windows 凭据管理器，重启后不用重填；在连接的“编辑”里可以修改或清除。不要放进游戏包、截图、预设或公开反馈。源码启动和便携包的依赖不同，普通测试包玩家不用安装 Rust、Node 或 Python。

### 官方试玩包

点击“开始序章”，再点“继续”或快进；112 条正式表达包含 5 条中性玩家问题。序章结束后自己决定是否收留角色，可以拒绝、离开或改变话题。自由阶段需要真实模型；生活事件从活动菜单进入，事件条件与后续行动仍依照角色在场、物品状态和规则裁定。

试玩包底部输入框的受众按钮可选公开、定向、私密或仅自己；定向/私密选择在场接收者。发送后显示加载状态，已提交的角色回应可先显示；达到预算或截止后停止本轮处理，保留已提交回应。点击历史图标查看玩家有权看到的 Galgame 式记录，不能读取其他角色私密历史。

模型配置可选择关闭、低、中、高思考强度；部分 Gemini 不支持关闭。运行参数默认 120 秒反应期限，思考强度不会自动延长它。参数修改在下次启动生效。

## 2. 日常游玩与恢复

当前源码的官方界面左侧显示场景与可用交互，右侧显示对话；活动面板在左下角。主输入框用于发言，展开“细节描写”可补充动作、神态或语气，两项统一发送，任一项可留空（合计最多 2000 字符）。描写是角色可观察的外显表现，不是私密心理；移动和物品转移仍使用规则提供的操作。窄屏下优先显示对话，卡片排列在下方。test3 已包含此界面。

普通交谈和叙事允许自由表达。需要追踪的物品转移、移动和受控交互由规则裁定；角色说“已经发生”不等于数据库已提交。发现台词与实际状态矛盾时，请记录上下文反馈。

模型调用中等待本次操作结束，避免重复点击。同一次失败可能已经提交玩家行为、但尚未完成 NPC 反应；先看公开历史和当前场景，再使用页面提供的重试。错误提示表示调用或规则问题，不一定是玩家输入不清楚。

活动中的“重试”用于恢复可继续的角色机会，“逃生”用于退出受控活动，不会撤销此前已提交的世界事实。社区前端卡住时可使用宿主的官方界面入口；停止后重新开始会继续当前线路，而非开新游戏。

当前源码另支持多个独立活动：当次角色处理结束后点“暂停”，保留进度并恢复自由互动；再选择另一场活动，之后点“继续”返回原玩法。恢复条件不满足时保留进度，可回到合适地点再试，或“放弃”该场暂停进度后重新开始。一次只运行一个，暂停期间不自动推进。“再次请求角色处理”与继续暂停活动不同。这些新增控制尚未包含在已有 test3 包中，参照[多活动示例](../../../examples/world-packs/multiple-activities/README.md)。

Launcher 使用 Core 记忆。游戏页顶部“游戏工具”可后台整理长期记忆，也可重载或切换官方界面；“中止活动 / 恢复”保留在菜单外。整理长期记忆涉及额外模型调用，可以后台运行、取消或失败后再试；整理完成前近期上下文仍可使用。模型表现和召回质量需要实际试玩判断。

### 重新生成最近一回合（当前源码）

等待当次玩家操作和角色处理结束，点击最后一条回复下方的刷新图标。程序从相同起点与输入生成新候选，自动选中，并保留此前结果。使用旁边的 ‹ 1/3 › 箭头切换；回复、世界状态、认知与活动结果一起恢复，切换不调用角色模型。生成期间可点击“停止”取消；失败或切换前取消保留当前选择。社区模板未提供这些按钮时，使用宿主顶部刷新与候选工具。

连续重新生成会复用同一起点，从任意已有候选刷新都会追加新候选。提交下一次操作后以当前选择继续，上一组停止切换；新回合从一个候选开始。没有保存起点的旧回合、暂停未完成的回合或环境不兼容的回合不支持此操作。此功能与活动“重试”、完整节点分叉不同；test3 已包含此功能。详见[重新生成说明](../tail-round-regeneration.md)。

## 3. 角色预设

在当前实例“角色预设 → 修改”中设置。全局默认可复用到多个实例，包推荐作为作者建议，实例可自定义。采用包推荐时，以全局字段打底，再由包明确设置的字段覆盖；仅用全局模式忽略包推荐。

实例内优先级是 **角色专属 > 角色组 > 实例默认**。每个角色最多属于一个实例内组，组只映射预设。专属或组配置替换下层配置，未填生成参数使用 Core 默认值，不逐字段继承下层。关闭专属或取消分组可恢复下层选择。

可调整附加提示、常用生成参数、原生提示节点、宏和文本规则；预览是配置展开结果，不证明模型一定遵从。参数也取决于模型服务，过低输出上限或停止词可能截断 JSON。预设不能替换 Core 输出协议、角色认知权限或规则裁定。

预设库可保存、导入和导出 Perspectra 原生配置；应用时复制到当前编辑范围，再保存生效，修改库内容不会自动更新已应用的配置。Launcher 里不能直接导入酒馆预设；源码仓库可先用 `corepack pnpm@11.7.0 preset:import` 离线转换成原生格式再导入。本机如保留 `preset/native-writing-suite.json`，其中的“极简 · 自然对白”“叙事质量 · 完整”“阶段规则 · 观察用”三份原生预设仍可导入预设库；`preset/` 已被 Git 忽略，不随源码分发。Assistant Prefill 与自定义上下文模板尚未接入。角色/组编辑先保存当前实例，取消会丢弃草稿；全局默认单独保存。修改后重新启动生效。详见 [预设说明](../model-presets.md)。

## 4. 保存、故事线与分叉

当前线路已提交的游玩进度保存在实例目录；“完整节点”是供未来分叉使用的快照，二者不是一回事。

1. 保持游戏运行，等待玩家动作和 NPC 调用完成；NPC 暂停时先处理失败。
2. 当前源码：在游戏页面顶部工具栏点“保存进度”，可填节点名，留空则用“保存于 时:分”。活动可以进行中，但当次操作须已提交；角色仍在行动时会提示稍后再试。test3 仍在 Launcher“故事线 → 管理”里保存。
3. 结束游戏，在本局抽屉“存档”里选择完整历史节点并创建新故事线，然后开始新线。
4. 首次启动恢复节点当时的角色记忆和授权经历，不额外调用模型整理。旧节点缺少长期档案时保留节点内原始经历。失败可重试；原线保留。
5. 切回原线继续原线最新进度，不会把原线回退到分叉节点。

历史列表只列真实保存的完整节点，不保证每一轮都能恢复。完整树分享、线路合并、跨设备自动同步和跨包升级未接入；Storyline 当前提供存档与分叉，不是剧情阶段追踪引擎。详见 [故事线边界](../storylines.md)。

### 分享完整节点（2026-10-15 源码版）

1. 当前源码：想分享最新进度，先在游戏页面“保存进度”，再到本局抽屉“存档 → 导出存档”选择该节点；Launcher 不再提供“保存当前进度并导出”。
2. 从“存档 → 导出所选节点”进入时沿用已选节点。该节点可能早于当前进度，核对标题、时刻与保存时间后保存 `.perspectra-story` 文件。只导出这一节点，不携带其他恢复节点或分叉树。
3. 接收者先载入内容完全相同的游戏包，结束当前游戏，点击“导入存档”，选择文件并填写新实例名称。
4. 导入不会覆盖已有实例；首次开始恢复节点内各角色当时的长期档案与授权原始经历，不额外调用模型整理；没有档案的角色使用授权原文。后续整理按正常阈值进行，使用接收者自己的模型配置。
5. 若保存成功但导出失败，完整节点仍在列表中，可选择它重试；不会用更早节点冒充刚刚的进度。

分享文件包含截至节点的历史、角色私密状态和长期档案，接收者能查看这些内容。它不包含游戏包、密钥、模型配置和请求日志。文件损坏、游戏包不同、长期档案来源或前缀不符，或超过当前限制会拒绝导入。test3 已包含旧版单节点分享；上述入口与长期档案传递需要本次源码构建，不能据此认为旧便携包已更新。

## 5. 社区前端与授权

没有自定义前端时使用官方默认界面；社区前端默认运行在 iframe 沙箱。需要网络和浏览器存储时，由玩家在 Launcher 明确确认受信任模式，授权绑定当前实例与实际前端内容。文件变更后需重新检查授权；不要把一次确认视为今后所有版本的许可。

> 受信任前端访问的远程内容可以在不改变游戏包摘要的情况下发生变化。

受信任模式仍不能读取 Core 令牌、模型密钥、私有接口和角色私密上下文。静态前端资源本身可能公开读取，作者不得放秘密。授权记录可撤销；运行中撤销会回到官方沙箱界面，保留游戏进度并阻止社区继续提交。切换模式按 Launcher 提示停止并重新开始。详见 [前端授权](../frontend-authorization.md)。

## 6. 常见问题与备份

| 现象 | 建议 |
| --- | --- |
| 连接失败或模型不存在 | 确认服务已启动、完整地址与模型标识正确；再测试连接 |
| 连接通过但游戏格式失败 | 检查服务是否支持约定的结构化输出，降低预设干扰；保留错误，不反复提交玩家操作 |
| 提示游戏包内容已变化 | 不覆盖旧存档；保留原包，更新内容使用新实例，当前无自动迁移保证 |
| 分叉恢复失败 | 保留原线和节点，核对游戏包及完整存档；恢复本身不需要模型整理 |
| 页面失去连接 | 确认 Launcher 中实例仍运行，重新打开当前游戏；不用旧 token 地址推断当前服务仍在 |
| 无法保存节点 | 等当次调用结束并处理 NPC 暂停；以 Launcher 返回的明确原因处理 |

在设置中查看实际数据目录。备份前结束游戏并退出 Launcher，再复制整个实例/数据目录，同时保留对应原游戏包。不要只拷贝运行中的 SQLite 主文件，也不要上传完整存档：其中可能含角色秘密。

反馈请附版本、包、前端模式、模型、复现步骤、预期和实际结果及脱敏错误；不要公开 API Key、带 token 的地址、原始模型请求或角色私有日志。[反馈模板](../../../scripts/release/feedback-template.zh-CN.md)。当前仍待干净 Windows、长时稳定性等发行验收，见 [候选包记录](../studies/launcher-portable-test3-20261009.md)。

### 启动器全局设置

右上角 ⚙ 打开设置窗口：“模型接口”管理连接、认证和查看可用模型（修改立即保存）；本局抽屉的“模型”为当前实例选模型。
“外观”提供浅色、深色、跟随系统主题、主题色和较大文字；外观、阅读与声音点“应用”或“保存”后生效，“取消”丢弃未应用的修改。设置保存在当前数据目录，重启可恢复。

全局设置显示当前数据根目录与实例目录，并支持打开文件夹。配置与预设保存在根目录的 `launcher.json`、`preset-settings.json`、`preset-library.json`；实例、故事线、存档与角色记忆保存在 `instances` 下；载入的游戏包留在原始位置。

停止游戏后可选择独立的空目录或已有 Perspectra 数据目录。目录选择立即保存，重启后生效；旧目录保留，不自动迁移。空目录显示新的游戏库，原有数据可通过重新选择旧目录后重启访问。重启前再次选择当前目录可取消切换。若设置了 `PERSPECTRA_LAUNCHER_DATA_DIR`，它优先于目录选择，需要修改环境变量后重启。

### 包级运行参数与游戏阅读偏好

本局抽屉“运行参数”可调整玩家输入与角色发布字符上限、反应波次与调用预算、请求/激活/周期超时，以及高级区的 Activity 和 Core 记忆预算。设置按当前包保存，作用于该包所有实例的下一次启动；游戏运行中修改也只在下次启动生效。恢复默认值后仍需点击保存，取消会丢弃草稿。它不修改作者规则或已提交世界事实。

玩家发言和细节描写合计使用输入字符上限；角色发布字符上限与预设的模型输出 Token 是不同限制。较短的外层时限会先终止处理，增加请求超时不等于增加整个反应周期时间。每角色次数统计激活机会，一次激活可能多次调用模型；Activity 独立于普通反应预算。

记忆 Token 为本地估算；单批整理和近期保留目标必须小于触发阈值。降低触发阈值可适配较小上下文模型，但可能增加整理频率与费用。长期记忆交付数量/体积只调整召回预算，不放宽角色认知隔离。

设置窗口“阅读与声音”中的“默认前端阅读偏好”可调对话字号、行距和自动跟随。下次游戏启动生效；社区前端可自行选择是否采用。完整默认值、范围与边界见[游玩参数说明](../launcher-play-settings-audit.md#8-本轮实现)。此前便携包需要重新构建才包含该入口。

全局设置的“主题色”可在樱色（默认）、灯火、月夜、森林之间切换，应用后立即作用于启动器；官方游戏舞台在下次启动游戏时换色。创作者页面固定使用深色与默认配色。


## 玩家发言范围

默认前端的发送区提供四种范围：公开（在场且有权观察的角色收到完整内容）、定向（仅指定角色收到，旁观者不收到观察）、私密（仅指定角色收到内容，旁观者只知道发生了私密交流）、仅自己（不向其他角色传播）。对白和可选细节描写共用所选范围。

定向或私密发言需选择接收对象，列表只包含当前可见角色。场景变化使对象离场时，选择会清空，需重新选择；没有可接收角色时不能发送这两种发言。后端也会核验当前接收资格，不接受隐藏角色或过期对象。发送效果预览说明本次投递范围，发送按钮会实际提交消息。

本功能位于默认游戏前端；世界包自带的自定义前端需自行接入 `speak` 的 `scope` 和 `addresseeIds` 字段。自然语言中的“悄悄说”不会自动改变受众范围。仅自己指世界内角色的投递隔离，不表示这段表达不进入本机存档。


NPC 发布也可选择上述四种范围：`publish` 接受 `segments`、可选 `scope` 和 `addresseeIds`。`direct` / `private` 必须指定当前可见的其他角色，`scene_public` / `self` 不指定接收对象。同次发布的所有对白与叙述片段共用范围；行动后续写也可以选择。没有其他可见角色时，只提供公开和仅自己。未填写范围时，有接收对象默认为定向，否则默认为公开。预设文本转换保留受众，不改变角色自己的选择。私密交流的发生观察可触发旁观者反应，但不会携带内容；仅自己不向其他角色投递刺激。
