# 玩家试玩指南

适用于当前 Windows x64 便携候选包与真实 Tauri Launcher。当前候选 ZIP 尚未上传为 GitHub Release 附件；下载状态以 [README](../../../README.md) 和实际 Release 为准。已有候选包的独立说明见 [测试包说明](../../../scripts/release/README.zh-CN.md)。

## 1. 配置并开始

1. 整体解压，保留 `Perspectra.exe` 同目录的 `runtime`。首次加载后包路径需要继续可用，先选好长期存放位置。
2. 打开“全局设置”，填写 OpenAI 兼容的完整 `.../v1/chat/completions` 地址、模型标识和必要的 API Key。
3. 点击“测试模型连接”，成功后应用设置。测试会实际调用一次模型，只证明接口能响应，不保证游戏 JSON 协议或角色效果。
4. 加载 `examples/启动器演示`，校验后导入，创建实例并开始游戏。源码仓库对应 `examples/world-packs/launcher-demo`。
5. 在系统浏览器中游玩，Launcher 保持独立窗口。普通发言、移动、物品与角色交互都以当前页面提供的选项和提交结果为准。

每个实例有独立进度。全局模型配置用于创建实例；修改已有实例的模型请进入该实例的模型配置，不能只改全局后假定旧实例已更新。运行期间先结束游戏，再修改模型或预设并重新开始。

API Key 只在当前 Launcher 会话内保留，退出后重新填写。不要放进游戏包、截图、预设或公开反馈。源码启动和便携包的依赖不同，普通测试包玩家不用安装 Rust、Node 或 Python。

## 2. 日常游玩与恢复

普通交谈和叙事允许自由表达。需要追踪的物品转移、移动和受控交互由规则裁定；角色说“已经发生”不等于数据库已提交。发现台词与实际状态矛盾时，请记录上下文反馈。

模型调用中等待本次操作结束，避免重复点击。同一次失败可能已经提交玩家行为、但尚未完成 NPC 反应；先看公开历史和当前场景，再使用页面提供的重试。错误提示表示调用或规则问题，不一定是玩家输入不清楚。

活动中的“重试”用于恢复可继续的角色机会，“逃生”用于退出受控活动，不会撤销此前已提交的世界事实。社区前端卡住时可使用宿主的官方界面入口；停止后重新开始会继续当前线路，而非开新游戏。

Launcher 使用 Core 记忆。整理长期记忆涉及额外模型调用，可以后台运行、取消或失败后再试；整理完成前近期上下文仍可使用。模型表现和召回质量需要实际试玩判断。

## 3. 角色预设

在当前实例“角色预设 → 修改”中设置。全局默认可复用到多个实例，包推荐作为作者建议，实例可自定义。采用包推荐时，以全局字段打底，再由包明确设置的字段覆盖；仅用全局模式忽略包推荐。

实例内优先级是 **角色专属 > 角色组 > 实例默认**。每个角色最多属于一个实例内组，组只映射预设。专属或组配置替换下层配置，未填生成参数使用 Core 默认值，不逐字段继承下层。关闭专属或取消分组可恢复下层选择。

可调整附加提示、常用生成参数、原生提示节点、宏和文本规则；预览是配置展开结果，不证明模型一定遵从。参数也取决于模型服务，过低输出上限或停止词可能截断 JSON。预设不能替换 Core 输出协议、角色认知权限或规则裁定。

预设库可保存、导入和导出 Perspectra 原生配置；应用时复制到当前编辑范围，再保存生效，修改库内容不会自动更新已应用的配置。不能直接导入酒馆预设。Assistant Prefill 与自定义上下文模板尚未接入。角色/组编辑先保存当前实例，取消会丢弃草稿；全局默认单独保存。修改后重新启动生效。详见 [预设说明](../model-presets.md)。

## 4. 保存、故事线与分叉

当前线路已提交的游玩进度保存在实例目录；“完整节点”是供未来分叉使用的快照，二者不是一回事。

1. 保持游戏运行，等待玩家动作和 NPC 调用完成；NPC 暂停时先处理失败。
2. 在“故事线 → 管理”命名并保存完整节点。活动可以进行中，但当次操作须已提交。保存会等待后台写入退出。
3. 结束游戏，选择完整历史节点并创建新故事线，然后开始新线。
4. 首次启动新线按节点以前各角色获准知道的经历重建记忆，可能等待并产生模型费用。失败可重试；原线保留。
5. 切回原线继续原线最新进度，不会把原线回退到分叉节点。

历史列表只列真实保存的完整节点，不保证每一轮都能恢复。分享、线路合并、跨设备同步和跨包升级未接入；Storyline 当前提供存档与分叉，不是剧情阶段追踪引擎。详见 [故事线边界](../storylines.md)。

## 5. 社区前端与授权

没有自定义前端时使用官方默认界面；社区前端默认运行在 iframe 沙箱。需要网络和浏览器存储时，由玩家在 Launcher 明确确认受信任模式，授权绑定当前实例与实际前端内容。文件变更后需重新检查授权；不要把一次确认视为今后所有版本的许可。

> 受信任前端访问的远程内容可以在不改变游戏包摘要的情况下发生变化。

受信任模式仍不能读取 Core 令牌、模型密钥、私有接口和角色私密上下文。静态前端资源本身可能公开读取，作者不得放秘密。授权记录可撤销；运行中撤销会回到官方沙箱界面，保留游戏进度并阻止社区继续提交。切换模式按 Launcher 提示停止并重新开始。详见 [前端授权](../frontend-authorization.md)。

## 6. 常见问题与备份

| 现象 | 建议 |
| --- | --- |
| 连接失败或模型不存在 | 确认服务已启动、完整地址与模型标识正确；再测试连接 |
| 连接通过但游戏格式失败 | 检查服务是否支持约定的结构化输出，降低预设干扰；保留错误，不反复提交玩家操作 |
| 提示游戏包内容已变化 | 不覆盖旧存档；保留原包，更新内容使用新实例，当前无自动迁移保证 |
| 分叉启动较慢或记忆重建失败 | 等待整理；确认模型可用后重试，不删除原线或数据库 |
| 页面失去连接 | 确认 Launcher 中实例仍运行，重新打开当前游戏；不用旧 token 地址推断当前服务仍在 |
| 无法保存节点 | 等当次调用结束并处理 NPC 暂停；以 Launcher 返回的明确原因处理 |

在设置中查看实际数据目录。备份前结束游戏并退出 Launcher，再复制整个实例/数据目录，同时保留对应原游戏包。不要只拷贝运行中的 SQLite 主文件，也不要上传完整存档：其中可能含角色秘密。

反馈请附版本、包、前端模式、模型、复现步骤、预期和实际结果及脱敏错误；不要公开 API Key、带 token 的地址、原始模型请求或角色私有日志。[反馈模板](../../../scripts/release/feedback-template.zh-CN.md)。当前仍待干净 Windows、长时稳定性等发行验收，见 [候选包记录](../studies/launcher-portable-release-20261007.md)。
