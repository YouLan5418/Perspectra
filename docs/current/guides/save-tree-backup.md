# 整个存档实例的备份与恢复

你在共同起点分出两条故事线，一条留下护盾，另一条留下持续伤害；备份后换一个数据目录，仍能选回各自的旧节点继续。Launcher 的「故事线与存档」现在提供「备份整个存档实例」和「恢复备份」。原来的 `.perspectra-story` 仍然只分享一个节点，不承担整树备份。

## 操作

1. 先在游戏中「保存进度」，再打开 Launcher 的「故事线与存档」。备份只包含已发布保存节点，不包含运行中目录、未保存尾巴或孤立临时目录。
2. 点「备份整个存档实例」，选一个新的 `.perspectra-backup` 文件名。不覆盖已有备份。
3. 在另一份 Launcher 数据目录载入**内容完全相同**的游戏包，点「恢复备份」，填写新实例名并选择文件。已有实例不变；重复恢复产生另一个独立实例。
4. 恢复保留当前所选线路、全部保存节点与叉点。没有独立保存头的线路保留为线路，起点是它已保存的叉点，未保存进度不带走。选线路后，可从该线路的任一可达旧节点分叉。

备份包含世界历史、角色私密信息、玩家已经获知的内容、身份历史、长期记忆及玩法状态，**不宜当分享包**。它不带游戏包、模型配置／凭证、请求检查日志或 Context 诊断数据库。接收者继续游戏使用自己的本机模型设置。文件选择取消不执行操作；开始后等待校验和写入，关闭启动器可能中断。未写入 Launcher 索引的实例不出现在列表，原数据不变，可重新恢复。

## 格式和界限

版本 1 是有界 JSON 容器，`kind: perspectra-save-tree`、`version: 1`，含 `tree`、`nodes`、`objects`。清单保留线路与节点 ID（新实例 ID 独立生成），节点的字面文件名引用 SHA-256 对象。对象只保存一次，每个节点的完整恢复不依赖其他备份、原机或从根重放。

白名单为 `world.sqlite`、`session.sqlite`、`memory-aliases.json`、`core-memory.json`、`plugin-set.json`。去重单位是文件内容；未变的记忆档案文件可共用对象。即使剧情一样，SQLite 租约记录或页布局不同也可能产生不同对象；本版没有 SQLite 页级增量、角色档案内部切块或语义去重。恢复时展开为节点自己的完整文件，不共享可写硬链接。

上限：64 条线路、256 个节点、1280 个对象；单对象 64 MiB，唯一对象总计 192 MiB，节点逻辑文件展开总计 512 MiB，JSON 容器 260 MiB。运行目录另复制各线路的保存头，最坏磁盘需求还包括这些头和一个节点的校验副本。超过限制明确失败，不截断线路。解码为内存对象，峰值内存高于文件体积；不适合超大存档树。

主线没有保存节点时不能备份。版本 1 要求节点含完整的五文件清单、记忆提供者及插件记录；历史实验节点缺少这些字段时明确拒绝。不能通过篡改兼容性记录把未知提供者当作已支持插件。当前只支持 `official-memory-core` 与 `official-memory-none` 的 `1.0.0` 档案契约，未知记忆提供者不能导入。玩法沿现有内容包编译和 `supportedDataVersions` 校验，不复制插件代码。

## 正确性与清理

- 单节点原有校验函数 `validateStorySnapshot` 在可丢弃副本上检查 World／Session 投递配对、完整性、静止时点、包内容和玩法兼容性。不会改写原节点。
- Core Memory 导入校验角色、世界、提供者、实际授权 Sources 前缀及身份历史；相同 `headSeq` 不能证明相同经历。无模型 importer 保留保存时的档案原文，不 Build，不取原线路当前记忆。
- World／Session 中已提交事实、玩家已知内容及裁定记录（包括已决定的随机／模型结果）保留。`memory.sqlite` 的授权原始 Sources 可从该节点事实重建；Context 诊断和请求检查文件不携带。重新打开仍会执行正常的运行时兼容检查。
- 引用、重复 ID、缺失父节点、循环、跨线不可达叉点、文件白名单、哈希、尺寸均先校验。另逐节点比较实际事件前缀，不能只用父 ID 和序号伪造祖先。已有节点关系与实际事实历史不一致时拒绝备份，不自行修树。
- 导出使用同目录临时文件与不覆盖的原子发布（目标文件系统须支持硬链接；不支持时失败，原文件不变）；恢复先在隐藏临时目录验证全部节点，然后生成各线路的运行头，再公布目录，最后原子替换 Launcher 索引。失败正常清理；索引写入失败删除本次新目录。
- 强杀进程可能留下隐藏临时目录；极窄的目录公布／索引写入间隙可能留下未索引目录。它们不会列入实例或后续备份，不会覆盖用户数据。当前不自动清扫，以免误删另一个进程的工作；人工清理须确认无恢复操作运行。本批保证进程中断边界，不承诺断电后的文件系统持久性。
