# 创作者：跑团玩法

2026-11-09 当前源码（分支 `feat/rpg-plugin`）：官方跑团机制 [official-trpg](../../../packages/official-trpg) 按世界包里的 `trpg.json` 生成一个叫 `trpg` 的活动：玩家请一名 AI 角色当主持人，其余角色保留各自的性格参与。验证范围分开看：

- **源码已接通**：配置校验、活动脚本（筹备、邀请、提出行动、检定、主持人工具、聚光、结束）、可信掷骰、私密点数进记忆、宿主载入与存档摘要、包透视与 `worldpack validate`。
- **自动测试范围**：上述各项有单元测试和真实宿主测试，见第 7 节；验收包 [雨夜古宅](../../../examples/world-packs/rainy-manor/README.md) 的三份推演通过。
- **真实体验验收**：只有一次 GLM-5.3-Flash 的脚本化试玩（两局，玩家一方是脚本），见[雨夜古宅试玩记录](../studies/2026-11-09-rainy-manor-playtest.md)。主持人都接下了，7 次检定的讲述都和点数一致；但主持人几乎只用说话讲结果、很少用“宣布结果”，于是待处理行动堆积，聚光几乎不转。此后改为：有待处理行动时，主持人说出结果也算一次宣布（自动测试覆盖，尚未重新试玩）。没有真人试玩。
- **发行包**：未重建，随程序发行的是否包含此机制以发行说明为准。

## 1. 一个例子

客厅里有玩家、澄和阿茹。玩家打开“跑团”，勾选阿茹和澄，再指定阿茹当主持人、选作者写好的剧本《雨夜古宅》。阿茹自己决定接不接；接下之后，玩家和澄读到开场：“雨夜，你们的车坏在一座古宅门口……”

玩家说：“我想撬开书房的门。”阿茹判断需要检定，要求“敏捷检定，难度 12”。程序掷出 d20 = 9，加上玩家的敏捷修正 +2，总值 11。这组点数只有玩家和阿茹知道；澄和别的参与者只看到“玩家进行了一次敏捷检定”。阿茹随后宣布：“门锁卡住了，撬棍发出一声刺耳的响动。”这句全体参与者都看得到，澄出于自己的性格接了一句“你小声点！”。阿茹还可以掷一次暗骰，判断管家有没有听见，点数只记进她自己的笔记。

一局结束，回到客厅，三人都记得“我们玩了一局跑团，玩家在古宅里撬门时出了声”，没有人以为主世界里真有一座古宅。没参加这一局的梅看不到活动面板、点数和主持人的秘密，也听不到玩家在局内说的话；但阿茹和澄在局内说出口的话，坐在同一间客厅的梅听得见。

哪些由程序保证，哪些由角色决定：点数由程序掷出，写进提交的事件，只发给该看的人；暗骰不出现在公开部分；主持人的私密笔记和“只有主持人知道”的内容别人读不到。检定要不要做、难度多少、结果怎么宣布、故事往哪里走，由主持人这个角色自己决定，程序不检查宣布的结果和点数是否一致。参与者说什么、做什么，也是各自的决定。

完整的可运行例子是[雨夜古宅](../../../examples/world-packs/rainy-manor/README.md)，下面的字段以它的 [trpg.json](../../../examples/world-packs/rainy-manor/trpg.json) 为例。

## 2. 它怎么接入

- 在 `worldpack.source.json` 的 `assetFiles` 里登记 `trpg.json`。没有登记的世界里没有跑团。
- 宿主打开世界时读 `trpg.json`，生成一个活动（键 `trpg`），不写回包目录。代码入口：[配置解析](../../../packages/official-trpg/src/config.ts)、[内容生成](../../../packages/official-trpg/src/content.ts)、[活动脚本](../../../packages/official-trpg/src/runtime/trpg.js)；取舍见[决策记录](../../superpowers/specs/2026-11-08-trpg-decisions.md)，设计见[跑团活动设计](../../superpowers/specs/2026-11-08-trpg-activity-design.md)。
- 包里不能再有叫 `trpg` 的活动，重名会拒绝。包里必须有玩家角色。
- 程序没有跑团机制或版本不同，包在世界创建前就失败（和 `rpg.json` 一样的提示）。没有 `trpg.json` 的包行为不变。
- 点数来自官方骰子机制 `official-dice`，活动脚本在 `resolve` 里用宿主注入的 `rollDice` 取数。需要自己写别的活动用骰子时，见[活动与状态](activity-and-variables.md)。

## 3. 一局怎么进行

1. **开局**：玩家从在场的 AI 角色里勾选参与者（1 到 8 人）。没被选上的角色留在局外：看不到活动视图、检定、笔记和局内内容，也听不到玩家在局内说的话；但 AI 参与者（包括主持人）在局内说的话按普通发言公开给同场的人，局外角色听得见。
2. **筹备**：玩家指定主持人（必须是参与者里的 AI 角色，玩家自己不能当主持人；`hosts` 写了名单就只能从名单里选），再选一个剧本，或者选/写一个题目，二选一。
3. **邀请**：被选中的主持人用自己的回合接受或拒绝。拒绝后回到筹备，玩家可以另选一人，或者结束。接受后，每名参与者收到开场（剧本的 `opening`，题目局则是“题目：……”）。
4. **进行**：参与者说话，或者用“提出行动”写下一句行动，进入待处理队列（最多 8 条）。主持人得到一次处理机会，用下面的工具推进。
5. **结束**：主持人或玩家随时可以结束，结局文字至多 500 字。主持人的权限随这一局一起结束。

主持人的工具（只有主持人看得到）：

| 工具 | 作用 |
| --- | --- |
| `check` 要求检定 | 指明对象、技能、难度、是否暗骰。程序掷骰：骰子结果加该参与者在这项技能上的修正，不小于难度就成功。点数只告诉对象和主持人，公开部分只出现“某人进行了一次某某检定”。暗骰没有对象，只有主持人知道 |
| `announce` 宣布结果 | 全体参与者可见，同时处理掉最早一条待处理行动。有待处理行动时，主持人直接说出结果也算一次宣布，效果相同（说的话记为最近结果）；没有待处理行动时，主持人说话不处理行动，也不轮转聚光 |
| `note` 写笔记 | 公开笔记全体参与者可见，私密笔记只有主持人读得到；可追加或整段替换，各至多 6000 字 |
| `set-stat` 改数值 | 改某名参与者角色卡上的一项数值，0 到上限 |
| `content` 局内内容 | 新建或修改局内地点、物品、NPC；可以标成只有主持人知道。至多 60 项 |
| `end` 结束 | 结束本局 |

聚光：每次主持人宣布之后（用 `announce`，或在有待处理行动时说出结果），其余 AI 参与者按顺序轮流得到一次处理新情况的机会（例子里的澄）；她可以说话、提出行动，也可以弃权，弃权就停下来，等下一次玩家行动。程序只给机会，不规定她做什么。

主持人用错工具（对象不存在、数值越界、笔记超长等）：状态不变，只有主持人自己读到原因，并再得到一次机会，次数有上限。

## 4. 字段手册

所有对象里不认识的字段都会报错并写出路径。

### plugin
`{ "id": "official-trpg", "version": "1" }`，固定写法。

### sheet：角色卡模板
```json
"sheet": {
  "stats": [{ "key": "hp", "label": "生命", "max": 10 }, { "key": "sanity", "label": "理智", "max": 10 }],
  "skills": [{ "key": "agility", "label": "敏捷", "modifier": 0 }, { "key": "observe", "label": "观察", "modifier": 0 }],
  "dice": "d20"
}
```
- `stats`：1 到 8 项数值。`key` 小写字母开头，只含小写字母和连字符，至多 32 字符；`label` 显示名至多 36 字；`max` 是 1 到 1000 的整数，也是初值。
- `skills`：1 到 12 项技能。`key` 规则同上；`label` 至多 36 字；`modifier` 是 -100 到 100 的整数，检定时加在骰子点数上。
- `dice`：掷骰写法，和官方 `official-dice` 完全相同：`d20`、`d100`、`2d6+1`。个数 1 到 20（可省略），面数 2 到 1000，修正 ±1000，不能有前导零，也不能写 `+0`。校验配置时用的是这个语法的副本，改骰子语法的一方必须同步另一方，由 `tests/host/trpg-dice-agreement.test.ts` 核对。

### characters：个别角色的卡面
```json
"characters": { "character:cheng": { "stats": { "sanity": 7 }, "skills": { "agility": 3, "observe": 1 } } }
```
可选。键必须是包里的 AI 角色（不能写玩家）。`stats` 的值在 0 到该项上限之间，`skills` 的值在 -100 到 100 之间，都只写和模板不同的项。**玩家没有预设卡面，用模板的默认值。**

### hosts：主持人候选
`"hosts": ["character:aru", "character:mei"]`。可选，1 到 8 个 AI 角色。不写时，参与的任何 AI 角色都可以当主持人。

### scenarios：剧本
```json
{ "id": "rainy-manor", "title": "雨夜古宅", "opening": "雨夜，你们开车穿过山路……", "truth": "二十年前……", "endings": ["找到账本……"],
  "content": [{ "kind": "place", "name": "门厅", "description": "……", "public": true }] }
```
可选，1 到 16 个。
- `id`：小写字母开头，只含小写字母、数字和连字符，至多 32 字符；`title` 至多 80 字。
- `opening`：开场文字，至多 2000 字，每名参与者在开局时读到。可以写“你们”，不要写进只有主持人知道的东西。
- `truth`：真相，至多 2000 字。`endings`：1 到 8 个可能的结局，每个至多 300 字。**两者只有主持人知道。**
- `content`：0 到 40 项局内内容。`kind` 是 `place`、`item`、`npc`；`name` 至多 40 字且不重复；`description` 至多 500 字；`location` 可选，必须是同一剧本里一个 `place` 的名字；`public` 为 `false` 时只有主持人知道，主持人以后可以把它改成公开。

### themes：预设题目
`"themes": ["深夜的废弃医院", "一场没人记得的生日会"]`。可选，1 到 16 条，每条至多 200 字。没有剧本也没有预设题目时，玩家开局自己写题目。题目局没有写好的真相，主持人可以先用私密笔记自己定下来。

## 5. 检查你写的

- `worldpack.cmd validate '<源目录>'`：检查字段、角色引用、骰子写法、剧本内容的地点引用。生成的活动脚本不超过 256 KiB。
- [包透视](pack-lens.md)：能看到生成的跑团活动。
- 推演：`lens simulate '<源目录>' <脚本>.json`。雨夜古宅的三份脚本在 `.perspectra-lens/scenarios/`：`npcPlans` 让主持人 `{ "kind": "perform", "interact": "activity:check", "arguments": { ... } }`，`steps` 里用 `{ "activity": "trpg", "operation": "setup", "parameters": { ... } }` 走玩家的操作，`knows` / `doesNotKnow` 查谁知道什么。**`doesNotKnow` 只检查角色的观察渠道，是冒烟检查**；真正的可见范围覆盖在 `tests/host/trpg-activity.test.ts`。推演不是试玩。

## 6. 已知限制

第一版不做的：
- 没有战斗回合、先攻和距离；没有完整规则书（职业、成长、法术表）。
- 没有跨局的角色卡：每一局的卡面都从模板和 `characters` 重新开始。
- 局内 NPC 由主持人代言，没有独立的模型扮演。
- 玩家不能当主持人。
- 主持人不能直接改主世界的状态或物品；局内的一切只属于这一局。

使用时要知道的：
- **裁定质量靠模型。** 程序只保证点数可信、可见范围正确；主持人宣布的结果和点数是否一致（检定失败却宣布成功），程序不检查，要靠真实试玩发现。
- **重新生成不会重掷。** 点数记在这一轮的随机记录里，回看、分支、重新生成都按原样重放。玩家不能靠重新生成刷检定。脚本里不要用 `Math.random`，它不被记录。
- **笔记长度受活动大小限制。** 每份笔记至多 6000 字，局内内容至多 60 项，待处理行动至多 8 条，每人只记最近 20 次掷骰。主持人超出时会被告知，用 `replace` 整理后再写。
- **活动版本号的变化所有参与者都看得到**，包括主持人写私密笔记或暗骰那一次，但看不到内容。
- **AI 回合路径里，主持人宣布里的“你”，其他人读到的是“行动者”**（已知）。2026-11-09 的试玩里主持人只宣布过一次，用的是名字，没有出现，样本太少，不能说明不会出现。
- **局外角色听得见 AI 的局内发言。** 主持人用说话讲故事时，讲出来的线索（包括她决定透露的隐藏内容）同场的局外角色也会知道。只有活动结果、点数、笔记和局内内容按参与者投递。
- **主持人常用说话代替“宣布结果”。** 试玩里两局各压下 5 到 6 条待处理行动（上限 8 条）。现在有待处理行动时，主持人的说话就算一次宣布，处理最早一条并轮转聚光；程序不判断这句话是不是真的在讲结果。玩家在局内点名问别的参与者，被点名的人仍然拿不到专门的回应机会，只能等聚光轮到。
- **存档会固定生成的规则**：程序升级或改动 `trpg.json` 后，生成内容的摘要变了，旧存档打开会失败，请用新存档。
- 剧本的 `opening`、`truth` 写成什么，主持人就读到什么。作者写的剧本是内容，不是对角色行为的规定；不要用它替主持人决定态度、台词或裁定。
