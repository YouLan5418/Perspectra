# 用创作工作台建立第一个开局

在「新建作品」填入作品名、玩家名、同行角色「阿林」和地点「门廊」，工作台会生成一份 v5 源包，把玩家和阿林放进同一个启用的场景，并设置玩家槽。点「试玩开局」，输入「阿林，早上好」，可以在正式 Host 的独立新档里看到双方实际说的话。角色会自行决定是否回应。

打开已有 v5 包会先进入「作品总览」。标题旁可以添加或更换封面。在「玩家开局」点角色名可编辑玩家槽，点「试玩这个开局」可开始试玩。在「作品内容」点数量可进入地点、角色或物品清单，下方「作品活动」按低代码活动和手写活动脚本分组。封面沿用舞台素材的 PNG、JPEG、WebP 格式和 4 MiB 导入上限，已有封面按原格式替换。

点「读便笺」进入整页活动画布，再点「拆阅便笺」查看内部选项。顶部路径返回上层，右侧抽屉编辑或新增节点。保存草稿会把分组和位置写回源包；从导出目录重新打开也能继续编辑。[活动编辑与查找引用](activity-editor.md)

## 编辑后直接检查

从启动器点「包编辑」可直接打开选中的源包。要单独打开已有包或新建作品，运行 `worldpack editor serve`。

## 设置谁在开局就知道一件事

例如柜号只有阿林知道。在「世界与角色开局 → 世界开局」选择「开局事实」，添加一条，填写事实标识和命题内容，在「开局知情角色」选阿林。新存档会把这个事实作为阿林已经相信的判断。若要表达她只是听人说过，在阿林的「初始认知 → 观察」选择「听人转述」，用含说话者 ID 与原话的 speech 对象填写内容，再用新档核对。[听闻内容示例](../../../skills/perspectra-creator/references/world-pack.md#从编辑器-cli-写人物和开局)

- 在角色记录点「编辑人物设定」可以写动机和原则，也可以从源包已登记的 Markdown 中选背景正文。
- 在「编辑初始认知」可添加观察、判断、目标、关系、情绪、内心冲突、承诺和未了事项。先写一条带键的观察，再写判断时就能按名称选它作依据。候选来自该角色自己的记录、动机和原则，并剔除会形成循环的依据。目标可以指向包内角色、地点或物品。
- 「编辑记忆设置」可选精简、标准或深入容量，并逐项添加关注话题。切换角色或分类页会先保存当前设置，校验失败时留在当前页。
- 命题、观察内容和情绪起因默认直接写文字。接入包含结构化值的已有包时，格式控件支持整数、布尔值、空值、列表和具名字段，能逐层编辑原有类型。

外部 Agent 用 `worldpack editor world-setup <源包> [请求.json]` 读取同一套字段、必填标记和当前表单。角色请求包含 `kind`（`portrayal`、`cognition` 或 `memory`）和 `character`。用 `world-setup-candidates` 传入同样的范围及字段路径，例如 `["claims","0","basisKeys","0"]`，也可附上未保存的 `config`。用 `world-setup-save` 带回 `kind`、角色、原 `file`、原配置 `base` 和完整新 `config`。

## 设置单向或双向通讯录

阿林和玩家即使分处两个场景，也可以私下发信。在「角色通讯录」启用通信，将「通信媒介」填为短信、电台等作品用语。选择玩家，在阿林这一行勾选「可发给对方」，玩家就能联络阿林。若她也可以主动联络玩家，同一行再勾选「可收到对方来信」。两列分别保存，切换角色能从对方的角度核对。角色记录中的「查看角色通讯录」直接打开该人的名单。

新包启用时名单为空。接入已有包时读取清单指定的配置文件。外部 Agent 用 `communication` 读取、`communication-enable` 启用、`communication-save` 保存。`mode-candidates` 的 `mode` 填 `communication`，`path` 如 `["contacts","character:player"]` 可列出该发送者的候选收件人。选择 `["contacts","character:player","1"]` 则剔除其他行已经选择的人。保存请求带读取时的 `file`、`base` 和完整新配置 `config`。`contacts` 为必填对象，每个收件人选填。

## 给角色设置主动行动的机会

例如玩家展开门廊的便笺时，希望隔壁的阿林也有一次自行行动的机会。在「角色自主机会」启用后添加阿林，在「触发条件」选「活动操作」，选「读便笺」和「展开便笺」。列表也包含本工作区已保存的活动图草稿。包里有多个活动时，操作列表会跟随所选活动更新。

填好触发频率、机会数和可活动地点。允许的交互列表可以为空，需要时可选包内的物品、状态或活动操作。勾选「允许交互的对象」可以限定角色或物品。地点和目标决定角色自主时可以尝试的行动。她在另一个房间获得机会时，仍然只依据自己知道的信息行动。宿主的自主行动预算决定本次实际能分配多少机会。

CLI 用 `autonomy` 读取、`autonomy-enable` 启用、`autonomy-save` 保存。新包的默认配置是空角色列表。`mode-candidates` 的 `mode` 选 `autonomy`；用 `["characters","0","triggers","0","activityKey"]` 读活动候选，末项换成 `operation` 并传入当前 `config` 即可读该活动的操作。其他字段的必填性和频率范围见[自主机会字段](creator-fields-gameplay.md#自主-autonomyjson)。

如果要改由玩家控制阿林，先在「角色自主机会」移除她，再修改玩家开局。如果阿林还关联随包的角色或分组预设，或在 TRPG 中有 AI 角色卡或主持人设置，保存时会指出需要先解除的引用。打开已有包时，即使玩家与自主机会已经冲突，也可以进入自主机会表单修正。导出会重新核对玩家、角色、地点与目标。

## 给角色配立绘和初始表情

在「舞台与美术 → 图片素材」选择「角色底图」，选阿林并导入 PNG 或 WebP。地点背景从地点列表选，封面直接导入。预览显示实际保存的图片和路径。每次上传上限 4 MiB。替换底图、背景或封面时用当前图片的格式，工作台按玩家端相同的文件优先级寻找图片。

1. 在素材用途选「表情、拼合图与姿势」，导入例如 `alin/eyes.png`。
2. 在「立绘与开场 → 角色立绘」添加阿林。启用「拼合图」，给图起名 `eyes`，从图片列表选择刚导入的文件。默认四行四列，也可以自己设行列。
3. 启用「默认面部框」，按底图比例填写左、上、宽、高。添加名为 `blink` 的表情，类型选「拼合图中的一格」。选完本角色的拼合图后，按行列选择格子。也可用整张透明图层，或给单个贴片单独设置位置。
4. 在「初始表情」选 `blink`。如需开场自动推进，切换字段分类，选择已有活动及其推进操作。「组件布局」另可设置物品栏等默认舞台组件的位置、文字和窄屏显示。

外部 Agent 可通过同一套舞台命令读取素材、候选和表单，详见[字段清单](creator-fields-presentation.md)。包有自定义首页时，表单会说明默认舞台配置的适用范围。

## 选择世界事件的触发与观察范围

第二天傍晚门廊停电时，门廊里的人看见灯灭了，隔壁的人只听见响声。在「变量与世界事件 → 世界事件」选「包内日历达到门槛」，从已有数值变量选天数，从文字变量选时段，再选触发日和时段。时段变量有枚举时可直接选用和排序。没有枚举时可复用同一变量在其他事件中的时段，或补充作品自己的名称。

将观察范围选为「事件现场」，点「添加分地点通知」选隔壁的地点，填写当地听到的文字。需要由特定操作触发该组通知时，从「来源操作」选包内状态操作。其他事件可选「全世界」、某个物品的持有人，或添加并列观察范围。唤醒角色可从包内非玩家角色中多选，实际能被唤醒的人还必须看到该事件。回到地点或角色记录的「查看引用」可以返回引用它的事件。

需要插件订阅时展开「插件事件订阅授权」，从包内插件和已声明的事件类型选择。持久订阅还可选布尔变量并指定允许写入的值。外部 Agent 用 `event-candidates <pack>` 取得以上候选，用 `rule-save` 保存规则或带 `kind: "grants"` 的授权列表，用 `event-references` 按地点或角色反查。

## 配置和试玩一场 RPG 遭遇

在「技能」选中一条技能后，可以逐项添加伤害、治疗、施加状态、护盾、净化或战斗数值效果。每项按类型显示必填字段。「完整配置」从官方 RPG 字段声明生成表单，可编辑战斗状态、数值定义和技能使用条件。先在战斗状态里定义「灼烧」，再回到技能选择要施加的状态。用于查看和编辑原文的入口是「源配置」。

在「玩法配置」选择起始地点并点「启用 RPG」，就能从新包做出第一场战斗。工作台会写入玩法声明、依赖的骰子插件以及一份含玩家、守卫和两种技能的配置。接入已有包时，工作台读取清单实际指定的路径。展开「已启用玩法与插件」可以核对插件、配置文件和包内玩法脚本。

1. 在「遭遇地图」选择地点、敌人和开战方式，填写初到描述。「技能」可调整目标、效果与消耗。「角色」「敌人」从已有技能中选择。表单标出必填项，地图可以重复放置同一种敌人。
2. 在「活动流程图」找到该地点的 RPG 地图活动，可直接进入它的配置与裁定来源，或打开它绑定的 HTML、CSS。「完整配置」能用表单编辑装备、掉落、队友演出等字段。「源配置」可查看完整字段声明。
3. 在「试玩起点」选择角色的场景，点「启动战斗试玩」和「打开玩家舞台」。玩家默认从所选地图的场景起步，同行者沿用包内起点。进入战斗后实际施放技能，可核对魔力余额与伤害播报。试玩使用独立临时档。
4. 保存后导出新目录，再从工作台重新打开。两个编辑者同时修改一份 RPG 配置时，后保存的一方会收到冲突，可保留自己的输入，重新读取并合并。

CLI 的等价操作和请求示例见[RPG 玩法](rpg.md#用编辑器-cli-配置与试玩)。

### 把澄的第二次火球移到第 2 轮

在「玩法配置 → 遭遇地图」选遗迹一层，找到「遭遇演出」。点「第 1 轮 · 澄」的节点，把「演出回合」改成 2。上方的流程图会立即更新，开战时的第一发火球仍是独立的一行。在「活动流程图」点「遗迹一层 · 演出流程」也能查看已保存的路线，点节点会回到对应的演出行。

| 字段 | 何时填写 |
| --- | --- |
| 触发时机、演出角色 | 每行必填。首次进入适用于所有地图。开战、指定回合、击败全部敌人要求地图有敌人。角色从包内已配置 RPG 数值的非玩家角色中选。 |
| 演出回合 | 仅指定回合时必填，从 1 开始。同一角色在同一回合只执行第一条匹配的演出。不同角色按实际行动顺序出手。 |
| 台词、技能 | 至少填一项。首次进入和击败敌人时填写台词。开战或指定回合可选该角色已学的技能，也可以同时填写台词。 |
| 技能目标 | 选填。对敌技能可点选本图敌人，留空时按技能规则选取。相同敌人重复出现时，源包里的敌人键指向第一只。 |

点「试玩到这条演出」会先保存，再让已配置的 RPG 角色在该图同场开局。到指定回合前玩家和无演出的同伴采用防御；要看胜利演出时玩家会尝试对敌伤害技能。最多推进 64 步。结果使用实际提交的出招、出招前的回合和角色发言。遇到资源不足、提前战败或没有可推进的操作时，可据此调整配置重试。

Agent 用 `gameplay` 读取 `activities[].cues` 和 `config.maps[].scripted`。`cues[].index` 是源数组从 0 起算的行号，流程图按时机排序。用 `rpg-cue-candidates` 查询候选、`rpg-save` 保存 `file,base,config`，然后调用 `rpg-cue-play`。以下为候选和试玩请求，各存为一份 JSON。

```jsonl
{"location":"location:ruin-1","when":"turn","characterId":"character:cheng","skill":"fire"}
{"location":"location:ruin-1","index":1,"expected":{"when":"turn","round":2,"characterId":"character:cheng","say":"再来一发！","skill":"fire","target":"golem"}}
```

检查 `played`，以及 `history` 里所选行的 `phase`、`round`、`skill`、`target`、`description` 和 `speech`。附上选填的 `expected` 可以避免读取后被另一位作者移动或替换的行被误用。

### 把遗迹一层的钥匙换成银钥匙

1. 打开 `hill-ruins` 的副本。在「物品」里新建银钥匙，填写物品种类，把起始地点选为掉落仓库并保存。在「物品用途」勾选「可拿起」。放下和交给他人可按玩法分别开启。
2. 进入「玩法配置 → 遭遇地图 → 遗迹一层」。把「胜利掉落 1」和通往遗迹二层的「开锁物品」都选成银钥匙。掉落候选只列出仓库里尚可分配的物品及当前选项。一个物品只能用作一次掉落。
3. 在「试玩起点」把澄也放到遗迹一层，点击该出口的「试玩掉落与通行」。工作台逐步报告空手过门、胜利掉落、未拾取过门、拾取、持有时过门、开锁和抵达。遇到第一处失败时会显示对应步骤和原因。
4. 从地图点「查看物品」，可核对物品的起始地点、地图掉落、开锁出口，以及活动选项、事件受众和专属页面里直接声明的持有条件。点击用途可回到相应记录。手写状态脚本可查看源码，脚本按运行时数据计算的引用需在源码中核对。

### 设置卧室休息、战败回家和同伴随行

在山脚遗迹，玩家可以在卧室睡一觉，也可以带澄出门。打开「玩法配置」就能修改这些规则。已有包会显示磁盘上的设置，新包先点「启用 RPG」。

| 位置 | 必填和选填 | 如何验证 |
| --- | --- | --- |
| 休息与返回 → 休息点 | 休息整体选填。启用后必填操作名称、至少一个包内地点。表单写入恢复方式 `full`。 | 选卧室点「试玩休息」，看玩家各项属性恢复前后的数值。换到未勾选的地点，可检查那里是否出现休息操作。 |
| 休息与返回 → 战败与撤退 | 战败返回选填，启用后必选返回地点。按需勾选属性并填写返回后的整数值，可填 0。撤退默认留在战场；选择返回时必须有战败返回地点。 | 选有敌人的遭遇，分别试玩战败和撤退。结果按参战角色列出实际落点与结算数值。撤退不会使用战败恢复值。 |
| 队伍 → 队伍与随行 | 队伍整体选填。启用后必选已配置 RPG 数值的队长，战斗中禁止离队默认开启。 | 另选一名成员、两个有场景的可通行地点，点「试玩入队、随行与离队」。同伴在自己的行动中加入，随队长抵达，离队后留在原地。 |

试玩先保存当前配置，再使用临时档。休息和随行检查会跳过所选地点的 RPG 遭遇自动开场。战败检查让 RPG 角色以低生命同场开局，最多推进 32 步；敌人没有造成全灭时会报告实际结果。队伍试玩中的角色选择由脚本给出。

外部 Agent 用 `gameplay` 取得当前配置和地点、场景、属性、角色候选，用 `rpg-save` 原样带回 `file`、`base` 及修改后的 `config`。调用 `worldpack editor rpg-journey-play <源包> <请求.json>` 运行同一项试玩。请求示例如下，每行代表一次调用。

```jsonl
{"kind":"rest","location":"location:bedroom"}
{"kind":"defeat","location":"location:ruin-1"}
{"kind":"retreat","location":"location:ruin-1"}
{"kind":"party","member":"character:cheng","from":"location:living-room","to":"location:bedroom"}
```

### 给宝箱药水配置恢复效果

在遗迹包副本的「物品」里选择二层木箱药水（`entity:potion-2`）。在「RPG 物品效果」勾选「作为消耗品」和「生命」，填写恢复量 20。可以同时勾选多项属性，每项分别填写恢复量。

在「物品试玩」把起始生命设为 15，点「试玩拾取与使用」。试玩会在物品所在地拾取、使用，再尝试重复使用。报告显示生命从 15 到 35、药水已用完。把起始生命改为 36 再试，结果为 40，等于玩家上限。起始值只用于本次独立试玩。

### 配置铁剑和角色装备槽

在「角色」打开玩家记录，在「RPG 角色」添加已有槽位，或输入新名称并点「创建并添加槽位」。切换到物品时工作台会保存。新包需要先在「玩法配置」启用 RPG。

打开物品，勾选「作为装备」，选槽位后可查看拥有该槽位的角色。攻击、防御、火焰抗性均可按需填写。选择有敌人的遭遇和玩家已学会的伤害技能，点「对照装备前后伤害」。两次试玩都先拾取物品，一次空手出招，一次装备后出招。结果记录玩家这次行动造成的实际生命差。遗迹铁剑的攻击加成是 3，对遗迹一层守卫使用普通攻击时，两次分别扣 8 和 11 点生命。

## 制作一场跑团

1. 在作品目录打开「跑团玩法」。新作品点「启用跑团」，工作台登记跑团和骰子插件，并生成含生命、观察和 `d20` 的起始角色卡模板。已有作品按清单指定的路径打开。
2. 在「字段分类」选择角色卡模板、角色卡或主持名单。模板定义数值与技能。角色卡按包内角色选择，可只覆盖一项数值或技能。主持人直接从非玩家角色中选。
3. 选择「预写剧本」，添加标题、开场、主持人掌握的真相和结局。添加剧本内容时先建地点，再从「所在地点」选择。公开条目只能选择公开地点。自由题目也可在「预设题目」中添加。
4. 点「保存跑团配置」。工作台在临时副本校验后保存。已有包的其他剧本、私密条目和未编辑字段一并保留。字段范围见[官方玩法字段](creator-fields-modes.md#trpg-跑团)。

## 给游戏操作写脚本

在「活动流程图」选中一个操作，可用表单设定数值消耗，也可绑定「规则脚本」中的 JavaScript 并填写参数。「规则脚本」还能打开已有手写活动的源码。扣除精力、发放线索和拒绝提示见[操作裁定](activity-editor.md#给选项添加裁定)。

## 只添加作品需要的日常交互

假设门廊这一幕只需要「倾听门外动静」。作者可以直接写这一项。新作品的包内操作清单默认为空，打开此页也不会启用脚本。

1. 在作品目录选择「日常交互」，填写操作名称「倾听门外动静」和稳定 ID `porch:listen`，点「加入脚本草稿」。已有作品会打开清单指定的原脚本，并列出它声明的操作。
2. 在 JavaScript 源码中修改这项操作。用 `offer` 决定谁在什么情况下能看到哪个选项，用 `resolve` 复核执行条件并返回结果。例如，倾听只在门廊可选，执行成功后可以通过 `observation.upsert` 只给行动者提交一条听觉观察。新生成的操作以自己为目标，效果列表为空。
3. 需要角色自主使用时，在 `npc.whenToUse` 写清用途。外部 Agent 可用 `worldpack editor interaction-script` 读取脚本，用 `interaction-script-save` 提交修改。
4. 点「保存并启用脚本」或「保存交互脚本」，再点「试玩日常交互」，从玩家舞台执行操作。删去某项操作后重新保存即可撤下它，也可以保留空的 `operations` 数组。

每个世界包可以用一个共同玩法脚本定义多项交互。操作可以有自己的名称、参数、目标和裁定。可用字段、必填项及效果见[共同玩法脚本字段](creator-fields-gameplay-sdk.md#操作和限制)。已有可运行实例见[搜证脚本](../../../examples/world-packs/investigation/scripts/gameplay.cjs)。

## 给活动配自己的页面

打开「活动专属页面」，按名称或键选中活动，选择包内 HTML，按需选附加 CSS。已有网页用相对路径引用多份 CSS 时，保留文件的目录关系即可。也可在「导入 HTML、CSS 和图片」一起选择文件并指定子目录，工作台会把它们写入 `frontend/activities/`。保存绑定后点「预览活动页面」再打开试玩窗口。预览使用独立新档和固定测试模型。有地点或组队要求的活动可在「试玩起点」配置初始位置，再按玩法条件进入。

在「元素交互与显示」选中 HTML 里带唯一 `id` 的元素。按钮可以选择点击后执行的活动操作；图片、按钮和容器都可以添加条件，决定何时显示、应用哪个 CSS 类或换成哪张图。要使用遗迹守卫的生命百分比等动态字段，先选好试玩起点，再点「读取试玩字段和操作」。

选择「使用原舞台」并保存即可解除绑定。导出会携带页面、样式和同目录下的随包资源。绑定格式、可用 HTML 标记及纸笺示例见[活动专属舞台](activity-stages.md)。

## 打开工作台

目录分为「作品总览」「地点与舞台」「角色」「活动与规则」「玩法与设置」。点组名进入常用页面，点旁边的箭头展开其他配置。窄屏可从「作品目录」展开导航。打开已有包仍先到作品总览，点地点、角色或物品数量就能进入对应清单。

选中地点后，可以在「地点与开局」「此地物品」「地点背景」之间切换。「此地物品」支持就地新建、改名和改种类，点物品名可打开完整配置。选中角色后，「设定与认知」集中人物设定、初始认知和记忆设置，「立绘」直接编辑该角色底图。启用了通讯或 RPG 的包还会出现相应分区。切换分区或记录前会保存已填写的修改。

从仓库根目录启动。首次使用或前端更新后需要先构建页面。

```powershell
corepack pnpm@11.7.0 launcher:build
node --import tsx apps/host/src/cli/worldpack.ts editor serve
```

- **打开已有包**时输入含有 `worldpack.source.json` 的本机 v5 源包目录。v3、v4 历史包需要先迁移到当前源格式。也可把该目录作为 `serve` 的参数直接打开。新建作品时选择父目录已存在的新路径。
- **试玩开局**使用宿主配置的真实游戏模型。启动工作台前，按[本机运行](local-runbook.md)设置 `PERSPECTRA_MODEL_ENDPOINT`、`PERSPECTRA_MODEL` 以及接口需要的认证。每点一次「开新档并发言」都使用一个新的临时存档。
- 在角色、地点、物品、场景、玩家开局列表按名称或 ID 搜索。玩家角色在「玩家开局」单选，保存后角色列表会标出当前玩家，其余角色由角色系统控制。角色可编辑名称、初始地点、称谓、人设摘要和说话风格。每个角色最多指定一个初始地点，场景支持选择多名参与者。开局启用的场景至少有一人；若场景指定了地点，参与者的初始地点与它不一致或未指定，作品总览、角色页和场景页会标红。点问题中的角色、场景地点或参与角色可直接定位，修改其中一处即可重新核对。
- 引用字段列出当前包的候选。如果阿林需要的开局地点尚未建立，可在该字段选择「就地新建地点」。创建成功后回到原表单并带回地点，其他输入保留。「查看引用」列出这五类基础记录中的使用位置；点击一条后可返回原记录。
- 在「地点 → 客厅 → 开局参与互动的角色」勾选角色后保存。地点只有一个未关闭场景时会沿用它；没有时，首次保存非空名单会创建场景。清空已启用场景的名单会将其设为「尚未启用」，留给角色以后进入。角色初始地点仍由角色页设置，其他启用场景中的成员可点名单旁的引用前往调整。
- 一个地点同时绑定多个「开局启用」或「尚未启用」场景时，作品总览、地点页和各场景页会标红，并逐条列出可点击的场景 ID。选择一条进入其「所在地点」字段，可改绑地点或将开局状态设为「已关闭」。解决冲突后即可在地点页继续选人。
- **保存记录会写入当前源包。** 切换记录、试玩、导出前会尝试保存当前表单。窄改一个角色只更新其所在的角色文件，其他角色的内容及未在表单提供的字段原样保留。上次保存的字段可在属性下查看。包已有的手写活动可在[活动流程图](activity-editor.md)里查看其标识。
- Codex、Claude Code 和 DSH 等外部 Agent 可通过 `worldpack editor records` 读取记录，用 `record-save` 提交字段修改。

## 做一次门廊停电

活动节点可以组合角色、物品和变量条件。从物品用途或变量引用点进「展开便笺」，会选中该物品或变量所在的条件行。见[便笺的三组试玩起点](activity-editor.md#让展开便笺同时检查物品和灯光)。

1. 打开「变量与世界事件 → 世界变量」。新建布尔变量，键填 `power-on`，显示名填「门廊有电」，初值选「是」。角色是否始终知道当前值可以单独设置。变量名可以改，活动和事件引用其键。
2. 进入「事件节奏表」，选好强度，点「新建节奏事件」。填事件键 `porch-blackout`、事件类型 `power.outage@1`、发生地点和观察文字。选择写入「门廊有电 = 否」。保存后会回到节奏表原行，带回新事件和刚才选的强度。再点「保存规则」。
3. 已保存事件的流程图并排列出事实写入、观察与唤醒。活动流程图在每个分支列出使用的条件与赋值。「观察范围」决定哪些角色收到事件文字。「唤醒角色」可留空。填入阿林时，她还需要实际观察到事件并处于可唤醒状态。「活动进行中也可发生」用于节奏事件。已有包继续使用原节奏脚本中的概率与冷却。没有节奏脚本的作品首次建表时，默认每个回合都尝试选取一个合格事件，冷却为零。
4. 点「运行事件试玩」。工作台在临时新档按设定回合数执行静观，列出实际发生的事件、观察者、唤醒名单和状态变化。观察文字、唤醒机会和角色主动回应分别记录。这里的 NPC 使用脚本化模型。
5. 在「活动流程图」的条件或结果中选择「门廊有电」，也可以就地新建变量。当前可创建布尔、安全整数、文字和文字枚举。世界变量旁的「被哪些地方引用」可跳到活动的条件、赋值或世界事件。活动开场节点管理局部变量，共享和行动者私有字段可用于选项条件，内部字段用于结果赋值。启动一次新活动会按初值初始化。

世界事件写入包级公共布尔状态。世界变量表可引用已有基础状态脚本中的简单公共字段，手写定义在原脚本维护。按地点可知的字段只有在角色实际可知时才会影响选项；单独告知的字段不列入可见条件候选。日历门槛、组合观察范围、订阅授权和自定义脚本仍可在源包中维护。事件原有的高级字段随导出保留。

规则草稿写在源目录的 `creator-rules.json`。导出把改动编入标准状态脚本、节奏脚本和 `world-events.json`，也可把导出目录作为新作品继续编辑。反向引用覆盖表单中的显式引用，手写 JavaScript 内计算出来的键需要在源脚本中核对。

## 让阿林在停电时想起备用灯

1. 在「知识库」点「新建条目」。保留生成的条目 ID，或在首次保存前改成 `document:spare-lamp`。用途选「世界设定」，读者范围选「指定角色」，从包里的角色中选阿林。正文填「备用灯在蓝柜子的第二层」。
2. 勾选「参与世界书投放」，触发方式选「命中任一关键词」，填入「备用灯」。在投放条件中选已有变量「门廊有电」，已知值选「否」。投放流程显示读者、条件、触发方式和预算，点击可回到对应字段。保存后可以从阿林的「查看引用」或世界变量的引用列表跳回条目。
3. 在「投放对照试玩」输入「备用灯在哪里？」，对照变量选「门廊有电」，开局 A 选「是」，B 选「否」。工作台用两个独立临时新档运行同一句玩家发言。结果逐个角色列出每次请求，区分「收到正文」「未收到正文」和「未发起请求」。加入另一名同场 NPC 后可以核对读者差异。这里使用正式 Host 与本地脚本化模型传输，判断依据是该次角色请求中实际投放的文档 ID 和完整正文。
4. 打开已有包时，公开或角色私有的世界设定与角色塑造文档都能继续编辑。已有复杂条件可以在高级 JSON Schema 中查看、原样保留或修改。关闭「参与世界书投放」并保存，文档会继续保存在源包里。变更先写入 `creator-knowledge.json`，导出才写成标准文档、Markdown 和 `knowledge.json`。

| 字段 | 填写条件 |
| --- | --- |
| 条目 ID、用途、读者范围、正文 | 必填。角色塑造须指定读者，世界设定可公开或指定读者。 |
| 指定读者 | 角色私有条目至少选一人，公开条目留空。 |
| 触发方式、优先级 | 启用投放时必填。工作台默认常驻、优先级 0。 |
| 关键词 | 关键词触发至少填一个，常驻条目可留空。词语匹配该角色获准看到的上下文。 |
| 投放条件 | 选填。可选单个包级变量，或在「组合条件」逐行选择字段、比较方式和值，选「全部满足」或「任一满足」。每一行都按当前读者获准看到的内容判断。 |
| 每轮字符上限 | 包级投放配置必填，取值 100–65536。条目整段进入请求，多个命中条目按优先级竞争预算。 |

## 给同场角色分配不同文风

1. 点「文风与模型预设」，在「包推荐」填“用短句，把话留给对方”，点「保存预设」。已有包会列出原有预设。新建作品可以从空表开始。
2. 新建角色组「门廊来客」。从下拉框选阿林和小余作成员，填写组提示。再为阿林新建一条角色专属预设，添加一个放在上下文之后的提示节点，内容填 `{{char}}先描述眼前的颜色。`。点「校验预设」可以同时核对原生字段、角色资格和组成员是否重复。
3. 在「预设作用范围」切换试玩分配方式。每个角色旁会列出适用预设，点击可以打开对应记录。点角色页的「查看引用」也能返回其专属预设和所属组。
4. 填一次玩家发言，先选「仅用包推荐」核对实际角色请求，再选「已分配随包角色预设」核对同一句话。第二次应看到阿林的专属节点展开了姓名，小余收到「门廊来客」组提示。若角色本轮没有获得发言机会，页面会单独标出。两次都用临时新档和本地固定模型响应，显示实际送出的预设消息与生成参数。判断实际对白风格时，包推荐可直接用「试玩开局」与游戏模型对话。要体验角色专属或组预设，导出作品并在 Launcher 实例中分配后试玩。

| 字段 | 填写条件 |
| --- | --- |
| 适用范围与标识 | 每条必填。包推荐只有一条，`id` 固定为空字符串。专属预设选择一个当前可调用的角色。角色组须有唯一组名和至少一名成员，同一角色最多加入一个组，仍可拥有专属预设。 |
| 附加提示、提示节点、文本处理规则 | 均可选。新增节点须指定名称、角色、位置、内容与启用状态。新增规则须指定名称、阶段、作用字段、正则及替换方式。编辑器生成稳定 ID。展开「示例预览」可对一段示例文本查看提示排列和逐条替换结果。 |
| 生成参数 | 均可选。温度 0–2，Top P 0–1，两种惩罚 −2–2，输出上限为 1–32768 的整数。停止词最多四项，每项 1–100 字符。分配后选择整份角色专属、角色组或包推荐预设，按此顺序取第一份。 |

若已有包里有多个指向退场角色的预设，可逐条移除专属预设、更换失效组成员，再校验和导出。

修改先写入 `creator-presets.json`。导出时按约定生成包推荐 `model-preset.json` 和角色映射 `role-presets.json`，只改动用到的文件。玩家在 Launcher 的实例预设里显式分配随包角色预设。工作台里的分配开关仅对当次试玩生效。

## 外部 Agent

以下命令接在 `node --import tsx apps/host/src/cli/worldpack.ts editor` 后，JSON 示例中的 ID 可以从 `records` 读取。GUI 和 CLI 共享字段定义、引用筛选、保存检查和正式试玩入口。

| 命令 | 用法 |
| --- | --- |
| `create <新目录> <opening.json>` | 输入 `{"title":"我的作品","player":"访客","companion":"阿林","location":"门廊"}`。返回目录和自动生成的包 ID。 |
| `records <包目录>` | 返回作品名以及角色、地点、物品、场景、玩家槽的稳定 ID、源文件、可编辑字段、表单规则，以及 `openingLocationIssues` 角色地点冲突和 `sceneBindingIssues` 地点绑定冲突（含全部相关场景 ID 和状态）。 |
| `location-opening-save <包目录> <edit.json>` | 提交地点 `locationId`、要使用的 `participantIds`，以及上次读到的唯一未关闭场景的 `sceneId` 和 `base`（场景的 `values`）。没有未关闭场景时两者填 `null`。校验与地点页相同。 |
| `candidates <包目录> <request.json>` | 例如 `{"kind":"character","field":"initialLocationId"}`。玩家槽的 `characterId` 列出包内角色；通过 `record-save` 修改玩家槽会同步角色控制方式。 |
| `references <包目录> <request.json>` | 例如 `{"kind":"location","id":"location:start"}`，返回基础记录中的使用位置。动态脚本引用不在此次查询范围。 |
| `record-save <包目录> <edit.json>` | 提交 `kind`、`id`、`base` 和 `values`。用上次读到的字段值作为 `base`，`values` 可只提供要改的字段，例如 `{"portrayal.speakingStyle":"喜欢用短句。"}`。新建用 `base:null`，可省略 `id`。返回实际字段差异；冲突退出码为非零。 |
| `record-assist <包目录> <request.json>` | 输入 `kind`、`id`、`provider`、`prompt`，成功返回的 `undo` 可原样交给 `record-save`。 |
| `opening <包目录> <request.json>` | 输入 `{"text":"阿林，早上好。"}`，在新档运行这一轮，返回实际对话和宿主状态。 |
| `export <包目录> <新目录>` | 校验并导出新源包，保留清单声明的内容和工作台支持的随包资源。 |
| `scripts <目录>` | 列出可复用裁定、参数声明和已有手写活动。 |
| `script-read <目录> <请求.json>`、`script-save <目录> <请求.json>` | 读取传 `{key}`。保存传 `{key,base,source}`，新建时 `base:null`，修改时传上次读取的源码。已有手写活动另传 `kind:"activity"`。 |
| `script-assist <目录> <请求.json>` | 传入 `key,source,provider,prompt` 和可选的 `kind`，取得可对照的候选源码。 |
| `ruling-candidates <目录> <请求.json>` | 传入活动 `key`，获取可读写变量与脚本声明。用 `save` 写入选项的 `ruling`，再用 `play` 试玩或 `export` 导出。 |
| `activity-pages <包目录>` | 列出活动键、操作和阶段声明、现有绑定、可选 HTML、CSS 和图片，以及预览起点候选。 |
| `activity-page-candidates <包目录> <请求.json>` | 输入 `key` 和当前 `html` 返回元素、变量、操作候选。可设 `trial:true` 和 `scenes` 读取真实玩家视图里的字段。 |
| `activity-page-import <包目录> <请求.json>` | 例如 `{"path":"activities/note.css","text":"main { color: navy; }"}`。图片传 `path` 与 `base64`。也可直接把资源放入源目录。 |
| `activity-page-save <包目录> <请求.json>` | 例如 `{"key":"read-note","base":null,"page":{"html":"activities/note.html","css":"activities/note.css"}}`。修改时用上次读取的绑定作 `base`，解绑传 `page:null`。 |
| `activity-page-preview <包目录> <请求.json>` | 例如 `{"key":"read-note"}`。可加 `scenes` 映射角色到初始场景。输出本地试玩地址及是否已进入所选活动，Ctrl+C 关闭。 |
| `open <包目录>` | 返回活动图及 `rules.variables/events/pacing` 三张表。 |
| `rule-candidates <包目录> <请求.json>` | `{"field":"condition","activity":"read-note"}` 查询条件变量，`effect` 查询可写变量，`event-set` 查询事件能写的公共布尔量，`pacing` 返回事件及其可选原因。 |
| `rule-references <包目录> <请求.json>` | `{"kind":"world","id":"power-on"}`。事件用 `event`，局部变量用 `local` 并传入所属 `activity`。 |
| `rule-save <包目录> <请求.json>` | 例如 `{"kind":"variable","base":null,"row":{"key":"power-on","label":"门廊有电","type":"boolean","initial":true}}`。事件用 `kind:"event"` 和世界事件原始行，节奏行用 `kind:"pacing"` 和 `{"id":"porch-blackout","intensity":"high"}`。修改时将上次读取的行放入 `base`。 |
| `rule-assist <包目录> <请求.json>` | 输入 `kind/id/base/provider/prompt`，本机助手的建议通过同一保存检查。 |
| `rule-play <包目录> <请求.json>` | 输入 `{"rounds":1}`。支持 1–16 回合，返回逐轮状态变化、已提交的事件发生记录和最终公共状态。 |
| `knowledge <包目录>`、`knowledge-candidates <包目录>` | 前者列出可编辑条目及每轮预算，后者只列读者和变量候选。 |
| `knowledge-fields <包目录>` | 列出可组合的字段路径、字段类型、所属活动、可选值、可选角色和已用记录键。活动变量连同其 `activity` 一起使用。 |
| `knowledge-condition <包目录> <请求.json>` | 接受 `{"condition":{"match":"all","terms":[{"path":["self","quests","market","stage"],"comparison":"eq","value":"done"}]}}`，返回可导出的 `when`。将同一 `condition` 与 `row/base` 一起交给 `knowledge-save` 即可保存。 |
| `knowledge-save <包目录> <请求.json>` | 输入完整的 `row` 和上次读到的 `base`，新建用 `base:null`。不同字段可合并，同一字段冲突返回原值、已保存值与待处理的版本。 |
| `knowledge-budget <包目录> <请求.json>` | 例如 `{"base":8000,"maximumCharacters":9000}`。 |
| `knowledge-references <包目录> <请求.json>` | 例如 `{"kind":"character","id":"character:companion"}`。支持 `world/character/location/item/activity`，活动变量使用 `{"kind":"local","activity":"tea","id":"ready"}`。返回引用对象的知识条目。 |
| `knowledge-assist <包目录> <请求.json>` | 输入 `documentId/base/provider/prompt`，provider 取 `codex`、`claude` 或 `dsh`。成功结果的 `undo` 可交回 `knowledge-save` 撤销这批修改。 |
| `knowledge-play <包目录> <请求.json>` | 例如 `{"documentId":"document:spare-lamp","variable":"power-on","values":[true,false],"text":"备用灯在哪里？"}`。省略变量和值可运行一次默认开局。传入上次读到的 `expected` 可核对参演条目版本。 |
| `presets <包目录>`、`preset-candidates <包目录>` | 查看预设表和可调用角色，或单独枚举角色 ID 与显示名。 |
| `preset-save <包目录> <请求.json>` | 例如 `{"base":null,"row":{"scope":"pack","id":"","preset":{"temperature":0.7}}}`。角色用 `scope:"character"` 和候选 ID，组用 `scope:"group"`、组名作 ID，另填 `members`。修改用上次读取的整行作 `base`，删除用 `row:null`。 |
| `preset-references <包目录> <请求.json>` | 例如 `{"id":"character:companion"}`。列出直接引用这个角色的专属预设和角色组。 |
| `preset-validate <包目录>` | 校验当前源包和预设草稿，返回有效条目数、可调用角色数。 |
| `preset-sample <包目录> <请求.json>` | 例如 `{"preset":{"prompt":"多用短句"},"stage":"display","target":"speech","text":"你好。"}`。可传未保存预设，返回排列示例和文本转换轨迹。 |
| `preset-assist <包目录> <请求.json>` | 输入已保存的 `base`、`prompt` 和 `provider`（`codex`、`claude`、`dsh`）。返回的 `undo` 可直接交给 `preset-save`。 |
| `preset-play <包目录> <请求.json>` | 例如 `{"text":"门廊今天好安静。","assigned":true}`。用 `false` 对照只用包推荐时的请求，可传上次选中的整行 `expected` 检查该预设是否已变更。 |

各类源字段的必填条件见[字段总览](creator-fields.md)。原生知识条件示例见[世界书设定](world-knowledge.md)。
