## 1. 已有可调参数，但 Launcher 没有接入

`tests/experiments/playtest-tuning.ts` 已有完整校验，`playtest-launch.ts` 接受 `--tuning` JSON，网页入口将其交给运行时。`desktop/launcher-core.ts` 的启动命令没有传入 `--tuning`，因此桌面游玩一直采用默认值。

| 参数 | 默认值 | 现有允许范围 | 实际含义 |
| --- | --- | --- | --- |
| maximumWaves | 3 | 1–10 | 一次普通反应周期最多推进几波 |
| maximumNpcCalls | 8 | 2–40 | 整个普通反应周期的 NPC 模型调用总数上限，包括执行结果后的续写 |
| maximumCallsPerCharacter | 2 | 1–10 | 每个角色最多激活几次；虽然字段叫 Calls，当前代码计数的是激活次数，不是模型请求次数 |
| reactionDeadlineSeconds | 30 秒 | 5–300 秒 | 整个普通反应周期的墙钟时间上限 |
| recentObservations | 16 | 1–100 | 原生记忆路径进入上下文的最近观察条数 |
| recentSelfObservations | 8 | 0–50 | 原生记忆路径进入上下文的最近自身观察条数 |

实际调度见 `packages/application/src/prototype-activation-cycle.ts`。每次激活预留至少两个模型调用槽位；有余量时可提供第三个槽位。单角色激活可以直接 publish/abstain，实际消耗少于预留值。因此“最多 8 次调用”不等于“8 个角色一定都能轮到”。

当前 Launcher 显式开启 Core 记忆。`prototype-character-turn.ts` 中一旦设置 `shortTermAfterSeq`，最近观察改为保留归档前缀之后的完整授权尾部，不按上面两项条数裁剪。不能把这两项当作当前 Core 记忆上下文长度的控制入口。

## 2. 单次输出有两个不同的限制

| 限制 | 默认/当前值 | 位置 | 接入注意事项 |
| --- | --- | --- | --- |
| 模型输出 Token | 默认 2048；预设支持 1–32768 | `packages/provider-chat/src/provider.ts:193`、`preset.ts:38`、`apps/launcher/src/components/PresetDialog.vue:164` | 已有预设入口，应明确与游玩参数的优先级，避免两个入口互相覆盖 |
| 一次角色发布的文字合计 | 2000 字符 | `packages/contracts/src/expression.ts:18`、`packages/provider-chat/src/prototype-turn.ts:11` | 提高 Token 上限仍不能超过该文字限制；改成可配时，必须同时修改模型可见 Schema、说明和实际发布校验 |
| 玩家输入文字合计 | 2000 字符 | `tests/experiments/playtest-server.ts:113` | 独立于角色输出，不应随角色输出限制一起改变 |
| 玩家意图解释输出 | 1024 Token | `tests/experiments/playtest-frozen-runtime.ts:239` | 属于内部结构化解释，建议首版保持内部默认值 |

Token 上限包含模型协议输出，不是角色对白字符数，也不是整个反应周期的累计 Token 预算。

## 3. 超时与活动存在独立限制

| 限制 | 当前值 | 位置/影响 |
| --- | --- | --- |
| 单次模型请求 | local/deepseek 默认 60 秒；ollama 默认 120 秒 | `playtest-frozen-runtime.ts:161`；创建选项已有 timeoutMs，但网页命令及 Launcher 未接入 |
| 一次角色激活 | 最多 120 秒 | `prototype-character-turn.ts:114`；包括激活内的执行与续写，外层更短的截止时间会先触发 |
| 普通反应周期 | 默认 30 秒 | `prototype-activation-cycle.ts:13`；只放宽请求超时不会放宽整个周期 |
| Activity 连续处理 | 最多 4 次机会、总计 90 秒 | `playtest-frozen-runtime.ts:615`；独立于普通反应周期，每次激活最多两次模型调用 |
| 写入租约 | 180 秒 | `prototype-character-turn.ts:124`、`:227`、`:259`；是内部一致性机制，应随激活超时协调，不作为玩家独立旋钮 |
| 玩家意图解释 | 最多 60 秒 | `playtest-frozen-runtime.ts:239`；另有 Host profile 校验上限，不能直接跟随无限增大的模型超时 |
| 普通 Core 启动 | 60 秒 | `desktop/launcher-core.ts:420`；不同于游玩中的模型请求 |
| 分叉记忆重建启动 | 3660 秒；重建自身 3600 秒 | `launcher-core.ts:420`、`playtest-frozen-runtime.ts:285`；首版建议保持内部默认值 |

Activity 处理之后可能再运行普通反应周期，因此普通反应周期的调用预算和截止时间不是整次玩家操作的统一预算。

## 4. Core 记忆的其他可配置候选

`tests/experiments/playtest-memory-core.ts` 已有创建选项，但 Launcher/网页 CLI 没有暴露：

- 上下文整理触发阈值：估算 170000 Token。
- 一次整理的前缀目标：估算 120000 Token。
- 保留最近内容的最低目标：估算 16000 Token。
- 角色整理并发、retain 并发：均默认 2，现有允许范围 1–4。

另外长期记忆交付固定最多 6 条、JSON 最多 12000 字符，后台整理有 600 秒截止时间。以上估算采用本地 ASCII/非 ASCII 字符估算，不是供应商精确 tokenizer。

可将整理阈值放入后续“高级：记忆”设置。对上下文较小的模型，170000 的触发阈值可能超过模型容量；这是一项明确的配置适配风险，不代表已复现了某个模型的上下文溢出。

## 5. 建议接入方式

游戏详情“游玩配置”增加“运行参数”卡片，设置属于 Launcher 中已载入的当前包，保存在 Launcher 数据根目录，作用于该包下各实例下一次启动。保留游戏包原文件、包摘要和已提交世界事实；故事线分叉沿用同一包的游玩配置。提供恢复默认值，运行中禁止修改运行参数。

首版建议暴露：角色发布字符上限、普通反应波次、NPC 模型总调用预算、每角色激活次数、模型请求超时、普通反应周期总时限，以及单角色激活总时限。Activity 机会与总时限在单独的高级区呈现，避免让用户误认为普通反应设置已经控制活动。

模型输出 Token 继续复用角色预设配置。若需要包级默认值，须明确“角色有效预设中显式值 > 包级默认 > Core 默认”，并在界面显示有效值；不要默默把它变成覆盖所有角色预设的硬上限。

优先复用现有 PlaytestTuning 校验与 --tuning 启动路径。新增参数只补当前缺口；文字上限需沿模型 Schema 和发布校验传递。超时必须明确各层作用，租约长度由程序协调。

旧 `round-coordinator.ts` 中的 responsive/v1 3 波/8 次调用，以及持久 Reaction Cycle 的 3 波校验，不是当前普通 NPC 激活的配置入口。不能为了本轮设置功能修改那套旧流程。

## 7. 进一步影响体验的配置候选

| 候选 | 当前实现 | 体验影响与建议归属 |
| --- | --- | --- |
| 玩家输入字符上限 | 默认前端和服务器均限制合计 2000 字符 | 长动作和场景描写容易遇限；可作为包级运行参数，前后端需同步，底层请求体大小也要协调 |
| Core 近期原文保留目标 | minimumRecentTokens 默认估算 16000 | 增大可保留更多近期细节，减少则降低上下文成本；是归档后保留重叠尾部的目标，不是全部上下文硬上限 |
| 整理触发阈值与单批目标 | 170000 / 120000 估算 Token | 影响长聊连续性、模型容量适配与后台费用；适合包级“高级：记忆” |
| 长期记忆交付数量与体积 | 最多 6 条、12000 JSON 字符 | 影响回忆丰富度与上下文噪声；需同时更新 Python 交付及 Host 校验，不改变授权来源检查 |
| 后台整理并发 | 角色并发 2、retain 并发 2；已有范围 1–4 | 影响完成速度、本机负载与接口限流；更适合全局资源设置，首版无须包级重复 |
| 玩家意图解释模型 | FrozenPlaytestOptions 已有 intentModel；默认与角色模型相同 | 能将解析意图与角色扮演分别适配；目前共享协议、地址和认证，独立提供商需要额外接线 |
| Activity 格式修正次数 | decideActivityFormat 固定最多额外修正一次 | 在等待/费用与合法输出成功率间取舍；只针对结构格式，不能跳过规则裁定或重试已提交动作 |
| 记忆内部请求超时及尝试次数 | core_bridge.py 每次 HTTP 120 秒，最多 3 次尝试；另有 worker 总超时 | 影响慢接口下的等待与稳定性；应限定到记忆请求并协调外层超时，不能作为全局“失败自动重试” |
| 预设生成参数与文本处理 | 已支持 temperature、topP、频率/存在惩罚、stop、提示节点、文本规则 | 已有预设入口，沿用即可；协议支持范围不同，stop 会截断 JSON，不宜放进普通游玩设置 |
| 默认前端阅读偏好 | 故事字号/行高在 CSS 中；自动跟随最新内容以距离底部 70px 判断 | 可增加字号、行距和跟随最新消息开关；属于玩家界面偏好，不改变 Core 规则，社区前端可自行支持 |

需要新增功能才能实现的候选，不应伪装成已有参数：流式输出、任意改变角色调度顺序、角色常驻后台自治、任意关闭认知隔离、绕过 Activity 创作者规则。尤其流式内容只有通过协议验证和发布提交后才可视为正式内容，不能仅加 UI 开关。

建议优先级：第一轮预算/输出/超时入口之后，优先增加玩家输入上限和 Core 记忆上下文配置；其次增加召回交付预算和阅读偏好。独立意图模型、重试策略与后台并发放进高级设置，避免默认界面堆满内部旋钮。本补查没有修改运行时行为。

## 8. 本轮实现

游戏详情 → 游玩配置 → 运行参数 → 配置。当前包的所有实例及分叉在下次启动采用这些参数；运行期间禁止更改。恢复默认值只修改草稿，仍需保存。配置按包 ID 保存在当前数据根目录 `launcher.json` 的 `playSettings` 中，不写游戏包或存档事实。

`desktop/play-settings.ts` 集中定义默认值、范围和校验，并由 Launcher 与 `--play-settings` JSON 启动路径共用。普通周期复用现有调度参数；Activity 保持独立预算。模型输出 Token 仍归角色预设管理。角色发布字符限制同时传入模型 Schema、格式校验、预设处理、Activity 和 Kernel 裁定；写入租约随激活总时限延长。玩家输入上限同步到公开视图、宿主、默认模板和服务器请求体校验，主发言与细节描写合计计数。

| 设置 | 默认值 | 范围 |
| --- | --- | --- |
| 玩家输入 / 角色单次发布字符 | 各 2000 | 各 100–16000 |
| 单次模型请求超时 / 单角色激活总时限（秒） | 60 / 120 | 5–300 / 5–600 |
| 普通波次 / NPC 总调用预算 / 每角色激活次数 | 3 / 8 / 2 | 1–10 / 2–40 / 1–10 |
| 普通周期总时限（秒） | 30 | 5–300 |
| Activity 机会 / 总时限（秒） | 4 / 90 | 1–20 / 5–600 |
| 记忆触发阈值 / 单批整理目标 / 近期保留目标（估算 Token） | 170000 / 120000 / 16000 | 4000–1000000 / 1000–900000 / 0–500000 |
| 长期记忆交付条数 / JSON 字符 | 6 / 12000 | 1–30 / 1000–64000 |

单批整理目标与近期保留目标必须小于触发阈值。召回预算沿用已有 Core 交付预算，不改变角色授权证据检查。改变运行参数会改变重新生成环境，新启动后旧回合候选可能不再支持重新生成；历史已提交结果仍保留。

全局设置 → 默认前端阅读偏好：字号 14–28（默认 17）、行距 1.4–2.4（默认 1.9）、靠近底部自动跟随（默认开启）。保存到 `preferences.reading`，下次游戏启动生效。公开玩家接口只提供输入上限与阅读偏好；社区前端可自行决定是否采用阅读偏好。

本轮不暴露意图模型、内部重试、后台并发与记忆内部请求超时。Core 启动/分叉重建截止时间沿用原值。
