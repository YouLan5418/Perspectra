# 角色预设首版

日期：2026-10-06。当前范围：全局默认、包推荐、实例覆盖、附加角色提示和常用生成参数。

## 1. 使用方式

真实 Launcher 的游戏详情提供“角色预设 → 修改”。选择编辑全局默认，或设置当前实例：

| 实例方式 | 生效内容 |
| --- | --- |
| 采用包推荐 | 全局默认逐字段打底，包推荐中明确填写的字段覆盖 |
| 仅用全局默认 | 忽略游戏包推荐 |
| 实例自定义 | 完整替代全局和包推荐；未填写参数使用 Core 默认值 |

附加提示作为一个完整字段覆盖，三个层级的提示不会串联。开始自定义时界面提供当前值供修改。全局变化影响继承实例，已保存的自定义保持独立。保存后在下次启动时生效；运行期间不允许修改。新实例默认采用包推荐。

附加提示用于表达风格和角色扮演建议，不替代角色设定、Core 输出契约或世界规则。预设可以影响模型尝试什么行为，但提交仍经过现有协议校验和事实裁定。它不提供自然语言绝不越权声称的保证。

## 2. 数据与参数

游戏包可在源目录根部提供可选的 `model-preset.json`：

```json
{
  "prompt": "对白简短，保留每个角色自己的语气与判断。",
  "temperature": 0.4,
  "topP": 0.9,
  "maxOutputTokens": 2048
}
```

| 字段 | 限制 |
| --- | --- |
| prompt | 最多 16000 字符，可多行 |
| temperature | 0–2 |
| topP | 0–1 |
| frequencyPenalty / presencePenalty | -2–2 |
| maxOutputTokens | 1–32768 整数 |
| stop | 最多 4 条，每条 1–100 字符 |

留空生成参数沿用现有角色请求默认值：temperature 0.3、角色最大输出默认 2048 Token。实际可用范围仍取决于模型服务。停止词可能截断受约束 JSON 输出，通常留空；截断不会绕过输出校验。

Launcher 在自身数据目录持久化 `preset-settings.json`，包含 `global` 与按实例 UUID 索引的 `instances`（mode、override）。预设不写入实例世界数据库，不保存模型凭证，也不改变世界包的权威世界内容 Hash。损坏设置明确报错，不覆盖旧文件。

包推荐属于附加配置，不是受信任前端授权对象。修改它不授予任何前端能力；启动时重新读取当前推荐。社区前端的公共 API 不提供预设编辑或角色私有上下文。

## 3. 请求边界

- Launcher 解析有效预设，通过子进程环境传递给 Core；独立网页入口也读取包推荐。
- provider-chat 在原 Core 契约之后追加角色提示，保留角色上下文、工具名、schema 和 forced tool choice。
- 只作用于 character 请求。玩家意图解释的消息、模型及输出上限保持原有配置；记忆整理、世界事件与 Rulebook 不读取预设。
- 参数采用字段白名单；endpoint、apiKey、tools、输出模板和世界规则字段不接受。
- Core 记忆上下文预算统计计入附加提示。模型返回仍沿用现有验证路径；不增加语义分类器或提示扫描。

## 5. 角色专属与实例内角色组

后续已实现角色专属预设与角色组预设映射。入口仍是“角色预设 → 修改”，编辑范围新增“角色专属”和“角色组”。

每个角色最多属于一个实例内角色组。优先级为：

**角色专属 > 所属角色组 > 实例默认**

专属或组配置完整替代下层配置，未填写生成参数使用 Core 默认值，不逐字段继承其他角色或组的设置。关闭专属恢复所属组，未分组恢复实例默认；删除组解除所有成员分组，已有角色专属预设保留。分组不改变世界关系、角色调度、模型接口或凭证。

组可以创建、改名、修改预设和删除。在“角色专属”页面选择成员归属和是否启用专属预设。弹窗中切换角色或组会保留实例内草稿，保存当前实例时一并写入；取消放弃草稿。全局默认单独保存。

现有 `preset-settings.json` 的实例记录增加可选字段，不引入新的数据库或协议版本：

```json
{
  "mode": "auto",
  "override": {},
  "characters": {
    "character:companion": { "prompt": "用简短对白回应。" }
  },
  "groups": {
    "4d6041be-7228-4f72-9c2a-733e82415f5d": {
      "name": "日常组",
      "preset": { "prompt": "自然口语，一次一句。", "temperature": 0.5 }
    }
  },
  "memberships": {
    "character:friend": "4d6041be-7228-4f72-9c2a-733e82415f5d"
  }
}
```

未设置映射的已有实例继续使用原默认预设。配置属于实例，不复制到新实例，也不写回游戏包。

角色列表由已编译包元数据生成，仅包含角色 ID 和显示名称，排除玩家、manual 控制和非 active 角色。它是本机配置列表，可能显示包中尚未在游戏里出现的名字，不是公开玩家视图；社区前端不会获得此列表。保存及启动检查角色属于当前包，拒绝其他包角色、玩家和悬空组引用。无效设置不会覆盖已有文件。

Core 复用同一套解析函数，在真实角色调用路径按 characterId 选择预设，包括后续 continuation 与可选 publication-audit 重试。附加提示的上下文统计使用该角色实际生效的提示。玩家意图解释与记忆整理不使用组/专属预设。Launcher 到 Core 传递一份实例映射，组提示不按成员重复序列化。

## 6. 原生提示节点与文本处理（2026-10-07）

当前角色预设已扩展为原生内容配置，不以 SillyTavern 格式兼容为目标。已有全局、包、实例、组与角色选择继续复用；不新增世界数据库、事件版本或插件运行时。现有附加 `prompt` 仍可单独使用，编辑器提供“将附加提示转为节点”。基础宏只在节点内容中展开。

Launcher 的角色预设弹窗新增节点和文本规则编辑，支持添加、删除、启用、上移/下移、身份和插入位置。保存仍在下次启动生效；取消放弃当前草稿。示例预览使用用户填写的文本和示例角色名称，不读取实际角色私密上下文；它展示节点排列、宏展开结果和各条匹配阶段规则处理后的文本。预览不代表真实模型已经遵循文风要求。

### 原生结构

可直接参考 [自然互动示例](../../preset/native-natural.json)。`nodes` 与 `textRules` 都使用数组顺序，不另外添加排序协议。

| 字段 | 含义与限制 |
| --- | --- |
| nodes | 最多 64 个节点；每节点 id 唯一、name、enabled、role、position、content 必填 |
| role | system / user / assistant；assistant 是普通提示消息，不承诺模型预填充能力 |
| position | beforeContext / afterContext；Core 系统契约固定在首位，当前授权上下文作为一个固定插槽 |
| content | 每节点最多 16000 字符；包括附加 prompt 的提示总长度最多 32000 字符 |
| textRules | 最多 32 条；每条 id 唯一，name、enabled、stage、target、pattern、flags、replacement 必填 |
| target | speech / narration / both；对白与外显叙述分开选择 |
| pattern / flags | 正则源文本不带 / 分隔符；最多 1000 字符；标志支持 g、i、m、s、u |
| replacement | 最多 4000 字符；支持 JavaScript 替换语法，如 $1；空字符串表示删除 |

宏按启用节点的数组顺序执行，然后按位置排列消息；因此一个仅赋值、没有可见文字的节点也能影响后面的节点。内置 `char/user/scene` 使用当前角色、玩家和该角色授权场景的名称；`date/time` 是请求时本机日期/时间，不是世界时间。支持 `setvar/getvar`、`random`、`roll`（最多 20 个骰子）、`trim`、`//注释`。预设变量每次角色请求重新创建，角色之间和 continuation 之间不共享，也不接触游戏包变量或世界状态。未知宏与嵌套宏明确失败，首版不做酒馆递归宏兼容。

### 四个处理阶段

| stage | 实际范围 | 保留的边界 |
| --- | --- | --- |
| input | 当前角色收到的最新玩家输入表达，包括已授权的完整 playerInput.sourceText 和刺激副本 | 原始玩家提交、意图解释与裁定不改变；不会补取未授权的完整输入 |
| history | observations/selfObservations/stimulus 中其他历史对白、叙述和玩家输入文本副本 | 不处理执行结果、物品、位置、可用交互或长期认识正文 |
| output | 模型返回 publish 的 speech/narration，提交公开表达之前 | 原始格式必须有效；不清理 decision、行动参数或执行结果；玩法闭合对白选项禁止被改写 |
| display | 玩家已有可见观察中每个说话角色自己的表达副本 | 不写回事件、观察或记忆；玩家表达和程序结果不套用 NPC 预设 |

发布前清理后的表达是实际发布、持久化并进入其他角色观察的内容；原始模型草稿不作为公开会话保存。展示规则只产生玩家展示文本，下一次模型仍从发布内容构建自己的历史。完整输入的投影若改变了 sourceText，会标注 sourceSpans 指向原始存档输入，避免把原始位置引用误认为投影的位置。

正则在独立工作线程执行，1 秒期限到达后终止，线程内存上限 32 MB；单段输入/每步输出最多 64000 字符，发布后的表达仍受原有每字段 2000 字符与非空校验约束。规则失败、超时或清理后为空明确失败，不冒充角色主动沉默；已提交事件不会回滚。错误的展示规则也可能使展示刷新失败，需要停止后修改预设。不会执行替换文本中的 HTML/JS；当前前端继续按纯文本显示。

Core 请求的上下文体积统计包含实际展开的节点。Launcher 启动只传递自身设置目录及实例 ID，子进程读取已有 preset-settings.json，避免大节点/角色映射超过 Windows 单个环境变量长度限制；独立网页入口原有显式环境配置仍可使用。模型账号、凭证、工具定义、角色权限和事实裁定不进入预设。

## 7. 实际角色请求 Inspector（2026-10-07）

启动实例后，在 Launcher 游戏详情的「实际模型请求 → 查看」打开检查器，启用采集，再进行互动并刷新。采集的是 Provider 最终发送的 JSON 请求，已经应用参数覆盖、附加提示、节点宏展开和输入/历史文本投影；不是预设编辑器中的示例。

可查看每次调用的角色、是否继续处理、模型、时间、耗时和传输状态；按最终消息顺序显示 Core 固定契约、预设节点、授权上下文与最终 role；预设节点保留原文供对照。授权上下文按实际渲染的 character、stimulus、memories、cognition、scene、observations、selfObservations、claims、goals、items、affordances 等字段展示；完整请求 JSON 包含工具定义和生成参数。已有的认知压缩表就是发送内容，不会额外读取或展开未授权材料。

Token 分项是本地文本估算，不是模型 tokenizer 计数。请求 JSON 估算包含 JSON 包装和工具定义，不能把上下文分项与消息估算重复相加。服务返回的 input/output/total usage 单独显示；缺失不补造，total 也不假定等于可见 input+output。

默认关闭，不持久化，保留最近 4 次角色调用；单个请求超过 100 万 UTF-16 字符时只保留元数据并明确提示正文未捕获。关闭采集或退出运行时清空；关闭窗口只清空窗口数据，运行时采集继续。请求头、密钥、完整响应和端点错误正文不进入检查器。私有检查 API 沿用宿主令牌和同源校验，Frontend API/PlayerView 不提供检查器；Launcher 原生桥仅允许读取当前运行实例。

这是调用级请求检查器，尚不保存每条正则的执行轨迹、输出草稿或语义裁定。ok 表示 Provider 传输与载荷提取成功，不保证 Core 接受决策。当前不承诺 assistant prefill；本机网关验证见 [验证报告](studies/request-inspector-prefill.md)。historyDepth 和条件节点仍未实现；命名预设库见下一节。


## 8. 命名预设库与编辑体验（2026-10-07）

Launcher 角色预设编辑器左侧提供命名预设库：搜索、另存当前草稿、重命名、用当前草稿覆盖、删除以及应用到当前范围。应用是复制到全局/实例/角色组/角色专属的编辑草稿，保存全部配置后生效；应用到实例会切换为自定义，应用到角色会启用角色专属。库中后续修改或删除不影响已应用副本。

预设库保存在 Launcher 设置目录的 `preset-library.json`，已有 `preset-settings.json` 继续保存已应用配置，两者独立。库条目包含本地 `id`、`name` 与已校验的原生 `preset`，不包含角色 ID 映射、模型账号、凭证、世界状态或私有请求。保存仍使用临时文件加 rename；加载损坏数据明确失败而不覆盖。

交换文件顶层统一标记 `format: "perspectra-model-preset"` 与数值 `schemaVersion: 1`。单项的载荷为 `name`/`preset`；整库的载荷为 `presets` 数组，每项包含 `name`/`preset`。检测到任一标记时，必须同时提供正确的 format 与受支持版本，不接受缺失版本、字符串版本、未来版本或混合载荷。既有裸 RolePreset、无标记命名对象及其数组仍可导入；后续导出统一使用 v1 标记。文件读取后先显示名称与节点/规则数量摘要，点击加入预设库后才写入。整批通过原生字段校验后再保存；同名项加 `(2)` 等后缀另存，不覆盖。重命名与覆盖则要求名称不与其他条目重名。当前不直接导入酒馆 JSON，不忽略其未知字段。

可导出当前草稿、所选库预设或整个库；单项导出为带标记的 name/preset 对象，整库导出为带标记的 presets 数组封装对象，不携带库条目本地 ID。原生窗口使用系统保存对话框，浏览器预览使用 JSON 下载；导入前文件大小检查为 4 MB，导入/导出内容最多 100 万字符。超过整库交换上限时请逐项导出。预设库内容不是私有请求导出。

编辑器使用宽面板，节点与规则可折叠、复制、排序，并可撤销最后一次节点/规则删除。无效正则就地提示；改动后旧预览失效。不同编辑范围保留各自草稿；「保存全部配置」在验证全局内容和当前实例全部角色/组配置后一次写入，避免切换后只保存当前页。未保存配置退出时可继续编辑或放弃。库操作立即保存，与右侧配置草稿分开。

Inspector 同样使用宽面板；自动刷新默认开启，每 3 秒只在窗口打开且采集开启时读取。支持跟随最新调用、手动选旧调用、按角色筛选、正文搜索、消息/上下文分项/完整请求切换、复制内容和清空记录；角色名称来自已有包元数据，权限与保留上限不变。关闭窗口清空界面数据并停止轮询，不停止运行时采集。

验证结果见 [预设库与易用性报告](studies/preset-library-polish.md)。historyDepth 暂缓，条件脚本与新兼容层未加入。


### 原生交换格式 v1 示例

单个预设：

```json
{
  "format": "perspectra-model-preset",
  "schemaVersion": 1,
  "name": "自然对白",
  "preset": { "prompt": "使用自然口语，保留角色自己的判断。" }
}
```

整库（即使只有一个条目，也保留 presets 数组）：

```json
{
  "format": "perspectra-model-preset",
  "schemaVersion": 1,
  "presets": [
    { "name": "自然对白", "preset": { "prompt": "使用自然口语。" } }
  ]
}
```

版本标记属于交换文件，不进入模型请求、RolePreset、游戏包 model-preset.json 或已有 Launcher 内部存储。版本不匹配时明确拒绝，不猜测或自动迁移。
