## 1. 玩家流程

开始游戏后，在浏览器游戏宿主页工具栏点击“保存进度”，输入节点名称；留空使用“保存于 HH:mm”，取消则不保存。当前玩家输入或角色调用未结束、NPC 暂停时，保存明确失败，原进度保留。活动可以处于进行中，只要求当次操作已经提交且没有后台写入。

`POST /api/story-save` 只接受 `{ title: string }`，最多 80 字符，成功返回 `200 { node: { id, title } }`；未鉴权 401，标题无效 400，忙碌 409（保留原文案），运行时不支持 501。保存失败不改变节点列表；本轮接口测试和打包后无模型真实保存已验证，完整前端流程及发行包未验收。

保存短暂冻结新的世界操作，取消未完成的后台长期整理并等待其退出，完成关键会话投递，释放 writer。原线既有长期档案保留；下一次正常整理仍可从保留档案继续。

结束游戏后，选择当前线路历史中的一个完整节点，创建新故事线。首次启动新线校验并恢复节点当时的长期档案；未来前缀、其他角色或授权来源不匹配时拒绝启动并保留恢复标记。旧节点缺少档案时使用节点内完整授权原文，不复制原线当前记忆。恢复不调用 Build；原线不变。既有文件名 rebuild-memory.json 仅保留为恢复标记。

切回原线会恢复原线自己的最新进度和长期认识，不回退原线，也不重复重建。节点列表表示最近保存的完整历史，可能落后于线路的当前进度。

## 2. 保存内容与同一时刻

| 内容 | 来源与恢复 |
| --- | --- |
| 位置、物品、关系、观察与活动 | 节点时刻的完整 World 数据库；沿现有 Event 投影和 activity.updated 恢复 |
| 状态 | 2026-10-19 起只存在 World 数据库的 `status.updated` 事件里，随节点时刻的世界数据库一起恢复；前端仍只看到玩家已知的值 |
| Session、原生派生记忆、Context | 同一次冻结中的既有 SQLite 数据，维持提交绑定及现有完整性检查 |
| 长期认识 | 复制节点当时已安装档案到 core-memory.json；恢复校验角色、世界、前缀与完整授权 Source；不复制当前原线档案或请求日志 |
| 身份称呼历史 | 从已有角色授权视图提取的名称记录，只保存节点之前的范围 |
| 节点元数据 | 本地 UUID、名称、创建时间、事件位置、tick、现有 packHash、父节点与文件清单 |

保存期间禁止输入、活动操作、逃生操作与新记忆构建；检查无 pending/claimed Round、未终结 Player Input、非 terminal Reaction Cycle、未投递关键 Outbox 和活动 writer lease。SQLite 使用一致 backup，包含 WAL 已提交数据，不拷贝运行中的主文件充当快照。

所有文件先写入不可选择的临时节点目录，最后原子 rename 公布节点。不建立跨库事务或新增事实协议。失败的临时目录可能留在磁盘，但不出现在历史列表。文件清单缺失时拒绝恢复，不静默初始化丢失的变量。

2026-10-19：包变量（`pack-variables.json`）已退役，由状态事件替代，节点文件清单不再包含它。因为全局事件清单变化，此前的存档和节点都无法在新版本打开，需新建存档；不提供迁移。过去没有节点副本的游玩轮次不能恢复为完整节点。

## 3. 数据目录与权限

主线沿用已有实例目录，保护已有数据；新线位于实例下 storylines/<本地 UUID>/。每条线路继续运行单分支 Core，沿用原 WorldAddress；线路隔离由独立目录和一次只拥有一个 Core 进程保证。没有启用共享数据库多分支调度。

每条线的 story-nodes/<节点 UUID>/ 是只读使用的完整节点副本。节点目录不会作为正常运行目录打开；恢复只复制节点白名单文件到新的空线路目录，不复制原线的最新状态、凭证、日志或整棵节点树。Launcher 索引保存线路名称、父线、来源节点和当前选中线路。

Launcher 只返回节点标题、来源、进度等公开元数据，不返回数据库内容、角色 Source、私有变量或长期档案。分叉请求只能引用所选线路可达的节点；不接受前端提供任意实例路径。游戏包内容变化仍按已有 packHash 预检拒绝运行。

## 7. 当前节点记忆规则（2026-10-09）

原先为防止未来认识回流，每次分叉都从原文重建全部角色档案。这解决了时间边界，但上下文未达整理阈值时仍产生额外模型调用，并改变原有认识措辞。当前改为保存节点时已安装的 archive、index 和 aliasHistory，恢复时复用既有角色、世界、Source 与前缀校验；不会用原线最新档案裁剪成过去。

未建立档案的角色与无 Core 快照的旧节点继续使用截至节点的完整授权原文，不调用模型补做摘要；旧节点无法恢复从未保存的摘要。分享仍排除 Core 档案，导入也走授权原文路径。后续自动阈值与手动整理不变，没有新增跨节点记忆协议。

当前回归验证：档案和未整理原文尾部完整恢复；连续三个节点/分叉与旧节点均零 Build；未来、其他角色及来源污染档案拒绝；原线保持。实际旧节点副本在模型 runner 禁止调用时恢复到事件 2227 / tick 328，未写入原存档。旧流程的重建速度与部分角色续建记录仅为历史证据，不再表示当前行为。原有档案半写/单角色安装中断测试已改为恢复快照后重试且零 Build；长时间角色文本质量和重新发行便携候选包仍待验证。

## 8. 进程强制终止验证（10-07 旧流程记录）

测试子进程通过测试专用的文件函数包装停在实际持久化边界；父进程在 Windows 上使用 taskkill /T /F 强制结束该子进程，并重新打开索引与运行目录。生产实现未添加故障注入接口。

| 中断点 | 重启后要求 |
| --- | --- |
| 节点数据库完成、身份文件写到一半、尚未公布 | 半节点不出现在列表，旧节点和原进度完整，能够重新保存 |
| 节点已原子公布、尚未返回确认 | 完整节点保留并可列出，原线可正常重启 |
| 分叉只复制完世界库 | 不写入线路索引，原线仍被选中，重新分叉使用新目录 |
| 分叉完整复制、索引替换之前 | 原线索引完整，未索引的新目录不会自动成为线路 |
| 线路切换索引替换之前／之后 | 分别保留完整旧选择／完整新选择，两条线路都可重新打开 |
| 记忆临时归档写到一半、尚未安装 | 重建标记保留，临时文件不冒充完整归档，重启重新构建 |
| 一个角色归档已安装、另一角色未完成 | 重建标记保留，重启只补未完成角色，全部成功后方可开始 |

测试实际发现并修复：首次刷新视图取得的世界写入租约原先被保持到漫长记忆重建结束；杀进程后立即启动会被未过期租约阻塞。现在重建前调用现有 application.release 释放世界运行实例与租约，角色记忆构建独立读取节点并写派生档案。无需新增恢复协议，也不强行接管其他进程的租约。

各场景核对原线事件、包变量、两角色长期归档内容，并运行相关 SQLite integrity_check；同时验证重启、重新保存或分叉。允许隐藏临时节点、未索引的分叉目录和索引临时文件残留，占用磁盘但不影响选择与重试，不自动删除可能含有数据的目录。这些是进程终止测试，不涵盖断电、磁盘故障或任意指令位置的崩溃。

## 9. 单节点分享（2026-10-15）

例如玩家在晚餐后希望把进度交给朋友：先在游戏宿主页点击“保存进度”，看到“已保存”后，再由 Launcher 选择已保存节点导出。保存与导出是两个独立操作；导出失败时节点仍保留。2026-10-17 后端删除了 Launcher 的 `story-save` operation，前端改版另行交付；原先“保存当前进度并导出”的两步联动不再适用。

导出已保存节点时，只读不可变快照，游戏运行中也允许执行。从分支管理点击“导出所选节点”会沿用选中的节点，弹窗显示游戏包、线路、节点标题、时刻与保存时间；不会将历史节点默默替换为当前进度。切换、分叉和导入仍要求先结束游戏。

文件仍为 `.perspectra-story` 单节点容器，不引入新版本或整线备份机制。接收者先载入内容完全相同的世界包，在游戏详情选择“导入存档”，创建独立实例并使用自己的模型配置。首次开始恢复节点当时已安装的 Core 档案与授权原文，不额外调用模型整理。没有长期档案的角色，以及未携带快照的既有节点，使用节点内授权原始经历；后续整理按正常阈值触发。

| 内容 | 边界 |
| --- | --- |
| 分享范围 | 一个节点以及其中截至该时刻的事件历史；不携带其他恢复节点或整棵线路树 |
| 数据 | World（含状态事件）、既有 Session、身份称呼种子、节点当时的 core-memory.json 长期档案与节点元数据 |
| 排除 | Context 请求记录、原生认知缓存、记忆请求与整理日志、游戏包、模型预设／接口配置、密钥、授权与本机路径配置 |
| 文件形式 | 有限 JSON 容器，SQLite 用 Base64；沿用现有节点元数据，替代通用 ZIP 解压，不新增压缩依赖 |
| 大小限制 | 单文件64MiB、原始文件合计96MiB、容器129MiB；当前完整内存解析，不承诺大历史高性能 |
| 导入身份 | 本地实例与节点使用新 UUID，父节点置空；所导入节点作为新的历史起点，保留节点标题与时刻 |
| 隐私含义 | 可续玩的存档包含角色私密状态与历史，接收文件的人能够检查这些数据；角色运行时仍按各自授权经历行动 |

导出只读取不可变节点，在副本上校验后写同目录临时文件，最后原子替换目标；失败或进程中断不替换已有导出。导入只接受固定文件名和规范 Base64，检查大小、清单、SQLite integrity_check、游戏包、事件链与节点 head/tick、Session 完整性及世界投递绑定、世界静止、变量角色集合以及身份种子的角色／世界／前缀。有长期档案时，复用 CoreMemoryAdapter.restoreArchives 校验角色、世界、记忆前缀及完整授权来源；不符则在公布新实例前拒绝。验证使用可丢弃副本，不迁移或改写发送者节点；导入文件中不携带脚本。

导入先写 `instances/.<新UUID>`，完成校验与运行目录准备后 rename 为正式目录，最后沿用 Launcher 原子索引写入；任何现有实例不被覆盖。中途终止可以留下隐藏临时目录或未索引的完整新目录，重试创建另一个独立实例，不自动认领或删除残留。
