## 1. 玩家流程

开始游戏后，打开 Launcher 的“故事线 → 管理”，填写节点名称，点击“保存完整节点”。当前玩家输入或角色调用未结束、NPC 暂停时，保存明确失败，原进度保留。活动可以处于进行中，只要求当次操作已经提交且没有后台写入。

保存短暂冻结新的世界操作，取消未完成的后台长期整理并等待其退出，完成关键会话投递，释放 writer。原线既有长期档案保留；下一次正常整理仍可从保留档案继续。

结束游戏后，选择当前线路历史中的一个完整节点，创建新故事线。首次启动新线会重新整理每个模型角色的记忆，全部必要角色成功后才打开游戏。失败时保留重建标记与已成功的角色档案，重试只继续未完成的角色；原线不变。此标记仅表示“尚不可开始游玩”，不恢复中断的模型任务。

切回原线会恢复原线自己的最新进度和长期认识，不回退原线，也不重复重建。节点列表表示最近保存的完整历史，可能落后于线路的当前进度。

## 2. 保存内容与同一时刻

| 内容 | 来源与恢复 |
| --- | --- |
| 位置、物品、关系、观察与活动 | 节点时刻的完整 World 数据库；沿现有 Event 投影和 activity.updated 恢复 |
| 包变量 | 同一次冻结中的 pack-variables.json；包括各角色私有值，前端仍只看到授权部分 |
| Session、原生派生记忆、Context | 同一次冻结中的既有 SQLite 数据，维持提交绑定及现有完整性检查 |
| 长期认识 | 不复制旧线 memory-core 档案或请求日志；新线按各角色授权 Source 重建 |
| 身份称呼历史 | 从已有角色授权视图提取的名称记录，只保存节点之前的范围 |
| 节点元数据 | 本地 UUID、名称、创建时间、事件位置、tick、现有 packHash、父节点与文件清单 |

保存期间禁止输入、活动操作、逃生操作与新记忆构建；检查无 pending/claimed Round、未终结 Player Input、非 terminal Reaction Cycle、未投递关键 Outbox 和活动 writer lease。SQLite 使用一致 backup，包含 WAL 已提交数据，不拷贝运行中的主文件充当快照。

所有文件先写入不可选择的临时节点目录，最后原子 rename 公布节点。不建立跨库事务或新增事实协议。失败的临时目录可能留在磁盘，但不出现在历史列表。文件清单缺失时拒绝恢复，不静默初始化丢失的变量。

包变量仍是现有独立文件，不改成事件机制；只有新保存节点才有对应的历史变量。过去没有节点副本的游玩轮次不能恢复为完整节点。

## 3. 数据目录与权限

主线沿用已有实例目录，保护已有数据；新线位于实例下 storylines/<本地 UUID>/。每条线路继续运行单分支 Core，沿用原 WorldAddress；线路隔离由独立目录和一次只拥有一个 Core 进程保证。没有启用共享数据库多分支调度。

每条线的 story-nodes/<节点 UUID>/ 是只读使用的完整节点副本。节点目录不会作为正常运行目录打开；恢复只复制节点白名单文件到新的空线路目录，不复制原线的最新状态、凭证、日志或整棵节点树。Launcher 索引保存线路名称、父线、来源节点和当前选中线路。

Launcher 只返回节点标题、来源、进度等公开元数据，不返回数据库内容、角色 Source、私有变量或长期档案。分叉请求只能引用所选线路可达的节点；不接受前端提供任意实例路径。游戏包内容变化仍按已有 packHash 预检拒绝运行。

## 5. 验证边界

新增集成场景在同一个世界中组合钥匙、两房间、两 NPC、变量与未结束的猜数字活动。节点后原线放下钥匙、返回前室、改变变量并产生新秘密；新线恢复节点的全部事件、活动与变量，记忆构建只收到该角色截至节点的授权经历。留守者不获得后室暗号，节点后秘密不进入任何新线角色构建。新线继续提交不会改动原线；重启新线不重复整理。

另验证角色调用期间拒绝保存、角色记忆部分失败后禁止开始并可重试、持久线路选择、拒绝非当前历史节点及非法路径。自动化假模型只证明机械边界，不证明角色自然度；真实模型结果与检查数量由下方验收记录补充。

完整 G3、长历史性能、跨设备分享和原生安装包仍未验收。重建保证来源授权和事件前缀，不能证明模型永远不虚构一个未来细节。

## 7. 完全重建与增量取舍

当前新分叉仍从该节点的全部角色授权 Source 完全重建。短历史实测启动约40秒，用户接受等待与模型调用成本；尚无长历史成本证据，因此暂不引入跨节点增量分叉。中断后已经完成的角色档案可以复用，这只是同一节点重建的失败重试。

将来如果长历史出现明显等待、上下文上限或重复调用成本，再考虑保存节点之前已完成的角色归档，复用其认识并整理剩余授权 Source。不能裁剪原线最新归档冒充过去：事实、总结与观察可能已经混入未来信息。仍复用现有 retainedPrefix，不需要新的记忆框架；但必须先验证归档的来源与节点前缀。

## 8. 进程强制终止验证

测试子进程通过测试专用的文件函数包装停在实际持久化边界；父进程在 Windows 上使用 taskkill /T /F 强制结束该子进程，并重新打开索引与运行目录。生产实现未添加故障注入接口。

| 中断点 | 重启后要求 |
| --- | --- |
| 节点数据库完成、身份文件写到一半、尚未公布 | 半节点不出现在列表，旧节点和原进度完整，能够重新保存 |
| 节点已原子公布、尚未返回确认 | 完整节点保留并可列出，原线可正常重启 |
| 分叉只复制完世界库 | 不写入线路索引，原线仍被选中，重新分叉使用新目录 |
| 分叉完整复制、索引替换之前 | 原线索引完整，未索引的新目录不会自动成为线路 |
| 线路切换索引替换之前／之后 | 分别保留完整旧选择／完整新选择，两条线路都可重新打开 |
| 记忆临时归档写到一半、尚未安装 | 重建标记保留，临时文件不冒充完整归档，重启重新构建 |
| 一个角色归档已安装、另一角色未完成 | 重建标记保留，重启只补未完成角色，全部成功后方可开始 |

测试实际发现并修复：首次刷新视图取得的世界写入租约原先被保持到漫长记忆重建结束；杀进程后立即启动会被未过期租约阻塞。现在重建前调用现有 application.release 释放世界运行实例与租约，角色记忆构建独立读取节点并写派生档案。无需新增恢复协议，也不强行接管其他进程的租约。

各场景核对原线事件、包变量、两角色长期归档内容，并运行相关 SQLite integrity_check；同时验证重启、重新保存或分叉。允许隐藏临时节点、未索引的分叉目录和索引临时文件残留，占用磁盘但不影响选择与重试，不自动删除可能含有数据的目录。这些是进程终止测试，不涵盖断电、磁盘故障或任意指令位置的崩溃。
