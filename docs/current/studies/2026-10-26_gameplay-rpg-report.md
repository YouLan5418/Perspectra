# 只用世界包能做到什么 RPG 战斗

2026-10-26，针对当前源码宿主。结论：**不改宿主，可以用可信包内脚本完成一场有同伴、有资源消耗和胜败奖励的回合战斗。** 这次做出了[遗迹守卫示例包](../../../examples/world-packs/rpg-turn-battle/README.md)，不是只有设计方案。尚未验证真实模型战术、自然对白、浏览器可见体验或发行包兼容性。

## 从一次互动看结果

你点“进入遗迹迎战”，战斗开始。第一轮对守卫使用火球：你消耗 3 MP，守卫由 70 降至 52 HP；澄在自己的处理机会提交火球，守卫降至 34 HP；守卫提交普通攻击，你由 32 降至 20 HP。第二轮你再次施放火球，澄随后击倒守卫；战斗结束，你获得 30 金币。结束状态和奖励在同一笔提交里，不靠角色说“已经打赢”改变数值。

这是实际宿主自动化用例验证的顺序。默认 NPC 策略由包内脚本提供；没有据此声称模型已经学会配合。进入战斗前可以把澄切换到模型模式，仍受同一套回合、目标和资源规则约束。

## 三种机制各负责什么

| 机制 | 本次用途 | 需要作者编程的部分 |
| --- | --- | --- |
| 状态 / 变量 | HP、MP、金币、药水数、遭遇进度、同伴决策模式 | 定义类型和初值；规则返回变化与告知对象 |
| 活动 | 阶段、轮数、换手、参与者、倒下跳过、NPC 调度、结束 | `initialize / policy / resolve / schedule / onOutcome` |
| 交互定义与操作 | 列出普攻、火球、治疗、防御、药水、撤退，声明参数 | 用活动操作或状态脚本实现具体效果；JSON 定义本身不生成战斗算法 |

包内 `autoStart` 检查“已进入遗迹、三人同场、此遭遇没开始过”；开始前菜单也按这些条件过滤。进入遗迹是状态操作，战斗技能是活动操作，不需要增加 Core 动作类型或新的宿主插件。

攻击裁定读取活动 `resolve` 的第六参数 `truth`，计算结果并返回 `status`。宿主将 `activity.updated` 与 `status.updated` 一起提交。HP/MP 不在活动 public 中重复保存，避免出现两份数值。public 中的站立名单、轮序和防御记录只负责本场战斗流程。

角色处理收到自己的活动视图和 `knownStatus`，不能直接拿 `truth`。本例作者显式把三人的 HP/MP 告知三名参与者，使脚本策略和模型都能据此决策；不公开其他人的金币，也没有隐藏属性玩法。`simulate` 返回的也是普通 `perform` 提案，随后接受相同格式校验、活动许可、规则裁定与执行结果续写。

## 实际能力范围

| 玩法 | 当前判断 | 证据边界 |
| --- | --- | --- |
| 固定轮序、多阵营、倒下跳过 | 已做通 2v1 | 不是动态增援或大规模队伍验收 |
| 伤害、治疗、MP、共享消耗品、防御 | 已做通 | 确定性数值，没有命中或暴击抽样 |
| 胜利 / 全灭 / 撤退、一次性奖励 | 已做通 | 单场遭遇；世界中没有通用死亡系统 |
| 暂停、重开进程、继续 | 已做通 | 保存已提交进度，不恢复未完成的模型计算 |
| NPC 脚本策略 | 已做通 | 通过现有角色激活与行动提交，不直接写数据库 |
| NPC 模型决策 | provider 链路已验证 | 本地模拟服务；真实模型的可靠性和耗时待验 |
| 技能、状态效果、速度排序、装备数值、任务奖励 | 原则上可继续写在包内 | 本例未实现，不能列为已验收功能 |
| 战斗血条、站位、动画和选目标体验 | 需要包内前端制作与单独验收 | 默认舞台只是通用活动卡片；本次未制作专用前端 |
| 只填静态 JSON 就自动得到 RPG | 做不到 | 公式、换手与结算目前都要写作者脚本 |

当前上限包括单场最多 8 名 NPC、16 种操作、一个前台活动，以及宿主的角色处理机会和耗时预算。定义技能并不会提高这些上限；也不能把一次模型机会当作一定完成一个行动。

## Evidence → Finding → Path

| Evidence：可复跑依据 | Finding：本次发现 | Path：当前处理 |
| --- | --- | --- |
| [战斗用例](../../../tests/scenarios/rpg-turn-battle.test.ts)的完整两轮胜利，核对每个操作的行动者和事件事务 | 玩家、同伴、敌方可用现有活动链轮流提交；伤害与胜利奖励能同时落地 | 规则留在包内，宿主不增加 RPG 分支 |
| 同一文件的目标错误、满血治疗、空药水、MP 不足、旧版本与非本人回合拒绝 | 菜单可见性和执行权限需要分别验证 | 回合由 policy 筛选，目标与资源由 resolve 重查；失败事件数不变 |
| 注入非法 HP 返回值后，事件总数、活动版本和所有状态不变 | 状态校验失败不会留下已推进的战斗进度 | 沿用现有活动与状态的原子提交 |
| provider 返回防御 / 弃权的用例 | 模型不执行操作时，回合可能停住；重试也不保证推进 | 接受此原型限制，使用现有重试 / 暂停 / 逃生，不强制模型替代行动 |
| [活动桥](../../../desktop/host/pack-activity.ts)、[状态桥](../../../desktop/host/pack-status.ts)、[活动调度](../../../desktop/host/world-runtime.ts) | 同步脚本可裁定游戏，但不应承担异步模型或动画循环 | 继续复用现有角色模型与前端 SDK，不给脚本添加外部运行时 |
