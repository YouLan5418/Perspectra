# 分支组件复用与写权限交接 · 2026-10-30

例如玩家提交一句话后，NPC 接着行动，随后活动与状态脚本结算：宿主需要在这些阶段之间交还世界写权限，但原实现同时销毁整套分支组件，后续读取又重新创建 Store、收件箱、投递和记忆服务。第二轮读取优化后的固定序章末段，一次操作仍挂载四次，打开 SQLite 连接 66 次。本轮保留组件，只交还写租约，减少重复连接和初始化。

前两轮提交已快进合入本地 main，本轮从 `5d28246f8e66c94b513322ac45afc4af6e7ee6b2` 新建 `codex/branch-runtime-reuse`。读取优化的基线与限制见[第二轮记录](2026-10-30_sqlite-activity-performance-round2-report.md)。

## 证据、发现与修改

| 证据 | 发现 | 修改路径 |
| --- | --- | --- |
| E1：同一末段操作创建分支组件四次；每次重新连接世界、会话与记忆库 | 写权限交接与组件销毁绑定，重复创建服务没有玩法收益 | [WorldApplication](../../../packages/application/src/world-application.ts)新增 yieldWriter，保留原分支；既有 release 仍完整释放 |
| E2：NPC、活动脚本需要自己的写租约；外部提交可能留下待处理授权记忆任务 | 不能只保留旧租约，也不能省略原挂载时的记忆同步 | [RoundCoordinator](../../../packages/application/src/round-coordinator.ts)交还租约后，恢复时重新 acquire 并处理 cognitiveJobs；失败则完整释放并报错 |
| E3：常规提交、活动、NPC、状态收尾和末端结算原来使用同一完整释放入口 | 普通阶段交接可以复用，存档与管理操作仍需要显式清理 | [WorldHostCore](../../../desktop/host/world-runtime.ts)六处常规交接改用 yieldWriter；手动存档、逃生和恢复等完整释放路径保留 |
| E4：修改后同一操作重建 0 次，新连接 26 次；历史读取次数和行数一致 | 减少的是组件和连接开销，没有扩大事件缓存或跳过历史校验 | 沿用现有 Cordis 生命周期，最终 dispose 仍关闭全部组件；没有新增连接池、包或持久化格式 |

组件只增加一个临时的“已交还写权限”标记，替代交接时销毁再创建。下次应用访问原分支时恢复写权限；另一写入方仍持有租约、分支已进入维护或记忆同步失败，都返回原错误并清理组件，不抢占或释放他人的租约。

## 不变量与代价

例如 NPC 在交接期间提交一条仅自己可见的观察，应用恢复后会读取对应授权记忆任务；回归检查该文本只进入 NPC 的记忆命名空间。恢复写权限仍由 WriterLeaseService 检查当前分支状态并取得新的 fencingToken，重要事实仍走原规则与短事务提交。保留连接不等于保留 SQLite 事务，也不让模型通过缓存修改权威世界。

常规末端备份仍要求结算与关键投递完成，并归还写租约；备份路径没有改变。手动存档、逃生、维护、隔离恢复与实例关闭继续完整 release／dispose。组件不跨分支地址共享，候选切换与旧节点恢复仍使用各自的运行实例。

代价是挂载分支的数据库句柄和服务对象占用时间更长，空闲时不自动淘汰，直到明确释放或实例关闭；内存和句柄增量没有量化，多分支长时间使用没有压测。恢复时仍要重新取得租约并同步待处理记忆任务，因此没有消除这些必要开销。该样本仍新开连接 26 次、完整读取历史 6 次，长历史成本和完整回合备份成本仍在。本轮没有调整玩法、角色协议或叙事生成。
