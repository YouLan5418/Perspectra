# 新包 45 步序章：单步历史与授权视图复用 · 2026-10-30

当前实现的生命周期、失效条件与维护注意事项见[运行时缓存设计](../architecture/runtime-caches.md)；本页保留当次测量与试验取舍。

例如玩家在 `model-girls-sweet-days` 的序章点一次“继续”，同一步中的活动操作、角色准备、记忆追赶、状态结算、自主判断和刷新，都需要已经提交的世界历史。此前各自查询并解析；本轮让它们在一个宿主操作内共享前缀，提交新事件后只补读尾部。

沿用 `codex/branch-runtime-reuse`，基线为分支复用提交 `5fd5745`。用户提供的新包 45 步剖析是调查线索，没有取得其原始 profiler 文件；以下计数与耗时来自本轮新数据目录复测，不把旧的 112 步官方包或用户提供的累计秒数当成本轮同口径数据。分支连接生命周期见[上一轮](2026-10-30_branch-runtime-reuse-report.md)。

| 证据 | 发现 | 修改路径 |

| E1：新包 45 步共查询事件 686 次、返回 129701 行 | 多个阶段和 Store 实例反复加载同一前缀 | [WorldStore](../../../packages/store-sqlite/src/world-store.ts)新增 withEventReadCache，用现有 readEvents／readEventsRange 接口共享操作内的已解析前缀 |

| E3：记忆追赶和刷新重复构建同一角色视图 | 事件对象完全相同的授权投影可以复用 | [CharacterViewBuilder](../../../packages/store-sqlite/src/character-view.ts)按地址、角色、序号及事件对象逐项相同核对缓存，向调用者返回独立副本 |

`WorldApplication.#integrityGuard` 本身负责捕获完整性错误并隔离分支，不是一个每次扫描历史的验证器；剖析中标在该调用栈下的时间包含它包裹的工作。本轮没有移除它。显式 `verifyBranchIntegrity` 继续绕过共享前缀，直接读取数据库、校验事件链与提交记录。

## 读取边界与代价

例如角色思考期间玩家插话，新事件已经提交，下一次读取仍查询当前世界头；普通追加从已有序号之后补读，旧目标序号仍排除后续事件。头回退或同序号的头 Hash／tick 改变会丢弃该前缀，尾部不能衔接时重新读取。权限过滤、提交前的世界头校验、写租约、fencingToken、规则裁定、SQLite 短事务与备份路径保留。

读取范围由 AsyncLocalStorage 隔离，按规范化绝对文件路径和分支地址区分，内存库按连接区分。事件对象深冻结，返回新数组；调用方需要修改事件内容时必须先复制。独立调用、不在该范围内的稀疏查询仍走原有 SQL 过滤。范围内的首次窄查询可能准备完整前缀，适用于随后本来就需要全史的完整宿主操作。

完成或失败时停用并清空前缀表；即使后台任务继承了异步上下文，结束后再次读取也不会借用过期快照。相同头的已提交历史在一步内视为不可变快照，手工修改旧行不会刷新该步的快照；显式完整性验证仍可立即发现存储与 Hash 不符。该机制不能作为历史文件热替换或修复接口，候选和节点替换仍走原实例关闭与恢复路径。

角色视图缓存只由 Store 返回的不可变事件建立，命中还要逐项核对事件对象及其顺序。返回副本，防止调用者修改自己的视图污染后续读取；地址、角色和旧前缀分别处理。共享的全局原始历史只在宿主内部使用，不直接作为其他角色的授权上下文。

代价是整份已解析前缀驻留到该步完成，增加冻结、头查询、数组筛选和视图复制；峰值内存没有量化。派生视图使用弱键缓存，相关事件不再持有后可回收。路径别名不额外做文件系统去重，可能多读，不合并不同路径的数据。没有新增跨步历史缓存、数据库字段、持久化投影或恢复协议。

## 计数对照

Node 24.14.1，当前 `model-girls-sweet-days` 包，Core 开启、没有长期档案，整理触发阈值 1,000,000；角色与记忆模型均禁止调用。从新目录手动开始 prologue 后测量 45 次 next。初始启动和开始活动不计时，每次完整 WorldHostRuntime.activityAction 包含末端备份和结算。

两版 esbuild bundle 只有 world-runtime.ts、world-store.ts、character-view.ts 三个生产文件不同，其余工作树输入相同。计数通过 SQLite 查询返回行与宿主 JSON.parse 插桩取得；VM 内部自己的 JSON 解析不计入此项，不能等同全部 parseWorldJson 调用。

| --- | ---: | ---: |
| 45 步事件查询次数（含增量） | 686 | 127 |
| 45 步查询返回事件行数 | 129701 | 15119 |
| 45 步宿主 JSON.parse 调用 | 134055 | 19473 |

## 无插桩测量与未完成目标

最终无插桩结果在同目录的 timing 记录中；启动与初始化排除在计时外，一组成对完整序章预热后，三组成对完整序章交替先后顺序运行，测量期间没有并行跑测试。每种实现各有 135 个有效步骤，统计完整序章总耗时、单步中位数与 P95。每次运行使用新目录，包含备份；结果不能保证其他机器或历史长度的延迟。

| 2 | 14418 | 8938 |

| 完整序章中位数 | **14418** | **11957** |

完整序章总耗时中位数降低约 17.1%，进程 CPU 时间中位数约 13547 → 11016ms。三组成对样本中两组更快、一组更慢，机器波动明显；中位数改善不等于每步更快，尤其没有增加该批不超过 300ms 的步骤比例。

候选哈希增量试验没有保留：中间实现的采样里 candidatePrefixHash 累计约 666 → 674ms，深不可变性判定和状态维护抵消了收益。最终 kernel 使用原算法，没有改变 Hash 字节、候选身份或协议。中间实现还测出了额外路径检查和视图复制的成本，最终改为仅规范化绝对路径，并避免先复制事件再复制视图；不能把这些候选实现的计时当作最终结果。

**本轮没有实现与历史长度无关的 300ms 保证。** 每步首次读取与 JSON 校验仍是 O(n)，投影、候选前缀 Hash、Core 材料准备及备份还有增长成本。下一步若要消除增长，需要测量并维护跨步的增量历史／投影；该工作要同时明确节点切换、删除事件、外部写入和修复时的失效边界。本轮只消除同一步的重复工作，不把跨步缓存的复杂度一起引入。
