# SQLite 与活动状态性能优化 · 2026-10-30

玩家点击固定序章的“继续”时，原来活动目录与单活动各自打开数据库查询同一份状态，普通世界读取还会附带审计库初始化。本轮复用活动连接、统一活动缓存并增量读取已提交活动事件；不改变角色决策、权威提交或回合备份。实现位于分支 `codex/sqlite-activity-performance`，尚未合并或重建发行包。

## 证据、发现与修改路径

| 证据 | 发现 | 修改路径 |
| --- | --- | --- |
| E1：原生记忆的常规序章推进打开 146 个连接，其中世界库 88、审计库 45、会话库 6、记忆库 7 | 普通读取反复初始化审计库；活动目录和单活动分别打开世界库 | [WorldStore](../../../packages/store-sqlite/src/world-store.ts)按需创建审计连接；[PackActivities](../../../desktop/host/pack-activities.ts)复用目录所属的世界库连接 |
| E2：缓存命中时查询当前活动 100 次，原来仍打开 400 个连接；修改后没有新连接或事件重读 | 两层状态缓存没有复用读取入口 | 目录维护已提交前缀和各活动最新完整状态，[PackActivity](../../../desktop/host/pack-activity.ts)通过目录读取当前状态；返回值仍独立复制 |
| E3：世界头改变后，原来从序号零读取全部活动更新 | 活动状态重读量随活动历史增长 | 首次恢复读取既有活动更新，之后只查询上一前缀之后的 `activity.updated`；每个活动只保留最新事件 |
| E4：同一第 112 次操作前快照的八组交替测量，中位数从 2511 ms 降到 1976 ms | 本机完整末端回合等待减少约 21.3%，仍有明显波动 | 保留完整备份、记忆捕获、规则和提交，测量外层 WorldHostRuntime.activityAction |

E1 的修改后连接数为世界库 59、审计库 0、会话库 6、记忆库 7，合计 **72**，减少约 50.7%。E1、E2 使用源码插桩，只采用计数，不把插桩耗时作为提速证据。审计连接只影响实际使用 WorldStore 的路径，并非每个直接打开世界库的服务都有审计连接。

审计初始化仍保留原有补链和错误处理；只有创建、激活、分叉等实际审计操作才初始化审计库。审计库出错会在该操作改变世界前失败。普通读取不再因未使用的审计库错误而失败，这是本轮有意接受的报错时机变化。

## 缓存与生命周期边界

例如模型等待期间又有角色发表了合法表达，下次活动读取仍检查最新世界头，并查询新增活动事件；只涉及普通表达时，活动状态可以保持原值。未提交的规则结果不进入活动缓存，提交失败后仍返回原状态。规则裁定使用调用者传入的正式事件前缀，不能把缓存当作写入世界的权限。

缓存替代目录与单活动的重复状态读取，不新增持久化格式或数据库。每个目录保留一个世界库连接和各活动最新完整状态，返回及脚本调用使用独立副本。节点、重新生成和候选切换创建各自的运行实例；[WorldHostCore.close](../../../desktop/host/world-runtime.ts)在关闭应用后释放活动目录，目录加载失败也关闭已打开连接。测试与实验直接拥有活动目录时，同样负责关闭。

单独构造的 PackActivity 仍使用原有局部读取路径。角色授权上下文、模型决策、可用性和记忆视图没有加入跨调用缓存。初次恢复仍读取活动历史；运行实例关闭后缓存丢弃，不恢复未提交计算。

## 对照方法与结果

Node 24.14.1，官方 `model-girls-official` 包，新数据目录；Core 记忆开启但没有长期档案，整理触发阈值为 1,000,000。角色模型指向不可用的本地地址，记忆模型回调禁止调用；没有使用真实模型或 Python 模型服务。

修改前版本取自 `9a77a14e23359323f5a0cf5dfee5d1341714800e` 的四个生产文件：world-store.ts、pack-activity.ts、pack-activities.ts、world-runtime.ts。通过相同 esbuild 配置替换这四个文件构建前后 bundle，其余工作树输入相同，包括本轮开始前已有的修改。没有用整个旧提交与当前工作树混做对照。

先完整运行修改前序章，取得第 112 次“继续”前的正式末端快照。每个样本通过原有 restoreTail 校验并恢复到独立新目录，在计时前启动运行实例，再计量一次完整 activityAction，包含回合前备份和前后收尾。两组预热后，八组成对样本交替运行先后顺序，没有同步运行其他测试。偶数样本的中位数取中间两个值的算术平均。

| 有效样本组 | 修改前 ms | 修改后 ms |
| --- | ---: | ---: |
| 1 | 2791 | 1973 |
| 2 | 2448 | 1979 |

六组更快、两组更慢；21.3% 只代表本机该前缀的中位数变化，不承诺其他存档、磁盘或真实模型回合的固定收益。启动、快照恢复、模型网络等待和 GUI 绘制不在这项计时中。

另一次独立计数中，该 Core 末段操作的完整历史读取仍为 10 次／14809 行；范围读取由 14 次／6015 行降到 12 次／5139 行。完整世界视图、记忆来源和每回合备份仍会随存档增长。分支组件仍可能在一轮中反复创建，本轮没有调整其写租约生命周期。

修改前后还分别从新世界完整运行 112 次“继续”。113 份状态快照（含开始）中的活动 game、revision、玩家转录及 headSeq 一致，事件类型顺序一致；两份最终世界各自通过完整性校验，均为 1484 条事件、222 个提交回合，最终进入 free 且活动结束。完整跑序章期间有其他诊断任务，因此只采用其正确性结果，不比较这两次连续执行的耗时。
