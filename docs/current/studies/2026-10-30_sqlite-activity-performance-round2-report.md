# 同一前缀的历史与视图复用 · 2026-10-30 第二轮

玩家在固定序章末段点“继续”时，第一轮后仍会读取完整历史十次：准备和提交读取同一前缀，角色视图又单独查询这些事件；结束活动后的自动开始与菜单刷新还会为没有 autoStart 的脚本准备完整世界。本轮消除这些实际重复读取，不改变角色协议、调度预算、规则裁定、写租约、原子提交或回合备份。

基线为第一轮提交 `d454640880871e7102dc98fa2f127de7322537e7`，沿用分支 `codex/sqlite-activity-performance`。第一轮数字与限制见[原记录](2026-10-30_sqlite-activity-performance-report.md)，本轮数据不能与不同批次的旧耗时直接相减或连乘。

## 保留的边界与代价

例如角色思考期间玩家又发表了可见新消息，提交时世界头已改变，仍会读取新前缀、检查授权状态并拒绝过期输出。只有同一次决策的前缀未变时才沿用已读历史；下一步和下一回合仍按自己的前缀重新读取。没有新增全局事件缓存或持久化协议，也没有通过缓存更新世界。

角色视图沿用原来的主体过滤、删除事件处理、创建证据与 Hash 计算。复用入口先核对目标前缀没有超出当前世界头，排除目标前缀之后的事件，并复制相关事件，防止返回视图的修改污染原始历史或其他角色视图。这个入口由宿主提供已经从 WorldStore 取得的事件，不是模型或前端可指定事件来源的新接口。

活动只缓存已锁定源脚本是否声明 autoStart，不缓存条件执行结果。没有 hook 的固定名单活动不准备 world；动态选人仍按授权场景生成候选，有 hook 的条件仍重新计算。声明错误类型的 hook 仍走原有失败路径。菜单和玩家场景共享的 ActivityWorld 仅存活于此次同步刷新，活动目录世界头不同就重新读取，授权角色视图不会跨回合复用。

代价是每次借用历史构建角色视图仍进行筛选、复制和投影，活动加载增加一次 hook 声明探测；它们替代重复数据库查询、JSON 解析和无用上下文准备。完整世界历史与记忆来源仍有增长成本。本轮没有调整反复挂载的分支组件，因为其创建和关闭仍绑定写租约，直接延长组件生命会改变写权限交接。

Node 24.14.1，官方 `model-girls-official` 包，Core 开启且没有长期档案，整理触发阈值 1,000,000；不调用真实角色或记忆模型。使用同一 esbuild 配置生成两版 bundle，只有 world-runtime.ts、pack-activity.ts、pack-activities.ts、character-turn.ts、character-view.ts 五个生产文件不同，其余工作树输入相同。
