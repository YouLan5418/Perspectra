# hill-ruins 真实模型试玩：GLM-5.3-Flash

2026-11-08，分支 `feat/rpg-plugin`。模型 `opencode-go/glm-5.3-flash`，经本机网关 `http://127.0.0.1:3495/v1`，记忆为 none。

脚本 [tests/experiments/hill-ruins-live.ts](../../../tests/experiments/hill-ruins-live.ts) 走的是默认界面的路径：说话用 `submit`，按钮用 `perform`。玩家一方按固定剧本走，NPC 一方全由模型决定。一共跑了三局，每局都用新的数据目录。原始记录在 `output/hill-ruins-glm53flash-20261108{,-b,-c}/`，仓库里不保存。

剧本依次是：在客厅邀请澄 → 进遗迹一层打守卫 → 拿钥匙 → 去二层 → 回家 → 跟阿茹说话 → 回卧室睡觉。玩家一方是脚本，所以这里只能看出角色怎样回应，看不出真人玩家玩起来的感受。

## 看到了什么

- **入队是澄自己选的。** 三局里，澄都在玩家邀请的那一轮自己执行了“加入队伍”，台词也自然，比如：“当然愿意！守卫什么的，正好让我试试新学的火球术”。她还会顺手带上桌上的药水。阿茹在三局里都留在家，符合人设，还会把铁剑递给玩家。
- **队伍跟随是自然的。** 玩家进遗迹时澄跟着进来，台词接得上，读起来不像被拖着走。
- **战斗按规则结算。** 写死的开场火球和台词（“小心，它的护甲很硬！”）、第一轮写死的“再来一发！”都照写的执行了。数值、胜负、掉落都由规则裁定。澄的技能选择被这两处写死覆盖了，所以这三局没有测到“模型自己选技能”。
- **信息隔离是对的。** 阿茹视图里的战斗内容，只来自澄回家后亲口讲的那几句（第二局）。第三局澄留在了二层，阿茹看见只有玩家一个人回来，问：“澄是不是还在外头？”这正是她实际看到的情况。
- **数值只在副本显示。** 回到客厅后，状态栏只剩装备和队伍，生命和魔力不显示；进了遗迹才出现。睡一觉能回满。

## 发现并已修复的问题

**问题：胜利的那一击被显示成“玩家把钥匙放下了”。** 第二局里，玩家打出决定胜负的火球后，画面上只有“铁钥匙 已解除个人保管，留在当前场所”，看不到胜利文字。目击者的记录也写着“玩家把钥匙从存放处挪了出来”，连隐藏存放点的地点 ID 都带上了。

**原因：** 记录行动时，程序把这次结算里出现的第一条物品转移当成了行动者本人的物品操作。但活动结果掉落的物品不是她亲手做的，它的 `interactionId` 是这次行动自己的 id。

**修复：** 新增 [`actorTransfer`](../../../packages/application/src/item-effects.ts)，只有不是规则结果的转移才算行动者本人的物品操作。玩家立即行动、协调回合、角色回合三处都改用它。回归测试在 [rpg-perform-path.test.ts](../../../tests/host/rpg-perform-path.test.ts)：没有修复时失败，修复后通过。

第三局确认画面上是“玩家使用火球术，遗迹守卫生命 6 → 0。……敌人全部倒下，战斗胜利。有东西掉在了地上。”。完整检查通过，共 2065 个测试。

## 还没处理的问题

1. **钥匙在队友手里时，玩家过不了锁门。** 第三局里澄先捡起了铁钥匙。玩家去二层被拒绝，澄自己拿着钥匙走了过去，于是自动离队，最后队伍为空。门的条件 `holds` 现在只检查移动的人自己手里有没有钥匙。要不要改成“同行队员拿着也算”，属于玩法设计，需要你决定。
2. **被锁门拒绝时，玩家看不到理由。** 脚本记录里，这次移动没有任何画面文字。默认界面的 `playerFeedback` 会不会显示这条拒绝理由，这次没有核对。
3. **状态栏里的队伍显示是原始 ID。** 队伍一项显示为 `null·队伍=["character:cheng"]`：没有归属者名字，成员也是角色 ID。装备显示为原始 JSON `{}`。这些对玩家都不友好。
4. **模型自己的战斗选择没测到。** 因为写死的台词和技能覆盖了澄的出手，这三局没测到她自己选技能。下次需要一份不写死战斗的配置。
5. **战败流程没有用真实模型跑过。** 战败传送目前只有自动测试覆盖。
