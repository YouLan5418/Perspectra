# M7：最小运行时与完整组合验收

日期：2026-11-05；分支 `fix/activity-notice-and-revision`；上一批 M6 为 `cfbad8a`。依据[迁移计划](../../superpowers/plans/2026-11-04-core-mechanisms-migration.md)与[统一规范](../architecture/plugin-standard.md)。本批完成 M7，并审查了分支上的 M0～M6 提交。

例如 RPG 战斗和狼人杀都用活动机制，各自只带包内脚本；战斗打到一半存档、继续打、再读档，血量和回合都回到存档时的样子。而一个规则或脚本即使声称“杯子从隔壁房间到了我手里”，只要与已提交的托管事实矛盾，就不能进入事件日志。

未发现认知隔离、角色权限或原子提交方面的其他问题。其余提交（活动、通信、自主、知识、角色循环、组合与分享）逐段阅读后未发现需要修改之处；这是阅读结论，不是形式证明。

只新增一个检查函数，没有新增包、事件、数据库、版本或兼容路径。HOST API 仍为 2.8：新检查只拒绝本来会破坏日志的结果，接受范围内的插件行为不变。

### 真实模型

通过本机 8045 网关使用 gemini-3.8-flash，驱动为 [m7-composition-live](../../../tests/experiments/m7-composition-live.ts)，转录在 `.tmp/migration-m7/live-1`、`live-2`。以下是阅读这些转录的判断，每种玩法只跑了一到两次：

| 玩法 | 观察 |
| --- | --- |
| 默认 RP | 三轮回应自然、切题；角色连续以反问收尾，略显重复 |
| 状态市场 | 同伴偷偷塞钱，事件只告知她自己的余额，玩家与第三人未获知；角色说出的余额是自己已知的值。物品归属与叙述一致，同伴移动后他人的说法与事实相符 |
| RPG | 战斗打到胜利，同伴由模型选择行动，台词与伤害结果相符；金币奖励与真值一致 |
| 狼人杀 | 只选活动机制打完一整局。预言家查验结果与实际身份一致；角色有悍跳、数票矛盾分析和归票；在读到的部分未见非狼角色说出只有狼人才知道的信息。长发言只读了开头部分，不是逐字核对，隐私边界以自动化断言为准 |

未做迁移前后同场景的真实模型对照，因此不能声称体验无退化，只能说本轮没有看到明显问题。未用 Core 记忆跑真实模型，也未试其他模型。判断角色自然度还需要用户亲自试玩。

## 验收结论

| 计划要求 | 状态 |
| --- | --- |
| 核心六项边界成立 | 事件记录、原子提交、认知隔离、授权视图、分支一致性、生命周期均有自动化场景；第三方可信插件的行为不在此保证内 |
| 不同玩法只靠选配机制与脚本 | 成立，五种组合未新增宿主分支或私有导入 |
| 真实模型和发布验证分别报告 | 见上，两者都有限制 |

## 有意接受的限制

- 物理检查只覆盖位置与物品。状态值由所选机制经 StatusState 校验；核心不验证任意第三方业务规则是否合理。
- 检查放在即时回合和规则插件层，官方内置规则仍由各自的解析器与交互运行时保证；NPC／收件箱提交路径本身没有再加一层。
- 最小核心是 WorldApplication 加核心函数的程序入口。网页宿主仍需要 scheduler、characterLoop 和模型通道。
- 狼人杀 activity revision 泄露夜间行动人数仍是已接受的限制。
- 分享预检与插件私有文件的范围不变，见[共同契约](../architecture/mechanism-contracts.md)。

剧情导演（扰动器＋节拍器）和通用外部插件持久化世界状态继续暂停。
