# 插件优先运行时：阶段 4 记录

日期：2026-11-03。分支：`feat/plugin-first-phase-4`。[摸底记录](2026-11-plugin-first-phase-4-survey.md)里用户选了方案 B，见[计划](../../superpowers/plans/2026-11-03-plugin-first-phase-4-rules-split.md)。

例如开发者想让前室谁都进不去。[locked-room](../../../examples/host-plugins/locked-room.mjs) 这样做了：玩家走过去被拒，读到“前室的门锁着，进不去”；真实模型下，留守者被叫去前室时也说门锁着，被追问时答“谁也没过去”，没有当作已经进去。

## 改了什么

| 项目 | 结果 |
| --- | --- |
| `ctx.rules` | 新增，可叠加，包在核心规则外面，宿主 API 升到 `1.4` |
| 核心规则来源 | 以前玩家、角色和活动各建一份，现在一个世界实例只有一份（[rule-layers.ts](../../../desktop/host/rule-layers.ts)）。只包角色那一份的话，玩家还是走得进上锁的房间 |
| 拒绝说明 | `reason` 以 `plugin:` 开头时原样读给玩家和角色 |
| 玩法模块 | 由 [world-gameplay.ts](../../../desktop/host/world-gameplay.ts) 持有，每个世界实例一个，留在宿主内 |
| 拆出的文件 | `activity-round`、`autonomy-round`、`round-notices`、`player-input`、`gameplay-projection`、`creator-queries` |
| 没做的 | `ctx.gameplay` 和 `official-gameplay`，原因见摸底记录 |

**和计划不同的一处：** 计划写规则层抛错时这一轮失败并提示插件 ID。实际试了以后发现，玩家回合里抛错会让这一轮停在未完成状态，之后什么输入都进不去。现在改成：抛错时拒绝这次行动，可选项不变，错误写到标准错误。这样规则不会被绕过，世界也不会卡住。

## 真实模型试玩（2026-11-03）

本机 8045，`gemini-3.8-flash`，思考强度 low。`main`（`bf5370c`）和本分支同时跑。

| 场景 | `main` | 本分支 |
| --- | --- | --- |
| `dynamic-scheduling` Core，8 轮加一次整理 | 整理完成 3，失败 0；14 次决策；记得“怕黑”和“不会游泳” | 整理完成 3，失败 0；23 次决策；同样记得 |
| 甜蜜日程，走完序章后自由对话（脚本逐步推进序章，没有经过舞台的自动播放） | 50 步，21 次决策，无错误 | 50 步，22 次决策，无错误 |
| 状态市场短局 | 9 次决策，无错误 | 13 次决策，无错误 |
| 狼人杀一局 | 打完，好人胜，34 次决策 | 打完，好人胜，40 次决策 |

- **决策次数：** 本分支都偏多，阶段 3 的 Core 对比也是 14 比 22。我查了 Core 这局，差别来自第一轮模型的回答：同行者如果留在前室，之后每轮多两个角色回应；`main` 那局同行者很快走了。请求逐字相同，调度的入参也没变。而且这次 `main` 已经包含阶段 3 的代码，阶段 3 时同样的代码跑出 22 次，这次跑出 14 次，阶段 2 同一场景是 24 次；阶段 3 的狼人杀反而是分支更少。所以这是模型回答带来的差异，不是改动造成的。这个判断没有多次重复验证。
- **角色表现：** 甜蜜日程里三位女主都有自己的性格，聊天和接话都自然。这是第一次走完序章做对比。
- **局限：** 每个场景只有一次样本，不能代替完整体验验收。

## 独立审查

由 Opus 审查（Fable 额度不足）。移动的代码逐段对照，没有发现顺序、守卫或副作用的变化，也认同抛错时拒绝的做法。发现 3 个重要问题：

- **活动里读不到插件的说明：** 玩家在允许移动的活动里被规则拒绝时，只看到通用提示。已修复，先写失败测试。我原来的活动测试只看发言，掩盖了这个问题。
- **文档夸大了覆盖范围：** 状态操作、活动操作和短信不经过规则层。文档和 SDK 注释已改准确，行为没有改，要不要让规则管这些路径留给用户决定。
- **拒绝角色发言算作这一轮失败：** 记为已知限制，指南建议只拒绝移动和互动。等真有人要写禁言规则再改。

## 接受的限制

- 规则是同步的，不能调用模型或网络。规则要是确定的，宿主不检查。
- 规则只管发言、移动和核心互动，不管状态操作、活动操作和短信。
- 拒绝角色发言算作这一轮失败。
- 规则层出错时只拒绝行动，玩家读到的提示里有插件 ID，详细错误只在标准错误。
- 没有清单的规则插件被跳过时，世界照常打开，规则不生效。
- 第三方不能替换整个活动或状态系统。
- 自主预算留在宿主内，没有进 `official-scheduler`。

## 后续判断

- **阶段 5** 是让这些接缝真正可用的一步：世界包声明依赖、Launcher 选配和校验、存档记录。现在装插件要手填路径，也看不出谁替换了什么。
- **真实第三方插件** 仍只有模型通道和规则各一个示例，记忆和决策还没有。
- **总装配** 还能再拆，但剩下的和生命周期绑得紧，收益在变小。没有具体痛点时不建议继续。
