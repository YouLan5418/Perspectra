# 插件优先运行时：阶段 5 记录

日期：2026-11-03。分支：`feat/plugin-first-phase-5`。见[计划](../../superpowers/plans/2026-11-03-plugin-first-phase-5-launcher.md)。

例如创作者做了一个世界包，要靠 `locked-room` 插件才讲得通。玩家没装插件就点开始，启动器说“这个世界包需要的插件有问题：缺少插件 locked-room（需要 ^0.1.0）”，世界不打开。装上并启用后进入世界，走向上锁的房间被拒，读到“前室的门锁着，进不去”。之后卸载插件再打开这个存档，玩家读到“这个存档使用的模块变了：世界规则：locked-room 0.1.0 → 无。世界事实不受影响。”

## 改了什么

| 项目 | 结果 |
| --- | --- |
| 世界包依赖 | `worldpack.source.json` 可选 `requiresPlugins`，启动器开局前和游戏进程启动时都查，一次列全 |
| 插件清单 | 新增可选的稳定 `id`，依赖按它匹配。示例插件都加上了 |
| 插件页 | 按用户给的 DSH 截图改成搜索框、可折叠分组、双列卡片。“模块”分组列出五个接缝当前生效的实现，有多个候选时可以选 |
| 存档记录 | 存档目录写 `plugin-set.json`，记录实际生效的模块，变了就提示，不阻止 |
| Python 检查 | 启用了提供 `memory` 的插件时，启动器不再要求 Python |
| 作者文档 | 新增[插件能替换什么](../guides/plugin-seams.md) |

**和计划不同的一处：** 计划在原设置页加一块“模块”。用户中途给了 DSH 的界面作参考，于是把整个插件页换成卡片式。

## 设计里有但没做的

用户在开工前同意了这三项不做，因为现在没有实际插件需要：

- 插件路由 `/plugins/<插件 ID>/`
- 写入事件日志的私有记录 `plugin:<插件 ID>/<记录名>`
- 节点、分叉和重新生成时复制 `plugins/<插件 ID>/`。重新生成已经按记忆接缝复制数据目录；节点仍然靠 `snapshotArchives`

## 真实流程查出的缺陷

世界包只要声明 `requiresPlugins`，世界就打不开，报 `worldpack.json/packHash: does not match the compiled v5 envelope content`。原因是打开世界时要重新解析编译产物，解析器接受了这个字段，返回时却丢了，重算的哈希对不上。

自动测试没发现，因为它们走到依赖检查就停了，没有真正打开过这样的世界。启动器把这个错误显示成笼统的“Core 初始化失败；请检查包、存档及本机记忆依赖”，所以玩家和创作者都看不出原因。

已修复，加了回归测试。笼统的错误提示没有改，它是既有行为。

## 验证

**打包后的后端（`desktop:build` 产物 `dist/backend/playtest.mjs`）：**

- `HCW_TEST_DESKTOP_BUNDLE=1` 下 `desktop-launch` 测试通过。
- 把 `simple-llm` 和 `locked-room` 复制到仓库外的目录加载，模型用本机 8045 的 `gemini-3.8-flash`。官方模型地址故意指向一个不通的端口，所以角色的回答只可能来自插件。

| 操作 | 结果 |
| --- | --- |
| 看可选目的地 | 前室不在其中 |
| 走向前室 | 被拒，读到“前屋的门锁着，进不去” |
| 说“你好，今天过得怎么样？” | 角色抬起头回答“你好。还算平静，我正在翻看之前的笔记……” |
| 卸载 `locked-room` 后重开 | 读到模块变化提示；再走向前室成功，角色说“来了。” |

另用一个放在仓库外、`import { Service } from '@deepseek-ai/cordis'` 的插件试了同一个构建：能定义并注入自己的服务，`ctx.scheduler instanceof Service` 为真，说明插件和宿主用的是同一份 Cordis。

这次构建早于下面那个缺陷的修复，打包产物没有打开过声明了 `requiresPlugins` 的世界包；Launcher 流程用的是源码入口。

**Launcher 流程（真实 `LauncherCore` 和真实游戏进程，Core 记忆，同样的模型）：**

| 步骤 | 结果 |
| --- | --- |
| 读插件清单 | 不执行代码，拿到 ID、版本和配置项 |
| 没有插件就开始 | 拒绝，“缺少插件 locked-room（需要 ^0.1.0）” |
| 添加但不启用 | 拒绝，“插件 locked-room 没有启用或加载失败（需要 ^0.1.0）” |
| 启用 | 进入世界，可选依赖 `not-there` 只给提示 |
| 走向上锁的房间 | 被拒，说明原样读给玩家 |
| `plugin-set.json` | `official-llm`、`official-memory-core`、`official-scheduler`、`locked-room 0.1.0` |

**插件页：** 在开发页面用模拟数据看过深浅色、窄屏、搜索、无结果提示、折叠、添加和移除、展开配置、冲突选择。

**自动测试：** 依赖版本匹配、一次列全、配置无效被跳过的插件不算生效、Launcher 拒绝、编译产物往返、模块列表和选择、存档记录的变化提示、损坏文件、候选不写记录、卸载后重开。决策探针与阶段 4 的基线逐字相同。

## 没有验证的

- **桌面版窗口。** 没有重建并点过 Tauri 窗口。添加插件要过系统文件对话框，这一阶段没有改 Rust。所以卡片页只在浏览器里看过，WebView2 里没看过。现有的 `src-tauri/target/release` 里的程序是旧构建，不包含这一页。
- **发行包。** 没有重建。
- **从节点或分享开新故事线时缺插件。** 和开局共用一个检查，没有单独走过。
- **第三方记忆和决策插件。** 仍然只用测试替身验证。

## 接受的限制

- 没有清单的插件能注册接缝，但插件页显示不出来，也满足不了依赖。
- 插件页显示的是清单声明，实际是否注册要运行才知道。一个声明了 `memory` 却没注册的插件，页面会说它提供记忆，世界实际用官方的。
- 两个调度器同时启用又没处理时，后加载的被跳过，和页面显示一致。
- 依赖的版本写法不支持预发布段（`1.0.0-beta`），只有 `1.2.3`、`^1.2.3`、`>=1.2.3`。
