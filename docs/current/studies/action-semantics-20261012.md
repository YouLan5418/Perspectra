# 当前操作的语义说明实验（2026-10-12）

角色希望回旅馆，工具只给出 perform → move → location:inn 时，可能没有把意图与具体操作联系起来。本次在[即时行动提示实验](action-intent-prompt-20261012.md)基础上，将现有操作渲染成模型可读的语义说明，不增加能力或从台词推导动作。

## 源码与权限边界

例如原选项包含旅馆时，模型输入额外展示：

```json
{
  "meaning": "前往旅馆",
  "description": "你现在可以请求离开档案室，实际移动到旅馆。成功后，你的位置会发生变化；不表示其他人与你同行。",
  "operation": {
    "decision": "perform",
    "actionType": "move",
    "parameters": {"locationId": "location:inn"}
  }
}
```

[character-action-explanations.ts](../../../packages/provider-chat/src/character-action-explanations.ts)只读取本次已授权 Context 的 affordances、在场人物和当前可见物品，确定性生成 actionExplanations。移动名称取实际提供的 destinations；当前位置名称由 Character Turn 使用本人当前 locationId 从现有 manifest 取出，不查询其他人物的位置或知识。历史重放没有记录当前位置名称时，用“当前位置”，不从 ID 猜测名字。

基础 base:take/give/drop version 1 使用与已有权威定义含义一致的本地文案模板，分别说明纳入保管、交由当前选项指定接收者保管、解除个人保管并留在当前位置。不是分析任意 ID 来猜行为。未知定义及不同版本只引用其定义身份，保留参数契约，不编造治疗、消耗、关系或其他效果。没有引入新的作者语义字段；自定义玩法的人类语义尚不能自动完整生成。

[character-context-text.ts](../../../packages/provider-chat/src/character-context-text.ts)仅在本次 canPerform 允许且确有现有选项时加入说明。保留原 affordances 和工具 Schema；operation 复制对应原选项的请求参数，不能当成成功保证或新的工具字段。执行仍通过 Action / Rulebook / Event；失败路径、预算及 publish 结束激活行为未改变。表达后继续决策保持关闭。

没有动作选项时不从“看得见物品”反推出可拿取能力；不使用 items.lastObserved 推测现在的归属；不查全局实体或其他角色私密上下文。语义说明只是呈现，不能改变当前候选权限、规则裁定或提交事实。

## 对照方法

本机 8045、gemini-3.8-flash。先重放此前实际提供 perform 的 9 个计划表达时刻，各请求无说明/有说明一次，共 18 次，保留各时刻 low/medium/high 强度、授权上下文、工具 Schema 与温度，统一 max_tokens 32768，部分交换请求顺序。两版都保留独立角色和即时行动提示，区别仅在系统解释段落与依据本次选项生成的 actionExplanations。重放仅产生可见提案，零世界提交，不能用 perform 提案证明实际行动成功。

随后用 [构建脚本](../../../tests/experiments/interaction-continuity-build.mjs)的 `--action-semantics` 运行新旧各 8 回合 D3 原件缺失、12 回合 E 材料协作，共 40 回合；固定 low，同一玩家策略、调度顺序、目标、预算、超时、初始状态与输出上限。当前场所名称在两版都有，排除名称本身成为额外变量。baseline 关闭说明生成及其解释段落，其他生产代码相同。源码与可执行文件内容身份保存在 build.json；辅助说明模块内容另记，运行中不依赖随后编辑的源码。

本地证据：`output/interaction-continuity/semantic-replay-qiVOzb/` 与 `output/interaction-continuity/comparison-SbUORT/`。只保存授权请求、可见工具输出、用量和耗时，不记录隐藏思考正文。历史试玩目录未使用，发行包未重建。

## 实测结果

### 固定上下文配对

无说明组 1 次 perform、8 次 publish；有说明组 4 次 perform、5 次 publish。3 对从表达变成行动，零对反向变化：原件缺失后回旅馆（low）、medium E r7 去找玩家、表达循环关闭组 E r7 去与玩家汇合，分别实际提出了既有 move 请求。两版都已提供同一动作 Schema，不能把这个差异解释成新增了动作权限。

三个 high 时刻仍选择表达，包括提议回旅馆与说要取原件。说明组另有一次 scene_public 同时填写 addresseeIds 的格式错误，没有修正重试或将它提交。不是所有提案均有效，也不能把正常邀请等同于失败。18 次请求均 HTTP 200；无说明/有说明累计耗时 141.8 / 113.6 秒，total_tokens 73930 / 78340，零世界提交。

### 完整低强度轨迹

| 场景 | 无 / 有说明调用数 | 无 / 有说明累计等待秒 | 无 / 有说明 total_tokens |
| --- | ---: | ---: | ---: |
| D3，8 回合 | 20 / 22 | 85.0 / 91.0 | 71809 / 92075 |
| E，12 回合 | 34 / 33 | 139.5 / 142.2 | 176041 / 220164 |
| 合计，各 20 回合 | 54 / 55 | 224.6 / 233.2 | 247850 / 312239 |

完整对照 40 回合、109 次实际调用；加重放共 127 次请求、712359 total_tokens。完整组无错误回合、无非 200 请求；无说明组两次格式修正成功，有说明组零次修正、一次过时候选被丢弃。当前样本的有说明组总 Token 比无说明组增加约 26%，等待增加约 3.8%，不是稳定成本或性能结论。

[审计](../../../tests/experiments/interaction-continuity-audit.py)通过四个世界的每回合 SQLite 完整性、提交重放、观察及记忆来源、私密标记、转移事件、真实 HTTP 计账、相同配置与初始状态。说明组 42 次请求带 150 条说明；逐条核对 operation 只能复制该请求实际 destinations 或完整 interaction 参数，同时核对选项覆盖，不添加目标、定义、绑定或参数，不在禁止 perform 的请求暴露动作。无说明组没有该字段。人工阅读 19 次移动成功后的模型响应（含一次格式修正），未见凭空加入缺席同行者；不把未发表的错误候选当作已提交表现。

- D3 有说明组仍第 1 回合去档案室、第 3 回合回旅馆。第 5 回合竞争者提出引路，第 6 回合正式返回档案室，第 7 回合患者也实际去了；无说明组二者最后留在旅馆。因此模型能作出更多实际操作，但竞争者重复寻找缺失原件，且继续补造卷宗分类、值守人与借阅登记等线索，不能评价为总体计划更好。原件始终由玩家保管。
- E 有说明组第 5 回合玩家与患者请求查验/交付后，竞争者真正执行 base:give，将备用材料转给患者（seq 147）；无说明组在患者第 9 回合提出分管后也执行同一交付（seq 233）。两版最终物品状态一致，主份由竞争者保管，备用份由患者保管。无说明组玩家未触发正式交付请求，有说明组在 r5/r6 触发，实际输入分岔；不能将“早四回合”全归因于说明。
- E 有说明组患者第 7 回合先表达失陪，第 8 回合才正式移动教会，当次表达实际提供 move。这项先说后做的停顿依然存在，说明不是立即行动的保证。
- 自主表达仍可正常选择。患者后期停止追赶反复移动的玩家，竞争者保留主份材料并等待协商；不把沉默、保留资源或拒绝自动计为模型失误。两版仍有未经包声明的具体三日流程被续接，说明层没有解决叙事事实一致性；包没有可执行治疗，不能把协商流程算作完成治疗。

当前结论：该呈现层出现了比只加即时行动文字更明确的积极样例，值得作为实验保留；但不同次模型抽样的基线自身也会变化，不能直接把两轮实验的 perform 比例当作严格横向优劣。它帮助辨认可用操作的迹象，不构成稳定决策提升、目标重选或完整玩法验收。未增加预算、模型阶段或自动执行计划的机制。

## 验证边界

每个固定时刻、每种完整场景条件仍只有一次模型响应或一条轨迹。语义更易读并不意味着因果改善已被证明；随机性、网关缓存和负载仍可能影响结果。完整轨迹的实际玩家输入会随角色选择分岔，沿用脚本的有限材料措辞匹配也会影响正式交付请求是否发出。

邀请同行、等待答复、拒绝或沉默可以合理；只在实际提供对应操作时评价行动选择，另行核对提案是否被丢弃及之后是否执行。不存在的治疗操作或未声明目的地，不能被当成模型忽略可用动作的证据。机械权限与提交核验不代替自由文本、知识来源及后续角色信念的语义验收。

类型检查、Lint、相关 8 文件 110 项测试通过，包括说明不扩大目标集合、保留原请求参数、关闭 perform 时不提供说明、未知定义不猜效果及原有执行/自主行为边界。未运行全仓测试、桌面界面或长期玩法验收。
