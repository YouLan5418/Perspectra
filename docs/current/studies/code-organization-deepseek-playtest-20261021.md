# 代码整理后的 DeepSeek 官方真实试玩（2026-10-21）

同行者实际拿到钥匙后再表示保管，收到玩家请求后也实际交回；私下约定的暗号在换房间、Core 整理和进程重开后仍能回答，留守者则表示不知道。启动、角色回合、活动、记忆整理、保存重开及候选生成在这次样本中均跑通。

仍发现一处叙事与事实不一致：留守者只用 publish 描写拿起并准备保管保温壶，当时没有对应的权威转移。不能把这次试玩写成“没有体验问题”，也没有同模型基点对照来证明这个问题由代码整理引入。

用户切换到官方 API 前的 OpenCode 失败样本单独保留，不计入以下数量。

## 请求与实际结果

| 范围 | 模型请求 | 结果 |
| --- | ---: | --- |
| 条件知识场景，19 个步骤 | 38 | 全部 HTTP 200；返回模型均为 `deepseek-flash` |
| 浏览器实例，10 次玩家输入及一次重新生成 | 28 | 全部 HTTP 200，无运行时错误 |
| 两个角色的实际 Core 整理 | 6 | Retain / Group / Consolidate 各两次，全部 HTTP 200，无重试 |
| 合计 | **72** | **72 次成功**；模型目录、页面轮询等非生成请求不计入 |

浏览器记录按两个候选的 request record ID 去重。只查询当前选中的候选会看到 27 条，不能据此漏掉另一个候选的真实调用。

- **知识与状态：** 38 次实际知识选择全部符合独立预期，越权活动知识交付为 0。同行者先承认旧余额不确定，实际查看后才报告 130；活动中解释自己的纸签，未交付玩家纸签和内部答案。纸签内容仍有模型自行扩写，选择正确不证明其每一句来源表达都准确。
- **私语隔离：** 浏览器实例中，留守者的 13 次角色请求均未包含虚构暗号“青瓷茶”。同行者多次通过 private 发表向玩家复述，留守者在整理前、重开后及重新生成的候选里都表示不知道。没有把旁观者获知“发生私下交流”当成获知交流正文。
- **重要状态：** 同行者拿取钥匙、交还玩家，留守者后续实际取得保温壶，以及跨房间移动都走既有规则。最终钥匙由玩家保管，保温壶由留守者保管。
- **Core 整理：** 两个角色均成功安装前缀 174 的档案，约 15.3 秒完成。同行者为 43 条 facts、13 个 episodes、6 条 observations；留守者为 32 条 facts、4 个 episodes、0 条 observations。没有把空 observations 当成存储失败。
- **保存重开：** 浏览器保存“官方Flash试玩-整理后”节点，headSeq 为 185。停止测试后端并打开同一实例后，转录、角色位置、物品状态逐项完全一致，两份 Core 档案前缀仍为 174；继续真实对话无错误。
- **末端候选：** 实际重新生成一次，约 2.56 秒完成；通过 API 切回原候选，再在浏览器点“下一个候选”切到第二份，界面显示 2/2，物品状态保持正确。

条件场景单请求耗时中位数 1.076 秒、P95 1.753 秒；浏览器角色请求中位数 1.147 秒、P95 1.598 秒。一次玩家输入可能串接多个角色调用，冷 Core 回忆的整轮等待约 7—8 秒；这些是本次样本记录，没有性能 A/B。

## 仍需处理的体验问题

### P2：叙述取得保管，缺少对应执行

浏览器第一轮，留守者在 seq42 的 publish 中描写把保温壶拿起来，随后说准备先拿着、路上使用。当时创作者真值仍是 `holderId: null`、`locationId: location:front-room`，只有钥匙发生了转移。这里后续“先拿着使用”的表达已经超出单纯触碰或短暂托起查看。

下一次单独问同行者保管情况时，seq58 正确回答保温壶还在桌上、没人拿；再下一轮留守者才实际 perform，seq75 出现权威拿取回执。样本中没有观察到其他角色持续采用错误保管状态，但玩家已经收到过一次误导性表现。程序没有改错数据库不能替代这部分体验验收。

| 证据 | 结论 | 后续定位入口 |
| --- | --- | --- |
| `after-ui-state.json` 的 seq42，与 `creator-before-followup.json` 的保温壶状态 | publish 表现与已裁定保管状态不一致 | [角色回合](../../../packages/application/src/character-turn.ts)、[模型上下文呈现](../../../packages/provider-chat/src/character-context-text.ts) |
| `turns.json` 中 seq58、seq75 | 后续角色能依据真值纠正；实际转移仍需 perform | [物品交互](../../../packages/interactions-basic)、[世界宿主](../../../desktop/host/world-runtime.ts) |

建议下一步先围绕这个具体场景做最小复核，区分临时触碰、实际保管与承诺表达；本轮没有追加语义模型、过滤阶段或动作枚举。

另外，角色仍会重复确认钥匙、柜子和“慢慢看”，数轮触及反应预算；模型也会把作者背景说成已经确认的经历，或自行扩写场景细节。没有同模型整理前对照，不能认定这些由本轮改名或包入口调整引起。示例没有两名角色的专用立绘，浏览器出现相应 404 后显示文字占位；未观察到脚本异常。
