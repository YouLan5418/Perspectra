# 活动与通信：回退及分享节点验证

分支 `codex/cross-scene-communication`，2026-10-10。沿用[活动组合实验](cross-scene-activity-20261010.md)：玩家和同行者在前室玩猜数，玩家与后室角色通信。保存节点后，玩家发送新的暗号、推进游戏，并在电话场景中挂断；从旧节点创建新故事线或导入分享后，角色应只保留节点前的经历。

## 接通范围

[实验运行时](../../../tests/experiments/cross-scene-runtime.ts)增加显式 storyNodes 选项，采用现有网页存档的地址及 Session SQLite 布局，复用原有 saveStoryNode、restoreStoryNode、exportStoryNode 和 importStoryNode。没有修改桌面快照／分享实现、容器格式或 Manifest 版本。

保存时等待实验入口的行动和角色处理结束，将每个角色的原生记忆捕获到当前提交前缀，再保存完整数据库节点。模型激活期间拒绝保存；保存期间阻止入口继续行动。测试与脚本使用 activate 包装入口；直接调用内部 turn 或 activities 对象的调研代码仍须自行等待其操作完成，不是公开并发宿主接口。

“静止节点”表示没有正在执行的模型处理或世界写入，并不要求电话必须结束。响铃或接通状态都是已提交事实，可以保存。恢复后从节点内的事件重建通话状态，不自动重放旧激活；收到新的输入后才能继续处理。

本页记录原生 CognitiveMemoryService 验证：本地回退恢复节点的原生记忆数据库，分享则按既有文件白名单排除派生记忆。首次打开从各角色有权获得的节点前观察重建原生记忆，确认 packHash 和 headSeq 一致后才移除 rebuild-memory.json。标记不一致时失败并保留恢复门禁。后续入口增加了显式 Core 选项，见[Core 验证记录](cross-scene-core-memory-20261010.md)；原生模式仍拒绝非空 Core 快照或身份别名。

## 自动验证

[七项回归](../../../tests/prototype/cross-scene-story-nodes.test.ts)实际使用 SQLite 快照及既有分享文件，而非只调整 UI 指针：

- 短信与接通电话分别回退，恢复全部事件到节点提交前缀，活动 ID、修订号、轮次一致，电话恢复为 connected。
- 回退后可续信／续话；挂断后再次传话被拒绝；原故事线仍保留后来消息、挂断和游戏进度。
- 短信与电话分别导出所选旧节点、导入独立实例。分享只包含 world.sqlite、session.sqlite、memory-aliases.json；样例没有包变量脚本。原生记忆缓存、Context 和后来消息不进入文件。
- 导入后实际调用原生 Recall：收信者能检索“青灯”，不能检索后来暗号“鸢尾”；短信旁观者不能检索私信，电话旁观者不能检索远端私密声音。本端声音属于现场授权信息，不能误判成泄漏。
- 同一分享再次导入得到另一个实例 ID，两次导入分别从原节点开始；接收者续写不改变发送者的事件。
- 未接听电话也能分享恢复为 ringing，不自动调用模型；未接听时传话仍被拒绝。
- 模型尚在执行时不发布可选节点；恢复前缀错误时不调用模型、不移除恢复标记。

最终相关检查：节点组合、活动组合、电话、短信、既有故事节点与 Cognitive Context，共 6 文件 42 项全部通过。类型检查、Lint 和文档链接检查通过。本轮没有重跑全仓默认 check，也没有增加强杀恢复测试；本次没有改变底层事务或快照发布边界。

## 真实模型结果

使用用户指定的 8046 / gemini-3.8-flash。两个独立短场景均为 passed：

| 场景 | 保存前缀 | 原实例后来前缀 | 分享实例续写前缀 | 恢复后的真实回答 |
| --- | --- | --- | --- | --- |
| 短信 | 34 | 49 | 44 | 回退和分享后均通过短信回答“青灯。” |
| 电话 | 52 | 74 | 63 | 回退后通过电话回答“是青灯。”；分享后回答“你刚才说是青灯。” |

短信数据在 `output/experiments/nodes-sms-gemini38-20261010-01`，电话数据在 `output/experiments/nodes-phone-gemini38-20261010-01`。report.json 保存操作结果、节点信息、观察和提交前缀；decisions.jsonl 保存有界模型决策，不保存 Provider 请求信封或凭证。

两次脚本都在通信节点之后发送“鸢尾”、推进猜数游戏；电话还在原线挂断。回退和导入打开时，脚本逐项比较全部事件与保存节点相等、活动完整状态相等，并确认收信观察没有“鸢尾”。电话恢复到 connected 后直接续话，没有重新拨号或接听。导入续写后重新打开原线，其事件仍与原未来完全相同。实际回答表明角色可以继续使用节点前通信经历，不能推广为所有长时记忆的体验证明。

## 复现及限制

在仓库根目录运行并使用新目录：

```powershell
node --import tsx tests/experiments/cross-scene-nodes-live.ts output/experiments/my-sms-nodes sms
node --import tsx tests/experiments/cross-scene-nodes-live.ts output/experiments/my-phone-nodes phone
```

电话角色可以自主拒接；未接通样本不会被计为接通节点验收。回退采用从不可变节点创建新目录的既有方式，保留原故事线未来。分享只验证单节点、本机不同目录和同一世界包的独立续写。

默认网页、Launcher、发行包仍未安装通信规则。分享文件可经现有导出／导入函数验证，但通信续玩需要本实验宿主及相同的 phone／activities／storyNodes 选项，不宣称普通 Launcher 已能运行电话节点。Core 的验证范围在后续记录中单独说明；跨机器传输、长时间连续通话和通信节点强制断电恢复尚未验证。

分享保留继续世界所需的角色私密事件；文件接收者可以查看其数据库。角色运行时仍只依据各自授权观察和记忆行动，运行时认知隔离不等于分享文件加密。
