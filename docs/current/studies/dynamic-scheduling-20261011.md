# 动态调度与玩家插话实验 · 2026-10-11

后续[自主目标与动态调度组合实测](autonomy-scheduling-20261011.md)记录了真实串行/动态对照的 60 次请求及 usage，并新增双向移动冲突回归。[自主机会接入记录](autonomy-dynamic-dispatch-20261011.md)进一步取消普通与自主启动间的屏障，当前符合条件的入口将两类机会及后续反应放进同一个队列。

玩家在前室与同行者说话，后室角色因自己收到的授权观察开始处理。后室模型调用尚未返回时，前室角色提交了回应，并让另一位在场角色获得新观察；调度器可以立刻启动下一次前室处理，不必等后室任务结束。玩家也可在公开允许插话的 NPC 阶段提交下一句话；当前未提交计算会取消，上一轮结算后再受理。

实验分支：`codex/dynamic-scheduling-experiment`。源码机制、受控假服务对比、自动回归和本机浏览器 DOM 合成验证已通过；7 文件／116 项集成复跑用时 105.55 秒。2026-10-11 使用 8045 的 Gemini 3.8 Flash 完成真实模型短测，覆盖前台独立推进、玩家插话和末端重新生成；长试玩与发行包尚未验收。本页区分源码能力、自动证据、真实体验和发行状态。

## 动态派发机制

- 普通反应从已提交的 `observation.upsert` 选择角色；调度机会只来自各角色有权收到的观察。新事件提交后立即刷新候选，空闲调用名额可接着派发，不等待整波完成。
- 默认最多同时有两个角色进行模型计算；调度优先考虑玩家当前场景，场外最多有一个在途任务。同一地点角色和同一角色不并行。就绪任务优先顺序是当前场景、连续 stale 次数较少、已完成激活次数较少；同级随机排序。
- 每次派发前先预留模型调用预算。根观察属于第一层因果深度；角色提交后带来的新授权观察增加深度。合并同一角色的待处理观察时保留最深因果深度；例如深度 3 的观察不会被后来深度 2 的观察降浅，因而不能借浅层观察派生越过上限的下一层激活。配置的最大波次限制因果深度，不再是批次之间的屏障；超限观察仍以 `wave_limit` 收束。角色激活次数、总调用数及周期期限仍限制任务总量。
- 活动与同地点处理继续串行。后续接入的自主候选共用动态并发槽位与地点互斥，预算分别记账；详见[自主接入记录](autonomy-dynamic-dispatch-20261011.md)。

动态模式只在普通路径启用：宿主未加载 `variables.js`，没有活动参与者调度，也未启用 `publicationAudit`。命令行 `--serial-scheduling` 关闭动态路径，可用于与串行结果对照。任一条件不满足时使用原有串行调度。

## 计算、过期与提交

角色准备自己的当前 view、认知、观察、可见物品、场景成员及 affordances 后调用模型。等待模型时不占世界写租约。模型返回时先比较授权投影；进入进程内提交队列后再取得写租约、读取最新 world head，并在持有租约时再次检查该角色投影。检查不一致会返回 `stale` 且不提交；租约在成功提交或 stale 返回时释放。随后按最新事件前缀执行 Rulebook 并原子提交；世界状态仍由 Action / Rulebook / Event 路径决定。

并行期间世界全局事件序号可能前进。过期检查比较角色自己的授权 view、认知、当前可见角色、可见物品和 affordances；单独的全局序号变化不会废弃结果。该比较针对角色授权投影，不对完整模型请求逐字求 hash。由全局 tick 变化的 sourceAgeTicks 属于相对时间信息，不单独令角色状态过期；提交时仍依据最新世界前缀重新运行 Rulebook。授权投影改变时，旧输出标记为过期，不按原上下文发布；调度器对该角色最多自动重算一次，第二次连续 stale 后停止该角色本轮，后续新观察也不再派发给它。stale 尝试消耗总模型调用预算，但不增加已完成激活次数；角色完成一次非 stale 结果后清零连续 stale 计数。角色 lifecycle 已非 active 时返回 `inactive`，只停止该角色，不把整周期标记为 `interrupted`。若旧轮的受控行动已经提交、只有结果续写过期，续写以真实提交结果作为 `continuationOf`；再次 stale 时可丢弃未提交的续写，不会重放或撤销已提交行动。

提交时按最新前缀重新裁定，因此两位角色并发提出的行动不会同时绕过 Rulebook。共享物品、关系或其他状态的先后竞争仍由顺序提交决定，后提交的行动可能被拒绝。若一次提交使另一个角色可见上下文改变，其在途计算可能过期并消耗额外预算；角色只接收自己有权知道的内容。

单个模型/preset/输出失败关联到实际失败角色并停止该角色；该失败会进入本周期的失败结果，其他已经在途的角色继续收束。存储、租约等基础故障仍可能使整个周期失败。这样不把“最后完成的其他角色”误报成失败来源。

调度队列和在途模型输出仅存在于当前运行过程。取消、暂停或关闭会结束未提交计算；运行时不保存可恢复的并行任务，也不保证未提交输出在崩溃后续跑。已经提交的玩家事实和 NPC 行动保留。

## 玩家插话与末端回合

普通 NPC 处理中，宿主通过公开 `canInterrupt` 表示当前是否受理玩家插话。活动仍在控制参与者调度时不开放此权限。页面允许玩家继续输入；新的文本请求到达后，TailRoundRuntime 取消旧回合未完成的 NPC 计算，并等待旧处理、投影及末端结算结束，再开始新输入。旧输入以及旧回合中已提交的 NPC 行动保留，未提交的模型结果丢弃。

这不会让后台 NPC 越过多次玩家输入持续运行，也不撤销已提交行动。每个完整末端回合仍按既有快照和结算边界处理；玩家插话只结束尚未完成的处理机会。

### 受控串行／动态对比

最终受控报告在同一包、相同调度预算与 fake 响应下重跑；最大因果深度合并修正后，动态组少发出一次到达深度上限后的模型调用。两组最终都向玩家显示相同的 3 句 NPC 表达，首条可见回应时间近似；主要变化是后台仍等待时，前台角色能否接着处理：

| 指标 | 串行 | 动态 |
| --- | ---: | ---: |
| 首条玩家可见 NPC 回应 | 522 ms | 528 ms |
| 前室同行者第二次决策调用开始 | 2686 ms | 665 ms |
| 后室 fake 调用结束 | 2662 ms | 2405 ms |
| 玩家回合完成 | 3045 ms | 2542 ms |
| 同时在途模型调用峰值 | 1 | 2 |
| 模型调用总数 | 5 | 4 |
| 最终玩家视图中的 NPC 句数 | 3 | 3 |
| 后室私密回复出现在最终玩家视图 | 否 | 否 |

动态组的前室第二次决策在后室调用结束前约 1.74 秒开始；相对串行组，第二次模型调用启动提前约 75%。这是**第二次模型决策调用开始时间**，不是第二条玩家可见语句显示时间。首条可见回复只差 6 ms，整轮完成时间缩短约 17%；当前证据支持“后台仍忙时前台可以续接”，不支持“所有输入都显著提速”。动态组触及最大因果深度后少发出一次模型调用，但两组最终玩家视图均有 3 句 NPC 表达，后室私密回复也未进入玩家视图。测量和公开视图保存在本机临时报告 `output/dynamic-scheduling/comparison-BWAkCi/summary.json`；较早的 `comparison-6OWrTG` 是因果深度修正前的历史结果，不与本表混用。该假服务驱动没有提交第二条玩家输入，因此插话取消与末端收束由自动回归和浏览器 DOM 验证覆盖，不属于本次计时结果。

### Gemini 3.8 Flash 真实模型短测

使用 `gemini-3.8-flash`、`http://127.0.0.1:8045/v1/chat/completions`、low 思考强度，在两个新数据目录分别验证正常完成与玩家插话。后室请求均额外等待 20 秒，用来放大后台阻塞条件；这不是日常模型延迟，也不是同模型串行／动态性能基准。

正常完成的报告为本机 `output/dynamic-scheduling/live-2mWL4M`：

| 指标 | 实测 |
| --- | ---: |
| 首条玩家可见 NPC 表达 | 5040 ms |
| 第二条玩家可见 NPC 表达 | 8131 ms |
| 后室调用完成 | 23862 ms |
| 整轮完成 | 23975 ms |
| 同时在途模型调用峰值 | 2 |
| 模型调用 | 3，均 HTTP 200 |

同行者说“来了”，目击者以颔首招呼玩家。前台两条表达都在后台结束前显示；本轮没有同行者的第二次模型调用，因此不能把受控组的后续对白链计时直接当成此次真实模型结果。模型选择了简短表达，调度器没有强迫角色扩展对话。

插话与重新生成的报告为本机 `output/dynamic-scheduling/live-U2GgxS`：后台实际 HTTP 请求已开始、尚未返回时，在第 20421 ms 提交第二句，第二句于第 20903 ms 出现在已提交玩家视图，受理用时 **482 ms**。旧后台请求被取消，旧回合已有的 1 条 NPC 表达保留；第二句只提交一次。末端重新生成成功产生 2 个候选，并继续保留旧回合前缀。该报告的 10 次调用包含初始回合、新输入以及重新生成，不能与正常完成报告的 3 次调用直接比较。

这两次真实短测验证了前台可以独立推进，以及插话的取消、结算和重新生成路径。角色相关上下文变化后的 stale 重算、活动排程、变量脚本、长期记忆整理与长时间自由试玩仍没有在本次真实模型验证中覆盖。
