## 1. 判断

当前不能原样导入。文本风格和局部扮演规则可以低成本转用；完整功能兼容代价高，部分语义与 Perspectra 的角色隔离和世界裁定边界冲突。

它更接近“提示组合器 + 叙事工作台 + 酒馆扩展应用”。放宽提示长度或把 JSON 转成字符串无法恢复其工作流。建议先精选表达规则，使用现有角色/组预设进行真实对照，暂不建设完整兼容层。

重型与效果好是两回事：本次确认功能范围与依赖，不能据体量确认“天花板”，不能证明模型稳定遵循全部规则。

## 4. 核心冲突

### 4.1 多角色导演与认知隔离

当前启用的“多角色内心OS”要求逐个角色列出感知边界、内心预演、导演检查，正文再穿插NPC内心。文字即便注明“只有本人知道”，若发布进公共观察或记忆，信息也已经交付给其他角色。

普通Character不能读取其他角色私密认知。可保留本角色表达指导；若将来需要玩家可见的角色内心，需要明确需求与独立受众路径，不能混进公开narration。上帝视角背景NPC、大纲、狐策吐槽也需逐项检查这个边界。

### 4.2 叙事补丁与权威结果

“分段转述”把括号当高权重事实补丁，允许元指令直接推动NPC/环境/剧情；“禁止抢话”仍让单模型统筹NPC位移和物体变化。当前普通文本是玩家发言，受控操作通过显式命令或NPC自主perform，再由Rulebook裁定。

不能把“让她进来”直接演成已到达，或把模型MVU Patch直接应用到位置/保管关系。适配必须改变这些语义，因而无法同时保证原样行为与当前权限不变量。

### 4.3 扩展宿主

主脚本实际引用getChatMessages、setChatMessages、getPreset、updatePreset、generateRaw、eventOn、CHAT_COMPLETION_PROMPT_READY、世界书API、localStorage、IndexedDB和fetch。

抽查确认：

- outlineSyncPresetByConfig：修改大纲条目与启用状态。
- foxMemorySyncToPreset：将剧情信息句、人物档案和表格写回预设。
- registerFoxMemoryAutoListener：监听生成结束，区分normal/swipe/regenerate/reroll。
- ssRescueProcessMessage：从推理来源提取标签内容；完成事件可触发救援。
- ssBuildMainContextMessagesDirect：直接读取酒馆角色卡与玩家设定。
- ssCallFoxJudgeApi：使用generateRaw进行独立模型请求。

当前公共玩家SDK没有这些能力。做同名API外壳也不够，还须还原楼层、重生成、事件时序、动态提示和UI生命周期。脚本实际模块默认开关与调用次数取决于运行时设置，本次未全面复现。

## 5. 借鉴价值

| 内容 | 收益 | 建议取法 |
| --- | --- | --- |
| 禁止抢话 + 自然停止点 | NPC能主动行动，也给玩家回应空间 | 单角色建议：提问、邀约或等待回应时可结束，不强迫每轮问问题 |
| 真实感文风 | 用具体动作、迟疑、呼吸承载情绪 | 可选组风格，保留人物自己的语气，避免人人一种文学腔 |
| 防全知/防剧透 | 强调感官、消息路径与猜测 | 补充既有宿主隔离，不能替代只交付授权信息 |
| 防恶意中的猜测归属 | NPC可以误解，旁白不替玩家确定动机 | 取“主观猜测不是事实”；不用“只能按字面理解”的绝对规则 |
| 防霸总正向例子 | 职业、资源与具体决策替代控制腔 | 按人物挑少量例子，不将职业表变成硬性性格分类器 |
| 多维偏好编辑 | 文风、互动、节奏、人称分别调整 | 优先改善现有编辑和实际生效内容展示 |
| 狐忆的选择/去重 | 表格已有信息时避免重复；按预算选剧情句 | 对照现有Delivery的冗余/遗漏实测，不再叠记忆系统 |
| 压缩缓存、后台状态、取消 | 少重复计算，让用户看到实际工作 | 只在现有路径出现实际等待/重复时考虑，保留角色/来源隔离 |
| 正文/建议/诊断分展示 | 建议帮助玩家而不打断正文 | 使用现有前端；建议不等于已执行行动 |

不建议直接搬：每轮强制公开长篇“思维链”、五狐辩论作为必经裁定、按词删除正文的杀八股、全局秘密注入、任意权威状态Patch，以及“防绝望”统一指定心理方向。它们可能增加等待、磨平人物差异或改变原文语义。

文件还含未启用的旧试玩记忆和小说文本。转用须区分作者规则与会话残留，不能当新世界设定或角色记忆。

## 6. 粗估成本

以下为一名熟悉项目开发者、包含相关验证的初步量级，不是排期承诺，不能相加成确定总工期。第三方实际行为与模型效果未验收。

| 目标 | 投入量级 | 达成与限制 |
| --- | --- | --- |
| 精选表达规则，做角色/组预设对照 | 1–3人日 | 复用现有设置；人工选文粘贴可更小；放弃原标签和扩展流程 |
| 受限导入：顺序、开关、基础宏、参数、不支持项报告 | 4–8人日 | 适配提示组合；动态槽位只取角色授权材料；不执行JS，不承诺原效果 |
| 重做选项、主题、诊断和少量公开面板 | 1–3人周 | 复用前端SDK，逐项选功能，不是正则全部原样运行 |
| 移植主要记忆/大纲/狐裁/生成拦截能力 | 4–8人周起 | 范围不确定，与现有机制重复，需重建宿主功能 |
| 原样行为和扩展生态兼容 | 无可靠工期 | 部分原语义与当前不变量冲突，无法承诺100% |

建议先取真实感、禁止抢话、猜测归属三个主题，压缩成短的单角色提示，对照相同场景的自然度与延迟。现有角色组配置已经提供接入位置，不需要先引入新协议、数据库或审查模型。

有真实导入需求后，再建设受限导入器，展示保留/改写/不支持内容与实际发送提示，不能静默宣称导入成功。

体验对照至少包括轻微表现、角色自主拒绝/误解、私语、跨房间信息、被拒绝的取物、复杂情境与连续互动。比较抢话、人物差异、私密泄露、叙事与受控结果分叉及延迟；长文不能仅因更长判为更好。
