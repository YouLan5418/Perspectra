# 条件知识：OpenCode DeepSeek 真实试玩（2026-10-19）

同行者的钱袋被规则私下加到 130 后，先说“不确定”，实际执行查看钱包后才报出“一百三十”；纸签活动里只解释自己的竹影细雨签；移动到后室后不再收到前室限定知识。这个样本中，新增条件的实际交付均符合预期。

这验证了条件筛选与一段连续互动，没有证明任意自由文本的来源表达都准确：角色仍会把作者背景说成“我在馆史里读到过”，并自行补充地名来历与场景细节。

## 1. 方法与范围

- 驱动：[knowledge-conditions-playtest.ts](../../../tests/experiments/knowledge-conditions-playtest.ts)。用 prototype-g1 示例和本次自编的 11 条虚构材料生成独立包，不读取既有存档或真实用户私有资料。
- 经用户授权，读取 Windows 用户环境变量 `OPENCODE_API_KEY`，调用 `https://opencode.ai/zen/go/v1/chat/completions` 的 `deepseek-v4.1-flash`。运行时开启真实 Python/E5 Core 记忆，与 Launcher 的记忆模式一致；本轮没有触发长会话整理。
- 本地观测器转发实际请求，附加固定的 `x-opencode-session`，只保存白名单：阶段、角色、授权场景／物品／已知状态／刺激／活动、已交付知识、模型决策、HTTP 状态、usage 和耗时。认证头与环境不写入证据。
- 玩家通过真实 take／give 操作把钥匙交给同行者；测试规则私下修改同行者余额，随后由模型自主决定是否执行查看；活动是否生成对白、是否移动等仍由真实模型决定。
- 在发送层，用独立的直接字段判断检查应交付 ID 与实际 ID，不调用生产知识选择器复算。发送层会把角色位置移到 context.locationId；刺激正文同时支持玩家 speech.text 和 NPC speech.segments。
- 完整样本在 `.tmp/knowledge-conditions-deepseek-20261019-v2`：`calls.json` 为逐次请求，`turns.json` 与 `transcript.json` 为互动，`summary.json`、`analysis.json` 与 `credential-scan.json` 为统计。本地数据不随源码分发。

| --- | --- | --- |

| 玩家实际给钥匙后 calls #12 开始交付 held-key，同行者说标签是“三号柜”；此前没有该条目 | 持有条件依据当前受控归属生效，背景没有单独执行开柜 | 钥匙转交是玩家控制的操作，本样本没有要求模型自主取钥匙 |
| calls #16、#17 的余额仍是旧值 100、current=false，交付 stale；角色先承认不确定，再 perform check-purse；#18 改为 130、current=true，只交付 fresh | 过时提示、真实操作与结果续写在连续互动中连上了 | 规则明确安排隐蔽加款；不是自然发生的偷窃或赠与验收 |

| calls #20 无 activity-own，角色仍能提及上一轮的竹纸防潮内容 | 退出后停止交付，不强制遗忘已发生的对话 | 不能用条件关闭实现保密撤回 |

## 4. 首轮中断与修正

`.tmp/knowledge-conditions-deepseek-20261019-v1` 保留首轮原始证据，8 次请求全部 HTTP 200，之后活动启动因参与者不在同一场景而被拒绝。该轮不能算完整验收。

首轮的记录器误用发送前的 character.locationId 判断发送后的请求位置，造成交付误报；刺激示例只写 segments，漏掉玩家的 speech.text。与此同时模型自主去了后室，后续定向问话无法触达。第二轮修正的是测试脚本、材料与场景衔接，不是知识选择器：支持两种正文形状，按实际提交的位置让玩家跟上，并通过真实 give 操作控制钥匙归属。首轮不与完整样本合算。

作者指南已补充正文形状区别；现有两条宿主协议的[回归](../../../tests/scenarios/pack-story-slice.test.ts)也加入正文条件。这不是为了保留旧协议而新增兼容路径，筛选仍复用标准 Schema。

## 5. 复跑与验收限制

在 PowerShell 中运行，路径应为 .tmp 内尚不存在的新目录。需要已准备好 Core Python/E5 环境；脚本把角色与测试设定发给 OpenCode，不发送现有存档。

```powershell
$env:OPENCODE_API_KEY = [Environment]::GetEnvironmentVariable('OPENCODE_API_KEY', 'User').Trim()
try {
  node --import tsx tests/experiments/knowledge-conditions-playtest.ts
} finally {
  Remove-Item Env:OPENCODE_API_KEY -ErrorAction SilentlyContinue
}
```

本轮是一次小型、受控的 Core 连续试玩，不是大型世界书召回、长期记忆整理、前端人工操作或性能 A/B 验收。响应会受模型选择与外部服务影响，复跑时仍需检查实际覆盖与转录。知识入口和权限没有因试玩新增模型阶段或持久化机制，发行包未重建。
