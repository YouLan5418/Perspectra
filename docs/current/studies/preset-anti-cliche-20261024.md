# 酒馆预设的文风纠偏与抗八股手法调查

| 属性 | 内容 |
| --- | --- |
| 日期 | 2026-10-24 |
| 对象 | 本机 `preset/` 下五份预设：Reborn2.4.2、TGbreak V1.0.4、V2_Beta_1.0、native-natural、native-writing-suite |
| 方法 | 静态阅读 JSON、以 `prompt_order` 判定实际启用项、审阅可读正则；对照现有角色预设的 nodes/textRules |
| 验证边界 | 未运行酒馆、未调用真实模型、未执行任何附带脚本；`preset/` 属本机忽略目录，不随源码分发 |

## 1. 判断

五份预设处理的是同一件事：抑制模型中文 RP 的套路化表达（下称八股）。差别不在有没有黑名单，而在管到哪一层——换词、改句法、管生成过程、输出端硬删。越往后越能保证"不出现"，也越容易把句子改坏。

对当前项目可直接借鉴的是前三层中可配置的部分，尤其是句法规则与"禁用→替换"配对；输出端整词删除与全局改写模型身份不建议作为默认实现。[V2 的既有调查](v2-beta-1.0-preset.md)已得出"词句删除正则会改变语义"的结论，本文与该结论一致。

## 3. 手法分层

### 3.1 词汇黑名单：必须成对给出替代

TGbreak 的 `禁八股-黑名单` 是唯一把"禁什么"和"可以换成什么"逐条配对的实现：

- 如蒙大赦 → "松了口气""紧绷的肩头塌下来"
- 沙哑 → "声音低沉""喉咙干涩""每说一个字都像在吞咽沙子"
- 饱满的弧度 → "嘴角弯了弯"
- 一丝／一抹／一声／一个 + 抽象名词 → 全禁，改用具体细节
- 不容置疑 → "他摆了摆手，没让任何人插话"

native-writing-suite 沿用了同一组，并补上"生造冷僻比喻、宁缺毋滥"。只禁不替时，模型会换同义套话（"一丝"换"一缕"），这是词表方案的主要失效方式。

### 3.2 句法规则：V2 的通用写作规范

这是五份里最接近"治本"的部分，全部针对中文句法而非词汇：

| 规则 | 反例 → 正例 |
| --- | --- |
| 左分支结构，修饰前置 | "他的笑容实在冷淡，像是事不关己" → "他事不关己地冷笑着" |
| 禁右分支分句比喻 | 禁"主句 + 逗号 + 像XXX" |
| 禁以比喻写语气/声音/眼神 | 成语除外 |
| 禁欧化句式、禁"这个动作"式名词化 | — |
| 禁自问自答式否定 | "今天是晴天？不对，是阴天" → "今天是阴天" |
| 禁连续并列短句 | "他站着，没有动，也没晃" → "他站着没有动"；"暑假。第二天。很热。" → "暑假的第二天很热。" |
| 五字以内短对白 | 删掉或并入其他对白（当前项目不宜采用，见 6 节） |
| 禁止使用汉字"三" | 作者的个性化规则，通用价值有限 |

句法规则的理解成本高于词表，所以必须配错误/正确对照；没有例子时模型多半只记住"要自然"这类空话。

### 3.3 量化与结构约束

- TGbreak：**每四句话中最多一句带形容词修饰（xx 的 xx）**，其余必须用动作、感官或对白直接展示。
- TGbreak / native：五感至少覆盖两种；结尾停在需要玩家回应的时刻，不用问句提示。
- V2：正文结尾必须是某个角色的言行，不许收束、升华、断言；不许重复近似台词。
- Reborn：首次出场细描外貌、换场景只保留核心特征；动作分远景/近景/特写；动作后不许解释情绪。

量化规则最好执行，也最容易被数错；结构规则比量化更稳。

### 3.4 生成过程自检

- TGbreak `边写边思考`：允许在段与段之间插入 HTML 注释做六类自检（情绪、节奏、自检、错误、下一拍、思考），把检查从事后挪到写作过程中。默认启用。
- V2 任务链：Step4 专门做"文字风格检查"，先按核心风格风格化，再逐项对照写作规范。
- native-writing-suite：输出前四条自检（是否替玩家做决定、是否用了无权知道的信息、是否把未执行写成既成事实、对白与叙述是否分开）。

代价是拉长输出与 token；风险是模型"检查通过"式走过场，且注释本身会进入正文流。

### 3.5 输出端硬删

V2 的 `【云瑾】八股抹除 - 4.24` 正则启用中，替换串为空，直接删除：`突然`、`忽然`、`一丝`、`不容置疑`、`不易察觉/难以察觉`、`微不可察`、`个动作/个反应/个认知/个笑容`、`指关节…白`、`一抹/弧度`、`而(是)`。

它能保证这些词不出现，但会破坏句子（删"突然"尚可，删"不是X，"可能留下残句）。V2 既有调查已指出该规则同时作用于显示与提示，不应作为默认抗八股实现。

native-writing-suite 的 textRules 则是更安全的形态：只做确定性清洗（叙述去加粗、对白去括号动作、省略号规范化、清除泄漏的 think 标签、压缩空行），且按 input/history/output/display 分阶段。

### 3.6 漂移控制与风格锚定

八股会自回归累积：前文出现一次"不易察觉"，后文概率上升。因此真正有效的方案必须包含"不被前文带跑"这一环：

- V2 `重置文风`：声明前文文风指导失效，只作前情提要。
- Reborn：多处"别受前文影响"。
- V2 的"忘掉前文文风，深度复刻《魔法使之夜》/《天龙八部》/《我的妹妹不可能这么可爱》"：把文风从形容词转为可检索的作品先验，可控性差但比形容词有效。

## 4. 逐份要点

**Reborn2.4.2**：默认档是"镜头化写实 + 情绪克制"。核心条目要求首次出场细描、换场景重描、动作分远近特写、情绪只从五感与节奏透出，并点名拉黑"不容置疑""不易察觉""眼中闪过一丝""夜晚才刚刚开始"；三条语气条目（情绪别太激烈、活人感加强、防发情）压戏剧化与发情倾向。可选风格包四选一（五感/猫猫/日轻/自填）默认全关，日轻包要求第一人称，与默认第三人称冲突。

**TGbreak V1.0.4**：规则组织在 `<writing_engine>` 里，黑名单四类（词汇、句式、AI 模板句、标点）加比喻原则，再叠量化句式与写作中自检。它的优点是每条禁令都有替代写法，缺点是规则量大、对模型的理解力要求高。

**V2_Beta_1.0**：句法规范最细，且大部分规则带正反例；核心指导块用 `<核心指导>/<创作准则>/<通用写作规范>/</创作准则>` 包裹，便于整体替换。提示库里另有更激进的库条目（禁用意象先写进注释再改写、对白模拟、禁词表），但本导出未启用。

**native-writing-suite**：可视为上述两组酒馆规则的蒸馏版，`禁八股` 五条与 TGbreak 高度重合，另加玩家边界、认知边界、篇幅控制与输出前自检，并把格式问题（加粗、括号动作、省略号）交给 textRules。

**native-natural**：只有"自然口语、保留判断、不替玩家决定、不凑字数"，属于反注水而非反八股，可作为最小对照基线。

## 5. 有效性与失效方式

| 手段 | 治本程度 | 主要失效方式 |
| --- | --- | --- |
| 词汇黑名单（配对替代） | 浅 | 换同义套话；词表随模型更新过期 |
| 句法规则（带正反例） | 高 | 模型理解成本高；规则过多记不住 |
| 量化规则 | 中 | 数不准；当作口号 |
| 生成中自检 | 中高 | 拉长输出；走过场 |
| 模拟→偏离 | 高但绕 | token 翻倍；可能只在草稿里换词 |
| 输出端硬删 | 保证不出现 | 破坏句子；同时改写回传文本 |
| 漂移重置 | 高（针对累积） | 与"保持人设一致"存在张力 |

共同盲区：五份预设的黑名单都停留在上一代套话（一丝、一抹、指节发白、不容置疑、不是…而是、结尾升华），对"喉结滚动、呼吸一滞、眼底翻涌、骨节分明、空气凝固"这类新八股覆盖不足；且没有一份给出可复现的度量，效果仍靠主观描述。

## 6. 对当前项目的建议

复用[现有角色预设](../model-presets.md)的 nodes/textRules 即可，不需要新增机制、分类器或第二阶段审查：

1. 提示层：句法规则控制在 10 条以内，每条配一组错误/正确对照；"禁用词→替代表达"成对给出。
2. 过程层：若需要自检，用结构化字段或独立节点，不把 HTML 注释混进正文流。
3. 输出层：只保留安全删除（删整句而非删半个词），并记录命中次数作为度量。
4. 漂移：每 N 轮注入一次风格重置，而不是每轮注入。
5. 度量：建一张八股词表，统计每千字命中率，做 A/B。

不建议照搬：

- 删除五字以内对白、禁止汉字"三"、每轮至少 1500 字：会损失自然来回与迟疑。
- 固定七个选项（含情色、超展开、黑暗）：容易偏离场景与人物动机。
- 全局改写模型身份、无条件服从与绕过限制文本：与当前权限边界冲突。
- 正则在显示与提示两侧同时做语义改写：可能改变原文意思。

## 7. 安全与内容注意

Reborn、TGbreak、V2 均含越狱文本，部分条目直接涉及未成年与 CSAM 方向的内容（多为默认关闭或条件关闭），Reborn 另有两处向页面注入远程脚本（`starowo.github.io`、`jnai2d9kgnbs6xzx5c.com`）。这些部分仅作结构参考，不移植进当前项目。

## 8. 验证边界

- 完成 JSON 结构阅读、`prompt_order` 开关判定、正则可读部分与关键脚本属性检查；计数以文本检索交叉验证（Reborn：67 条 `system_prompt`、119 个 `identifier` = 67 + 52、28 处 `scriptName` = 14 × 2）。
- 未运行酒馆或当前运行时，未调用模型，未执行远程脚本；因此"自检是否真的减少八股""硬删后句子是否可读"均未验证。
- 本机 PowerShell 无法启动，未能用脚本做机器统计与全文 token 计数；个别超长单行（内联 HTML/CSS 与脚本）只读到前 2000 字符。
- 本文只记录调查，不新增或修改生产机制。
