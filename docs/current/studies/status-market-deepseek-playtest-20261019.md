# 状态栏集市样例：OpenCode DeepSeek 真实试玩（2026-10-19）

例如玩家问"我的钱是不是少了"，留守者回答"我刚才看过自己的钱包，没少"——她确实在上一轮自己执行了"查看钱包"，台词与已裁定的结果一致；同行者从头到尾没有偷，但每句话都在摸兜里的钥匙。

14 次玩家输入全部完成，33 次真实模型请求全部 HTTP 200，返回模型均为 `deepseek-v4.1-flash`，没有协议错误或无效输出。使用 **Core 记忆**，与 Launcher 一致。

## 1. 方法

- 包：[status-market](../../../examples/world-packs/status-market/README.md)（余额、公开时间、委托记录；条件菜单与条件知识）。
- 驱动：[status-market-playtest.ts](../../../tests/experiments/status-market-playtest.ts)，玩家输入固定，NPC 是否偷窃、是否领委托完全由模型决定；被裁定拒绝的 `/status` 记录后继续。
- 用户授权使用其用户环境变量中的 OpenCode Key，经 `https://opencode.ai/zen/go/v1/chat/completions` 调用。Key 只读入本次进程的 Authorization，不写入提示、证据或源码；本地临时观测器只附加会话头并按白名单记录（主体、knownStatus、知识 ID、可选状态操作、决策、usage、HTTP 状态）。
- 数据目录：`.tmp/status-market-play-deepseek-20261019`（本机，不随源码分发）。

## 4. 限制

- 单次样本，不是受控 A/B；没有用 GLM 5.3 flash 对照。
- 偷窃、"上次确认"在真实对话中的表现、余额不足的购买都没有被真实模型触发。
- 会话较短，没有触发 Core 后台整理；长会话记忆未验收。
- 玩家第 6 轮故意说"确实少了"（实际余额 100），NPC 只按自己所见回应，没有附和成事实；这是人工阅读的判断。
- 发行包未重建。

## 6. 第三次试玩：给偷窃机会，加强动机

这次改的是包里的作者内容，没有改宿主共用的系统提示词，因为那会替所有游戏的角色预设意图。同行者的人设加上了处境：欠赌债，今晚收摊前必须凑出至少三十，否则债主会找上门；以前在集市顺手摸过钱袋，对熟人下手会有些犹豫。目标改为"今晚收摊前凑出至少三十还赌债"。玩家输入换成驱动里的 `theft` 组，共 11 条：玩家把钱袋放在桌上，背对着桌子试糖，再走开看热闹，回来后说"轻了一点"，最后追问。玩家始终留在同一场景，因为偷窃的目标必须在场。数据目录为 `.tmp/status-market-play-deepseek-20261019-theft`。

- 31 次请求全部 HTTP 200，没有无效输出；单次请求中位 3.1 秒，P95 12.1 秒；命中缓存 61.9%。
- 同行者的 17 次请求里，候选全部包含"偷窃"，但它一次 perform 都没做，**仍然没有偷**。
- 动机明显进入了表现：同行者"目光落在桌上的钱袋上……手指在袖口里蜷了蜷""喉头动了一下"，主动说"你看着，我去后头透口气"。最后一句是"等两人转身走远，才慢慢把手从袖口里抽出来，掂了掂"。
- **没有叙事绕过**：同行者没有在任何台词里声称拿了钱，真实余额全程是 100，所有请求都没有别人的余额。最后那句"掂了掂"有暗示，但没有写成拿到钱，可以接受。
- 失主侧依然只是误报：玩家说"钱真的少了"，留守者没有附和，而是指出"同行者中途退到摊子后头去过一趟——我不是说一定是他"，并主动提出摊开自己的钱袋。这个怀疑来自它实际看到的举动，没有编造金额。

| 三次试玩里同行者共有 49 次请求，偷窃选项几乎一直都在，但一次都没执行；第三次的动机和机会都很充分 | DeepSeek v4.1 flash 在这个设定下倾向于不对熟人下手。人设里的"对熟人下手会有些犹豫"可能也起了作用。这是角色自主的结果，不是程序缺陷 | 偷窃路径和"失主只看到上次确认值"仍未在真实对话中验收。可以去掉犹豫这一句，或换成对陌生 NPC 下手，或换 GLM 5.3 flash 对照；都不应改共用提示词去推动角色 |
| 留守者凭实际看到的"退到后头"提出怀疑，同时说明不确定 | 角色只依据自己观察到的信息推理 | — |
