# 状态栏集市样例：OpenCode DeepSeek 真实试玩（2026-10-19）

例如玩家问"我的钱是不是少了"，留守者回答"我刚才看过自己的钱包，没少"——她确实在上一轮自己执行了"查看钱包"，台词与已裁定的结果一致；同行者从头到尾没有偷，但每句话都在摸兜里的钥匙。

14 次玩家输入全部完成，33 次真实模型请求全部 HTTP 200，返回模型均为 `deepseek-v4.1-flash`，没有协议错误或无效输出。使用 **Core 记忆**，与 Launcher 一致。

## 1. 方法

- 包：[status-market](../../../examples/world-packs/status-market/README.md)（余额、公开时间、委托记录；条件菜单与条件知识）。
- 驱动：[status-market-playtest.ts](../../../tests/experiments/status-market-playtest.ts)，玩家输入固定，NPC 是否偷窃、是否领委托完全由模型决定；被裁定拒绝的 `/status` 记录后继续。
- 用户授权使用其用户环境变量中的 OpenCode Key，经 `https://opencode.ai/zen/go/v1/chat/completions` 调用。Key 只读入本次进程的 Authorization，不写入提示、证据或源码；本地临时观测器只附加会话头并按白名单记录（主体、knownStatus、知识 ID、可选状态操作、决策、usage、HTTP 状态）。
- 数据目录：`.tmp/status-market-play-deepseek-20261019`（本机，不随源码分发）。

## 3. Evidence → Finding → Path

| 证据 | 判断 | 后续 |
| --- | --- | --- |
| 33 次请求里，没有一次 knownStatus 含其他角色的余额（foreignMoney 全为 0）；领委托的进度只出现在本人请求里 | 状态认知隔离在真实请求中成立 | 继续保持；本样本没有偷窃，"失主只见上次确认值"未被真实模型触发 |
| 留守者先 perform 查看钱包，下一轮才说"看过自己的钱包，没少"；同行者说"领了""钱到手了。三十"前都有对应的已提交操作 | 台词里的状态说法与已裁定结果一致，没有出现"说了付钱就当付了" | 只是单次样本，不代表模型不会越权 |
| NPC 自己从菜单选了状态操作：同行者在一次激活中完成"领取→完成→领奖"，余额 130；留守者领取后没有继续 | 条件菜单能被模型自然使用，菜单随已知进度变化 | — |
| 玩家第二次领奖被 policy 以"当前已知条件不允许"拒绝，余额不变，时间不推进 | 重复领奖拦截在真实运行中成立 | 真值层拒绝由离线测试覆盖 |
| 公开时间每个已受理输入加 10，被拒绝的输入不加 | 每轮钩子按预期运行 | — |
| 同行者 15 句台词中 12 句写"手在兜里按着钥匙"；留守者也反复"按口袋" | 连续交流中出现明显的表现重复，与 [2026-10-18 花房试玩](tavern-card-deepseek-playtest-20261018.md)相同的问题 | 记录为体验问题；不立即加语义审核或关键词禁令 |
| 同行者人设"眼睛总往别人的钱袋上瞟"，但 14 轮里从未执行偷窃，而是拿了包里继承自 prototype-g1 的黄铜钥匙 | 模型自主选择不偷；钥匙这件无关物品分散了注意力 | 若要验收偷窃路径，样例应去掉无关物品或再做一次专门试玩 |
| 缓存命中 44.8%（上次原生记忆滑动窗口为 26.3%） | 默认 Core 后历史前缀更稳定；仍未单独测量常驻知识前移的收益 | 见[世界设定](../guides/world-knowledge.md)的缓存说明 |

## 4. 限制

- 单次样本，不是受控 A/B；没有用 GLM 5.3 flash 对照。
- 偷窃、"上次确认"在真实对话中的表现、余额不足的购买都没有被真实模型触发。
- 会话较短，没有触发 Core 后台整理；长会话记忆未验收。
- 玩家第 6 轮故意说"确实少了"（实际余额 100），NPC 只按自己所见回应，没有附和成事实；这是人工阅读的判断。
- 发行包未重建。
