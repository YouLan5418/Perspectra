# 花房切片：OpenCode DeepSeek 真实试玩（2026-10-18）

20 次玩家输入完成，22 次真实模型请求全部 HTTP 200，返回模型均为 `deepseek-v4.1-flash`。自由交流、设定交付、跨场景和本轮私语隔离有实际证据，后半段存在明显重复描写。

**版本边界：** 本文记录当时 v2 的原始观测，数据不覆写。用户后续明确不需要好感度／信任分数，当前 v3 已撤销相关机制及情感门槛。以下旧数值未变化不是当前待修目标，也不表示角色情感未变化；当前方向见[世界设定指南](../guides/world-knowledge.md)。

## 1. 场景与方法

使用[花房切片](tavern-card-slice-20261018.md)的 v2 本机包，守岸人在花房、椿在庭院；先交流、给守岸人一个定向暗号，前往庭院询问椿，再返回向守岸人核对。初始信任均为 50，达到 52 时可获得后续机会提示。

本轮在用户明确批准将原卡人设、世界书、NPC 私有设定和测试暗号发送给 OpenCode 后执行。用户级 `OPENCODE_API_KEY` 只读入本次进程，用于 Authorization；不写入模型提示、证据文件、源码或持久环境变量。调用使用 `https://opencode.ai/zen/go/v1/chat/completions`，同一轮维持稳定 `x-opencode-session`。

通过现有[真实试玩驱动](../../../tests/experiments/tavern-slice-playtest.ts)调用默认宿主和角色协议，没有模拟 NPC 输出、预先写好成功动作或强制修改数值。临时 fetch 观测器只附加会话头并记录白名单结果，没有改写模型的决策。使用 **Native 原生记忆**，没有启用 Python/E5/Core。

数据目录：`.tmp/tavern-slice-deepseek-20261018-v1`。结果由进程完成后离线复核，并以只读 SQLite 查询核对事件；旧 Gemini 失败样本保持独立。

## 4. 怎样理解“信任没有变化”

模型收到本人的数值及其说明，但本轮始终选择表达或沉默，没有提出状态交互。因此没有证据表明是提交失败，也不能据此认定 DeepSeek 无法调用工具；本轮没有实际 perform 样本可用于判断。

离线测试打通执行通道，不代表自然交流必须使用它。按用户后续明确的方向，本项目不把情感换算成额外分数：角色依据预设、人设、记忆和对话历史动态形成态度。旧报告把“数值没有变化”列作反馈缺口的目标已撤销，不再通过追加调分机会或每轮加分追求所谓闭环。客观变量仍由玩法规则维护。

守岸人即使没有获得门槛提示，也会自然提出弹琴。这不是受控剧情解锁绕过：当前门槛只开放一段机会提示，没有禁止普通对白里的类似提议，也没有定义“弹琴完成”的受控世界事实。若作者需要真正锁住某项玩法，应在该项玩法的规则里声明条件。
