# 酒馆卡花房切片：本机实验（2026-10-18）

当前 v3 按用户最新方向撤销好感度／信任数值、专用交互、面板及门槛。角色情感依据人设、预设、记忆和对话历史动态变化，变量优先维护客观玩法事实。保留按权限交付世界设定；未发布、未提交 Git、未生成新版便携包。

此前 v2 经用户授权完成[DeepSeek 20 次输入的真实试玩](tavern-card-deepseek-playtest-20261018.md)：22 次请求成功，知识与私语边界有样本证据。旧数值与门槛未触发的事实保留为历史记录，不再作为待补功能或体验验收目标。历史数据不覆写，v3 只做离线验证，没有追加模型调用。

## 1. 初版 v2 场景（历史）

以原卡 `alternate_greetings[2]` 的黑海岸花房开局为起点：玩家与守岸人休息、自由交谈，可以前往相邻庭院遇见椿，再返回继续交流。知识按角色权限交付；两名角色只能提出各自信任刻度变化。玩家状态栏显示已提交数值；守岸人的信任达到 52 后，她获得“可以考虑邀请听琴／共同休息”的私有机会提示，决定仍留给角色。

这是原卡局部改编。椿位于相邻场景以及 50 点信任初值是本切片实验设置，没有复刻 MVU 数值和全世界进度。没有自动演出原开场，进入后由玩家第一句话推动；原开场保存在本机 `OPENING.md` 并交付守岸人作为开局设定。原卡飞讯、CG、传送、全部开局、宏和脚本没有执行。

## 2. 本机生成

原卡文本只生成在 Git 忽略的 `.tmp`，不加入公开示例或发行资源。工具只读取 PNG 的 chara/ccv3 文本或 JSON，不运行其中脚本，不渲染其中 HTML。

```powershell
node --import tsx tests/experiments/tavern-card-slice.ts 'C:/Users/Administrator/Desktop/QQ图片20261018140202.png' '.tmp/tavern-slice-local-new'
```

输出目录必须是 `.tmp` 下尚不存在的新目录，不覆盖旧实例。[生成器](../../../tests/experiments/tavern-black-shores-slice.ts)当前输出为 `.tmp/tavern-slice-20261018-v3`，含 3 个主体、2 个地点、7 条文档、4 条关键词背景知识，没有信任数值或情感门槛。每名 NPC 的人设只有本人可读。`slice-source.json` 记录原文选择与改编限制；原测试世界的人设、认知、记忆关注主题及物品被替换，保留现有角色 ID 复用基础包结构。旧 v2 及真实试玩目录原样保留，不能继续将其当成当前包使用。

生成器依赖这张卡的固定开局和人物名称，不是通用迁移器。创作者无需为每一句对白写分支；包内没有新增作者 JavaScript。通用声明见[世界设定](../guides/world-knowledge.md)。

## 5. 当前 v3：移除情感分数

用户明确角色态度应依据预设、人设、记忆与对话历史变化，变量优先负责客观玩法事实。已删除本次新增的角色数值执行模块、事件、上下文、前端字段与面板，知识交付也不再接收数值门槛。不用新的情感阶段、标签或固定涨分替代它，没有新建客观变量框架。

当前 v3 包有 7 条文档，只登记 `knowledge.json`。在默认宿主实际打开后，花房当前角色为守岸人，没有数值面板字段，模型调用数为 0。旧 v2 包与 OpenCode 数据只保留作历史研究，不覆盖、不迁移；新实验从 v3 创建新实例。

本次 TypeScript strict、Lint、文档导航检查通过；知识与公共前端相关 2 个测试文件、25 项通过，其中模拟 Ollama／OpenAI HTTP 路径验证私有设定和定向发言不会触发其他角色的知识，重开和末端候选重算仍可用。本次未再调用真实模型，旧 DeepSeek 结果不能直接当作 v3 的真实体验验收。
