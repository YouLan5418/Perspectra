# 末端玩家回合重新生成

| 属性 | 内容 |
| --- | --- |
| 日期 | 2026-10-08 |
| 范围 | 本机、单用户、同一故事线，只替换最近一次玩家操作及其完整有界反应 |
| 入口 | 默认聊天末端回复下方刷新图标与 ‹ i/n ›；社区模板使用宿主顶部工具，SDK regenerate / selectCandidate |
| 行为 | 保存原起点 → 隔离重演 → 检查候选 → 追加并自动选中新候选；保留此前候选，可切换完整结果 |
| 不包含 | 任意历史重写、跨回合候选浏览、线路合并、通用创作者脚本重放 |

## 1. 回合边界

玩家回合是一次普通输入、结构化操作或活动操作，包含它引发的玩家提交、NPC 行动与表达、观察、连锁反应及活动处理。它不等于一条文本或一个数据库 commitRound。

执行器返回后，还必须完成必要会话投递、释放 writer，并确认没有 pending/claimed Round、未完成 Player Input、非 terminal Reaction Cycle 和未投递关键 Outbox，才公布可重新生成的末端记录。调度预算正常耗尽和角色主动沉默是合法结束；暂停期间保留已提交进度，但不公布完整回合。已经停止并完成结算的失败回合可以再次生成，失败的候选不自动替换。

下一次玩家世界操作开始前，先持久化撤销旧末端资格及该组候选切换资格，以当前选择推进；新回合从 1 个候选重新开始。逃生活动和变量调试也会撤销资格。没有保存起点的旧存档回合不能补成可重生成回合。

## 2. 起点、长期档案与短期认知

起点保存四个既有 SQLite 数据库、包变量、角色称呼历史及当时已安装的 Core archive/index。SQLite 使用一致 backup，包含 WAL 的已提交内容；文件清单与内容校验在恢复前检查。不会复制诊断 trace、凭证或未提交任务。

长期档案的安装在回合起点到完成期间延后，后台模型计算可以继续。当前回合始终使用起点的长期档案；候选自己的新事件、授权观察、短期经历与自身表达照常传给后续角色。重新生成不调用 Core 重建旧认知。

每个运行实例持有世界版本；后台任务捕获该版本，安装前检查实例仍有效且版本匹配。切换时关闭旧实例、取消并收束旧任务，不把旧世界同序号的档案交给新世界。候选采用新的执行器、脚本 VM、队列、缓存、Core 子进程和日志目录；旧 trace 不成为候选称呼历史。

活动只记录 initialize 期间 Math.random 的取值。重演仍经过原活动 start 的角色、场景、请求参数和版本检查，再由同一脚本 initialize 使用这些取值计算结果并走原提交路径。不直接注入活动状态。后续角色仍依据候选当前活动状态自主行动。

## 3. 原子替换与恢复

故事线根目录继续保存故事节点和运行实例权限标记；current-world.json 指向当前实际数据目录，并携带世界版本、唯一末端记录及该回合的候选列表和当前选择。初始数据保持原位置，候选进入 .tail/results/<UUID>；内部起点位于 .tail/bases/<UUID>，不出现在玩家故事节点列表。

候选执行期间正式世界不接收新的世界操作，前端继续显示原结果。候选结算、关闭、重新打开验证并刷新持久文件后，关闭旧执行器，再以 fsync 临时文件和原子 rename 切换选择记录。提交点前可以取消；提交点后按成功处理，不撤回已切换结果。前端一次替换历史、场景与行动选项。

重启只打开选择记录指定的目录，不猜测残留候选。保存故事节点和 Launcher 预检使用当前数据目录；故事节点仍归属固定故事线根目录。旧结果不覆盖、不删除。保存一个新的故事节点不会创造额外候选世界线。

同一故事线只有一个宿主所有者，候选由该宿主隔离管理，正式执行器在重演时静止。运行权限初始化用短暂的目录互斥，防止两个启动者同时回收死亡 PID 的标记。死亡宿主的普通所有者标记可回收；如果恰在权限初始化中断而留下互斥目录，则明确拒绝启动，需先检查该标记，不能冒险接管仍存活的实例。

### 3.1 末端候选切换

原结果计为第 1 个候选，每次重生成在同一个起点追加候选并自动选中；从较早候选重新生成也追加到列表末尾。候选列表与选择在同一次 current-world.json 原子更新中持久化，失败或取消不会增加计数。

箭头切换已有目录中的完整世界，包括事件、会话、变量、活动状态、角色称呼及该候选自己的认知文件；不重新调用角色模型。切换前检查当前世界与目标候选都处于记录的完整回合末端、环境相容且目录没有被替换为链接。先关闭当前实例并收束后台任务，再以新世界版本打开目标候选；完成校验和文件刷新后提交选择。重新进入此前候选也使用新任务版本。

切换操作刷新末端请求标识，旧操作不能覆盖后来的选择。原子选择前中断或取消保留当前候选；选择成功后按成功处理。提交下一次玩家操作后不再开放上一组切换，不添加历史重写入口。

## 4. 环境与权限

回合记录保存现有 packHash、声明脚本资产、交互包定义、可执行代码标识、模型标识和非凭证配置、角色预设、记忆及调度参数。重新生成前和生成后检查环境；包、脚本、规则或配置不一致时拒绝，不自动迁移。

公开 API 只接受末端回合标识、候选标识和请求 ID，不接收文件路径、备份内容、角色档案或随机结果。重复请求不重复执行，返回当前公开视图；不让旧请求缓存重新展示已替换历史。私有数据仍通过既有角色授权投影处理。

## 5. 验证与接受的限制

回归覆盖位置/保管/表达撤回、长期档案原样复用、候选新观察传播、私语隔离、后台结果延迟安装与过期版本拒绝、活动随机初始化、失败/取消/重复请求、环境不兼容、快照损坏、保存节点及重启。

强制终止使用真实子进程，在候选世界文件复制到一半、选择切换前、选择切换后停止；重启应分别得到完整旧结果、完整旧结果和完整新结果，并保留原目录内容及 SQLite integrity_check。未提交候选可以丢弃，不续跑模型调用。

完整副本增加磁盘与回合起点备份成本；当前保留内部起点、旧结果和失败候选，不自动清理。只对现有同步 VM 和活动初始化随机路径作保证；不支持依赖外部副作用或通用时钟/随机重放的脚本。带外部写回调的 publicationAudit 实验明确拒绝重新生成。远端模型标识相同不证明供应商模型内部实现未变化。

文件刷新、SQLite 原有 WAL/FULL 和选择原子替换用于保护正常持久化与进程中断；强制终止测试不等于断电或磁盘故障验收。真实角色是否自然、是否误记被替换经历，另以真实模型试玩核对。
