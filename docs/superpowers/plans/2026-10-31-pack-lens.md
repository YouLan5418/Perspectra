# 包透视 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 Launcher 里提供一个只读的“包透视”：不开游戏实例，看清世界包的全部作者设置；用桩模型推演回合；标出与上次查看相比的变化；作者圈选的待改条目可由 AI 通过 CLI 自己读取。

**Architecture:** 新增 `desktop/lens/` 模块，作为唯一的透视后端。推演复用真实的 `WorldHostRuntime`：在临时目录复制一份包，按“起点”覆盖初始数据，模型指向一个进程内的桩 HTTP 端点。透视结果（`LensView`）由包 JSON 加上开场时刻的运行时数据组装而成；改动标记和待改清单都基于 `LensView` 的条目来比较。Launcher 的 Node 桥（`desktop/launcher-core.ts`）新增 `lens-*` 操作，界面是 Launcher 窗口内的一个全屏面板，复用创作者控制台的样式；CLI 是 `desktop/lens/cli.ts`，由 `worldpack.cmd lens …` 转发调用。

**Tech Stack:** TypeScript strict ESM（显式 `.ts` 导入）、Node 24 `node:vm`/`node:http`、Vitest 4、Vue 3 + Pinia（Launcher）、esbuild（发行 CLI 打包）。

**Spec:** [docs/superpowers/specs/2026-10-31-pack-lens-design.md](../specs/2026-10-31-pack-lens-design.md)

## Global Constraints

- 只读：不修改世界包内容文件，不写 `D:/worlds` 或任何存档，不调用真实模型，不需要凭证。
- 唯一的写入是包源目录下的 `.perspectra-lens/`（查看快照、对比点、待改清单、推演脚本）；它不能出现在 manifest 的引用里，并加入仓库 `.gitignore`。
- 推演必须复用真实宿主运行时，不允许另写简化规则；脚本仍在现有 `node:vm` 沙箱与超时限制内执行。
- 推演起点是“另一种开场”：在运行时启动前改写临时副本，运行中途不注入事实。
- 第一阶段不自动试跑活动选项；选项效果只在推演中实际选过之后显示。
- 不翻译 JS：条件说明只来自 `when` 标签和运行时实际算出的真假。
- 改动基准只在作者点“已看过”时前移；打开、关闭页面或 CLI 读取都不前移。
- AI（CLI）不能关闭或修改待改清单条目。
- 不依赖 git，不做 MCP，只支持 `worldpack-source/v5`。
- 界面上明确写出：推演只验证规则与触发，不验证角色表现。
- 沿用 ESM、TypeScript strict、显式 `.ts` 本地导入；损坏的 `.perspectra-lens` 文件要明确报错，不能当成空数据。
- 验收包：`examples/world-packs/model-girls-sweet-days`。

## Review Focus

1. **起点引用了不存在的角色、场景或状态键**：推演应在启动前给出指明字段的错误，不能静默忽略，也不能起一个“差不多”的世界。→ Task 2 测试 `rejects unknown start references`。
2. **推演中脚本抛错或超时**（例如 autoStart 写坏了）：这一步的 trace 应显示错误，后续仍能重置；不能让 Launcher 的 Node 桥崩溃。→ Task 2 测试 `step with a throwing autoStart reports the error in the trace`。
3. **待改条目指向的东西被 AI 删了或改名**：清单应显示“已删除”，而不是报错或消失。→ Task 5 测试 `request whose item disappeared is marked removed`。
4. **`.perspectra-lens/` 里的 JSON 损坏**：应明确报错并指出文件，不能当作“没有快照”，否则会把所有内容都标成新增。→ Task 5 测试 `corrupt seen snapshot fails with the file path`。
5. **游戏正在运行时打开透视，或在透视开着时开始游戏**：两者互不影响（推演使用独立临时目录）；开始游戏不能被透视会话阻塞。→ Task 7 测试 `lens session survives start and does not touch instance data`。

  ```ts
    readonly note: string                   // 作者原话，1–2000 字符
    readonly valueAtCreation: readonly LensField[]
    readonly createdAt: string              // ISO
    readonly closedAt?: string
  }
  export type LensRequestState = 'open' | 'changed' | 'removed' | 'closed'
  export interface LensRequestView extends LensRequest { readonly state: LensRequestState }
  export class LensStore {
    constructor(packPath: string)           // 目录：<packPath>/.perspectra-lens/
    seen(): LensView | null                 // seen.json；不存在时为 null，损坏时抛出带路径的错误
    markSeen(view: LensView): void          // 只能由 Launcher 调用
    checkpoints(): readonly { name: string; savedAt: string }[]
    saveCheckpoint(name: string, view: LensView): void   // checkpoints/<name>.json，name 为 1–40 个非路径字符
    checkpoint(name: string): LensView
    requests(current: LensView): readonly LensRequestView[]
    addRequest(item: LensItem, note: string): LensRequest
    closeRequest(id: string): void
    scenarios(): readonly string[]          // scenarios/*.json 文件名
  }
  ```
  `requests` 的状态判定规则：closedAt 存在时为 closed；current 里找不到 itemId 时为 removed；字段与 valueAtCreation 不同时为 changed；其他为 open。写文件时先写临时文件再 rename。
