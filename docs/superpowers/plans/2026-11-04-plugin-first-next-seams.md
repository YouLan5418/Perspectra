# 插件优先运行时后续实施方案

日期：2026-11-04。源码基线：a8ffbf8。状态：实施草案，供用户审阅；尚未开始编码。

本文接续[第一轮插件优先设计](../specs/2026-11-02-plugin-first-runtime-design.md)与[阶段 5 记录](../../current/studies/2026-11-plugin-first-phase-5.md)。阶段 0～5 的历史验收不改写；本文中的新增接口、文件名和包名均为实施目标，不表示当前已经提供。

## 1. 先看这一轮想做到什么

玩家和两名角色在客厅聊天。作者希望：普通聊天时角色可以抢着回应；进入狼人杀后，依旧只能由合法的下一位参与者行动；离开活动后，角色恢复自主行动。开发者应能换一个调度插件控制处理机会，无需修改宿主，也不必重写狼人杀。

另一位开发者只想让对话发到本地模型，同时保留玩家设置的预设、输出处理与请求检查。现在替换整个模型通道会一起失去这些能力，后续应当允许只换发送部分。

再往后，开发者可以替换角色的一轮执行方式，例如先尝试操作，收到真实结果后再表达。无论如何组织模型调用，移动、物品变化和发言受众仍由主干检查并提交。

本轮的目标是把这些具体能力开放出来，让官方实现也走相同入口。减少宿主行数只是结果之一，不作为验收指标。

## 2. 当前证据与实施范围

| 当前证据 | 实际限制 | 对应工作 |
| --- | --- | --- |
| [环境比较](../../../desktop/host/tail-runtime.ts)只记录部分 Provider 的 ID、版本和 Core 的一个 identity 字段 | 换调度器或改变第三方明确声明的 identity，旧回合仍可能重新生成、切换候选 | 阶段 6：补全现有环境比较 |
| [模块列表](../../../apps/launcher/src/stores/modules.ts)逐接缝推断生效者；[加载器](../../../desktop/host-plugins.ts)按整个插件回滚 | 多服务插件因一个冲突被跳过，页面仍可能把其他服务显示为生效 | 阶段 6：统一冲突展示 |
| [版本匹配](../../../desktop/plugin-requirements.ts)丢弃预发布段，caret 在 0.0.x 上只限制 minor | 不符合依赖声明的版本可能通过检查 | 阶段 6：修正受支持范围的语义 |
| [活动轮次](../../../desktop/host/activity-round.ts)与[自主分段](../../../desktop/host/autonomy-round.ts)直接驱动角色 | 调度替换没有覆盖整个机会分配过程；部分模型预算仍由宿主掌握 | 阶段 7：补全调度 |
| [决策准备](../../../desktop/host/world-runtime.ts)先固定执行记忆、状态、知识、表情，再执行第三方 context | 插件可以追加内容，难以替换或重排官方扩充步骤 | 阶段 8：组合官方决策步骤 |
| [官方模型通道](../../../packages/official-llm/src/index.ts)同时负责预设和发送 | 只想换发送方式，也必须接管预设和显示处理 | 阶段 9：分离发送适配器 |
| [CharacterTurn](../../../packages/application/src/character-turn.ts)同时包含循环策略与授权、裁定、提交 | 直接搬到插件会把主干检查一起搬走；单纯代理 run 也不能算开放执行循环 | 阶段 10：先分离执行能力，再开放循环 |
| [WorldGameplay](../../../desktop/host/world-gameplay.ts)认识固定的状态、活动、通信等实现 | 默认游戏还不能完全由服务组合装配 | 阶段 11：在具体使用场景下逐项迁移 |

前 3 项来自本轮审查的本机复现，其余来自源码调用关系。当前已有的自动测试和历史真实模型对比只能说明对应版本、场景的结果，不能代替后续重构验收。

DSH 参考的是本机 0.2.2-alpha.2 快照中服务依赖、Agent 工厂和默认组合配置的做法，不是最新版本声明，也不以复制其内部实现为路径。历史 0.1.1-rc.1 目录当前没有可用的对应源码；不依赖它或其他仓库的未发布路径。

### 这一轮怎样分批

| 阶段 | 交付 | 工作量与风险判断 |
| --- | --- | --- |
| 6 | 接缝修复、可重复的行为基线 | 小；局部行为修复 |
| 7 | 普通反应、自主处理、活动机会均经过调度接缝 | 中高；涉及时序、预算和中断 |
| 8 | 官方上下文扩充按组合执行，复用 decisions | 中高；涉及顺序与认知隔离 |
| 9 | 第三方发送适配器保留官方预设与检查 | 中；涉及请求格式和模型路由 |
| 10 | 官方角色循环可被另一种循环替换 | 高；涉及事实与权限边界 |
| 11 | 默认组合装配，以及有实际替代者的玩法服务 | 高；范围取决于前面得到的接口和使用需求 |

先把阶段 6、7 作为首批实施。8、9 是下一批有明确收益的工作。10、11 保留路线与验收要求，在前面的公开接口跑通后展开到函数级任务，不把尚未验证的大接口一次性承诺下来。不用未经验证的天数或完成百分比代替工作量判断。

## 3. 保持的边界与有意接受的限制

- 事件日志、原子提交、授权视图、授权记忆来源、写租约和玩家读取授权继续由主干负责。第三方仍是可信代码，没有沙箱。
- 官方实现必须满足认知隔离与事实一致性；第三方可使用特权读接口，但不能把这种能力包装成对模型默认开放的私有信息。
- 官方调度继续有界。玩家预算对第三方只作建议；不因补全调度而新增宿主总量拦截。暂停、关闭、插话时的取消及失效世界拒绝提交仍是宿主职责。
- 活动规定哪些操作和参与者合法，调度插件决定是否、何时提供处理机会。插件不能通过官方入口让非法活动行动变成合法事实。
- 不改变自由叙述默认不结构化的原则，不新增 Grounding、语义分类器或全动作枚举。
- 不新增数据库、持久调度队列、Receipt、环境 Hash 协议或崩溃后续跑。复用现有环境比较、存档与候选机制。
- 不做市场、下载、热更新、通用插件 HTTP 路由、私有事件和任意前端代码注入。它们不是此次运行时拆分的前置条件。
- 世界包格式和既有官方包脚本语义尽量保持。若将来替换活动等玩法，依赖旧脚本的包可以明确不兼容，不建设永久兼容层。
- 新实验使用新目录，D:/worlds 只读。凭证只在进程中使用，不进入 identity、快照、模型请求基线或文档。

接口版本沿用现有 hostApi 机制：增量能力按兼容面更新，破坏 SchedulerInstance.run 等调用形状时明确升级主版本并更新示例，不为按阶段编号而升版本，也不靠旧接口回退来掩盖行为未接通。

## 4. 阶段 6：先修当前接缝并固定基线

### 6.1 执行环境记录

修改[环境比较](../../../desktop/host/tail-runtime.ts)，统一收集 scheduler、memory、llm、decisions、rules 的 ID、版本和公开 identity，保留可叠加实现的顺序。复用现有 JSON 环境比较，不再单独认识 memoryContextBudget 以外的某种实现。

identity 是插件作者明确声明的可公开、会影响执行行为的设置。官方 Provider 应提供它自身需要的字段；不自动序列化整个配置，不记录密钥，也不承诺识别未声明的配置变化。对象键顺序不应造成虚假变化，可复用现有规范 JSON 工具；不新增摘要算法。

继续区分两件事：打开存档允许更换模块并提示；旧回合的重新生成、候选切换需要匹配其记录的执行环境。模块配置变化也不自动变成玩家看到的模块版本变化。

- [ ] 为切换 scheduler ID/版本、修改 rules identity 各补最小回归，覆盖重新生成和选择旧候选。
- [ ] 验证相同 identity 换对象键顺序仍可重生；凭证轮换不改变公开执行环境。
- [ ] 更新后续拆分文件涉及的现有源码身份清单，避免移动文件后漏掉比较范围；不顺势建设全仓依赖哈希系统。

主要文件：[tail-runtime.ts](../../../desktop/host/tail-runtime.ts)、[tail-runtime-identity.ts](../../../desktop/tail-runtime-identity.ts)、[plugin-sdk](../../../packages/plugin-sdk/src/index.ts)、[tail-round 测试](../../../tests/host/tail-round.test.ts)。

### 6.2 组合冲突与依赖版本

- [ ] 在模块页按插件整体推断冲突：插件因已占用的单例接缝被整体排除时，其余声明不能显示为生效。上次运行的 skipped 结果仍保留原因。
- [ ] 页面区分“声明提供／下次预计使用”和“上次实际生效”，不能把读取清单等同于执行成功。清单不诚实、apply 临时失败仍只能在运行时确认。
- [ ] 复现 A 提供 scheduler、B 同时提供 scheduler 和 rules 的情况，检查模块页与真实加载器结果。
- [ ] 保留现有版本写法范围，修正 caret：^0.0.1 不接受 0.0.9；没有预发布支持时明确拒绝预发布值，不能删除后缀后按正式版比较。构建元数据不影响版本优先级。
- [ ] 验证 Launcher 和游戏进程使用同一依赖检查，稳定插件 ID 与已保存密钥不受影响。

主要文件：[模块列表与测试](../../../apps/launcher/src/stores/modules.ts)、[插件页](../../../apps/launcher/src/components/PluginSettingsPage.vue)、[加载器](../../../desktop/host-plugins.ts)、[依赖检查与测试](../../../tests/desktop/plugin-requirements.test.ts)。

### 6.3 固定可重复基线

- [ ] 将既有阶段 3、4 的 scratchpad 决策探针整理为仓库内可重复运行的测试支持或研究脚本，使用假服务端，不依赖本机私有脚本。
- [ ] 对同一初始场景连续运行两次，记录实际请求、执行结果、玩家转录、机会顺序和预算计数，确认可比较后再拆分。
- [ ] 只规范随机 ID、时间和明确的非语义差异。不得删除受众、私有字段、规则参数、错误或状态结果来让对比通过。
- [ ] 请求实际为 0 次的脚本场景明确标成“脚本结果比较”；不重复声称它覆盖了真实模型请求。

基础场景沿用 dynamic-scheduling、预设映射、Google/Anthropic、stageExpressions、Core 注入替身、甜蜜日程、状态市场、觉醒活动与脚本模拟。狼人杀单独通过正常活动流程验证，不依赖一个未发出请求的探针。

完成条件：3 个缺陷有回归；官方请求和转录除缺陷修复的预期差异外保持一致；后续实施者不需要原机器的 scratchpad 才能比较。

## 5. 阶段 7：让调度接缝覆盖完整的处理机会

### 7.1 职责与接口方向

保留 ctx.scheduler 和每世界 open/close。扩展其轮次输入，使同一个调度实现能够区分场景反应、自主处理和活动处理；不再增加 activityScheduler 或 autonomyScheduler 服务。

| 留在宿主／玩法的输入与执行能力 | 移到官方调度实现的策略 |
| --- | --- |
| 当次角色、场景、授权观察序号与最新世界前缀 | 顺序、并发、波次、停止条件 |
| 作者自主配置的到期机会和活动的合法下一参与者 | 自主机会怎样消费，是否和普通反应整合执行 |
| 绑定当前世界、角色及玩法的 turn 能力 | 活动最多处理几次、何时让回玩家 |
| 活动提交后的 outcome 计算、外部结果未知标记 | 官方机会预算、调用预算、调度截止时间 |
| 暂停、关闭、失效世界拒绝提交 | 官方调度内部的剩余预算与结果汇总 |

活动输入只提供选择下一合法参与者所需的少量数据／回调，不把 PackActivities、WorldGameplay、WorldStore 或 CharacterTurn 直接交给插件。宿主执行活动 turn 时重新检查角色是否合法，并用实际执行结果推进 outcome；插件不自行伪造 outcome 参数。活动刺激仍按当前路径构造，第一步不顺带改变角色看到的历史窗口。

普通反应、自主处理的观察继续以序号引用；[scheduler-round](../../../packages/application/src/scheduler-round.ts)检查归属。活动所需的观察适配也由宿主完成，不让插件传入任意原始刺激。

### 7.2 迁移任务

- [ ] 先列出当前普通／整合自主／分段自主／活动四条路径的入参、计数和退出行为，沿用 6.3 基线。
- [ ] 在 plugin-sdk 定义上述轮次输入和最小活动能力，结果只携带宿主展示与继续流程实际使用的计数、激活和结束原因。
- [ ] 将 autonomy-round 中的循环、剩余预算和超时策略移入 official-scheduler；PackAutonomy 的配置解析、合法行动规则仍在玩法内。
- [ ] 将 activity-round 中的机会循环和预算策略移入 official-scheduler；保留宿主的合法参与者与结果桥。
- [ ] 分清现有 calls 的计数口径与实际模型发送次数。重试和结果续写继续计费，脚本模拟不算真实发送；不得悄悄改计数口径。
- [ ] 把官方自主预算在 runDecision 发送前使用的检查，改为由官方调度随本轮调用传入的预算回调；包括格式重试，不能只在最终结果上估算。第三方没有提供该回调时不施加官方总量限制。
- [ ] 宿主删去已迁走的机会循环与 #callBudget 策略，只负责构造当次能力、调用 scheduler 和映射玩家提示。删除或收缩空壳辅助文件，不保留两套生产调度路径。
- [ ] 更新 impulsive-scheduler 示例，证明同一第三方 Provider 收到了普通、自主和活动机会；活动中只能处理合法参与者。

主要文件：[world-runtime](../../../desktop/host/world-runtime.ts)、[autonomy-round](../../../desktop/host/autonomy-round.ts)、[activity-round](../../../desktop/host/activity-round.ts)、[character-decision](../../../desktop/host/character-decision.ts)、[scheduler-round](../../../packages/application/src/scheduler-round.ts)、[official-scheduler](../../../packages/official-scheduler/src/index.ts)、[plugin-sdk](../../../packages/plugin-sdk/src/index.ts)、[示例调度器](../../../examples/host-plugins/impulsive-scheduler.mjs)。

### 7.3 验收与停止条件

- [ ] 官方配置下整合／分段自主、普通反应、活动正常与失败路径都和基线一致；变化必须逐项解释。
- [ ] 非法活动角色、伪造观察序号、暂停后晚到的结果不能通过官方执行入口提交。
- [ ] 覆盖活动 abstain 不换手、失败不换手、外部结果未知停止、机会耗尽和格式重试计数。
- [ ] 第三方能改变自主机会顺序及活动处理次数；仍不能改变活动规则的合法顺序。
- [ ] 重新生成、候选切换和节点重开各获得独立实例，已启动工作在关闭前完成或取消，注册资源被清理。
- [ ] 用真实模型走普通聊天、甜蜜日程正常序章、自主触发和狼人杀轮次；与阶段 6 新基线对照可见行为、调用次数和等待。出现明显重复、静默断层、越权知识或事实分叉时先调查，不以测试通过替代解释。

若新增接口只是要求插件接收宿主对象、然后调用原来的整个 activity-round/autonomy-round，视为未完成。若接口需要复制玩法的大部分方法，先缩小桥接的数据，不能借本阶段重做 ctx.gameplay。

## 6. 阶段 8：把官方扩充步骤放进决策组合

### 8.1 默认顺序与数据边界

复用 ctx.decisions 的 context、decide 和生命周期。将宿主固定的扩充步骤注册为有稳定 ID 的官方实现，默认顺序保持：

~~~text
主干构造授权基础上下文与活动约束
→ 记忆投影
→ 最近执行证据（启用时）
→ 已知状态与公开变化
→ 按当前上下文选择设定
→ 舞台表情材料
→ 第三方追加 context
→ 决策包装、预设准备、发送与格式处理
~~~

“已知状态”和设定读取不能随文件移动而退化成直接把全量状态交给模型。复用 WorldGameplay、PackStatus、PackKnowledge 已有选择逻辑，将所需的授权派生读取作为窄能力注入；若第三方替代者需要同一读取，则补进公开 SDK，而不是给官方实现留一个私有宿主捷径。

不把每个步骤拆成一个包。少量官方扩充先放一个职责明确的官方包；记忆整理仍由 memory Provider 负责，context 步骤只调用它的 project，不另建记忆系统。

### 8.2 实施任务与验收

- [ ] 注册与执行顺序分离：由默认组合的有序 ID 列表确定官方顺序，未指定位置的第三方步骤按加载顺序追加。不引入拓扑排序、优先级打分或依赖图引擎。
- [ ] 相同官方步骤允许被明确的第三方实现替代；显式停用的步骤不再被默认补回。替代和停用进入执行环境记录。
- [ ] 明确必需的授权基础材料不可停用；可关闭的是扩充步骤，不是主干权限检查。
- [ ] 对依赖前序材料的知识条件验证顺序；默认组合下请求逐项相同，避免两次 memory.project 或重复加入状态。
- [ ] 第三方示例替换一项知识扩充，在保留其余官方步骤的情况下改变可见材料，并证明其他角色的私有状态没有进入请求。
- [ ] context／decide 失败仍报告对应实现，玩家输入和已提交行动保留；候选和关闭生命周期无新增全局状态。

主要影响：[world-runtime](../../../desktop/host/world-runtime.ts)、[world-gameplay](../../../desktop/host/world-gameplay.ts)、[character-decision](../../../desktop/host/character-decision.ts)、[official-bundle](../../../desktop/official-bundle.ts)、[决策接缝测试](../../../tests/host/decision-seam.test.ts)、plugin-sdk 与新增的官方扩充包。

完成条件：宿主不再手写官方扩充调用顺序；开发者替换一个步骤不需要接管整条决策。模块地图和认知、作者文档据实际能力更新。

## 7. 阶段 9：只换模型发送，保留官方处理

在现有 ctx.llm 内区分“完整模型通道”和“发送适配器”，后者由官方通道包装；不是再新增一个模型网关服务。完整替换仍保留，不能悄悄给旧的完整替换插件套上预设。

- [ ] 从 official-llm 的 send 中分离实际传输调用与 presetOutput，prepare、promptText、display 仍可由官方提供。
- [ ] 给传输适配器公开标准 LlmCall、返回值和取消接口，复用每世界 open/close。新传输的请求形状不能由一个没有实际被调用的官方模型协议配置决定。
- [ ] 只读的请求检查和调用完成记录由官方包装层维护，记录发出的实际 messages/schema；不向适配器传递官方模型 Key 或整份模型连接。
- [ ] 完整通道与发送适配器互斥；出现冲突时页面和加载器一致。适配器失效时不开世界或本轮明确失败，不能回退官方发送，把故事发到另一个地址。
- [ ] 新模式下明确玩家意图 dispatch 与 Core 记忆仍走哪里；第一批只替换角色决策发送，不宣称它覆盖 Core。无法支持启用中的 dispatch 时在启动前报明原因。
- [ ] 实际组合身份同时记录官方包装和发送适配器；配置 identity、候选比较和模块变化提示使用阶段 6 的机制。
- [ ] 用 simple-llm 的发送部分作为示例：官方端点设为不可用，本地服务收到带预设的请求；输出规则、展示规则和创作者检查仍有效。

主要文件：[official-llm](../../../packages/official-llm/src/index.ts)、[角色连接与预设](../../../packages/official-llm/src/role-providers.ts)、[决策发送](../../../desktop/host/character-decision.ts)、[host-plugins](../../../desktop/host-plugins.ts)、[模型接缝测试](../../../tests/host/llm-seam.test.ts)、[simple-llm](../../../examples/host-plugins/simple-llm.mjs)、Launcher 模块展示和 plugin-sdk。

验收：默认官方三协议请求保持原行为；自定义传输保留预设；重试只做现有的一次，脚本模拟仍绕过模型输出规则；取消、401／格式错误、候选重开与凭证不落盘通过。最后用一个真实第三方传输与预设组合短局验证。

## 8. 阶段 10：开放角色执行循环前，先抽出主干执行能力

此阶段需要一份独立的接口设计记录。不能只把 CharacterTurn 改成 official-character-loop 的导出：当前类包含授权上下文、过期检查、受众、规则、观察和 commitRound，这些不是可替换策略。

### 10.1 先做内部拆分

- [ ] 把角色绑定、授权上下文构造、最新前缀检查、写租约、规则执行、受众计算、观察与原子提交留在 application 的执行对象内。
- [ ] 将 perform/publish/abstain 的循环次数、是否续写、如何处理执行结果等默认策略独立；内部拆分后先跑官方基线，不立即开放任意策略。
- [ ] 保持目前模型计算不持有 SQLite 事务、提交串行和取消后拒绝晚到结果的行为；不要为了接口便利把长事务跨过模型请求。

### 10.2 再定义公开循环

建议一个角色循环接缝，沿用 SeamProvider。名称暂按 characterLoop 讨论，实际命名以接口设计记录为准。它替代现有 CharacterTurn 的循环策略，不在现有循环外面再包一层循环。

每次 run 只获得绑定当前世界实例、角色与激活的能力：读取当前授权请求、调用决策组合、申请受控行动／发布、读取实际执行结果、结束本次处理。不得传入其他角色充当执行者，不返回原始存储句柄，不暴露 commitRound。

主干必须在每次申请时检查信号、世界版本、合法动作及受众；插件返回的“成功”只作为策略结果，不能单独成为已提交事实。新循环仍使用现有重要事件，不开放自定义事实事件类型。

- [ ] 先以现有官方循环消费这些公开能力，证明没有给官方留下私有能力。
- [ ] 第三方示例采用另一种明确的策略，例如最多一次操作后仅续写一次；不能只是调用旧 CharacterTurn.run。
- [ ] 验证过期前缀、同角色并发、非法角色、非法动作、不可达私聊受众和取消后的调用被拒绝；角色循环不能伪造 action.resolved 或自行指定观察接收者。
- [ ] 验证行动已提交、后续模型失败时行动保留；续写与 continuationOf 不重复执行原行动。
- [ ] 用外部插件在打包后端加载，走活动、自主和普通处理；第三方的模型材料仍来自授权请求。

当前 publish／perform 输出协议暂保留。其他模型协议将来可由循环或适配器翻译为主干认识的申请，不在本阶段同步重写所有世界包。

如果一次抽取必须公开大量租约／存储／宿主内部方法，应先保留内部拆分结果、缩小能力接口并记录原因，不能将一个仍需理解 CharacterTurn 内部的代理宣布为已开放循环。

## 9. 阶段 11：默认组合与玩法服务，分开交付

### 11.1 先让默认组合真正参与装配

把 official-bundle 从若干工厂的集中导出，变成声明“安装哪些官方服务、哪些步骤、什么执行顺序”的默认组合。复用 Cordis 已有 Service、inject、effect 和每世界 Provider，不造第二个服务容器，不把两个不同生命周期的 Cordis 根强行合并。

- [ ] 官方实现通过公开接缝注册；第三方与官方遵守相同冲突及生命周期规则。
- [ ] 装载器负责装载和诊断，组合负责策略选择；宿主负责世界能力和提交，不直接选择具体算法实现。
- [ ] 明确三种不同关系：世界包 requiresPlugins、Cordis 服务 inject、决策步骤的执行顺序。它们互不替代，也不合成一个通用依赖协议。
- [ ] 补服务依赖缺失和循环依赖的启动诊断；复用 Cordis 的就绪行为，避免串行 await 某插件导致其后提供的依赖永远没有机会注册。
- [ ] 默认无需配置即可启动；显式关闭的可选功能不被补回，缺少必需主干能力时明确失败。
- [ ] Launcher 展示实际组合与冲突。第一批只支持启动时生效，不建设热卸载和 HMR。

### 11.2 有替代需求时再迁玩法

保持此前不做巨大 ctx.gameplay 的决定。逐项考察活动、状态、通信、知识和自主配置中哪些需要被独立替换。优先从状态／知识的授权读取和阶段 7 的活动机会桥复用能力，避免为迁包先公开数据库。

每迁一项必须有：现有消费者清单、真实替代者、最小服务能力、包脚本兼容范围、独立验收。若只能把约二十个宿主方法一起公开，就先保留官方玩法，不以“一切皆插件”为理由接受该接口。

完成这一批才能称“默认游戏由插件组合构成”。插件市场、前端组件生态和热更新另立需求；没有它们不妨碍运行时服务化，也不能把服务化称为已经达到 DSH 的生态成熟度。
