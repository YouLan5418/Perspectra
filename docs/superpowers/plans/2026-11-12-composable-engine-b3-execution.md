## 审阅后固定范围

- WorldApplication 提供绑定现有实例 scope 与分支的公开执行协调器。一次请求的激活数、并发与期限同步占额，周期换界不重置。调度、活动、直接角色请求以及经 Host 的 Lens 共享此入口。
- 公共默认预算为 27 次激活、2 并发、270 秒；Host 依现有游玩参数和显式 executionBudget 覆盖授予请求。策略可以少用，不能绕开核心准入。单角色时限仍受请求剩余时限约束。
- 周期完成、预算耗尽、取消和失败由核心观察到的执行结果决定；调度器返回值不能覆盖已发生的核心停止原因。关闭请求后旧能力失效，未提交周期不持久化。
- onCycleEnd 接收具名纯效果钩子，经现有 executeWorldRound 验证与逐钩子原子提交；按插件和钩子 ID 排序，失败保留前面已经提交的结算。B4 接玩法注册。既有 status／pacing 的业务归属迁移留 B5，本批保留静观的现有顺序，不用人为 legacy ID 或改变静观体验解决排序问题；它们的收尾激活仍消费同一 grant。
- 修正 B1 激活结果的强制提交状态，记录实际行动／表达是否提交与最后合法决策。abstain 和零提交不伪造 accepted；NPC 私有结果不进入玩家 state/debug。
- 复用 provider-chat 的 fetch／onCall 观察计量发送、格式重试、可见 HTTP 尝试和已报告用量。Google 与不透明原生 transport 明确标记不可见范围，未知用量不记零；不引入全局 fetch 修改或新的后台预算框架。

## 当前实现与初步证据

公开工厂复用 application 的实例 scope 和已有 branch；创建时释放读取带来的 writer，结算时重获同一分支并先 yieldWriter，不缓存已被保存节点释放的 Store。钩子只收到克隆快照，效果先检查，再经原事务提交。循环结束撤销旧控制能力，结算后的激活使用新控制能力和原 grant，不重开额度。

CharacterTurn 在真实 commit 后、回调前上报提交进度；合法 abstain 在校验后记录。执行结果保留受控行动与表达提交标志、最后合法决策、失败分类和部分结果，不增加持久 Receipt。取消与同拍核心异常分别处理，不能因请求恰好取消就吞掉已观察到的存储错误。忽略取消的 runner 仍占用并发，直至真实执行结束。
