## 实施落点

1. 在 application 绑定已有世界实例 scope／分支的原生玩法注册与执行适配，公开 SDK 定义仍是唯一作者结构。注册按所属 Context 清理，装配检查模块、状态、操作、方法和活动重名；不生成旧脚本文本。
2. 状态继续用 StatusState、status.updated 和既有 Schema／可见性。初始化显式区分 public／characters，替代 B1 未绑定归属的扁平初值；无状态模块可以不声明初始化。候选读取已知投影，裁定与周期钩子只读取所属状态。活动继续用 ActivityStateRules 和现有 activity.updated／生命周期。
3. 定义 Restriction，按稳定 ID 对适用规则合取；候选许可不能替代提交时复核。每个操作绑定唯一 Handler。公开计算方法只贡献所属模块的受控效果，不能直接提交；方法与主处理器读取同一快照。
4. 对主结果先做结构／权限检查，形成共同候选，再执行单层 afterAction。各钩子不读取其他派生的中间结果；重复地址需要所属模块显式组合，否则故障。最终检查 Schema、受众、状态转换和所属模块不变量后原子提交。伤害修正和倒地由伤害模块计算组织，验证追加派生不会留下最终不一致。
5. 原生 onCycleEnd 绑定 B3 内部适配器，作者只收到所属状态与 SDK 效果，不得到原始全量快照或提交权限；逐钩子原子结算、至多一次语义沿用 B3。
6. offer／参数 Schema／NPC 用途接通通用候选材料。结果先按接收者投影再格式化；无显式旁观者投影时只给基础目击说明。格式化失败只告警并保留已提交事实。

### 实现说明

- [GameplayRuntime](../../../packages/application/src/gameplay-runtime.ts)绑定原有 scope、引擎与分支，支持多模块状态／方法／操作／限制／活动，注册检查重名、依赖与 Context 归属，清理由所属 Context 和实例 scope 拥有。
- [WorldApplication](../../../packages/application/src/world-application.ts)在既有玩家入口和借出的角色回合上统一接入分支规则；[CharacterTurn](../../../packages/application/src/character-turn.ts)将授权原生材料加入模型上下文和新鲜度比较。无需调用者手动包一套可选规则后才受限制。
- [作者契约](../../../packages/plugin-sdk/src/gameplay.ts)把初值绑定到已有 StatusTruth；无状态模块可省略初值。methods 复用强类型操作契约，compute 提供同步、同快照、只贡献所属效果的计算能力。combineChanges 由所属模块归并整组冲突，允许一并归一化生命值和倒地，不能留下重复地址或越权字段。
- 原生操作先验证主效果，再把同一 candidate 交给全部单层钩子；派生故障、合并冲突和最终不变量失败都在提交前终止。候选只消费已知投影，正式执行重新检查限制和当前状态。
- 活动复用 ActivityStateRules 和既有生命周期；绑定的原生操作检查参与者、当前行动者及版本。操作／活动结果都先做接收者投影及结果 Schema 校验再格式化，旁观者默认不获得完整 outcome。可选格式化故障只留下脱敏诊断。
- 原生周期钩子只收到所属真值和 actor 投影，经 B3 内部适配执行。contracts 的 status cycle 来源区分系统周期和玩家轮次；恢复值调用 StatusState.validateSnapshot，不以重新初始化覆盖已提交数据。随机初始化的实际抽样以十进制字符串记入既有 authority，遵守 WorldJson 仅允许安全整数的约束。
