## 实际修改与原因

### RPG 只有技能名，缺少能用于决策的效果说明

最初角色请求主要提供技能枚举和当前数值，不能可靠解释新增技能的成本、护盾、持续效果或共享值。复用原生定义已有 `projectState`，共同运行时将**角色授权已知状态**的投影加入 `context.gameplay[].state`。RPG 补入该角色所学技能及相关公共规则。

没有新增 Prompt 框架、事件总线、SDK 钩子或持久字段。新增技能说明不包含敌人策略、掉落、完整 truth 或其他角色的技能成本与效果表。既有活动参数枚举仍可能包含全队技能名称并集；正式裁定继续检查角色自己是否掌握该技能，不把名称枚举宣称为完整技能隐私隔离。初版把说明放入活动私有状态，经独立审查发现合法大技能表会超过 64 KiB，已移除；最终说明从配置派生，不扩大存档。100 项额外技能、两位参战角色的容量回归和独立复验通过。

### 示例许可与模型候选收窄

独立回归审查发现同居示例未显式允许 attack／magic／heal／guard／vote，模型正常使用这些活动操作会被拒绝。只补示例角色的对应许可，没有恢复默认全放行。

活动桥原先在 `projectContext` 里重新构造 policy 选项，可能重新放出上游已剔除的动作。现与上游合法候选求交，保留原始选项和参数 Schema。负例验证：policy 声明猜测和退出，而上游只允许退出时，模型只能收到退出。

### 实际浏览器刷新重新占用写租约

便携版浏览器中，玩家的雨中火球已提交并扣血，NPC 返回后却报 500。堆栈精确落在 `CharacterTurn.pendingSubmit`：SSE 刷新 `playerView` 调用 `WorldApplication.#branch`，恢复了宿主写租约，NPC 无法取租约。

已挂载分支的快照、head、玩家候选、授权角色视图、`read` 查询及死信读取不再恢复写租约。执行、管理写入、结算仍走原来的恢复、认知同步、维护屏障、fencing 与完整性保护。首次挂载仍会初始化协调器，不承诺任意首次读取都无租约副作用。

新回归先准确复现同一 `WORLDSTORE_BUSY`，再在同一次 NPC 提交前遍历正式只读入口，验证发表确实提交。旧复用测试改由执行入口触发恢复，仍检查认知同步、其他写者租约、维护屏障和失败清理。

### B10 后残留的测试与发行验收入口

旧测试夹具补显式 pacing／脚本插件、实际安装清单与空 seams，故障断言采用当前结构化 PluginFault；没有为旧测试增加运行兼容分支。Windows `--import` 使用文件 URL；隔离布局测试让 esbuild 返回构建内容，由 Node 写外部目录。

发行验收补齐 core worker 测试导出、明确离线不可连接模型目标；舞台资源比较采用正式入口实际注册的官方舞台，仍完整比较 HTML／CSS／JS。移除 26 个仅残留 `node_modules` 的旧包空目录，未删除源码或用户文件。
