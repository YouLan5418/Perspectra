# 启动器改版设计

日期：2026-10-17
状态：待评审
前置：先把 `feat/launcher-model-connections`（worktree `.claude/worktrees/launcher-model-connections`，比 main 多 16 个提交）合入 main，本设计以合并后的代码为基线（用户决定）。
草图：`.superpowers/brainstorm/2912-1792244158/content/`（`layout-v2.html` 选 C；`settings-v2.html`）

## 1. 为什么改

现在的启动器（`apps/launcher`）用起来像“套了壳的网页”：

- Steam 式“左侧游戏列表 + 右侧可滚动长页面”。右侧依次是封面、进度卡、实例下拉、“关于这个世界”、“游玩准备”，以及折叠的“引擎与创作者工具”。
- 系统标题栏、可任意拉伸的窗口、底部网页式状态栏。
- 重要入口藏得深或重复：前端沙箱权限在页面最底部的折叠区里；角色预设、模型各有两个入口；API 地址可以在全局和实例里各填一次。
- 创作者控制台直接占满启动器窗口。

用户的参照物是 PCL2 和米哈游启动器：一个固定的“窗口”而非一张页面，一屏放完，主操作只有一个且醒目，大面积留给画面。用户明确不喜欢 Steam 式列表。

玩家打开启动器最常做的四件事：**启动游戏、配置 API、调整预设、选择要玩的包。**

## 2. 目标、非目标、反目标

**目标**

- 主界面是“米哈游启动器式”的全窗口封面，一屏放完、不滚动，主按钮唯一。
- 本局相关设置收进一个右侧抽屉，全局设置收进一个弹出设置窗口，各只有一个入口层级。
- 沙箱 / 模型状态常驻可见，点击直达对应设置。
- 创作者控制台改为在系统浏览器中单独打开，和玩家前端一样。
- 存档职责重新划分（见 §6）。

**非目标**

- 不改 Core、世界事实、权限隔离、提交逻辑。
- 不重做角色预设编辑器、运行参数表单的内部字段；只是换容器。
- 不做独立的系统级设置窗口（设置是启动器内部浮层）。
- 不做从封面自动取色。

**反目标（即使能用也算失败）**

- 改完仍然需要上下滚动才能找到开始按钮或沙箱状态。
- 对话框叠对话框。
- 封面被大面积遮挡或压暗到看不清角色（群像图左右两侧都有人物）。
- 运行中误改设置后，玩家以为已对当前这局生效。

## 3. 主界面（C · 米哈游启动器式）

参照 `layout-v2.html` 的 C。

```
┌ Perspectra ──────────────────────────── ⚙  –  ✕ ┐  ← 自绘标题栏，透明渐变压在封面上，可拖动
│▣│                                                 │
│▢│              世界包封面（铺满，cover）            │
│▢│                                                 │
│+│ 晚餐时分                         [⋯] [继续游戏]  │  ← 底部渐变托住文字和按钮
│ │ 主故事线 · DeepSeek V4 · ◉沙箱                   │
└─┴─────────────────────────────────────────────────┘
```

- **左侧细图标栏**（约 46px，半透明深色 + 模糊）：每个世界包一个小方图标（封面裁切；无封面用现有 artwork 色调 + 首字），当前包描边高亮；hover 显示包名。最下方“＋”= 载入游戏包（现有 `ImportDialog` package 模式）。
- **封面**：铺满窗口其余区域。无封面时用现有 `artwork` 色调生成的排版封面。
- **左下**：包名（大）、副标题行：当前故事线 · 当前模型 · 前端权限状态。后两者是可点击的小标签，点击打开抽屉并定位到对应行。校验未通过时这里显示原因（沿用 `playBlockedReason` / `validation.issues`）。
- **右下**：主按钮 + “⋯”。
  - 空闲：主按钮“开始游戏 / 继续游戏”（沿用现有判断）；`playBlockedReason` 非空时禁用并在副标题行说明原因。
  - “⋯”打开本局抽屉。
- **右上**：⚙ 打开全局设置窗口；最小化、关闭。

**运行中**（用户原话：和米哈游启动器类似）：

- 主按钮变“结束游戏”；旁边增加“回到游戏页面”（现有 `reopenGame`）和“打开创作者页面”（§5）。“⋯”保留。
- 主按钮附近一个小呼吸灯表示运行中，替代现在的底部状态栏（状态栏删除）。
- 左侧图标栏变灰不可切包（与现状一致）。
- 设置仍可打开、可修改，但**只在下一次启动的游戏生效**（见 §4.3）。

**空状态**：没有任何世界包时，图标栏只剩“＋”，主画面是默认封面加一句“载入一个世界包，开始你的故事”和一个载入按钮。本机初始化失败时显示原因和“重试初始化”（沿用现有逻辑）。

## 4. 设置

### 4.1 本局抽屉

参照 `settings-v2.html` ①。

- 从右侧滑出，宽约 44%，**偏白的透明毛玻璃**（`backdrop-filter: blur`，白色半透明底），左侧封面仍可见；不加压暗遮罩。点 ✕、按 Esc 或点抽屉外区域关闭。
- 抽屉标题：包名 + 游玩实例下拉（切换实例 / 新建独立实例，沿用现有逻辑）。
- 行（点击后在抽屉内部翻页到该项详情，带返回；不再弹对话框）：

| 分组 | 行 | 摘要 | 详情页内容来源 |
|---|---|---|---|
| 游玩 | 存档 | 当前故事线 · N 条 | §6 启动器侧：切换故事线、载入旧节点、导入、导出（现 `StorylineDialog` + `ImportDialog` story 模式 + `ExportDialog`） |
| 游玩 | 模型 | 默认模型 ·（另有 N 个角色单独配置） | 分支里的实例“角色模型分配”内容：默认（所有角色）连接+模型+思考强度、按角色覆盖决策/记忆整理模型（即分支版 `ModelConfigDialog` + `ModelPicker`） |
| 游玩 | 角色预设 | 采用包推荐 / … | 现 `PresetDialog` 内容 |
| 游玩 | 前端权限 | 沙箱 / 已信任 / 官方模板 | 现 `FrontendAuthorizationDialog` 内容 |
| 进阶 | 运行参数 | 波数 · 调用 · 超时 | 现 `PlaySettingsDialog` 内容 |
| 进阶 | 创作者工具 | — | “打开创作者页面”（运行中才可用，否则说明原因） |

- “前端权限”当状态为“沙箱 + 自定义前端”时，该行用淡橙底提醒，右侧动作文字为“解除沙箱 ›”。详情页保留现有的风险说明与确认流程，不弱化。
- 抽屉内详情页若有未保存修改，返回或关闭时提示（沿用 `PresetDialog.requestClose` 的思路）。

### 4.2 全局设置窗口

参照 `settings-v2.html` ②。

- 启动器内部的居中浮层（不是独立系统窗口），背后启动器轻度压暗。
- 左侧分类：**模型接口、外观、阅读与声音、数据位置、关于**。内容来自现 `ModelSettingsDialog` 与 `SettingsDialog`。
- 底部按钮：**取消**（丢弃未应用改动并关闭）、**应用**（生效，不关闭）、**保存**（生效并关闭）。✕ 等同取消；有未应用改动时提示。

### 4.3 模型接口：沿用 `feat/launcher-model-connections`（用户决定）

该分支已实现“连接只配一次、模型从列表里选、按角色分配”，设计见分支内 `docs/superpowers/specs/2026-10-17-launcher-model-connections-design.md`。要点：

- 全局维护多条连接（名称 + 协议 + 完整地址），每条可拉取模型列表、测试连接；Key 存 Windows 凭据管理器（`Perspectra/model-connection/<id>`），不写盘、不进日志与请求检查器。
- 实例只从汇总模型列表中选：默认（所有角色）决策模型 + 思考强度 + 记忆整理模型；可按角色覆盖。
- 删除仍被引用的连接时提示，引用处显示“连接已删除，请重新选择”，修好前不能启动。
- 旧数据的一次性迁移已在分支内完成。

本改版**不改其数据形状和行为**，只换容器：

- 分支的全局“模型设置”（连接管理）放进全局设置窗口的“模型接口”分类；其中的即时保存操作（新增 / 编辑 / 删除连接、写入凭据）保持分支现有语义，不套用窗口底部“应用 / 保存”的草稿语义——“取消”只丢弃外观、阅读与声音等草稿类改动。窗口在“模型接口”页时于页内注明“连接修改立即保存”。
- 分支的实例“模型配置”放进本局抽屉的“模型”详情页。
- 主界面副标题行与抽屉“模型”行显示默认模型；有覆盖时追加“另有 N 个角色单独配置”（分支已有此摘要）。
- 合并后若 `GameDetail.vue` / `GameList.vue` 中分支新增的入口与本改版重叠，以本改版布局为准。

### 4.4 运行中允许修改设置（行为变更）

现在 `desktop/launcher-core.ts` 的 `settings / configure / play-settings / preset-save / preset-global / preset-instance` 都先调 `#idle()`（合并分支后，连接与实例模型分配相关的写请求以分支实际名称为准，一并处理），运行中直接拒绝，前端也全部禁用。

- 这些设置都只在 `start` 时读取并注入子进程（main 上已核对；合并分支后实现者需复核模型分配与 Key 也仍只在 `start` 时读取），运行中改写持久化配置不会影响当前这局。因此对上述请求去掉 `#idle()` 限制，前端不再按 `running` 禁用。
- 运行中打开抽屉或设置窗口时，顶部固定一行提示：“修改将在下次启动游戏时生效”。
- **仍保持运行中禁止**：切换包、切换实例、新建实例、存档类操作（`story-select / story-fork / story-import`）、授予前端信任（`frontend-grant`）。导出允许（只读）。
- **例外（我的决定）**：撤销前端信任（`frontend-revoke`）保持现状——运行中可用且立即生效（`#revokeRunning`）。收紧权限应当即时，抽屉里该项单独注明“立即生效”，不套用“下次启动生效”提示。
- 外观类（主题、配色、大字）立即作用于启动器本身，与运行状态无关。

## 5. 创作者页面搬到系统浏览器

**现状**：`CreatorConsole.vue` 在启动器窗口里全屏打开。数据走 启动器 → Tauri → `desktop/launcher-core.ts` → 运行中子进程的 HTTP `/api/creator-debug | creator-history | creator-records`（`tests/experiments/playtest-server.ts`，带 `x-playtest-token`）。请求探查走同一服务器的 `/api/request-inspector`。

**改为**：

- playtest 服务器新增一个页面路由（如 `/creator`），提供单独打包的创作者控制台前端；页面直接用 fetch 调用上述已有 `/api/creator-*` 和 `/api/request-inspector`，token 与玩家前端相同（启动器打开 URL 时通过 `#token=` 传入，与玩家前端一致）。
- 请求探查（现 `RequestInspectorDialog`）并入创作者页面，作为其中一个视图；启动器里不再单独放入口。
- 启动器里“打开创作者页面”= 用系统浏览器打开该 URL。仅在游戏运行时可用。现有 `open` 通道在 Tauri `main.rs` 里严格校验返回地址必须是 `http://127.0.0.1:端口/#token=`，因此新增一个专用 operation（如 `open-creator`）并做同样严格的 `/creator` 路径校验，不放宽现有 `open` 的校验。
- **迁移而非共用（我的决定）**：`creator/` 组件迁到新入口，数据源从 Tauri `invoke` 改为同源 fetch；启动器内的 `CreatorConsole` 全屏模式、`creator/` 目录、`inspectCreator*` / `inspectRequests` IPC 以及 `launcher-core` 中 `creator-*` / `request-inspector` 透传全部删除。页面需要的游戏名、故事线、角色列表由 playtest 服务器新增一个只读元信息接口（同 token）提供。mock 预览源随组件迁走，供开发预览。
- **发行包也必须可用（用户决定）**：
  - 创作者页面作为独立的 Vite 构建入口产出静态资源；`scripts/release/build-portable.mjs` 仿照现有 `packages/frontend/assets → runtime/frontend-assets` 的做法，把产物复制到 runtime 目录（如 `runtime/creator-assets`），开发模式从仓库构建目录读取。`scripts/release/verify-portable.mjs` 增加对该目录存在的检查。
  - playtest 服务器为 `/creator` 及其静态资源单独设置路由和 CSP：允许 `script-src 'self'` 与 `connect-src 'self'`，不放宽宿主页现有 CSP；静态资源只从该资源目录提供，拒绝路径穿越。
- 权限：创作者页面能看到所有角色的私有上下文，这和现在启动器里的控制台能力一致；访问边界仍是本机地址 + token，不新增、不放宽。

## 6. 存档职责划分（用户决定）

| 位置 | 做什么 |
|---|---|
| 玩家前端 | **保存当前进度**：创建完整节点，保存后继续游玩 |
| 启动器 | **切换故事线、载入旧节点、导入存档、导出存档** |

- **玩家前端保存**：现在保存由启动器通过子进程 IPC `story-save` 触发，子进程调用 `runtime.saveNode(title)`（`tests/experiments/playtest-web-entry.ts`）。改为在 playtest 服务器加一个带 token 的 `POST /api/story-save` 直接调用同一个 `runtime.saveNode`；“保存进度”按钮放在**宿主页工具栏**（`tests/experiments/playtest-host-page.ts`，用户决定），所有包、包括自定义前端都可用，不扩展公开的 Frontend API。按钮可填节点名，默认给一个时间名。忙碌时沿用现有 `PlaytestBusyError` 提示。启动器侧的“保存完整节点”按钮和 `story-save` IPC 删除。
- 启动器通过现有轮询刷新节点列表，看到新节点。
- **启动器侧**：抽屉“存档”详情页提供故事线列表、节点列表（选中节点 = 从该节点分叉 / 载入）、导入、导出。运行中只可浏览和导出，切换与载入在下次启动生效需先结束游戏（按钮禁用并说明）。

## 7. 窗口与外观（我的决定，可推翻）

- Tauri 窗口去掉系统边框，自绘标题栏（拖动区域 + 最小化 / 关闭；双击是否最大化由实现者决定）。尺寸沿用现状 1180×800、最小 800×640，允许拉伸；封面始终 `cover` 铺满。
- 主色沿用现有“配色方案”设置（`palette`），不从封面取色。草图里的暖橙只是示意。
- 主题（浅 / 深 / 跟随系统）保留；抽屉的“偏白毛玻璃”在深色主题下改为偏深毛玻璃。
- 删除底部状态栏；`notice` 提示保留为浮动 toast。

## 9. 验证

- 类型检查与 `apps/launcher` 现有单测。
- 先合并 `feat/launcher-model-connections` 并跑通其测试，作为基线。
- `launcher-core` 运行中放开的请求加测试：运行中修改不影响当前子进程环境，下次启动生效；仍禁止的请求仍被拒绝。
- 玩家前端保存接口：token 校验、忙碌时失败、成功后节点出现在启动器列表。
- 创作者页面：`/creator` 静态路由拒绝路径穿越；CSP 头正确；`build-portable` + `verify-portable` 产物包含创作者资源，便携包中能打开创作者页面。
- **真实试玩验收**（测试不能替代）：用带封面的包走一遍——开始、回到游戏页、打开创作者页、游戏内保存、结束、在抽屉里载入刚存的节点再开始；检查不滚动、沙箱状态一眼可见、封面人物不被遮挡。
- 更新 `docs/current/architecture/` 中涉及启动器、创作者工具、存档的章节，运行 `node scripts/docs/check-links.mjs`。

## 10. 已接受的限制

- 创作者页面只在游戏运行时可用。
- 运行中不能切换存档 / 实例 / 前端授权。
