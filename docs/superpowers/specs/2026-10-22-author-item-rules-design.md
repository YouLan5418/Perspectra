# 作者定义物品规则（2026-10-22）

## 例子

官方同居包里，DeepSeek 想煮饭：厨房里有一锅生米和一个电饭煲。以前“煮饭”写在核心包 `home.ts` 里，作者只能绑定、不能改；现在它是作者 `scripts/status.js` 里的一个操作：

```js
{ id: 'cook-rice', label: '用电饭煲煮一锅白米饭', targets: ['entity:rice-batch'], schema: { type: 'object', additionalProperties: false, properties: {} } }

resolve(truth, actorId, operationId, parameters, world, targetId) {
  const rice = world.items.current.find(item => item.entityId === targetId)
  const cooker = world.items.current.find(item => item.entityId === 'entity:rice-cooker')
  if (rice?.kind !== 'raw-rice-kit') return { rejectReason: '这锅米已经不是生的了。' }
  if (!cooker || cooker.holderId !== null) return { rejectReason: '需要放在这里的电饭煲。' }
  return { changes: [], reveals: [], items: [{ entityId: targetId, kind: 'cooked-rice' }], description: '煮好了一锅白米饭', audience: 'scene' }
}
```

在场的人看到锅里的样子变成熟饭；后进厨房的人走进来也能看到。脚本说“煮好了”，但宿主只按 `items` 里的变化改世界。

## 分工

| 作者决定 | 宿主保证 |
| --- | --- |
| 有哪些操作、名称、参数、条件、成功或失败、结果文字、受众 | 行动者资格、场景与可达范围、物品存在、同一时间只有一个持有者 |
| 物品变成什么样（`kind`）、交给谁、放在哪 | 变化只能是固定词汇：改外观或移动；与对白、观察原子提交；目击者收到交接观察 |
| 物品的隐藏事实（谁知道、谁不知道） | 用已有状态和告知机制，宿主填值 |

## 机制

- 操作可声明 `targets`：它作用于哪些物品。每件在行动者可达范围内（自己拿着、在所在位置的地上、或被同场角色拿着）的物品各给一个选项，`targetRef` 指向该物品；`resolve` 第六个参数是这件物品的 ID。不声明 `targets` 的操作保持原样，目标是行动者本人。
- `resolve` 结果可多一个 `items`：至多 8 项 `{ entityId, kind?, to? }`。`kind` 为 1–500 字的外观；`to` 为 `{ holderId }`（行动者或同场角色）或 `{ locationId }`（只能是行动者所在位置），每个结果至多一项 `to`。物品必须在可达范围内。宿主写成 `entity.upsert`（改外观，保留持有者）和 `entity.transferred`（移动，`interactionId` 为 `status:<操作>`），任何一项不合法则整次结果什么都不提交，按作者错误处理。
- 内核 `entity.upsert` 新增可选 `holderId`：带字符串持有者时 `locationId` 为 null，物品改外观后仍在原持有者手中。初始事件不带该字段，旧事件含义不变。
- 物品外观仍按现有可见性投影：拿着的、在你所在位置的物品，你看到当前样子；别人手里的，只有目击过最近一次交接才继续知道。改外观会结束这种“目击仍有效”，之后只保留上次观察。

## 替代与迁移

- 替代：核心包 `home.ts`（煮饭、吃饭）、`dinner.ts`（修理、三种做菜）和 `character-execution-result.ts` 里为煮饭写的措辞。官方包和两个晚宴包改用作者状态脚本，活动许可与自主行动配置里的定义 ID 改为 `status:<操作>`。
- 拿、放、给仍是内置规则；第二步再提供可修改的脚本模板，验证后决定内置版本去留。
- 旧存档：已导入的旧包仍引用 `home:`、`dinner:` 定义，删除后不再能编译；用户确认没有需要保留的存档，两个核心包已删除。

## 不做

不新增事件类型、数据库或协议版本；不让脚本写任意事件；不解析叙事文本；关系类交互（牵手）不变。

## 验证（2026-10-22）

- 自动测试：全量 144 个文件、1350 项通过；新增覆盖改外观、拿在手里改外观仍保留持有者、交给同场角色并被目击、够不着时拒绝、非法移动整次不提交、NPC 回合内执行物品操作。
- 真实模型：官方 DeepSeek（`deepseek-flash`，经 local 入口）跑《赔罪晚宴》A 路线 18 步，无错误、无跳过。DeepSeek 开场自选“做一桌凉拌冷盘”；GLM 先拿起工具箱；Claude 没有工具箱时尝试修理，被作者理由“手边没有工具箱。”拒绝，随后台词为“连把螺丝刀都摸不到”，没有声称修好；GLM 修好灶台后，DeepSeek 把食材拿在手里开火做成家常晚饭，食材仍在她手中；晚宴读到家常晚饭。证据在本机 `.tmp/model-girls-dinner-live/run-lddq7y`（不随源码分发）。单次样本，未跑官方同居包的真实煮饭，也未覆盖玩家对物品的“说加做”。
- 已删除核心包 `home.ts`、`dinner.ts`；引用旧定义的已导入包不再能编译（用户确认没有需要保留的存档）。

## 第 2 步：拿、放、给的作者模板（2026-10-22）

- 集市样例不再绑定内置 take/drop/give，改用 `status.js` 开头可复制的“物品规则模板”。`policy` 第三个参数 `place` 给出行动者拿着或脚下的目标物品现状，可返回 `targets` 把操作只给能成的物品（地上的才能拿，手里的才能放下或交出）；执行时宿主再检查。选项名可写 `{item}`。
- 提供选项时“够得着”收窄为自己拿着或脚下的物品，不再包括别人手里的物品，避免泄露谁拿着什么；作者暂时写不了“从别人手里拿走某件物品”。
- 自动测试：全量 145 个文件、1352 项通过；新增集市样例用模板拿起、只出现能成的选项、交给同行者并被留守者目击、伪造未提供的选项被拒绝。
- 真实模型：官方 DeepSeek 跑 10 回合“说加做”驱动（本机 `.tmp/item-template-deepseek-1792650797`），模板的拿起、交给都成功提交，同行者第 9 回合仍知道保温杯在自己手里并说“还热”。同一回合她叙述“把杯子往玩家那边递了递”却没执行交给，保温杯仍在她手里；留守者说“给我也包一包”却没执行购买。这两处是叙述与裁定的已知差距，与本次改动无关，未额外处理。
- 内置 take/drop/give 仍保留供其他包使用；是否删除待更多包迁移后再定。

## 第 3 步：删除内置拿、放、给（2026-10-22）

- `interactions-basic` 只剩牵手与松手；`/take`、`/give`、`/drop` 玩家命令删除；给模型的行动说明改用作者名称（如“拿起{item}”）加物品现状，不再有内置的“取得保管/转交保管”释义；执行结果与界面兜底名称也不再特判。
- 所有 v5 示例包改用 `examples/templates/item-rules.js` 模板（按原绑定逐项保留哪些物品可拿、可放、可给）；官方包与晚宴包的料理、修理同时按条件收窄，条件不满足的选项不出现。`hidden-cure-next` 生成器与 E 案例玩家策略随之改为作者操作。
- 修复：玩家执行的状态操作现在能命中 `autonomy.json` 里按 `status:<操作>` 配置的自主触发。
- 测试：核心回合、分支、输入队列等机制测试改装 `tests/fixtures/item-custody-package.ts`（原内置包的测试专用副本，宿主不安装）；用示例包的测试改用作者操作。全量 145 个文件、1351 项通过，launcher 44 项通过。
- 行为差别：
  1. 玩家对够不着或不能成的物品发出的请求在作者脚本运行前就被拒绝，不再提交一条场景可见的“拒绝”记录；NPC 的被拒尝试仍只告知本人。
  2. “交给”由一个选项加“交给谁”参数构成，而不是每个在场者一个选项。hidden-cure-next D2 的真实对比中，竞争者把摘要交给了玩家而不是伊蕾（基线交给伊蕾）；伊蕾已在档案室看过原件，这一选择合理，但单次样本不能排除这一差别的影响。随后用模板再跑 3 次：两次交给伊蕾（与基线相同），一次竞争者留在手里；没有再出现交给玩家。其中两次第 7 回合有一名角色输出格式损坏（一次把工具调用标记混进 `decision` 字段），自主机会被丢弃，与物品规则无关。证据在本机 `output/hidden-cure-next/live-5CB6Dz`、`live-Oj8IZn`、`live-srGpEm`。4 次样本里接收者分布未见明显偏向，仍不足以做统计结论。
  3. 默认模板名称“拿起{item}”与含英文的物品名相连时显示为“拿起GLM 的工具箱”，作者可自行改写。
