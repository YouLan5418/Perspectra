# 角色执行循环接缝

日期：2026-11-04。实施基线：`1166904b`。对应[后续计划阶段 10](../plans/2026-11-04-plugin-first-next-seams.md#8-阶段-10开放角色执行循环前先抽出主干执行能力)。

例如角色先申请拿钥匙，再看到裁定结果决定如何表达。第三方循环可以只允许一次操作和一次续写，官方循环保留表达后继续、两次操作、不可达受众修正等既有策略。两者使用同一组主干能力，不能自己提交“已拿到钥匙”的事件。

## 能力与职责

`ctx.characterLoop.register(SeamProvider<CharacterLoopInstance>)` 是单例接缝，替代原 `CharacterTurn.run` 内的循环策略。每个世界实例独立 open/close，包括重生候选。新增服务使用 hostApi 2.4。

主干 `CharacterTurn` 仍绑定世界、NPC 和一次激活，持有授权上下文构造、视图前缀、写租约、规则、受众、观察和原子提交。`run` 将临时能力交给循环，结束后立即失效；同一存储对象上的同一角色不能并发激活。循环遗留的能力调用会在结束时取消并等待清理，避免存储句柄关闭后才提交。调用模型时没有 SQLite 事务。

循环收到：

- `signal`、当前角色 ID，以及原有次数配置和 continuation 标记。
- `prepare(options)`：读取最新授权上下文，声明本次是否提供操作、发布后继续等模型协议选项。返回副本，内部保留实际裁定所需请求与前缀。
- `decide(reserveFormatRetry?)`：使用刚准备的请求调用既有决策组合；调用与格式修正由主干计数，策略决定是否预留格式修正预算。
- `submit(decision)`：将 publish/perform/abstain 申请交给主干；返回真实提交结果。申请不能指定 actor、事件或观察接收者。每个 prepare 最多消费一次申请，异步能力不允许重叠。
- 只读 `calls`、`performResult`：本次实际决策计数及最近操作结果的副本。

循环返回结束原因。主干汇总真实 calls、前缀及操作结果；没有成功发布时不能把返回的 published 当成成功。取消、失效能力、过期前缀、非活动角色和非法申请仍由主干拒绝。`continuationOf` 由宿主提供并在日志中验证，循环不能自行传入，续写不会重交原行动。

官方策略放进 `official-character-loop`，仅使用 SDK 类型和上述公开能力。`CharacterTurn` 不提供隐式默认循环；所有生产入口从官方组合或第三方服务取得循环，直接构造它的回归夹具明确传入官方实现。这样没有两套默认生产策略，也没有官方私有入口。

## 保留与限制

沿用 publish/perform 协议、决策组合、模型通道、规则链和现有事件类型。调度器仍决定处理机会，循环决定一次激活内部如何组织请求；不合并两层，不新增数据库或恢复协议。行动已提交而后续模型失败时保留行动。

第三方仍是受信任代码，其预算由自身负责；不能把它的任意输出当作世界事实。官方不变量仍需自动回归，真实角色自然度需要另做模型试玩。无可用凭证时明确保留未验收范围，不以假服务端替代真实体验结论。
