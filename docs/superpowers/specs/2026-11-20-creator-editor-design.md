# Perspectra 创作者编辑器设计稿

2026-11-20 · 创作流程与验收方案

各表单可使用的源字段、必填条件和当前运行时限制见[创作者编辑器字段总览](../../current/guides/creator-fields.md)。

从《门廊便笺》开始。作者写下阿林，设定她和玩家都在门廊开场，用新档聊一句。接着加一封便笺，玩家可以先把它放回去，拿到开信刀后再来拆。编辑器要让第一次做包的人知道该填什么、在哪里试，以及为什么有个选项还没有出现。

## 已确定的方向

### 独立创作工作台

第一版首页并列提供「打开世界包」和「新建作品」。打开已有源包目录后，作者能查找、修改和试玩已有内容。例如在《甜蜜日程》只改一个角色的说话风格，保存时应能确认改动集中在该字段，手写脚本和素材引用保留原样。遇到无效引用时，尽可能定位到可修复的记录。新建作品由编辑器生成稳定 ID、文件版本、玩家槽和清单，作者选好角色、地点和同场开局后即可试玩。两个入口使用同一套工具。工作台可以独立使用，安装方式以及是否从 Launcher 打开留到交付时决定。

首次打开已有包先展示作品总览，可查看或更换封面，进入玩家开局或作品目录。两页布局见[门廊便笺交互线框稿](../../prototypes/porch-note/index.html)。作者可以从角色跳到关联活动，返回后保留列表筛选和选中位置。进入活动后使用以下布局：

| 位置 | 用途 |
| --- | --- |
| 顶部 | 作品与活动路径、保存状态，以及带起点选择的「试玩」按钮 |
| 作品目录 | 在总览中按角色、地点、物品、活动、知识等浏览，活动画布可直接返回总览 |
| 活动编辑区 | 整页画布显示当前层的流程。分组以单个节点显示，进入后展示内部流程，顶部层级路径可返回任一上层 |
| 右侧浮层 | 点节点或端口打开属性，点「新增节点」打开创建表单；关闭后回到当前画布位置 |
| 底部抽屉 | 问题和试玩记录，可与右侧属性同时查看；展开或收起时保留选中节点 |

### 从出场角色开始

先列出会出场的角色，再设置地点和开局。表单区分必填、可选和稍后再填。作品做到什么程度，就使用相应的创作环节。

| 创作环节 | 作者先决定什么 | 可以何时验收 |
| --- | --- | --- |
| 角色、地点与开局 | 谁出场，玩家和角色从哪开始。人设与说话方式可逐步补充。 | 编译后开新档，在同场发一句普通对白。 |
| 活动与玩法 | 谁参加、如何进入、哪些选择可做、如何结束。使用现有玩法时填写该玩法要求的数据。 | 从日常手动进入，完成一条选择并回到日常。 |
| 变量与世界事件 | 哪条行动写入哪项状态，什么条件读取它，事件何时发生、谁能观察、哪些角色可获一次决策机会。 | 分别验证状态改变、可见性和调度，检查活动进行中发生事件的情形。 |
| 知识 | 像世界书一样维护正文，分别确定谁有权读、什么时候向该角色提供。 | 同一场景比较合格与不合格角色的实际请求。 |
| 预设 | 在外围配置文风和模型提示。 | 用单独的预设校验和角色请求核对生效范围。 |

包级变量与活动内状态分组。活动的参与者共享信息与角色各自的私有信息需要明确标识。物品持有权可直接作为条件，避免为同一物品再维护一个「是否拿到」变量。世界事件的观察与显式唤醒分别配置和验收，角色能观察到事件时也可以没有额外决策。

### 在整个编辑器中选择已有记录和字段

作者在「读便笺」活动里定义了参与者共享的数值「已读页数」，回到流程图添加分支时，点开条件的第一格就能选「本活动 → 已读页数」，接着选「大于」并填 `0`。如果另一活动也有「已读页数」，这里仍引用「读便笺」的字段。表单、流程图和试玩断言都遵循同一条规则：凡是引用作品已有记录、字段或操作的地方，都列出当前用途可选的对象。作者可以直接浏览，也可以按名称或键搜索。

| 作者正在填写 | 选择器怎样联动 |
| --- | --- |
| 活动条件或结果里的包级状态 | 选「门廊灯光 → 等于 → 明亮」。若活动获准写入，可在结果里选「门廊灯光 → 设为 → 熄灭」。选到按角色持有的状态，再选该处可用的持有者，例如当前行动者。 |
| 活动变量 | 按当前活动区分参与者共享、个人私有和活动内部字段。选个人字段时还要指定谁的值。玩家可见的条件只提供该玩家可知的字段，活动内部结算可以选择该规则有权读取或写入的字段。 |
| 活动、阶段与操作 | 配置「执行某活动操作后」时，先选活动，再列出它的适用操作。配置活动衔接时，「在哪个阶段收尾」列当前活动已声明的阶段，「如何收尾」列当前活动合格的结束操作，「接下来去哪里」列其他活动。流程图连线可直接点选目标节点。 |
| 世界事件 | 在节奏配置中选已声明为节奏触发的事件规则，再选强度。例如新建「门廊停电」规则，保存草稿后就能在节奏表里选它。回到事件表单，「发生地点」列地点，「显式唤醒」列可指定的 NPC。这里引用事件规则的 ID，试玩时间线中的每次发生另行展示。 |
| 角色、地点、物品、知识及玩法内容 | 开局地点从作品地点中选，持有条件从作品物品中选，知识的指定读者从该字段允许的角色中选。启用的玩法声明了可引用的内容时也沿用这一交互，例如选择技能。 |

候选来自当前作品草稿和已启用玩法的声明。打开已有包时直接读取其中可识别的定义。新建作品时，若缺少需要的记录，可在支持新建的选择框里就地创建，保存后返回原字段并带回选择。候选显示名称、类型和所属范围，保存时沿用包格式规定的键及必要的归属信息。修改显示名后，各处随之更新。遇到已删除或无法解析的引用，保留原键，在使用处提示并允许重新选择。

选好字段后，下一格随类型变化。布尔值给「是／否」，枚举列声明的合法值，数值给适用的比较符和数字输入框，自由文本可直接写。读条件和写结果各自按能力与可见范围筛选，实际执行时仍要校验。手写脚本中的动态字段若无可识别声明，保留源码入口。

验收时，无需编译或启动游戏即可完成三次操作：在活动条件和结果中选用「门廊灯光」，改显示名后两处仍指向原键；在两个活动分别定义「已读页数」，各自的分支只选到本活动的字段；新建「门廊停电」后，在节奏表中选到该规则。对同一份已保存草稿和同一字段，外部 Agent CLI 与界面应能查到相同候选，并保存同一引用。

现有包格式和运行时代码已提供状态声明、活动状态的可见范围、世界事件规则和节奏配置。当前工作树接通基础公共状态和本活动变量、世界事件和节奏条目的选择，以及表单内的反向引用。其余联动按本节的目标继续实现。[状态声明](../../../packages/sdk/src/contracts/status.ts) · [状态校验](../../../packages/core/src/application/status-state.ts) · [活动状态](../../../packages/core/src/application/activity-state.ts) · [世界事件规则](../../../packages/sdk/src/world-events.ts) · [节奏配置](../../../packages/plugins/src/pacing/definition.ts)

### 选择框里搜不到时

作者在「节奏配置 › 事件」里搜索「门廊停电」。优先列出可直接选用的事件；若没有可选结果，选择框根据当前草稿说明原因，并在原处提供下一步。

| 当前作品里是什么情况 | 作者看到什么、可以怎么做 |
| --- | --- |
| 没有匹配的事件定义 | 显示「没找到匹配的事件」，保留搜索词，并提供「新建节奏事件」。创建表单带入搜索词和节奏触发方式；作者补齐定义并保存后，回到原来的节奏表行，自动选中新事件，继续填强度。 |
| 找到了「门廊停电」，但它按固定回合触发 | 显示「门廊停电 · 固定回合触发，此处需要节奏触发事件」和「查看事件」。作者可打开原定义核对；返回时保留原表单输入。如果显式修改了定义，选择框按最新草稿刷新，由作者选用。 |
| 合格事件被作者临时加的筛选隐藏 | 提供「清除筛选」，保留搜索词并重新列出匹配项。当前字段对触发方式的要求始终有效。 |

这套反馈也用于活动变量、角色、物品等引用。新建入口只用于该处支持创建的记录。取消新建或查看后返回，都保留原字段的值和同一行尚未保存的输入。匹配到多个同名对象时，列出各自的键和归属，由作者挑选。外部 CLI 可取得相同的匹配结果、不适用原因及定义位置；查询本身不会创建记录或修改触发方式。

### 查看谁在使用这条记录

在「门廊灯光」的属性旁点「查看引用」，能看到「读便笺 › 展开便笺 › 出现条件」读取它，以及哪条活动结果写入它、哪条试玩断言检查它。每行都能跳到具体字段，返回后保留原来的筛选、选中项和滚动位置。角色、地点、物品、活动操作和事件规则也有同一入口。例如在「门廊停电」上能找到引用这条规则的节奏配置。

删除记录、移除某个枚举值或改变字段类型前，先列出受影响的位置。删除枚举值「昏暗」时，列表应定位到选择了「昏暗」的条件、结果或断言。作者可以就地换值，也可以保存待修复的草稿。手写脚本中按运行时数据拼出的键可能无法静态识别，引用面板应标出检查范围，提供源码位置供核对。外部 CLI 可查询相同的引用关系和检查范围。

### 变量在什么时候保留

创建「已读页数」时，表单分别展示「谁能看」和「再次开始时」。作者可以让全体参与者看到页数，也可以给每人单独记录。字段旁用实际初值说明保留规则，例如「暂停后继续会保留页数。活动结束后再开始，从 0 开始」。

| 作者希望的体验 | 编辑器里的设置 |
| --- | --- |
| 暂停读信，再回来接着读 | 恢复同一次活动时保留全部活动进度，包括页数和当前回合，无需逐项设置。 |
| 读完后再打开，从头读 | 新建活动变量默认「从初值开始」。打开已有包时沿用其初始化逻辑，自定义脚本可从字段回到源码查看。 |
| 读完后再打开，接着上次读 | 对初始化时能从上次活动视图取得的字段，可选「沿用上次值」。首次进入、独立新档或上次无对应字段时使用初值。候选遵循持有者和可见范围。 |
| 第二封信也要判断第一封是否读过 | 将「已读第一封信」定义成包级状态，按需要选择公开或按角色持有。两封信都引用该状态，各自的页数仍归各自活动。 |

现有运行时在暂停时保留活动状态，再次开始时按活动键取得上一次的授权视图。「看看时间」示例已在重新打开时沿用参与者共享的时间值。上表描述编辑器如何把这些差异呈现给作者。[暂停与恢复](../../../packages/core/src/application/activity-lifecycle.ts) · [开始活动](../../../packages/core/src/application/gameplay-runtime.ts) · [沿用上次值的实例](../../../examples/world-packs/model-girls-dinner/scripts/activities/evening.js)

### 复制活动时引用跟谁走

作者在活动列表中复制「读便笺」，命名为「读第二封信」。新活动获得独立的键。副本里的节点、连线、阶段、操作和局部变量归新活动，原先判断「本活动 → 已读页数」的分支随副本指向新活动的页数。引用的「阿林」「开信刀」「门廊灯光」以及明确指向另一活动的去向继续使用原记录。原来从其他活动进入「读便笺」的入口仍去第一封信。复制的是定义，第二封信从自己的初值开始。

完成复制后显示「已复制到新活动」和「继续共用」两组记录，作者可从中替换第二封信需要改用的物品或角色。遇到手写脚本中的动态引用时标出需核对的位置，保留源码。界面、外部 CLI 执行复制都使用相同的归属规则。

验收时，在同一新档把第一封读到第 2 页，暂停并恢复应仍在第 2 页。结束第一封，再首次打开第二封，页数应为第二封的初值。回到编辑器，从第一封的「已读页数」只应看到引用该字段的位置，从共用的「门廊灯光」则能跳到两封信各自的条件。

### 用流程图看清创作意图

线框稿从「读便笺」进入「拆阅便笺」，可在子流程入口与出口之间编辑两个玩家选项；上层用一个分组节点概括它们。分组允许嵌套、移入或移出同层节点，解散后保留内部内容。分组属于编辑布局，试玩仍使用原选项 ID、顺序、条件与结果。层级交互参考 [articy:draft 的流程导航](https://articy.com/help/adx/Flow_Navigation.html)。

流程图与表单读取同一份草稿。点击角色、地点、选项或条件可回到对应编辑处。先展示开局和剧情走向，再逐步加入状态的读写关系、并行事件与知识引用。

「门廊便笺」线框稿采用从左向右的阅读顺序。开场分出三个玩家选项，选中某项就加粗它的来路和去向。点输入端的条件可定位到角色或物品字段，点输出端的结果可修改该选择的叙述。这里的结果文字只描述选择后的呈现，状态变化仍由活动规则裁定。连线跟随节点移动；草稿单独记录画布坐标，玩家看到的选项顺序由活动定义决定。交互参照 [articy:draft 的端口与连线](https://articy.com/help/adx/Flow_PinsConnections.html)。

第一版应允许作者仅靠图和表单完成六件事：写开场、加玩家选项、设出现条件、写选择结果、修改游戏状态、结束活动或转入另一活动。既有脚本中无法可靠还原成节点的判定以「自定义规则」显示，保留源码入口，试玩后可看实际执行结果。

#### 低代码规则与手写脚本

例如「搜查房间」需要至少 1 点精力，成功时扣 1 点并给行动者一条线索。作者在工作台新建这条规则时，用表单选择字段、条件、拒绝原因和结果；分支和去向在流程图中编辑。表单、图和外部 Agent CLI 修改同一份低代码定义，导出时由它生成运行脚本。作者让 AI 把消耗改为 2 点后，回到工作台能看到对应数值的变动。

同一个包可以同时使用低代码规则和普通脚本。作者或 AI 可以用普通脚本编写更自由的裁定逻辑，脚本源码是这类规则的编辑来源。工作台读取脚本声明的操作、参数和可配置字段，按稳定操作 ID 提供候选；活动可以在流程图中引用它，作者可以打开源码、配置参数、查看试玩结果。已有包沿用原有脚本；保存引用它的低代码活动时只更新活动自己的定义。创作 Skill 说明如何编写这些声明，CLI 向外部 AI 提供同样的查询、引用、校验和试玩入口。

活动专属页面的接管范围限于舞台区域，外围导航和中止活动由宿主提供。页面上的按钮引用玩法操作，动作仍走该操作的正式裁定。可用同一个「搜查房间」操作验收：在低代码活动和自定义舞台里各执行一次，精力不足时都收到同一拒绝原因，成功时都按所配数值扣减。工作台、CLI 与玩家宿主现已接通按活动键绑定 HTML 和独立 CSS，支持导入、带玩法的预览和导出。作者可给 HTML 中有唯一 `id` 的按钮指定现有操作，给页面元素按玩家可见字段配置显隐、CSS 类和换图。工作台和 CLI 共用字段候选，脚本玩法可从试玩读取单位生命百分比等动态数据。页面字段与实际标记见[活动专属舞台](../../current/guides/activity-stages.md)。数值消耗和单变量自定义裁定已接入工作台、CLI 和活动脚本。完整手写活动的操作与参数可在源码入口查看。

选中「展开便笺」时，右侧显示选项文案、出现条件、选择后的去向，以及「试玩此选项」。作者从记录选择器依次选「玩家 → 持有物品 → 开信刀」。若还没建开信刀，可以就地新建后继续。如果作者请 AI「再给玩家一种办法，阿林在场时可以请她帮忙」，图上应新增「请阿林帮忙」选项，带自己的在场条件和后续回应。玩家发出请求后，是否帮忙由阿林决定。若两条条件都应开启同一个选项，作者可在该选项下选「满足任一条件」。

- **剧情主线**显示玩家能走到哪里、条件成立后的选项和普通退路。
- **世界事件**从触发条件连到事实变化、观察与可选唤醒。活动可以同时继续自己的进度和结算。
- **知识引用**连到读取它的角色或条件。选择读者与设置命中时机各自独立。
- **试玩时间线**记录实际提交的事实、可见结果和真实执行的检查。条件应区分未检查、通过和未通过。事件与对话相邻不足以证明前者触发了后者。

2026-11-20 的「读便笺」交互草图用模拟数据走通了「选变量 → 改条件 → 试玩 → 从结果定位回条件」。作者体验后的反馈是「这个交互流程没感觉出来什么问题」。正式编辑器沿用同页操作，点「定位条件」后直接选中对应节点，并把输入焦点放回条件字段。接入引擎后，用真实包重新核对这条路线上的选项和判定记录。

### 多条分支同时满足时怎么走

作者添加分支时，可以选择「让玩家选」或「按条件自动走」。用同一个试玩起点就能看出差别：玩家手里有开信刀，阿林也在门廊。

| 节点 | 两个条件都成立时 | 调整顺序的含义 |
| --- | --- | --- |
| 让玩家选 | 「自己拆信」「请阿林帮忙」都可选，等玩家点击才走相应连线。作者还可放一个无条件的「先不拆」。 | 改变选项的显示顺序。每个选项独立判断是否可用。 |
| 按条件自动走 | 若第一条为「持有开信刀 → 显示拆信提示」，第二条为「阿林在场 → 显示求助提示」，本次只走第一条。每条都未命中时走作者指定的「否则」，例如回到「把信收好」。 | 右侧列表从上到下判断，拖动或用上移、下移可改优先级。图上的连线标出相同顺序。「否则」固定在最后。 |

画布上移动节点只调整布局。外部 CLI 读取和修改的都是属性列表里的分支顺序。自动分支若改变玩家看到的内容，其条件也遵循玩家可见范围。进入「显示求助提示」只呈现求助机会，玩家仍可决定是否开口，阿林仍可决定是否帮忙。

试玩时，从上述起点运行「让玩家选」，核对两个选项都可点击。再运行自动分支，时间线记录第一条「命中」、第二条「未检查」和实际去向。交换两条顺序后重跑，应进入求助提示；改成玩家没有刀、阿林也不在场，应进入「否则」。若作者还没给「否则」连线，草稿可以保存，节点试玩遇到这种情况时停在该节点，提示「所有条件都未满足，尚未设置去向」。

### 选项怎样随世界变化

阿林在读信期间把开信刀交给玩家，物品转交一经提交，当前节点就应重新判断「展开便笺」是否可用。即使活动仍在同一阶段，选项也应更新，同时保留阅读位置和已读内容。玩家点击时，正式规则还要根据最新持有关系再次判断。若刀已经交走，玩家留在当前节点，读信进度维持原状。

右侧表单给每个选项提供「条件未满足时」设置，默认隐藏，也可选「显示为不可选」并填写玩家提示，例如「信封封得很紧，得找件工具」。这两种表现共用同一个条件。选项是否出现、是否可点击，本身就是玩家可见信息，因此玩家选项的条件只使用玩家获准知道的输入。例如阿林私下读过信，仅此事不应改变玩家的按钮；等她向玩家提起那封信，作者可以用这次对玩家可见的交流开启后续选项。创作者可在试玩记录中查看实际检查及依据。

### 所有修改落在同一份草稿

作者可以在外部 Codex、Claude Code 或 DSH 中描述创作要求，让 Agent 通过 CLI 查询候选、修改字段和编写包内脚本。

Perspectra 对外提供功能对等的创作 CLI。外部 Agent 即使在编辑器关闭时，也能按名称或稳定 ID 查记录和关联、改表单和流程图、处理资源与脚本、查差异和撤销、跑试玩、校验和导出。界面与外部 Agent 共用编辑操作和校验。

包编辑维护角色、地点、物品和玩法配置，活动页提供流程图与试玩。外部 Agent 通过 `worldpack editor` 读取和修改同一源包，通过 `worldpack simulate` 执行剧本断言。

### 作者和 Agent 同时编辑时怎样保存

外部 Agent 成功写入条目后，编辑器应直接载入新版本，覆盖该条未提交的输入并保留当前位置。其他条目的草稿继续保留，引用候选随已保存内容刷新。CLI 写操作仍按其保存契约校验。

## 编译、试玩与导出

**正式游戏能正确编译和加载，是最高硬门槛。** 保存未完成草稿、编译当前快照、打开隔离新档应是分别可理解的操作。编译失败可回到具体字段或脚本位置，草稿仍可继续编辑。

编辑器与正式 CLI 共用编译实现。交付验收应从真实导出的源包重新执行 `validate` 和 `compile`，再开新档走关键路线。导出须保留作品使用的视觉资产和预设，包括由宿主独立读取的文件。作者批注、试玩回放与协作聊天默认留在工作区。CLI 可复用随 Perspectra 发行版提供的 `worldpack.cmd`。每份内容包是否另带工具仍待决定。

### 点击「试玩」时使用哪一版

作者刚把「展开便笺」改成「沿封口拆开」，光标还在输入框里，直接点「试玩」就应能试到新文案。编辑器先将当前未保存的修改按字段合并到草稿，取本次保存得到的快照，再编译并从选定起点打开。没有待保存的输入时，直接使用当前已保存草稿。编译期间或开局后发生的编辑留给下一次试玩。

试玩前自动保存，编译失败时指向相关字段或脚本。试玩后的撤销操作仍可恢复先前编辑。

「试玩」记住上次使用的起点。作者可以从正式新档开始、为所选节点设置测试初值，或从上次试玩继续。节点试玩要在时间线开头标明测试初值，例如「玩家已持有开信刀」。后续通过正式操作拿起物品时，则显示该步实际提交的结果。继续试玩遇到需要重新开档才生效的修改时，提示受影响的内容。

作者可以把一次试玩保存为可重跑的测试场景，在时间线上勾选以后要自动核对的预期，例如选项是否可用、能否返回日常，以及哪位角色收到了哪条观察。重跑时只核对勾选项，未到达的步骤标为「未执行」。失败项可回到步骤和条件查看实际结果。真实模型的角色表现可从相同起点单独试玩。

## 《门廊便笺》的贯通验证

1. 新建阿林与门廊开局。新档应能和同场的阿林聊一句。
2. 第一次打开便笺，玩家还没拿开信刀。选择「先不拆」可正常回到日常。
3. 日常用正式操作「拿起开信刀」。Host 提交物品持有权。再次打开便笺，选项读取当前持有权，玩家可以「展开便笺」，读到结果后继续日常。还要验证重开原档仍持有、独立新档从未持有开始，以及过期选择无法提交。
   - 保持便笺界面打开，让阿林通过正式操作把刀交给玩家。分别验证隐藏的选项出现、置灰的选项变为可用，且阅读位置保持。若显示后又交走刀，再提交旧选择应被拒绝。
   - 保持玩家已知信息相同，仅改变阿林私下是否读过信，两次试玩中的玩家选项、置灰状态和提示应一致。
4. 下一步试验停电影响：核对停电的可见变化能否与读信并行出现，谁看见、是否另外安排角色决策，以及读信原来的选择能否照常完成。该步骤仍待在编辑器流程中验证。
5. 在编辑器里新建作品，将上述路线保存为测试场景，导出时勾选「附带作者测试场景」。关闭编辑器，由外部 Agent 通过 CLI 在导出的源包中新增「请阿林帮忙」选项并重跑测试。重新打开该源包，应能找到并手改新增的节点、条件与去向，随后仍能编译和试玩。
