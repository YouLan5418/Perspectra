# Perspectra 创作者编辑器设计稿

2026-11-20 · 创作流程与验收方案

从《门廊便笺》开始。作者写下阿林，设定她和玩家都在门廊开场，用新档聊一句。接着加一封便笺，玩家可以先把它放回去，拿到开信刀后再来拆。编辑器要让第一次做包的人知道该填什么、在哪里试，以及为什么有个选项还没有出现。

## 已确定的方向

### 从出场角色开始

先列出会出场的角色，再设置地点和开局。表单区分必填、可选和稍后再填。作品做到什么程度，就使用相应的创作环节。

| 创作环节 | 作者先决定什么 | 可以何时验收 |
| --- | --- | --- |
| 角色、地点与开局 | 谁出场，玩家和角色从哪开始。人设与说话方式可逐步补充。 | 编译后开新档，在同场发一句普通对白。 |
| 活动与玩法 | 谁参加、如何进入、哪些选择可做、如何结束。使用现有玩法时填写该玩法要求的数据。 | 从日常手动进入，完成一条选择并回到日常。 |
| 变量与世界事件 | 哪条行动写入哪项状态，什么条件读取它，事件何时发生、谁能观察、哪些角色可获一次决策机会。 | 分别验证状态改变、可见性和调度，检查活动进行中发生事件的情形。 |
| 知识 | 像世界书一样维护正文，分别确定谁有权读、什么时候向该角色提供。 | 同一场景比较合格与不合格角色的实际请求。 |
| 预设 | 在外围配置文风和模型提示。 | 用单独的预设校验和角色请求核对生效范围。 |

包级变量与活动内状态分组。活动的参与者共享信息与角色各自的私有信息需要明确标识。物品持有权可直接作为条件，避免为同一物品再维护一个「是否拿到」变量。世界事件的观察与显式唤醒分别配置和验收，角色能观察到事件时也可以没有额外决策。

### 用流程图看清创作意图

流程图与表单读取同一份草稿。点击角色、地点、选项或条件可回到对应编辑处。先展示开局和剧情走向，再逐步加入状态的读写关系、并行事件与知识引用。

- **剧情主线**显示玩家能走到哪里、条件成立后的选项和普通退路。
- **世界事件**从触发条件连到事实变化、观察与可选唤醒。活动可以同时继续自己的进度和结算。
- **知识引用**连到读取它的角色或条件。选择读者与设置命中时机各自独立。
- **试玩时间线**记录实际提交的事实、可见结果和真实执行的检查。条件应区分未检查、通过和未通过。事件与对话相邻不足以证明前者触发了后者。

### 所有修改落在同一份草稿

作者可在一个能编辑和保存的小工作区里使用 AI。AI 可以只建一个角色，也可以跨处更新初始位置、事件唤醒等关联。它应直接在同一份草稿上工作，作者随后可以细改。允许它编写包内规则脚本，新的原生玩法插件留给后续阶段。

包透视的查看、核对和推演能力逐步并入编辑器。等新入口覆盖旧入口实际承担的工作，再退独立入口。底层能力、编译 CLI 和场景推演继续可用。

## 编译、试玩与导出

**正式游戏能正确编译和加载，是最高硬门槛。** 保存未完成草稿、编译当前快照、打开隔离新档应是分别可理解的操作。编译失败可回到具体字段或脚本位置，草稿仍可继续编辑。

编辑器与正式 CLI 共用编译实现。交付验收应从真实导出的源包重新执行 `validate` 和 `compile`，再开新档走关键路线。导出须保留作品使用的视觉资产和预设，包括由宿主独立读取的文件。作者批注、试玩回放与协作聊天默认留在工作区。CLI 可复用随 Perspectra 发行版提供的 `worldpack.cmd`。每份内容包是否另带工具仍待决定。

## 《门廊便笺》的贯通验证

1. 新建阿林与门廊开局。新档应能和同场的阿林聊一句。
2. 第一次打开便笺，玩家还没拿开信刀。选择「先不拆」可正常回到日常。
3. 日常用正式操作「拿起开信刀」。Host 提交物品持有权。再次打开便笺，选项读取当前持有权，玩家可以「展开便笺」，读到结果后继续日常。还要验证重开原档仍持有、独立新档从未持有开始，以及过期选择无法提交。
4. 下一步试验停电影响：核对停电的可见变化能否与读信并行出现，谁看见、是否另外安排角色决策，以及读信原来的选择能否照常完成。该步骤仍待在编辑器流程中验证。
