# 官方试玩包实际验收

每轮使用新实例和独立数据目录，记录模型、服务、预设、玩法操作及可见结果。自动测试通过仅证明其列出的机制。

| 场景 | 操作 | 应观察到的结果 |
| --- | --- | --- |
| 固定序章 | 逐句或跳过，途中关闭再进入 | 112 条正式表达，5 条玩家问题，进度恢复，末句保留自由输入 |
| 自由交接 | 最后一问后分别答应、拒绝、反问 | 真实模型根据玩家实际表达决定，不强制同居，不额外模拟承诺 |
| 第一顿饭 | 同场到厨房，开始生活菜单并选晚餐；让 NPC 煮饭或选择别的方案 | 活动只给开场；材料与电饭锅缺失则拒绝；说“做好了”不算熟饭，正式操作才改变状态 |
| 私密交流 | 同场给 Claude 分别发送 direct、private 内容，再问 GPT | direct 旁人不知道发生；private 旁人只知发生，不能复述秘密；接收者可合理回应 |
| 蛋糕认知 | 安排部分角色目击合法转移，另一些不在场；到别的房间提问 | 不知道位置的角色不能从全局库存回答；允许猜测，不能把猜测当权威转移 |
| 第二天 | 第一天真实谈成一条安排，再显式推进日标签并回访 | 记得真正发生的安排；没有达成时不能补造承诺 |
| 长期记忆 | 超出当前上下文／启用已有 Core 整理后回访，核对已有记忆证据 | 角色召回授权经历，不从其他角色的私密记忆获取答案；不只依赖仍在上下文的原文 |
| 有界反应 | 自由场景观察角色间回应及停止 | 沿现有串行观察驱动与有界反应，等待玩家输入或活动触发，不声称持续后台自治 |

源码实验：`node --import tsx tests/experiments/official-demo.ts`。回归：`corepack pnpm@11.7.0 exec vitest run --config vitest.prototype.config.ts tests/prototype/official-demo.test.ts`。

当 provider 不可用时，先完成固定序章和权限／状态测试，记录真实模型体验未验收。不要用模拟角色自由回应替代该验收。

## 普通玩家界面复验

优先从原生 Launcher 导入目录、设置模型、创建新实例并启动，使用系统浏览器游玩；先不运行实验脚本。先按默认反应窗口观察一次截止，再按服务延迟选择已有的 120 秒设置。核对等待阶段、已等待秒数、已发表回复及截止后输入恢复；不要通过重发催促。下一位无指导试玩者重点记录：能否找到生活菜单、能否理解开场后自由输入、能否区分私密范围与接收者、跳过演出是否等待过长。

晚餐同时核对未煮饭与角色已提前煮饭的路径；熟饭只邀请用餐，不重复料理。新脚本应使用新实例，不能绕过旧存档的世界包不一致检查。已完成的开发者界面复验与保留失败见 [PLAYER-VALIDATION.md](PLAYER-VALIDATION.md)。
