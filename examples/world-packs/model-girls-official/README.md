# 《大模型变成美少女了？！》官方试玩包 0.1

以用户提供的《序章 Activity 演出脚本 V1.2》为对白来源，包含 112 条正式表达（107 条 NPC、5 条中性玩家问题）。末句“你愿意让我们暂时留下来吗？”后直接交自由输入，不替玩家答应收留。剧情标签用于显示，不成为世界事实。

差异调查与代码阻塞处理见 [GAP-ANALYSIS.md](GAP-ANALYSIS.md)，初次开发检查见 [VALIDATION.md](VALIDATION.md)，后续 Gemini 实玩见 [LIVE-VALIDATION.md](LIVE-VALIDATION.md)，启动器与实际玩家界面复验见 [PLAYER-VALIDATION.md](PLAYER-VALIDATION.md)。

## 启动

使用更新后的本仓库宿主，在启动器导入本目录作为 worldpack-source/v5 源包，创建新的游戏实例，配置你已授权使用的真实模型服务后启动。点击“开始序章”，再点“继续”或快进。test3 便携包内对应 `examples/大模型变成美少女了`。不要复用 D:/worlds 的历史实例。

命令行也可运行（先配置对应 provider 的服务地址、模型及必要凭证环境变量）：

```powershell
corepack pnpm@11.7.0 experience:web --pack examples/world-packs/model-girls-official --data-dir .tmp/model-girls-play
```

确切启动参数见仓库网页入口；不要把凭证写进世界包。序章角色决策不需要 provider，但自由阶段需要可用真实模型。可独立验证固定流程：

```powershell
node --import tsx tests/experiments/official-demo.ts
```

实验保存独立转录、事件和 summary，不调用角色 provider，不代表自由阶段真实体验已验收。

## 已制作玩法

- 序章逐句提交，五条玩家问题有脚本来源记录。快进／跳过仅加速同一提交路径；读档从已提交游标继续。
- 自由阶段可答应、拒绝、追问或离开；公开／定向／私密／仅自己沿已有权限路径发送。没有持续后台调度。
- 再次开始活动进入生活菜单。现有活动开始要求声明参与者同场，组织角色到厨房后选择“第一顿晚餐”；需要 DeepSeek、可见熟饭或米与水材料及电饭锅；已煮饭时改为用餐邀请，开场后解除活动，由角色真实决定如何行动。
- 一份米与水材料 → 一锅白米饭 → 空容器，同一实体，正式煮／吃操作裁定，不能重复生效。NPC 使用与玩家相同机制，可以选择其他方案。
- 蛋糕在厨房。先通过正常拿取、交付或放下改变位置；只有玩家曾合法目击移动且现在不可见，菜单“找一找草莓蛋糕”才提出寻找问题。各角色依据自己的经历判断，不预设谁偷吃。
- “推进到第二天并聊聊约定”是明确选择的日标签推进和回访问题；不自动假定已承诺，后续决定交模型。

## 验收边界

已覆盖权限观察、玩家表达与游标原子提交、NPC 发表失败不跳句、旧选项拒绝、读档恢复、料理条件与不可重复。完整固定序章有独立自动实验；网页按真实宿主点按检查。

当前使用 CSS 简单背景与名字牌，无正式立绘、音乐及逐镜头演出。没有冰箱层级、食物份额、饥饿或持续后台自治。跨房间蛋糕位置代替“藏在冰箱某层”；厨房同场者能看见地面实体。日标签不是系统真实时间流逝。

已按 [PLAYTEST.md](PLAYTEST.md) 用本机 Gemini 验证自由交接、拒绝／分歧、私密回应、正式料理、蛋糕目击差异和归档后的约定召回，具体样例与限制见 LIVE-VALIDATION。当前启动器默认反应期限为 120 秒，可在运行参数中调整；此前真实样例使用 30 秒时曾发生后续反应截止。test3 的包内序章、前端资源与离线记忆编码通过，但其构建验收时 8046 不可用，未重新测自由阶段。详见[便携构建记录](../../../docs/current/studies/launcher-portable-test3-20261009.md)。不能把短样例通过当作全部自然度与所有角色组合已验收。
