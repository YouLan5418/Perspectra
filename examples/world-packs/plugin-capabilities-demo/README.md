# 两种插件入口的最小演示

你和澄各自向设备打招呼，设备确认后只增加本人的次数；旁观者没有自动获得其他人的次数。选择“排队请求设备”只记录排队说明，不增加次数。“切换设备可用状态”完全由包内规则执行，不调用原生插件。

1. 在 Launcher 全局设置的插件页添加并启用可信本地文件 [demo-device.mjs](../../host-plugins/demo-device.mjs)。这是宿主能力，须由玩家安装。
2. 导入本目录并新建实例。[plugins.json](plugins.json)及[规则模块](plugins/greetings.js)随世界包分发，不需要另装 Cordis。
3. 打开场景操作，先请求确认，再试排队、切换可用状态。本机设备只是异步演示，没有连接外部服务。

原生插件提供 `ctx.demoDevice.requestCharacter(worldVersion, characterId)`，请求绑定 NPC 运行原有角色回合。角色自己选择行动或沉默，结果通过既有规则和授权观察提交。这个调用不接受外来 Context 或凭证。

本包使用 `demo-device@0.1.0`，缺失时启动明确失败。把依赖改为可选后，没有安装能力的相关操作隐藏，包内操作仍可执行。原生插件不随世界包自动安装。

包含外部写方法的会话暂不支持故事节点、候选切换和重新生成，因为尚未配对保存外部状态。世界事件仍正常写入本地数据库；这不代表外部设备会随重开恢复。

详见[双入口开发指南](../../../docs/current/guides/dual-plugin-entrypoints.md)。源码入口、打包后端、模拟模型的角色回合及提交失败路径有自动测试；没有验收真实模型、Launcher 人工操作或发行包。
