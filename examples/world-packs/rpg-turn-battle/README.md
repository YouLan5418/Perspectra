# 遗迹守卫：只用包内容的回合战斗

你和法师澄进入遗迹，轮流攻击守卫。你可以施放火球、治疗、防御、使用药水或撤退；澄和守卫在各自回合通过正常角色行动入口操作，伤害、资源和胜败由包内程序裁定。

2026-10-26：当前源码宿主的完整链路已通过自动化验证。没有修改宿主、Core、前端或内置交互实现；不代表真实模型表现、浏览器人工操作或便携发行包已验收。

## 开始试玩

在当前源码 Launcher 中导入本目录，用新游戏实例开始。先点“进入遗迹迎战”，满足条件后自动开始战斗。无需自定义前端，沿用默认舞台的活动卡片、目标下拉框和状态面板。

有开发环境且已配置可用模型连接时，也可从仓库根目录运行：

```powershell
corepack pnpm@11.7.0 experience:web --memory-native --pack examples/world-packs/rpg-turn-battle --data-dir .tmp/rpg-turn-battle-manual-20261026
```

这里显式选择原生记忆，避免把 Core 环境安装混进战斗规则验证。默认模型连接仍按宿主配置读取；营地和战后的普通角色回应可能调用模型。每次重新测试单场遭遇，请使用新的数据目录，不覆盖历史试玩。

默认战斗中两个 NPC 使用包内 `simulate` 提供确定性策略，不调用战斗决策模型。想让澄自己通过模型决策，进入遗迹前点“让同伴使用真实模型决策”；守卫仍使用脚本策略。这一入口的 provider 链路已用模拟服务验证，真实模型自然度、策略质量与耗时尚未实测。

## 玩法

| 项目 | 规则 |
| --- | --- |
| 队伍 | 冒险者 32 HP / 6 MP；澄 24 HP / 9 MP |
| 敌方 | 遗迹守卫 70 HP；普通攻击 12 伤害 |
| 换手 | 冒险者 → 澄 → 守卫，循环；倒下者跳过 |
| 普通攻击 | 玩家 9、澄 7；目标必须是敌方 |
| 火球术 | 消耗 3 MP，造成 18 伤害 |
| 治疗术 | 消耗 3 MP，为存活队友恢复 12 HP，不超过上限 |
| 防御 | 下次受击减半，向上取整；最晚在自己下次行动时解除 |
| 药水 | 队伍共享 2 瓶，每瓶恢复 16 HP；玩家使用，目标可为自己或澄 |
| 胜利 | 守卫 HP 归零，玩家获得 30 金币，同次提交战斗结束与奖励 |
| 失败 | 玩家和澄全部倒下，没有奖励；倒下不等于从世界删除或剧情死亡 |
| 撤退 | 保留 HP、MP、耗材，没有奖励 |

默认策略：澄在自己或玩家 HP 不超过 12 时优先治疗，有魔力时用火球，否则普攻；守卫优先攻击仍站立的玩家。两次对守卫施放火球可以完成一场确定性的两轮胜利。

所有生命、魔力、药水和金币都保存在已有状态事件中。活动只存轮序、防御、站立名单和战斗阶段；不另存一份 HP。这里将敌我 HP/MP 明确公开给三名战斗参与者，金币只由持有者获知；没有测试隐藏敌方属性或旁观者玩法。

## 文件怎么分工

- [status.js](scripts/status.js)：定义客观数值、初值、营地菜单和进入遗迹条件。
- [battle.js](scripts/activities/battle.js)：定义回合操作、规则、换手、NPC 策略与胜败奖励。
- [interactions.json](interactions.json)：选择现有基础交互包；没有新增宿主交互实现，战斗操作由活动桥注册。
- [worldpack.source.json](worldpack.source.json)：登记玩法脚本及世界资料。漏登脚本不会启用玩法。

“只用包内容”包括可信包内 JavaScript 编程，不等于只填写 JSON。静态交互定义不会自动生成伤害、治疗或胜败规则。

## 已知限制

- 这是一场不可重复刷新的遭遇；没有地图探索、装备、经验升级或商店。结束后使用新游戏实例重玩。
- 原型的“倒下”只约束本场战斗；结束后的普通对话没有全局死亡系统。
- 目标下拉框列出三名参与者，选错阵营、满血治疗或资源不足时拒绝且不提交。尚未按技能动态细分目标列表，也没有自动隐藏魔力不足的技能。
- 模型可以说话或沉默而不执行操作。当前回合会保留，玩家可重试、暂停或通过宿主逃生。宿主逃生只中止活动，不调用包内撤退结算；本例保留已有资源变化，并结束本次遭遇的可重开入口。
- 暂停继续不恢复消耗品，也不重新发奖；未实现多场关卡衔接。
- 默认舞台提供通用活动表单和状态面板；没有战斗专用布局、血条、命中特效或动画。浏览器自动化连接失败，本次未完成可见界面验收。
