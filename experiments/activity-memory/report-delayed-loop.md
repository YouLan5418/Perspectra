## 1. 结果与阶段判断

原来的延迟断点已经修通：三条真实新Source进入已有更新器；每条经过八次真实无关互动；当前和旧认识都自然进入候选并被Character读到；Character提出的13次取证经Rulebook接受、原子提交新Source；三组各自首次新Source又进入同一已知家族的更新。

18次首步选择中，当前认识真实取证5/6，旧认识2/6，无认识6/6。无认识的六次全部重读大厅旧牌；当前认识是四次再次问人、一次读取办事终端；旧认识两次问人。其余五次只发表建议，没有因文字建议而执行能力。

当前和旧认识的12条对白全部保留203/105分歧。无认识六条都只复述重新读到的203，省略已交付的105线索。这为延迟认识改变可见表达与取证方式提供了条件证据，但没有证明稳定行动率或正文抽象本身的收益：材料呈现、分支数量、证据摘选和长度同时有差异。

## 2. 从真实Source开始，选择规则先固定

复用6.3数据，每个种子按原trials顺序选择首次实际取证，不按更新结果挑样本：

| 新轨迹 | 6.3实际来源 | 本轮新增认识证据 | 初次更新结果 |
| --- | --- | --- | --- |
| delayed-0 | immediate-0 / sample-0 / raw-direct | `event:47`工作人员发言 | reinforcement，一条当前认识，原正文保留 |
| delayed-1 | immediate-1 / sample-1 / existing-cognition | `event:47`工作人员发言 | unresolved_conflict，两条当前分支 |
| delayed-2 | immediate-2 / sample-1 / existing-cognition | `event:47`工作人员发言 | reinforcement，一条当前认识，原正文保留 |

这里相同Source序号属于不同克隆，不合并计数。事件Hash、observer、原生actionId及事务归属均验证。发言内容是“我记得登记处在二楼203，不过我这周还没去过。”，来源继续为reported_speech，不能作为位置已确认的事实。

更新仍使用已有`notice_board_action_loop.revise`和`cognition_lineage.update`：提交规范的第一条已知认识与全部旧证据、全部真实新证据。两个原分支都留在previousCurrent，供旧认识臂使用；没有自动家族发现或通用多分支合并。强化允许正文不变、证据修订，不能把“新版本”误解为每次都改写文字。

初次整理的时间取原证据tick区间；进一步更新使用已有record的形成/正文修订时间，不用新证据时间重置正文年龄。三次抽样再更新都保留firstFormedTick=2、lastRevisedTick=5，evidenceUpdatedTick推进至27。旧的乱序实验sidecar、Source及正文不改写，不增加运行时兼容分支。

## 3. 八轮间隔、完整授权历史与自然交付

三条轨迹各有八次玩家闲聊和八次Character发布，共24次真实Character调用。没有新增取证或移动。更新后的认识在间隔中未注入memories；所有闲聊仍保留原生近期窗口，不能把它解释为已验证正常网页每轮自动召回下的噪声表现。

原始Source全保留，未来三臂各索引相同的31条本角色授权Source，包括八轮的16条实际发言历史。未来玩家问题只有“今天又来这栋办事楼，想给另一份材料办理登记。接下来怎么办？”，未加入认识ID、203/105、核实要求或强制行动。非记忆请求每个种子完全一致，旧读牌结果已离开近期窗口。

复用原有本地向量/词法/RRF检索、简单ID准入和极简Delivery；本轮不经过JEV，不伪造其接受结果。每个种子/臂只准备一次，两次Character重复复用；执行后允许真实历史分叉。

| 轨迹 | 原检索当前/旧目标入池 | ID准入后当前/旧目标 | 实际正文交付当前/旧 | 无认识正文 |
| --- | --- | --- | --- | --- |
| delayed-0 | 0 / 0 | 1 / 2 | 1 / 2 | 0 |
| delayed-1 | 0 / 0 | 2 / 2 | 2 / 2 | 0 |
| delayed-2 | 0 / 0 | 1 / 2 | 1 / 2 | 0 |

因此两条认识臂都实际阅读6/6，已经不同于此前“各臂为空、请求相同”的采样差异。当前认识依据的最新Source距本轮18 tick，旧认识20 tick；不是因为较新就视为真。

均采用三项/4500 JSON字符预算。当前认识每条显示2/3证据并标注不完整；一条反向分支的反证显示1/2，反证存在及总数仍保留。旧认识显示2/2完整，但仍声明冲突未解决。正文与原引用逐字核验；不恢复“支持全为直接观察”或“整个证据组放不下就取消”的门槛。

## 4. 行动、对白与进一步更新

| 种子/重复 | 当前认识 | 旧认识 | 无认识 |
| --- | --- | --- | --- |
| 0/0 | 问工作人员 | 问工作人员 | 重读大厅牌 |
| 0/1 | 问工作人员 | 问工作人员 | 重读大厅牌 |
| 1/0 | 只发表建议 | 只发表建议 | 重读大厅牌 |
| 1/1 | 读办事终端 | 只发表建议 | 重读大厅牌 |
| 2/0 | 问工作人员 | 只发表建议 | 重读大厅牌 |
| 2/1 | 问工作人员 | 只发表建议 | 重读大厅牌 |

13次新增取证均是native perform/interact，接受动作与私有观察在同一事务；新Source为各克隆的event:141。没有实际移动，没有完成登记，也没有独立核实登记处真实位置。

当前认识读取终端的一条，读到了“登记业务受理：一楼105；本页未标明更新时间。”，发言同时保留203旧线索与缺少更新时间的限制。问人样本均承认工作人员这周没去过，并保留105反向线索。旧认识一条把旧读牌说成“刚才看”，该克隆本轮实际新动作只有问人；不补造额外读取Source。

无认识六条都成功重读牌，但只据203建议去办理。较多perform不代表较多有效信息或较好认识；同一人重复发言、同一牌重复读取都不是独立核实。

按预先固定的规则，各臂首次新增Source再更新一次，三次都接受并保留105反证：当前和旧认识臂再接工作人员的重复发言，无认识臂再接大厅牌读取，均为reinforcement，正文没有重写。这里无认识臂的再更新只验证宿主所存同一家族可继续整理，不回填到已经完成的Character对照。

唯一的终端读取Source已经提交并被角色使用；它没有被选为“各臂首次”再更新样本。本轮不声称对每个后续Source都进行了模型更新。

## 5. 证据、观察与取舍

| Evidence | Finding | Path |
| --- | --- | --- |
| 六个当前/旧认识准备在原检索中均无目标，ID准入后正文全读到 | 原断点仍是候选入口，不能归给角色无法理解 | 保留简单ID准入；不在查询里塞目标ID或答案 |
| 当前5/6问人/查终端，旧认识2/6问人；两者12/12保留分歧 | 更新后的材料出现行为差异，仍是小样本条件证据 | 保留可修订认识，继续正常连续试玩验证 |
| 无认识6/6重复读大厅牌，6/6不再提105 | 原始历史路径仍可能在续写中压平矛盾 | 保留这个体验问题；不能以执行更多证明认识更好 |
| 当前两条强化正文不变、证据新增；三次再强化仍保留反证 | 新Source不必触发正文改写，更不意味着矛盾收敛 | 在明确整理点更新，允许主观冲突持续 |

无认识臂的非认识材料仍沿用原有投影：两份带JSON的读牌行动结果，以及一条“另一办事点曾指错路”的旧经历。它不是6.3清楚自然语言双牌的纯原始证据对照。三臂共享可搜索Source，但最终阅读内容、格式、长度和分支数不同；不能把差异只归因于认识抽象或单次更新。

24轮闲聊逐条复核没有硬塞登记细节，delayed-2第一轮回答衣服后轻微续提“准备过去了吗”；保留为旧行程延续，不增加语义分类器或提示修补。
