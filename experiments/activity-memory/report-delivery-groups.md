# Delivery 完整阅读组续验（2026-10-04）

本轮支持显式历史查询的旧版／新版成组，也确认必要反证必须保留到最终裁剪。按整个认知家族强制绑定所有当前 RELATED 冲突支没有通过：它恢复了不适用分支，挤掉了必需项。三项预算仍会扣留过大的完整证据组，不能把分组当作解决预算不足。

## 1. 范围与三个对照

只读复用 Delivery 排序实验及其上游冻结档案：四条检索路径、五个固定问题、每个问题三次既有 JEV 返回，共60个普通记录，另3个显式历史记录。先精确重现上轮两种 Delivery，再比较：

| 路径 | 组织方式 |
| --- | --- |
| P：related_probability | 上轮逐条概率排序，作为原样对照 |
| H：history_pairs | 仅显式历史问题把已准入的旧／新修订端点成组，旧版先读；普通问题逐条选择 |
| HC：history_and_conflict | H 再加已声明未解决冲突的当前支；仅当两支都已 RELATED 时成组 |

组用最好成员的排序位置／适用性作优先级，不累加分支分数。相交的依赖组合并，避免同一认识重复竞争；历史端点必须已经进入候选，不制造漏掉的旧版。Relation 为冻结实验旁侧元数据，不是自动发现或新的世界事实。

每组保留原认识正文及既有投影生成的完整证据、反证、活动补齐内容。去重按规范证据段，实数计算条目与JSON字符，最后一次整组决定接受或扣留。默认上限仍3个实际条目、4500JSON字符；没有把两条认识或六条证据藏成一个名额。

为看清一组全部成本，临时调用现有投影器时使用按本角色档案大小计算的有限工作预算，实际输出始终重新受默认预算约束。这是实验适配，不是放宽正式交付预算；没有改既有投影器或活动交付器。

新增模型调用0，JEV／utility／core模型调用均被阻止。首个 v1 目录只写了协议后，合成对照误用 retain 触发模型入口，被禁止调用的断言截住；未发起真实请求。改为确定性构造该机械测试的 Atom，成功结果在新的 v2 目录，未覆写旧输入。

## 2. 历史问题：新旧成组恢复完整对照

| 项目：三个重复 | P | H | HC |
| --- | ---: | ---: | ---: |
| 读到旧版 | 2/3 | 3/3 | 3/3 |
| 读到新版 | 3/3 | 3/3 | 3/3 |
| 读到旧版＋新版＋当前相反支 | 0/3 | 0/3 | 3/3 |

H 三次都交付：旧 obs:1 → 当前新版 → 资料日期 bank:09。旧／新版实占两个名额，另一名额继续由概率排序分配。HC 将历史对照与当前冲突关系合并，三次都交付旧／新／bank:10，资料日期因预算被排后。

这是同一冻结历史问题上的结构结果。正文不改写，trace 保存历史修订关系，阅读先后明确为旧→新；没有给角色增加新的时间标注或运行 Character Turn，因此不能宣称角色已经理解修订历史。历史模式仍由调用者明确声明，没有增加自然语言意图分类。

## 3. 普通问题：盲目冲突成组导致退化

H 在60个普通记录上的读取内容与 P 保持一致。HC 在熟悉场景中，把被 JEV 误判 RELATED 的陌生地点 bank:10 与高分新版绑在一起，占两个名额，随后允许背景 bank:12 占第三个名额，必需 bank:05 被排后。

| 路径：每行五问题各三次 | 必需项未读 P/H→HC | 无关项读取 P/H→HC |
| --- | ---: | ---: |
| A 更新后原投影 | 6→8 | 4→6 |
| B 有效旧入口继承 | 3→6 | 3→6 |
| C 短情境 | 3→6 | 5→8 |
| D 家族初筛 | 0→3 | 5→8 |

D 的等候点仍三次交付新版、相反导航支与资料日期；两种导航刺激的必要相反支读取仍6/6。退化集中在熟悉地点：原本逐条排序降低了弱分支的曝光，HC 又让它借高分成员一起进入。目标正情境读取仍9/9，但这不能抵销丢掉其他必需认识的退化。

标签沿用原库探索标签，预先定义、非盲评；三次重复不是独立问题。结论是这批明确反例不支持“同家族＋两支 RELATED 就永久强制共同交付”，不是证明所有冲突都不该共同阅读。应区分有必要共同理解的证据依赖与宽泛维度关联。

## 4. 必要反证与真实预算：复用六个合成记录

复用此前 C／D 类认知更新实验各三个归档版本，仅机械验证交付，不重新形成认识或调用 JEV。手工适用性数值明确标为合成排序控制，不计入真实模型效果。

| 对照 | 默认3项结果 | 较大预算诊断 |
| --- | --- | --- |
| C：一条稳定认识＋一个反例 | 三次都交付正文与反证，共2项 | 仍2项 |
| D：两个冲突支＋六段相互反证 | 三次完整组全部扣留 | 12项上限下实际交付8项：2认识＋6证据段 |

D 默认仍为空，已知预算限制没有被解决；这次只证明不会为了留下正文而丢反证。诊断上限12仅用于展示真实成本，不代表默认配置改变。六段证据按规范证据键去重，引用映射未合并为模糊文本。反证已经在当前观察上下文时不重复占名额，局部测试确认可只新增正文。

## 5. 新确认的缺陷：活动补齐能拆散正文与反证

构造一个仅本角色可见的合成机械对照：已裁定活动开场、结尾，以及一条独立反证；一条主观认识引用开场并保留反证。源数据和认识位于新输出目录，不写入世界或正式记忆。

现有 projections.delivery_projection 先把正文＋反证作为2项提交，但 activity_delivery.deliver 随后将结束、开场放在它们之前，再逐项按3项裁剪：

```text
结束、开场、正文、反证
       ↓ 三项预算
结束、开场、正文       ← 反证丢了
```

当前旧交付器的实际输出为3项，正文存在、反证不存在。实验的完整组算法算出4项，在3项上限下扣留整组；仅在单独4项诊断中共同交付正文与反证。

这不是模型语义误判，是可复现的两次裁剪顺序缺陷。相关原代码位置为 activity_delivery.py 的最终逐项 pool 选择。新增最小回归测试保留复现，并验证实验的最终分组不能暴露无反证的正文；既有活动交付器本轮没有改，因此不能说正式路径已修复。

将开场、结尾一并视为硬依赖是本轮保守实验选择，导致这例整组为空。后续更小的修法可以保留“正文＋必要反证”的不可拆组，再独立决定活动补齐项的优先级／必要性，但不能在最后截断反证。此细化尚未实施或验证。

## 6. 建议

保留普通认识的适用性排序和显式历史端点成组；保证正文＋必要反证的依赖一直保持到最终预算分配。不要全局开启按宽泛家族强制冲突成组。

下一步优先修已复现的活动二次裁剪缺陷，区分必要证据与可选开场补充。三项放不下完整反证组是另一项内容／预算问题，不能靠改排序掩盖；暂不改预算、schema或认识本体。自动家族发现、条件重叠判定及长期角色行为仍未验证。
