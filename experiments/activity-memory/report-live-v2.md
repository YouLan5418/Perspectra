`packages/application/src/scene-decision.ts` 的最后一人离开仅自动关闭没有固定地点的临时会话；地点房间保持空但有效，显式关闭仍是终态。移动和成员变更继续走既有规则与原子提交，不重开历史 closed 场景。

`experiments/activity-memory/activity_delivery.py` 保留 Episode 的结构关联，但不让没有活动元数据的闲聊 Atom 继承它。自动补齐只由真正命中的活动 Atom 触发；没有通过相关性检查的具体活动 Atom，就不扩展开场和结尾。明确授权活动 ID 仍能直接取本局收尾。三项／4500 JSON 字符预算和材料完整度标注保留。

没有修改正式 Memory schema、World State schema、Event Log schema 或 Rulebook。正式网页仍使用原生 CognitiveMemoryService；本轮 Core 在实验驱动的真实角色请求中注入。活动私有状态可按原权限交给当时的角色，但不作为额外世界知识送入 Core 查询。

## 5. 结局冷问题：补齐取得了一个明确成功样本

另建 `.tmp/hosted-memory-cold-probe-20261003-v2`。三个条件各复制冻结的 world／memory 数据，不向原轨迹插入问题；移除近期观察和自我观察，省略活动私有上下文。向 Claude 提问：

> 我们之前在卧室玩过的那局猜数字，最后是怎么结束的？

| 条件 | 模型调用 | 最终交付来源 | 可见回答与判断 |
| --- | ---: | --- | --- |
| 原生记忆 | 1 | 352、363、193 | 记得被中止，但补出“为了空间效率和舒适度，移步客厅，所以中止”的因果关系 |
| Core 原交付 | 2 | 352、104、22 | 主动查“卧室 猜数字”，只看到开场等片段，回答注意力转移后“无疾而终” |
| Core 补齐交付 | 2 | 181、104、352 | 主动查“猜数字”，读到中止和开场，准确回答第四轮按宿主逃生按钮中止 |

补齐组的实际回答为：

> 严格来说，那局并没有按常规流程决出胜负。你在第四轮直接按下了宿主逃生按钮，把活动强行中止了。

来源 181 是 Claude 获准观察的 accepted 活动结束记录，包含 `phase=host-aborted`、`round=4` 和宿主逃生结果；它距离提问 256 tick。交付明确标注活动已结束、当前含结束记录、过程仅为选取片段。模型没有补写玩家中止的动机。

原生组来源 193 是 Claude 自己游戏结束后的发言，它先说中止无妨，再提议因空间舒适度去客厅。这个来源证明她说过这些话，不能证明舒适度是先前中止的原因；冷回答将两者连成因果。这是阅读自己旧发言后产生更确定叙述的实际例子，**本例不是 Observation 生成回路**。Core 原交付组连真实结尾也没读到，仍给出了具体结束原因。

两组 Core 的主动查询不同，每个条件只跑一次，不能将回答差异当相同查询的模型因果对照。为单独核实交付机制，又做了零模型、零编码调用的重放：同一最终档案、同一查询“猜数字”、同一批检索候选，原交付为 352、104、115，补齐交付为 181、104、352，与真实补齐请求完全一致。该结果证明结束记录由交付补齐加入，而不是由不同模型查询才偶然搜到。

因此可保留的结论是：**在这个样本中，真实结束证据进入角色阅读材料后，角色准确回顾了结束方式。** 不能据此宣称整体召回质量、所有结局问题或长期行为均已改善。

## 6. 认知隔离、来源与存档核验

全部已保存前缀中，原 Source 不变；Atom、Episode、Observation 和实际交付的引用均通过验证。六字段 `sourceId / sourceHash / epistemicKind / worldSeq / CharacterId / WorldAddress` 与各自授权来源映射一致，记忆前缀没有越过当前世界序号。

四角色使用明确活动 ID 的只读检查中，Claude、GPT 分别获得自己的结束来源 181、180，且包含开场；非参与者 DeepSeek、GLM 返回空。非参与者档案未出现直接游戏元数据，猜测者及玩家的请求中未出现私有答案属性。旁听后来公开谈及游戏可以成为发言来源，不等于获得游戏私有裁定数据。

这些是本次数据的程序边界核验，不证明所有自由对白都不存在语义泄漏，也不证明主持人永久记住未归档的私有答案。本轮没有把临时私有变量补写成长久 Source。

原存档五个 SQLite 文件 quick_check 均为 ok。冷问题之后再次核对五文件 SHA-256，全都未改变；三个副本的最终回答分别真实提交，原世界仍停在 1884。存档关闭前后 SQLite 正常落盘会改变文件哈希，冷问题的不变性以关闭后的 `storage-integrity.json` 快照为准。

## 7. 提炼成本与实验恢复

旧 retain 输出上限为 2500 token；CP4 成功时 GPT、Claude 的实际可见输出分别为 5441、8367 token。原 CP3 JSON 解析失败未保留 finish_reason，不能断定该次一定是截断。实验桥现在保存输出预算、finish_reason 和实际返回，遇到 length 或非法 JSON 仍失败，不做修补。

root 46 的 GPT 135 条来源整批提炼超过 240 秒。随后按完整 Source 边界约 9000 叙述字符分批，所有来源先做授权检查，合并 Atom 再验证。Source 不截断，六字段不改变。最终完整重建仍在十分钟期限内超时过一次：CP7 留下十批有效返回，但没有伪装成完整档案。

为完成当前实验，桥接改为验证并复用已有授权前缀的 Atom，只对新增 Source retain；前缀任一来源变化或属主不同均在模型调用前拒绝。Episode／Observation 仍按新完整前缀整理。前缀完全相同且档案有效时复用整份整理结果，仅重建检索索引，避免重复调用；CP9 四角色均复用了 CP8 的同前缀档案。

整理请求去掉重复嵌入的 Atom／来源结构：完整 Atom 证据文本只发送一次，Episode 用 Atom ID 引用。完整映射保留在档案和交付 trace。这些是实验传输和复用调整，不是正式记忆架构迁移。

CP6 的 Claude 166 来源生成 556 Atom；七个模型分组中一组因未知 Atom ID 整组拒绝，176 Atom 保守独立存放，总计 182 Episode。最终 CP8／9 得到七个 Episode，但来源更多、传输表示也改变，不能将差异归因于单一优化。证据未丢失不等于经历分组已经稳定。

共出现九个编号 checkpoint，其中六个四角色完整，三个保留部分失败产物。所有中断与恢复记录均保留，未覆盖旧失败。运行中调整过传输、期限和前缀复用，所以本轮不是参数全程固定的对照实验。自然角色调用已完成，但提炼成本仍偏高，尚未验证常规试玩每数回合整理的可接受延迟。
