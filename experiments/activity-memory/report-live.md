# 连续真实试玩：活动记忆与结束证据

日期：2026-10-03。模型：本机 8045 的 `gemini-3.7-flash`。新实验目录：`.tmp/hosted-memory-live-20261003-v1`。

**结论：结束证据的保存与精确活动关联有效；自然查询的召回仍有明显噪声，不能宣布长期认知体验通过。** 两局正常结算、一局宿主中止后，实际连续游玩还暴露了房间场景无法再次进入的问题。停止失去 NPC 观众的后半段，没有修改场景规则、既有玩家存档或网页进程。

## 1. 实际范围

AI 玩家依据玩家可见场景、转录、活动公开／本人私有视图和可用移动目的地提出操作；NPC 使用实际包脚本、活动调度、PrototypeCharacterTurn、Rulebook 和原子提交。四位少女的模型均为 Gemini 3.7 Flash，角色名字不是提供商选择。

实验代理在 NPC 的实际请求里注入 Core Recall + Observation，保留近期上下文。记忆核心只接收 CognitiveMemoryService 导出的角色授权 Source 和本人查询上下文，不接收世界库路径、完整世界状态或游戏私有答案；当前私有答案仍仅由宿主直接授权给主持人。继续使用 E5、现有清理／门槛、最多三项与 4500 JSON 字符，没有换编码器或重新调参。

## 3. 证据 → 判断 → 后续路径

### 3.1 活动的“当前刺激”混入旧记录

证据：call 39 开始第二局，stimulus 却包含第一局的旧猜测与初始身份观察。`playtest-frozen-runtime.ts` 活动调度调用 `view.observations.slice(-8)`；`ProjectionRebuilder` 按观察 ID 排序，并非 sourceSeq 时间排序。PrototypeCharacterTurn 的近期观察本身已按 sourceSeq 排序，问题在活动唤醒的刺激取样。

第一局之后的 42 次活动期间调用全部非空，111 个交付条目只引用 event:19／22／23／66／69 五个初始来源。占全轮交付条目的约 78%。所以 55／114 的非空率不能解释为有效长期召回，也不能据此夸大行为收益。

路径：下一轮先按授权 sourceSeq 选活动刺激，继续保留真实新事件的来源边界。不要在这些混杂输入上继续调语义门槛。

### 3.2 结尾补齐会被过宽的 Episode 关联带偏

证据：call 89 的当前刺激明确提到刚中止的 [32,33] 那局，交付却是第二局 72 猜中的结尾与开场。Claude 的回答仍正确提到中止键，但近期上下文已经包含第三局中止，不能归因于长期记忆。

更明确的噪声是 call 103：玩家问冰乌龙茶、气泡水和大家想喝什么；匹配的是 event:547 的饮料发言及 event:537 的赛后交谈。它们被归入 `episode:4`“主持第二轮猜数字游戏及赛后交谈”，随后 `activity_delivery.atom_links` 继承 Episode 的活动关联，补出第二局的开场和 72 猜中。这两项占了三项预算中的两个位置。call 107 也出现类似交付。

判断：结束来源没有写错，**“命中这段经历的一句话”不等于“正在回忆这场活动”**。这里同时存在相似多局选错和结束补全范围过宽，不能全归给编码器。

路径：保留明确活动 ID 与明确活动内容命中的结束补全；收窄仅凭 Episode 成员关系触发的补全。应以命中的具体 Atom 为依据，避免喝饮料的命中自动带出牌局／小游戏结局。本轮没有中途修改该逻辑。

### 3.3 房间返回后失去所有观察者

证据：root 27–31 确实通过受控移动去了厨房、返回客厅，产生 27 次 NPC 调用。所有角色最后的位置均为 living-room，却没有可用客厅场景。

`SceneDecisionService.transitionForMove` 在最后一人离开时提交 scene.closed；选择目的地又排除了 closed 场景。客厅被关闭后，返回只更新位置，没有加入目的地场景。玩家问第三局正确答案的 root 32 没有 NPC 观察者，root 33–38 又在厨房与客厅往返，均没有 NPC 调用。

判断：这是场景生命周期与重访的缺陷，不是角色忘事或拒绝回应。原计划 24 次自由操作，实际记录 12 次，其中前五次 root 27–31 有互动，后七次失去 NPC 观众；没有把空房间往返算作有价值的长试玩。发现后在记忆维护阶段停止，保留第六次部分档案。

路径：先让固定地点场景支持空房间后的重访，再用新目录继续有分离与重新相遇的试玩。固定房间与临时会话的关闭语义应区别处理，优先复用现有场景机制，本轮未改世界规则。

### 3.4 Observation 没有行为收益证据

第三局关闭后的完整档案共生成 15 条 Observation，但实际交付 0 条；36 次扣留条目来自原严格规则和重复候选。本轮不能判断这些主观认识是否会影响角色行为，也不能凭没有交付就断言认识质量良好。

角色自然对白和受控移动确实发生，但自身设定、近期上下文、当前游戏状态及长期原文记忆同时存在，没有旧对旧波动基线，不能作因果拆分。Observation 的事实／印象分离仍是后续事项，不在这轮直接全面放宽。

## 4. 返回与提交分别核验

七个非法混合输出 call 17／55／56／65／86／87／88 未执行；call 27／31 返回了对白，但已经超出宿主期限，没有对应提交事件。其余有效动作和对白按实际提交记录统计，不把 HTTP 返回当角色已行动。

10 个入口带错误：七次非法输出，两次普通反应超时，一次分场景开始游戏拒绝。重试没有冒充 pass；已提交的移动保留，被拒猜测不换手。玩家入口与 NPC 行动分别记录，宿主逃生不是角色主动放弃。

核验通过：

- 各次已保存 Source 与原导出逐项一致，跨整理前缀内容不变；交付及结束关联的六字段追溯均属于对应角色授权前缀。
- DeepSeek／GLM 没有直接游戏元数据，精确游戏 ID 检索为空；后来听到的公开讨论仍可以形成 reported_speech 来源。这不是“未参与者完全不知道游戏”。
- 玩家／猜测者当前活动上下文没有私有 answer 属性；记忆查询未传游戏私有状态。角色完整私有实验请求只在本机 trace 保存，不进入玩家页面；认证头不保存。
- 所有实验交付最多三项、4500 JSON 字符，标注计入预算。
- 停止后 world／memory／session／context SQLite `quick_check` 均为 ok。
- 本轮类型检查与 Lint 通过。没有重跑默认 133 项测试，也没有修改核心事实、提交或权限机制来绕过玩法失败。

这些检查不证明任意自由文本语义绝不越权。例如 call 29 曾在自身移动后写“随着众人走进客厅”，而当时只有 Claude 的移动已经提交；该句仍只是外显叙述，不是其他人的位置证据。

## 5. 下一轮重心与产物

优先处理固定房间重访和活动刺激按发生顺序取样；然后收窄日常 Atom 的活动结束扩展。暂不继续扩大模型、重排器、盲评或门槛校准。修好这几个具体问题后，在新存档中继续普通互动、分离和重新相遇，再看旧活动是否能影响回应。
