## 1. 实际问题与本次修改

上一轮延迟选择时，相关认识在初筛被全部拒绝，角色收到空记忆。先落实方案6.0，比较原路径与直接阅读授权原始历史；没有先删除检索器、JEV、Observation或更改正式Memory schema。

宿主复用已验证的角色Source表，逐项核对来源事件、观察者、namespace、原文、认识论类型及hash。先取得角色／世界／时点的授权前缀，再用当前人物、地点、活动与明确关联选择旧经历。角色的observer身份或其自身actor身份不构成通配关联。

当前可见`items.current`明确提供对象和地点关系，因此旧牌面读取可由targetId关联到当前地点。此关系只表示该旧经历涉及当前可见对象，不宣称该对象历史上一直在此处。人物关联包括发言主体、目标人物和明确接收者；不从自由文本猜人物ID。没有ID关联的四条旧背景经历被排除，并在trace记录覆盖限制。

原始Source逐条自然语言交付，保留发言、读取和已裁定结果的区别；hash与完整引用在trace，角色读到来源ID、主体、类型、worldSeq、获知tick与年龄。不调用嵌入、BM25、RRF、JEV、摘要或认识更新。近期窗口仍为最近4条观察及4条自身观察，重叠Source用sourceSeq及原文去重。按最新完整来源优先预算，再按时间升序呈现，未提供来源单独记录。

## 2. 冻结和测量边界

复用旧自主取证实验的三份`future-prefix`，分别对应先前raw／paired／updated轨迹。每份都已经经历8次无关互动，并包含同一后续玩家刺激。第一次选择前，对照的世界前缀、非记忆Context、人物、模型、能力、输出预算和最多2次Character调用完全一致。初始请求逐项比较，历史输入文件前后hash相同。发生真实行动后各组历史可分叉。

三份历史是实验轨迹，不是三种新模型或独立场景。仍允许角色publish、perform或abstain，禁止额外主动recall，与旧闭环保持一致；没有加入核实指令。对白中的建议不计执行。只有accepted及对应`action.resolved`实际提交才计执行，获取新证据还需同事务提交的角色私有Source。

网关`/v1/models`列出原`gemini-3.7-flash`，没有上下文容量字段。因此采用8000／24000 **UTF-8 JSON字节**的实验历史预算，而非宣称8k／24k token容量。未估算金额，材料token为null；提供商返回的全请求token原样统计。实际短历史不足以测试长窗口极限。

## 4. 逐样本阅读与体验边界

原始路径的7次首次publish中，5次明确提及两个相反房间，1次只提及旧203说法并建议再确认，1次泛泛建议查终端，没有重新讲出旧矛盾。材料确实可见，不代表每次表达都完整保留反证。

例如updated轨迹重复0的raw8000表达：

> 既然是办理登记，之前大厅公告牌写着二楼203，指示牌上写着一楼105，工作人员之前也说印象里在203。大厅里还有办事终端，咱们可以先查查终端确认一下，或者直接选一楼105或二楼203去看看。你打算怎么安排？

这次只publish，程序没有替它查终端或移动。逐条核对5次真实读取后的续写：全部说明终端显示一楼105且未标更新时间；终端文字仍是显示内容，世界日志没有提交“登记处位置已确认”或玩家移动。本轮可接受“先去看看”的主观选择，不将其升级为地点真理。首次对白没有硬塞外套、电影、做饭等旧闲聊，但这些噪声真实存在于材料中；一个场景不能证明噪声已经普遍受控。

## 5. 保留的v1探索及修正

v1也完整跑了18次选择，29次Character调用，输入101499、输出2373、总126777 token。较早的选择器没有接收者关系，只交付13条／4157字节。审计从实际Event重新计数：complex取证1/6、raw8000为6/6、raw24000为4/6。

实现复核发现它遗漏了“自身旧对白明确对当前人物说”的参与关系，因此补全现有addresseeIds，并在新目录跑v2；不是按模型成功与否择样重试。保留v1全部原始请求、响应和世界记录。

v1派生行动计数曾错误使用`performResult.actionId`，现有字段实际是`operationId`，导致初始result／summary将已提交行动计为none。运行器已修正，v1正确统计以只读`audit.json`为准；原始世界与模型输出未改写。v2的运行计数与独立审计一致。

v1与v2新增共53次Character调用，总输入200439、输出4512、总249021 token。v1与v2的材料组织不同且均为小样本，不能把取证次数变化直接归因于旧自身对白或当作稳定概率。它提示需要测噪声和少量材料，而不是以v1较高次数直接接入。

### 5.1 v3移除宿主的隐式检索

最终源码复核发现：v1／v2虽然角色只阅读实验交付，但`PrototypeCharacterTurn`因传入memory服务，仍会先执行原生`prepareStimulus`关键词检索，再被实验材料覆盖。因此这两轮是有效的角色材料对照，不能作为“执行路径不经过任何检索”的证明，也不能用它们估计取消这次隐式检索的耗时。

最终入口不向实验Character Turn注入原生memory服务；授权Source捕获仍独立复用现有memory。prepare及run中把`prepareStimulus`设为误调用即抛错，防止无用调用重新出现。最近观察、事实、能力与执行结果仍由同一Character Turn生成，输出时将实验memories放回原来的位置，没有更改角色提示或权威路径。

在全新v3目录，对3条轨迹、3条路径各做1次真实选择，共9次。对应v2首次选择的9个最终请求hash全部相同，误调用断言未触发。原始历史仍20条，两块牌及工作人员来源不变；complex取证0/3、raw8000为2/3、raw24000为1/3，原始路径3次均实际读取终端。没有把这个额外小样本当作新的概率结论。
