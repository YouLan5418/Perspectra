# Observation 适用性检索投影实验（2026-10-04）

## 1. 结论

仅把适用情境、条件、例外和主题抽成搜索文本，再送入现有 E5 / BM25 检索，未打通自然召回：原三个刺激仍为 0/3，新增两个对照也未交付目标认识。等候点场景的目标语义排名有所提升，但无关闲聊的排名也明显上升，不能把排名提升直接解释为质量改善。

这轮验证的是“适用性字段序列化为一个搜索文本”的最小版本，**不是已经实现了结构化适用性匹配**。对象 ID 已提取，但只存作投影诊断元数据，不参与对象约束或新增实体投票；条件和例外也未由宿主裁定是否成立。结果不证明整个适用性检索方向无效，只表明这种单窗口文本改写不足以解决当前失败样本。

未强制交付，未放松门槛，未根据结果继续改投影。由于目标认识在所有场景都未自然交付，没有启动角色行为对照；不能引用上一轮干预中的行为差异来宣称本轮链路成功。

## 2. 冻结内容与唯一变量

复用 .tmp/observation-choice-20261004-v3 的 build.json，与 v2 的有效认识、索引相同。档案与所有支持证据不重新 retain 或 consolidation。形成 tick 为 15，探针 tick 为 55，最新支持证据年龄为 42 tick，仍是四个独立 Source。55 tick 历史是受控预写经历，不是自然长试玩。

目标原认识：

> 【主观认识，可修正】旅人在初次前往或陌生的场所容易参考旧材料指路导致跑错位置，但在熟悉的常去场所能够准确指引目的地。

Gemini 3.7 Flash 一次生成适用性字段。模型输入只有以上正文和该角色已有授权视图中的姓名／角色 ID 表，身份表单独从上一轮已保存视图提取，不发送其刺激、其他上下文或世界完整状态。生成请求看不到测试刺激，也看不到原始历史事件。

保留整个原认识作为本体，单独保存可重建投影。只替换 retrieval:33 的 text / retrievalText 和对应向量，34 个索引窗口总数不变；原 atomIds、六字段 sourceRefs、实体元数据、其他 33 个窗口与向量全部不变。所有搜索命中仍回指 obs:1。诊断图边用原算法及原阈值重算；语义边在当前检索里只记录诊断，不负责额外准入或投票。

编码器仍为 Xenova/multilingual-e5-small、固定 revision 761b726、int8、384 维；没有换 Qwen、重切窗口或增加表示数量。适用性搜索文本为 99 个 passage token，在原 220 token 窗口预算内。

每个相同 Character Turn 请求分别用原索引和投影索引检索。查询完全一致。语义门槛仍为余弦 ≥ 0.30 且 lift ≥ 0.30，或者关键词覆盖 ≥ 0.15；同人物姓名没有成为额外内容信号。候选中位数因索引表示变化可能略变，它是现有算法的派生值，不是本轮主动调整的门槛。Delivery 仍最多三项，不修改来源规则。

## 3. 实际生成的适用性字段

- 对象：旅人，character:player。
- 情境：前往陌生场所、初次到访新地点、路线指引与导航、参考旧材料寻路、前往熟悉常去的地点。
- 条件：身处陌生或初次前往的场所；参考旧材料进行指路。
- 例外：身处熟悉且常去的场所；指引熟悉的目的地。
- 主题：指路与寻路、路线准确度、陌生环境导航、旧资料参考。

正文和派生字段经非盲阅读，没有加入“必须询问资料”“不许跟随”等行动指令，也没有新增欺骗意图或独立事实。这里只做了字段形状、身份合法性与来源映射的程序校验，语义忠实性属于本轮人工阅读，不称作已证明的自动蕴含校验。

## 4. 原刺激与新增对照

原三个刺激保持逐字一致：

1. new-task：“这是我们第一次来这里。登记表在隔壁小屋，我来带路，我们先过去吧。”
2. new-stop：“第一次到这儿也没什么复杂的，隔壁就是等候点，我看过介绍了。我们走吧。”
3. familiar-control：“这是我们经常来的地方，隔壁小屋的老位置没有变。我来带路，我们过去吧。”

新增对照在运行前写进 protocol：

4. same-person-unrelated：仍由旅人说“桌上的杂志我看完了，里面那篇花园随笔挺有意思。你平时喜欢读什么？”
5. other-person-navigation：与 new-task 台词相同，仅说话者改为陆舟 character:bob。

熟悉地点不是必须返回空的负例：认识本身包含熟悉场所的例外。若召回完整认识并没有引发不恰当怀疑，也可能是正确使用。本轮没有交付，无法测量这一点。不同人物导航也不一概定义为错误联想；它用于检查系统是否能区别“关于旅人的认识”与“另一人正带路”，并防止把联想误当成关于另一人的证据。

两个领表刺激的 semanticQuery 和 keywordTerms 完全相同，entitySeeds 能看到说话者 ID 的差别，但本轮目标的原实体元数据为空，语义／词项分数因此完全相同。只在投影旁保存 subjects，不会自动得到对象匹配能力。这个限制与权限泄漏是不同问题：它是适用性／归属区分不足，并未读入另一角色的私密来源。

## 6. 核验与调用

本轮一次 Gemini 适用性生成调用、十次本地只读检索、零次 Character Turn 模型调用。没有为了得到行为结果强行注入目标认识，也没有新生成“更好命中”的认识。

audit.json 核对：

- 原档案与冻结 build.json 完全一致，前三个刺激完全一致；
- 两路对照查询及准入参数相同；
- 仅一个搜索窗口变化，其他窗口与向量相同，实体元数据未变；
- 来源／角色／世界地址映射通过，未包含另一角色的私密来源；
- 错误角色、篡改来源哈希、未授权对象 ID 的三次负向检查全部拒绝；
- 输入、原档案、索引与输出没有 Unicode 替换字符。

类型检查和实验 TypeScript Lint 通过。未修改正式运行时、Memory schema、World State、Event Log 或 Rulebook，未运行全量测试，也未开展新的长试玩。活动实验目录中的共享实验入口新增可选参数，原自然检索与明确交付干预入口仍保留。
