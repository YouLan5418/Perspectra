# Observation 对自主选择的延迟影响（2026-10-04）

## 1. 结论与范围

读到一条由历史证据形成的 Observation 后，本轮角色确实出现了不同的首次自主选择：在陌生等候点场景中，从直接执行移动变为先询问资料是否最新。但现有检索没有自然交付这条认识，完整的“延迟相似场景 → 自动唤起认识 → 改变选择”链路尚未通过。

行为结果来自明确标记的交付干预，不是自然召回成功。没有修改正式记忆、查询门槛、角色人设、World schema 或 Rulebook。

## 2. 如何形成和保留认识

新建独立受控世界，角色为小芷。第 2、6、10 tick 的亲历记录分别描述旅人在展馆、旅馆、码头依据旧资料找错位置；第 13 tick 描述他在熟悉商店正确指路。记录只进入小芷的授权观察，另一个角色的私密观察作为隔离检查，不传入核心。

Gemini 3.7 Flash 在第 15 tick 通过真实 retain、Episode 分组、Observation consolidation 形成：

> 【主观认识，可修正】旅人在初次前往或陌生的场所容易参考旧材料指路导致跑错位置，但在熟悉的常去场所能够准确指引目的地。

支持证据来自四个独立 Source，不按拆出的多个 Atom 当作多个独立来源。该认识没有写成欺骗意图，也没有变成世界事实。

随后世界实际提交了 40 个无关观察回合，推进到第 55 tick。测试保留第 15 tick 的记忆档案，未重新 consolidation；认识形成距今 40 tick，最新支持证据距今 42 tick。三个当前场景都不提示“请回忆”或要求角色按既往经历采取某种行为。

**历史是预写的受控经历，共 55 个提交 tick，不是 55 回合真实模型自由试玩。** 它能测试保存、时间差和相似场景选择，不证明自然长试玩中这条认识会一直存活或不被后续整理改写。

## 3. 自然召回：这轮没有通过

三个预定刺激分别为：首次到这里领取登记表、首次到这里找等候点、常去地点沿原位置行走。认识在档案中存在且满足来源交付规则，但自然检索交付为 0/3。

其原始余弦约 0.862–0.872，相对背景 lift 均为 0，词项覆盖为 0–0.054，未通过现有准入条件。没有出现因来源不可信而扣留的 trace，它还没走到 Observation 交付阶段。

行为输出前，额外检查了两条明确提到旧介绍／旧资料的刺激；也未交付目标认识。其中一条返回了一个旧登记处 Atom。诊断单独保存在本机，不与三个预定场景或行为试验混报。没有据此改门槛或筛选有利的模型回答。

## 4. 交付干预对照

使用同一份已生成的认识，通过现有 Delivery Projection 校验和生成阅读项，在新世界副本开展真实 Character Turn：

- 有认识：交付这一条 Observation。
- 无认识 A：从同一份交付中只删除目标 Observation。
- 无认识 B：与 A 完全相同，用来观察模型自身波动。

每个场景每组 3 次，组别顺序轮换，总计 27 次调用。其余角色上下文、刺激、可用行动和其他记忆完全一致；近期观察、自身近期观察为空。两组都保留相同授权历史，当前被交付的其他长期记忆为空。只比较首次选择，统一关闭进一步 recall，最多一次模型调用；不把后续询问的答案或后续行动混入本次测量。

干预没有绕过来源门槛，没有给模型行为指令，阅读项仍标为可修正主观认识，保留四个 Source 的映射和 42 tick 的证据年龄。干预记录的 selectionMethod 是 explicit_delivery_intervention，没有伪装成语义路或图路命中。

| 场景 | 有 Observation（3 次） | 无 Observation A（3 次） | 无 Observation B（3 次） |
| --- | --- | --- | --- |
| 新地点领登记表 | 3 次答应，但自主增加核对路线／指示的提醒 | 3 次直接答应 | 3 次直接答应 |
| 新地点找等候点 | 3 次先询问介绍是否最新，未执行移动 | 2 次成功移动；1 次非法混合输出被拒 | 3 次成功移动 |
| 熟悉地点原位置 | 2 次答应、1 次成功移动；均无怀疑 | 2 次答应、1 次成功移动 | 2 次答应、1 次成功移动 |

等候点的一个真实回答为：

> 你手里的介绍是最新的吗？之前几次去陌生地方，你按旧资料走可容易跑偏，咱们过去先看一眼门牌吧。

对应无认识试验实际提出 move，Rulebook 接受，生成 character.moved。成功移动的结果状态是 budget_exhausted：本试验只有一次调用，不继续动作后续写；这不表示移动失败。非法混合输出整包拒绝，未产生任何事件，也不计作角色主动选择停留。

新登记表场景主要是回应策略的改变，未体现移动差异。等候点场景出现了结构化行动与先询问的分叉；熟悉地点没有出现持续不信任。没有验证后续询问完成后她最终是否也会移动。

## 5. 证据与检查

有效自然召回目录：.tmp/observation-choice-20261004-v2。交付干预目录：.tmp/observation-choice-20261004-v3。前者有三次真实整理调用，后者复用其已验证档案，没有再次生成或改写目标认识。

27 次角色调用全部返回，26 次结果合法；1 次非法混合输出保留原文。155 个带六字段的对象通过核验；逐次请求的非记忆上下文完全一致，其他交付记忆一致，独立历史库始终未变。错误角色请求和篡改引用的六次负向检查全部拒绝，历史库 quick_check 为 ok。

首轮 v1 因 Windows 管道编码损坏中文输入而排除，保留 invalid.json 和原结果，不将其计作召回失败。脚本已加入输入检查；后续输入 Unicode 核验通过。

标签由本轮非盲阅读给出，属于小样本探索，不是人工 gold 或统计显著性证明。可复核的逐次回答与选择摘要见 observation-choice-assessment.json。只能支持这个角色、这条认识、这组刺激中的条件效应，不能泛化到所有角色与所有场景。

运行了类型检查、实验文件 Lint、真实模型调用与上述来源／上下文／执行审计。正式运行时未修改，没有重跑全量测试或新的长试玩。

## 6. 复现

先按本目录 README 准备 Python、E5 和本机 Gemini 网关，使用不存在的新目录：

```powershell
node --import tsx tests/experiments/observation-choice.ts .tmp/my-observation-natural
node --import tsx tests/experiments/observation-choice.ts .tmp/my-observation-intervention --delivery-intervention-from .tmp/my-observation-natural
```

第一条进行形成、时间推进和自然召回；若没有目标认识或它没有自然交付，不进行假装有认识的行为调用。第二条明确开启交付干预，复用并校验第一条的授权来源前缀。新的生成可能形成不同的认识；报告的结果只对应本次冻结档案。

当前最值得继续核对的是这条认识为什么未进入自然候选。读到后的行为效应已有具体证据，不需要再扩展通用评估设施。
