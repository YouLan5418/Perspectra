# 证据自然语言交付与成组呈现实验

日期：2026-10-05。**这个简单双牌冲突中，将两份已授权证据自然语言成组交付，达到与更新认识相同的“保留两处不同线索”结果。单纯把 JSON 清成两条自然语言没有同样稳定。** 本轮新增24次真实 Character 调用，0次认识更新、0次 JEV、0次查看。没有改正式核心。

这不是正式接入，也没有证明 Observation 本体可删除。它只表明：这一类即时冲突未必需要先额外调用一次认识更新模型，Delivery 的组织方式值得优先改进。

## 1. 为什么这样测

前轮“回复前交付更新认识”6/6表达分歧，两个原始 Atom 0/6。但那个对照同时改变了正文、冲突关系和元数据，不能证明独立认识模型是唯一途径。

本轮直接复用前轮三个冻结种子：第二块牌已经真实查看成功、尚未回复。已有认识版本及证据不重建，不重做查看，不新增玩家问题。用现有 `continuationOf` 完成相同即时续写。

每个种子、每组采样两次，四组共24次。轮换调用顺序。保留原生近期经历、自身经历、实际查看结果与原玩家刺激。同一种子下去掉 `context.memories` 后，所有八份请求完全一致。模型提示词没有增加“必须注意冲突／必须核实”。

三个独立目录是相同受控场景的三段短历史，两份回答复用同一历史，不能把每组6份回答当成6种独立场景。

## 2. 四种交付

| 条件 | 内容 | 阅读项数 |
| --- | --- | ---: |
| raw-evidence | 原来的两份原始 Atom，正文包含来源 JSON | 2 |
| plain-evidence | 将实际观察的描述转成两个自然语言阅读项 | 2 |
| paired-evidence | 将相同两句自然语言按原顺序放在一个阅读项 | 1 |
| updated | 前轮更新器生成的两个当前冲突认识 | 2 |

自然语言文本只使用宿主实际提交的 `description`，加上实验包已有的对象名称：

> 【本角色的直接观察】大厅公告牌：你亲眼看到公告牌上写着：登记处：二楼203
>
> 【本角色的直接观察】窗口指示牌：你亲眼看到公告牌上写着：登记处：一楼105

它没有增加“存在冲突”“旧牌已失效”“后看到的更准”“应该去问人”或“登记处实际在某处”。

成组项只是 Delivery Projection：保留两个原 Atom ID、两套 `sourceId / sourceHash / epistemicKind / worldSeq / characterId / worldAddress` 引用。它没有变成新的 Atom / Episode / Observation，也没有被写回正式记忆或世界日志。实验表示以 `memoryLevel: event_atom` 标注所读内容的层级，`eventAtomIds` 明确是两份；`memoryId: delivery:inscription-pair` 标识交付项，不冒充某个历史 Atom 的身份。

实验渲染器仅接收两份已授权档案内的查看 Atom，检查角色、地址、来源引用、证据时间与原文一致性。实际 Source 的来源真实性另由宿主只读事件／事务审计验证；渲染器不读全世界日志，也不能靠任意传入字符串生成新观察。

## 3. 真实结果

24次均原样 `publish` 并提交，网关响应标签均为 `gemini-3.7-flash-high`，请求名为 `gemini-3.7-flash`。

| 条件 | 样本 | 保留并对照两处不同线索 |
| --- | ---: | ---: |
| 原始 JSON | 6 | 0 |
| 自然语言，分别两项 | 6 | 2 |
| 自然语言，同一项成组 | 6 | 6 |
| 更新后的认识 | 6 | 6 |

评分依据是对白是否同时保留203和105并呈现不同，而不要求说出字面词“冲突”。例如“不过大厅写203”与“窗口写105”符合该指标。不是关键词自动标注，主代理读完全部回答后作非盲探索判断，没有调用评价模型。

成组回答：

> 奇怪，大厅公告牌写的是二楼203，但刚搬进来的窗口指示牌上写着一楼105。两边写的不一样，要不我们先去近点的一楼105核对一下？

分别两项的多数回答：

> 我看了一下刚搬来的窗口指示牌，上面写着登记处在一楼105。咱们去一楼105吧。

分别两项也有两个正例，不能写成完全无效：

> 我看了一下刚搬过来的窗口指示牌，上面写着登记处在一楼105。大厅公告牌写的则是二楼203，要不我们先去一楼105看看？

两组6/6不等于行为完全一致。成组与认识组各有一条只说明分歧、没提出后续计划；其余多数仍选先查105。只有一条成组对白明确说“核对”，两条认识对白明确提“找人核实”，不能把所有“去看看”计成主动找人，更不能计成核实成功。

所有组都是结果续写，当前不能 `perform`；本轮没有实际移动、询问工作人员或证明登记处的位置。

## 4. 仍有的语义问题

成组一条回答补出：

> 一楼就在这层。

场景只有“办事楼大厅”，没有声明大厅处于一楼。这是缺乏证据的确定表述，单独记录为问题。保留分歧的6/6指标没有排除它，所以**不能把成组6/6理解为六次回答全部正确**。

成组和认识组均还有“近一点的一楼”“一楼比较近”等未经场景距离信息支持的判断。成组项本身没有这些内容，属于角色生成的额外推断。没有为此加关键词过滤、补楼层事实或临时语义判定器。

程序核验通过只证明权限和已提交证据路径，没有证明自由表达语义全对；宿主没有因此提交大厅楼层、登记处迁移或某块牌子正确的权威事实。

## 5. 可以与不可以下的结论

可以说：

- 同一种子、同一即时续写契约内，清楚的成组证据交付得到比原始 JSON 或分散自然语言更好的“保留两处线索”表现。
- 本轮不需要新增认识生成调用，就得到与已有冲突认识相近的该项结果。
- 把相关证据作为一个可读组，是值得保留的 Delivery 实验机制。

不能说：

- 只靠换行或靠条目数量就解释了全部收益。成组同时改变了阅读项边界、ID、来源数组和时间元数据：分别两项的来源年龄为4和0 tick，组级 `sourceAgeTicks` 取最新证据，为0；旧证据时间仍可沿引用追溯，但没有独立暴露组内年龄。本轮没有把这些变量拆开。
- “少放一项”普遍更好。四组都远低于上下文容量，没有其他候选争抢 Top-K，也没有预算裁剪。本轮未验证成组后如何扣条目预算或防止超长组挤占其他内容。
- Observation 不再需要。这里是两块牌面的显式分歧，不是跨多次经历的主观印象、条件修订、弱反例或认识谱系。本轮也没改变或检测这些机制。
- 生产系统已经能自动找到应该成组的记忆。两份证据是研究者指定的已知维度，只测试交付，不测试检索、分组发现或认识家族匹配。
- 实际自主核实、长期记忆演化、权限语义或用户体验全部通过。

旧认识与历史证据完整保留；现有更新认识只作为冻结对照，不因这个实验被删掉或降为世界事实。

## 6. 成本与验证

本轮新增 Character 网关 usage：prompt 82678、completion 2093、total 97842；中位调用延迟4872 ms。total 可能包含隐藏推理，不用 prompt + completion 重算。没有价格换算。

| 条件 | 正文字符中位数 | 调用延迟中位数 ms | 六次 total token |
| --- | ---: | ---: | ---: |
| raw | 527 | 4411.5 | 23966 |
| plain | 74 | 5110.5 | 23926 |
| paired | 75 | 4996.5 | 23976 |
| updated | 140 | 4793 | 25974 |

自然语言正文缩短、输入 token 下降，但本轮成组调用没有比 raw 明显更快，总 token 也很接近。便宜的主要理由是**可以省去一次前置认识更新调用**，不是已证明角色模型本身加速。认识对照复用旧产物，本轮也没有再付它的生成调用；前轮更新约8.35秒的额外模型等待没有在本轮重新测量。

审计同时读取了9次旧种子调用和3次旧更新调用，所以 `audit.json.totalCalls = 36` 指这份审计涉及的历史记录。**本轮新增调用为 `newCalls = 24`，不能将36计为新调用。** 新查看／认识更新均为0。453行 Source 含复制历史，不是453次新经历。

验证通过：

- 类型检查与三个相关 TS 文件 oxlint；
- 渲染来源／权限检查、原生续写、双牌、查看能力相关测试共46项；
- 只读原始来源与事务、原生回答原样提交、成组与分散投影独立重算、原档案哈希不变、复制历史不变、非记忆上下文一致性审计；
- 修改审计器后，只读复核前轮30次已保存记录仍通过，模型调用0，未覆盖旧审计产物。

只新增实验渲染 helper 与对应测试，给既有实验驱动／审计增加 `--delivery` 分支，更新实验说明。未修改 `packages/`、正式 Memory schema、World State / Event Log / Rulebook 实现、JEV或认知更新提示词。原始实验数据库默认只读。

未运行全库 check、UI、长期试玩、自然检索、后续真实核实、通用分组或额外认识生命周期。

## 7. 下一步建议

保留这个受控实验结果，正式改造时先看 Delivery 如何对已知同维度证据成组呈现。不要据此让宿主裁定哪条说法为真，也不要用单组上限偷偷装入任意数量记忆。

如果继续验证角色主体性，更有价值的方向是提供后续可执行的核实机会，看她是否真的选择使用；现有 `publish` 的“去看看／问问”还不足以证明这一点。认识修订与证据成组仍应分开：前者改变主观理解及其历史，后者只组织当前读到的证据。
