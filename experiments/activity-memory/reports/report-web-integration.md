# 可选网页 Core 接入冒烟（2026-10-03）

## 问题与改动

之前只能经专门实验驱动使用 Core，正常网页仍走原生召回，而且源码、Python 和模型默认路径依赖另一工作树。现在 Core 随当前树保存，新增可选 `--memory-core`，宿主可手动整理角色长期记忆。默认行为不变。

## 真实执行

入口：`tests/experiments/activity-memory-web-smoke.ts`。独立新目录：`.tmp/web-core-integration-20261003-v1`。模型为本机 8045 的 `gemini-3.7-flash`，没有使用伪造模型响应。

顺序：普通问候 → 开始主持人猜数字 → 玩家猜 50 → 宿主逃生 → 四角色记忆整理 → 普通提问 → 关闭并重新创建运行时 → 再次正常发言。所有这些 HTTP 操作返回 200。游戏由逃生中止，未宣称自然完成结算。

共 22 次实际角色返回（publish 14、abstain 3、perform 3、主动 recall 2），12 次真实整理调用全部返回有效结果、finishReason=stop。这里的分类是模型提案，不将 perform 计数直接当作已提交行动计数。

整理后的四份角色档案共 69 条来源、94 条 Atom、7 段 Episode、11 条 Observation。宿主审计将档案逐项对照各自 CognitiveMemoryService 来源前缀，索引来源也完全一致；782 个带六字段的对象通过追溯核验。缓存前缀为 171，整理前后 World Event Log head 同为 171。模型在后续交流中继续提交新世界事件，最终 head 为 227。五个 SQLite 库 quick_check 均为 ok。

## 可以和不能得出的结论

真实来源能经本地 Core 提炼成档案，整理不改变世界事实；整理后和重启后可以继续普通发言。重启、取消与角色隔离另有自动回归覆盖。

10 次已建索引的召回交付全部为空：六次没有检索候选，另外四次共 11 个候选因“已在当前上下文”被去重。Observation 也没有交付。因此这轮不能支持“角色通过长期记忆记得游戏”或“召回质量已改善”。近期上下文没有清空，回答仍可能来自它。长期质量仍以此前长试玩及独立冷探针报告的限定结论为准，没有为获得非空而重新调门槛。

走的是与浏览器相同的 HTTP 接口，校验了宿主 HTML 含维护按钮；未操作真实浏览器，也不宣称视觉或点击流程验收完成。`desktop:build` 通过，但桌面发布仍不包含实验 Python/Core 资产。

本地记录：`steps.json`、`summary.json`、`audit.json`、`utility-calls.jsonl` 和存档 `memory-core/` 下的独立缓存／召回／模型 trace。它们含角色私有上下文，未加入 Git 或玩家接口。凭证和认证头不入记录。
