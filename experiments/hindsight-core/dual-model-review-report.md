# 双模型独立盲标（2026-10-01）

按用户最新要求改用本机 8045 接口的 Claude Opus 4.6 与 Gemini 3.1 Pro。两者分别完成同一冻结池的 48 组、367 项标注，共 96 组有效模型调用结果、734 条候选判断；其中 3 次格式/覆盖校验失败原输入重试，实际标注尝试 99 次。没有人工 gold；每个模型的答案独立保留，未强行形成共识，也没有重新提炼、改变门槛或使用 30 点留出。

## 输入与边界

- 输入严格复用人工盲评 blind-pool.json：当前角色已授权 Context、当前刺激、打乱后的候选证据及认识。无系统名、检索分数、排序、旧标签或另一模型答案。每组为独立请求；模型不能读取完整档案、其他角色私密信息、World Event Log 或 World State。
- 保留原 five-way 分类：useful/background/irrelevant/harmful/uncertain；查询需求 none/some/missing/uncertain；每个标签带短理由。候选覆盖与需求一致性校验失败会原输入重试，拒绝遗漏键或未知候选。失败不会自动补为负例。
- 原证据六字段与排名仍在冻结池的私有映射中保留；本次标签以 opaque queryId/candidateId 回连，不覆盖 Source、Atom、Episode 或 Observation。

## 对结果的判断

**本轮标签足以探索分歧，不能直接用来确定召回门槛或选择编码器。**

- Claude 没有正例，因此它的 precision 恒为 0，poolRecall/nDCG/AUC 无法计算；这不是检索系统已经被证明完全无效，而是这套评审结果没有提供排名区分度。
- Gemini 有 19 项正例，但只有 8 个查询有正例，只有 4 个查询同时有 useful 与 irrelevant/harmful 可算 AUC。Qwen 清理相对 E5 清理的 poolRecall 差值约 +0.083，95% 区间 [-0.333, 0.500]；nDCG 差值约 +0.057，区间 [-0.223, 0.325]。仍无法确认哪种编码器更好。
- “有用/其余”一致率 94.8% 来自类别极不平衡：Claude 全部判无用，所有 19 项正例都只来自 Gemini，kappa=0，不能把高一致率说成可靠的有用性标注。
- 没有把双方交集当正例，也没有把分歧自动当负例。E5 清理与 Qwen 清理继续并行保留。

### 核对两条具体证据

第 95 回合，Gemini 把“旅人要理随身物件”的 Atom、另一通道的 Atom、原输入 Atom 与包含它的 Episode 共四项判有用，理由是可以关心行囊是否整理好。Claude 说这段原话已在 observations 中、没有增量。核对实际 Context：出现的是沈南自己的“成，你先理着，待会儿茶水间见”，没有完整的“旅人打算理理随身物件”原话。**Claude 的“原文已经覆盖”理由过于肯定；但 Gemini 将同一件事的四种表示算作四个正例，也不等于四段独立有用经历。**不能只凭某一模型的理由替另一套标签盖章。

第 97 回合 obs:1 仍写“泡好茶后特意相告”，引用来源却标注“听到发言；所述内容未经独立核实”。两个模型都判 background，理由聚焦当前已在喝茶、无需复读，没有标出此前指出的确定性升级问题。34 项 Observation 候选（跨查询重复计数）全部未获 harmful 标签，**不证明 Observation 失真消失**；相关度盲标不能替代独立保真审计。
