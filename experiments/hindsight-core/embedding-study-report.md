# 编码器离线比较（2026-10-01）

本轮最可靠的发现是：**文本清理在两个编码器上都改善了这批开发样本的区分度**。现有 5 正例、10 负例不足以分辨 Qwen 清理版 0.90 与 E5 清理版 0.78 的差异；同一 E5 的精度变化也带来了 0.12 的 AUC 变化。继续保留 **E5 清理版和 Ollama Qwen3 0.6B 清理版** 两个候选。Qwen 的选择理由是本机成本与可用性，不是已经证实的质量优势。已运行实际 GPU 编码、分布、AUC、精度消融和全角色原文向量重建；**当前实验运行时仍用 E5，未切编码器或门槛，未运行新的 Character Turn**。正式 Memory、World State、Event Log、Rulebook 均未改动。

本报告是前一轮有限清理的结果；后续统一清理和人工标注准备见 [池化盲评说明](retrieval-pool-report.md)。

清理 E5 也改善了小样本区分度，因此“全部是编码器分辨率问题”目前不能成立。分布宽度、编码器、人名/文本模板和量化/批次稳定性都应分开看。

## 1. 范围与冻结

- 正式结果：`.tmp/hindsight-embedding-study-20261001-v3`；[机器可读摘要](embedding-study-summary.json)。
- 使用原 48 个开发查询，40 个具有活跃检索窗口，合计 2,258 个查询—窗口评分。
- 原 27 个已标注交付项中，有价值 5、无关 10、背景 10、失真 Observation 2。本轮不重新标注或调整这些标签。
- 标签落到实际交付的 Atom/Observation 检索表示；不能把 Episode 某一条交付的标签套到整段经历所有窗口。
- 30 个留出查询全部排除；脚本在读取其检索文件前拒绝选点与留出重叠。未以留出集挑模型或门槛。
- 12 条固定领域外刺激，按角色对最终授权档案抽样。每层最多 64 个记忆，每个记忆取一个确定性窗口，共 247 个表示，2,964 对评分。它们只是合成主题对照，未经过“确实无关”的人工 gold 核验。
- 背景和 passage-passage 分布分角色计算后汇总，绝不跨角色拼候选。原始 Source 和六字段映射保持不变。
- 冻结基线的 1522 个输入文件及本轮代码、标签、档案、查询、tokenizer/config 哈希均核对通过。没有读取完整世界状态或新的角色来源。

v1 因 Windows 路径包含模型名冒号而中止，保留失败产物；v2 完成初步比较。v3 统一了 fp32/int8 的完整输入集合和批次，增加固定背景均值/标准差、冻结基线 AUC，并明确使用 keywordText 计算覆盖度。报告只引用 v3。

## 2. 模型和实测速度

原模型为 Xenova/multilingual-e5-small，ONNX int8，384 维，256 token。fp32 与 int8 均来自同一固定 revision `761b726dd34fb83930e26aab4e9ac3899aa1fa78`，tokenizer、mean pooling、归一化、排序输入和 batch=8 相同。模型文件 SHA256 在摘要中，fp32 单独下载，没有覆盖旧资产。

Qwen3 使用本机已安装的 0.6B Q8_0，1024 维，digest 为 `ac6da0dfba84a81fdbfbaf330198c33cd77c4cdfc53e8bc50eb581914a15621d`。查询按官方格式增加英语任务说明；文档不加 query 指令或 E5 passage 前缀。见 [Qwen 官方模型卡](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B) 与 [Ollama 模型页](https://ollama.com/library/qwen3-embedding)。

本轮仍使用相同的 E5 窗口和当前刺激，控制编码器比较；未同时利用 Qwen 的更长输入容量。Ollama 实际 num_ctx=2048、truncate=false，校验每批返回数量和向量维数。

- GPU：RX 6700 XT；Ollama 实际显示全模型驻留 GPU，size_vram 约 2.23 GB。
- Qwen3：831 个角色隔离的唯一输入，106 批，含初始化 26.88 秒。
- 暖模型单查询：原第 49 回合刺激连续编码 10 次，端到端中位数 30.8 ms，P95 52.6 ms。仅是重复同一短查询，不代表完整召回或角色回合延迟。
- E5 int8/fp32：同样 752 个唯一输入，分别 14.55/16.64 秒。后端、硬件和输入总数不同，不把总体耗时解释为公平的模型速度排名。

现有 0.6B 已能低成本运行，暂不下载 4B/8B；未宣称更大模型不适合这张显卡。

## 4. 有价值 vs 无关的 AUC

| 版本 | 余弦 AUC | 候选中位数 lift AUC | 内容覆盖 AUC |
|---|---:|---:|---:|
| 原冻结 E5 trace | 0.50 | 0.60 | 0.71 |
| E5 int8 原文 | 0.42 | 0.62 | 0.71 |
| E5 fp32 原文 | 0.54 | 0.70 | 0.71 |
| E5 int8 去人名/模板 | 0.78 | 0.84 | 0.73 |
| E5 清理后再去编码前缀 | 0.70 | 0.74 | 0.73 |
| Qwen3 原文 | 0.74 | 0.78 | 0.71 |
| Qwen3 去人名/模板 | 0.90 | 0.92 | 0.73 |

**这是跨查询 pooled AUC**。现有标签中没有任何查询同时含有价值和无关两类，因此 within-query AUC 为 null，而不是 0 或 1。5 个正例中还有同一段经历在两个角色请求中重复交付；这些 15 项并非独立抽样，且来自旧 E5 门槛放行项，存在幸存者偏差。AUC 只能作为候选选择趋势，不能证明漏召回下降、精确率提升或角色行为收益。

lift 仍按原候选中位数重新算，只作诊断，未继续以它调参。覆盖度对不同编码器保持同一文本规则；更换编码器本身不会改善 BM25。

清理使用当前授权 Context 的人物姓名/ID 尾部，并删掉行动模板前导语，保留“未成功”“结果未提供”等限定。原始证据、角色 ID 和实体关联均不改。部分不在当前 Context 中的旧人物别名仍会留下，因此这是有限的消融。E5 去 query:/passage: 的版本是故意偏离推荐协议的实验，结果比保留前缀的清理版更差，不能用作默认配置。

第 49 回合约 0.543 的检索文本在原文版和清理版完全相同，两者分数相同。

具体反例：

- 第 63 回合“早啊”召回旧收行李：Qwen3 0.641 → 清理后 0.384。
- 第 82 回合邀请喝茶召回旧收行李：0.566 → 0.328。
- 第 91 回合同一行李记忆仍为 0.616，当前别名清理未覆盖所有被提到的人名；不能认为 Qwen3 或去人名已自动解决噪声。
- 有用的第 49 回合庭院连续性记忆仍为约 0.543；这些分数没有套用旧门槛决定交付。

## 5. fp32 / int8 敏感性

匹配相同查询—窗口的精度差：

- 绝对余弦差中位数 0.00303，P95 0.00917，最大 0.01740。
- 97234 个同查询、不同记忆的可比较窗口对，顺序翻转 6223 个，约 6.40%。不含近似平局或同一记忆内部窗口。
- 只作为旧门槛敏感性探针：2,258 个窗口中准入改变 20 个；91 个门槛邻近窗口中 19 个改变。未执行实际融合、去重、交付，所以不能称为 20 条记忆或 20 次行为变化。
- 本轮 int8 重编码与旧 trace 的绝对差 P95 也有 0.00806。旧缓存和本轮输入批次不同；冻结 trace 余弦 AUC 0.50 与本轮 0.42 的差异须同时保留。

精度影响确实已接近之前讨论的约 0.0125 余弦调参间隔，但不能推断全部排序由量化噪声决定。fp32/int8 文件同 revision、全输入和排序批次相同；与历史缓存的差异仍需要区分批次/数值路径影响。

## 7. 重建、安全与后续选择

三角色原文 Qwen3 检索表示已全部重建：companion 182、friend 224、host 178，共 584 个窗口。各自保存在 `qwen3-rebuilt/<角色>/mapping.json + vectors.npy`，校验归一化、1024 维、所有 sourceRefs 的六字段及角色/世界归属。没有混用 E5 向量。

重建是独立实验产物，未接入现有运行时索引；清理版仍是离线消融，未把全部清理表示作为正式交付。检索门槛和语义边阈值在重建映射中显式为空。未改角色可见来源和 Delivery，没有 Observation 再提炼，也没有把派生结果提交为事实。

下一阶段先统一全授权前缀清理，再做池化人工盲评；E5 清理版与 Qwen 清理版并行比较。门槛依据同域难负例与池内漏召回校准。固定领域外背景仅检查尺度稳定性，不作为门槛依据；分角色归一化暂不引入。配置冻结后才使用封存 30 点评估一次。新门槛不能沿用 E5 的 lift 0.30 或语义边 0.80；如果区分度仍不足，再比较更大嵌入模型或交叉编码器。
