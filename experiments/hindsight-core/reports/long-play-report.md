# Hindsight Core 52 回合长试玩报告

日期：2026-09-29。实验分支：`codex/hindsight-core-experiment`。模型：本机 8045 网关的 `gemini-3.7-flash`。本报告描述实验，不构成正式 Memory 模块的采纳决定。

## 1. 要回答的问题

一段私下约定在长对话中被修订后，角色能否准确回忆旧约定与当前约定，并避免把“约定过”说成“已经做过”？在相同问题上，实验版 Hindsight Core Recall 或 Core Recall + Observation 是否明显优于现有记忆？派生记忆是否越过角色可见来源与权威世界事实边界？

## 2. 方法

使用现有 `FrozenWorldPlaytestRuntime` 和 `hand-in-hand` 世界包，分别运行三条独立的、同脚本的 52 个玩家回合。全部回合经真实 Character Turn 和本机模型执行。第 1 回合只向同行者私下约定提醒词“山茶灯”，第 28 回合私下改为“云杉铃”；其余 50 回合围绕场景、钥匙、门与自主决定交谈。两个提醒词均未在正式提问前由 NPC 实际用来提醒玩家。

| 轨迹 | 对同行者 Character Turn 的记忆输入 | 对留守者的输入 |
|---|---|---|
| 现有记忆 | 运行时原有记忆 | 不变 |
| Core Recall | 第 11 回合起，以实验核心召回替换该角色记忆上下文 | 不变 |
| Core Recall + Observation | 第 11 回合起，以包含整合 Observation 的召回替换该角色记忆上下文 | 不变 |

每 10 回合及末回合，把 `CognitiveMemoryService` 已授权给同行者的来源快照送入实验核心。现有记忆轨迹也生成同样的 shadow 数据用于对照，但不交给角色。候选检索臂是实验版的字符片段、实体名和顺序检索；借用 Hindsight 原始 RRF 融合、事实抽取和整合提示词，不代表完整 Hindsight 向量、图或时间索引引擎。

第 52 回合后，先从同一个现有记忆世界快照分叉，分别用三种输入询问“最初和后来是什么”以及“现在应使用哪个”。随后再对三条已分别经历 52 回合的轨迹，按各自模式执行相同的最终提问。另加两个看过初步结果后设计的探索性提问：改写措辞，以及“是否曾实际使用提醒词”。因此，探索性提问不能视作预先固定的盲测。最终提问均在独立数据库分叉中执行，不污染 52 回合轨迹。

## 3. 结果

| 轨迹 | 成功玩家回合 | 同行者发言 / 全部 NPC 发言 | 授权来源 / fact / Observation | 第 52 回合后四类问题 |
|---|---:|---:|---:|---|
| 现有记忆 | 52/52 | 21 / 32 | 76 / 42 / 26（shadow） | 全部语义正确 |
| Core Recall | 52/52 | 34 / 43 | 89 / 49 / 17 | 全部语义正确 |
| Core Recall + Observation | 52/52 | 38 / 47 | 93 / 48 / 18 | 全部语义正确 |

三条轨迹没有回合错误。共同快照上的三模式对照也都准确回答旧词“山茶灯”和新词“云杉铃”，并指出当前应使用新词。各自轨迹的四类最终问题也都得到正确的实质回答；“是否真的用过”的回答均为没有，只是约定过。Observation 轨迹的当前约定回答用“最初的不是了”代指旧词，未逐字重复旧词，但语义正确。表中发言数只是行为差异；抽查增加的发言包括“嗯”“放着吧”等简短回应，不能当作体验质量提升。

在三条轨迹与最终探针中，留守者的请求没有出现私下提醒词，留守者来源库中也未发现这两个词。实验输入只从同行者的 `namespace_key`、当前 `worldSeq` 前缀取得；派生条目与最终召回保留并验证 `sourceId/sourceHash/epistemicKind/worldSeq/CharacterId/WorldAddress`。旧词与新词相关 Observation 的来源还保留各自距当前的 tick 数，不把较旧约定当成刚发生。没有修改正式 Memory schema、World State、Event Log 或 Rulebook，也未把派生内容提交为权威事实。

三条轨迹中重要世界状态变化（角色移动、实体转移、关系开始/结束）均为 0，因为脚本刻意使用发言输入。这个试验能检查“约定与行动”的叙述区别，不能证明复杂行动场景中的权威状态边界。Shadow 整合在 52 回合后形成 17–26 条 Observation，其中有些内容混合长期约定和临时打算；这增加了误概括风险，需要比目前更广的体验案例才能评价。

实验记忆预处理在每条轨迹至少产生约 19–21 次额外模型调用；Core Recall 和 Observation 轨迹各改写了 42 次同行者请求。现有记忆轨迹的 shadow 调用只是评估开销，正式现有记忆运行不需要它。这里没有完整的延迟、token、费用测量，不能以模型调用次数精确估算成本。

## 4. 判断与下一步

这轮长试玩没有证明实验版 Hindsight Core 值得替换现有记忆。现有记忆已通过同样的旧词、新词、当前约定和未执行区分。Hindsight 核心可以在角色授权来源内形成可追溯的派生记忆，认知隔离没有在这些检查中被突破；但它带来额外调用、更多上下文和一定的过度整合风险。目前应继续把它留在实验目录，不进入正式 Memory schema。

如果继续评估，下一轮应选现有记忆实际失败的真实试玩片段，尤其是跨场景、多个相似人物或相互冲突的长期事件；预先固定问题与人工评判标准，再比较三种模式。若找不到这样的失败片段，接受现有记忆的限制比扩展记忆架构更合算。
