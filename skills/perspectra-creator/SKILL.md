# Perspectra 创作

先定玩家在什么地方遇到谁、此刻可以做什么、谁知道哪些事，以及哪个行动会改变后续处境。交付物是有内容且能继续编辑的 v5 源目录。只提供本 skill 也可直接写文件；装有 worldpack 时用它验证，有工作台时再按作者需要协作。

## 选择本次工作

- 原创或修改源包：读[源包与人物](references/world-pack.md)和[直接写文件](references/editor-handoff.md#直接写文件)。可用随附脚手架和活动模板，无需编辑器 CLI。
- 配合作者：读[与编辑器协作](references/editor-handoff.md#与编辑器协作)，沿用现有源目录、ID、草稿和布局，并交付可重开的导出包。
- 酒馆角色卡分析／转换：读[酒馆卡迁移](references/tavern.md)。本 Skill 已收录旧 tavern-to-perspectra 的提取器、容量分析与迁移／验收方法，不依赖另装旧 Skill。只评估时不建包；明确转换时继续完成源包与所需规则。
- RPG 玩法（战斗、队伍、副本地图）：读[RPG 玩法](references/rpg.md)，在包里写 `rpg.json`。
- 从零写一种玩法，或把它做成可跨作品安装的原生插件：读[玩法插件与 SDK](references/gameplay-plugins.md)，内含两种入口、可复制示例、宿主服务清单与验收步骤。
- 条件遭遇、委托和奖励抽取：按作品已有变量写[遭遇与委托表](references/gameplay.md#遭遇与委托表)，用同一份条件预览匹配和排除原因。
- 跑团玩法（AI 主持人、可信掷骰、检定）：读[跑团玩法](references/trpg.md)，在包里写 `trpg.json`。
- 预设创作／修改：读[原生预设](references/presets.md)，按包推荐或命名交换格式输出。仅做预设时不生成游戏包；同时迁移卡和创作预设时共用本次选定人物及风格。

按作者指定的原卡、作品与还原范围工作。大型卡按原始条目和可玩路线记录覆盖、差异与剩余工作。

## 找到目标程序

创作只需要能写文件。运行 skill 中的 .mjs 工具可用系统 Node 或程序内 runtime/node.exe。需要校验时，使用目标程序的 worldpack.cmd，先看 --version、--help；编辑器命令另查 editor --help。目标源格式为 worldpack-source/v5，编译制品为 worldpack/v5。多个程序可能共用版本号，按实际可用命令和运行结果交付。只有 skill 时可完成源包，注明尚缺哪些运行验证。

## 创作或修改

先给一段玩家与角色的互动例子，明确核心角色、开场、信息差和当前确实要追踪的玩法。普通文案与目录选择可自行决定；只有答案会实质改变作品时才询问。用户要求完整作品时，脚手架只是起点，继续实现内容和必要规则，不能以空模板代替交付。

世界包新作品用脚手架创建**不存在的新目录**，随后把人物、地点和认知改成用户的内容：

```powershell
& '<程序目录>/runtime/node.exe' '<skill目录>/scripts/create-world.mjs' '<作品目录>' 'pack:my-world' '我的世界'
& '<程序目录>/worldpack.cmd' validate '<作品目录>'
& '<程序目录>/worldpack.cmd' test '<作品目录>'
```

脚手架仅生成一个玩家、一个 NPC、一个地点的文件结构，不含剧情、玩法脚本或固定结局。编辑已有作品时先读清单与相关文件，不运行脚手架覆盖它。独立作品使用新 packId，发布内容更新时提升 packVersion；不要改旧存档或强行修改摘要来续玩新内容。

读 [源包与人物](references/world-pack.md) 了解文件引用、初始认知和知识。涉及物品、客观状态、活动（含多场、自动开始和隐藏回合）、剧情节奏、角色自主、短信、插件或界面时再读 [玩法扩展](references/gameplay.md)，有物品规则需求才使用 `assets/status-items.js`；只想换官方舞台的配色、字体或卡片样式时，复制 `assets/theme.css` 到作品的 `frontend/theme.css` 再改。

- 角色的情绪、好感、信任等主观态度默认写进人设、预设、记忆与对白；只有用户明确要追踪这项机制时才设计数值。
- 不将秘密塞入公开描述、公共前端或全员初始观察。背景设定与亲身经历分开；知识条件只检查接收者授权的材料，不能靠条件扩大文档受众。
- 重要位置、物品归属与明确追踪的状态由 Action／规则／事件路径裁定。普通姿态和语气保留自由，不扩成闭合动作码；拒绝后不靠台词或旁白补成成功。
- 调度给角色机会，不能代替它决定态度与行为；固定脚本演出只用于用户确实需要的片段。
- 酒馆原卡、HTML、EJS 和第三方脚本先当数据静态阅读，所需逻辑另写包内代码，不直接执行原卡。复杂迁移单独列出待核查内容，不把本 Skill 当自动兼容层。

## 用推演自查

用 `worldpack.cmd editor records '<源目录>'` 查角色、地点和物品；活动与规则的机器接口见 `worldpack.cmd editor --help`。修改后运行 `validate`，再用 `worldpack.cmd simulate '<源目录>' '<剧本路径>'` 核对动作、触发和状态变化。退出码 2 表示剧本已执行但未通过，查看各步的 `expectations` 和 `error`。角色表现需另行真实模型试玩。[推演脚本](references/gameplay.md#推演脚本)

交接时在作品工作区保存作者确认的目标、对应的用例 ID、清单与剧本。导出完整源目录后运行 `worldpack.cmd accept '<导出目录>' '<验收清单.json>'`，把程序生成的 JSON 连同该版作品交接。交付通过须核对本次全跑的 `deliveryPassed:true` 及输入摘要。按 ID 筛选适合改作时回归，换导出内容、剧本、清单或引擎构建后要重新全跑。[清单与断言示例](references/gameplay.md#交付验收)

## 校验与实际运行

有永久告别、失踪或分队的章节，按[角色退场](references/gameplay.md#角色退场)安排各人的可达地点、队伍与回程，再用已经开门的地图试着让她跟来。

凡是脚本写了「某角色告诉玩家、答应或亲手交给玩家某物」，就在下一轮用自然语言回头问这个角色。分别核对玩家看见的文案、当事人有权收到的观察、实际对白与世界状态。再问一位没在场的人。活动等待选择时，按作者意图设置自由发言、固定台词或禁言。允许自由提问的作品，在原选项上直接问在场角色，聊完再选一次。[活动发言与剧情选择](references/gameplay.md#活动发言与剧情选择) · [正式 Host 试玩入口](references/tavern/validation.md#用命令行做真实模型试玩)

用目标程序的 `validate` 修正文件、引用和资产错误，再运行 `test`。读取退出码及 JSON；非零失败不得当成功。包契约诊断通常有 `details.diagnostics[].file/jsonPointer/message`，命令错误使用 `INVALID_REQUEST`。

当前 CLI 的 `validate` 编译源包、校验启用的插件组合，检查已声明的共同玩法脚本及绑定前端。活动具体分支、知识命中、玩家可见结果仍需推演或实玩。`test` 只编译适配，`assertionsExecuted: 0`；`compile` 的 JSON 制品不替代 Launcher 所需的完整源目录。预设另用 `preset validate <file>` 或包推荐的 `preset validate <file> --pack`，它们复用原生校验器，只检查字段／宏／正则语法，不证明风格效果。不要使用 `activate` 冒充完整游戏启动或断言执行。

把完成的源目录载入本版本 Launcher，在**新实例**中检查启动与扩展配置，然后按作品核心循环检查自然回应、信息差、可见选项、规则拒绝和成功后状态；需要续玩时再验证停止与重新启动。后台记忆整理、模型调用、外部服务沿用用户已有授权，未授权或缺少配置时完成其余工作并明确未验证项，不索取或记录明文凭证。

游戏源文件和程序运行环境分开保存；不改程序 runtime，不写历史数据目录，不把原始角色卡、凭证、数据库、模型请求和私人日志装进公开作品。后端玩法脚本是可信代码，前端沙箱不意味着任意游戏包都安全。

交付说明玩家能做什么、源目录位置、所需程序版本、校验结果、宿主启动和真实模型试玩各自的范围，以及已接受的限制。没有实际运行的步骤写成待验收步骤，不标成通过。用户没要求时不发布、推送或安装额外插件。
