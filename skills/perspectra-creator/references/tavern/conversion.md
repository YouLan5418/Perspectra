# 从体验重创世界包

例如“雨夜旅店遇见隐瞒身份的同伴，一起调查失物”：玩家应能自由交谈、选择相信或怀疑、离开房间、真的取得物品、给或不给。同伴只知亲历和获告知的事。不先建设通用任务编辑器。

## 内容落位

| 原卡内容 | 优先去向 | 必要决定 |
| --- | --- | --- |
| 身份/性格/语言范例 | 角色、人设、专属预设 | 谁是独立人物，谁是讲述者或背景 |
| 历史/传闻/误会 | 对应角色初始认知、授权资料 | 谁亲历、谁听说、谁不知道 |
| 主观态度变化 | 历史、记忆、人设与预设 | 默认不新增好感/信任量表；移除原量表需说明差异 |
| 世界背景 | documents/markdown和条件知识 | 公共常识、私有设定、分阶段揭示分开 |
| EJS状态输出 | 已知状态、静态条件片段、前端 | 公式走规则，显示走视图，不泄密 |
| 金钱/任务/时间/资源 | 作者状态接口与schema | 改变入口、告知、失败无变化 |
| 地点/物品改变 | move与当前作者物品规则 | 实际对象和可达地点，不能靠文本patch |
| 小游戏/战斗/邀请 | Activity及跨场状态 | 操作、资格、结算、受众、暂停/退出 |
| 固定开场 | 当前活动/固定决策机制 | 限定确定片段，之后交还角色判断 |
| 多开局 | 独立初始包或当前选择机制 | 玩家身份、地点和过去一起处理，不能只换首句 |
| 章节/结局 | 作者条件、活动和明确选择 | 完成条件可核验，失败后可继续 |
| HTML/按钮 | frontend与公共SDK | 原Tavern DOM/MVU/模型调用不能直接复用 |
| 手机/群聊 | 核查已安装通信，否则降级/缺失 | 不用同场私语冒充远程 |

混合性质的条目拆分；禁用条目保留为候选模块，不自动删除。默认不复刻防盗、CDN自更新或酒馆内部管理台。

## 生成

1. 打包版用本 Skill 的 scripts/create-world.mjs 在新目录生成源结构；另有源码时也可复制当前可运行的最小示例。使用新 packId，引用保持一致。默认使用创作者工作目录下的新作品目录，用户指定路径则遵从；原始提取另放平级 source，不覆盖旧包／存档，也不写入程序 runtime 或 Skill 安装目录。
2. 依据当前schema写人物、地点、物品、场景、玩家槽、表现和初始认知。清理示例无关人物、秘密、操作、剧情和资源，不能混入新作品。包内脚本按当前扩展点重写，不粘原卡代码运行。
3. 独立角色用稳定ID，公开介绍不含谜底；私史进入对应认知/文档，不进frontend。讲述者知道的一切不自动给每个角色。
4. 当前清单显式登记documents/markdown/assets，追到实际加载链。when是针对接收者授权运行时Context求值的JSON Schema条件，不执行代码或模板；知识正文不插值。关键词按新授权上下文重创。世界书单条比 knowledge.json 的 maximumCharacters 还长时宿主会拒绝加载：先 `& '<程序目录>/runtime/node.exe' '<skill目录>/scripts/split-knowledge.mjs' '<作品目录>' --dry-run` 查看计划，再去掉 --dry-run 执行；需要更细的分段时加 `--max <字数>`。拆分后逐段改写关键词，让每段只在相关话题出现时注入；报告里 skipped 的文档在其他文件中被引用，需手动处理。
5. 为玩法写明确policy/resolve：候选用有权知道的信息，执行重验真值、位置、工具、目标和范围。调查/领奖有正式入口，不能只信“查过了”。重要变化返回当前类型化效果。
6. 需要自主才给目标、区域和机会；控制类别不代表固定对白。机会允许沉默/拒绝，不强制角色喜欢玩家。预算按重要人物控制。
7. 默认先官方UI；UI是核心才重绘。按钮使用当前选项与参数；文字建议只是意图，不替NPC同意，不证明行动成功。
8. 开场/路线/活动之间应有可执行路径。当前扩展点满足不了的部分记录差异；默认不改core、不加通用EJS/MVU兼容器或新框架。

特别核对`first_mes`和选中的备用开场：新包没有同名字段不表示可以丢弃原开场。优先用现有演出/玩家可见开场重建；尚未实现时列为未完成，并区分“本包没接”与“宿主无能力”。固定台词不能只出现在迁移说明里却标为已还原。

Activity的opening仅展示给玩家，不自动成为NPC对白或经历。需要角色确实说过的开场，核查当前simulate/固定决策是否进入普通发布、观察与记忆路径；只画在前端不算共同经历。角色控制类别只用当前源码接受的值，不能虚构narrator控制器。世界旁白、作者确定演出与人物判断分别安排。

明确开场何时触发：实例创建、玩家点击开始、进入场景或首次发言。将原本启动即见的首句延后到玩家首个输入，是体验差异，必须列明。桩模型固定回首句只证明发布链可用，不能证明新包已通过配置实现自动开场；需要确定台词时优先核查已有固定演出路径。

多开局分三种处理：独立包可改变初始身份与世界；同一初始身份的后续选择可用现有Activity/状态；运行中改写genesis身份或过去须单独核查，不能只切换一句问候。先选最小能满足体验的方式。

状态先声明schema与正式改变入口。模型可提出已声明操作；只有宿主裁定后的类型化效果提交世界。Activity.resolve、作者状态resolve/onRoundEnd及初始化分别核查，不能笼统说“模型不能提变量”。原卡UpdateVariable文本不会自动执行，但可能进入显示/历史或破坏输出协议，迁移时需清理并测试，不能承诺宿主总会忽略。

容量超限先删去无关模块、拆分授权文档和按条件选择，再考虑缩写/摘要；保留原始正文与来源，不偷偷截断。摘要不能把秘密变公开或把历史推断改成事实。完成后核查总模型请求；重写EJS不等于支持原扫描/递归/位置语义。

小卡可一次完成，大卡先选完整核心循环并注明范围。用户明确要全量时持续按模块实现并列余项，不能静默删功能。关键身份、路线和结局确实无法确定时先完成独立部分，再问最小选择；目录、标签和脚本组织不逐项追问。

## 交付记录

在包平级写`migration.md`，不新增运行时元数据协议：

- 玩家能做什么，选用配置、人物与开场。
- 源SHA-256、变体和条目索引/JSON Pointer到产物文件/规则的映射；拆分也保留去向。
- 已映射、明确省略、未知和未审阅模块；不得全标完成。
- 原机制/玩家体验/当前机制/A-B-C-D-E-U/证据/差异/建议。
- 秘密接收者、客观状态改变入口、外部依赖处置，概述不复制不必要的私密正文。
- 编译、规则测试、真实模型、浏览器、发行各自状态；直接可用的启动命令。

原始来源、分析全文和调试日志不默认进入交付包。若用户要分享，先核对作者用途说明和发布范围，发布不是转换授权的延伸。远程资源仅有URL不能说已完整随包提供。
