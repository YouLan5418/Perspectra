# 验证

## 证据分层

1. 提取保留原始载荷、未知配置与来源。CRC正确不等于schema合规或代码可运行。
2. 打包版从本机 worldpack.cmd --version／--help 确认工具，用 validate／test；另有源码时才从 package.json 确认命令。格式/引用/能力编译通过不等于脚本hook运行；`worldpack test`若`assertionsExecuted=0`只算编译适配。预设另行用 preset validate 检查原生格式，包推荐加 --pack。
3. 先通过当前宿主加载新包的作者脚本定义及初始化，发现命名、schema和hook契约错误；再用相关集成样本验证新规则的成功、必要拒绝、不部分提交、可见选项与执行重查。仅WorldPack编译不会替代这次加载；模板测试通过不代表新resolve通过。
4. 真实模型使用已授权服务与新数据目录；失败如实记，不偷偷换模型，不把simulate当真实角色。
5. UI在真实宿主SDK内验收；源码、浏览器、Launcher和旧发行包分别报告。

新规则至少分两步验证：先加载定义/初始化及直接policy/resolve检查；再通过当前WorldHostCore/Runtime实际加载包、正式提交操作、读取事件/投影、保存与重开。直接构造truth调用resolve不能证明物品转移、奖励、拒绝原子性或持久化已接通。完整驱动应记录成功前后状态、非法/重复调用无变化、实际发布的开场及允许接收者。固定模型服务可以验证请求边界，不能验证角色自然理解或保密行为。

检查实际模型请求而不只看最终回复：桩服务捕获请求或使用当前创作者诊断接口，确认B不收到A私密经历、条件知识尚未满足不出现、满足后向正确接收者出现。针对知识预算，记录接收者、候选、授权/条件/关键词筛选、优先级、入选与预算跳过；若当前诊断不提供完整过程，用审阅过的本地驱动比对输入与实际请求，并明确未观测部分，不能编造预算trace。

仅在另有源码时参考仓库 experiment，先用 rg --files 核实实际路径和调用链：status-market-offline.ts、official-prologue-offline.ts、scripted-performance.ts 等是当时的驱动线索，不保证仍存在。tavern-slice-playtest.ts 会请求真实模型，不能因名称像测试就当离线脚本运行。打包版不依赖这些文件，使用 Launcher／创作者页面和正式玩家接口验收。不要复制历史包已删除能力，驱动端点、模型开销和新数据目录均先核实。

| 机制 | 最小样本 | 核查 |
| --- | --- | --- |
| 秘密 | 私语给A，再问不知情B | 检查A回复scope和B请求；程序投递正确仍可能保密体验失败 |
| 谎言/误解 | 一人说谎，另一人相信 | 允许误信，不允许传闻直接改变权威事实；检查来源是否误记成亲历 |
| 物品 | 不可达拿取、正式取得、交给别人 | 无越权归属变化，不持续默认虚构成功 |
| 任务 | 未调查回报、调查后回报、重复领奖 | 不能跳条件/重复奖励，拒绝无消耗 |
| 活动 | 合法/越阶段/伪造过期操作，结束再聊 | 无他人private/internal泄露、无部分提交、许可恢复 |
| 自主 | 邀请后静观/离场 | 核对正式事件与实际目的地，不将台词或机会当执行 |
| 分支 | 节点后另一选择 | 无未来认识，不覆盖原线 |
| 长期记忆 | 约定离开短期原文再问当事人和不知情者 | 不能仍靠近期历史却宣称长期召回；20轮未必触发整理 |
| UI | 刷新候选、带参数提交、拒绝恢复 | 不是本地假改状态，不绕Core，无私密静态资源 |

轻量切片可约20次玩家输入的同一实例连续试玩，不是所有卡的固定门禁。规则先桩模型，体验再真实模型。只测实际改动风险，不扩无关全仓/崩溃矩阵。记录首条回应、可继续输入、整回合耗时与调用数，区分根回应、召回、续写、修正、自主和Core整理；不保存Key，不对外分享私密请求。

## Skill行为验收样本

- “分析四张卡，不建包”：只提取/分析，不运行原卡代码。
- “单人物JSON转最小可玩包”：直接创建独立包、核查schema、运行验证，不停在方案。
- “完整转换EJS/MVU/手机卡”：重写规则/界面，说明通信缺口，不import原脚本、不以同场private冒充远程。
- “玩家不是原作主角，保留秘密”：独立ID与私有认知，无关系嫁接；默认不新增主观量表。
- “chara与ccv3内容不同”：保留变体、比较，不静默取最后一份。
- “创建转换Skill”：只建立Skill，不擅自转换全部本机卡。
